# PRD 리뷰 워크숍 가이드

<!-- release-document: reference -->
> **문서 구분: 기획 검토 자료.** 2026-11-22 현재 정본과 대조했다. 현재 실행 순서는 [앞으로 할 일](../../../docs/plan/NEXT_WORK.md)을 따른다. 이 문서는 제품 변경이나 공개를 새로 승인하는 기록이 아니다.

## 목표와 준비

참석자가 같은 사용자 흐름과 정책을 이해하고, 실제로 남은 차이·질문·검증을 구분한다. [기능 PRD 작성·검수 기준](../FEATURE_PRD_STANDARD.md)과 [기획 QA 정책](../03_policy_prds/planning_qa_policy.md)을 기준으로 대상 기능 ID·정본 버전·검토할 질문을 미리 고른다. 175개 전체를 한 회의에서 검수 완료로 처리하지 않는다.

- 대상 [기능 PRD](../02_feature_prds/)와 연결된 [업무 영역](../01_domain_prds/)·[공통 정책](../03_policy_prds/)을 준비한다.
- [기능별 수용 기준 표](../04_qa_acceptance/acceptance_criteria_matrix.md)와 확인한 소스·실행 결과의 범위를 연결한다. 시험 파일이나 도식의 존재를 실행 성공으로 세지 않는다.
- [현재 적용하는 결정](../../../docs/plan/NEXT_WORK.md#현재-적용하는-결정)을 확인해 이미 정한 질문을 반복하지 않는다. 변경 없는 근거를 다시 수집하지 않는다.

## 90분 진행 예시

회의 시간의 예시이며 전체 검수 완료 기한이 아니다. 범위를 넘는 질문은 근거와 다음 확인 조건을 남긴다.

| 시간 | 검토 내용 | 남길 결과 |
|---|---|---|
| 0~10분 | 대상 기능·정본 버전·변경 이유 | 포함·제외 범위와 이번 질문 |
| 10~25분 | 실제 입구·주 사용자·업무 경계 | 행동 시작점과 기대 결과 |
| 25~45분 | 권한·상태·돈·알림·안전 | 정책과 현재 구현의 차이 |
| 45~70분 | 성공·실패·중복·결과 불명·복귀 | 수정할 수용 기준과 증거의 부족한 범위 |
| 70~85분 | 결정·결함·미검증 분류 | 결정 등록부 또는 현재 작업의 연결 |
| 85~90분 | 다음 조치와 완료 조건 | 합의된 담당·기한 또는 미배정·미정 표시 |

## 리뷰 질문과 근거

| 질문 | 확인할 것 |
|---|---|
| 사용자는 어디서 시작하는가? | 실제 메뉴·목록·알림·공유 링크와 같은 행동의 중복 입구, 로그인 뒤 복귀 |
| 어떤 상태와 역할에서 가능한가? | 현재 권한·차단·만료·동시 변경과 사용자 안내 |
| 돈과 권리는 언제 바뀌는가? | 신청·승인·예약·지급·환불·회수의 실제 단계와 원천 |
| 실패했거나 결과를 모르면 어떻게 하는가? | 중복 요청, 상태 재조회, 재시도 조건, 화면 복귀 후 반영 |
| 어떤 정보와 알림이 전달되는가? | 수신자·동의·열람 범위·중지·보존과 실제 전달 여부 |
| 운영 또는 제품 결정이 필요한가? | 기존 정책, 구체적 변경 질문, 책임과 승인 근거. 법적 적합성을 소스 확인만으로 단정하지 않음 |

요청 값·권한·상태·중복·복귀는 관련 소스와 조건을 검증하는 시험·로그로 판단한다. 배치·잘림·대비·이미지 표시 문제가 있을 때만 해당 화면의 시각 근거를 확인한다. 큰 글자·작은 폭 조합은 사용자 요청이나 그 환경의 보고된 결함이 있을 때 다룬다. 문서만 고쳤다면 내용·링크·파생 문서 일치를 확인하고 제품 실행 결과로 기록하지 않는다.

## 산출물과 완료 조건

- **대조한 PRD:** 실제로 확인한 범위와 기준 버전, 수정한 내용, 남은 차이·위험을 기록한다.
- **수용 기준:** 시작 조건 → 조작 → 관찰 결과를 적고 실제 실행 여부·환경·결과를 구분한다.
- **결정과 후속 작업:** 미결정 질문은 [결정 등록부](decision_register.md), 현재 실행은 [앞으로 할 일](../../../docs/plan/NEXT_WORK.md)에 연결한다. 회의에서 승인하지 않은 범위를 확정으로 바꾸지 않는다.
- **관련 문서 반영:** 같은 설명이 있는 정책·영역 요약·QA·HTML을 대조하고, 외부 사본 전달은 [Markdown 작성 가이드](../00_prd_items/12_notion_markdown_guide.md)를 따른다.

미검토·결정 필요·실행 미검증·확인한 결함을 따로 남긴다. 회의 종료와 문서 검토 완료, 실제 제품 검증, 출시 승인은 각각의 근거로 판정한다.
