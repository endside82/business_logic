## 검토 범위와 숫자의 의미

175개 기능의 수용 조건은 해당 [기능 정본](05_feature_definitions.md)에 있다. 등록 확인 항목·상세 제목·실행 결과는 [시나리오 커버리지](../04_qa_acceptance/scenario_coverage_matrix.md)에서 구분한다. 과거 등록 1,403개·상세 제목 1,086개·불일치 49개를 현재 값으로 재사용하지 않는다.

먼저 변경한 행동과 아직 풀리지 않은 질문을 고른다. 아래 범주 중 적용할 항목과 제외 이유를 기록한다. 모든 기능에 같은 시험 수·기기·이미지·예외 범주를 강제하지 않는다. 기본·예외 시나리오의 개수만으로 완성도나 운영 부담을 판정하지 않는다.

## 공통 예외를 고르는 기준

| 범주 | 구체적인 확인 질문 |
|---|---|
| 진입과 복귀 | 메뉴·목록·알림·공유·로그인 후 복귀에서 같은 대상과 현재 상태를 보는가? |
| 빈 상태·부분 실패 | 실제 데이터 없음, 조회 실패, 일부 구역 실패를 구분하고 이전 값을 최신처럼 표시하지 않는가? |
| 권한과 관계 | 현재 계정·위임·회원·차단·공개 조건을 실행 때 다시 확인하는가? 권한 조회 실패를 권한 없음으로 확정하지 않는가? |
| 상태와 기한 | 화면을 연 뒤 마감·취소·납부·권한 변경이 일어났을 때 최신 상태를 확인하는가? |
| 입력 | 기능별 필수·범위·시간·동의·대상 원천 검사를 적용하고 거절 뒤 필요한 입력을 보존하는가? |
| 확정 실패·결과 불명 | 반영되지 않은 것이 확인된 거절과 응답만 잃은 요청을 구분하는가? 조회 실패를 새 요청 근거로 쓰지 않는가? |
| 중복·동시·부분 처리 | 같은 명령의 계약을 따르는가? 모든 API가 같은 요청 키·보존 기간·일괄 원자성을 갖는다고 가정하지 않는가? |
| 외부 결과·후속 의무 | 공급자 접수·실입금·기기 수신·저장소 소거를 구분하고 남은 반환·보존·처리를 안내하는가? |

## 가입·세션·본인 정보

- 가입 전 번호 확인과 유효한 가입 확인표·동일 이메일·계정 생성·세션 설치를 구분한다. 미확인 이메일의 로그인만으로 현재 가입 절차를 설명하지 않는다.
- 온보딩 이탈·건너뛰기를 모든 추천 불가능 상태라고 단정하지 않는다. 해당 정보가 필요한 행동의 조건을 확인한다.
- 토큰 동시 갱신·응답 유실·일시 오류·계정 전환에서 세션과 결과가 섞이지 않는지 확인한다. 소셜 연결 해제는 남은 유효 로그인 수단과 실제 후속 상태를 본다.
- 내보내기 요청·완료·만료·재발급, 삭제 예약·본인 취소·실행 전 의무·즉시 탈퇴·후속 파기를 구분한다.

[인증·온보딩](../01_domain_prds/01_인증_and_온보딩_prd.md), [프로필·설정](../01_domain_prds/13_프로필_and_설정_prd.md), [개인정보·안전 정책](../03_policy_prds/privacy_safety_policy_prd.md)을 따른다.

## 모임·클럽·회차·활동 제도

- 정원 경합, 승인 후 납부 대기, 은행 이체 신고 뒤 확인, 참석 불가 뒤 반환을 구분한다. 게스트 책임 회원과 실제 참석·체크인 자격을 함께 확인한다.
- 신청·대기열·출석·일정 동의는 다른 상태다. 기한 경과와 실제 일정 적용, 모집 마감과 활동 종료를 섞지 않는다.
- 강퇴·차단·역할 제한·소유권 이전·탈퇴는 명령별 회원/위임 조건과 남은 금전 책임에 미치는 영향을 확인한다.
- 정기모임 코스 등록·개별 회차·출석 확정·자동 종료·코스 정산을 나눈다. 취소된 회차나 이전 호스트의 남은 책임을 놓치지 않는다.
- 마일리지·사진 심사·반복 수동 적립 검토·스탬프는 제도·권한·중복·취소·정정 결과를 확인한다. 신호 저장·검토 승인·원장 반영·알림을 각각 확인한다.

[이벤트](../01_domain_prds/03_이벤트_prd.md), [클럽](../01_domain_prds/04_클럽_prd.md), [정기모임](../01_domain_prds/17_정기모임_prd.md), [마일리지](../01_domain_prds/16_마일리지_prd.md)를 따른다.

<a id="결제정산"></a>

## 돈·판매·제공자 거래

- 결제수단 등록·충전·원래 구매를 별도 요청으로 본다. 외부 응답이 없을 때 확정 실패처럼 재송금·원복을 반복하지 않는다.
- 직접 송금과 지갑 결제의 수취·확인·반환 주체를 구분한다. 정산의 작성자와 실제 수취자가 같다고 가정하지 않는다.
- 정산 취소·송금 만료·환불 승인 뒤 남은 지갑 반환·은행 직접 반환·실패 수습·미결 의무를 확인한다.
- 마켓 심사 후보와 승인 버전, 구매 당시 번들 구성, 부분 환불 대상과 남은 권리·매출을 대조한다. 현재 상품 구성으로 과거 구매를 재계산하지 않는다.
- 제공자 계약·분담·보조금·이행·정산 준비 판정·정산 확정·실제 지급·기지급 회수의 조건을 구분한다.
- 보정 전표·외부 반환 기록·원장 저장을 실제 송금이나 외부 세금 납부 성공으로 확대하지 않는다.

[결제·정산 정책](../03_policy_prds/payment_settlement_policy_prd.md), [플랜 마켓](../01_domain_prds/08_플랜_마켓_prd.md), [제공자 배정·정산](../01_domain_prds/21_제공자_배정_정산_prd.md)을 따른다.

## 관계·위치·알림·민감 자료

- 데이팅 본인확인·활성 프로필·공개 범위·현재 매칭·차단을 구분한다. DB 종료와 실시간 통지·다른 기기의 반영을 한 번에 끝난 결과로 쓰지 않는다.
- 동의·기기 위치 권한·좌표 전송·조회 자격·만료는 별도 조건이다. 공유 중지와 열람 로그 파기를 구분한다.
- 관심인 등록이 상세 열람 권한을 만들지 않으며, 공개 모임 달력과 본인 전용 가능 시간을 구분한다.
- 알림 카테고리 끄기·방해금지·항상 전달 종류·광고 동의·OS 권한을 따로 확인한다. 알림함 기록·공급자 수락은 실제 수신이 아니다.
- 파일 업로드 완료·검사 상태·열람 토큰·보존·파기를 구분한다. 증빙 참조 제거를 저장소 소거 완료로 표시하지 않는다.

[개인정보·안전](../03_policy_prds/privacy_safety_policy_prd.md), [알림](../03_policy_prds/notification_policy_prd.md), [관심인](../01_domain_prds/19_관심인_prd.md), [캘린더](../01_domain_prds/10_캘린더_prd.md)를 따른다.

## 후기·신고·제재·지원·분쟁

별점 후기와 사람 선택의 자격·기간·중복·노출 범위를 구분한다. 신고 접수를 모든 점수·경고·제재의 확정으로 읽지 않는다. 수정·삭제·숨김 뒤 본인/타인의 조회와 실제 점수 반영 조건을 대조한다.

문의·운영 이슈·분쟁·이의는 원천 ID·당사자·관할·기한·증빙 접근이 다르다. 종결 표시는 보상 완료·은행 반환·파일 파기의 완료가 아니다. 플랫폼 관리자·클럽 운영진·현재 호스트의 권한을 이름만으로 합치지 않는다.

[후기·신고](../01_domain_prds/11_리뷰_and_신고_prd.md), [권한 정책](../03_policy_prds/permission_policy_prd.md), [분쟁](../01_domain_prds/18_분쟁_해결_prd.md), [고객지원](../01_domain_prds/20_고객지원_prd.md)을 따른다.

## 확인할 증거와 남길 결과

[기획 QA 정책](../03_policy_prds/planning_qa_policy.md)의 증거 선택을 적용한다. 요청 값·권한·상태·횟수·복귀는 해당 소스와 조건을 검증하는 시험·로그로 판단한다. 배치·잘림·대비·이미지 표시 질문이 있을 때만 대표 화면의 시각 근거를 확인한다. 문서 수정은 내용·링크·파생 문서 일치로 검사하며 제품을 실행했다고 기록하지 않는다.

| 기록 | 남길 내용 |
|---|---|
| 대상과 경로 | 기능 ID, 변경한 행동, 실제 입구와 복귀 위치 |
| 조건 | 현재 계정·대상·상태·기한·공개·원천 |
| 예외와 기대 결과 | 확정 거절·결과 불명·부분 처리·재조회·남은 의무 |
| 증거 | 기준 버전·소스/기존 실행/새 실행/외부 확인의 범위 |
| 판정 | 확인한 결함, 위험, 결정 필요, 실행 미검증, 아직 내용 미판정의 구분 |

[공통 수용 기준](11_qa_acceptance_criteria.md)과 각 기능 PRD에 연결하고, 적용하지 않은 범주와 이유도 남긴다.
