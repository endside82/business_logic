## 영역 사이에서 구분할 책임

| 연결되는 업무 | 합치지 말아야 할 것 |
|---|---|
| 이벤트·정기모임·클럽 | 클럽 회원, 코스 등록, 회차 신청·실제 참석. 모임 분류만으로 같은 권한을 부여하지 않음 |
| 모임 정산·제공자 정산·지갑 | 비용 분담, 서비스 계약·수익, 실제 돈의 실행. 정산 확정과 지급·반환을 별도 판단 |
| 활동 제도·재정 | 마일리지·스탬프와 무료 포인트·클럽 기금. 자동 환산이나 기금 유입을 가정하지 않음 |
| 후기·신고·경고·분쟁 | 평가·선택, 접수, 제재, 사건·이의·보상. 통합 분쟁을 원천 조회만 하는 계층으로 축소하지 않음 |
| 문의·운영 이슈 | 일반/이벤트/클럽 문의와 원천별 운영 문제의 자격·처리자·대화. 같은 출처 이름만으로 같은 권한을 부여하지 않음 |
| 관심인·달력·공개 설정 | 단방향 관심 목록, 공개 모임 집계, 본인 전용 가능 시간. 등록이 열람 권한을 만들지 않음 |
| 알림·위치·개인정보 | 기록·발송·실수신, 동의·좌표·열람 기록·파기. 서로 다른 완료 시점을 유지 |

## 기획 검토 원칙

한 기능의 실제 입구 → 행동 → 현재 상태·권한 → 결과·실패 복구 → 원래 화면 복귀를 확인한다. 여러 영역을 지나면 각 원천과 책임자를 명시한다. 넓은 관계도를 실제 API 의존·돈 이동·데이터 공유의 증거로 쓰지 않는다.

[상태 정책](../03_policy_prds/state_policy_prd.md), [권한 정책](../03_policy_prds/permission_policy_prd.md), [대표 사용자 여정](06_user_journeys.md)을 함께 대조한다. 정책 변경은 승인된 결정과 현재 구현의 차이를 기록하고, 단순 분류 수정으로 공개 범위나 새 기능을 확정하지 않는다.
