## 별점 후기와 선택형 피드백의 구분

별점 후기는 일반 이벤트의 ATTENDING 또는 고정 회차의 실제 체크인을 확인하고 endTime 뒤 7일 안에 현재 호스트에게 한 번 작성한다. 삭제도 작성 이력으로 남으며 수정은 작성자 최대 5회다. 수정·삭제의 목록 복귀와 관련 집계 갱신, 응답 유실 시 불확실성을 구분한다. 작성 화면에는 현재 초안 복원·제출 준비·완료 연결이 있다.

함께할 사람 선택은 별도 원본이고 closedAt 뒤 7일을 기준으로 한다. 체크인 우선·참석 fallback·노쇼/계정/차단 제외 후 후보 2명 이상과 표시 순서를 검사한다. 선택 0명은 가능하고 선택 상한·긍정 인상 태그·분위기 태그 최대3개를 적용한다. 같은 clientRequestId는 기존 결과를 반환하고 다른 키는 중복 거절한다. 이 멱등 계약을 별점 후기의 POST/PATCH에도 적용되는 것으로 설명하지 않는다.

## 조회·숨김·호스트 처리 권한

이벤트 후기 목록은 차단 작성자를 필터하고 사용자별 목록은 그 사용자가 받은 후기를 반환하며 프로필 상세 접근을 검사한다. 제목이 「내 후기」여도 내가 쓴 후기 전체의 목록은 아니다. 반환된 활성·미삭제 목록으로 앱 평균·개수를 계산하고 「최신순」 문구를 정렬 선택 기능으로 세지 않는다.

임시 숨김은 행과 별점을 삭제하지 않는다. 서버는 일반 조회자의 본문과 비호스트의 사유 글을 가리고, 앱 카드에서는 숨김 안내를 표시한다. 앱 호스트 메뉴의 revieweeId, 답변 작성·숨김의 현재 이벤트 호스트, 답변 수정의 저장된 답변 호스트는 서로 다른 권한 원천이다. 호스트가 바뀐 상황에서도 동일 인물이라고 가정하지 않는다.

답변은 한 개이며 24시간 경계 안에 수정한다. 앱은 수정 직전 GET으로 현재 본문·권한을 확인한다. 임시 숨김의 운영팀 검토 요청 기본값은 앱·서버 모두 false다. 허위 후기 선택으로 켜져도 사용자가 해제할 수 있고, 종결 신고만 있으면 숨김 성공과 검토 미접수를 나눠 알린다. 해제는 기존 신고 철회나 회수된 마일리지 재적립이 아니다.

모임 후기와 받은 후기 목록은 조회자와 양방향 차단 관계인 작성자를 제외하고, 차단된 주최자의 답변도 붙이지 않는다. 커뮤니티·데이트 차단을 함께 적용한다. 앱이 반환된 목록으로 계산하는 평균·개수와 서버의 모임 결과 카드 집계는 다르며, 서버의 후기 수·평균을 조회자마다 다시 세지는 않는다.

## 신고 접수와 담당자의 후속 처리

현재 신고 Enum은 15종이다. 이동수단·이벤트 사진의 전용 접수, 앨범 출시 범위, 데이트 프로필 사진의 추가 자격을 구분한다. 신고자·당사자·원래 대상과 context/source 관계는 서버가 해석하며 요청 값으로 임의 관할이나 중복 기준을 정하지 않는다.

범위는 클럽 내부·플랫폼 정책·사적 이해관계이고 관할은 실제 출처와 담당자 이해충돌에 따라 이벤트 호스트·클럽 운영진·플랫폼으로 정한다. 접수는 PENDING이며 최초 플랫폼 배정의 이관 사유/시각을 상태 ESCALATED와 혼동하지 않는다. 주간 기존5건 뒤 접수와 월간 서로 다른3명 조건은 우선 검토다. 데이트 사진 유효 신고자5명에 따른 사진 숨김·승인사진3장 미만 프로필 비활성은 별도 추가 효과다.

본인 신고 목록·상세는 현재 앱에 연결돼 있고 처리 결과·증빙·시각과 해당 신고 문의 입구를 제공한다. 담당자의 실제 검토·경고·제재와 신고자 알림 수신은 접수 성공과 별도로 확인해야 한다. 여기의 접수 문서 갱신을 다른 영역의 운영 처리 전체 검수 완료로 합산하지 않는다.

## 신뢰점수와 취향 원본의 구분

신뢰점수 GET은 활동·인증·감점과 저장된 수동 조정을 현재 계산해 반환하며, 영속 재계산은 별도다. 마지막 저장 점수·스냅샷과 현재 조회가 항상 같지 않을 수 있다. 활동0.5·인증0.25·감점0.25의 실제 원천, 수동 조정 유지, 후기 평균의 별도 정보 성격을 기능 기준 문서에서 관리한다. 현재 기본 계산기 상수로 수동 조정 없이 도달 가능한 상한67.5와 등급90 기준도 구분한다. 이력은 본인만 조회하고 마지막 스냅샷 대비1점 이상 변화 또는 최초에 남긴다.

취향의 긍정 태그 누적은 본인이 다른 사람에게 준 이벤트 선택 피드백에서 만든다. 받은 평가가 아니다. 선언 선호는 세 항목을 덮어쓰며 null은 초기화다. 앱은 저장 실패 때 이전 프로필과 시트 선택을 유지한다. 행동 근사는 별도 참석 원천으로 저장·내보내지만 현재 프로필 API나 레이더에는 없다. 본인 분위기 태그 내보내기는 현재 포함돼 있다.

데이팅의 내부 신뢰점수·태그 활용은 양쪽 communityDataOptIn이 있을 때만 계산하고, 미동의에는 해당 성분을 빼고 남은 가중치로 정규화한다. 이 동의와 커뮤니티의 타인 프로필 상세 접근은 독립된 검사다.

## 남은 제품 경계와 문서 검증 범위

기능 문서에 기록한 현재 한계는 정렬 문구·실제 정렬 보장 차이, 호스트 권한 원천 차이, 기타 신고 설명의 앱 전용 최소 검증, 일반 INVALID_INPUT의 본인 신고 오안내, 태그 누적의 퍼센트 표시, 행동 근사 API 미노출, 피드백 후 관련 화면 갱신, 신뢰점수 수동 조정 표시 등이다. 문서에서 발견했다고 제품 코드까지 수정·시험한 것으로 기록하지 않는다.

검토된 기능 PRD의 해시와 해당 소스 근거를 재사용해 이 PRD·로컬 개요·HTML을 맞췄다. 링크·앵커·파생 해시·서버 주소 참조·시나리오 집계를 검사하고, 수정/삭제와 신고의 과거 E2E 기록은 인용으로 보존한다. 이번에 앱 화면 검수나 제품 시험을 새로 실행하지 않았다. 전체 완료 여부는 [문서 최신화 추적 자료](../../verification/document-refresh-2026-11-22.json)를 따른다.
