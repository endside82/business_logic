## 설정·원장·등급의 현재 규칙

설정 조회는 기존 행을 요구하며 누락은 무결성 오류다. 새 클럽용 기본값은 NOT_STARTED/365일/BALANCE/시즌 꺼짐이다. 최초 활성화에 없는 기본 적립 규칙만 보충한다. NOT_STARTED → ACTIVE, ACTIVE ↔ PAUSED만 허용하고 실제 상태 전이는 재인증한다.

새 적립·차감·호스트 제출/승인은 ACTIVE를 확인한다. 반려·수동 정정·기존 조회·만료는 같은 조건으로 일괄 차단하지 않는다. 만료 기간은 새 적립에 적용하고 기존 만료를 중지/재개로 미루지 않는다.

EARN은 잔액과 누적을 늘리고 REDEEM은 만료 임박 적립부터 소비 관계를 만든다. EARN 정정은 이미 만료된 양을 제외해 회수하고 원시/등급 누적은 원래 적립액만큼 감소한다. REDEEM 정정은 사용을 복원한다. EXPIRE는 잔여 잔액을 없애며 등급 누적을 감소시키지 않는다. 과거 ‘REVERSE/EXPIRE 모두 등급 누적 차감’ 설명은 현재 구현과 다르다.

등급 정의 생성/삭제/기준 변경은 재계산을 예약하고 저장 성공과 전체 회원 재계산 완료는 분리한다. 규칙 POST는 트리거 중복을 거절한다. 등급 오류는 개수·이름·금지어·기준 중복·사용 중 삭제 등으로 나뉜다. 배지 정의/차감 사유/시즌 생성 키와 실제 배지 부여 명령의 키 계약도 다르다.

## 조회와 공개 정보의 경계

본인 원장과 배지의 운영자 식별 필드는 가린다. 메인 최근 원장은 DB 5건, 원장은 페이지 조회다. 월간 순증은 REVERSE를 제외하지만 월초/말 잔액은 포함한다. 과거 월 등급은 EARN 합과 현재 정의로 재구성하고 배지는 현재 활성 상태의 영향을 받는다.

회원 랭킹 화면은 BALANCE를 명시해 시작한다. 서버 미지정 기본값이 정책 기준이라는 사실과 다르다. 현재 랭킹에는 회원 상태/차단 제외 조건이 없고 동점도 개별 순번을 갖는다. 별도 프로필 카드 API는 차단/점수 가림을 적용하지만 현재 화면 소비자가 확인되지 않는다.

종료 시즌 순위는 적립 기준만 사용하며 동점은 공동 순위다. 양수 적립과 확정 순위가 있는 기록만 공개하고 앱은 상위 첫 20건과 별도 본인 기록을 보여 준다. 회원 랭킹과 시즌 확정 순위의 계산·페이지 지원을 구분한다.

## 실패·복구·운영 결과

시즌은 SCHEDULED → ACTIVE(집계 준비) → CLOSING → CLOSED로 이어진다. 회원별 기록과 순위 확인이 끝나기 전에 완료로 바꾸지 않는다. 준비/마감 재시도와 자동 후속 처리가 있고 다음 시즌도 시작 시각·다른 시즌 상태 조건을 만족해야 활성화된다.

점수 일괄 명령은 회원별 부분 성공이다. 같은 본문 재시도의 키를 유지한다. 즉시 결과와 서버 재조회는 다르며 재조회의 실패 감사/배지 결과 복원에는 제한이 있다. 모든 운영 명령을 같은 멱등·전체 원자 처리로 설명하지 않는다.

검토 대기열은 4종이고 일반 처리는 IGNORE만 받는다. 반복 수동 적립 NORMAL/FRAUD, 자동 회수 재시도, 원장 변경 없는 종결은 별도 명령이다. FRAUD가 PROCESSED여도 잔액 부족 원장은 회수 검토로 남을 수 있다.

호스트는 본인 제안 상태를 볼 수 있다. 승인은 최종 적립액/원장 연결과 별도 적립 트랜잭션을 가지며 현재 화면에는 조정 점수 입력과 처리 사유 표시가 없다. 결과 outbox와 알림 이동 경로는 존재하지만 실제 푸시 전달을 이번 문서 대조로 증명하지 않는다.

## 해결된 과거 설명과 남은 제한

현재 대시보드·회원 상세·일괄 결과·설정 미리보기는 전용 응답 모델로 연결된다. 최근 원장·대시보드 집계·만료 후보는 과거의 전체 원장 findAll 방식과 다르다. 자동 적립 신호의 호출 경로도 있다. 해결된 과거 진단을 현재 미구현 항목으로 계속 남기지 않는다.

남은 차이는 상세 원장 첫 50건과 미표시 감사/열린 검토 항목, 전역 outbox 수치, 월 영수증 산식/과거 상태 복원, 랭킹 기본값/공개 범위, 시즌 첫 20건, 배지 부여 중복 요청 계약, FEFO 미배정 경고, 일괄 실패 내역 재조회와 호스트 승인 화면 범위다. 각각의 정본 PRD에서 조건과 증거 범위를 확인한다.

이 영역에는 기존 로컬 units 폴더가 없어 새로 만들지 않는다. HTML과 목록은 기능 PRD에서 맞추고 실제 API 함수/주소·내부 링크·소스 지문을 검사한다. 이번 작업은 문서와 문서 검사기 수정이며 제품 코드·브라우저·실기기 시험 결과로 확대하지 않는다.
