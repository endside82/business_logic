# 릴리즈 준비와 증거 확인

<!-- release-document: reference -->
> 2026-11-22 문서 대조. 공개 범위별로 적용할 확인 기준이며, 아래 항목을 이번 작업에서 실행하거나 통과했다는 뜻이 아니다. 현재 작업·보류 결정은 [앞으로 할 일](../../../docs/plan/NEXT_WORK.md), 마지막 배포·실행 기록은 [다른 세션이 이어받을 출시 상태](../../../docs/release-gate/LAUNCH_COMPLETION_OVERVIEW.md#다른-세션이-이어받을-출시-상태)를 따른다.

## 현재 기록을 읽는 방법

Android 내부 테스트 배포, iOS 서명 IPA 생성, 스토어 업로드·처리·설치·정식 공개를 따로 기록한다. 기존 설정과 산출물은 [앱 배포 준비와 남은 확인](../../../community_app/docs/DEPLOYMENT_CHECKLIST.md)에서 확인한다. 내부 트랙 배포나 소스 병합을 첫 공개 출시 완료로 읽지 않는다.

최신 프로그램 소스와 현재 운영 서버·설치 앱이 같다고 가정하지 않는다. 새 API를 먼저 배포해야 하는 앱 변경은 [현재 출시 준비](../../../docs/plan/NEXT_WORK.md#첫-출시에서-확인할-것)의 배포 차례를 따른다. 임시 결제 기록을 실제 돈의 승인·송금·반환 증거로 쓰지 않는다. 실제 공개 판정과 후보 고정·복구 규약의 기존 보류 결정도 해당 정본을 따른다.

이전 체크리스트의 53개 시나리오 완료나 날짜별 시험 건수는 현재 후보의 통과율이 아니다. [현재 앱 시나리오 검사 기록](../../../community_app/docs/testing/SCENARIO_TEST_STATUS_CURRENT.md)은 실행 범위·버전·미실행을 구분해 읽고, 문서 등록 개수는 [시나리오 커버리지](scenario_coverage_matrix.md)에서 별도로 확인한다.

<a id="1-기능-범위"></a>

## 기능 범위와 후보

- 175개 기능 인벤토리 중 이번 공개에 포함·제외할 기능과 이유를 정한다. 공개 API·실시간의 설정, 앱 메뉴·직접 주소·알림·공유 입구가 같은 범위를 적용하는지 확인한다.
- 서버·앱·관리자·소개 웹의 버전, 환경·기기·설치 경로를 한 후보에 연결한다. 다른 버전의 통과 결과를 자동 승계하지 않는다.
- 기존 키·프로파일·외부 설정을 먼저 확인한다. 코드·빌드·업로드·설치·외부 연동·공개 판단을 각각 기록한다.

<a id="2-사용자-흐름"></a>

## 사용자 흐름과 복귀

- 가입 번호 확인·계정 생성·세션 설치·선택형 온보딩, 홈·검색·메뉴·알림·공유에서 대상 도착과 복귀를 확인한다.
- 공개 대상인 모임 신청·클럽 가입·회차 등록·구매·데이트·제공자 업무의 실제 역할과 상태를 고른다. 제외 기능의 검사를 이번 공개의 필수 통과로 추가하지 않는다.
- 게스트 책임 회원과 참석 행, 출석·노쇼·반환을 구분한다. 투표·사진 심사·마일리지·스탬프는 공개 범위의 권한·결과를 확인한다.

<a id="3-상태와-권한"></a>

## 상태·권한·복구

- 계정 전환·권한 회수·취소·만료·삭제·차단 이후 현재 상태와 허용 행동을 다시 확인한다.
- 조회 실패와 권한 없음, 확정 거절과 결과 불명, 부분 성공과 전체 성공을 구분한다. 중복 클릭·재시작·동시 변경은 해당 명령의 실제 계약으로 검사한다.
- 진입점별 권한과 뒤로가기·입력 복구가 같은 원천을 가리키는지 확인한다. 모든 기능에 같은 기기 수·시나리오 수를 강제하지 않는다.

<a id="4-돈과-알림"></a>

<a id="5-개인정보와-안전"></a>

## 돈·알림·위치·안전

- 결제·입금 신고·수취 확인·환불 승인·실제 반환·정산 생성·실지급을 구분한다. 잔액·거래·원천 상태와 미결 의무가 맞아야 한다.
- 정산 초안 미리보기의 허용 정보와 실제 청구·납부·이의 조건은 각 기능 PRD를 따른다. 모든 알림을 같은 화면으로 연결한다고 가정하지 않는다.
- 알림 의도 저장·전송·기기 수신·탭 이동, 카테고리와 방해금지·OS 권한을 구분한다.
- 위치 동의·철회·만료·열람 권한·좌표 갱신을 확인한다. 지도 키 설정을 실제 지도·GPS 성공으로 쓰지 않는다.
- 차단·신고·제재의 DB 상태와 실시간 접근 회수, 내보내기 범위·탈퇴 의무·자료 보존·후속 삭제를 각각 확인한다.

## 공개 판정에 남길 결과

| 항목 | 기록할 내용 |
|---|---|
| 범위 | 기능·역할·대상 상태·입구·외부 연동과 제외 이유 |
| 후보 | 각 제품 버전·환경·설정·배포 산출물·설치 경로 |
| 근거 | 소스 대조·자동 검사·기기 이용·외부 결과·복구 실행을 구분한 위치와 날짜 |
| 결과 | 통과·실패·미실행·결정 대기 및 남은 위험·의무 |
| 판단 | 해당 범위의 공개 여부와 담당 판단; 내부 테스트·부분 공개와 전체 완료 구분 |

무단 정보 노출·권한 우회, 중복 과금·반환 누락, 결과 불명을 성공/실패로 잘못 확정하는 흐름, 탈퇴·차단 뒤의 허용되지 않은 접근은 공개 범위에 미치는 영향을 판정한다. 미실행이나 간접 증거만 있는 항목을 통과로 바꾸지 않는다.

[예외와 경계 사례](../00_prd_items/09_exceptions_edge_cases.md)의 질문에 맞는 증거를 고른다. 배치·잘림·대비처럼 시각적으로 판단할 질문이 있을 때만 화면 이미지를 확인한다. 요청 값·권한·저장 상태·반환 횟수는 해당 소스와 실행 결과로 판단한다.
