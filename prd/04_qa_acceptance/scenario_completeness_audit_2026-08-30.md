# 기능별 시나리오 정의와 검증 근거

<!-- release-document: reference -->
> 2026-11-22 현재 문서·생성 데이터를 대조했다. 파일명의 2026-08-30은 최초 감사의 식별자로 유지한다. 이번 갱신은 문서와 연결 근거의 검토이며 새 제품 실행·실기기·출시 완료 기록이 아니다.

## 핵심 결론

175개 기능 정본의 수용 조건과 별도 상세 시나리오 문서를 구분한다. 현재 상세 `units` 문서는 117개 기능에 있고 제목은 1,276개다. 별도 상세 문서가 없는 58개 기능도 해당 PRD의 수용 조건을 읽는다. 등록 확인 항목 1,654개와 상세 제목 1,276개는 같은 집계가 아니며 둘 다 테스트 통과 수·통과율 분모가 아니다.

[시나리오 커버리지의 집계 기준](scenario_coverage_matrix.md)과 [기능별 검색·연결 표](../../docs/qa/scenario-completeness.html)를 따른다. 과거 49개 불일치, 19개 문제 기능, 59개 자동 테스트 연결 같은 수를 현재 값으로 재사용하지 않는다. 새 소스와 문서로 다시 계산한 데이터가 현재 연결 수의 근거다.

## 출시 상태와 시나리오 근거는 별개다

| 구분 | 확인하는 내용 | 여기서 증명하지 않는 것 |
|---|---|---|
| 기능 정본·상세 정의 | 기능의 행동·권한·상태·실패 조건과 수용 기준 | 코드 구현·검사 통과 |
| 코드 위치 | 대상 파일·함수·HTTP 방식·전체 주소와 실제 선언 일치 | 함수 내부 계약 전체·실행 결과 |
| 테스트 파일 연결 | 문서가 특정 자동 테스트·통합 실행 파일을 지목 | 모든 기대 결과의 단언·현재 실행 통과 |
| 테스트 안의 기능 번호 | 기존 관련 파일을 찾을 후보 | 같은 기능을 검증한다는 확정 |
| 기록된 로컬 실행 분류 | 기존 상태표에 남은 로컬 서버·신규 계정 검사 분류 | 새 후보·휴대전화·운영 외부 서비스 성공 |
| 출시 판단 | 공개 범위·후보·설정·실제 이용·외부 결과·복구 근거 | 내부 테스트나 소스 병합만으로 전체 공개 완료 |

기능 정본, 자동 테스트 파일, 사용자 여정 기록을 세 칸으로 더해 완성도 백분율로 만들지 않는다. 파일 연결률도 구현률이나 제품 통과율이 아니다. 과거 상태표의 기본 자동 검사 분류를 개별 기능의 최신 통과 증거로 승격하지 않는다.

## 변경에 맞는 검토 순서

1. [현재 남은 작업](../../../docs/plan/NEXT_WORK.md)에서 실제 변경·결함·실행 미검증·사용자 결정 대기를 구분한다. 오래된 감사의 우선순위·문제 수를 현재 작업 목록으로 복제하지 않는다.
2. 해당 기능 정본과 현재 서버·앱의 실제 입구·상태·권한을 확인한다. 철회된 기능은 유지할 차단 경계로 다루며 구현 복구 대상으로 올리지 않는다.
3. 기존 소스 대조·테스트 단언·실행 기록을 먼저 찾는다. 문서에 파일 링크가 없다는 사실만으로 테스트를 새로 만들거나 제품을 다시 실행하지 않는다.
4. 변경이 기존 근거를 무효화하는 부분과 남은 질문을 정한다. 필요한 단언·통합 여정·외부 확인을 그 범위에 한정한다. 결과값·권한·저장 상태를 판단할 때 화면 이미지를 의무로 추가하지 않는다.
5. 실제 실행을 했다면 버전·환경·조건·기대 결과·관측 결과·근거 위치를 남긴다. 이번 문서 대조와 기존 실행을 새 실행 통과로 쓰지 않는다.

## 근거 기록과 판정

하나의 기능 아래 여러 시나리오와 단언이 연결될 수 있다. 기능 번호나 파일 존재만으로 분기별 통과를 계산하지 않는다. 정상·권한·상태 변화·입력·실패/복구·중복/동시성 중 적용할 범주와 제외 이유를 적는다.

필요한 기록은 기능과 시나리오 식별자, 기대 결과, 코드·테스트의 확인 범위, 최근 실행의 버전·환경·결과, 남은 결정·위험이다. 실행하지 않은 것은 미실행으로 유지한다. [릴리즈 준비와 증거 확인](release_readiness_checklist.md)에서 공개 판단과 연결한다.

## 재생성과 문서 검사

작업공간 루트에서 문서 입력이 바뀌었을 때 실행한다. 제품 앱·API·외부 서비스를 실행하는 명령은 아니다.

```bash
node business_logic/verification/build_scenario_audit_data.mjs --write
node business_logic/verification/build_scenario_audit_data.mjs --check
node business_logic/verification/sync_source_reference_docs.mjs --check
node business_logic/verification/check_scenario_audit.mjs
```

코드 위치 표를 실제로 갱신해야 할 때만 `sync_source_reference_docs.mjs --write`로 재생성하고 다시 검사한다. 생성기는 현재 등록된 파일·처리 함수·HTTP 방식·전체 주소를 대조한다. 함수나 주소가 달라졌으면 가까운 다른 API로 대신 연결하지 않는다.

로컬 전용 `units` 자료가 있으면 검사에 사용하지만 공개 웹 링크로 노출하지 않는다. 독자는 저장소에 포함된 기능 PRD로 이동한다. 서버 코드 링크는 확인한 커밋에 고정하며 해당 소스의 미커밋 변경이 있으면 링크를 만들지 않는다. 웹 페이지는 행·이름·검색·필터·철회 구분·연결 대상을 문서 데이터로 검사한다.
