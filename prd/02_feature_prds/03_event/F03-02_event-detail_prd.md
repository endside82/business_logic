# F03-02. 이벤트 상세 조회 PRD

<!-- release-document: reference -->
> **문서 구분: 현재 기능 설명.** 2026-11-22 서버·앱 소스를 대조했다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 소스 대조를 실제 앱·외부 결제·기기 캘린더 검수 완료로 보지 않는다.

## 결론

이벤트 상세는 카드·검색·알림·공유 링크·내 이벤트에서 들어와 정보를 확인하고, 본인의 신청·참석·결제 상태에 맞는 다음 행동을 고르는 화면이다. 서버의 열람 권한과 행동별 허용 여부가 기준이다. 초안·공개·종료·취소의 네 상태와 공개 범위·운영자 숨김은 서로 다른 조건이다.

초안은 하단의 **수정·공개**, 더보기 맨 아래의 **삭제**로 나눈다. 공개 후 수정은 상세의 관리 구역에 있고, 공유는 상단의 한 입구에서 연다. 종료·취소에는 삭제 버튼을 두지 않는다. 취소 상세의 일반 본문은 차단하되 정산·환불과 대화 입구를 권한에 따라 유지한다.

과거 문서의 초안 삭제 누락, 종료 상태의 삭제 노출, 공동호스트·비공개 모임의 다음 회차 누락, 결제 기한 뒤 배치까지 결제 허용이라는 설명은 현재 소스와 달라 정정했다.

## 전체 동작 흐름

1. 이벤트 카드나 목록·알림·공유 경로에서 상세로 들어온다. 로그인·공개 범위 관문을 통과해야 하며 링크로 들어왔다는 이유로 권한을 얻지 않는다. 링크 전용 상세는 보관한 공유 토큰을 함께 조회한다.
2. 서버가 초안·공개 범위·취소·숨김·클럽 소속을 판정한다. 허용하지 않는 상세는 없는 이벤트로 응답한다. 로딩·조회 실패·권한 상실을 빈 정상 화면으로 대신하지 않는다.
3. 허용된 상세는 제목·일정·장소·가격·신청 상태·호스트·설명·사진과 필요한 업무 입구를 표시한다. 관리 구역은 허용한 행동을 모으며 모든 호스트·공동호스트·운영진에게 같은 버튼을 일괄 제공하지 않는다.
4. 비로그인 상태에서 참석 행동을 하면 로그인으로 이동하고 돌아올 상세 주소를 남긴다. 신청 심사 중이면 검토 중을 표시하고, 참석·대기·결제 대기·결제 만료에 맞는 행동으로 바뀐다.
5. 승인 후 결제는 결제 수단과 공개 범위를 판정한다. 지갑 결제는 명령 식별자를 유지해 실행하고, 계좌이체·혼합 방식은 해당 납부 화면으로 이동한다. 정책 꺼짐·제공하지 않는 수단·불명확한 응답은 이유를 안내한다.
6. 지갑 결제 결과가 납부 완료이면 앱의 참석 표시를 먼저 반영하고 상세와 관련 자료를 다시 읽는다. 응답 유실·처리 결과 불명은 관련 자료를 재조회하며, 실패 토스트만으로 미결제라고 단정하지 않는다. 잔액 부족·자동충전 결과 대기·상태 변경은 서로 다른 안내로 처리한다.
7. 수정·신청 관리·정산·사진·투표 등 다른 업무를 열 때도 해당 업무의 권한을 따른다. 돌아오면 관련 자료의 변경 신호로 상세를 다시 읽는다. 권한이 없어졌으면 예전 본문과 행동을 계속 사용할 수 없다.
8. 초안 삭제는 더보기 → 삭제 → 확인 순서다. 취소하면 요청하지 않는다. 성공하면 관련 목록을 갱신하고 원래 화면으로 돌아가며, 실패하면 상세에 남아 오류를 안내한다. 결과를 알 수 없는 실패도 관련 자료를 다시 읽는다.
9. 다음 회차 만들기는 허용된 원본에서 실행한다. 제공자 기능이 열렸으면 배정만 이어갈지 묻고, 성공하면 새 초안 편집으로 이동한다. 진행 중 중복 명령을 제한하고 응답 전에 화면·계정이 바뀌면 이전 작업이 새 화면을 강제로 열지 않도록 확인한다.
10. 캘린더 내보내기는 파일을 받아 시스템 공유창을 연다. 기기 캘린더 추가는 별도 행동이다. 일정 결정 전에는 둘 다 숨기고 서버도 내보내기를 거절한다. 외부 앱에서 저장을 마쳤는지는 앱 내부 요청 성공과 구분한다.

| 종료 모임의 열람 허용 사용자 | 정상 본문과 종료 표시, 자격 있는 후속 업무 | 삭제나 다시 공개하는 행동은 없음 |
| 클럽 운영진·권한을 위임받은 사람 | 서버가 허용한 출석·명단·공지·환불·정산 관련 업무 | 역할 이름만으로 수정·생명주기 변경·모든 운영 권한을 부여하지 않음 |

### 운영 권한과 다음 회차

수정·신청 관리는 호스트와 유효한 공동호스트가 맡는다. 출석·공지·환불·분쟁 등은 위임한 개별 권한과 정지 여부에 따라 달라진다. 정원 관리는 서버가 계산한 허용 여부를 따른다. 일반 클럽 회원이라는 이유만으로 운영이나 사진 열람을 허용하지 않는다.

다음 회차는 독립·비공개 유형의 호스트·유효한 공동호스트에게 열리고, 클럽 모임·정기모임 회차·취소·운영자 숨김은 제외한다. 새 호스트는 원본 호스트다. 새 시작을 주지 않으면 원본 시작에 7일을 더하며 결과가 과거이면 서버가 거절한다. 참가자·결제·정산·후기·활동 사진을 이전 회차에서 가져오지 않는다. 제공자 배정 이어가기도 돈·정산 복사를 뜻하지 않는다.

### 승인 후 결제

현재 서버는 이벤트·신청을 잠근 뒤 결제 기한을 직접 검사한다. 기한이 지났으면 납부를 거절하고 신청의 만료 상태 전환은 배치가 맡는다. 따라서 만료 배치가 아직 실행되지 않았어도 계속 납부할 수 있다는 과거 설명은 적용되지 않는다. 기한이 없는 옛 신청과 경계 시각의 구체적인 판정은 서버 정책 함수가 정본이다.

화면의 결제 대기 카운트는 신청 건수다. 서버의 좌석 확보는 동반 인원과 추가 입금 대기 좌석까지 반영하므로 같은 값으로 보지 않는다. 실제 납부·정원 확정·환불의 상세 계약은 [이벤트 선입금](F03-13_event-prepayment_prd.md)에서 관리한다.

## 설명과 사진

상세 설명과 첨부 사진은 같은 열람 조건을 따른다. 대표 이미지·설명 첨부 사진·행사 후 활동 사진첩은 용도가 다르다. 활동 사진첩 입구는 서버의 사진 열람 허용값과 초안 여부를 확인한다. 사진이 있다는 이유로 클럽 상세나 다른 사람의 권한을 우회하지 않는다. 사진 업무의 상세 조건은 [이벤트 사진첩](F03-09_event-photos_prd.md)을 따른다.

## 호스트와 개인화 정보

호스트 카드는 서버가 프로필 열람을 허용했을 때 이동·신뢰점수·재방문 배지를 제공한다. 로딩·실패·열람 거절 때 이름을 남기고, 제한 응답의 0을 실제 신뢰점수 0으로 표시하지 않는다. 차단·프로필 비공개·계정 이용 불가도 카드 권한에 영향을 준다.

‘나와의 핏’은 개인별 명단·원점수를 공개하는 기능이 아니다. 현재 규칙은 다음과 같다.

- 출석 근거는 체크인이 있으면 체크인 회원, 없으면 참석자에서 확정·소명 중 노쇼를 뺀 회원이다.
- 아는 사람·비슷한 성향의 개인화 계산은 호스트·공동호스트·차단 관계를 제외한 후보를 사용한다. 아는 사람·비슷한 성향 신호는 호스트·공동호스트·참석 행이 있는 사람에게만 보낸다.
- 아는 사람과 비슷한 성향의 수는 ‘소수(1~2)’·‘여럿(3 이상)’ 구간으로 표시한다. 비슷한 성향은 최신 제출 점수의 공통 축 4개 이상·평균 차이 20 이하이며 점수가 있는 후보 5명 미만이면 신호를 내지 않는다.
- 단골·초면 비율은 모수 5명 이상이고 0이 아닌 집단이 각각 5명 이상일 때 10% 단위로 제공한다.
- 성향 분포는 별도의 출석 근거 명단을 사용한다. 공개·공개 중/종료·숨기지 않은 모임이거나 명단 열람 자격이 있어야 하며, 축별 모수와 0이 아닌 구간마다 최소 5명을 요구한다. 점수 구간은 낮음 0~33, 보통 34~66, 높음 67~100이다.
- 재방문 배지는 종료된 주최 모임 3개 이상, 출석 근거 회원 15명 이상, 그중 2회 이상 방문한 비율 30% 이상일 때 판정한다. 원인원·원비율을 카드에 표시하지 않는다.
- 신호가 없거나 요청이 실패하면 핏 영역을 숨긴다. 영역이 없다는 사실만으로 아는 사람이 0명이라고 추정할 수 없다.

## 수용 기준과 검증 근거

- **AC-01 카드 진입과 복귀:** 카드·검색·내 이벤트에서 상세를 열고 돌아오면 출발 목록과 선택 상태가 유지된다. 상세 권한이 사라지면 오류·제한을 표시한다.
- **AC-02 초안 권한:** 다른 사람이 초안 주소를 직접 호출해도 본문을 받지 못한다. 호스트·유효한 공동호스트의 정상 입구는 열리고 위임 정지도 반영한다.
- **AC-03 삭제 확인과 결과:** 초안 더보기에서 삭제를 취소하면 요청하지 않는다. 확인 후 성공하면 같은 주최 목록·탭으로 돌아와 해당 항목이 사라지고, 실패·돈 연결 제한은 오류를 안내한다.
- **AC-04 공개·종료·취소:** 초안 하단은 수정·공개, 공개 뒤 수정은 관리 구역에 한 번만 나타난다. 종료·취소 삭제는 없고 취소 후 허용된 정산·환불/대화 경로는 남는다.
- **AC-05 클럽·공유 권한:** 클럽 비회원의 상세 직접 조회를 차단한다. 링크 전용 모임은 필요한 토큰을 확인하며 토큰으로 초안·숨김·취소 권한을 우회하지 않는다.
- **AC-06 결제 수단과 기한:** 지갑 결제·계좌이체 이동·정책 제한을 구분하고 기한 뒤에는 배치 상태와 무관하게 서버가 새 납부를 거절한다.
- **AC-07 납부 결과 복구:** 완료 결과 뒤 상세·목록을 다시 읽는다. 응답 유실·잔액 부족·자동충전 결과 대기를 미결제나 완료로 잘못 확정하지 않는다.
- **AC-08 다음 회차:** 허용 역할·유형에서만 만들고 성공하면 새 초안 편집으로 이동한다. 제공자 배정 선택·취소·실패·화면 이탈·계정 변경을 구분한다.
- **AC-09 사진과 호스트:** 상세 사진·활동 사진첩·호스트 프로필 입구를 각각의 권한으로 제한하고 로딩·거절 응답을 실제 점수나 공개 정보로 표시하지 않는다.
- **AC-10 개인화 비노출:** 최소 모수·차단·열람 권한 조건을 지키며 신호가 없는 것과 0명을 혼동하지 않는다.
- **AC-11 캘린더:** 일정 결정 전에는 내보내지 않는다. 정상 파일 공유·외부 저장·공유 토큰 누락 실패를 구분하고 화면 이탈 중 완료돼도 잘못된 화면을 열지 않는다.
- **AC-12 좌석과 후속 업무:** 동반 인원·결제 대기·정기모임의 정원과 정산/출석/투표 입구가 서버 판단과 일치하는지 확인한다. 상세 도달만으로 후속 업무 성공을 완료 처리하지 않는다.

현재 앱에는 초안 삭제 메뉴와 목록 복귀, 다음 회차의 성공·실패·화면 이탈·계정 변경, 결제 CTA, 정산 입구의 구체적인 시험이 있다. 서버의 `EventPrepaymentServiceTest`는 기한 경과 뒤 지갑 차감·결제 행 생성이 없는지도 다룬다. 이번에는 시험 소스의 목적을 확인했으며 이 버전에서 재실행한 통과 결과를 주장하지 않는다.

과거 2026-11-09 기록은 웹의 먼 미래 모임에서 발생한 반복 조회를 긴 타이머 분할로 수리한 결과다. 그 기록과 발송 복구의 남은 실행 확인은 [현재 남은 작업](../../../../docs/plan/NEXT_WORK.md)에서 확인하며, 이번 문서 검수 결과로 날짜를 바꾸지 않는다. 이번 검토 버전·파일 지문은 [문서 갱신 검토 기록](../../../verification/document-refresh-2026-11-22.json)에 남긴다.
