# F03-17. 차량 좌석 배치도 운영 PRD

<!-- source-measured: 2026-09-02; authority: community_api/community_admin_api/community_admin_front/community_app current source -->

> 현재 상태: **첫 출시에 필요한 코드와 운영 화면 완료**. 대절 버스 봉인을 막는 미구현 항목이 아니다.

## 제품 목적

여러 모임이 반복해서 사용할 차량 좌석 구조를 운영자가 준비하고, 호스트가 활성 배치도를 골라 지정 자리
차량을 만드는 기능이다.

## 현재 제공 범위

| 사용자 | 할 수 있는 일 |
| --- | --- |
| 플랫폼 운영자 | 배치도 목록·상세·좌석표 조회, 복제, 이름·설명 수정, 사용 시작·중지 |
| 호스트 | 활성 배치도 목록 조회, 배치도를 사용한 차량 등록 |
| 참가자 | 행·열·좌석 종류와 점유 상태가 반영된 좌석표 조회·선택 |

표준 데이터는 25·28·41·45인승 버스와 7·9·11·12·15인승 승합차 9종이다. 운영자가 별도 입력하지
않아도 첫 대절 버스를 편성할 수 있다.

## 시나리오 기준 수용 조건

| 시나리오 | 기대 결과 | 현재 판정 |
| --- | --- | --- |
| V-01 운영자가 표준 배치도 확인 | 9종의 이름·좌석 수·상태와 실제 좌석표를 관리자 화면에서 확인한다 | 코드·운영 화면 완료 |
| V-02 운영자가 복제·수정·활성화 | 복제본은 비활성으로 시작하고, 이름·설명을 바꾼 뒤 선택 가능한 좌석이 있을 때만 활성화한다 | 코드·운영 화면 완료 |
| V-03 호스트가 활성 배치도로 차량 등록 | 비활성 배치도는 보이지 않고 활성 배치도의 선택 가능한 자리만 차량에 복사한다 | 코드 완료 |
| V-04 참가자가 좌석표 확인 | 통로·기사석·잠김·빈자리·내 자리·타인 점유를 구분하고 신원을 권한에 맞게 숨긴다 | 코드 완료 |

## 안전장치

- 생성한 배치도는 항상 비활성으로 시작한다.
- 선택 가능한 좌석이 하나도 없으면 활성화할 수 없다.
- 좌석 번호·좌표 중복과 좌석 수 불일치를 거절한다.
- 통로는 선택 가능한 좌석이 될 수 없다.
- 이미 차량이 참조하는 배치도의 좌석표 교체를 거절한다.
- 같은 이름의 배치도를 데이터베이스 유일 제약으로 막는다.

## 구현 위치와 검증

- 사용자 API: `VehicleLayoutController`
- 관리자 API: `ManageVehicleLayoutController`, `ManageVehicleLayoutService`
- 관리자 웹: `features/vehicle-layouts`
- 기준 데이터: 두 API 저장소의 `R__seed_reference_data.sql`
- 주요 검증: `ManageVehicleLayoutGuardTest.java`, `SharedV1SchemaMirrorTest.java`,

- 2026-09-02 검증: 관리자 API 23건, 관리자 웹 E2E 3건 실패 0

## 이번 출시 범위가 아닌 것

- 표준 9종 외 차량의 좌석 위치를 웹에서 직접 그리는 편집기
- 참고용 차량 사진
- 복제 중 연결이 끊겼을 때 생긴 비활성 배치도를 지우는 관리자 명령

이 세 항목은 현재 표준 차량 운영을 막지 않는다. 실제 운영 수요가 확인될 때 별도 개선으로 진행한다.

## 출시 전에 남은 일

차량 배치도 자체에 추가 구현은 없다. 같은 출시후보에서 관리자 화면→호스트 차량 등록→참가자 자리 선택을
실제 계정과 서명 앱으로 왕복하고, 전체 이동수단의 알림·신고·책임 고지 검증을 마친 뒤 `TRANSPORT`를
연다.
