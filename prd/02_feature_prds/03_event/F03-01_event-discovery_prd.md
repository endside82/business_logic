# F03-01. 이벤트 발견과 탐색 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 2026-11-22 현재 서버·앱 소스와 기존 시험 단언을 대조했으며, 새 제품 시험이나 실제 앱 검수 통과 기록이 아니다.

## 결론

이벤트 목록은 비로그인 사용자도 열 수 있다. 클럽에 소속되지 않은 독립 모임·정기모임 중 공개 또는 승인제이고 모집 중이며 숨기지 않은 모임을 대상으로 한다. 로그인하면 차단한 호스트의 모임을 제외하고 본인의 참여·찜 상태를 함께 표시한다.

앱 목록의 정렬은 **날짜순·인기순** 두 가지다. 위치 권한과 가까운순 선택은 이 화면의 조건이 아니다. 카테고리는 하나를 선택하고 전체 칩으로 해제한다. 상세의 유사 이벤트와 로그인 사용자의 개인화 추천은 일반 목록과 별도 조회다.

## 실제 입구와 사용자별 행동

| 입구·사용자 | 현재 동작 |
| --- | --- |
| 이벤트 탭·전체 메뉴의 이벤트 찾기 | 같은 이벤트 목록으로 간다. 전체 메뉴에서는 탭 루트로 이동한다 |
| 홈의 이벤트 목록 더보기 | 이벤트 탭으로 이동하며 날짜순을 사용한다. 기존 목록이 있으면 정렬을 날짜순으로 바꾸고 나머지 조건을 전부 초기화하지는 않는다 |
| 비로그인 | 공개 목록과 상세를 둘러볼 수 있다. 이벤트 열기 버튼은 보이지 않으며 찜 등 회원 행동은 해당 인증 흐름을 따른다 |
| 로그인한 호스트 | 목록의 이벤트 열기 버튼으로 만들기 화면에 간다 |
| 로그인한 비호스트 | 같은 위치에서 이벤트 열기 신청으로 간다. 로그인 여부만으로 만들기 화면을 여는 것은 아니다 |
| 이벤트 상세 | 이런 이벤트는 어떠세요? 구역의 더보기로 해당 모임의 유사 이벤트 목록을 연다 |

일반 검색 결과와 클럽의 모임 목록은 각 화면의 조건·권한을 따른다. 이를 이 공개 목록과 같은 입구로 묶지 않는다. [통합 키워드 검색](../05_search/F05-01_keyword-search_prd.md), [이벤트 상세](F03-02_event-detail_prd.md), [추천 이벤트 더보기](../02_home_feed/F02-04_recommend-events-more_prd.md)를 함께 본다.

## 공개 목록의 범위

서버는 공개 분류, 모집 중 상태, 숨김 여부, 로그인 사용자의 호스트 차단을 검색 조건에 반영한 뒤 총 건수와 페이지를 계산한다. 클럽 모임, 비공개 모임, 숨긴 모임, 모집 중이 아닌 모임을 이 목록에 섞지 않는다. 승인제 모임은 발견할 수 있지만 참가 가능 여부는 상세와 신청 정책에서 별도로 판정한다.

조회 결과에는 호스트 표시 정보, 본인의 참석·신청·찜 상태와 정기모임 맥락을 붙인다. 목록에 보인다는 사실이 신청·찜 등 모든 행동의 허가를 뜻하지 않는다. 카드와 서버의 행동 판정을 따른다.

## 검색·필터·정렬

| 조작 | 적용과 해제 |
| --- | --- |
| 검색어 | 입력을 제출할 때 제목·설명에서 검색한다. 입력만으로 자동 조회하지 않는다. 빈 검색어를 제출해 검색 조건을 바꿀 수 있다 |
| 카테고리 | 화면의 카테고리 칩 하나를 고른다. 선택한 칩을 다시 눌러도 전체로 돌아가지 않으며 전체 칩으로 해제한다 |
| 필터 시트 | 날짜·가격 범위·무료만·지역을 고른 뒤 결과보기를 눌러 적용한다. 시트를 닫으면 편집 중인 조건을 적용하지 않는다 |
| 필터 초기화 | 시트 안에서 날짜·가격·무료만·지역 초안을 초기화한다. 결과보기를 눌러야 적용되며 검색어·카테고리·정렬을 함께 지우지 않는다 |
| 날짜순 | 기본 정렬. 아직 시작하지 않은 모임을 시작 시각 오름차순, 같은 시각은 모임 번호 오름차순으로 정렬한다 |
| 인기순 | 현재 참가 인원 내림차순, 동률이면 모임 번호 내림차순이다. 날짜순에서만 적용하는 미래 시작 조건은 이 정렬에 자동으로 붙지 않는다 |

날짜 범위는 모임 시작 날짜, 가격은 모임 가격, 지역은 주소 문자열을 기준으로 거른다. 필터 시트에서 선택한 값은 현재 검색어·카테고리·정렬에 합쳐진다. 조건을 바꾸면 첫 페이지부터 다시 조회한다.

서버가 받는 검색 조건 전체가 이 화면에 노출되는 것은 아니다. 서버의 좌표·반경 검색은 사각 경계 범위로 거르며 정확한 원형 거리 검색이나 거리 정렬과 같지 않다. 서버에 정렬을 보내지 않을 때의 기본값과 앱이 명시해 보내는 날짜순도 구분한다. 공통 검색 규칙은 [검색 필터](../05_search/F05-03_search-filter_prd.md)를 따른다.

## 목록·실패·결과와 복귀

첫 페이지부터 20개씩 조회하고 아래로 이동하면 다음 페이지를 붙인다. 첫 조회 실패에는 재시도가 있고, 다음 페이지 실패에는 기존 항목을 유지한 채 하단 오류와 재시도를 표시한다. 항목이 있는 목록은 당겨서 다시 읽을 수 있다. 빈 결과는 조건에 맞는 이벤트가 없습니다를 표시하며 검색·카테고리·필터를 바꿔 다시 조회한다. 빈 상태 본문에는 당겨서 새로고침이 없다.

카드를 누르면 상세를 위에 열고 뒤로 돌아와 목록 탐색을 이어간다. 앱은 계정·이벤트 카드 데이터 변경과 찜 임시 반영을 구독한다. 찜 추가·해제의 인증, 낙관적 반영, 실패 복원과 다른 목록 반영은 [찜하기](F03-11_wishlist_prd.md)의 현재 규칙을 따른다. 상세에서 상태가 바뀌었는데도 원래 목록과 배지가 무조건 즉시 맞는다고 실행 확인 없이 단정하지 않는다.

## 유사 이벤트와 개인화 추천

유사 이벤트는 기준 모임을 제외하고 공개 목록 분류에 속하는 미래 모임을 후보로 삼는다. 로그인 사용자가 차단한 호스트도 제외한다. 카테고리·위치 또는 지역·가격·시간대의 가중치를 합해 정렬하고, 동점이면 시작 시각·모임 번호로 순서를 정한다. 코사인 유사도나 인기 정렬용 Redis 점수라고 설명하지 않는다.

앱은 유사 목록을 5개 요청한다. 상세에는 가로 카드, 더보기 화면에는 세로 목록을 표시하며 카드는 다른 이벤트 상세를 연다. 더보기는 같은 5개 조회를 사용하고 추가 페이지를 요청하지 않는다. 5개는 앱 요청값이자 서버 기본값이며 서버의 강제 최대값은 아니다.

현재 Provider는 Repository 실패를 빈 목록으로 바꾼다. 따라서 정상적으로 결과가 없을 때와 일반적인 조회 실패 모두 상세·더보기 화면에 유사한 이벤트가 없습니다로 보일 수 있다. 더보기 화면에 오류·재시도 분기가 있어도 이 실패 변환을 거친 오류에는 도달하지 않는다. 상세의 예상하지 못한 Async 오류를 숨기는 분기와 이 일반 실패 경로를 구분한다.

개인화 추천은 로그인 필수인 별도 페이지 조회다. 목록의 인기순이나 유사 이벤트의 가중치와 같은 기능으로 합치지 않는다. 추천 후보·점수·페이지 동작은 [추천 이벤트 더보기](../02_home_feed/F02-04_recommend-events-more_prd.md)에서 관리한다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 현재 근거·영향 | 남은 확인 |
| --- | --- | --- | --- |
| Gap | 유사 조회 실패와 빈 결과 혼동 | Provider가 실패를 빈 목록으로 바꿔 사용자에게 추천이 없는 것으로 보인다 | 실패 안내·재시도 동작을 별도 제품 수정에서 정하고 검증 |
| Risk | 유사 목록 limit | Controller 기본값은 5지만 서비스에서 별도 상한·음수 보정 없이 limit을 사용한다 | 서버 입력 경계와 오류 응답 확인. 앱의 고정 5개 요청과 구분 |
| Risk | 빈 목록의 새로고침 | 항목이 없는 분기는 RefreshIndicator 밖에 있다 | 같은 조건의 재조회가 필요할 때 사용할 동작과 안내 검토 |
| 미검증 | 실제 앱 업무와 서버 실행 | 이번에는 소스와 기존 시험 단언을 대조했다 | 실제 권한별 입구·필터·목록 복귀·조회 실패는 실행 결과가 있어야 통과 판정 |

이전 문서의 가까운순·카테고리 재선택 해제·로그인만으로 만들기·최신순 기본·유사 추천 최대 5개·실패 시 항상 숨김 설명은 현재 동작으로 교정했다. 오래된 시나리오의 고정 결과 건수와 시험 파일 존재를 현재 통과 근거로 사용하지 않는다.

## 수용 기준과 검증 근거

- **AC-01 공개 후보:** 클럽 소속·비공개·숨김·모집 종료와 공개 승인제 모임을 섞어 준비하면 공개 분류·모집 중 조건을 만족하는 모임만 목록과 총 건수에 포함한다.
- **AC-02 차단과 익명:** 익명은 공개 목록을 열 수 있고 로그인 사용자는 차단한 호스트의 모임을 결과·총 건수에서 제외한다.
- **AC-03 만들기 입구:** 호스트는 이벤트 열기, 로그인한 비호스트는 이벤트 열기 신청을 보며 비로그인에는 두 행동이 보이지 않는다.
- **AC-04 검색어 제출:** 입력만 바꿀 때 조회하지 않고 제출할 때 첫 페이지를 조회한다. 빈 검색어 제출로 해당 조건을 바꿀 수 있다.
- **AC-05 카테고리 해제:** 선택한 칩을 다시 눌러도 선택을 유지하며 전체 칩으로 카테고리 조건을 해제한다.
- **AC-06 필터 적용·취소:** 시트에서 날짜·가격·무료·지역을 바꾼 뒤 닫으면 기존 조건을 유지하고 결과보기를 누르면 새 조건을 반영한다.
- **AC-07 초기화 범위:** 시트 초기화 후 결과보기를 누르면 시트 조건만 지우며 검색어·카테고리·정렬은 유지한다.
- **AC-08 정렬:** 기본 날짜순은 미래 시작 모임의 시각·번호 오름차순, 인기순은 현재 참가 인원·번호 내림차순으로 읽는다.
- **AC-09 페이지 실패:** 다음 페이지 실패 시 기존 카드를 유지하고 하단에서 재시도한다. 첫 조회 실패에는 첫 조회 재시도를 제공한다.
- **AC-10 빈 결과:** 결과가 없으면 빈 안내와 조건 조작부를 유지한다. 이 분기에는 당겨서 새로고침이 없음을 검증 범위에 명시한다.
- **AC-11 상세와 찜:** 목록에서 상세를 열고 복귀해 탐색을 이어간다. 찜은 인증·실패 복원·연결 화면 갱신을 찜하기 문서의 조건과 함께 판정한다.
- **AC-12 홈 더보기:** 기존 목록에 다른 정렬이 있으면 홈 더보기로 진입할 때 날짜순으로 바꾸며 다른 필터를 일괄 초기화한 것으로 기대하지 않는다.
- **AC-13 유사 후보·개수:** 기준 모임·차단 호스트를 제외한 공개 미래 후보를 가중치 순으로 최대 요청 수만큼 읽는다. 앱 더보기는 5개 요청이며 무한 스크롤을 제공하지 않는다.
- **AC-14 유사 실패의 현재 제한:** Repository 실패를 빈 목록으로 바꾸는 현행 동작을 확인하고, 이를 오류 재시도 검증 통과나 정상 빈 결과 확인으로 대체하지 않는다.

검증 근거: seed_event_list_badge_matrix_test.dart의 전체 칩·총 건수·날짜순·대표 모임 제목 단언, seed_event_recommendation_empty_state_test.dart의 빈 Provider 대체와 더보기 화면 빈 문구 단언을 읽었다. 후자는 서버의 실제 빈 후보·통신 실패를 검증하는 시험이 아니다. 이번에 제품 시험을 새로 실행하지 않았다.
