# F03-08. QR·코드·직접 체크인 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 2026-11-22 해당 서버·앱 함수와 명시한 기존 시험 단언을 대조했다. 새 제품 시험·실DB·카메라·기기·마일리지 적립의 통과 기록은 아니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

출석 관리자가 모임의 QR과 6자리 코드를 보여 주고, 참석자가 본인의 계정으로 스캔하거나 입력해 체크인한다. 게스트를 함께 처리하거나 관리자가 회원·게스트의 참가 행을 골라 직접 체크인할 수 있다. 참석자가 만든 QR을 관리자가 스캔하는 별도 흐름은 현재 화면에 없다.

체크인은 실제 참석 기록이다. 신청 승인·대기열 승격은 [신청과 참석](F03-05_event-attendance_prd.md) 및 [정원 설정·대기열·모집 관리](F03-07_capacity-and-waitlist_prd.md), 이미 확정된 노쇼의 소명·번복은 [이벤트 노쇼](F03-20_event-no-show_prd.md)의 별도 업무다. 단순 미체크인 인원과 노쇼 확정 인원을 같다고 설명하지 않는다.

## 실제 입구와 업무별 권한

| 대상 | 확인한 입구·판정 | 도착 후 행동 |
| --- | --- | --- |
| 출석 관리 권한이 있는 사용자 | 모임 상세의 ‘출석 관리’ → 체크인 화면. 서버의 출석 관리 허용 값을 사용 | ‘체크인 QR / 직접 체크인 / 통계’ 세 탭 |
| 실제 ATTENDING 참가 행이 있는 회원 | 체크인 경로 진입 허용. 안전 체크인 알림은 이 경로로 연결 | 본인 체크인 허용·현재 시간에 따라 스캐너와 코드 입력 또는 제한 안내 |
| 신청만 승인됐고 실제 참석 행이 없는 회원·대기자 | 합성된 참석 표시만으로 체크인 경로를 열지 않음 | 참석 자격을 충족해야 함 |

서버의 출석 관리자는 호스트, 출석 관리 권한이 있는 공동호스트, 클럽에서 출석 관리가 허용된 사용자다. 위임 권한 정지도 판정한다. 공동호스트·OWNER·ADMIN이라는 이름만으로 모두 허용한다고 쓰지 않는다. 일반 참가자를 위한 모임 상세의 직접 체크인 버튼은 이번에 확인한 구현에서 찾지 못했으며, 알림·경로가 있다는 사실과 구분한다.

처음 모임 정보를 불러올 때는 대기 상태를, 실패하면 재시도를 보인다. 화면은 시간 경계에서 모임 정보를 다시 읽는다. 관리자 화면은 본인 체크인 시간 밖이라는 이유만으로 전체를 막지 않고 직접 체크인의 허용 조건을 별도로 표시한다.

## QR·6자리 코드 발급과 만료

출석 관리자가 QR 탭을 처음 열면 발급을 한 번 요청한다. 발급에는 모임 상세 열람과 출석 관리 권한이 필요하며, 발급 자체와 참석자의 실제 체크인 시간 조건은 별개다. 발급된 QR과 숫자 코드는 5분간 유효하다.

새로 발급할 때 이전 6자리 코드를 지우고 새 코드를 만든다. 이전 QR 토큰을 함께 폐기하는 저장·대조는 없으므로, ‘재발급하면 이전 QR도 즉시 무효’라고 안내하지 않는다. 잘못된 서명·만료된 QR·다른 모임의 QR, 형식이 틀리거나 없어진 6자리 코드는 거절한다.

QR에는 남은 시간이 표시되고 만료되면 ‘새 QR 코드 받기’를 눌러 갱신한다. 만료만으로 자동 재발급하지 않는다. 처음 발급 실패 후 ‘다시 시도’로 상태를 초기화하면 ‘QR 만들기’가 나타날 수 있고, 해당 버튼으로 다시 요청한다. 숫자 코드의 만료 표시 차이는 현재 제한에 남긴다.

## 본인 체크인의 시간·자격·결과

| 조건 | 현재 결과 |
| --- | --- |
| OPEN, 유효한 시작·종료 시각, 시작 2시간 전 이상·종료 시각 미만 | 본인 체크인 시간 조건 충족 |
| DRAFT·CLOSED·CANCELED, 일정 없음·종료가 시작 이하, 시간 밖 | 본인 체크인 거절 |
| 실제 ATTENDING 참가 행 없음 | 참석 행 없음 또는 참석 상태 오류로 거절 |
| 본인 일행 책임 회원의 반환 대기 결제, 번복되지 않은 노쇼 기록 | 체크인 거절 |
| 이미 체크인됨 | 새 기록을 더 만들지 않고 중복 결과 반환 |

QR 인식은 한 번 감지한 뒤 추가 감지를 멈춘다. 실패하면 오류 안내를 보고 ‘다시 스캔’으로 스캐너를 다시 만들거나 코드 입력으로 전환한다. 코드 입력은 숫자 6자리일 때 제출할 수 있고, 제출 중 버튼이 비활성화된다. 실패 시 입력창과 코드가 남고, 성공 시 입력창을 닫아 완료 상태로 돌아온다.

QR 성공 시 같은 화면을 ‘체크인 완료’로 바꾸고 성공 안내를 보인다. 서버의 본인 체크인 허용 값이 중복 사유로 거절되어도 허용 시간 안에서는 완료 상태로 표시한다. 시간 밖이면 완료 표시보다 시간 제한 안내가 먼저 적용된다. 체크인 성공을 다른 목록 전체의 즉시 갱신이나 알림 수신으로 확대하지 않는다.

## 게스트 함께 체크인

앱은 내 일행을 읽어 게스트가 있으면 ‘게스트 N명 함께 체크인’ 선택을 표시하며 기본은 선택 상태다. 조회 실패는 게스트 수 0으로 처리되어 선택이 나타나지 않는다.

포함을 선택하면 서버는 본인 체크인 후 본인이 책임지는 ATTENDING 게스트 행을 처리한다. 이미 체크인된 게스트는 건너뛴다. 본인과 게스트는 이 요청의 같은 트랜잭션 안에서 처리되므로, 처리 중 거절이 발생하면 이 요청에서 새로 기록한 본인·게스트 체크인이 함께 취소된다. WAITING 게스트를 참석 상태로 바꾸지는 않는다.

본인이 먼저 체크인된 뒤 게스트만 추가로 셀프 체크인하는 흐름은 없다. 본인 중복에서 요청이 끝나므로 남은 게스트는 출석 관리자의 직접 체크인으로 처리한다. 게스트 처리에는 책임 회원과 처리 사유를 남긴다. 게스트에게 회원 계정이 생기거나 회원 기준 마일리지가 자동 지급되는 것으로 설명하지 않는다.

## 직접 체크인과 부분 완료

직접 체크인은 OPEN 또는 CLOSED이며 시작 2시간 전 이상·종료 후 2시간 미만일 때 허용한다. 정확히 종료 후 2시간이면 거절한다. 취소·일정 미정은 시간 안내로 대신하지 않고 서버 거절 사유를 표시한다. 앱은 현재 모임의 허용 값과 각 참가 행의 허용 값을 함께 사용한다.

관리자는 ATTENDING 목록에서 이름을 검색하고 회원·게스트 행을 선택한다. 게스트에는 책임 회원 안내가 표시된다. 보낸 번호는 회원 번호가 아닌 참가 행 번호다. 앱은 선택 목록을 한 번 요청하며, 서버는 각 행을 순서대로 별도 트랜잭션으로 처리한다. 감사 사유는 선택 입력을 받을 수 있지만 현재 화면에는 사유 입력란이 없다.

없는 행·다른 모임 또는 공개되지 않는 행·이미 체크인된 행·참석 중이 아닌 행은 건너뛴다. 잠금 후 참석 상태·반환 대기·중복·노쇼를 다시 판정하며, 자격이 없어진 행도 완료 수에 넣지 않는다. 정상 응답의 수치는 실제로 새 기록을 저장한 행 수다.

| 결과 | 사용자에게 보이는 것과 후속 행동 |
| --- | --- |
| 보낸 행 전부 새로 처리 | 실제 처리 수만큼 ‘N명 체크인 완료’, 명단·통계 재조회 |
| 일부만 새로 처리 | 완료 수와 건너뛴 수를 함께 안내, 명단·통계 재조회 |
| 새로 처리한 행 없음 | ‘체크인된 사람이 없습니다. 명단을 확인해 주세요’ |
| 뒤 행 처리 도중 요청 실패·응답 유실 | 앞 행의 완료가 남아 있을 수 있음. 명단·통계를 다시 읽고, 복수 행 요청에는 일부 처리 가능 안내 |

직접 체크인 성공·실패 후에도 같은 관리 화면에 남는다. 오류를 전체 취소로 해석하거나 보낸 인원을 전원 성공으로 표시하지 않는다. 재전송 시 이미 처리된 행은 건너뛸 수 있지만, 이전 요청의 응답 전체를 그대로 재생하는 명령 영수증 방식은 아니다.

## 통계·미체크인·후속 기록

통계 조회는 출석 관리 권한이 필요하다. 유효한 ATTENDING 중 신청 취소 후 반환 대기인 책임 회원의 일행을 제외하고, 회원 계정 기준과 게스트를 포함한 인원 기준을 나누어 집계한다. 미체크인 참가 행 목록은 직접 체크인 명단의 표시에도 사용한다.

현재 통계 카드는 ‘계정 기준’과 ‘인원 기준’ 수치, 미체크인 회원 수를 표시한다. 개인별 미체크인 이름 목록을 통계 카드가 제공한다고 쓰지 않는다. 서버의 회원 체크인율은 0~100 백분율이지만 앱 표시의 단위 불일치는 아래 제한에 남긴다. 통계의 미체크인은 노쇼 확정이나 자동 패널티를 뜻하지 않는다.

직접 체크인 뒤 명단·통계를 다시 읽으며, 통계 읽기 실패는 통계 탭에서 재시도할 수 있다. 탭을 누를 때마다 새로 조회하거나 다른 회원의 체크인을 실시간으로 자동 반영하는 별도 주기 갱신은 확인되지 않았다.

서버는 모임·참가 행·처리 방식·처리자·사유를 체크인 기록에 남긴다. 클럽의 회원 체크인에는 마일리지 프로그램 활성 여부에 따라 자동 적립 신호를 보낸다. 프로그램 판정 실패는 별도 신호로 남기는 경로가 있으며, 이 연결을 실제 적립 완료로 판정하지 않는다.

## 수용 기준과 검증 근거

- **AC-01 실제 입구와 역할:** 출석 관리자는 상세의 출석 관리에서 세 탭으로 들어간다. 일반 참석자는 실제 참가 행으로 경로 접근을 판정하고, 상세 입구의 현재 차이는 숨기지 않는다.
- **AC-02 코드 발급과 갱신:** 허용된 관리자가 발급하면 QR·6자리 코드·5분 만료 시각을 받는다. 재발급 뒤 이전 숫자 코드는 거절하고 이전 QR의 유효기간과 혼동하지 않는다.
- **AC-03 QR 만료:** 만료 시 새 코드 받기 행동을 표시하고 버튼을 누를 때 다시 발급한다. 숫자 코드의 별도 만료 표시 차이를 남긴다.
- **AC-04 본인 시간 경계:** OPEN 모임의 시작 2시간 전은 허용하고 종료 시각은 거절한다. 일정 없음·잘못된 일정·다른 상태도 거절한다.
- **AC-05 본인 자격과 중복:** 실제 ATTENDING 행, 반환 대기, 유효한 노쇼 기록, 기존 체크인을 판정한다. 중복 요청으로 체크인 기록을 더 만들지 않는다.
- **AC-06 QR 실패 복구:** 잘못되거나 다른 모임의 QR은 오류가 되고, 다시 스캔 또는 숫자 코드 입력으로 같은 모임에서 재시도할 수 있다.
- **AC-07 숫자 코드 입력:** 숫자 6자리만 제출하고 제출 중 중복 행동을 막는다. 실패하면 값을 유지하고 성공하면 입력창을 닫아 완료 상태로 돌아온다.
- **AC-08 게스트 포함:** 포함 선택 시 본인과 ATTENDING 게스트만 처리한다. 이미 처리한 게스트는 건너뛰고, 도중 거절이면 이 요청의 신규 체크인들을 함께 취소한다.
- **AC-09 본인 완료 후 게스트:** 이미 체크인된 본인의 재요청으로 게스트만 추가 처리하지 않는다. 남은 게스트는 관리자 직접 체크인 대상이다.
- **AC-10 직접 체크인 경계:** OPEN·CLOSED의 시작 2시간 전 이상·종료 후 2시간 미만에서 관리자와 참가 행의 허용 조건을 모두 검사한다.
- **AC-11 행 단위 요청:** 선택한 회원·게스트의 참가 행 목록을 한 번 보낸다. 없는 행·다른 모임·부적격·중복 행을 성공 수에 더하지 않는다.
- **AC-12 일괄 결과 표시:** 3행 요청에 새 처리 1행이면 ‘1명 완료·2명 건너뜀’, 0행이면 명단 확인 안내를 보인다. 보낸 수를 완료 수로 쓰지 않는다.
- **AC-13 일괄 중간 실패:** 앞 행이 완료된 뒤 실패해도 전부 되돌아갔다고 안내하지 않는다. 명단·통계를 다시 읽고 현재 결과로 다음 행동을 정한다.
- **AC-14 통계 축과 제한:** 회원·전체 인원·미체크인 행을 구분하고 반환 대기 일행 제외를 확인한다. 계정 비율의 앱 단위 오류와 통계 미수신 표시 차이는 별도 판정한다.
- **AC-15 노쇼와 적립 구분:** 단순 미체크인 수를 노쇼 확정 수로 쓰지 않는다. 체크인 기록·자동 적립 신호·실제 적립 완료를 구분한다.

기존 CheckInServiceTest의 672–711행은 이전 숫자 코드 폐기·생성 충돌, 747–779행은 반환 대기 회원 제외와 50.0 백분율을 단언한다. BatchCheckInOrchestratorTest의 58–87행은 한 행씩 호출·실제 수 합산·빈 요청의 권한 확인·외부 트랜잭션 거절을 단언한다. qr_check_in_batch_toast_test.dart의 28–115행은 실제 처리 수 안내·부분 완료 표시·직접 체크인 시간 밖 안내를 모의 객체로 확인한다. 이번 작업에서는 이 단언을 읽었으며 시험을 새로 실행하지 않았다.
