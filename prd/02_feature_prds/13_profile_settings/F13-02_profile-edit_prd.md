# F13-02. 프로필 편집과 사진 변경 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 2026-11-22 현재 소스·시험 목적 대조이며 새 실행·실기기 검증 기록은 아니다.

## 결론

프로필 카드의 **프로필 편집**에서 닉네임·자기소개·사진·MBTI를 바꾼다. 현재 인증 계정의 값을 처음 폼에 채우며, 변경이 있고 사진 처리·저장 중이 아닐 때 저장할 수 있다. 저장 응답의 표시 필드만 같은 계정에 적용하고 사진·사람 정보의 갱신을 알린다.

사진 선택·파일 업로드·프로필 연결 저장은 서로 다른 단계다. 업로드가 끝났다고 새 프로필 사진이 저장된 것은 아니며, 프로필 편집이 이메일·계정 권한·가입 상태를 바꾸는 기능도 아니다.

## 실제 진입과 복귀

1. 하단 마이 → 사진·닉네임 카드 → **프로필 편집**을 선택한다. 아래 메뉴가 닫힌 뒤 편집 화면을 연다.
2. 현재 닉네임·소개·사진·MBTI를 초기값으로 표시한다. 계정이 바뀌면 폼을 새로 만들어 이전 계정의 초안을 계속 쓰지 않는다.
3. 상단 저장으로 변경을 제출한다. 값이 같으면 저장을 비활성화하고 저장·사진 처리 중에는 중복 실행과 일반 이탈을 막는다.
4. 변경 없이 뒤로 가면 닫는다. 변경 중에는 **계속 쓰기 / 버리고 나가기** 확인을 받는다. 저장 성공 뒤에는 성공 안내와 함께 원래 화면으로 돌아간다.
5. 저장 실패에서는 폼을 유지한다. 중복 닉네임은 전용 안내, 그 밖 실패는 수정 실패 안내를 보인다.

## 입력과 저장 규칙

| 항목 | 현재 앱·서버 동작 |
|---|---|
| 닉네임 | 앱은 앞뒤 공백을 제거하고 2~30자로 제출함. 서버도 길이·다른 계정과의 중복을 검사하고 변경 이력을 남김 |
| 자기소개 | 앱은 200자 입력 한도와 앞뒤 공백 제거를 적용함. 빈 문자열 저장으로 지울 수 있음. 서버 상한은 500자로 앱보다 큼 |
| 사진을 바꾸지 않음 | 새 사진 키를 보내지 않아 기존 사진을 유지함. 조회한 임시 표시 URL을 새 사진으로 다시 저장하지 않음 |
| 새 사진 저장 | 서버가 현재 회원 소유·프로필 용도의 이미지 키인지 검사한 뒤 연결함. 기존 소유 파일은 후속 소거 대상으로 넘김 |
| MBTI 선택·변경 | 16개 선택지 중 현재 값을 보냄. 같은 선택지를 다시 누르면 선택을 해제함 |
| MBTI 해제 | 현재 선택이 없으면 명시적 해제 의도를 함께 전송함. 서버의 ‘값 생략=유지’와 구분함 |
| 계정 종료 | 서버는 회원 잠금 뒤 탈퇴 진행·완료 계정의 쓰기를 거절함 |

서버가 받는 언어 설정은 별도 기능이며 현재 편집 폼에 없는 입력을 여기서 바꿀 수 있다고 안내하지 않는다. 가입 단계의 닉네임 한도와 프로필 변경의 한도를 같은 값으로 덮어 쓰지 않는다.

## 사진 선택·실패·저장 경계

- 앨범에서 사진을 고르며 선택 취소는 기존 사진을 유지한다. 선택 이미지의 10MB 초과는 업로드 전에 안내한다. 선택기는 최대 512×512·품질 85 설정을 사용한다.
- 로컬 바이트로 즉시 미리보기하고 프로필 용도로 업로드한다. 미리보기에 저장소 키를 이미지 URL처럼 사용하지 않는다.
- 업로드 실패·읽기 오류는 안내하고 직전 미리보기로 복구한다. 성공하면 새 키를 임시로 보관하고 **저장** 때 프로필과 연결한다.
- 업로드 성공 뒤 폼에서 나가기를 버린 것은 프로필 변경 취소다. 이미 올린 파일의 즉시 물리 삭제를 이 화면이 보장한다고 설명하지 않는다.
- 저장 성공 응답의 표시 URL을 현재 계정에 적용한다. 이전 사진의 삭제 예약과 저장소의 실제 소거 완료는 구분한다.

## 공개 범위와 계정 경계

저장 응답은 닉네임·소개·사진·언어·MBTI 등 표시 필드만 현재 계정에 적용한다. 이전 계정의 늦은 응답이 새 계정의 정보나 권한을 바꾸지 않으며, 화면이 이미 닫혔어도 같은 계정의 성공 결과는 표시 정보에 반영한다.

다른 사람이 보는 소개·MBTI는 공개 범위 판정을 따른다. 본인 외에는 같은 클럽 또는 확인된 모임 관계의 상세 권한을 사용하고 차단·대상 계정 상태를 먼저 확인한다. 제3자 기본 정보에는 닉네임·사진만 제공한다. 예전 문서의 ‘데이트 매칭이면 커뮤니티 MBTI를 공개한다’는 설명은 현재 관계 정책과 다르다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 영향·다음 확인 |
|---|---|---|
| Risk | 자기소개 상한 차이 | 서버는 500자, 현재 편집 입력은 200자다. 다른 경로로 저장한 긴 소개의 편집 경험을 별도로 확인해야 함 |
| Risk | 사진 업로드와 폼 취소 | 업로드 후 저장 취소·응답 유실·기존 파일 소거를 하나의 성공/실패로 묶지 않음 |
| 미검증 | 실제 사진·기기 | 현재 소스와 계정 경계 시험 본문을 대조했으며 새 앨범 선택·업로드·표시·외부 파일 소거를 실행하지 않음 |

## 수용 기준과 검증 근거

- **AC-01 진입:** 마이의 프로필 메뉴에서 현재 계정 값으로 편집하고 원래 화면으로 돌아간다.
- **AC-02 입력:** 닉네임 길이·공백·중복과 자기소개 빈 값·앱 상한·서버 상한을 구분한다.
- **AC-03 변경 없음:** 바뀐 값이 없으면 저장하지 않고 그대로 나갈 수 있다.
- **AC-04 이탈:** 변경 중 계속 쓰기·버리고 나가기와 저장/사진 처리 중 이탈을 구분한다.
- **AC-05 사진 선택:** 취소·용량 초과·로컬 미리보기·읽기 실패·업로드 실패 복구를 확인한다.
- **AC-06 사진 적용:** 업로드 성공과 프로필 저장 성공을 따로 확인하고 사진 미변경은 기존 값을 유지한다.
- **AC-07 MBTI:** 신규 선택·변경·재탭 해제·선택 없음의 전송 의도와 저장 결과가 일치한다.
- **AC-08 저장 실패:** 중복과 일반 실패에서 폼을 유지하고 서버의 기존 상태를 성공으로 오인하지 않는다.
- **AC-09 계정 전환:** 늦은 응답과 새 계정 폼에서 표시·권한·초안을 섞지 않는다.
- **AC-10 공개:** 본인·같은 클럽/확인된 모임·제3자·차단 상태의 소개와 MBTI 공개 범위를 구분한다.

`profile_edit_safety_test.dart`는 화면이 닫힌 뒤 같은 계정 갱신, 계정 전환 뒤 늦은 응답 무시, 초안 교체·이탈 확인을 다룬다. 사진·스크롤 시험과 `UserServiceTest`도 관련 확인 위치이며 이번 대조에서 새 실행 통과로 기록하지 않는다.

검토 버전과 지문은 [문서 갱신 검토 기록](../../../verification/document-refresh-2026-11-22.json)에 둔다.
