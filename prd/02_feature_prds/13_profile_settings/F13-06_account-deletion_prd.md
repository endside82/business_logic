# F13-06. 계정 삭제 요청과 취소 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 2026-11-22 현재 소스 대조이며 새 시험 실행·운영 환경 검증 기록은 아니다.

## 결론

계정 삭제 요청은 바로 로그아웃하는 탈퇴와 달리, 요청 시점부터 30일 뒤를 예정일로 잡는 개인정보 파기 예약이다. 현재 앱은 사전 의무 점검 → 해당되는 보관금 포기 동의 → 최종 확인을 거친다. 삭제 대기 중에는 명시적으로 취소할 수 있으며 로그인 자체는 취소 동작이 아니다.

예정일은 파기 완료 보장이 아니다. 정지·차단 상태, 새로 생긴 의무, 동의가 덮지 못하는 보관금, 처리 실패가 있으면 예약 파기는 미뤄진다. 일부 활동 정리와 파일 삭제·환급 같은 후속 처리는 계정의 파기 완료와 구분한다.

## 실제 진입과 복귀

- 전체 메뉴 → 설정 → 계정 → **데이터 내보내기·탈퇴**에서 데이터 프라이버시 화면을 연다. 내 프로필의 삭제 진행 배너 **관리**도 같은 화면으로 간다.
- 이용 제한 안내의 **계정 삭제 요청·취소** 입구가 현재 구현되어 있다. 제한 세션은 요청·상태 조회·취소와 사전 점검을 사용할 수 있고, 즉시 탈퇴는 닫힌다. 상세 제재 정책은 [제재 집행 기능](../15_warning/F15-08_sanction-enforcement_prd.md)을 따른다.
- 요청 없음은 새 요청 버튼, 대기는 남은 일수·삭제 취소, 승인은 새로고침을 보인다. 승인 상태에서는 취소 버튼이 없다.
- 요청 없음으로 해석하는 응답은 서버의 정확한 ‘자료 없음’이다. 그 밖의 조회 실패는 오류 상태이지만, 현재 프라이버시 화면은 오류 자리에도 요청 버튼을 보여준다. 내 프로필 배너는 오류·다시 시도를 보인다.
- 확인 창에서 취소하면 삭제 요청을 보내지 않는다. 상태를 읽거나 배너를 여는 것만으로 계정이나 예약을 바꾸지 않는다.

## 사전 점검과 보관금 동의

1. 정산·환불·출금·유료 활동·클럽 소유권·제공자 배정 등 현재 의무를 점검한다. 점검 실패면 안내 후 멈추며, 차단 항목이 있으면 이유와 상세 최대 3건·나머지 건수를 보여준다.
2. 해결 경로가 있는 항목의 **해결하기**는 창을 닫고 해당 화면으로 이동한다. 클럽 폐쇄 가입비 환불은 고객센터 입구도 보인다. 돌아와 다시 요청할 때 의무를 새로 점검한다.
3. 보관금 포기 대상이 있으면 서버가 준 제목·설명·모임별 금액·조건을 별도 창에 표시한다. **동의하고 계속** 뒤 최종 삭제 확인을 받는다. 어느 창에서든 취소하면 요청하지 않는다.
4. 서버는 현재 안내 버전과 대상 모임·금액을 대조한다. 대상이 없으면 동의 본문 없이 요청할 수 있다. 대상이 새로 생기거나 금액·안내가 달라지면 예전 동의로 진행하지 않는다.
5. 최종 요청에서 차단 상세가 오면 같은 차단 창을 보인다. 동의 재확인이 필요하고 차단 상세가 없으면 안내 뒤 점검부터 다시 시작한다. 비밀번호 재입력은 이 흐름에 없다.

## 예약·취소·실행 규칙

| 조건 | 현재 결과 |
|---|---|
| 요청 성공 | 30일 뒤 예정일과 삭제 대기 상태를 저장하고 앱 상태를 갱신함. 계정은 즉시 탈퇴하지 않음 |
| 이미 대기·승인 요청이 있음 | 활성 요청은 회원당 하나. DB 중복 제약을 포함해 두 활성 예약을 만들지 않음 |
| 이미 즉시 탈퇴한 계정 | 새 예약 삭제를 거절함 |
| 대기 요청 취소 | 요청 잠금 뒤 대기 상태를 다시 확인해 취소함. 앱은 성공 시 진행 상태를 비움 |
| 취소 실패·이미 진행된 요청 | 성공으로 표시하지 않음. 실행과 취소의 경합은 잠금 뒤 상태로 판정함 |
| 대기 상태이며 예정일이 지남 | 매일 04:00 예약 작업의 대상이 됨. 실행 전과 잠금 뒤 조건을 다시 확인함 |
| 정지·차단 중 | 예약 자동 파기를 미룸. 요청을 받았다는 사실이 제재 중 자동 파기를 허용한다는 뜻은 아님 |
| 의무·동의 부족·처리 실패 | 완료로 바꾸지 않음. 해결 후 후속 실행이 필요하며 정해진 완료 시간을 보장하지 않음 |
| 취소·완료 상태 | 사용자 상태 조회는 활성 대기·승인만 반환하므로 최신 활성 요청이 없다는 응답이 됨 |

예약 커밋 뒤 판매 예약·상품·플랜·꾸러미·제공 상품의 판매를 내리는 처리를 시작한다. 개별 실패는 기록되며 예약 취소가 이미 내린 판매를 자동 복원하지 않는다. 예약 실행 직전에는 활동을 항목별로 정리하므로, 그 뒤 취소·제재·재판정으로 최종 파기가 멈춰도 먼저 정리된 활동은 남을 수 있다.

관리자 즉시 처리와 예약 자동 처리는 같은 경로가 아니다. 관리자 실행도 취소·완료 상태와 실행 시점 의무를 판정한다. 회원 화면의 30일 안내만으로 관리자의 실행 권한과 처리 일정을 설명하지 않는다.

## 파기 범위와 완료의 경계

- 계정 식별 정보와 비밀번호·연결 계정·세션을 정리하고, 프로필·주소·관심사·알림 설정·기기 정보·검색·일정·취향·데이트 관련 개인정보를 각 담당 소거기로 넘긴다. 외부에 저장된 사진·본인인증 자료·내보내기 파일은 삭제 표시·재시도 처리가 따르므로 DB 완료와 물리 파일 삭제 완료는 다르다.
- 제재·분쟁과 법적 보존 대상은 별도 정책을 따른다. 분쟁 보존 중인 알림·대화 등과 거래·정산에 결박된 계좌 자료까지 모두 즉시 지운다고 안내하지 않는다. 개인정보 보존의 법적 적합성을 이번 코드 대조로 새로 인증한 것은 아니다.
- 지갑 유료 잔액은 파기 트랜잭션에서 환급 출금을 예약하고 무료 잔액은 소멸시킨다. 예약은 외부 송금 완료가 아니다. 필요한 계좌와 의무 조건이 충족되지 않으면 완료를 단정하지 않는다.
- 닉네임 이력을 모아 행위자 알림 사본과 댓글 언급 등을 익명화한다. 제3자가 적은 본문·과거 사본·이미 전송된 푸시까지 완전 소거했다고 확대하지 않는다.
- 즉시 탈퇴 뒤 유예 만료 파기와 공통 소거기를 사용하지만, 사용자 진입·취소 가능성·세션 종료 시점은 [계정 즉시 탈퇴](F13-07_account-deactivation_prd.md)와 다르다.

| 판정 | 항목 | 영향·다음 확인 |
|---|---|---|
| Gap | 조회 오류에서도 새 요청 버튼 노출 | 기존 예약 유무를 확인하지 못했는데 새 요청처럼 보일 수 있음. 서버 중복 차단과 화면 안내를 구분함 |
| Gap | 승인 상태 배너의 취소 안내 | 내 프로필 배너는 대기·승인에 같은 ‘그 전까지 취소’ 안내를 쓰지만 승인 상태는 취소할 수 없음 |
| Gap | 파기 예정일을 확정처럼 안내 | 남은 일수·배너는 제재·의무에 따른 지연을 설명하지 않음. 0일·예정일 경과도 완료가 아님 |
| Risk | 부분 정리와 취소 | 판매 내리기·실행 전 활동 정리는 예약 취소나 최종 파기 실패로 모두 복구되지 않음 |
| Gap | 화면 명세의 예약 요청 설명 | 관련 프로필 화면 명세의 삭제 부분에는 사전 점검·조건부 보관금 동의 본문이 아직 빠져 있음 |
| 미검증 | 실제 파기·외부 처리 | 새 실행·물리 기기·운영 스케줄러·파일 소거·실제 송금 완료를 이번 문서 작업에서 확인하지 않음 |

## 수용 기준과 검증 근거

- **AC-01 진입:** 설정·내 프로필 배너·제한 안내에서 같은 화면에 도달하고 원래 화면으로 돌아간다.
- **AC-02 상태:** 정확한 요청 없음, 조회 실패, 대기, 승인, 알 수 없는 상태를 구분한다.
- **AC-03 점검:** 차단·점검 실패에서는 예약하지 않고 해결 경로로 이동할 수 있다.
- **AC-04 동의:** 대상·금액·안내 버전에 맞게 동의하고 취소·대상 변경·재점검을 구분한다.
- **AC-05 요청:** 활성 요청은 하나만 저장하며 응답 유실 후 상태 조회로 실제 예약을 확인한다.
- **AC-06 취소:** 대기만 취소할 수 있고 승인·완료·실행 경합을 성공으로 오인하지 않는다.
- **AC-07 예정일:** 30일 뒤 예정과 자동 작업 실행·제재·의무·실패에 따른 지연을 구분한다.
- **AC-08 부분 처리:** 취소 또는 최종 파기 중단 뒤 이미 내린 판매·정리된 활동을 확인한다.
- **AC-09 파기 결과:** 개인정보 소거·보존 자료·파일 삭제·환급 예약과 실제 완료를 별도로 확인한다.
- **AC-10 관리자와 제한:** 제한 세션의 요청 허용과 제재 중 예약 실행 보류, 관리자 실행의 재판정을 구분한다.

`DataDeletionServiceTest`·`DataDeletionServiceLegalHoldTest`·`DataDeletionRequestTest`와 앱 `data_privacy_deactivation_gate_test.dart`가 상태·보존·동의·차단 확인의 진입점이다. 현재 코드와 시험 목적·일부 본문을 읽었으며 새 실행 통과로 기록하지 않는다.

검토 버전과 지문은 [문서 갱신 검토 기록](../../../verification/document-refresh-2026-11-22.json)에 남긴다.
