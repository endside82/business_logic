# F09-07. 데이트 차단과 안전 신고 PRD

<!-- release-document: reference -->
> 2026-11-23 후속 변경까지 대조한 현재 서버·앱 소스를 대조했다. 문서 최신화이며 새 제품 시험·운영·실기기 검수 통과 기록이 아니다.

## 입구와 공개 계약

후보 카드와 매칭 목록 메뉴에서 차단 사유 시트를 연다. 본인 프로필의 차단 목록에서는 현재 차단을 보고 해제한다. 채팅 화면에는 상대 사진 신고와 만남 제안 입구가 있지만 차단 사유 시트를 여는 메뉴는 현재 연결돼 있지 않다. 사진 신고와 상대 차단을 같은 동작으로 설명하지 않는다.

DateBlockController 전체는 DATING의 safetyExit 경로다. GET /api/v1/date/blocks는 본인이 데이트에서 건 BLOCKED 행의 List<DateBlockVo>, POST /blocks/{targetUserId}는 201 본문 없음, DELETE는 204 본문 없음이다. 내부 서비스가 만든 VO를 공개 POST 응답으로 기대하지 않는다.

POST는 선택 본문 DateBlockParam(reason·fileReport·reportReason·evidenceFileIds)을 받고 과거 query reason도 지원한다. 본문이 없으면 안전 신고 없이 차단하며 본문 사유가 비어 있고 query 사유가 있으면 보완한다. reason은 최대 200자이며 서버에서 필수는 아니다. 증빙은 최대 5개로 본인 자격을 검증·정규화한다.

## 차단 저장과 대화방 종료

자기 자신 차단을 거절하고 계정 번호 순서로 공유 잠금을 잡은 뒤 가능한 경우 사용자 쌍 잠금을 잡는다. 기존 차단 행은 커밋된 식별자 조회와 행 잠금으로 확인한다. 이미 살아 있는 데이트 출처 차단에 신고 없이 다시 요청하면 CONFLICT다. fileReport=true이면 기존 차단에 안전 신고·증빙을 붙일 수 있으며 같은 신고가 이미 있으면 REPORT_ALREADY_EXISTS로 거절한다. 커뮤니티 출처의 살아 있는 행은 데이트에서 명시적으로 차단하면 DATING으로 올려 기록한다. 해제된 행도 기존 행을 BLOCKED로 되돌려 사유·source·해제 시각을 갱신한다. 따라서 재차단의 createdAt은 반드시 새로운 시각이 아니다.

기존 데이트 차단에 신고만 붙인 요청은 신고·증빙·필요한 분쟁 보류를 연결한 뒤 끝나며, 매치·방 종료·실시간 쌍 차단 이벤트를 다시 실행하지 않는다. 새 차단·재차단·커뮤니티 출처 승격에서는 현재 매치가 있으면 BLOCKED로 바꾸고 두 사람 사이의 ACTIVE MATCH 방과 선택된 비공개 모임 방을 모두 CLOSED 및 closedAt으로 변경한다. 데이터베이스 변경은 같은 차단 거래에 포함된다. 커밋 뒤 PairBlockedEvent를 실시간 제어 발행기에 전달하지만 발행 예외는 로그로 남기는 경로이므로 모든 기기의 즉시 수신까지 보장하지 않는다.

양방향 BLOCKED 조회는 후보 제외와 매칭·채팅 관련 접근 판정에 쓰인다. 차단한 쪽의 목록 API에만 사유를 반환하며 실시간 제어 이벤트의 인자는 사용자 쌍과 닫힌 방 ID다. 사유·안전 신고 내용을 상대에게 알려 주는 알림으로 설명하지 않는다.

## 안전 신고와 증빙 보존

fileReport=true면 DATE_USER 신고를 만들고 reportId·증빙 ID를 차단 행에 연결한다. reportReason이 없거나 알 수 없는 값이면 OTHER를 사용한다. false면 신고·증빙 연결 필드를 비우고 해당 차단 증빙 참조를 남기지 않는다. 증빙 입력의 자격 검증은 그 전에 수행되므로 신고를 끈 요청이라도 잘못된 증빙 값을 무시한다고 보장하지 않는다.

신고가 있고 두 사람 사이에 보류 대상 비공개 모임 에스크로가 있으면 DATE_BLOCK 분쟁 사례와 REPORTER/TARGET 당사자를 만들고 해당 모임을 보류한다. 단순 차단만으로 모든 금전 흐름을 중단하거나 환불 완료로 처리하지 않는다.

차단 증빙의 정리 기준은 연결 신고가 RESOLVED 또는 DISMISSED이고 processedAt에서 1년을 넘긴 경우다. 처리 중 신고는 이 조건에 들지 않는다. 정리 때 차단 행을 잠근 뒤 조건을 다시 확인하고 증빙 필드를 비우며 참조 해제 절차를 거친다. 차단한 날부터 무조건 1년 뒤 삭제하거나 차단 해제 즉시 증빙을 없애는 정책이 아니다. 실제 파일 삭제 완료는 별도 저장소 작업과 보류 조건을 따른다.

## 해제와 다시 보이는 조건

데이트 해제는 본인의 살아 있는 DATING 출처 행만 대상으로 한다. 커뮤니티 출처 행·이미 해제된 행·없는 행은 NOT_FOUND다. 같은 방향의 커뮤니티 차단이 남아 있으면 BLOCKED를 유지한 채 출처를 COMMUNITY로 내려 기록하고, 없으면 UNBLOCKED·unblockedAt을 저장한다. 데이트 목록에서는 COMMUNITY 출처를 제외하므로 데이트 해제 뒤 다른 출처의 차단이 남을 수 있다. 커뮤니티 해제는 COMMUNITY 출처만 풀며 별도로 건 DATING 차단을 풀지 않는다. 차단 기록·신고·증빙을 삭제하거나 매치·채팅방을 자동 복원하지 않는다.

커뮤니티의 통합 차단 목록에도 데이트에서만 건 차단이 DATING 출처와 함께 나온다. 그 줄의 해제는 데이트 API로 보내고 커뮤니티 프로필 사진 주소는 제공하지 않아 이름 첫 글자로 표시한다. 양쪽에서 차단했다면 COMMUNITY 줄 하나로 보이며, 커뮤니티 해제 뒤 데이트 차단이 남으면 DATING 줄로 다시 나온다.

해제 성공 뒤 통합 목록에 상대가 남으면 출처에 따라 “데이트에서 건 차단이 남아 있어 계속 차단됩니다” 또는 “커뮤니티에서 건 차단이 남아 있어 계속 차단됩니다”를 안내한다. 재조회가 끝나기 전에 화면을 떠나면 안내하지 않고, 재조회 실패에는 평소의 해제 안내를 사용한다. 풀 데이트 차단이 없던 NOT_FOUND에는 이 성공 후 조회를 실행하지 않는다.

후보 재노출에는 활성·PUBLIC·유효 인증·선호·기존 매치 행동 제외가 계속 적용된다. 상대가 여전히 나를 차단한 경우도 제외된다. 따라서 해제 성공을 즉시 다시 후보에 나타남 또는 기존 대화 재개로 설명하지 않는다. 직접 선택 API의 기존 상태 처리 한계는 [후보 탐색과 좋아요·넘김](F09-03_candidate_swipe_prd.md)을 따른다.

## 앱의 사유·증빙과 실패 복구

현재 시트는 안전 신고를 기본으로 켜고 사유 선택을 요구한다. 기타면 공백 아닌 설명이 있어야 하며 증빙 업로드 중 제출을 막는다. 최대 5개 증빙을 연결하고 신고를 끄면 현재 증빙 선택을 비운다. 선택 해제가 서버 파일의 즉시 삭제까지 뜻하지는 않는다. 제출 중 중복 실행·미저장 이탈을 제어하고 성공한 경우에만 시트를 닫는다. 실패하면 사유·증빙 입력을 유지한다.

차단 성공은 매칭·후보·차단 목록을 다시 읽게 하며 후보 화면은 현재 카드도 뺀다. 이미 차단된 일반 CONFLICT는 성공으로 처리하되 REPORT_ALREADY_EXISTS는 신고 중복을 안내하고 입력을 유지한다. 차단 명령의 불명 결과에서는 성공 갱신이 자동 실행되지 않는다. 매칭 목록의 차단 대상은 로그인 사용자를 기준으로 상대를 고르며 [매칭 목록과 대화 연결](F09-04_match_list_prd.md)을 따른다.

해제는 확인창에서 본인의 blockedId를 사용한다. 데이트 차단이 없는 NOT_FOUND는 noDatingBlock으로 구분하고, 일반 성공처럼 ‘해제했습니다’라고 알리지 않는다. 성공 또는 반영됐을 가능성이 있는 오류에 대화 목록 변경 신호와 차단 목록 갱신을 수행한다. 실제 해제 성공 뒤에는 통합 차단 목록을 다시 읽어 다른 출처의 차단이 남으면 계속 차단된다는 안내를 한다. 목록은 페이지가 아니며 빈 안내·오류 재시도가 있다. 자료가 있는 상태의 일반 재조회 실패는 기존 자료를 유지하고 다시 시도 안내를 제공하며, 접근 거절은 별도 처리한다. 도움말은 F09-03으로 연결돼 있어 차단 기능 안내와의 차이를 남긴다.

## 수용 기준과 검증 근거

- **AC-01 API 형태:** 본인 List·본문 없는 생성/삭제와 선택 JSON/과거 query 사유를 구분한다.
- **AC-02 차단 거래:** 자기 차단 금지·기존 행/쌍 잠금·매치 BLOCKED·해당 쌍 활성 방 CLOSED를 연결한다.
- **AC-03 신고 연계:** 선택 신고/증빙 자격·OTHER 대체·조건부 에스크로 보류와 참조를 구분한다.
- **AC-04 보존 기준:** 신고 종결 처리 시각부터 1년과 잠금 아래 재검사를 적용하며 해제 즉시 삭제로 설명하지 않는다.
- **AC-05 해제 결과:** 출처별 해제·남은 커뮤니티 차단·noDatingBlock을 구분하고 매치/방 자동 복원 부재와 별도 후보 제외 조건을 유지한다.
- **AC-06 앱 복구:** 사유 필수·업로드/중복 제출 차단·실패 입력 유지와 차단/해제의 서로 다른 재조회를 명시한다.
