## 1. 결론

데이팅의 횡단 안전 보호 기능. 어디서든(후보자 카드/매칭 목록/채팅) 상대를 차단할 수 있고, 차단 시 활성 매치는 `BLOCKED`로, 채팅방은 `CLOSED`로 즉시 전환된다. 차단된 사용자는 후보자 노출과 매칭 액션에서 제외된다(F09-03 양방향 검사). 해제 시 매치 상태는 자동 복원하지 않으며, 다시 후보자 풀에 노출될 수 있다.

프론트 진입과 사용자 조작은 다음 원천 흐름을 기준으로 판단한다.

- **차단 발동**: 어느 화면에서나 발동 가능
  - F09-03 후보자 카드 우상단 ⋮ → "차단" → `DateBlockReasonSheet`
  - F09-04 매칭 목록 카드 ⋮ → "차단" → `DateBlockReasonSheet`
  - (스펙) F09-05 채팅 화면에서도 발동 가능 — 현 화면 코드에는 차단 메뉴 미연결
- **차단 목록 조회**: 데이팅 프로필 화면(F09-02) → "차단 목록" ListTile → `datingBlocks` 라우트
- **커뮤니티 차단 목록에서 해제**: 설정 > 프라이버시·안전 > 차단 목록(`/my/blocks`)에도 데이트에서만 건 차단이 「데이트에서 차단」 표지와 함께 나오고, 그 줄의 "해제"는 데이트 해제(`DELETE /api/v1/date/blocks/{userId}`)로 간다. 그 줄에는 커뮤니티 프로필 사진을 보이지 않고 이름 첫 글자로 그린다(서버도 그 줄의 사진 주소를 주지 않는다)

## 3. 전체 동작 흐름

### 차단 목록 (`date_blocks_screen.dart`)

- **사용자가 보는 것**:
  - `CommunityAppBar('차단 목록')`
  - 목록(`GET /api/v1/date/blocks`)은 데이트에서 건 차단만 싣는다. 커뮤니티에서 건 차단은 데이트 화면도 막지만 여기 나오지 않는다
  - 빈 상태: `AppEmptyState(icon: block_outlined, title: '차단한 사용자가 없습니다', description: '차단된 사용자는 매칭/채팅에 노출되지 않습니다')`
  - 차단 카드 `_BlockCard` — 첫글자 placeholder 아바타(`gray100` 배경) + `blockedNickname or "알 수 없음"` + `reason` (있을 때 2줄까지) + 차단일 `차단일 yyyy.MM.dd`
  - 우측 `AppButton(variant: outline, size: sm, label: '해제')`
- **사용자가 할 수 있는 액션**:
  - "해제" 탭 ▶ `AppDialog.confirm("차단 해제", "{nickname}의 차단을 해제하시겠습니까?", confirmLabel: '해제')`
  - 확인 시 `dateBlocksNotifier.unblockResult(blockedId)` ▶ `DELETE /api/v1/date/blocks/{blockedId}` ▶ 토스트 (성공: "차단을 해제했습니다", 실패: "차단 해제에 실패했습니다"). 이 창구로 풀 차단이 없다는 404(우리 서버 오류 번호가 실린 `NOT_FOUND` — 이미 풀렸거나 커뮤니티에서 건 차단)는 실패를 안내하지 않고 목록을 다시 읽는다
  - 해제에 성공하면 커뮤니티 차단 목록을 한 번 읽어 그 사람이 남았는지 본다. 남아 있으면 성공 토스트 대신 주의 토스트 "커뮤니티에서 건 차단이 남아 있어 계속 차단됩니다"(남은 줄이 데이트에서 건 차단이면 "데이트에서 건 차단이 남아 있어 계속 차단됩니다")를 보인다. 해제한 카드가 목록에서 빠진 뒤에도 뜨고, 그사이 화면을 떠났으면 띄우지 않는다. 이 읽기에 실패하면 평소의 성공 토스트만 보이고, 풀 차단이 없던 404 와 실패한 해제에는 읽지 않는다
- **상태 분기**:
  - 로딩: `CircularProgressIndicator`
  - 에러: `AppErrorState.fromError(onRetry: invalidate)`

### 차단 사유 입력 시트 (`date_block_reason_sheet.dart`)

- **사용자가 보는 것**: 사유 입력 바텀시트 (구현 세부는 본 작업 범위 외 — 단 호출 시그니처는 `DateBlockReasonSheet.show(context, targetNickname: ...)` → `Future<String?>`)
- **반환**: null이면 액션 취소, 문자열이면 사유로 전달

## 4. 제품 규칙

- 후보 카드와 매칭 목록 어디서든 상대를 차단할 수 있다. 차단하면 그 상대와의 매칭은 차단 상태가 되고 그 쌍의 채팅방은 모두 닫힌다. 차단은 양방향으로 적용되어 서로의 후보 노출과 좋아요가 막힌다.
- 차단은 건 곳에서 푼다. 데이트에서 건 차단은 데이트 차단 목록에서, 커뮤니티에서 건 차단은 커뮤니티 차단 목록에서 푼다. 커뮤니티 차단도 데이트 쪽에 함께 걸려 데이트 화면을 막지만, 데이트 차단 목록에 나오지 않고 데이트 해제로 풀리지 않는다.
- 커뮤니티에서 이미 차단한 사람을 데이트에서 또 차단하면 성공하고 데이트에서 건 차단으로 올려 적힌다. 그 뒤 커뮤니티에서 풀어도 데이트 차단은 남는다.
- 이미 데이트에서 차단한 상대를 안전신고 없이 다시 차단하면 서버는 충돌 오류(이미 차단됨)를 주고 아무것도 바꾸지 않는다. 앱은 이를 실패로 안내하지 않고 차단된 상태로 다룬다(차단 성공과 같은 안내와 목록 정리).
- 이미 데이트에서 차단한 상대를 안전신고와 함께 다시 차단하면 신고와 증빙이 기존 차단에 붙어 접수된다. 차단 사유는 이번에 고른 것으로 바뀌고, 차단일과 차단 목록의 줄은 그대로다.
- 그 상대를 데이트 안전신고로 이미 신고한 적이 있으면 요청 전체가 거절된다. 상대는 차단된 채로 남고 이번 신고·증빙은 접수되지 않는다. 앱은 「이미 신고한 대상입니다」 를 보이고 사유 시트를 열어 둔다(신고를 끄고 다시 보낼 수 있다). 후보 카드·매칭 줄은 빼지 않는다.
- 데이트에서 건 차단이 없는 상대를 데이트에서 해제하면(이미 풀림, 커뮤니티에서 건 차단, 차단한 적 없음) 찾을 수 없음 오류다. 앱은 이를 실패로 안내하지 않고 목록을 다시 읽는다.
- 커뮤니티와 데이트 양쪽에서 차단한 사람을 데이트에서 풀면 성공 응답이지만 커뮤니티 차단으로 남는다. 데이트 목록에서는 빠지고 커뮤니티·데이트 화면 모두에서 계속 막히며, 커뮤니티에서 풀어야 다 풀린다.
- 커뮤니티 차단 목록에는 데이트에서만 건 차단도 「데이트에서 차단」 표지와 함께 나온다(커뮤니티 화면도 그 차단으로 막힌다). 그 줄의 해제는 데이트 해제로 간다. 그 줄에는 커뮤니티 프로필 사진을 보이지 않고 이름 첫 글자로 그린다.
- 해제가 한 사람을 다른 목록으로 옮길 수 있으므로, 어느 쪽에서 풀든 데이트·커뮤니티 차단 목록을 둘 다 다시 읽는다.
- 한쪽에서 풀어도 다른 쪽에서 건 차단이 남아 있으면 「해제했다」 고 안내하지 않는다. 해제 뒤 다시 읽은 커뮤니티 차단 목록에 그 사람이 남아 있으면 「데이트에서 건 차단이 남아 있어 계속 차단됩니다」 또는 「커뮤니티에서 건 차단이 남아 있어 계속 차단됩니다」 로 알린다. 다시 읽기에 실패하면 평소의 해제 안내를 보인다.
- 해제해도 매칭과 채팅방은 되살아나지 않는다. 해제는 기록으로 남고(해제 상태) 지워지지 않는다. 해제 뒤에는 후보 풀에 다시 나올 수 있다.
- 차단할 때 사유(200자까지)를 남길 수 있고, 안전신고를 함께 접수할 수 있다(신고 사유를 안 고르면 기타). 증빙 파일은 5개까지다. 안전신고가 딸린 차단은 분쟁 케이스에 포함되어, 처리 중에는 증빙을 지울 수 없고 처리 뒤 1년 보관한다.
- 차단당한 사람에게는 차단 사실도 사유도 알리지 않고, 사유는 차단한 본인만 본다.
- 데이트 차단 목록에는 데이트에서 건 차단만 나온다. 닉네임(없으면 「알 수 없음」), 사유, 차단일이 보이고 해제는 확인을 거친다. 차단한 사람이 없으면 「차단한 사용자가 없습니다」 안내가 나온다.

## 9. 수용 기준

- **AC-01. 후보자 카드에서 차단 (Happy Path)**: Given 활성 매치 없음, 후보 카드 표시 중. When 사용자가 해당 흐름을 실행하면 Then 차단 row 1개. 다음 후보자 fetch에서 해당 사용자 제외 (양방향 차단 필터).
- **AC-02. 매칭 카드에서 차단 → 매치 BLOCKED + 채팅 CLOSED**: Given `Match.MATCHED`, `ChatRoom.ACTIVE`, 메시지 5건 교환됨. When 사용자가 해당 흐름을 실행하면 Then 메시지 송신 차단, 새 매칭 액션 차단.
- **AC-03. 이미 차단한 사용자에게 다시 차단 시도**: Given 원천 시나리오의 시작 조건 When 사용자가 해당 흐름을 실행하면 Then 변동 없음. 안전신고와 함께면 신고·증빙이 기존 차단에 붙어 접수되고, 그 상대를 이미 신고한 적이 있으면 거절된다.
- **AC-04. 차단 해제 — 매치 복원 없음**: Given 과거에 차단한 사용자 1명. 매치는 BLOCKED 상태로 잔존. When 사용자가 해당 흐름을 실행하면 Then 차단 row status=UNBLOCKED 전환(row 보존), 매치/채팅 그대로. `FavoriteService.isBlockedBetween()` 등 소비자는 이 row를 "차단 중" 아닌 이력으로 처리.
- **AC-05. 권한 — 존재하지 않는 차단 해제**: Given 원천 시나리오의 시작 조건 When 사용자가 해당 흐름을 실행하면 Then 변동 없음.
- **AC-06. 차단당한 자의 관점 (간접)**: Given 원천 시나리오의 시작 조건 When 사용자가 해당 흐름을 실행하면 Then 원천 시나리오의 종료 상태와 화면/API 결과
- **AC-07. 신고와의 관계 (간접)**: Given 원천 시나리오의 시작 조건 When 사용자가 해당 흐름을 실행하면 Then 원천 시나리오의 종료 상태와 화면/API 결과
- **AC-08. 차단 시 데이터 보존 정책**: Given 원천 시나리오의 시작 조건 When 사용자가 해당 흐름을 실행하면 Then 원천 시나리오의 종료 상태와 화면/API 결과
