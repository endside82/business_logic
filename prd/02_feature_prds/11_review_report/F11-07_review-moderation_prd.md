# F11-07. 호스트 후기 답변과 임시 숨김 PRD

<!-- release-document: reference -->
> 2026-11-22 현재 소스를 기준으로 갱신했다. 구현 계약의 대조이며 새 앱 실행·운영 검수 통과 기록이 아니다. 현재 할 일은 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)에 있다.

## 현재 역할과 입구

후기 카드의 처리 메뉴에서 답변 작성·수정과 임시 숨김·해제를 실행한다. 앱은 `revieweeId == currentUserId`인 비작성자에게 호스트 콜백을 준다. 서버의 답변 작성·숨김·해제는 현재 이벤트의 호스트인지 검사하며, 답변 수정은 답변에 저장된 `hostUserId`를 검사한다. 이 권한 차이를 단일 조건으로 축약하지 않는다.

## 답변 생성과 수정

`POST /api/v1/reviews/{reviewId}/reply`는 삭제되지 않은 후기와 현재 호스트를 확인하고, 살아 있는 답변이 있으면 `REVIEW_REPLY_ALREADY_EXISTS`로 거절한다. 본문은 공백만 있는 값이 불가하고 최대 1000자다. 성공은 201 `ReviewReplyVo`, 작성자 알림은 답변 식별자로 outbox에 한 번 등록한다. 알림 발송·수신 완료와 outbox 등록은 구분한다.

`PUT`은 기존 답변의 호스트 본인이고 `allowEdit=true`이며 생성 후 24시간 경계 이내여야 한다. 정확히 24시간인 시점까지는 열려 있고 그 뒤에는 `REVIEW_REPLY_EDIT_WINDOW_EXPIRED`다. `GET`은 답변 호스트와의 차단 관계가 있으면 답변 없음으로 처리하며, 조회자 기준 `canEdit`를 계산한다. 답변 삭제 API는 공개 컨트롤러에 없다.

앱은 새 답변과 수정 호출을 구분한다. 수정 선택 직전에 GET으로 현재 본문과 권한을 다시 읽고, 허용된 응답으로 시트를 채운다. 이미 지난 24시간을 오래된 목록의 true만으로 통과시키지 않는다. 같은 후기의 재확인 중 중복 진입도 막는다. 서버가 `canEdit`를 주면 앱은 그 값을 우선하고 없을 때 `allowEdit`·생성 시각으로 판정한다.

## 임시 숨김과 운영팀 검토 요청

`POST /api/v1/reviews/{reviewId}/hide`는 `{reasonCode, reasonText, autoEscalate}`를 받는다. 사유는 `HARASSMENT`, `DEFAMATION`, `SPAM`, `OFF_TOPIC`, `FAKE_REVIEW`, `OTHER` 중 하나가 필수이고 자유 글은 선택·최대 500자다. `OTHER`에도 글 필수 조건은 없다. 이미 숨긴 후기는 `REVIEW_ALREADY_HIDDEN`이다.

**현재 앱 시트·앱 요청 모델·서버 모두 `autoEscalate` 기본값은 false다.** 앱에서 허위 후기 사유를 선택하면 true로 바꾸지만 사용자가 체크를 해제할 수 있다. 따라서 허위 후기를 골랐다는 이유만으로 신고가 항상 생기는 것은 아니다.

true이고 같은 호스트의 해당 후기 신고가 없으면 플랫폼 정책·플랫폼 관할의 `REVIEW` 신고를 `PENDING`으로 만든다. 사유는 `INAPPROPRIATE`, 허위 후기일 때 우선 검토다. 기존 신고가 있으면 새로 만들지 않는다. 기존 신고 중 `PENDING`, `IN_REVIEW`, `ESCALATED`가 하나도 없으면 숨김은 성공하되 `escalationNotAccepted=true`로 검토 요청이 접수되지 않았음을 알린다. 앱은 이를 별도 경고 문구로 표시한다.

숨김은 후기의 별점을 신뢰점수에서 제외하는 동작이 아니다. 연결 클럽의 후기 적립 회수 신호는 발행하지만 후속 소비 완료를 이 API 성공만으로 단정하지 않는다. [목록의 본문 마스킹](F11-02_review-list_prd.md)의 조회자별 반환과 앱 숨김 안내가 적용된다.

## 해제와 앱 실패 처리

`POST /api/v1/reviews/{reviewId}/unhide`는 현재 호스트만 호출할 수 있고 숨김 상태가 아니면 `REVIEW_NOT_HIDDEN`이다. 성공 시 `temporarilyHidden=false`로 바꾸고 사유·숨긴 사람·시각을 비운다. 기존 자동 신고를 철회하거나 마일리지를 재적립하는 호출은 없다. 서버는 `ReviewVo`를 반환하지만 앱은 이 응답 본문을 사용하지 않고 목록을 다시 읽는다.

앱은 해제 확인 후 호출하고 성공하면 목록을 갱신한다. 답변·숨김 시트는 제출 중 중복 클릭을 막고, 실패 시 입력을 유지한다. 답변 생성에서 이미 존재 오류는 목록 재조회 후 시트를 닫으며, 결과를 확정할 수 없는 오류는 목록 확인 안내와 함께 시트를 유지한다. 답변 수정도 실패 시 시트를 유지하며 확정된 상태 변화는 목록을 갱신한다.

## 수용 기준과 검증 근거

- **AC-01 답변 작성:** 현재 호스트가 비어 있지 않은 1000자 이하 본문을 제출하면 201로 답변을 반환하고 중복 생성을 거절한다.
- **AC-02 수정 전 재확인:** 앱은 GET으로 현재 답변을 다시 읽고 수정 가능할 때만 그 본문으로 시트를 연다. 중복 재확인 진입을 막는다.
- **AC-03 수정 기간과 권한:** 답변에 저장된 호스트 본인·allowEdit·24시간 경계를 서버에서 검사하고 범위를 벗어나면 거절한다.
- **AC-04 숨김 기본값:** 시트·요청 모델·서버의 자동 검토 요청 기본값은 false다. 허위 후기 선택으로 켜져도 사용자가 끌 수 있다.
- **AC-05 자동 신고 중복:** 검토 요청을 켜면 기존 신고를 먼저 확인한다. 종결 신고만 있으면 숨김 성공과 검토 미접수를 구분해 표시한다.
- **AC-06 숨김 해제:** 현재 호스트가 확인 후 해제하면 숨김 정보가 비워지고 목록이 갱신된다. 기존 신고 철회나 마일리지 재적립은 포함하지 않는다.
- **AC-07 시트 오류 복구:** 확정된 답변 중복은 목록을 갱신하고 닫는다. 결과 불명·수정·숨김 실패는 해당 입력을 유지하며 원인 또는 확인 안내를 표시한다.

근거는 현재 서버 계약·권한과 앱 메뉴·재확인·시트 처리다. 이번에 제품 시험을 새로 실행하지 않았다.
