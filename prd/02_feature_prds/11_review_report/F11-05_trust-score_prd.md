# F11-05. 신뢰점수 계산과 본인 변동 이력 PRD

<!-- release-document: reference -->
> 2026-11-22 현재 소스를 기준으로 갱신했다. 구현 계약의 대조이며 새 앱 실행·운영 검수 통과 기록이 아니다. 현재 할 일은 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)에 있다.

## 조회 입구와 권한

본인 라우터는 로그인 사용자의 식별자로 `TrustScoreScreen(isMyScore: true)`를 연다. 앱은 본인 점수 단축 주소를 쓰고 이력 구간을 표시한다. 타인 모드 분기는 있지만 현재 앱 소스에서 이 화면을 타인 모드로 생성하는 호출자는 없다. 분기 존재를 실제 타인 화면 입구로 세지 않는다.

| 호출 | 반환과 접근 |
|---|---|
| `GET /api/v1/users/me/trust-score` | 본인 `TrustScoreVo` |
| `GET /api/v1/users/{userId}/trust-score` | 대상이 다른 사람이면 양방향 차단과 이용 가능 계정을 확인하고, 프로필 상세 접근 권한도 검사한다. 거절 시 `USER_NOT_FOUND` |
| `GET /api/v1/users/{userId}/trust-score/history?days=N` | 본인만 허용, 타인 요청은 `FORBIDDEN`. `ScoreHistoryVo` 반환 |

「차단만 없으면 다른 사람의 점수를 항상 볼 수 있다」는 과거 설명은 현재 상세 접근 검사를 빠뜨린다. 화면 모드와 서버의 소유자 검증은 별도로 적용된다.

## 현재 조회값과 저장 이력

점수 GET은 활동·인증·감점을 현재 자료로 계산하고 저장된 `manualAdjustment`를 더해 응답한다. 조회 자체가 `TrustScore`나 스냅샷을 갱신하는 메서드는 아니다. `recalculate`가 호출될 때 행을 확보·잠금 후 구성 점수·총점·등급·개수를 저장하고 이력 저장을 요청한다. 따라서 현재 조회값과 마지막 저장·이력이 항상 같다고 보장하지 않는다.

후기 작성·수정·삭제는 재계산을 부른다. 하지만 아래 총점 공식에 받은 후기 평균 별점이 직접 들어가는 것은 아니다. 후기 평균과 받은 후기 개수는 응답의 별도 정보다. 임시 숨김은 후기를 삭제하거나 별점을 총점에서 별도로 차감하는 처리도 아니다.

## 실제 점수 계산식

총점은 `0.5 × activityScore + 0.25 × verificationScore − 0.25 × penaltyScore + manualAdjustment`를 소수 한 자리로 반올림한 뒤 0~100으로 제한한다. 원래 구성 점수와 총점에 반영된 기여도를 구분한다.

| 구성 | 현재 계산 |
|---|---|
| 활동 | `ATTENDING` 참석 수를 50회에서 상한 100, 주최 수를 20회에서 상한 100으로 환산한다. 참석 환산값 ×0.4 + 주최 환산값 ×0.3 + 고정값 50×0.15 + 50×0.15 |
| 인증 | 이메일 인증 30, 비어 있지 않은 휴대전화 30, 프로필 사진 10, 자기소개 5, 이름 5, 소셜 로그인 1개면 10·2개 이상이면 20 |
| 감점 | 사용자 대상 신고 중 `RESOLVED` 또는 `ESCALATED`이며 범위가 `PLATFORM_POLICY` 또는 `PRIVATE_INTEREST`인 건수 ×20, 최대 100 |
| 수동 조정 | 저장된 누적 조정값을 가중치 없이 더하며 일반 재계산에서도 유지 |

휴대전화 항목은 현재 계산기의 문자열 존재 조건이지 별도 전화 인증 성공 검사를 뜻하지 않는다. 참석 수도 이 계산기에서는 `ATTENDING` 집계이며 실제 체크인 횟수라고 바꾸어 쓰지 않는다. 모든 신고나 지역 모임 내부 신고가 감점 원천인 것은 아니다. 해당 신고 한 건의 원시 감점 20은 가중치 반영 후 총점 5 감소에 해당한다.

현재 상수대로 계산하면 활동은 이력이 없어도 15, 최대 85다. 인증 최대 100·감점 0·수동 조정 0인 경우 총점 상한은 67.5다. 이는 현재 코드에서 계산한 범위이며 등급 정책을 새로 결정한 것이 아니다.

## 등급과 구성 응답

등급은 40 미만 BRONZE, 40 이상 SILVER, 60 이상 GOLD, 75 이상 PLATINUM, 90 이상 DIAMOND다. 서버는 다음 등급 기준을 `nextGradeScore`로 주고 최고 등급이면 null이다. 앱은 이 값을 사용해 다음 등급까지 필요한 점수를 표시한다.

응답에는 사용자 식별자, 후기 평균·개수, 참석·주최 개수, 총점·등급·다음 기준·배지·breakdown이 있다. breakdown은 `activityScore`, `verificationScore`, `penaltyScore`, `manualAdjustment`, 세 `*Weight`, `activityContribution`, `verificationContribution`, `penaltyDeduction`을 제공한다. 현재 앱은 활동·인증·감점과 비중·기여도 이름을 한국어로 매핑하고 비중은 퍼센트로 표현한다. 과거의 구성 키 전체 불일치를 현재 미해결로 남기지 않는다.

배지는 후기 수 10/50, 참석 수 5/20/50, 주최 수 1/5/20, 총점 60/75/90의 구간에서 각 계열의 가장 높은 항목을 고른다. 받은 후기 개수는 삭제되지 않은 행을 기준으로 센다.

## 스냅샷과 기간 선택

첫 재계산에는 스냅샷을 남기고 이후에는 마지막 저장 스냅샷의 총점과 절댓값 차이가 1.0 이상일 때만 추가한다. 직전 API 조회나 매번의 재계산값과 비교하는 것이 아니다. 이력은 날짜·총점·등급·구성 점수·변경 사유를 저장하며 매일 한 건의 연속 기록이라고 보장하지 않는다.

이력 API의 days 기본값은 90이고 최대 365만 적용한다. 현재 컨트롤러에는 양수 최소값 검증이 없다. 조회는 오늘에서 days를 뺀 날짜보다 뒤의 행을 날짜 오름차순으로 받는다. 추세는 그 조회 결과 중 최근 30일에 속하는 행이 2개 이상일 때 처음과 마지막 총점 차이로 판단한다. +5 이상은 UP, -5 이하는 DOWN, 나머지와 표본 부족은 STABLE이다. 7일 조회의 추세가 조회하지 않은 30일 전체를 다시 읽어 계산하는 것은 아니다.

앱 초기 선택은 7일이며 7·30·90일로 바꾸면 해당 provider 키로 다시 조회한다. 본인 식별자가 없는 경우 이력을 표시하지 않는다. 빈 이력은 안내 카드, 조회 오류는 재시도를 제공한다. 본인 점수는 사람 탐색 변경, 타인 점수·이력은 대상 접근 변경 신호를 구독한다.

## 데이팅 내부 활용의 동의 경계

`MatchScoringService.calculateMatchScore`는 양쪽 `communityDataOptIn`이 모두 true일 때만 관심사 태그와 신뢰점수 유사도 성분을 사용한다. 신뢰점수의 기본 가중치는 0.15다. 한쪽이라도 동의하지 않으면 해당 두 성분을 빼고 남은 가중치 합으로 나눈다. 미동의를 0점 벌점으로 처리한다고 설명하지 않는다. 이 내부 계산 조건과 커뮤니티 점수 조회의 상세 접근 권한은 서로 다른 검사다.

## 현재 제한과 확인 범위

| 분류 | 현재 경계 | 문서 처리 |
|---|---|---|
| Risk | 조회 재계산과 영속 재계산이 분리돼 현재 점수와 마지막 스냅샷이 다를 수 있다. | 모든 조회를 새 이력 적재로 쓰지 않는다. |
| Gap | 타인 화면 생성 호출자가 없고 수동 조정 없이 현재 기본 공식의 최대값은 67.5다. | 모든 등급·화면 경로가 일반 활동만으로 도달 가능하다고 설명하지 않는다. |
| Gap | manualAdjustment의 한국어 이름 매핑이 없고 음수 일반 항목은 값 표시 함수에서 절댓값으로 보일 수 있다. | 구성 이름 전체 불일치와 구분해 남은 표시 한계를 기록한다. |
| 미검증 | 실제 계정 조회·재계산·운영 조정·데이팅 계산을 이번에 실행하지 않았다. | 소스 계약 대조만 완료한 것으로 기록한다. |

## 수용 기준과 검증 근거

- **AC-01 조회 권한:** 본인·대상 이용 가능 상태·양방향 차단·프로필 상세 접근을 검사하고 타인의 이력은 거절한다.
- **AC-02 조회와 저장 구분:** 현재 GET은 계산해 반환하고 스냅샷을 적재하지 않는다. 영속 재계산만 구성값 저장과 스냅샷 판정을 수행한다.
- **AC-03 계산식:** 활동·인증·감점의 현재 원천과 0.5/0.25/0.25 비중, 누적 수동 조정·반올림·0~100 제한을 적용한다.
- **AC-04 감점 범위:** 해당 상태·범위의 사용자 신고만 원시 감점에 포함하고 건당 원시20과 총점 반영5를 구분한다.
- **AC-05 등급과 구성:** 서버의 등급·nextGradeScore와 구성 키를 사용하며 앱의 현재 매핑 및 수동 조정 표시 경계를 기록한다.
- **AC-06 스냅샷:** 최초 또는 마지막 스냅샷 대비 1점 이상 변동일 때 기록하고 매 조회·매일 기록을 보장하지 않는다.
- **AC-07 기간과 추세:** 본인 7·30·90일 화면 선택을 해당 조회로 연결하고 반환된 이력 안의 최근30일 표본으로 추세를 계산한다.
- **AC-08 데이팅 동의:** 양쪽 동의가 있을 때만 신뢰점수·태그 성분을 사용하고 미동의 때 남은 가중치로 정규화한다.

근거는 현재 서버 계산·권한·이력과 앱 호출·기간 선택·값 표시다. 이번에 제품 시험을 새로 실행하지 않았다.
