# F10-05. 타 사용자 가능 시간 공개 기능 폐기와 비공개 경계 PRD

<!-- release-document: reference -->
> 2026-11-22 소스 대조. 현재 계약과 검증 경계이며 새 제품 실행 기록이 아니다. 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 현재 상태와 폐기된 기능

이 기능 ID는 **폐기된 타 사용자 가능 시간 공개 조회의 추적 항목**이다. 공개 슬롯·친구 슬롯·상호 후기 기반 친구 판정으로 다른 사람의 가능 시간을 읽는 기능은 현재 제품 계약이 아니다. 과거 시나리오를 실행해야 할 출시 필수 기능으로 복구하지 않는다.

소스 참조표의 옛 `/api/v1/users/{userId}/availabilities/public`·`friends` 두 행도 retired이고 연결 함수가 없다. 서비스·모델과 앱 API에 공개/친구 가용성 입력·조회가 없으며 저장 visibility 컬럼/enum의 호환 모델도 제거됐다. 새 공개 기능은 공유 동의·대상·회수 범위를 먼저 결정하는 별도 제품 작업이다.

## 코드 위치

현재 `AvailabilityController` 전체 창구, `AvailabilityService`의 본인 목록/단건/수정/삭제, `Availability` 모델, `AvailabilityParam`·`RecurringParam`, 앱 `availability_api.dart`와 입력 화면을 대조했다. 옛 함수나 API를 새로 만들지 않았다.

<!-- source-references:start -->
**설계 철회.** 타 사용자 가용시간 조회의 두 옛 기록은 삭제된 같은 파일을 가리킨다. 복구 대상이 아니며 현재 구현 근거에서 제외한다.
<!-- source-references:end -->

## 현재 본인 전용 계약

생성은 로그인 principal을 소유자로 저장하고 목록은 같은 userId로 조회한다. 단건 읽기는 소유자를 검사하고 수정·삭제·반복 규칙 조회는 본인 ID 조합으로 판정한다. 클라이언트에서 타인 userId나 PUBLIC/FRIENDS를 선택해 요청하는 필드는 없다.

가능 시간은 [본인 가능 시간 관리](F10-03_single-availability-crud_prd.md)와 [반복 가능 시간 관리](F10-04_recurring-availability-rule_prd.md)에서 다룬다. 본인이 ICS 파일을 내보내는 동작은 사용자가 선택한 파일 전달이며, 타인에게 상시 조회 권한을 주는 API와 다르다.

## 관심인 달력과 구분

월 달력의 관심인 보기는 별도 공개 모임 자료를 합친다. 해당 카드가 모임 상세로 연결돼도 상대방의 개인 가능 시간·반복 규칙을 읽는 기능이 생기지 않는다. `ownerUserId`가 있는 모임 카드와 AVAILABILITY 레코드 소유권을 같은 공유 모델로 해석하지 않는다.

## 현재 제한과 확인 범위

| 구분 | 현재 경계 |
| --- | --- |
| 기준 | 기능 없음은 구현 누락이 아니라 폐기된 공개 정책의 현재 상태다. 기능 수와 활성 기능 수를 구분한다 |
| 미검증 | 현재 소스·요청 모델·폐기 참조를 대조했다. 익명/타계정 실제 HTTP 보안 시험을 새로 실행한 기록은 아니다 |

## 수용 기준과 검증 근거

- **AC-01 폐기 상태:** 공개/친구 조회를 현재 구현이나 남은 출시 과제로 표시하지 않는다.
- **AC-02 요청:** 가용성 요청에 타인 소유자·공개 범위 입력을 추가하지 않는다.
- **AC-03 소유권:** 현재 본인 목록·단건·수정·삭제·반복 규칙의 권한 경계를 유지한다.
- **AC-04 관심인:** 관심인 공개 모임과 개인 가능 시간 공유를 구분한다.
- **AC-05 추적:** 옛 두 API 참조를 retired로 보존하고 실제 실행 확인과 소스 확인을 구분한다.

위 항목은 비공개 경계의 문서 수용 기준이며 폐기된 기능의 실행 통과 수가 아니다.
