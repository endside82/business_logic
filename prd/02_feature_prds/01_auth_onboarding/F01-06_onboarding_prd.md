# F01-06. 온보딩 PRD

<!-- release-document: reference -->
> 2026-11-22 현재 서버·앱 소스 대조. 현재 작업은 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 코드·시험 목적 확인과 실제 실행·외부 수신·운영 환경 검증을 구분한다.

## 결론

가입 후 웰컴 → 프로필 → 관심사 → 위치를 거쳐 일반 이용으로 이동한다. 단계별 진행은 기기에 저장하고 마지막에는 서버에도 온보딩 완료를 요청한다. 각 단계는 건너뛸 수 있지만 건너뛰기가 이미 저장한 프로필·태그·주소를 취소하는 것은 아니다. 서버 완료 요청 실패가 앱의 완료 상태로 가려질 수 있어 완료 표시와 데이터 저장을 나누어 확인해야 한다.

## 진입과 재개

새 로그인에서는 서버의 신규 여부가 온보딩 진입을 결정한다. 신규이면 로컬 진행을 지우고 시작하며 기존 사용자이면 로컬 완료를 표시한다. 같은 로그인 세션으로 앱을 다시 시작할 때는 서버의 완료 표시와 로컬 완료 여부를 함께 보고, 미완료이면 웰컴·프로필·태그·위치 중 다음 미완료 단계를 고른다. 따라서 ‘언제 다시 로그인해도 중간부터 재개’라고 보장하지 않는다.

완료 후 이동은 라우터가 처리한다. 일반적으로 홈으로 이어지지만 계정 제한·약관·보관된 초대/이동 대상의 조건을 함께 따른다. 계정이 실제로 없는 비로그인 사용자에게 네 단계로 가입을 대신시키는 흐름은 아니다.

## 네 단계의 실제 동작

| 단계 | 현재 동작 | 성공·건너뛰기·실패 |
|---|---|---|
| 웰컴 | 서비스 소개 페이지를 넘김 | 마지막 다음 또는 건너뛰기로 로컬 표시 후 프로필로 이동. 서버 저장 없음 |
| 프로필 | 가입 때 정한 닉네임·기존 소개를 표시하고 사진·닉네임·소개를 저장 | 저장 성공 뒤 로컬 표시 후 관심사로 이동. 건너뛰기는 이 단계의 편집값을 저장하지 않음 |
| 관심사 | 서버 카탈로그에서 선택, 3개 이상이면 다음 | 태그를 순서대로 저장한 뒤 위치로 이동. 건너뛰기는 새 태그를 보내지 않음. 중간 실패는 일부 저장될 수 있음 |
| 위치 | 현재 위치 감지 또는 주소 검색과 좌표 확인 | 집 유형의 기본 주소를 저장한 뒤 완료. 건너뛰기는 새 주소 없이 완료 절차를 진행 |

## 프로필과 사진

닉네임은 앱에서 2~16자, 소개는 200자까지 입력한다. 중복 닉네임이나 저장 오류는 안내하고 머문다. 화면 상단에는 뒤로 버튼이 없지만 이를 모든 시스템 뒤로 가기를 차단한다는 설명으로 확대하지 않는다.

사진은 갤러리에서 최대 512×512로 축소 요청해 선택하며, 프로필 용도로 업로드 URL 발급 → 객체 업로드 → 업로드 완료 요청을 거친다. 완료된 파일 키를 프로필 저장에 사용하고 서버는 소유자와 프로필 이미지 용도를 확인한다. 사진 업로드 성공과 프로필에 연결된 상태는 다르다. 업로드 중에는 일반 다음을 막고 실패하면 오류를 안내한다. 사진 없이 닉네임 조건을 맞춰 진행할 수 있다.

## 관심사와 위치

관심사 최소 3개는 일반 다음의 앱 조건이며 건너뛰기가 가능하다. 서버 상한 20개와 순차 저장·중복 재시도의 차이는 [관심사 태그 관리](F01-07_preference-tags_prd.md)를 따른다.

위치 권한을 거부하거나 위치 서비스가 꺼져 있어도 주소 검색 또는 건너뛰기를 사용할 수 있다. 주소 검색은 실제 좌표 확인까지 성공해야 저장할 수 있다. GPS 좌표를 얻은 뒤 주소 변환만 실패하면 좌표 설명 문자열을 주소로 유지할 수 있다. 이를 정상 도로명 주소 확인으로 표시하지 않는다. 주소는 집 유형·기본 주소로 요청하며 기존 집 주소가 있으면 중복 유형 오류를 받을 수 있다. 실패 시 재시도나 건너뛰기를 선택한다.

## 완료 처리의 경계

현재 앱은 먼저 로컬 완료를 표시한 뒤 서버 완료 요청을 보내고, 그 결과 객체의 성공/실패를 검사하지 않은 채 앱의 사용자 정보를 완료로 바꾼다. 서버는 본인 계정에 완료 표시를 저장하며 이미 완료한 요청은 그대로 성공한다. 앱에서 홈이 열리거나 로컬 완료가 참이라는 사실만으로 서버 완료 기록까지 확인됐다고 보지 않는다.

프로필·태그·주소와 완료 표시는 각각 다른 요청이다. 어느 단계에서 화면을 나가거나 건너뛰어도 이미 서버에 저장된 내용을 되돌리지 않는다. 업로드한 사진도 프로필에 연결하기 전에 건너뛰면 연결 완료로 간주하지 않는다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 영향·다음 확인 |
|---|---|---|
| Gap | 서버 완료 실패 결과 미확인 | 로컬 완료를 먼저 쓰고 서버 결과를 검사하지 않아 앱과 서버의 완료 표시가 다를 수 있음 |
| Risk | 재시작과 새 로그인의 차이 | 로컬 단계 재개와 신규 여부에 따른 로그인 초기화는 다르다. 서버 완료 표시와 신규 응답이 충돌하는 경우를 포함해 확인해야 함 |
| Risk | 단계별 부분 저장 | 태그 순차 요청의 일부 성공, 주소 응답 유실 뒤 집 유형 중복 등은 전체 롤백으로 복구되지 않음 |
| Risk | 저장 중 건너뛰기 | 사진 업로드·프로필/태그/주소 저장과 건너뛰기가 하나의 취소 작업으로 묶이지 않는다. 이동 전후 실제 저장 결과 확인 필요 |
| 미검증 | 실제 기기·지도·사진 | 현재 코드와 관련 시험 목적을 확인했으며 실제 권한 거부·외부 지도·업로드·재시작 여정을 새로 실행하지 않음 |

## 수용 기준과 검증 근거

- **AC-01 진입:** 신규 로그인과 같은 세션의 앱 재시작에서 온보딩 진입·다음 미완료 단계가 어떻게 결정되는지 구분한다.
- **AC-02 웰컴:** 페이지 넘김·마지막 다음·건너뛰기는 로컬 표시 뒤 프로필로 이어지며 서버 계정을 새로 만들지 않는다.
- **AC-03 프로필:** 닉네임·소개를 저장하고 중복·오류에서는 성공 단계로 이동하지 않는다. 건너뛰기는 편집 저장과 구분한다.
- **AC-04 사진:** 선택 취소·업로드 실패·업로드 완료·프로필 연결을 구분하고 업로드 중 일반 다음을 막는다.
- **AC-05 관심사:** 3개 조건과 건너뛰기, 20개 상한·순차 저장·중간 실패·중복 재시도를 구분한다.
- **AC-06 위치:** 권한 거부 후 주소 검색을 사용할 수 있고 좌표 확인 실패는 저장하지 않는다. 좌표만 있는 경우와 도로명 주소 확인을 구분한다.
- **AC-07 주소 결과:** 집 기본 주소 저장·중복 유형·응답 유실·건너뛰기를 확인하고 이미 저장한 주소를 자동 삭제로 취급하지 않는다.
- **AC-08 완료 동기화:** 앱 완료·로컬 기록·서버 완료를 각각 확인한다. 서버 실패를 무시하는 현재 차이는 통과로 처리하지 않는다.
- **AC-09 중간 이동:** 저장 중 건너뛰기·뒤로 가기·앱 재시작 후 부분 데이터와 단계가 일치하는지 확인한다.
- **AC-10 최종 이동:** 네 단계 완료와 모두 건너뛰기를 별도로 확인하고 홈·보관된 이동 대상·약관·계정 제한 조건에 맞게 이동한다.

관심사 서버 시험과 인증 상태 전환 시험은 일부 경계의 확인 위치다. 파일 존재나 이전 가입 E2E의 홈 도달만으로 사진·주소·태그 상한·서버 완료 동기화를 모두 통과했다고 기록하지 않는다.
