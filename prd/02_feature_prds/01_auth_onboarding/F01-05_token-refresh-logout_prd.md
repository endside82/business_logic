# F01-05. 토큰 갱신과 로그아웃 PRD

<!-- release-document: reference -->
> 2026-11-22 현재 서버·앱 소스 대조. 현재 작업은 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 소스 대조·시험 목적 확인과 실제 시험 실행·기기 검수를 구분한다.

## 결론

접근 토큰 만료 뒤에는 같은 로그인 세션의 요청들이 한 번의 갱신을 함께 기다린다. 통신 장애·서버 오류·경합 응답만으로 로그인 상태를 지우지 않으며, 현재 갱신 토큰에 대한 명시적인 서버 거절과 구분한다. 로그아웃은 앱의 현재 세션을 먼저 끝내고 서버의 해당 기기 세션·푸시 등록을 정리한다. 다른 기기의 새 로그인은 기존 세션을 대체하지만, 늦게 도착한 옛 로그아웃이 새 세션까지 지우는 계약은 아니다.

## 실제 진입과 복귀

1. 토큰 갱신 전용 화면은 없다. 로그인 상태의 API 요청이 갱신 가능한 401을 받거나 사용자 정보를 수동 갱신할 때 같은 세션 갱신 처리를 사용한다.
2. 서버가 현재 세션의 갱신 토큰을 명확히 거절한 경우에는 세션을 종료한다. 로그인·갱신 요청 자체의 401은 다시 자동 갱신하지 않는다.
3. 이미 다른 요청이 토큰을 바꿨다면 그 새 토큰으로 원래 요청을 한 번 다시 보낸다. 갱신 중 계정이 바뀌거나 세션이 끝났으면 옛 결과를 새 계정에 적용하지 않는다.
4. 로그아웃 입구는 전체 메뉴 → 설정 → 계정의 ‘로그아웃’이다. 확인 창에서 취소하면 현재 세션을 유지한다.
5. 확인하면 종료 기록을 남기는 절차를 거쳐 앱 세션을 끝내고 로그인 화면으로 간다. ‘로그아웃되었습니다’ 안내는 한 번 표시한다. 온보딩 기록 정리·푸시 해제·서버 로그아웃은 이전 세션에 묶인 후속 작업이다.
6. 서버 정리가 실패해도 앱의 로그아웃을 되돌리지 않는다. 뒤로 가거나 늦은 갱신 응답이 도착해도 이전 계정 화면·토큰이 복구되지 않아야 한다.

## 갱신과 세션 규칙

- 접근 토큰은 1시간, 갱신 토큰은 30일이다. 정상 갱신은 같은 세션 번호를 유지하며 갱신 토큰과 만료를 새로 정한다. ‘앱을 한 달 안 켜도 항상 자동 로그인’이라는 보장은 아니다.
- 새 로그인은 이전 로그인 세션을 대체한다. 정상 토큰 갱신은 기존 세션을 회전시키는 동작이므로 그 자체를 다른 기기의 새 로그인과 혼동하지 않는다.
- 서버는 분산 잠금과 회원·토큰 행 잠금으로 갱신을 조정한다. 동시에 잠금을 얻지 못하면 경합 오류를 돌려준다. 앱은 이를 토큰 만료로 처리하지 않는다.
- 회전 직후 응답을 잃은 경우 직전 갱신 토큰으로 현재 세션의 토큰을 다시 받을 수 있다. 새 접근 토큰이 보호된 API에 도착하면 직전 갱신 토큰 기록을 지운다. 오래된 토큰을 계속 사용할 수 있다는 뜻은 아니다.
- 앱은 새 토큰 쌍의 저장을 확인한 뒤 사용한다. 저장 지연·실패나 세션 전환 때는 새 쌍을 무조건 적용하지 않는다.
- 정지·차단 계정은 갱신 때 제한된 토큰과 계정 제한 정보를 받을 수 있다. 이를 무조건 로그아웃 또는 정상 기능 복구로 설명하지 않는다. 탈퇴 상태 등 명시적 거절과 구분한다.

## 로그아웃의 범위

서버는 서명과 회원·세션 정보를 확인한 뒤 해당 세션 행을 지우고 그 세션의 푸시 등록을 비활성화한다. 이미 지워진 세션의 반복 요청은 새 로그인 세션을 지우지 않는다. 접근 토큰을 Redis 블랙리스트에 개별 등록하는 방식이라는 옛 설명은 현재 로그아웃 구현과 다르다. 보호된 API는 회원의 인증 버전과 로그인 세션의 존재를 확인한다.

로그아웃 전용 검사는 접근 토큰 만료 뒤 30일까지 서명된 토큰으로 해당 세션 정리를 허용한다. 이를 일반 API의 접근 토큰 수명 연장으로 해석하지 않는다. 서버 DB 정리 뒤 실시간 해지 알림을 비동기로 보낸다. 앱의 성공 안내·서버 세션 삭제·푸시 등록 정리·실시간 연결 종료는 각각 확인해야 한다.

## 상태별 결과

| 조건 | 현재 처리 | 사용자 결과·복구 |
|---|---|---|
| 접근 토큰 만료, 갱신 토큰 유효 | 같은 세션의 갱신 공유 후 원래 요청 재전송 | 원래 화면에서 결과 확인 |
| 통신 오류·서버 오류·잠금 경합 | 세션 유지, 요청에 실패 반환 | 연결·서버 복구 뒤 다시 시도 |
| 현재 토큰의 명시적 만료·무효·대체·탈퇴 거절 | 해당 세션 종료 | 로그인 또는 다른 기기 로그인 안내 |
| 정지·차단 계정 | 제한된 갱신 응답과 계정 제한 처리 | 제한 화면의 허용된 업무만 진행 |
| 로그아웃·계정 전환 뒤 늦은 응답 | 이전 세션 결과 폐기 | 새 계정에 토큰·업무 결과를 적용하지 않음 |
| 로그아웃 확인 취소 | 요청하지 않음 | 현재 화면·로그인 유지 |
| 로그아웃 확인, 서버 정리 실패 | 앱 세션 종료 유지 | 로그인 화면, 서버 정리 완료와 구분 |

## 현재 제한과 확인 범위

| 판정 | 항목 | 영향·다음 확인 |
|---|---|---|
| Risk | 앱 종료와 서버 정리의 차이 | 서버 호출이 실패·유실되면 앱의 로그아웃 안내만으로 서버 세션·푸시·실시간 연결이 모두 정리됐다고 볼 수 없음 |
| Risk | 결과 유실과 저장 장애 | 회전 응답 유실·디스크 지연·계정 전환이 겹치는 경우를 구분해야 함. 모든 갱신 오류를 만료로 바꾸면 재로그인을 강요함 |
| 미검증 | 현재 기기·서버 실행 | 이번에는 코드와 시험 목적을 확인했다. 실제 두 기기 교체·통신 단절·프로세스 종료·푸시·소켓 결과는 새로 실행하지 않음 |

## 수용 기준과 검증 근거

- **AC-01 자동 갱신:** 접근 토큰 만료 뒤 유효한 갱신 토큰으로 같은 화면의 요청 결과를 받는다. 로그인·갱신 요청을 재귀적으로 갱신하지 않는다.
- **AC-02 동시 요청:** 같은 세션의 여러 갱신은 하나의 진행 결과를 공유하고, 이미 교체된 토큰으로 보낸 늦은 401은 현재 토큰으로 재전송한다.
- **AC-03 일시 오류:** 통신·서버·경합 오류에서는 로그인 상태를 보존하고 실패를 호출한 화면에 돌려준다.
- **AC-04 명시적 종료:** 현재 토큰의 만료·무효·다른 기기 대체·탈퇴 거절은 해당 세션을 끝낸다. 다른 계정의 늦은 오류는 현재 세션을 끝내지 않는다.
- **AC-05 회전 응답 유실:** 새 토큰의 응답을 잃으면 직전 토큰으로 복구하되 새 접근 토큰 사용 뒤에는 옛 갱신 토큰을 다시 허용하지 않는다.
- **AC-06 제한 계정:** 정지·차단 상태의 갱신은 제한 화면을 유지하고 일반 기능을 다시 열지 않는다.
- **AC-07 로그아웃 입구:** 전체 메뉴의 설정에서 확인·취소를 구분하고 확인 뒤 로그인 화면과 한 번의 안내를 확인한다.
- **AC-08 서버 정리 범위:** 로그아웃은 그 세션·기기 푸시만 정리한다. 반복 요청이나 옛 접근 토큰으로 새 로그인 세션을 지우지 않는다.
- **AC-09 실패·복귀:** 로그아웃 서버 실패·뒤로 가기·지연 응답·저장 장애 후 이전 로그인 상태가 되살아나지 않는다.

서버의 `DeviceSessionLogoutCommitTest`는 세션별 로그아웃·회전 전 토큰·반복 호출·만료 토큰의 적용 범위를 다룬다. 앱의 `session_store_refresh_test.dart`, `session_refresh_single_flight_test.dart`, `session_store_lost_refresh_reply_test.dart`, `refresh_interceptor_retry_test.dart`는 동시 갱신·명시적 거절·통신 오류·결과 유실·계정 전환의 시험 근거다. 시험 파일의 목적 확인이며 새 실행 통과 기록은 아니다.
