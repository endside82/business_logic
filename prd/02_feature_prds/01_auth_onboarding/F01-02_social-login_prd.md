# F01-02. 소셜 로그인 PRD

<!-- release-document: reference -->
> 2026-11-22 현재 서버·앱 소스 대조. 현재 작업은 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 코드·시험 목적 확인과 실제 실행·외부 수신·운영 환경 검증을 구분한다.

## 결론

로그인 화면은 서버가 활성화한 제공자를 표시하고 외부 인증 결과로 기존 로그인·신규 가입·기존 이메일 계정 연결을 구분한다. 기본 활성 구성은 이메일·Google이며 실제 운영 설정은 별도로 확인한다. 같은 이메일이라는 이유만으로 자동 병합하지 않고, 기존 계정 이메일의 번호 확인을 거쳐 명시적으로 연결한다.

## Google 인증 뒤 세 갈래

1. 로그인 화면에서 활성 Google 버튼을 누른다. 외부 인증을 취소하면 서비스 로그인 요청을 진행하지 않고, 공급자 설정·통신 오류는 취소와 구분해 안내한다.
2. 앱은 Google ID 토큰을 서버에 보낸다. 서버는 토큰 검증과 서비스의 대상 앱 일치·신원 식별자를 확인한다. 앱이 함께 받은 이메일 문자열만 믿고 계정을 연결하지 않는다.
3. 이미 연결된 Google 신원이면 기존 회원으로 로그인한다. 재방문 사용자에게 신규 가입 정보를 먼저 다시 묻지 않는다.
4. 처음 보는 신원이고 연결할 기존 이메일 계정이 없으면 추가 정보 필요 응답 뒤에 닉네임·생년월일·필수 약관을 입력받는다. 취소하면 가입을 진행하지 않는다.
5. 검증된 이메일의 기존 계정이 있으면 가린 이메일과 연결 확인표를 받아 연결 화면을 연다. 신규 가입 중 같은 이메일 생성이 경합한 경우에도 연결 확인으로 전환할 수 있다.

## 기존 계정에 Google 연결

연결 확인표는 30분 유효하다. 화면을 열기만 해서는 메일을 보내지 않고 사용자가 번호 요청을 눌렀을 때 기존 계정 이메일로 보낸다. 가입·비밀번호 찾기와 목적이 분리된 6자리 번호를 사용한다. 번호의 수명·오입력·재발송 제한은 [이메일 인증](F01-03_email-verification_prd.md)의 공통 처리와 같다.

번호 확인에 성공하면 연결 확인표를 한 번 꺼내 소모한 뒤 서버가 회원 행을 잠그고 이메일·상태·기존 연결을 다시 검사한다. 이미 사용 중인 Google 신원을 다른 계정에 합치거나 같은 계정에 두 Google 신원을 붙이지 않는다. 번호와 표는 DB 연결 처리 전에 소모될 수 있으므로 이후 실패에서 재사용을 보장하지 않는다.

## 상태 변경·실패·취소

- 정상 기존 계정은 연결 후 로그인한다. 정지·차단 계정은 제한된 로그인 결과를 받는다. 탈퇴 대기 계정도 처음에는 연결 안내 대상이 될 수 있지만 발송·확정의 상태 검사에서 일반 연결 성공으로 처리하지 않는다.
- 번호 오류·만료·재발송 제한은 연결 화면에서 안내한다. 확인표 무효·다른 Google 연결 등은 화면을 닫고 처음부터 Google 로그인 또는 해당 오류를 안내한다.
- 통신·서버 오류는 연결 화면에서 실패를 안내한다. 요청이 서버에 도착했을 가능성과 이미 소비한 확인표를 고려해 현재 계정 상태를 다시 확인해야 한다.
- 연결 중 화면을 닫으면 늦은 결과로 앱 로그인 상태를 설치하지 않는다. 닫기 전에 서버가 연결을 확정했다면 연결 자체가 취소된다는 뜻은 아니다.
- 새 계정은 닉네임 2~16자·만 19세 이상·필수 동의를 확인한다. Google의 검증된 이메일이 없거나 사용할 수 없으면 내부 식별용 주소가 쓰일 수 있으므로 모든 소셜 계정에 실수신 가능한 이메일이 있다고 가정하지 않는다.

## 앱 로그인 완료와 계정 관리

소셜 응답 뒤에도 내 정보 조회와 세션 설치를 거친다. 온보딩·계정 제한·약관·원래 이동 대상의 처리는 [이메일 가입·로그인의 완료 경계](F01-01_email-signup-login_prd.md)와 공통이다. 로그인 상태에서 새로운 제공자를 연결하거나 해제하는 입구는 설정의 ‘로그인 연동 계정’이며, 로그인 전 기존 계정 연결 화면과 구분한다. [소셜 계정 연결 해제](F01-08_social-unlink_prd.md)에는 비활성 제공자와 마지막 로그인 수단 계산의 차이가 남아 있다.

## 제공자 활성·운영 확인

Apple·카카오·네이버 관련 코드가 있다는 사실은 현재 신규 로그인 공개를 뜻하지 않는다. 앱은 활성 목록을 따르고 서버도 비활성 제공자를 거절한다. Google 클라이언트 설정이 없거나 ID 토큰의 대상 앱이 다르면 로그인하지 못한다. Android 서명·패키지와 iOS 로그인 구성의 현재 결정·실제 계정 확인은 [외부 준비 현황](../../../docs/qa/external-readiness.html#ios-login-review)을 따른다.

서버는 제공자별 로그인 시도의 결과를 기록한다. 신규 가입 정보 요구와 기존 계정 연결 요구는 로그인 실패 통계에서 제외한다. 기록 실패가 이미 정해진 로그인 결과를 바꾸지 않으며, 통계를 모든 요청이 빠짐없이 남는 감사 기록으로 해석하지 않는다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 영향·다음 확인 |
|---|---|---|
| Risk | 연결 확정 전 번호·확인표 소비 | 상태 변경·연결 경합·DB 실패 뒤 같은 번호·표로 재시도할 수 있다는 보장이 없음 |
| Risk | 화면 취소와 서버 결과 | 늦은 응답의 앱 적용은 막지만 이미 서버에 확정된 연결을 되돌리지는 않음 |
| Risk | 가입 응답과 실제 로그인 | 내 정보 조회·세션 설치가 뒤따른다. 응답 성공만으로 앱 로그인 완료를 판정하지 않음 |
| 미검증 | 운영 제공자·실제 계정 | 현재 운영 활성값·서명 앱·실수신·물리 기기·iOS를 이번 문서 작업에서 새로 검증하지 않음 |

## 수용 기준과 검증 근거

- **AC-01 활성 입구:** 활성 제공자만 로그인 입구에 표시하고 비활성 호출을 서버도 거절한다.
- **AC-02 외부 인증:** Google ID 토큰의 검증·대상 앱·신원을 확인하며 취소·설정 오류·통신 오류를 구분한다.
- **AC-03 기존 로그인:** 연결된 기존 회원은 신규 정보 입력 없이 로그인하고 정상·정지/차단·탈퇴 상태를 구분한다.
- **AC-04 신규 가입:** 새 신원만 추가 정보를 요청하고 성년·닉네임·동의를 검사한다. 입력 전 취소 시 가입하지 않는다.
- **AC-05 명시적 연결:** 같은 이메일을 자동 병합하지 않고 가린 이메일·확인표·사용자의 번호 요청·번호 확인 순서로 연결한다.
- **AC-06 경합과 만료:** 이메일 생성 경합·이미 연결된 신원·표 만료·번호 오류·확정 전 상태 변경을 구분한다.
- **AC-07 취소와 늦은 결과:** 외부 인증·추가 정보·연결 화면 각각의 취소와 서버 확정 뒤 늦은 응답을 확인한다. 취소된 앱 시도가 새 세션을 설치하지 않는다.
- **AC-08 완료 경계:** 로그인 응답·내 정보 조회·세션 설치·온보딩/제한 화면을 따로 확인한다.
- **AC-09 실제 계정:** 현재 서명 앱과 실제 Google 계정으로 세 갈래를 확인하고 과거 에뮬레이터·메일 링크 기록을 새 검증으로 확대하지 않는다.

`SocialLoginServiceTest`는 기존·신규 Google 분기와 연결 상태를, `EmailCodeAuthServiceTest`는 연결 번호/표를, `social_link_dismissal_test.dart`는 연결 중 닫기와 늦은 결과를 다룬다. 코드와 시험 목적의 대조이며 새 실행 통과 기록은 아니다.

검토 버전과 지문은 [문서 갱신 검토 기록](../../../verification/document-refresh-2026-11-22.json)에 남긴다.
