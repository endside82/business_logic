# F01-08. 소셜 계정 연결 해제 PRD

<!-- release-document: reference -->
> 2026-11-22 현재 서버·앱 소스 대조. 현재 작업은 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 소스 대조·시험 목적 확인과 실제 시험 실행·기기 검수를 구분한다.

## 결론

전체 메뉴의 설정에서 ‘로그인 연동 계정’을 열어 실제 연결된 소셜 계정을 해제한다. 서버의 활성 제공자 목록과 회원의 연결 목록을 함께 사용하며, 비활성 제공자도 과거 연결이 남아 있으면 해제용으로 표시한다. 최소 로그인 수단 보호는 구현돼 있지만, 현재 계산에는 비활성 제공자도 포함되므로 ‘항상 다시 로그인할 수 있다’고 보장할 수 없다.

## 실제 진입과 복귀

1. 전체 메뉴 → 설정 → 계정의 ‘로그인 연동 계정’에서 연동 계정 관리 화면을 연다. 전용 화면이 없거나 진입 위치가 추정이라는 옛 설명은 현재와 다르다.
2. 활성 제공자와 실제 연결 목록을 읽는다. 어느 조회든 실패하면 오류와 다시 시도를 표시하고 두 자료를 다시 읽는다. 읽는 중에는 로딩을 표시한다.
3. 비밀번호 로그인 사용 여부를 별도로 표시한다. 소셜 제공자는 활성화됐거나 이미 연결돼 있을 때만 보인다. 연결되지 않은 비활성 제공자의 신규 연결 입구는 숨긴다.
4. 연결된 제공자의 해제를 누르면 확인 창을 연다. 취소하면 요청하지 않는다. 마지막 로그인 수단으로 계산되는 항목은 화면에서 해제를 막는다.
5. 확인 뒤 해당 제공자의 처리 중 상태를 표시한다. 성공하면 연결 목록을 다시 읽고 해제 안내를 보여 준다. 화면에 머물러 다른 로그인 수단을 확인할 수 있다.
6. 마지막 수단·연결되지 않은 계정·기타 실패를 구분해 안내한다. 화면 뒤로 가기는 설정으로 돌아간다. 해제는 로그아웃이나 계정 탈퇴가 아니다.

## 연결 해제 규칙

- 요청은 현재 인증 회원의 연결을 대상으로 한다. 제공자 이름의 앞뒤 공백과 대소문자를 정규화하고 모르는 값·이메일 제공자 해제는 거절한다.
- 서버는 회원 행을 잠근 뒤 연결 존재와 남을 수단을 검사한다. 트랜잭션이 있다는 이유만으로 동시성이 보장된다고 설명하지 않는다. 같은 회원의 연결·해제가 공유하는 잠금이 근거다.
- 비어 있지 않은 비밀번호를 한 수단으로, 이메일을 제외한 연결된 소셜 행을 각각 한 수단으로 센다. 합이 1 이하이면 마지막 수단 해제를 거절한다.
- 서비스 내부의 소셜 연결 행을 지운다. 외부 제공자의 계정·동의·앱 권한을 철회하는 호출이나 현재 로그인 세션을 종료하는 호출은 포함하지 않는다.
- 서버 기본 활성 목록은 이메일·Google이며 운영 설정과 활성 목록 응답이 실제 노출을 정한다. Apple·카카오·네이버 모두가 현재 신규 로그인 수단으로 제공된다고 쓰지 않는다.
- 이메일 행은 현재 비밀번호 로그인 사용 여부를 보여 주는 표시다. 이 화면에 비밀번호 설정 버튼이 있으니 먼저 설정하라고 안내하지 않는다. 새 연결과 해제 후 재로그인의 계정 선택은 [소셜 로그인 PRD](F01-02_social-login_prd.md)의 별도 확인 범위다.

## 상태별 결과

| 조건 | 화면·서버 결과 | 복귀·실패 처리 |
|---|---|---|
| 비밀번호 있고 소셜 1개 연결 | 해제 가능 | 비밀번호 로그인은 남음, 연결 목록 새로 읽음 |
| 비밀번호 없고 소셜 1개 연결 | 화면 비활성·서버 마지막 수단 거절 | 연결 유지 |
| 활성 소셜과 비활성 기존 소셜이 함께 있고 비밀번호 없음 | 현재 계산은 두 수단으로 취급 | 활성 수단 해제 후 비활성 수단만 남을 수 있음. 아래 Gap 참조 |
| 비활성 제공자가 이미 연결됨 | 해제용 항목 표시 | 신규 연결·로그인 허용과 구분 |
| 비활성 제공자가 연결되지 않음 | 항목 비노출 | 임의로 신규 연결을 안내하지 않음 |
| 목록 읽기 실패 | 오류·다시 시도 | 활성 목록과 연결 목록 다시 읽음 |
| 중복 해제·이미 없는 연결 | 서버 입력 오류, ‘연동되지 않은 계정’ 안내 | 성공 재생 응답이 아니며 현재 목록 재확인 필요 |
| 확인 창 취소 | 서버 요청 없음 | 기존 목록 유지 |

## 현재 제한과 확인 범위

| 판정 | 항목 | 영향·다음 확인 |
|---|---|---|
| Gap | 비활성 제공자도 마지막 수단 계산에 포함 | 비밀번호 없이 활성 Google과 비활성 기존 소셜이 연결돼 있으면 앱·서버 모두 Google 해제를 허용할 수 있다. 이후 비활성 제공자의 로그인은 거절된다. 실제 대상 계정 존재를 확인한 기록은 아니며, 이용 가능한 수단 보호와 구현의 조건부 차이임 |
| Risk | 해제 응답 유실 뒤 목록 | 성공 응답 때만 연결 목록을 다시 읽는다. 서버가 해제했으나 응답을 잃으면 오래된 연결이 남고 재시도는 ‘연동되지 않은 계정’이 될 수 있음 |
| 미검증 | 실제 제공자·계정 전환 여정 | 이번에는 서버·앱 코드와 시험 목적을 확인했다. 운영 제공자 설정·실제 외부 계정·해제 후 재로그인을 새로 실행하지 않음 |

## 수용 기준과 검증 근거

- **AC-01 입구와 목록:** 설정의 로그인 연동 계정에서 비밀번호 여부·활성 제공자·실제 연결을 구분하고 로딩·오류·재시도를 제공한다.
- **AC-02 해제와 취소:** 해제 확인을 취소하면 변경하지 않는다. 성공하면 같은 화면에서 목록과 안내가 갱신된다.
- **AC-03 마지막 수단:** 비밀번호 없는 단일 소셜은 화면과 서버 모두 해제를 막는다. 비활성 기존 연결이 함께 있는 경우 실제 이용 가능한 수단이 남는지 별도로 확인한다.
- **AC-04 회원과 제공자:** 다른 회원의 연결을 바꾸지 못하고 이메일·알 수 없는 제공자·연결되지 않은 제공자를 거절한다.
- **AC-05 동시 요청:** 같은 회원의 동시 연결·해제가 잠금 아래 최종 상태를 다시 판정한다. 반복 해제의 입력 오류와 첫 성공을 구분한다.
- **AC-06 범위와 복귀:** 내부 연결 해제·외부 제공자 권한 철회·로그아웃·계정 탈퇴를 구분하고 설정으로 돌아올 수 있다.
- **AC-07 비활성 제공자:** 과거 연결은 해제용으로 표시하되 신규 연결·로그인 가능으로 안내하지 않는다.
- **AC-08 결과 유실:** 해제 응답이 없을 때 미변경으로 단정하지 않고 목록을 재확인한다. 마지막 수단과 재로그인 경로를 실제 계정에서 확인한다.

`connected_accounts_screen_test.dart`는 활성 목록에 따른 노출·비활성 기존 연결·단일 Google 보호·새 연결 인증의 화면 조건을 다룬다. 기존 시험의 단일 수단 사례만으로 비활성 제공자가 섞인 조건까지 통과했다고 보지 않는다. 이번 확인은 시험 목적과 소스 대조이며 새 실행 기록은 아니다.
