# F01-04. 비밀번호 재설정 PRD

<!-- release-document: reference -->
> 2026-11-22 현재 서버·앱 소스 대조. 현재 작업은 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md), 승인된 설계는 [이메일 번호 인증](../../../../docs/plan/auth/EMAIL_CODE_AUTH_2026-10-29.md)을 따른다. 실제 외부 수신·현재 운영 설정 확인과 구분한다.

이메일 입력, 6자리 번호 확인, 새 비밀번호 설정의 세 단계로 계정 접근을 회복한다. 이메일 링크로 앱을 여는 방식과 30분 링크 유효기간은 현재 동작이 아니다.

## 이메일에 따른 발송

사용 가능한 비밀번호 계정이면 인증번호 메일을 보낸다. 비밀번호 없이 Google로 가입한 계정이면 Google 로그인을 이용하라는 안내 메일을 보낸다. 존재하지 않거나 닫힌 계정에는 보내지 않는다. 정상 요청 응답은 이 경우들에서 같다. 다만 실제 메일 발송 장애는 503으로 드러날 수 있으므로 장애 중까지 가입 여부가 완전히 숨겨진다고 보장하지 않는다.

## 번호 확인 뒤 새 비밀번호

6자리 번호는 10분 동안 유효하다. 확인하면 15분 유효한 재설정 표를 받고 새 비밀번호를 입력한다. 확인 요청에는 이메일과 번호, 변경 요청에는 이메일·표(token)·newPassword를 보낸다. 가입과 같은 영문·숫자·특수문자 포함 8~20자 규칙을 적용한다.

## 변경 결과와 세션 종료

표와 이메일이 일치해야 하며 표는 변경 요청에서 한 번 꺼내 소모한다. 그 뒤 이메일 불일치·계정 상태 변경·처리 실패가 나도 표가 복원되는 계약은 아니므로 다시 번호를 받아야 할 수 있다. 비밀번호가 바뀌면 기존 로그인 권한을 갱신하고 모든 갱신 토큰을 지우며 AI 연결도 해지한다. 실시간 연결에는 비동기 해지 알림을 보낸다. 알림 발행 실패가 이미 완료한 비밀번호 변경을 되돌리지는 않는다. 새 비밀번호로 다시 로그인한다. 과거 미인증 계정도 이 복구가 성공하면 이메일 인증 완료로 기록한다.

## 번호를 받고 확인하기

이메일로 받은 6자리 번호를 앱에 입력한다. 번호는 10분 유효하며, 5회 틀리면 폐기된다. 다시 받기는 60초 뒤에 가능하고 같은 목적·이메일로 첫 발송부터 24시간 동안 10회까지 보낸다. 새 번호를 받으면 이전 번호는 사용할 수 없다. 발송 예외가 나면 번호와 그 발송 회차를 되돌리도록 처리한다. 수신 제한 때문에 보내지 않는 정상 응답은 회차를 센다.

## 실패와 다시 시작

잘못된 번호는 같은 화면에서 고친다. 만료되거나 시도 횟수를 넘기면 새 번호를 받는다. 가입·재설정·계정 연결용 확인 표가 만료되거나 이미 사용됐다면 이메일 또는 Google 인증부터 다시 시작한다. 메일이 늦게 도착했을 때에는 마지막으로 요청한 번호만 사용한다.

## 출시 확인

- 비밀번호 계정·Google 전용 계정·미가입 이메일의 안내와 실제 발송을 구분해 확인한다.
- 번호 만료·오입력·재발송·15분 표 만료·이메일 불일치·재사용 거절·비밀번호 규칙을 확인한다.
- 변경 뒤 새 비밀번호만 성공하고 이전 비밀번호·Access/Refresh 토큰·실시간 세션을 사용할 수 없다.

이전 링크 방식의 10월 12일 실수신 결과를 번호 인증의 통과 기록으로 사용하지 않는다. [외부 준비 현황](../../../docs/qa/external-readiness.html)에서 운영 메일·새 패키지·물리 기기·iOS의 남은 검증을 확인한다.

## 실제 진입과 복귀

1. 로그인 화면의 ‘비밀번호 찾기’에서 이메일을 넣고 번호를 요청한다. 가입 여부를 확인해 주는 화면으로 사용하지 않는다.
2. 새 번호·재발송 대기·만료·오입력을 같은 입력 화면에서 안내한다. 이메일을 바꾸면 번호 상태를 비우며 다른 이메일에 늦은 응답을 적용하지 않는다.
3. 번호 확인이 성공하면 새 비밀번호와 확인 입력을 받는다. 영문·숫자·특수문자 포함 8~20자 규칙과 두 입력의 일치를 검사한다.
4. 뒤로 가면 이메일 단계로 돌아가 확인표·번호·새 비밀번호 입력을 비운다. 변경 요청 중 반복 제출을 막는다.
5. 변경 성공 시 성공 안내와 함께 로그인 화면으로 이동한다. 새 비밀번호로 다시 로그인해야 한다.
6. 확인표 무효 응답이면 이메일 단계로 돌아가 번호를 다시 받는다. 다른 실패는 오류를 안내한다. 응답 유실 뒤에는 실패 안내만으로 비밀번호가 바뀌지 않았다고 단정하지 않는다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 현재 동작·남은 확인 |
|---|---|---|
| Risk | 발송 성공과 실제 수신 | 수신 제한 주소는 메일을 보내지 않아도 정상 요청 응답을 주고 발송 회차는 센다. 발송 기록의 성공도 수신함 도착을 증명하지 않음 |
| Risk | 발송 실패 복구 | 메일 발송 예외에서는 번호와 발송 회차를 되돌리도록 요청한다. 저장소 복구까지 실패하면 회차가 남을 수 있으므로 오류·제한 상태를 함께 확인 |
| Risk | 변경 결과와 실시간 종료 | 확인표 소비·비밀번호 저장·실시간 알림은 서로 다른 단계다. 응답 유실이나 알림 발행 실패를 미변경·모든 연결 종료로 단정하지 않음 |
| 미검증 | 외부 수신·운영 환경 | 이번에는 소스와 시험 목적을 대조했다. 실제 수신함·운영 우회 설정·물리 기기·실시간 연결 종료를 재검증한 기록이 아님 |

## 수용 기준과 검증 근거

- **AC-01 복구 입구:** 로그인에서 비밀번호 찾기를 열어 이메일→번호 확인→새 비밀번호 순서로 진행한다.
- **AC-02 메일 종류:** 비밀번호 계정에는 번호, Google 전용 계정에는 로그인 안내를 보내고 미가입·닫힌 계정에는 보내지 않는다. 정상 화면 응답은 같게 유지한다.
- **AC-03 번호 제한:** 10분 번호 수명·60초 재발송·24시간 10회·5회 오입력·목적 분리를 확인한다.
- **AC-04 변경 확인표:** 15분 확인표와 이메일을 묶어 확인하고 재사용을 거절한다. 계정 상태 거절·이메일 불일치 뒤 표가 이미 소모될 수 있어 재인증으로 복구한다.
- **AC-05 비밀번호·뒤로 가기:** 비밀번호 규칙과 확인 입력을 검증하고 앞 단계로 돌아갈 때 새 비밀번호·번호·확인표를 비운다.
- **AC-06 세션과 AI 연결:** 변경 뒤 새 비밀번호로 로그인하고 기존 로그인과 AI 연결이 해지되는지 확인한다. 실시간 해지 알림 발행과 실제 연결 종료는 별도로 관찰한다.
- **AC-07 결과 유실:** 서버 오류·통신 단절·늦은 응답에서 변경 성공 여부를 섣불리 확정하지 않고 로그인 확인 또는 새 번호 인증으로 복구한다.
- **AC-08 실제 수신:** 발송 예외·수신 제한·Google 안내·정상 번호 수신을 실제 외부 수신함에서 구분한다. 과거 링크 메일 기록으로 대신하지 않는다.

`EmailCodeServiceTest`는 목적 분리·만료·재발송·오입력·발송 실패·수신 제한을 다룬다. 앱의 `email_code_auth_flow_test.dart`와 `email_code_auth_wire_test.dart`는 번호 흐름과 요청 계약의 근거다. 이번 문서 갱신은 시험의 목적과 소스를 확인했으며 새 실행 통과를 기록하지 않는다. 검토 버전과 파일 지문은 [문서 갱신 검토 기록](../../../verification/document-refresh-2026-11-22.json)에 남긴다.
