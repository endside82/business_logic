# F01-03. 이메일 인증 PRD

<!-- release-document: reference -->
> 2026-11-22 현재 서버·앱 소스 대조. 현재 작업은 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md), 승인된 설계는 [이메일 번호 인증](../../../../docs/plan/auth/EMAIL_CODE_AUTH_2026-10-29.md)을 따른다. 실제 외부 수신·현재 운영 설정 확인과 구분한다.

가입 전에 이메일로 보낸 6자리 번호를 앱에서 확인한다. 가입 뒤 메일 링크를 눌러 제한을 해제하던 방식은 2026년 10월 29일 제거됐다. 번호 확인은 가입·비밀번호 찾기·Google 기존 계정 연결에서 목적별로 분리된다.

## 번호를 받고 확인하기

이메일로 받은 6자리 번호를 앱에 입력한다. 번호는 10분 유효하며, 5회 틀리면 폐기된다. 다시 받기는 60초 뒤에 가능하고 같은 목적·이메일로 첫 발송부터 24시간 동안 10회까지 보낸다. 새 번호를 받으면 이전 번호는 사용할 수 없다. 발송 예외가 나면 번호와 그 발송 회차를 되돌리도록 처리한다. 수신 제한 때문에 보내지 않는 정상 응답은 회차를 센다.

## 실패와 다시 시작

잘못된 번호는 같은 화면에서 고친다. 만료되거나 시도 횟수를 넘기면 새 번호를 받는다. 가입·재설정·계정 연결용 확인 표가 만료되거나 이미 사용됐다면 이메일 또는 Google 인증부터 다시 시작한다. 메일이 늦게 도착했을 때에는 마지막으로 요청한 번호만 사용한다.

## 가입 확인과 계정 생성의 경계

가입 번호를 확인하면 60분 유효한 가입 표를 받는다. 이 단계에서는 사용자·지갑·프로필이 아직 생성되지 않는다. 가입 정보를 제출해 계정 생성이 성공하면 이메일 인증 완료 상태로 로그인한다. 주소를 잘못 썼다면 계정 삭제 없이 이메일 입력부터 다시 시작한다.

## 없어진 정책

가입 뒤 미인증 계정의 이용을 막던 EMAIL_NOT_VERIFIED 제한, 인증 링크 진입 화면, 가입 후 인증 메일 재발송 API, 미인증 30일 뒤 안내·7일 뒤 익명 처리 작업은 제거됐다. emailVerified 필드는 남지만 옛 제한 세션을 유지하는 근거가 아니다. 기존 메일 링크를 받으면 로그인 전에는 로그인 화면으로 안내한다. 로그인한 상태에서는 옛 인증 요청을 소모하고 현재 인증 상태의 이동 규칙을 유지하며, 옛 링크 때문에 다시 로그인시키지 않는다.

## 발송 장애와 운영 확인

인증번호 메일은 요청 중 발송하고 발송·실패·수신 제한 기록을 남긴다. 실제 발송 예외는 오류로 안내하지만 수신 제한 주소는 정상 응답을 받을 수 있다. 이전 링크 메일의 아웃박스 재처리 정책을 번호 메일에 적용하지 않는다. 운영 환경의 번호 인증 우회는 꺼져 있어야 하며, 실제 외부 수신함·물리 기기·iOS에서 지연·재발송·만료를 별도로 확인해야 한다.

## 출시 확인

- 새 번호 메일을 실제 외부 수신함에서 받아 10분 안에 확인하고 가입으로 이어진다.
- 60초 재발송 제한·24시간 10회 제한·5회 오입력·새 번호 뒤 이전 번호 거절을 확인한다.
- 운영 우회가 꺼져 있고, 번호·가입 표·개인정보가 로그나 오류 응답에 노출되지 않는다.

이전 링크 방식의 10월 12일 실수신 결과를 번호 인증의 통과 기록으로 사용하지 않는다. [외부 준비 현황](../../../docs/qa/external-readiness.html)에서 운영 메일·새 패키지·물리 기기·iOS의 남은 검증을 확인한다.

## 실제 진입과 복귀

1. 로그인 화면의 회원가입에서 이메일을 넣고 인증번호를 요청한다. 이미 가입한 이메일이면 로그인·비밀번호 찾기로 안내한다.
2. 번호 입력 단계에서 남은 시간과 다시 받을 수 있는 시간을 확인한다. 서버가 재발송 대기 시간을 반환하면 그 시간으로 화면을 다시 맞춘다.
3. 이메일을 바꾸면 기존 번호 입력과 타이머를 비운다. 요청 중 이메일을 바꾸거나 화면을 나간 경우 늦게 도착한 결과를 다른 이메일·사라진 화면에 적용하지 않는다.
4. 올바른 번호를 확인하면 가입 정보 입력 단계로 이동한다. 이때 받은 가입용 확인표는 계정 생성 요청에만 사용한다.
5. 정보 단계에서 뒤로 가면 이메일 단계로 돌아간다. 확인표 만료·이메일 중복이면 해당 단계로 돌아가 재인증하거나 로그인한다. 닉네임 등 다른 가입 입력의 오류는 가입 트랜잭션이 실패했을 때 기존 유효한 확인표로 고쳐 제출할 수 있다.
6. 번호 확인만으로 사용자·지갑이 생기지 않는다. 계정 생성 성공 뒤 확인표 삭제를 요청하고, 같은 이메일의 중복 생성은 서버가 차단한다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 현재 동작·남은 확인 |
|---|---|---|
| Risk | 발송 성공과 실제 수신 | 수신 제한 주소는 메일을 보내지 않아도 정상 요청 응답을 주고 발송 회차는 센다. 발송 기록의 성공도 수신함 도착을 증명하지 않음 |
| Risk | 발송 실패 복구 | 메일 발송 예외에서는 번호와 발송 회차를 되돌리도록 요청한다. 저장소 복구까지 실패하면 회차가 남을 수 있으므로 오류·제한 상태를 함께 확인 |
| 미검증 | 외부 수신·운영 환경 | 이번에는 소스와 시험 목적을 대조했다. 실제 수신함·운영 우회 설정·물리 기기에서의 가입 완료를 재검증한 기록이 아님 |

## 수용 기준과 검증 근거

- **AC-01 가입 입구:** 로그인에서 회원가입을 열고 미가입 이메일로 번호를 요청하면 입력 단계가 열린다. 기존 이메일은 로그인·비밀번호 찾기로 안내한다.
- **AC-02 목적과 이메일:** 가입용 번호를 다른 이메일·다른 인증 목적에 사용하지 못한다. 주소를 바꾸면 이전 입력·대기 상태를 비운다.
- **AC-03 번호 수명:** 6자리 번호를 한 번만 확인하고 10분 경과·5회 오입력 뒤에는 새 번호를 요구한다.
- **AC-04 재발송 제한:** 60초 안의 재요청은 서버의 남은 시간을 표시하고 같은 목적·이메일의 24시간 10회 제한을 지킨다. 재발송 후 이전 번호는 무효다.
- **AC-05 가입 경계:** 번호 확인만으로 계정이 생성되지 않는다. 60분 가입 확인표를 사용한 계정 생성 성공과 이후 로그인 결과를 따로 확인한다.
- **AC-06 취소와 입력 오류:** 가입 정보에서 뒤로 가면 이메일 단계로 돌아간다. 닉네임 등 다른 입력 오류를 고친 재요청과 확인표 자체 만료를 구분한다.
- **AC-07 발송·수신 실패:** 발송 예외·수신 제한·늦은 메일·오류 응답 유실을 구분하며 정상 응답만으로 실제 수신을 완료 처리하지 않는다.
- **AC-08 과거 방식·운영 환경:** 옛 인증 링크 기록을 현재 번호 방식의 증거로 쓰지 않는다. 운영 우회 비활성과 실제 외부 수신은 별도 근거로 확인한다.

`EmailCodeServiceTest`는 목적 분리·만료·재발송·오입력·발송 실패·수신 제한을 다룬다. 앱의 `email_code_auth_flow_test.dart`와 `email_code_auth_wire_test.dart`는 번호 흐름과 요청 계약의 근거다. 이번 문서 갱신은 시험의 목적과 소스를 확인했으며 새 실행 통과를 기록하지 않는다. 검토 버전과 파일 지문은 [문서 갱신 검토 기록](../../../verification/document-refresh-2026-11-22.json)에 남긴다.
