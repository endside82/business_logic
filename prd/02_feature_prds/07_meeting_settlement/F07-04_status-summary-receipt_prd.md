# F07-04. 정산 현황·금액 요약·영수증 열람 PRD

<!-- release-document: reference -->
> **2026-11-23 후속 소스 대조.** 현재 조회 경로·공개 범위·표시 금액·실패와 복귀를 설명한다. 새 제품 시험이나 실제 기기 검증 결과가 아니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

정산 현황은 현재 모임 정산의 상태, 방식별로 주고받을 돈, 참여자별 확인 상태와 첨부 영수증을 보여 준다. **총 기록 금액·지출·수입·분담·실제 납부·입금 확인은 서로 다른 값**이다. 진행률은 납부 금액 비율이 아니라 확인이 끝난 참가자 수를 기준으로 표시한다.

읽기 자격은 주최자와 일반 참석자에 한정되지 않는다. 정산 생성자, 고정 회차의 실제 출석자, 현재 정산의 분담·송금 당사자도 조건에 따라 조회할 수 있다. 반면 초안의 비관리자에게는 메모·다른 사람의 상세·항목·영수증을 제한한다. 현재 현황과 취소된 원본의 금전 이력은 조회 대상과 경로가 다르다.

## 실제 진입과 조회 대상

- 주최자는 모임 상세 관리 영역의 **비용 기록·정산**에서 현황으로 들어간다. 참여 허브는 주최자·참여 중·취소·종료 관점의 사용자에게 정산 상태를 조회하고, 작성 중이 아닌 정산 또는 권한·없음으로 확정되지 않은 조회 오류가 있으면 정산 입구를 표시한다. 비주최자의 초안 입구는 모임 종료 뒤에 제공한다. 모든 참석자에게 항상 같은 메뉴를 노출하는 구조가 아니다.
- 진행 중에는 참여 허브의 **정산 안내**, 그 외 표시 가능한 상태에는 **정산 내역**으로 구분한다. 취소된 모임 화면에도 조건에 맞는 사용자에게 **정산·환불 내역 확인** 입구가 있다. 메뉴 노출만으로 서버 읽기 자격이 확정되는 것은 아니다.
- 정산 시작·납부·완료·독촉 등 모임 번호가 있는 알림은 해당 모임의 현재 현황으로 연결한다. 취소·송금 신고 알림에 분담 또는 송금 번호가 있으면 그 원본의 개인 내역 상세가 우선이다. 모든 정산 알림이 같은 현황 화면을 여는 것은 아니다.
- 현재 본체와 요약은 모임 번호로 조회하며, 서버는 **취소 상태를 제외한 가장 최근 정산**을 선택한다. 완료된 정산도 조회 대상이다. 취소 직후 앱이 명령 응답을 표시할 수는 있지만, 일반 현황 재조회로 같은 취소 원본을 계속 읽는다고 설명하지 않는다.
- 개인 금전 이력의 분담·송금 카드는 원본 종류와 번호로 상세를 연다. 같은 모임에 새 정산이 생겨도 옛 카드가 새 정산 현황으로 바뀌는 경로가 아니다. 이력 전체 범위는 [본인 정산 이력](F07-10_account-history-reputation_prd.md)에서 다룬다.

## 읽기 권한과 초안 공개 범위

서버는 현재 주최자 또는 정산 생성자에게 읽기를 허용한다. 일반 모임은 `ATTENDING`, 고정 정기모임 회차는 실제 출석을 검사한다. 이에 해당하지 않아도 현재 정산의 분담자 또는 송금 양쪽 당사자이면 읽을 수 있다. 아무 관련 없는 사용자는 거절한다.

앱의 읽기 경로는 이미 읽어 둔 모임 정보에서 주최자 또는 일반 모임의 참석 행을 확인하면 빠르게 통과한다. 고정 회차의 참석 행만으로 통과시키지 않는다. 빠른 판정이 안 되면 서버의 **내 분담금 조회**를 이용해 읽기 자격을 확인하고 실패하면 모임 상세로 돌아간다. 경로 검사 때문에 모임 상세를 새로 조회하는 흐름과 구분한다.

초안 제한의 서버 기준은 **정산 관리자 여부**, 즉 생성자 중심이다. 현재 주최자라도 생성자가 다르면 아래 제한을 받을 수 있다.

| 자료 | 초안을 읽는 비관리자에게 보이는 범위 |
| --- | --- |
| 정산 본체 | 메모를 비운다. 상태·합계 등 본체 전체를 숨기는 처리는 아니다. |
| 정산 요약 | 참가자 행은 본인만, 송금 행은 본인이 보내거나 받는 행만 반환한다. 총액·지출·수입 같은 정산 전체 합계는 유지한다. |
| 항목 목록 | 빈 목록을 반환한다. |
| 내 분담금 | 영수증 파일 번호를 비운다. |
| 영수증 주소 | 발급을 거절한다. 파일 번호를 알더라도 우회할 수 없다. |

요청 이후 읽기 자격이 있는 사용자는 참가자·송금 요약을 조회한다. 그 안에서도 송금 신고 정보는 추가로 제한한다. 본인의 신고 여부와 신고·철회 행동은 보내는 사람, 신고 시각은 받는 사람 또는 생성자에게 노출한다. 상각 사유는 보내는 사람·받는 사람·생성자에게만 노출한다. 전체 요약 열람을 모든 민감 필드 공개로 확대하지 않는다.

## 요약 금액의 의미

| 값 | 현재 계산과 읽는 방법 |
| --- | --- |
| `totalAmount` | 저장된 항목 금액의 합계다. 지출과 수입을 합친 기록 금액이며 실제 낼 돈·순지출과 다르다. |
| `expenseAmount`, `incomeAmount` | 항목 종류별 지출과 수입을 각각 합한다. 화면에서도 지출·수입을 분리한다. |
| `totalShare`, `incomeShare` | 본인의 지출 분담 합계와 나눠 받을 수입 배분 합계다. 보유자의 자기 몫도 포함할 수 있다. |
| `netAmount` | 지출은 보유자에게 더하고 분담자에게 빼며, 수입은 보유자에게 빼고 배분받는 사람에게 더한 차액이다. 양수는 받는 쪽, 음수는 보내는 쪽이다. 납부할 때마다 줄어드는 실시간 미납 잔액이 아니다. |
| `completedAmount` | 완료된 분담과 보유자 본인 분담의 합이다. 지출·수입 분담을 함께 포함하며 실제 입금 총액과 다를 수 있다. |
| 항목별 납부의 `payableAmount`, `paidAmount` | 실제 지급 방향에 따른 낼 돈과 완료 처리된 납부 금액이다. 본인 몫은 제외한다. 지출과 수입의 지급 방향이 반대다. |
| 항목별 납부의 `receivableAmount`, `receivedAmount` | 실제 받을 사람의 받을 돈과 수취 완료 금액이다. 받을 돈이 남아 있어도 본인이 낼 돈이 없으면 개인 납부 완료 표시는 가능하다. |
| 직접 송금의 네 납부·수취 합계 칸 | 항목별 납부용 값이므로 0이다. 직접 송금의 실제 주고받을 금액은 송금 행으로 판단한다. |

요약의 사람 목록은 실제 항목 보유자·분담자로 계산된 차액 집합이다. 모임 전체 참석자 명부와 동일하다고 보지 않는다. 이름·사진 정보를 별도로 보충하며, 이름을 구하지 못하면 앱은 대체 이름으로 표시한다. 항목 추가 가능 여부도 요약의 서버 행동 권한으로 전달한다.

## 진행률과 다음 행동

개인 원본 상세는 `canWithdrawSent`·`canMarkReturned`와 `actions.withdrawSent`·`actions.markReturned`로 허용 여부와 거절 오류 번호를 전달한다. 현재 수행할 행동이 없으면 해당 행동 정보를 생략할 수 있다. 공용 송금 응답의 `actions.selfRefund`는 실제 받는 사람의 자체 반환 조건을 나타낸다. 앱은 이 서버 판정으로 단추와 이의 중 안내를 정하며, 명령 시 서버는 최신 상태를 다시 확인한다.

- **정산 요약**은 지출 합계, 수입이 있으면 별도 수입 합계, 참가자 수로 나눈 지출 평균, 정산 방식과 확인 완료 인원을 보여 준다. 평균은 정수 나눗셈이며 개인별 실제 분담금이 아니다.
- 참가자 확인은 먼저 서버의 `allCompleted`를 사용한다. 항목별 납부에서는 본인이 낼 돈을 다 냈는지가 기준이다. 직접 송금에서는 여기에 본인이 보내거나 받는 모든 송금이 완료·취소·대체·은행분 포기 중 하나인지도 확인한다.
- 진행률은 **확인 완료 인원 ÷ 요약 참가자 수**다. 사람이 없으면 0으로 표시한다. ‘확인 전만’ 필터는 진행 중이고 확인 전 인원이 있을 때 제공하며 같은 판정으로 사람 목록을 거른다. 금액을 적게 낸 사람만 거르는 필터가 아니다.
- 직접 송금의 개인 카드는 진행 중이면 본인 `PENDING` 송금의 보낼 돈·받을 돈, 완료 상태이면 `COMPLETED` 송금의 보낸 돈·받은 돈을 합한다. 그 밖의 추가 확인 대상은 위 금액에 합치지 않고 별도 건수로 알린다. 확인 전 금액을 이미 보냈다면 다시 송금하지 말고 확인을 기다리라고 안내한다.
- **송금·입금 확인 / 완료 내역 보기**는 송금 목록, **내 분담금 보기**는 본인 분담금 화면으로 이동한다. 항목별 납부는 내 분담금을 주 입구로 삼고, 자동 계산된 정보성 송금 완료를 실제 입금 확인으로 보지 않도록 안내한다.
- 개인 금액 카드는 진행 중·완료에서 제공한다. 초안·취소·알 수 없는 정산 상태에는 제공하지 않는다. 완료 상태도 내역 열람 입구는 남으므로 ‘끝나면 모든 버튼이 사라진다’고 설명하지 않는다.
- 항목별 납부 현황은 초안 이후 현재 주최자에게 전체 항목, 그 밖에는 본인이 보유자인 항목의 입구를 보여 준다. 화면 노출과 개별 납부·확인 권한은 별개다. 후속 행동은 [분담금 납부](F07-05_pay-share_prd.md)와 [송금 확인](F07-06_host-confirm-transfers_prd.md)을 따른다.
- 진행 중 주최자에게 알림·마감 연장 입구를 제공한다. 상세 조건은 [리마인드와 마감 연장](F07-07_remind-extend_prd.md)을 따른다. 진행·취소 설명은 별도로 접어 둔다.

## 영수증 열람과 복귀

현황의 항목 목록에 영수증 파일 번호가 있으면 가로 갤러리를 표시한다. 초안의 비주최자에게는 앱에서도 갤러리를 숨기고, 최종 서버 공개 판정은 앞의 생성자 기준을 따른다. 영수증 업로드·교체는 [정산 항목과 영수증 관리](F07-02_settlement-items_prd.md)의 별도 저장 흐름이다.

썸네일과 전체 보기는 모두 모임 번호·파일 번호로 정산 전용 다운로드 주소를 요청한다. 서버는 읽기 자격, 초안 제한, **현재 정산 항목에 실제로 연결된 파일인지**를 확인한 뒤 주소를 발급한다. 일반 파일 소유자 검사를 생략하는 내부 함수가 호출되더라도 임의 파일 번호 접근을 허용한다는 의미가 아니다.

썸네일을 누르면 전체 보기 경로에서 주소를 다시 발급받는다. 전체 보기는 확대·축소를 지원하고 뒤로·닫기 모두 이전 화면으로 돌아간다. 주소 발급 실패·빈 주소와 실제 사진 표시 실패를 구분해 오류와 다시 시도를 제공하며, 다시 시도는 주소를 새로 요청한다. 현재 썸네일의 주소 요청 실패는 오류를 표시하지 않고 로딩 표시가 남는 제한이 있다.

## 조회 실패와 갱신

본체·요약·항목은 각각 조회한다. 당겨서 새로고침하면 이 자료와 수취 계좌 조회를 무효화해 다시 읽는다. 1초마다 갱신하는 폴링으로 설명하지 않는다. 상세 Provider는 명령 결과와 늦은 조회 응답이 서로 덮이지 않도록 기존 변경 기록을 적용하며 계정별 자료 경계를 사용한다.

정산 없음 전용 서버 코드에만 ‘아직 정산이 없음’ 화면을 표시하고, 현재 주최자에게 생성 입구를 제공한다. 일반 권한·통신 실패는 정산 없음으로 바꾸지 않고 오류와 재시도를 보여 준다. 요약 실패는 진행 중·완료의 개인 금액 영역에서 오류와 재시도를 제공하지만 일반 요약 카드·참가자 목록은 숨겨질 수 있다. 영수증 목록의 로딩·오류도 현재 현황에서는 갤러리를 숨긴다. 빈 자료와 조회 실패가 모든 영역에서 같은 방식으로 표현되는 것은 아니다.

## 수입과 취소 뒤 확인할 돈

지출 분담은 참가자에서 보유자로, 수입 배분은 보유자에서 참가자로 향한다. 보유자 자기 몫에는 송금 의무가 없다. 차액·확인 전 송금·실제 납부를 함께 읽되 어느 하나를 다른 값의 대체로 사용하지 않는다.

취소된 정산에도 실제로 보냈지만 수취 확인이 안 된 은행 송금이나 직접 돌려줄 돈이 남을 수 있다. 이를 현재 현황의 0원이나 취소 라벨만으로 종료 처리하지 않는다. 원본별 이력과 [금액 검토·정산 요청·취소와 반환](F07-03_activate-cancel_prd.md)을 함께 확인한다.

## 수용 기준과 검증 근거

- **AC-01 실제 입구:** 주최자 관리 입구와 참여 허브의 정산 상태별 노출 조건을 구분하고, 알림의 원본 번호가 있으면 개인 원본 상세 경로를 우선한다.
- **AC-02 현재와 이력:** 일반 현황은 취소 제외 최신 정산을 읽는다. 개인 분담·송금 카드는 원본 종류·번호로 이동하며 같은 모임의 새 정산으로 바꾸지 않는다.
- **AC-03 읽기 자격:** 주최자·생성자·허용 참석자·현재 정산 당사자를 서버에서 판정한다. 고정 회차의 참석 행만으로 앱 경로를 통과시키지 않고 서버 판정을 사용한다.
- **AC-04 초안 제한:** 비관리자 메모·다른 참가자/송금·항목·영수증을 정해진 범위로 제한한다. 전체 합계 유지와 본인 행 필터를 구분한다.
- **AC-05 송금 정보 공개:** 송금 신고 여부·시각·행동과 상각 사유를 보는 사람에 맞게 제한한다. 요약 읽기 권한이 모든 필드 열람 권한은 아니다.
- **AC-06 금액 구분:** 기록 합계·지출·수입·분담·차액·완료 분담 합·실제 납부와 수취를 구분하며 수입의 반대 지급 방향과 자기 몫 제외를 유지한다.
- **AC-07 인원 진행률:** 같은 확인 판정으로 완료 인원·진행률·확인 전 필터를 계산한다. 직접 송금은 관련 송금 상태까지 확인하며 개인 납부 완료를 모든 수취 완료로 확대하지 않는다.
- **AC-08 개인 금액:** 직접 송금은 진행 중 PENDING·완료 시 COMPLETED 행의 주고받을 돈을 합하고 추가 확인 건을 분리한다. 초안·취소·알 수 없는 정산 상태에서는 개인 금액 카드를 숨긴다.
- **AC-09 다음 행동:** 방식에 맞게 내 분담금·송금 목록·항목별 납부 현황으로 이어지며 완료 뒤에도 허용된 내역 열람은 유지한다.
- **AC-10 영수증 권한:** 서버 읽기·초안·실제 항목 파일 연결을 통과해야 주소를 발급한다. 다른 파일 번호로 조회하면 거절한다.
- **AC-11 영수증 실패와 복귀:** 전체 보기의 주소·사진 실패는 재시도를 제공하고 새 주소를 요청한다. 뒤로·닫기는 이전 화면으로 돌아간다. 썸네일의 현재 실패 표시 제한을 숨기지 않는다.
- **AC-12 조회 실패:** 정산 없음 전용 오류와 권한·통신 오류를 구분한다. 주최자에게만 생성 입구를 제공하고 부분 조회 실패를 전체 정상 조회로 기록하지 않는다.
- **AC-13 갱신 경계:** 당겨서 본체·요약·항목·수취 계좌를 갱신하고 늦은 응답·계정 변경을 처리한다. 1초 폴링이나 단일 시점 조회로 보장하지 않는다.
- **AC-14 취소 뒤 금액:** 취소 라벨이나 현재 현황 부재로 외부 반환·미확인 송금을 종료 처리하지 않고 원본 이력과 취소·반환 규칙을 따른다.

근거는 현재 조회·계산·공개 서비스와 앱 경로·Provider·표시 코드, `MeetingSettlementSummaryPartiesTest`의 수입/지출 지급 방향·개인 완료·직접 송금 요약 단언, `MeetingSettlementServiceTest`의 초안/활성 요약과 초안 영수증 거절 단언, `settlement_read_route_gate_test.dart`의 고정 회차·당사자 경로 단언, `settlement_connected_readability_test.dart` 중 영수증 재요청·뒤로 이동 단언이다. 기존 시험 코드를 읽은 범위이며 화면 확대·이미지 캡처·새 시험 실행을 하지 않았다.
