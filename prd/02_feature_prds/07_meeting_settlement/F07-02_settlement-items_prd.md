# F07-02. 정산 항목·기존 배분 편집·영수증·최근 항목 재사용 PRD

<!-- release-document: reference -->
> **2026-11-22 소스 대조.** 현재 항목 관리의 권한·저장·실패·조회 범위다. 새 제품 시험이나 실제 기기 검증 결과가 아니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

정산 초안의 항목마다 비용명·금액·결제자 또는 수입 보유자·분담 대상을 정하고, 균등·직접 입력·비율 중 하나로 나눈다. **항목 목록은 전용 서버 조회로 읽고**, 수정할 때는 저장된 분담금과 비율을 별도로 불러온다. 저장된 개인별 배분을 전체 참가자에게 임의로 다시 나누지 않는다.

서버의 항목 변경 권한은 정산 생성자를 기준으로 하며 작성 중인 정산에만 열린다. 앱은 서버가 보내는 추가·수정·삭제 가능 여부에 따라 행동을 제공한다. 다만 항목 화면 경로는 현재 모임 주최자를 요구하므로, 주최자 변경 뒤에는 서버 권한과 화면 접근 조건이 어긋날 수 있다.

## 목록·진입과 권한

- 첫 비용 저장·지난 정산 복사·계산기 가져오기 후 비용 목록으로 이동한다. 항목 화면 경로는 현재 주최자에게 열리며, 처음 정산을 만드는 흐름은 [정산 생성과 첫 비용 복구](F07-01_create-settlement_prd.md)를 따른다.
- 목록은 서버 항목 조회로 읽는다. 실패하면 오류와 다시 시도를 표시하며 기기의 옛 사본을 정상 조회처럼 돌려주지 않는다. 계정이 바뀌면 이전 계정의 목록에 새 항목을 합치지 않는다.
- **항목 추가**는 정산 요약의 추가 권한, 카드의 **수정·삭제**는 각 항목의 권한을 따른다. 권한 정보가 없으면 행동을 닫는다. 카드의 더보기 메뉴에서 허용된 수정·삭제만 제공한다.
- 서버는 읽을 수 있는 정산인지, 생성자인지, 항목이 요청한 모임에 속하는지, 여전히 초안인지 확인한다. 항목을 잠근 뒤 실제 소속 정산으로 검사하므로 다른 모임의 항목 번호로 수정·삭제할 수 없다.
- 초안을 읽을 수 있는 일반 참가자에게도 작성 중인 항목 목록은 숨긴다. 개별 배분 조회는 해당 정산을 읽을 수 있고 항목의 모임이 맞는 정산 생성자 또는 현재 주최자에게만 허용된다. 배분 조회 권한과 변경 권한은 동일하지 않다.
- 초안이고 항목이 있으면 **금액 검토하기**로 이어진다. 항목 조회 중·실패·빈 목록 또는 첫 비용 저장 중·결과 불확실 상태에서는 검토 진입을 막는다. 목록 화면 자체가 납부 요청을 실행하지 않는다.

## 입력과 저장 규칙

기본 입력은 비용명, 1원 이상의 정수 금액, 먼저 결제한 사람 또는 돈을 받은 사람, 이 항목을 나눌 사람이다. 앱은 현재 후보에 있는 결제자·분담 대상과 한 명 이상의 선택을 요구한다. 결제자와 분담 대상은 다를 수 있고, 항목마다 다른 사람을 선택할 수 있다. 고정 정기모임의 후보는 실제 출석 기준을 따른다.

추가 설정에는 나누는 방식·영수증·수입/지출·선택 분류가 있다. 분류는 음식·카페·술·교통·숙박·쇼핑·오락·기타이며 필수가 아니다. 서버는 빈 제목, 제목 200 UTF-16 코드 단위 초과, 0 이하 금액, 결제자 누락, 알 수 없는 분할 방식·항목 종류·분류를 거절한다. 수입도 금액은 양수로 저장하며 음수 지출로 만들지 않는다.

| 나누는 방식 | 현재 계산과 저장 조건 |
| --- | --- |
| 균등 | 참가자 순서를 유지한다. 먼저 계산한 1인 금액을 10원 단위로 반올림하고 마지막 사람이 나머지를 맡는다. 이 방식이 총액을 초과할 경우 정수 단위 몫과 마지막 나머지 방식으로 바꾼다. 모든 최종 분담금이 양수여야 한다. 예를 들어 10,000원을 세 명이 나누면 3,330·3,330·3,340원이다. |
| 직접 입력 | 각 사람의 양수 금액을 입력하고 합계가 항목 금액과 같아야 앱에서 저장할 수 있다. 서버에는 부족액을 마지막 사람에게 더하는 선택 기능도 있지만 현재 공용 입력창은 이를 켜지 않는다. 초과 합계는 그 옵션으로도 보정하지 않는다. |
| 비율 | 앱은 선택한 사람마다 양수 비율을 받는다. 서버는 마지막 사람을 제외한 금액을 10원 단위로 반올림하고 마지막 사람에게 잔여 금액을 배정한다. 최종 분담금이 모두 양수이고 합계가 총액과 같아야 한다. |

서버는 같은 참가자가 한 항목에 중복되지 않는지, 배분 결과의 합계와 양수 조건을 공통으로 확인한다. 비율 항목에는 계산된 원화 금액과 입력한 원래 비율을 구분해 저장한다. 나열 순서가 마지막 사람의 금액에 영향을 주므로 미리보기와 저장 요청의 참가자 순서를 유지한다.

균등 미리보기는 앱의 같은 배분 규칙을 사용한다. 비율은 서버 계산 결과를 받아 사람 수·중복·양수·합계를 확인한 뒤 보여 주며, 현재 입력의 계산 결과가 없으면 저장하지 않는다. 직접 입력은 합계 차이를 보여 주고 사용자가 조정한다. 화면의 계산 결과는 아직 저장된 비용이나 송금 완료가 아니다.

## 기존 항목의 배분을 불러와 편집

1. 기존 항목의 제목·금액·보유자·수입/지출·분류·영수증을 채우고, 배분 조회와 현재 참가자 후보를 기다린다. 배분을 불러오는 동안 저장을 막는다.
2. 저장된 사람 순서와 직접 입력 금액을 복원한다. 비율 항목은 저장된 비율을 사용하고, 비율이 없는 옛 항목은 기존 분담금을 비율 입력값으로 채운다. 이것이 옛 원본 비율의 복원이라고 주장하지 않는다.
3. 목록의 분할 방식과 배분 응답이 다르면 사용자가 아직 방식을 바꾸지 않은 경우 배분 응답을 따른다. 불러오는 사이 사용자가 방식을 바꿨다면 그 선택을 유지하고 다른 방식의 금액을 덮어쓰지 않는다.
4. 배분 조회 실패나 중복 사람이 든 응답은 자동 적용하지 않는다. 기존 내용을 바꾸게 된다는 안내 뒤 사용자가 대상과 금액을 다시 지정할 수 있다. 현재 후보에서 빠진 사람은 선택에서 빼고 제외 인원을 알린다. 편집 중 참가자 목록이 바뀌어도 선택을 다시 맞춘다.
5. 저장 거절 시 입력창과 입력을 남긴다. 성공하면 자기 입력창만 닫고 항목 목록과 요약을 갱신한다. 저장 도중 다른 화면이 위에 열렸다고 그 화면까지 닫지 않는다.

첫 비용에는 원래 초안 번호를 확인하는 별도 복구가 있다. 일반 추가·수정의 모든 응답 유실에 그 복구가 적용되는 것은 아니다. 자세한 구분은 [정산 생성과 첫 비용 복구](F07-01_create-settlement_prd.md)를 따른다.

## 추가·수정·삭제의 결과

| 동작 | 서버 변경 | 앱 결과 |
| --- | --- | --- |
| 추가 | 초안을 잠그고 항목과 분담을 저장한다. 첫 비용이 원래 초안 번호를 보내면 현재 정산과 일치하는지도 확인한다. | 성공 응답의 항목을 목록에 더하고 관련 정산 조회를 갱신한다. |
| 수정 | 기존 분담을 지우고 반영한 뒤 새 배분으로 다시 만든다. 제목·금액이 같아도 참가자·금액·비율 변경을 기록한다. | 성공한 항목을 교체한다. 항목별 수정 실행 중복과 입력창의 중복 저장을 막는다. |
| 삭제 | 확인 후 항목의 분담과 영수증 참조를 해제하고 항목을 삭제한다. | 성공 후 목록에서 제거하고 요약을 갱신한다. 삭제 실패를 성공으로 표시하지 않는다. |

세 동작 모두 정산 합계를 다시 계산하고 변경 전후 또는 생성·삭제의 감사 자료를 남긴다. 수입과 지출을 모두 양수로 더한 저장 합계는 실제 낼 돈이나 순지출이 아니다. 개인별 받을 돈·낼 돈은 항목 종류와 분담을 반영한 정산 요약으로 판단한다. 새로 생기는 차단 관계의 금전 교환도 서버 검사 대상이다.

명령이 권한·상태 변경으로 거절되면 앱은 항목과 요약의 행동 가능 여부를 다시 읽는다. 계정 변경 뒤 늦게 끝난 명령 결과는 다른 계정의 목록에 적용하지 않는다. 일반 추가·수정·삭제는 서버 멱등 키를 받지 않는다.

## 영수증 첨부와 열람

- 카메라 또는 갤러리에서 고른 사진을 증빙 용도로 올린다. 업로드 중에는 저장을 막고 실패하면 안내 후 잠금을 푼다. 영수증 없이 비용을 저장할 수도 있다.
- 서버는 연결하려는 유효한 파일 번호의 소유자가 행위자인지, 업로드가 완료됐는지, 증빙 또는 후기 용도인지 검사한다. 항목 하나의 영수증 연결은 하나다.
- 추가·수정 시 항목의 파일 참조를 맞추고 교체·해제 시 예전 참조를 제거한다. 입력창에서 영수증 제거를 눌렀다는 사실만으로 서버 항목이 즉시 바뀌지 않으며 항목 저장이 필요하다. 항목 삭제도 파일 원본을 지우는 명령과 다르다.
- 미리보기 주소 조회가 실패해도 파일 번호를 임의로 버리지 않는다. 크게 보기는 입력창 위에서 열고 닫으면 입력창으로 돌아온다.
- 정산용 영수증 주소 조회는 정산 읽기 권한·초안의 공개 제한·현재 정산 항목의 실제 파일 연결을 검사한다. 참가자 누구나 파일 번호만 알면 열 수 있는 주소 발급 기능이 아니다.

## 최근 항목과 제목 자동완성

최근 항목은 **본인이 생성한 정산**의 항목을 조회한다. 제목·금액·분류가 같은 항목을 묶고 가장 최근 생성 시각, 같은 시각이면 최근 항목 번호 순으로 정렬한다. 단순히 제목만 중복 제거하거나 현재 모임의 항목만 찾는 기능이 아니다. 정산 상태를 제외하는 조건은 없어 초안·취소 이력의 항목도 남아 있으면 후보가 될 수 있다.

서버 기본은 10개이며 0 이하 요청도 10개, 최대는 30개다. 분류를 고르면 해당 분류만 조회하며 알 수 없는 분류는 거절한다. 앱의 일반 조회는 기본 10개다.

추가 입력창의 최근 항목 칩은 제목·금액과 유효한 분류를 채운다. 결제자·참가자·영수증·기존 납부 상태까지 복사하지 않는다. 제목 자동완성은 제목 후보를 최대 8개 보여 주는 별도 입력 보조다. 분류도 입력 글도 없을 때는 후보를 열지 않는다. 수정 입력창에서는 최근 항목·제목 자동완성을 제공하지 않는다. 최근 항목 읽기 실패는 앱에서 빈 목록으로 처리되어 보조 후보 없이 직접 입력을 계속한다.

## 수입 항목과 요청 이후의 경계

수입 항목은 돈을 받은 사람과 나눠 받을 사람을 지정한다. 항목별 납부와 직접 송금 방식 모두 수입 항목을 저장할 수 있다. 비용 저장을 실제 입금으로 보지 않으며, 정산 요청 이후의 지급 방향·입금 확인·취소 후 미확인 송금은 [분담금 납부](F07-05_pay-share_prd.md), [송금 확인](F07-06_host-confirm-transfers_prd.md), [정산 시작과 취소](F07-03_activate-cancel_prd.md)에서 판단한다.

| Risk | 일반 항목 추가의 응답이 유실되면 오류 후 입력창을 다시 저장할 수 있고 서버 멱등 키가 없다. | 이미 저장된 항목을 중복 추가할 수 있다. 첫 비용의 결과 불확실 복구를 일반 추가의 보장으로 확대하지 않는다. |

| 미검증 | 소스와 선택한 기존 시험 단언을 대조했다. | 실제 업로드·사진 표시·기기 조작·서버 왕복·새 시험 실행은 하지 않았다. 화면 명세의 옛 아이콘 설명 대신 현재 카드 메뉴를 기준으로 작성했다. |

## 수용 기준과 검증 근거

- **AC-01 서버 목록:** 항목 전용 조회로 목록을 읽고 서버 실패를 기기 사본으로 대체하지 않으며 계정 변경 시 이전 계정 목록을 재사용하지 않는다.
- **AC-02 행동 권한:** 추가는 요약의 권한, 수정·삭제는 항목의 권한에 따라 열리고 정보가 없으면 닫힌다. 서버는 생성자·모임 소속·초안을 다시 검사한다.
- **AC-03 필수 입력:** 유효한 비용명·양수 금액·현재 후보의 결제자·한 명 이상의 분담 대상을 선택해야 앱에서 저장한다. 항목마다 대상을 다르게 지정할 수 있다.
- **AC-04 균등 배분:** 참가자 순서와 끝자리 배분을 유지하며 모든 분담금이 양수이고 총합이 항목 금액과 일치한다.
- **AC-05 직접 입력:** 앱은 각 금액의 양수와 합계 일치를 요구한다. 서버의 부족액 자동 보정 선택 기능을 현재 앱의 기본 기능으로 설명하지 않는다.
- **AC-06 비율 배분:** 현재 입력의 서버 미리보기가 검증돼야 저장하며 저장된 원래 비율과 계산 금액을 구분한다.
- **AC-07 중복과 수입:** 서버는 중복 분담 대상과 잘못된 항목 종류를 거절한다. 지출·수입은 양수 금액으로 각각 저장한다.
- **AC-08 기존 배분 복원:** 수정 시 저장된 사람 순서·직접 금액·원래 비율을 불러오고 로딩 중 저장을 막는다. 사용자 변경을 늦게 온 응답으로 덮지 않는다.
- **AC-09 복원 실패와 이탈자:** 배분 조회 실패·중복 응답은 자동 적용하지 않고 다시 선택하도록 알린다. 현재 후보에 없는 사람은 제외 사실을 알려 주고 합계를 재검증한다.
- **AC-10 수정·삭제 반영:** 수정은 기존 분담을 새 배분으로 교체하고 삭제는 해당 분담과 파일 참조를 해제한다. 성공 후 항목·요약을 갱신한다.
- **AC-11 저장 실패와 화면 복귀:** 저장 실패면 입력을 유지한다. 성공은 자신의 입력창만 닫고 전송 중 중복 저장과 다른 계정의 늦은 결과 적용을 막는다.
- **AC-12 영수증:** 업로드 중 저장을 막고 실패 후 직접 입력을 이어 갈 수 있다. 서버는 파일 소유·완료·허용 용도를 검사하고 항목 저장에 맞춰 참조를 갱신한다.
- **AC-13 최근 항목:** 본인 생성 정산의 제목·금액·분류 묶음을 최근 순으로 읽고 기본 10개·최대 30개를 지킨다. 칩은 비용 기본값만 채운다.
- **AC-14 검토와 납부 분리:** 초안의 항목이 정상 조회되고 첫 비용 저장 결과가 확정됐을 때 금액 검토로 이동한다. 항목 저장만으로 정산 요청·입금 완료를 표시하지 않는다.

기존 `settlement_item_form_allocation_test.dart`의 비율 복원·옛 비율 보완·이탈자 제외·저장 실패 보존, `settlement_items_server_only_test.dart`의 연결/권한 실패 시 기기 사본 미사용, `settlement_item_receipt_upload_save_lock_test.dart`의 업로드 중 저장 차단·실패 후 잠금 해제, `MeetingSettlementItemServiceTest.java`의 배분 순서·실제 소속 정산 인가 단언을 읽었다. 시험 코드의 선택한 목적 확인이며 이번 작업의 실행 통과나 모든 수용 기준의 자동 검증을 뜻하지 않는다.
