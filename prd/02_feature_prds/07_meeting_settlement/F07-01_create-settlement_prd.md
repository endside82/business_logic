# F07-01. 정산 초안·첫 비용 저장·지난 정산 복사·계산 결과 가져오기 PRD

<!-- release-document: reference -->
> **2026-11-22 소스 대조.** 정산을 준비하는 현재 동작과 확인 범위다. 실행 시험·실기기·운영 검증 완료를 뜻하지 않는다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

현재 주최자는 정산이 없는 모임에서 **첫 비용 작성**으로 들어가 비용명·금액·먼저 결제한 사람·나눌 사람을 입력한다. 앱은 확인창 뒤 정산 초안을 만들고 첫 항목을 저장하는 두 요청을 차례로 보낸다. 첫 비용 저장만으로 참여자에게 납부를 요청하지 않는다. 성공 뒤 비용 목록에서 금액을 검토하고 별도로 정산을 요청한다.

지난 정산의 항목·분담 구조를 복사하거나 계산기 결과를 모임의 초안으로 가져올 수도 있다. 정산 본체 생성, 첫 비용 저장, 복사, 계산기 가져오기는 서로 다른 동작이다. 결과를 모르는 첫 비용 저장의 자동 재전송을 막는 복구를 복사·가져오기에도 동일하게 제공한다고 해석하지 않는다.

## 실제 입구와 초안 생성

1. 모임 정산 현황에서 서버가 정산 없음으로 응답하면 현재 주최자에게 **정산 만들기**를 표시한다. 다른 회원은 담당자의 생성을 기다리는 안내를 본다. 생성 경로도 현재 주최자인지 다시 확인하고 아니면 모임 상세로 돌려보낸다.
2. 첫 비용 작성에서 **항목별로 납부하기** 또는 **서로 주고받을 돈만 송금하기**를 고른다. 전자는 각 비용의 결제자에게 분담금을 내고 수입은 보유자가 나누는 방식이고, 후자는 비용과 분담금을 모아 필요한 송금을 계산하는 방식이다. 주최자 한 사람이 모든 돈을 받는다는 뜻이 아니다.
3. 첫 비용 저장 확인창은 임시 저장만으로 참여자에게 요청하지 않으며 다음 화면에서 검토해야 한다고 설명한다. 취소하면 요청하지 않는다.
4. 서버의 일반 생성은 이벤트 행을 잠근 뒤 현재 주최자와 기존 정산을 확인하고 금액 0의 초안을 저장한다. 첫 항목·분담금은 이 생성 요청에 포함되지 않는다. 모임 종료 조건은 여기서 검사하지 않으며, 정산 요청 단계에서 모임 상태와 종료 시각을 별도로 판단한다.
5. 같은 모임에는 취소되지 않은 정산이 하나만 존재할 수 있다. 초안·진행·완료 정산이 남아 있으면 새 생성은 거절된다. 취소 이력은 보존하면서 새 정산을 만들 수 있다. 조회 코드와 DB의 조건부 유일성 기준이 이를 뒷받침한다.
6. 서버는 메모와 정산 방식을 받지만 현재 첫 비용 화면에는 별도 정산 메모 입력칸이 없고 생성 요청에도 메모를 싣지 않는다. 비용명과 정산 메모를 혼동하지 않는다.

## 첫 비용 저장과 실패 복구

초안 생성 응답 뒤 앱은 **생성한 초안 번호를 함께 보낸 첫 항목 요청**을 보낸다. 서버는 요청의 초안 번호가 현재 정산과 다르면 거절한다. 취소 후 새로 생긴 다른 정산에 오래된 비용 요청이 붙는 것을 막기 위한 조건이다. 성공하면 관련 조회를 갱신하고 비용 목록으로 이동한다.

| 상황 | 앱의 처리와 다음 행동 |
| --- | --- |
| 초안 생성이 명확히 거절됨 | 입력을 남기고 수정 후 다시 저장할 수 있다. |
| 초안은 생성됐으나 첫 항목이 명확히 거절됨 | 초안 번호와 입력을 보존한다. 비용 목록의 **입력한 첫 비용 이어서 작성**에서 수정한다. 재시도 전에 같은 초안이 여전히 작성 중인지 확인하며 초안을 다시 만들지 않는다. |
| 생성·항목 응답 유실, 결과가 불확실한 오류, 생성 충돌 | 저장을 잠그고 서버의 현재 정산과 항목 목록을 다시 조회한다. 같은 비용을 자동으로 다시 보내지 않는다. 빈 목록 한 번만으로 저장 실패를 확정하지 않는다. |
| 불확실한 저장 뒤 목록을 읽음 | 다시 읽은 비용을 표시하고 **저장 결과 다시 확인**과 비용 목록 이동을 제공한다. 목록 화면의 확인 완료는 사용자의 검토 표시이며 해당 비용의 서버 저장을 자동으로 증명하는 절차가 아니다. |
| 알고 있던 초안이 취소되거나 다른 정산으로 바뀜 | 입력을 남기고 예전 초안 번호를 해제한다. 새 정산 존재 여부를 안내하며 다음 저장도 서버의 중복·초안 조건을 통과해야 한다. |
| 생성 결과를 몰랐는데 서버에 정산이 없음 | 입력을 남겨 다시 저장할 수 있게 한다. 반대로 이미 요청됐거나 끝난 정산이 확인되면 작성을 잠그고 현황 확인을 안내한다. |
| 조회 자체가 실패함 | 불확실 상태를 해제하지 않는다. |
| 중복 탭·계정 변경 뒤 늦은 응답 | 저장 중 추가 실행을 막는다. 이전 계정 응답으로 후속 항목을 저장하거나 새 계정의 상태를 갱신하지 않는다. |

이 복구 상태는 계정에 묶인 앱 메모리 상태다. 프로세스 종료 후 입력 복원까지 보장한다고 적지 않는다. 저장 중·영수증 업로드 중 이탈과 미저장 입력 이탈은 화면의 이탈 보호를 따른다.

## 지난 정산 복사

- 첫 비용 화면의 **지난 정산에서 비용 가져오기**를 누른다. 저장 중·불확실·저장 완료 상태 또는 이미 초안 번호가 있는 상태에서는 이 동작을 막는다.
- 앱 후보는 **본인이 만든 진행 또는 완료 정산**이다. 분담·송금 당사자로 이력에 나타난 타인 작성 정산과 취소 정산은 후보가 아니다. 목록이 없거나 읽지 못한 상태도 구분한다.
- 서버는 대상 모임의 현재 주최자, 대상 모임에 취소되지 않은 정산이 없는지, 원본 정산의 생성자가 요청자인지를 확인한다. 서버 자체는 원본의 진행·완료 상태를 제한하지 않는다.
## 복사되는 내용과 검토

- 새 초안에 항목 이름·금액·보유자·수입/지출·분할 방식·정렬 순서와 각 분담의 사람·금액·비율을 복사한다. 결제 완료·납부액·거래 이력·송금·영수증·항목 분류는 복사하지 않는다. 새 분담은 미납 상태다.
- **메모도 복사**는 기본 꺼짐이다. 켜면 메모 글을 복사하되 원본 메모 작성자가 복사한 본인이 아닌 경우 그 글의 작성자를 본인으로 바꾸지 않는다.
- 원본 사람을 새 모임 참석자로 자동 치환하지 않는다. 정산 요청 시 대상 모임의 주최자·실제 참석 자격을 다시 검사하므로 복사 성공만으로 요청 가능한 구성이 된 것은 아니다. 차단 관계가 새로 돈을 주고받게 되는 구성도 서버 검사 대상이다.
- 성공하면 첫 비용 복구 상태를 초기화하고 비용 목록으로 이동한다. 실패하면 오류를 안내한다. 일반 생성과 복사 모두 서버 멱등 키를 받지 않는다.

## 계산 결과 가져오기와 참가자 후보

계산기 결과의 **모임 정산으로 가져오기**에서 본인이 주최하는 모임을 고르고, 계산에 실제 사용된 사람을 모임 참가자 후보에 연결한다. 이름이 같은 후보를 자동 연결하지만 사용자가 바꿀 수 있다. 자동 연결은 계정 동일성의 확정이 아니다. 모든 계산기 참가자가 연결돼야 제출한다.

후보 조회는 초안이 없어도 현재 주최자에게 열리며, 기존 정산 생성자의 준비 조회 권한도 유지한다. 후보는 주최자를 먼저 포함하고 참석자 중복을 제거한다. 정원이 고정된 정기모임 회차는 실제 출석 기록을 추가로 확인한다. 서버는 가져오기 때 각 연결의 사람 자격을 다시 검사하며 중복 계산기 키나 같은 실제 회원을 여러 키에 연결한 요청은 거절한다.

| 조건 | 가져오기 결과 |
| --- | --- |
| 현재 주최자이고 정산 없음 | 새 초안을 만들고 계산 결과를 항목·분담으로 저장한다. |
| 현재 주최자이고 기존 초안 있음 | 기본은 기존 항목 뒤에 더한다. **임시 저장한 항목을 지우고 가져오기**를 선택하면 기존 항목과 분담을 지우고 가져온다. |
| 기존 정산이 초안 아님 | 상태 오류로 거절한다. |
| 사람 연결 누락·중복·참석 자격 없음 또는 유효하지 않은 항목 | 서버에서 거절하고 같은 트랜잭션의 변경을 되돌린다. |
| 가져오기 성공 | 계산 결과의 정산 방식과 계산된 분담금을 저장한다. 앱은 분담금을 직접 지정하는 항목으로 보내고 메모를 ‘계산기에서 가져온 정산’으로 지정한다. 시트를 닫고 해당 모임의 비용 목록으로 이동한다. |

가져온 항목의 보유자·분담 대상은 실제 회원으로 치환된다. 항목과 분담은 미납 상태이며 영수증·기존 결제 이력을 가져오지 않는다. 서버는 금액 배분을 검증하고 새 차단 관계가 생기는지도 검사한다. 전송 중 시트 이탈·중복 제출을 잠그고 계정이 바뀐 뒤의 늦은 명령 결과를 현재 계정에 적용하지 않는다.

기존 초안에 가져올 때는 정산 방식과 앱이 지정한 메모도 바뀐다. ‘기존 항목 뒤에 더하기’가 기존 초안의 모든 설정을 유지한다는 뜻은 아니다.

## 빠른 추가와 후속 단계의 경계

빠른 추가 경로는 제목·금액 등의 입력값을 받아 비용 입력을 돕는다. 선택한 모임의 정산 요약과 항목 추가 권한을 확인하며, 정산이 없다고 해서 초안을 자동 생성하지 않는다. 실제 저장 성공 때 해당 비용 목록으로 이동한다. 카드사 푸시 자동 수집·외부 앱 공유 연동이 현재 작동한다고 이 경로의 존재만으로 주장하지 않는다.

항목의 세부 분할·영수증·편집은 [정산 항목 관리](F07-02_settlement-items_prd.md), 금액 검토 뒤 요청과 취소는 [정산 시작과 취소](F07-03_activate-cancel_prd.md) 범위다. 생성·복사·가져오기 완료를 납부 요청·입금 완료로 표시하지 않는다.

## 정산 준비 이후 납부와 취소

이 문서는 납부 전 초안을 준비하는 범위다. 지출·수입의 실제 납부자와 수취자, 취소 후 이미 보냈지만 확인되지 않은 송금은 [분담금 납부](F07-05_pay-share_prd.md), [송금 확인](F07-06_host-confirm-transfers_prd.md), [정산 시작과 취소](F07-03_activate-cancel_prd.md)에서 각각 확인한다. 초안 생성 완료를 입금 확인·환불 완료로 확대하지 않는다.

| Gap | 복사 후보의 진행·완료 제한은 앱에만 있고 서버에는 원본 상태 제한이 없다. | 다른 호출자는 본인이 만든 초안·취소 정산도 복사를 시도할 수 있다. 원하는 제품 제한을 서버 계약과 함께 정해야 한다. |
| Risk | 가져오기는 현재 모임 주최자를 검사하지만 기존 정산의 일반 관리자는 생성자를 기준으로 판단한다. | 주최자를 넘긴 모임에서 새 주최자가 옛 생성자의 초안에 가져오는 경로와 일반 편집 권한이 다르다. 이 차이를 권한 검토에 남긴다. |
| Risk | 복사·가져오기에는 서버 멱등 키가 없고 첫 비용 저장의 불확실 결과 복구도 직접 적용되지 않는다. | 전송 중 잠금은 완료 후 재시도까지 막지 않는다. 특히 기존 초안에 더하는 가져오기는 응답 유실 후 재시도로 중복 항목이 생길 수 있으므로 별도 결과 확인이 필요하다. |
| Risk | 계산기 가져오기는 이름 기반 자동 연결을 하고 중복 실제 회원 연결은 서버에서 거절한다. | 동명이인·중복 이름은 사용자가 연결 대상을 검토해야 한다. 이름만으로 정확한 사람을 보장하지 않는다. |
| 미검증 | 기존 시험의 선택한 단언과 현재 코드를 읽었다. 새 시험·실기기·외부 공유·운영 서버 왕복은 실행하지 않았다. | 코드 대조, 기존 시험 목적, 실제 환경의 완료 여부를 분리한다. |

## 수용 기준과 검증 근거

- **AC-01 실제 입구:** 정산 없음 응답을 받은 현재 주최자는 정산 만들기에서 첫 비용 작성에 들어가고, 다른 회원은 생성 단추 없이 안내를 보며 직접 생성 경로도 거절된다.
- **AC-02 본체 생성:** 현재 주최자가 중복 정산 없는 모임에서 일반 생성을 요청하면 금액 0의 초안만 만들어지고 첫 항목은 별도 요청으로 저장된다.
- **AC-03 취소 이력과 중복:** 취소되지 않은 정산이 있으면 새 생성을 거절하며 취소 이력만 남은 모임은 새 정산을 만들 수 있다.
- **AC-04 첫 항목 보존:** 첫 비용의 제목·금액·결제자·참가자 순서를 보존하고 생성 응답의 초안 번호를 항목 요청에 함께 보낸다. 성공하면 비용 목록으로 이동한다.
- **AC-05 항목 거절 복구:** 첫 항목만 거절되면 원래 초안과 입력을 남기고 같은 초안의 상태 확인 뒤 수정한 비용만 재요청한다.
- **AC-06 불확실 결과:** 생성·항목 결과를 모르면 서버 조회만 수행하고 빈 목록을 실패로 단정하거나 같은 비용을 자동 재추가하지 않는다.
- **AC-07 취소와 교체:** 원래 초안이 취소·교체된 경우 예전 번호를 해제하고 입력과 안내를 남긴다. 늦은 항목 요청은 다른 정산에 붙지 않는다.
- **AC-08 계정과 중복 실행:** 전송 중 중복 탭을 차단하며 계정 변경 뒤의 늦은 생성 응답이 후속 항목 쓰기를 만들지 않는다.
- **AC-09 복사 후보와 권한:** 앱은 본인이 만든 진행·완료 정산만 후보로 표시하고 서버도 타인이 생성한 원본의 복사를 거절한다. 두 계층의 원본 상태 제한 차이는 별도로 기록한다.
- **AC-10 복사 내용:** 새 초안에 항목·분담 구조를 옮기고 결제 상태·이력·영수증·항목 분류를 옮기지 않는다. 메모는 선택에 따라 복사한다.
- **AC-11 참가자 재검증:** 후보는 주최자·참석 기준을 따르고 고정 정기모임은 실제 출석을 확인한다. 복사한 옛 참가자가 새 모임의 요청 자격까지 자동 취득하지 않는다.
- **AC-12 계산기 연결:** 계산기의 모든 사용된 사람을 실제 후보에 연결해야 하며 서버는 중복 키·중복 회원·비참석 회원 연결을 거절한다.
- **AC-13 가져오기 방식:** 정산이 없으면 초안을 만들고 기존 초안이면 기본 추가·명시적 교체를 구분한다. 진행·완료 정산에는 가져오지 않는다.
- **AC-14 가져오기 설정과 결과:** 계산된 금액을 직접 지정한 분담으로 저장하고 정산 방식·메모도 반영한다. 저장 중 이탈을 막고 성공하면 대상 비용 목록으로 이동한다.
- **AC-15 준비와 요청 구분:** 첫 비용 저장·복사·가져오기만으로 납부 요청을 보내지 않는다. 빠른 추가는 기존 정산과 권한을 요구하며 초안을 자동 생성하지 않는다.

기존 `settlement_first_expense_provider_test.dart`의 첫 비용 입력 보존·부분 실패·응답 유실·다른 초안·계정 변경 단언, `clone_settlement_sheet_test.dart`의 본인 진행/완료 후보 단언, `MeetingSettlementServiceTest.java`의 생성·가져오기 참가자 검증·분담 저장·복사 순서 단언을 현재 소스와 대조했다. 이는 선택한 시험 코드의 목적 확인이며 이번 작업의 새 실행 통과 기록이나 위 수용 기준 전부의 자동 검증을 뜻하지 않는다.
