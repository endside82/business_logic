# F12-05. FCM 디바이스 토큰 등록 & 기기 관리 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 본문의 요구사항·과거 확인은 현재 미구현 목록이 아닙니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따릅니다.

## 1. 결론

로그인 세션에 기기의 푸시 토큰을 등록하고, 토큰 변경·앱 복귀·로그아웃·계정 전환 때 등록 상태를 맞춘다. 사용자는 설정의 ‘기기 관리’에서 현재 발송 가능한 기기를 조회한다. 앱 실행 때마다 회원과 무관하게 등록하는 흐름은 아니다.

2026-11-22 소스 대조 기준이다. 다른 회원이 쓰던 토큰을 가져와 새 회원에게 옮기지 않으며, 충돌하면 기존 토큰의 발송을 중단하고 새 토큰 발급으로 복구를 시도한다. 기기 목록에서 다른 로그인 세션의 기기를 삭제하는 동작은 서버의 세션 조건과 맞지 않는 제약이 남아 있다.

## 3. 전체 동작 흐름

1. 로그인 세션이 확정되면 기기 등록을 시작한다. 필요한 권한을 요청하고 APNs·FCM 토큰 준비를 기다려 현재 세션으로 등록한다. 준비되지 않았으면 토큰 변경 또는 앱 복귀 시 다시 맞춘다.
2. 토큰이 바뀌면 현재 사용자 세션에서 이전 토큰을 새 토큰으로 바꾼다. 일반 실패는 등록으로 보완하고, 다른 회원 소유 충돌은 토큰을 재발급해 등록한다.
3. 앱 복귀 시 현재 로그인 세션의 등록을 재조정한다. 이전 세션에서 시작한 작업이 새 계정의 등록을 덮어쓰지 않게 세션 작업 순서를 관리한다.
4. 로그아웃하면 서버 세션과 토큰의 연결을 정리하고, 기기의 알림 창·FCM 토큰·등록 표지를 정리한다. 기기 정리가 실패한 몫은 다음 복귀·등록 시 재시도한다.
5. 설정 → 기기 관리에서 서버가 현재 발송 가능하다고 판단한 기기 목록을 읽는다. 비어 있으면 빈 안내, 조회 실패면 재시도를 보여 준다.
6. ‘삭제’를 누르면 확인 창을 거쳐 서버에 요청한다. 앱은 성공 응답을 받으면 목록에서 제외하고 성공을 안내한다. 실패 응답은 목록을 유지하고 오류를 안내한다. 다른 세션 기기의 무변경 성공 응답은 아래 위험을 따른다.

## 4. 제품 규칙

- 서버 등록은 활성 계정과 유효한 로그인 세션을 요구한다. 다른 회원의 토큰을 그대로 재할당하지 않는다.
- 다른 회원 소유 토큰 충돌에서는 이전 발송을 비활성화한 뒤 충돌을 반환한다. 앱은 FCM 토큰을 새로 발급받아 현재 계정으로 다시 등록한다.
- 한 번의 발송과 기기 목록은 발송 가능한 토큰 최대 10개를 대상으로 한다. 계정에 존재하는 모든 과거 기기 기록을 표시하는 화면이 아니다.
- 기기 목록은 운영체제 종류·등록일·수신 상태를 표시한다. 기기를 삭제하는 것은 푸시 수신 등록 정리이며 계정 삭제나 원격 앱 제거가 아니다.
- 삭제는 사용자와 요청 세션이 같은 활성 토큰에 적용된다. 다른 회원뿐 아니라 같은 회원의 다른 세션에도 실제 변경이 없을 수 있다.
- 권한·APNs·토큰 발급·서버 등록이 실패해도 앱의 다른 업무는 계속할 수 있다. 등록 코드가 있다는 사실을 실기기 푸시 전달 성공으로 보지 않는다.

## 6. 상태·권한·시나리오 매트릭스

| ID | 시작 조건 | 행동 | 관찰할 결과 |
|---|---|---|---|
| S1 | 새 기기에서 로그인 | 권한·토큰 준비 후 등록 | 현재 사용자·세션에 토큰이 연결된다 |
| S2 | 같은 계정의 여러 기기 | 기기 관리 조회 | 현재 발송 가능한 기기를 최대 10개 표시한다 |
| S3 | 로그인 중 토큰 변경 | 새 토큰으로 갱신 | 현재 세션의 토큰을 교체하고 일반 실패·소유 충돌을 구분해 복구한다 |
| S4 | 기기 목록에서 삭제 | 확인 후 삭제 요청 | 요청 세션과 같은 기기는 비활성화된다. 다른 세션 기기의 무변경 응답은 위험 표로 구분한다 |
| S5 | 로그인 상태 | 로그아웃·계정 전환 | 이전 세션의 등록·알림 정리를 수행하고 새 계정에 이전 알림 목적지를 섞지 않는다 |
| S6 | 권한 거부 또는 토큰 준비 지연 | 등록 시도·앱 복귀 | 다른 앱 업무는 유지하고 등록은 준비 상태에 따라 재시도한다 |
| S7 | 토큰이 다른 회원 소유 | 현재 회원으로 등록 | 기존 토큰 발송을 비활성화하고 충돌을 반환한다. 앱은 새 토큰을 발급해 등록한다 |
| S8 | 이전 토큰 소유자가 다름 | 토큰 갱신 요청 | 다른 회원 토큰을 현재 회원에게 이전하지 않는다 |

## 8. Gap / Risk

| 판정 | 항목 | 확인 근거 | 영향·남은 확인 |
|---|---|---|---|
| Gap | 다른 세션 기기 삭제의 무변경 성공 | 목록은 계정의 발송 가능한 기기를 조회하지만 `removeDevice`는 사용자·세션 조건으로 갱신한다. 0건 갱신도 성공 응답이고 앱은 해당 행을 숨긴다 | 같은 계정의 두 기기로 다른 세션 기기를 삭제하고 재조회하는 여정을 확인해야 한다. 현재 ‘목록의 모든 기기를 원격 해제할 수 있다’고 안내하지 않는다 |
| 해소됨 | 다른 계정 토큰 충돌을 단순 등록 실패로 취급 | 서버의 기존 발송 비활성화와 앱의 토큰 재발급 분기가 있다 | 충돌 복구 동작을 현재 설명에 반영했다 |
| 미검증 | 실제 기기의 등록·로그아웃·푸시 | 과거 FCM 대역 시험과 현재 소스 대조는 운영 수신 증거가 아니다 | 실제 계정·서명 앱·OS에서 등록·수신·계정 전환을 확인하고 버전을 기록한다 |

## 9. 수용 기준

- **AC-01. 세션 등록**: 로그인한 계정·세션에 토큰이 연결되고 게스트 상태에서는 사용자 등록을 하지 않는다.
- **AC-02. 여러 기기**: 목록의 표시 범위와 최대 10개 발송 범위를 구분하며, 만료·종료된 세션은 발송 대상으로 삼지 않는다.
- **AC-03. 토큰 변경**: 갱신 실패 시 등록 보완, 다른 회원 소유 충돌 시 재발급으로 나뉜다. 이전 세션의 결과가 새 계정에 적용되지 않는다.
- **AC-04. 기기 삭제**: 동일 세션 삭제 후 재조회에서 제외된다. 다른 세션 삭제의 무변경 성공은 현재 공백으로 재현·추적한다.
- **AC-05. 로그아웃**: 서버의 세션 발송을 끊고 기기 알림·토큰 정리를 수행한다. 기기 정리 실패는 재시도 대상으로 남긴다.
- **AC-06. 준비 지연**: 권한·APNs·토큰 발급 지연 때 다른 앱 업무는 유지하며 복귀·토큰 갱신으로 등록을 다시 맞춘다.
- **AC-07. 소유 충돌**: 다른 회원 토큰을 새 계정에 옮기지 않고 이전 발송을 중단한 뒤 재발급 등록을 시도한다.
- **AC-08. 잘못된 갱신**: 다른 회원의 이전 토큰을 지정한 요청으로 그 토큰의 소유자를 바꾸지 않는다.
