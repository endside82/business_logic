# F12-02. 알림 그룹 보기 · 미읽음 배지 PRD

<!-- release-document: reference -->
> **문서 구분: 기능 명세.** 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 2026-11-22 소스 대조이며 실기기 푸시 시험 결과를 뜻하지 않는다.

## 1. 결론

각 탭 첫 화면의 상단 알림 아이콘에서 읽지 않은 수를 확인하고 알림함을 연다. 알림함 안에서 목록 보기와 유형별 그룹 보기를 전환한다. 그룹 보기도 오래된 알림을 이어 불러오며 같은 유형의 건수를 합산한다. 하단 알림 탭과 ‘최근 20건만 그룹화’ 설명은 현재 앱에 해당하지 않는다.

그룹 카드의 수는 지금까지 불러온 알림의 합계이고, 상단 배지는 서버에서 읽은 미읽음 수다. 그룹 카드를 누르면 가장 최근 알림 하나를 열며 그룹 전체를 읽음 처리하지 않는다.

## 2. 코드 위치

서버: `NotificationController`, `NotificationService#readAfter`, `NotificationGroupCursorVo`, `NotificationUnreadCountVo`. 앱: `AppTopBarActions`, `NotificationListScreen`, `GroupedNotificationListNotifier`, `mergeNotificationGroups`, `UnreadCountNotifier`, `NotificationRepository`.

## 3. 전체 동작 흐름

1. 로그인한 회원이 상단 알림 아이콘을 눌러 알림함을 연다. 비로그인 상태에서는 배지 수를 조회하지 않고 로그인으로 안내한다.
2. 알림함 상단의 보기 전환 아이콘을 누르면 같은 종류를 묶은 카드가 보인다. 카드에는 최근 알림, 받은 건수와 그중 읽지 않은 수가 나온다.
3. 끝까지 내리면 이어지는 알림을 받고 같은 종류의 카드에 합친다. 마지막까지 받으면 추가 요청을 멈춘다. 다음 조회 실패 때는 기존 카드를 유지하고 재시도를 제공한다.
4. 카드를 누르면 최근 알림 하나를 읽음 처리하고 해당 업무 화면으로 이동한다. 읽음 처리 중 상단 수를 먼저 줄이고 실패하면 그 차감만 되돌린다. 다른 알림의 읽음 상태까지 바꾸지 않는다.
5. ‘모두 읽음’은 계정의 알림을 일괄 읽음 처리한다. 배지를 먼저 0으로 표시하고 실패하면 복구한다. 같은 시점에 새로 온 알림은 후속 조회로 다시 반영한다.
6. 그룹 보기를 아래로 당기면 그룹과 배지를 다시 읽는다. 업무 화면에서 돌아왔다는 이유만으로 그룹 카드의 수가 즉시 새로 계산된다고 보장하지 않는다. 아래 위험 표의 갱신 범위를 따른다.

## 4. 제품 규칙

- 그룹 조회는 최신 알림부터 20건씩 이어 받는다. 중간에 새 알림이 들어와도 이미 받은 알림을 다음 묶음에 중복 계산하지 않도록 커서를 사용한다.
- 차단한 상대 때문에 한 응답의 표시 항목이 모두 빠져도 뒤에 남은 알림이 있으면 이어 읽는다.
- 상단 배지는 0이면 숨긴다. 읽음·모두 읽음의 실패는 임시 차감을 복구하며, 계정이 바뀌면 이전 계정의 수와 진행 중 변경을 비운다.
- 읽지 않은 알림이 1,000건 이하면 차단 상대의 알림을 빼고 배지를 계산한다. 1,000건을 넘으면 조회 비용을 제한하기 위해 차단 필터 적용 전 수를 반환한다. 이때 배지와 화면에서 센 수가 다를 수 있다.
- 목적지가 없으면 알림을 열 수 없다는 안내를 제공한다. 아직 공개하지 않은 기능의 알림은 목록에 남기고 이동만 제한한다.
- 옛 그룹 페이지 조회는 서버에서 제거됐다. 일반 알림의 쪽 번호 조회는 MCP 위임 조회용으로 남아 있으며, 현재 앱은 일반·그룹 보기 모두 커서 조회를 사용한다.

## 6. 상태·권한·시나리오 매트릭스

| ID | 시작 조건 | 행동 | 관찰할 결과 |
|---|---|---|---|
| S1 | 공지 5건·가입 요청 2건·결제 알림 1건이 모두 미읽음 | 공지 그룹의 최근 알림을 연다 | 최근 공지 1건만 읽음이고 나머지 7건은 미읽음이다. 재조회한 배지는 7이다 |
| S2 | 앱이 열린 상태에서 새 알림이 도착 | 알림함을 열고 새로고침한다 | 새 알림과 서버의 미읽음 수가 표시된다. 실제 FCM 수신은 별도 기기 확인 대상이다 |
| S3 | 미읽음 5건, 읽음 요청이 실패 | 한 건을 열거나 모두 읽음을 누른다 | 임시로 줄인 배지가 복구된다. 동시에 성공한 다른 요청의 결과는 유지된다 |
| S4 | 20건보다 많은 알림과 페이지 사이의 새 알림 | 그룹 보기 끝으로 이동한다 | 다음 묶음을 이어 받고 같은 알림을 중복 계산하지 않는다. 끝에서는 추가 조회가 멈춘다 |
| S5 | 알림이 없음 | 그룹 보기를 연다 | ‘알림이 없습니다’가 보이고 상단 배지는 숨겨진다 |
| S6 | 한 그룹에 여러 미읽음 알림 | 그룹 카드의 최근 알림을 연다 | 나머지 알림은 미읽음으로 남는다. 그룹 전체를 읽으려면 ‘모두 읽음’을 사용한다 |

| 판정 | 항목 | 확인 근거 | 사용자 영향 | 남은 조치·완료 조건 |
|---|---|---|---|---|
| 해소됨 | 첫 20건 한도와 페이지 중복 | 서버 `readAfter`, 앱 `GroupedNotificationListNotifier`·`mergeNotificationGroups` | 오래된 알림을 이어 받고 같은 종류로 합친다 | 본문·수용 기준의 옛 한도 설명을 제거했다 |
| Risk | 읽음 이후 그룹 카드 갱신 | 그룹 화면은 별도 그룹 provider를 보고, 읽음·모두 읽음은 일반 목록과 배지에 적용한다. 그룹 provider에는 이 변경의 직접 반영·무효화가 없다 | 그룹 보기를 유지하면 카드의 미읽음 수가 새로고침 전까지 이전 값일 수 있다 | 실제 알림 여정에서 그룹 보기 → 읽음 → 복귀와 모두 읽음 직후를 재현해 갱신 범위를 확인한다 |
| Risk | 큰 미읽음 수의 차단 필터 한도 | `NotificationService#getUnreadCount` | 1,000건 초과에서는 배지가 표시 가능한 알림 수보다 클 수 있다 | 현재 제한으로 명시한다. ‘항상 목록과 정확히 같다’고 판정하지 않는다 |
| 미검증 | 운영 푸시·기기 복귀 | 이번 갱신은 소스 대조다 | OS 권한·기기·발송 환경의 정상 수신 여부는 별도다 | [공통 완료 기준과 증거](../../../docs/qa/completion-criteria.html#evidence)에 따라 기록한다 |

## 9. 수용 기준

- **AC-01. 그룹의 최근 알림 읽기**: 공지 5건 등 미읽음 8건에서 공지 카드를 열면 최근 공지만 읽음이 되고 재조회 수는 7이다.
- **AC-02. 새 알림 반영**: 새 알림이 저장된 뒤 알림함을 새로고침하면 해당 내용과 서버의 미읽음 수가 표시된다. FCM 수신 시험은 기기 결과를 별도로 기록한다.
- **AC-03. 실패 복구**: 읽음·모두 읽음 요청이 실패하면 해당 임시 변경만 취소한다. 그 사이 받은 새 알림이나 성공한 다른 읽음을 되돌리지 않는다.
- **AC-04. 이어 불러오기**: 20건이 넘는 그룹 보기에서 다음 알림을 합치고, 중간에 삽입된 새 알림 때문에 같은 알림을 중복 계산하지 않는다. 추가 조회 실패 시 기존 카드와 재시도 입구가 남는다.
- **AC-05. 빈 상태와 계정 변경**: 빈 알림함은 빈 안내와 배지 숨김으로 표시하며 다른 계정으로 바꾸면 이전 계정의 수가 남지 않는다.
- **AC-06. 읽음 범위 구분**: 그룹 카드 탭은 최근 1건만, ‘모두 읽음’은 전체에 적용한다. 그룹 카드의 즉시 갱신은 위 위험 항목과 함께 확인한다.

## 10. 검증 근거

`notification_cursor_wire_test.dart`는 요청 커서와 응답 필드를, `grouped_notification_paging_test.dart`는 이어 읽기와 빈 응답 후 진행을, `grouped_notification_merge_test.dart`는 같은 그룹의 합계를 다룬다. 이번 문서 작업에서는 이 시험의 대상과 소스를 확인했으며 새 실행 통과를 주장하지 않는다. 기준 저장소 버전과 문서별 처리 기록은 [전체 문서 최신화 대조 기록](../../../verification/document-refresh-2026-11-22.json)에 있다.
