# F12-03. 카테고리별 알림 설정 PRD

<!-- release-document: reference -->
> **문서 구분: 기능 명세.** 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 2026-11-22 소스 대조이며 외부 푸시·메일의 실제 전달 확인을 뜻하지 않는다.

## 1. 결론

알림함의 설정 아이콘에서 알림 종류를 역할별 묶음으로 켜고 끈다. 현재 앱 스위치는 푸시와 알림함 기록을 함께 바꾸며 이메일 채널은 이 화면에서 변경하지 않는다. 한 묶음을 바꿀 때 한 번에 저장하므로 종류마다 별도 요청을 보내 일부만 저장하는 방식이 아니다.

‘광고성 정보 수신’은 채널 설정뿐 아니라 마케팅 수신 동의와 동의 이력도 함께 바꾼다. 동의하지 않은 회원에게 광고성 채널을 기본 켜짐으로 표시하지 않는다. 설정을 끌 수 없는 절차·안전 알림은 별도 기준으로 전달한다.

## 2. 코드 위치

서버: `NotificationController`, `NotificationSettingService`, `NotificationService`, `NotificationType`, `PolicyConsentService`. 앱: `NotificationSettingsScreen`, `NotificationSettingsNotifier`, `NotificationRepository`.

## 3. 전체 동작 흐름

1. 알림함 상단 설정에서 현재 수신 설정을 읽는다. 조회 실패 시 오류와 재시도를 보여 준다.
2. 사용자가 카테고리 스위치를 바꾸면 해당 묶음의 푸시·알림함 설정을 같은 값으로 한 번에 저장한다. 화면에는 변경을 먼저 보여 준다.
3. 서버는 묶음 전체를 한 트랜잭션으로 저장한다. 성공하면 응답값을 반영하고, 실패하면 그 변경만 되돌린 뒤 ‘설정 변경에 실패했습니다’를 안내한다.
4. 광고성 정보 수신을 바꾸면 동의 처리 결과가 알림함에 남는다는 안내도 제공한다. 별도 이메일 설정값은 이 스위치 때문에 바뀌지 않는다.
5. 화면 하단의 방해금지 시간으로 이동해 시간·요일을 설정할 수 있다. 돌아온 뒤에도 저장한 카테고리 설정은 유지된다.

## 4. 제품 규칙

- 현재 묶음은 이벤트, 모임 운영, 클럽, 1:1 메시지, 클럽 채팅, 결제·환불, 정산·지갑, 서비스 제공자 활동, 데이팅, 문의·안전·신고, 광고성 정보 수신, 추천의 12개다.
- 한 묶음에 속한 종류의 푸시와 알림함 설정이 모두 켜져 있을 때만 스위치가 켜진다. 일부만 켜진 중간 상태는 별도 표시하지 않는다.
- 끈 카테고리의 새 푸시와 새 알림함 기록은 함께 중단된다. 이미 받은 알림을 삭제하는 행동은 아니다.
- 설정이 없는 일반 종류의 기본 채널 값은 켜짐이다. 광고성 종류는 마케팅 수신 동의가 없으면 푸시·이메일·알림함 모두 꺼짐으로 조회된다.
- 광고 스위치는 수신 동의를 변경한다. 직접 이메일 채널만 변경하는 별도 요청은 수신 동의를 변경하지 않는다.
- 항상 전달하도록 정한 안전·계정 권리 관련 알림은 카테고리 스위치로 끌 수 없다. 방해금지는 별도 기능이며 OS 알림 권한과도 다르다.
- 서버에 없는 종류 이름은 저장을 거절한다. 호환 대상인 폐기 종류 이름은 묶음 요청에서만 건너뛰고 실제로 유지 중인 종류를 저장한다.

## 6. 상태·권한·시나리오 매트릭스

| ID | 시작 조건 | 행동 | 관찰할 결과 |
|---|---|---|---|
| S1 | 광고 수신 동의와 채널이 켜짐 | 광고성 정보 수신을 끈다 | 광고 푸시·알림함 수신과 동의가 꺼지고 처리 안내가 나온다. 과거 알림은 남는다 |
| S2 | 데이팅 묶음이 꺼짐 | 스위치를 켠다 | 그 묶음의 두 채널을 함께 저장한다. 기능 공개·OS 권한까지 켜는 동작은 아니다 |
| S3 | 같은 묶음 안 일부 채널만 켜짐 | 설정 화면을 연다 | 묶음 스위치는 꺼짐으로 보인다. 켜면 해당 묶음의 두 채널을 모두 켠다 |
| S4 | 저장 중 네트워크 실패 | 묶음 스위치를 바꾼다 | 서버의 일부 종류만 저장되는 결과가 없고, 앱은 실패 안내와 해당 임시 변경 복구를 제공한다 |
| S5 | 알림 설정이 열림 | 방해금지 시간을 열고 저장해 돌아온다 | 시간 설정이 저장되고 카테고리 설정은 그대로다 |
| S6 | 알 수 없는 종류를 포함한 직접 요청 | 묶음 저장을 요청한다 | 전체를 잘못된 입력으로 거절한다. 폐기 이름의 명시적 호환은 구분한다 |

## 8. Gap / Risk

| 판정 | 항목 | 확인 근거 | 사용자 영향 | 남은 조치·완료 조건 |
|---|---|---|---|---|
| 해소됨 | 종류마다 요청해 부분 저장 | `updateSettingsBulk`와 앱 `_updateCategory` | 카테고리 한 번의 변경이 한 요청·한 트랜잭션으로 처리된다 | 본문의 옛 병렬 PATCH·부분 저장 설명을 제거했다 |
| 해소됨 | 푸시만 꺼져 알림함에 계속 기록 | 앱이 두 채널을 함께 보내고 서버가 알림함 설정을 검사한다 | 스위치 의미와 실제 수신 중단 범위가 일치한다 | 이메일 토글이라는 옛 설명도 제거했다 |
| Risk | 혼합 채널 상태 표시 | `_CategoryToggle`의 전체 켜짐 판정 | 일부 채널만 켜진 경우도 꺼짐으로 보인다 | 현재 표현의 한계로 명시한다 |
| 미검증 | 실제 전달 환경 | 이번 작업은 소스 대조다 | 설정·동의 저장만으로 기기 수신이나 메일 발송까지 보장하지 않는다 | 실제 발송 확인은 별도 환경·버전·결과를 기록한다 |

## 9. 수용 기준

- **AC-01. 광고 수신 변경**: 광고 스위치를 끄면 두 채널과 동의가 함께 바뀌고, 다시 조회해도 꺼짐이다. 이미 받은 기록은 남는다.
- **AC-02. 묶음 켜기**: 꺼진 묶음을 켜면 묶음 안 현재 종류의 푸시·알림함 설정이 함께 저장된다. 이메일은 기존 값을 유지한다.
- **AC-03. 혼합 상태**: 일부 채널만 켜진 데이터에서는 꺼짐으로 표시하고, 켜기 이후에는 전체 켜짐으로 표시한다.
- **AC-04. 저장 실패**: 잘못된 요청은 부분 저장 없이 실패한다. 앱은 실패한 변경만 취소하고 다른 성공한 변경은 보존한다.
- **AC-05. 방해금지 왕복**: 방해금지 화면을 저장·닫은 뒤 원래 설정 화면으로 돌아오며 카테고리 저장 결과가 유지된다.
- **AC-06. 종류 검증**: 미등록 이름은 거절하고 명시된 폐기 이름 호환은 묶음 요청에서만 적용한다.

## 10. 검증 범위

앱의 `notification_settings_taxonomy_test.dart`는 현재 알림 종류가 조정 가능한 묶음 또는 항상 전달하는 집합에 분류되는지 확인한다. 이번 갱신의 기준 소스와 처리 결과는 [전체 문서 대조 기록](../../../verification/document-refresh-2026-11-22.json)에 둔다. 시험 파일 존재를 새 실행 통과로 기록하지 않는다.
