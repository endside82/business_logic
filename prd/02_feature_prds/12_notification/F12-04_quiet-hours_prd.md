## 1. 결론

알림 설정의 ‘방해금지 시간’에서 푸시를 받지 않을 시간·요일을 저장한다. 한국 시간 기준으로 자정을 넘는 구간도 지원한다. 이 설정만으로 알림함 기록을 막지는 않으며, 실제 기록 여부는 카테고리·수신 동의·대상자 조건도 따른다. 안전·계정 권리 등 방해금지 예외 종류는 별도 정책을 따른다.

2026-11-22 소스 대조 기준이다. 방해금지를 끄는 것은 시간에 의한 제한을 푸는 동작이며, OS 권한·카테고리 설정·토큰·발송 환경까지 모두 정상으로 만드는 동작은 아니다.

## 3. 전체 동작 흐름

1. 알림 설정 하단의 ‘방해금지 시간’을 열어 현재 사용 여부, 시작·종료 시각, 요일을 읽는다. 처음 설정하는 경우는 꺼짐·22:00~08:00·매일이다.
2. 사용 여부를 켜면 시간과 요일을 바꿀 수 있다. 끄면 입력은 비활성화되고 기존 설정값은 유지한다.
3. 켠 상태에서 요일을 모두 해제하고 저장하면 ‘방해금지 요일을 하나 이상 선택해주세요’를 표시하고 요청을 보내지 않는다.
4. 저장 중에는 진행 상태를 표시한다. 성공하면 ‘저장되었습니다’와 함께 알림 설정으로 돌아간다. 실패하면 오류 안내와 함께 입력 화면에 남는다.
5. 발송할 때 현재 수신자·발송 대상·카테고리·동의와 방해금지 조건을 다시 확인한다. 방해금지에 걸린 푸시는 건너뛰며 종료 시각까지 보류했다가 자동 재발송하는 기능은 아니다.

## 4. 제품 규칙

- 방해금지는 정한 시간과 요일에 푸시만 보내지 않는 규칙이다. 알림 종류별 설정과 따로 작동하고, 알림은 알림함에 정상으로 쌓이며 차단된 푸시를 나중에 다시 보내지는 않는다.
- 시각은 한국 시간 기준이다. 시작과 종료가 같으면 선택한 요일 하루 전체가 방해금지다. 같은 날 구간(예 09:00~22:00)은 시작 이상 종료 미만이다. 자정을 넘는 구간(예 금요일 22:00~토요일 08:00)은 시작 요일 기준으로 다음 날 새벽 종료 시각 전까지 이어진다.
- 앱은 켠 상태에서 최소 한 요일을 요구한다. 직접 요청의 빈 요일 목록은 매일로 저장하고, 요일 자체를 보내지 않으면 기존 값을 유지한다. 월요일은 1, 일요일은 7이다.
- 계정 권리와 관련된 절차 통지와 안전 체크인 알림은 방해금지 중에도 전달된다.
- 화면: 스위치를 끄면 시간과 요일 입력이 막힌다. 켜져 있으면 「HH:mm ~ HH:mm · N일 적용」 요약이 보인다. 요일을 하나도 고르지 않으면 오류색 안내가 나온다. 저장하면 「저장되었습니다」 토스트와 함께 이전 화면으로 돌아가고, 실패하면 오류 토스트와 함께 화면에 남는다.

|---|---|---|---|
| S1 | 야간 방해금지 22:00~07:00, 평일만 적용 (Happy Path) | 처음 방해금지 화면 진입(서버 미저장) | 알림 설정 화면 복귀. 월~금에 시작하는 22:00~다음 날 07:00 구간의 푸시는 차단되고 인박스는 정상 적재 |

| S5 | 권한 카테고리(F12-03) OFF + 방해금지 모두 적용 | 광고성 정보 수신 스위치가 꺼져 있고, 이벤트 카테고리는 켜짐·방해금지 22:00~07:00 | 광고는 새 알림함 기록과 푸시가 모두 중단된다. 일반 이벤트 알림은 알림함에 남되 야간 푸시만 제한된다 |

## 9. 수용 기준

- **AC-01. 평일 야간**: 월~금·22:00~07:00을 저장하면 선택한 날 밤부터 다음 날 07:00 전까지 일반 푸시를 제한한다. 다른 수신 조건이 허용하면 알림함에는 기록한다.
- **AC-02. 일시 해제**: 꺼짐을 저장하면 시간에 따른 제한을 해제하고 기존 시간·요일을 보존한다. 다른 차단 조건은 유지한다.
- **AC-03. 자정·경계 시각**: 금요일 야간은 토요일 새벽까지 이어지고 종료 시각부터 해제된다. 시작과 종료가 같으면 선택한 요일 전체에 적용한다.
- **AC-04. 저장 실패**: 저장이 실패하면 오류 안내와 입력 화면이 남는다. 네트워크 응답을 잃은 경우 다시 조회해 서버 적용 여부를 구분한다.
- **AC-05. 카테고리와 동의**: 광고 스위치를 끄면 새 광고 기록과 푸시 모두 중단한다. 켜진 일반 카테고리는 야간에도 알림함에 남고 푸시만 제한한다.
- **AC-06. 빈 요일**: 앱은 켜짐·0요일 저장을 막는다. 직접 API의 빈 목록은 매일로 정규화되며, 범위 밖 정수 검증의 공백은 위험 표에 남긴다.


## 10. 확인 근거

시간 판정은 서버 `PushDeliveryEligibility#isQuiet`, 설정 저장은 `NotificationSettingService`·`QuietHoursSetting`, 앱의 입력·복귀는 `QuietHoursScreen#_save`와 `QuietHoursNotifier`에서 확인했다. 도움말의 잘못된 연결과 직접 API의 요일 범위 검증 공백은 현재 코드에도 남아 있으므로 해소 처리하지 않는다. 실제 기기 푸시 결과는 별도 확인 대상이다.
