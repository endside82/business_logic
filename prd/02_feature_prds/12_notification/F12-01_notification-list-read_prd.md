# F12-01. 알림 목록 조회 & 읽음 관리 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 본문의 요구사항·과거 확인은 현재 미구현 목록이 아닙니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따릅니다.

## 1. 결론

각 탭 첫 화면의 상단 알림 아이콘에서 내 알림함을 연다. 최신 알림부터 이어 읽고 개별·전체 읽음과 삭제로 정리한다. 알림을 누르면 해당 업무 화면으로 이동한다. 하단 네 번째 탭이라는 설명과 앱이 쪽 번호로 조회한다는 설명은 현재 구현에 해당하지 않는다.

2026-11-22 서버·앱 소스 대조 기준이다. 읽음과 배지는 실패한 임시 변경을 복구하지만, 스와이프 삭제 실패에는 안내·명시적 화면 복구의 공백이 남아 있다. 푸시를 눌러 들어오는 경로는 알림함을 거치지 않고 대상 화면으로 직접 연결한다.

## 3. 전체 동작 흐름

1. 상단 알림 아이콘에서 알림함을 열어 최신 알림과 미읽음 수를 읽고 기기 권한 상태도 확인한다. 목록은 오늘·어제·이번 주·이전으로 나눈다.
2. 읽지 않은 알림을 누르면 읽음과 배지를 먼저 반영하고 목적지로 이동한다. 서버 요청이 실패하면 그 읽음 변경만 되돌린다. 이미 읽은 알림은 다시 차감하지 않는다.
3. ‘모두 읽음’은 현재 계정의 알림을 일괄 처리한다. 임시 0 표시가 실패하면 복구하고 동시 수신은 후속 조회로 다시 반영한다.
4. 목록 끝에서는 커서로 다음 알림을 읽는다. 새 알림이 삽입되거나 이전 알림이 삭제돼도 쪽 번호 이동 때문에 같은 알림을 반복하거나 건너뛰지 않는다. 추가 조회 실패 시 기존 목록과 재시도를 유지한다.
5. 아래로 당기면 목록과 배지를 새로 읽는다. 업무 화면으로 이동한 뒤 되돌아오면 목록 상태와 배지를 확인한다. 그룹 보기의 별도 집계·갱신 제약은 F12-02를 따른다.
6. 스와이프 삭제가 서버에서 성공하면 목록에서 제외하고 ‘알림이 삭제되었습니다’를 표시한다. Undo는 없으며 실패 시 별도 오류 안내와 명시적 스와이프 복구가 없다.
7. 목적지를 확인할 수 없으면 열 수 없다는 안내를 보여 준다. 공개하지 않은 기능은 목록에 남기고 이동을 제한한다.

## 4. 제품 규칙

- 알림함은 내 알림만 최신순으로 20건씩 보여 주고 아래로 내리면 다음 쪽을 불러온다(마지막 쪽이면 멈춘다). 남의 알림을 읽음 처리하거나 지우려 하면 서버가 거절한다. 읽음의 임시 표시는 복구하지만 삭제 화면의 복구 공백은 아래 표를 따른다.
- 알림을 누르면 읽음 처리와 함께 해당 화면으로 이동한다. 읽음 표시와 미읽음 수는 먼저 화면에 반영하고, 서버 요청이 실패하면 되돌린다. 「모두 읽음」 도 같고 미읽음 수는 0이 된다.
- 삭제는 알림을 왼쪽으로 밀어서 하고 영구 삭제이며 되돌리기는 없다. 삭제 성공 시 「알림이 삭제되었습니다」 토스트가 나온다. 실패에는 오류 안내와 스와이프한 항목을 명시적으로 복구하는 처리가 없다.
- 이동할 화면을 찾지 못한 알림은 읽음 처리한 뒤 「알림을 열 수 없습니다 / 해당 콘텐츠가 삭제되었거나 접근 권한이 없을 수 있습니다」 창을 보여 준다.
- 일정 변경 제안 알림(이벤트 변경 알림 중 제안 종류)은 참가자 응답 화면으로 바로 가고, 변경 확정이나 자동 변경 알림은 이벤트 상세로 간다.
- 푸시 알림을 누르면 알림함을 거치지 않고 해당 화면으로 바로 간다.
- 목록은 오늘, 어제, 이번 주, 이전으로 묶어 보이고, 미읽음은 점과 옅은 배경으로 구분한다. 결제 실패나 정산 거절처럼 사용자가 조치해야 하는 알림은 「주의」 표시와 강조 막대가 붙는다. 시각은 방금, N분 전, N시간 전, N일 전, 그 이상은 월/일이다.
- 알림이 없으면 「알림이 없습니다」 안내가 나온다. 아래로 당겨 목록과 미읽음 수를 새로 받는다.

## 6. 상태/권한/시나리오 매트릭스

|---|---|---|---|
| S1 | 누적된 알림 일괄 정리 후 한 건 딥링크 진입 (Happy Path) | 로그인됨, 상단 알림 배지 "12" | 모든 알림 읽음 처리됨, 사용자는 이벤트 상세에 위치, 상단 알림 배지 0 |

## 8. Gap / Risk

| 판정 | 항목 | 확인 근거 | 영향·남은 확인 |
|---|---|---|---|
| 해소됨 | 선입금·환불·안전 체크인·분쟁 알림의 옛 미연결 설명 | `NotificationRouter`가 결제·입금 확인 큐·정기모임·체크인·분쟁 목적지를 분기한다 | 옛 알림 번호만 보고 현재 미연결이라고 세지 않는다. 종류별 필수 식별자와 공개 범위에 따른 실제 진입은 여정에서 확인한다 |
| 해소됨 | 옛 카풀·버스 개별 알림을 기준으로 한 미연결 설명 | 현재 이동 알림은 `transportCoordinationUpdated`와 통합 이동수단 화면으로 연결한다 | 폐기된 번호의 과거 상태와 현재 생산 알림을 구분한다 |
| Gap | 스와이프 삭제 실패 안내·복구 | `_NotificationItem`의 `Dismissible.onDismissed` → `_onDelete`는 성공 토스트만 처리한다. provider는 실패를 false로 돌려준다 | 삭제 실패 때 사용자가 결과를 확인하고 다시 시도할 수 있는 경로를 실제 화면에서 재현해 수리 범위를 정한다 |
| Decision Needed | 삭제 Undo | 현재 서버는 영구 삭제이고 앱에 Undo가 없다 | 제공 여부를 제품 결정으로 구분한다. 구현됐다고 안내하지 않는다 |
| 미검증 | OS 푸시와 업무 화면 왕복 | 이번 갱신은 소스 대조이며 운영 기기 실행이 아니다 | 해당 앱·서버 버전과 계정으로 도착 화면·행동·결과·복귀를 확인한다 |

미읽음 수의 1,000건 초과 차단 필터 한도와 그룹 카드 갱신 제약은 [그룹 보기 · 미읽음 배지](F12-02_notification-grouped-badge_prd.md)에 있다.

## 9. 수용 기준

- **AC-01. 읽음과 이동**: 미읽음 목록에서 한 건을 열면 해당 알림만 읽음이 되고 올바른 업무 화면으로 이동한다. 모두 읽음 성공 후에는 당시 대상 알림이 읽음이 된다.
- **AC-02. 새 알림**: 새 알림이 도착하면 목록·배지를 갱신하고, 알림에서 해당 역할의 업무 화면으로 이동한다. 실제 FCM 수신은 별도 기기 결과로 기록한다.
- **AC-03. 삭제**: 내 알림 삭제 성공 후 새로 조회해도 항목이 없고 Undo는 제공하지 않는다. 실패 안내·스와이프 복구는 위 공백을 따로 확인한다.
- **AC-04. 소유권**: 남의 알림 읽음·삭제 요청은 서버에서 거절하고 데이터가 바뀌지 않는다. 실패한 읽음의 임시 표시는 복구한다.
- **AC-05. 다음 알림**: 커서로 끝까지 읽으며 삽입·삭제 때문에 같은 알림을 중복 표시하거나 건너뛰지 않는다. 실패하면 기존 목록과 재시도가 남는다.
- **AC-06. 목적지 없음**: 필요한 식별자가 없거나 열 수 없는 대상이면 안내를 표시한다. 공개 범위 차단은 삭제·권한 상실 안내와 구분한다.
