# F06-09. 수익 대시보드 조회 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 2026-11-22 서버·앱 소스와 기존 시험의 확인 대상을 대조했다. 새 제품 시험·실기기·실제 돈 이동의 통과 기록은 아니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

수익 대시보드는 본인의 호스트 정산을 집계해 이번 달·누적 실수령액, 최근 12개월 월별 그래프와 최근 정산 다섯 건을 보여준다. 지갑의 수익 바로가기에서 들어오며, 전체 내역은 정산 목록으로 이어진다. 현재 기간 선택 탭·전 기간 대비 증감률·항목별 상세 이동은 없다.

## 집계 대상과 최근 정산

| 값 | 현재 집계 |
|---|---|
| 누적 수익 | 본인 호스트 정산 중 지급 완료의 실수령액 합계 |
| 이번 달 | 지급 완료이고 정산 시각이 서버의 이번 달 범위에 해당하는 실수령액 |
| 월별 그래프 | 이번 달을 포함한 12개월, 정산 시각 기준 지급 완료 실수령액. 없는 달은 0 |
| 대기 건수·금액 | 대기와 승인 정산. 지급 중·실패·거절을 전부 합친 값이 아님 |
| 최근 정산 | 상태와 무관하게 본인 정산의 생성 시각·번호 내림차순 다섯 건 |

최근 정산은 수익 상위 다섯 이벤트나 지급 완료 다섯 건이 아니다. 이벤트 제목과 정기모임 제목을 구분하고, 정기모임은 정기모임 번호·이름을 유지한다. 이벤트 번호가 없는 정기모임을 이벤트 0번으로 바꾸지 않는다.

서버·앱 API에는 기간 인자가 없다. 서버의 금액 응답은 정수이고 앱도 정수로 읽는다. 대기 건수·금액은 응답과 모델에 있지만 현재 대시보드 본문에 별도 카드로 표시하지 않는다.

## 화면·선택·복귀

본문은 이번 달 총 수익, 월별 막대그래프, 누적 실수령액, 최근 정산 순서다. 차트의 터치 툴팁은 막대의 금액을 보여주며 별도 상세 목록이나 하단창으로 이동하지 않는다. 그래프의 빈 배열 안내와 12개월 0원 자료는 구분한다.

현재 구역 이름은 「이벤트별 수익」이지만 정기모임과 미지급 정산도 들어간다. 행에는 제목·있는 정산일·금액을 표시하고, 정기모임 이름에는 정기모임 표지를 붙인다. 행 자체에는 탭 동작이 없다. 「전체 내역 보기」만 현재 화면 위에 정산 목록을 연다.

누적 수익이 0이고 최근 정산도 없으면 수익 없음과 이용 안내를 보여준다. 생성 버튼은 없다. 누적이 0이어도 대기 정산 행이 있으면 일반 본문을 보여준다. 최초 로딩은 골격, 실패는 오류와 다시 시도다. 일반 본문에는 당겨 새로고침이 있고, 빈 상태에는 이 새로고침을 감싸지 않는다.

## 정산 상태와 외부 지급의 경계

수익 집계의 지급 완료 표시는 호스트 정산의 상태다. 은행 출금 신청·외부 지급의 완료를 이 그래프만으로 증명하지 않는다. 지급 대기·실패·결과 불명은 각각의 돈 흐름에서 판정하며 [정산 내역·이의 제기](F06-10_settlement-appeal_prd.md)와 [결제·정산 공통 정책](../../03_policy_prds/payment_settlement_policy_prd.md)을 함께 확인한다.

## 출금 계좌와 회수 처리의 범위

출금 신청 때의 계좌 보존·결과 불명 복구·미수금 회수는 이 대시보드 조회에서 수행하지 않는다. 과거 이 페이지에 요약한 출금 규칙의 정본은 [결제·정산 공통 정책](../../03_policy_prds/payment_settlement_policy_prd.md)이다. 이번 소스 대조를 실지급·송금처·외부 공급자 계약 검증으로 기록하지 않는다.

## 현재 제한과 확인 범위

| 분류 | 확인한 차이·한계 | 영향·후속 |
|---|---|---|
| Gap | 기존 화면 명세의 기간 탭·증감률·항목 이동·생성 버튼이 현재 구현에 없음 | 현재 기능으로 소개하지 않고 요구 유지 여부와 후속 구현을 구분 |
| Gap | 「이벤트별 수익」에 미지급·정기모임 정산도 들어가지만 행에 상태 배지가 없음 | 완료 수익과 최근 정산 금액을 혼동하지 않도록 명칭·표시 보완 대상 |
| Gap | 빈 상태는 당겨 새로고침이 없고 공급자는 지갑 변경·복귀 갱신을 직접 구독하지 않음 | 새 정산이 생겼거나 상세 처리 후 돌아와도 자동 최신화된다고 보장하지 않음 |
| 미검증 | 계정 변경 후 이 화면의 자료 수명·실제 정산 처리·외부 지급과 대사 | 이번 조회 소스와 기존 시험 목적 대조 밖의 실행 범위 |

## 수용 기준과 검증 근거

- **AC-01 집계 분리:** 누적·이번 달·월별 수익은 지급 완료 실수령액을 사용한다.
- **AC-02 대기 분리:** 대기 응답은 대기·승인만 포함하며 현재 본문 표시와 구분한다.
- **AC-03 최근 순서:** 최근 다섯 건은 모든 상태의 생성 순서이며 수익 순위로 설명하지 않는다.
- **AC-04 정기모임:** 정기모임 번호와 제목을 보존하고 존재하지 않는 이벤트 0번을 만들지 않는다.
- **AC-05 월별 자료:** 최근 12개월을 채우고 거래 없는 달은 0으로 표시한다.
- **AC-06 차트 행동:** 터치는 금액 툴팁이며 월별 상세 페이지나 하단창 이동이 아니다.
- **AC-07 빈 상태:** 누적 0·최근 없음일 때 안내를 보이며 없는 생성 버튼·갱신 행동을 있다고 적지 않는다.
- **AC-08 다음 행동:** 행은 표시용이고 전체 내역만 정산 목록을 위에 연다.
- **AC-09 재조회:** 정상 본문의 당겨 새로고침과 오류 재시도를 제공하며 복귀 자동 갱신의 한계를 남긴다.
- **AC-10 지급 경계:** 수익 조회를 은행 출금·실지급 확인의 근거로 쓰지 않는다.

기존 `EarningsDashboardServiceTest`와 `earnings_event_list_widget_test.dart`는 정기모임 번호·제목 보존과 이벤트 0번 오표시 방지를 확인한다. 이번에는 해당 단언과 조회·집계·화면 소스를 대조했다. 전체 집계의 실DB 재생·실제 정산 지급·기기 검수는 새로 실행하지 않았다.
