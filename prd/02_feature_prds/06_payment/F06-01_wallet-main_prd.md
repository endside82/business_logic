# F06-01. 지갑 메인 조회 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 2026-11-22 서버·앱 소스와 기존 시험의 확인 대상을 대조했다. 새 제품 시험·실기기·실제 돈 이동의 통과 기록은 아니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

지갑은 현재 사용할 포인트와 최근 거래를 확인하고 충전·거래·정산·출금으로 이동하는 허브다. 잔액과 최근 거래는 별도 조회이며, 지갑 잔액 전체가 은행으로 출금할 수 있는 금액이라는 뜻은 아니다. 지갑을 읽을 수 있어도 충전·구독 등 목적지의 공개 범위와 돈 명령 조건은 따로 적용한다.

## 입구·표시·다음 행동

마이의 지갑에서 잔액을 읽은 뒤 다음 구역을 순서대로 보여준다. 자식 화면은 현재 화면 위에 열며, 지갑으로 돌아왔을 때 잔액과 최근 거래를 다시 읽는 경로를 둔다.

| 구역 | 표시와 행동 |
|---|---|
| 잔액 카드 | 전체·유료·무료 포인트, 숨김 토글, 충전하기 |
| 네 바로가기 | 거래내역 → 결제수단 → 수익 → 정산 순서 |
| 내 정산 | 보낼 돈·받을 돈·지난 모임 비용 정산으로 이동. 호스트 정산 바로가기와 목적이 다름 |
| 출금 내역 | 출금 목록과 새 신청으로 연결 |
| 멤버십 | 개인 구독 관리로 연결 |
| 최근 거래 | 최신 세 건과 전체보기. 행 선택은 해당 거래 상세 |

최근 거래는 첫 페이지 세 건을 생성 시각·번호 내림차순으로 읽는다. 지갑 응답에 거래 목록이 포함된다는 옛 설명은 적용하지 않는다. 거래가 없어도 잔액 카드는 0으로 남고 최근 거래 구역만 빈 안내를 보여준다.

## 무료 포인트와 표시 잔액

처음 읽는 회원에게 지갑이 없으면 회원 존재를 확인해 0 잔액 지갑을 만든다. 회원별 고유 제약 경합은 별도 생성 트랜잭션을 재호출해 처리한다. 일반 조회가 잔액을 증가시키지는 않는다.

아직 저장 잔액에서 정리되지 않은 만료 무료 지급분도 조회 시 만료 잔량을 계산해 전체·무료 표시 잔액에서 제외한다. 제외액은 현재 무료 잔액을 넘지 않는다. 이 읽기 보정과 실제 만료 거래 생성은 구분한다. 지급·사용·환불의 만료 규칙은 [결제·정산 공통 정책](../../03_policy_prds/payment_settlement_policy_prd.md)에서 함께 관리한다.

누적 충전·사용·환불·무료 지급 값은 완료 거래에서 각각의 분류 조건으로 다시 집계한다. 지갑 행의 과거 누계 값을 그대로 내보내는 것으로 설명하지 않는다. 현재 메인 화면은 이 네 누계 값을 별도 통계 카드로 표시하지 않는다.

## 갱신·숨김·실패·복귀

| 상황 | 현재 결과 |
|---|---|
| 최초 잔액 로딩·실패 | 골격 또는 지갑 오류와 다시 시도 |
| 최근 거래만 실패 | 잔액·다른 입구는 유지하고 최근 거래 구역에 오류 문구 |
| 화면을 아래로 당김 | 지갑 공급자를 갱신. 최근 거래 공급자를 함께 명시적으로 갱신하지 않음 |
| 자식 화면에서 지갑으로 복귀·앱 재개 | 지갑과 최근 거래를 무효화하는 공통 복귀 처리 |
| 지갑 자료 변경 알림 | 계정 범위를 구독하는 잔액·최근 거래 공급자가 다시 읽음 |
| 잔액 숨김 | 총액을 점으로 가리고 유료·무료 분해 표시도 숨김. 최근 거래 금액은 별도 표시 |

숨김 설정은 기기의 공통 저장 키를 사용하며 계정별 설정이 아니다. 공급자는 처음에 표시 상태로 시작한 뒤 저장된 설정을 비동기로 읽는다. 계정 전환 시 금액 재조회와 기기 표시 취향을 구분한다.

## 모임 환불 회수금과 출금의 경계

모임 환불 회수금·판매 대금 미수금 해결과 출금은 잔액 조회와 별도 돈 흐름이다. 관련 규칙은 [결제·정산 공통 정책](../../03_policy_prds/payment_settlement_policy_prd.md)과 [정산 내역·이의 제기](F06-10_settlement-appeal_prd.md)를 함께 본다. 지갑 허브의 출금 입구가 있다는 사실을 실지급 확인이나 전액 출금 가능 판정으로 쓰지 않는다.

## 현재 제한과 확인 범위

| 분류 | 확인한 차이·한계 | 영향·후속 |
|---|---|---|
| Gap | 당겨 새로고침은 잔액만 명시적으로 갱신하며 최근 거래 오류 구역에 전용 재시도가 없다 | 외부에서 생긴 거래와 잔액을 함께 다시 확인하려는 사용자의 복구 흐름 보완 대상 |
| Risk | 잔액 숨김은 기기 공통 키이고 최초 표시값은 보임이다 | 숨김 복원 전에 금액이 잠시 보일 가능성과 계정별 기대를 구분 |
| 미검증 | 실제 결제·환불·출금 뒤 기기에서의 최신 잔액과 최근 거래 | 이번 작업은 조회 소스 대조이며 실거래·실기기 성공으로 확대하지 않음 |

## 수용 기준과 검증 근거

- **AC-01 첫 지갑:** 회원의 지갑이 없으면 0 잔액 지갑을 만들며 회원별 고유 제약을 유지한다.
- **AC-02 잔액 분리:** 총액·유료·무료를 표시하고 만료 대상 무료 잔량은 조회 표시에서 제외한다.
- **AC-03 조회 분리:** 최근 거래는 지갑 객체와 별도 요청의 최신 세 건이다.
- **AC-04 빈 거래:** 거래가 없어도 지갑 카드를 유지하고 최근 거래에 빈 안내를 보인다.
- **AC-05 입구:** 네 바로가기와 내 정산·출금·멤버십의 목적지를 구분한다.
- **AC-06 부분 실패:** 최근 거래 조회가 실패해도 잔액과 다른 행동 입구를 전체 오류로 바꾸지 않는다.
- **AC-07 복귀:** 자식 화면에서 지갑이 다시 드러나면 잔액과 최근 거래를 재조회하며 단순 팝업 닫기와 구분한다.
- **AC-08 숨김:** 총액과 유료·무료 표시를 숨기되 기기 공통 저장과 최초 복원의 한계를 밝힌다.

이번 근거는 조회·집계·생성 경합 처리·화면과 복귀 공급자의 소스다. 관련 거래 부호 시험의 단언은 별도 거래 기능에서 추적하며 지갑 전체의 새 실행 통과로 세지 않는다.
