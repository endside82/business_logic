# F06-07. 이벤트 개설권 구매·사용·반환 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 2026-11-22 서버·앱 소스와 명시한 기존 시험 단언을 대조했다. 새 제품 시험·기기·실결제·운영 배치의 통과 기록은 아니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

앱 화면 이름은 이벤트 개설권이며 내부 기능명은 호스팅 티켓이다. 유료 지갑 잔액으로 1장당 3,000원, 한 번에 1~100장을 산다. 구매 건 하나에 수량과 6개월 만료일을 저장한다. 등급·수수료 할인·무제한 개최권 상품은 이 구매 화면의 현재 기능이 아니다.

## 입구·보유 목록·구매 조건

앱 경로는 `/profile/wallet/hosting-tickets`다. 개설권 부족 오류의 티켓 구매 이동 대상과 이 경로가 연결된다. 단순히 경로가 있다는 이유로 지갑에 별도 바로가기 메뉴가 있다고 설명하지 않는다. 구매 성공 뒤 자동으로 모임을 개설하거나 새 화면으로 이동하지 않고 현재 화면에서 결과를 알린다.

목록은 본인의 남은 수량이 0보다 크고 만료 시각이 현재보다 뒤인 구매 건을 생성 시각 오름차순 배열로 돌려준다. 앱은 수량을 모두 합산하고 목록 첫 항목의 만료일로 보유·만료 임박 안내를 만든다. 각 구매 건의 만료일을 전부 나열하는 화면은 아니다. 만료된 기록은 새 목록 조회에서 제외되며 화면의 만료 안내 분기는 이전 값이 남은 상태 등과 구분한다.

새로고침은 개설권 목록을 다시 읽는다. 처음 로딩·오류와 재시도를 구분하고, 앞 목록이 있는 새로고침에는 이전 내용을 유지한다. 결제 기능이 닫히면 앱은 구매 영역을 안내로 바꾸고 보유 정보 영역을 유지한다. 서버의 `MARKET` 공개 범위 제한은 이 앱 표시 분기와 별도 조건이다.

수량은 증감 단추로 1~100장, 빠른 선택으로 1·5·10·20장을 고른다. 앱과 서버 단가는 각각 3,000원으로 정의돼 있다. 무료 포인트는 살 때 쓰지 않는다. 유료 잔액을 읽는 중이거나 확인된 잔액이 부족하면 일반 신규 구매를 막고 충전 후 다시 구매하라고 표시한다. 현재 화면에는 부족액을 채워 충전 화면으로 보내는 단추가 없다. 지갑을 못 읽은 상태의 표시 한계는 아래에 기록했다.

## 돈 처리의 재시도와 현재 구매 규칙

구매 확인창은 단가·수량·합계·유료 잔액을 보여 준다. 확인하면 창을 먼저 닫고 요청을 기다린다. 성공은 구매 장수 토스트와 목록·지갑 재조회, 실패는 오류 안내다. 구매 실패만으로 앞 목록 전체를 오류 화면으로 바꾸지 않는다.

요청 본문은 `count`이며 `Idempotency-Key` 헤더가 필수다. 앱은 계정·구매 수량에 결합한 요청 번호를 보관한다. 같은 구매가 진행 중이면 그 요청을 함께 기다리고, 결과를 알 수 없는 실패 뒤 같은 수량으로 다시 시도하면 같은 번호를 보낸다. 이미 끝난 구매의 재생과 새 구매를 구분한다. 같은 번호를 다른 요청 내용에 쓰면 서버가 충돌로 거절한다.

확인하지 못한 같은 구매가 남아 있으면 앱은 그 사실을 표시하고 잔액 부족만으로 결과 재확인까지 막지 않는다. 다만 지갑이 로딩 중이면 단추는 비활성이다. 성공 또는 반영됐을 가능성이 있는 결과에서는 개설권과 지갑을 다시 읽는다. 이미 처리됐지만 저장된 응답을 읽지 못한 전용 오류도 재조회하며, 성공 토스트로 바꾸지 않고 오류를 유지한다.

서버는 요청 수량을 검사하고 구매 가능한 본인 계정·지갑을 잠근 뒤 유료 잔액을 차감한다. 남은 수량과 총수량을 같은 값으로 만든 구매 건, 구매 거래 연결, 회계 기록을 저장한다. 부족하면 차감 정책에 맞는 잔액 부족 오류와 필요액·가능액을 돌려준다. 이 구매 경로가 자동충전을 실행한다고 설명하지 않는다. 요청 번호 재사용 방어와 실제 네트워크 단절·실DB 경합 시험은 별개다.

## 개설 시 사용·모임 취소 시 반환·만료

비공개 모임의 개설 비용으로 개설권을 선택하면 서버가 본인 계정을 잠그고 사용 가능한 후보를 번호 오름차순으로 찾는다. 후보를 잠근 뒤 소유자·회수 여부·잔여 수량·만료 시각을 다시 검사하고 한 장을 줄인다. 모임에는 실제 사용한 개설권 번호를 남긴다. 티켓 구매만으로 별도의 모임 개설 권한·조건까지 충족했다고 보장하지 않는다.

모임 취소 등에서 반환을 요청하면 그 모임의 소비 기록이 가리키는 개설권에만 한 장을 돌려준다. 사용한 적이 없거나 이미 반환해 기록이 지워졌으면 다른 개설권을 늘리지 않는다. 소유자가 맞고, 회수되지 않았고, 잠근 뒤에도 만료 전이며 총수량보다 적을 때만 돌려준다. 만료된 원본을 새 유효기간으로 되살리지 않는다. 반환할 수 없는 원본이어도 소비 기록은 정리한다.

만료 처리 작업은 잠금 뒤 다시 조건을 확인하여 남은 수량을 0으로 만들고 만료 알림을 저장한다. 이 작업은 만료된 장의 포인트 환불을 수행하지 않는다. 실제 알림 수신·배치 실행 완료는 이번 확인 범위가 아니다.

## 운영자가 남은 개설권을 환불하는 경우

회원 앱에는 이 화면의 직접 환불 단추가 없다. 관리자 연계 내부 창구는 구매 거래 근거가 있는 건의 남은 유효 개설권을 환불한다. 대상 계정과 원 구매 자료를 확인하고 잠금 아래 사용 가능한 잔여 수량을 확정한다. 사용했거나 만료된 장, 구매 근거가 없는 건은 임의 금액으로 환불하지 않는다.

환불 단가는 원 구매 금액을 원 총수량으로 나눈 값이고, 현재 상품 상수를 다시 곱해 정하지 않는다. 남은 장을 0으로 만들고 원 거래에 연결해 지갑 반환·회계 기록을 남긴다. 운영 작업 번호를 같은 요청에 재사용하면 최초 결과를 재생한다. 환불 전에 썼던 한 장은 이후 그 모임의 취소에서 반환 조건을 따로 판정한다. 이 반환과 남은 장 환불을 같은 사건으로 합치지 않는다.

## 수용 기준과 검증 근거

- **AC-01 수량과 가격:** 1~100장을 단일 3,000원 단가로 유료 잔액에서 구매한다.
- **AC-02 보유 범위:** 남은 유효 개설권만 조회하며 합계와 첫 항목 만료 안내를 구분한다.
- **AC-03 기능 제한:** 구매 영역 제한과 기존 보유 표시, 서버 공개 범위 조건을 분리한다.
- **AC-04 잔액 부족:** 신규 구매를 막고 결과 미확인 구매의 재시도와 구분한다.
- **AC-05 요청 번호:** 결과 불명의 같은 구매에는 같은 요청 번호를 사용하고 다른 내용 재사용은 거절한다.
- **AC-06 결과 갱신:** 성공·반영 가능 오류에서는 목록과 지갑을 재조회하고 앞 목록을 보존한다.
- **AC-07 사용:** 잠금 뒤 사용 조건을 다시 보고 한 장을 소비하며 모임에 원본 번호를 남긴다.
- **AC-08 반환:** 소비한 원본만 조건에 맞게 복구하고 만료·타인·이미 반환한 원본은 되살리지 않는다.
- **AC-09 만료:** 만료 작업은 잔여 수량을 정리하고 알림을 저장하며 환불과 구분한다.
- **AC-10 운영자 환불:** 원 구매 근거와 남은 유효 장수로 환불하며 작업 번호 재시도를 중복 반환하지 않는다.

기존 `withdrawal_and_ticket_request_key_test.dart`의 장기 응답 유실 뒤 동일 번호, 실패 시 앞 목록 보존, 처리 결과 읽기 실패 뒤 목록·지갑 재조회 단언과 `HostingTicketServiceTest`의 사용 가능 후보 재판정·반환 만료 경계 단언을 확인했다. 이번에는 새 제품 시험·실DB·실결제·알림 수신을 실행하지 않았다.
