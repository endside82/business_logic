# F04-11. 클럽 사진첩·사진 등록·공개 범위·댓글 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계 참고 문서.** 2026-11-22 서버와 앱 소스, 선택한 기존 시험의 단언을 대조했다. 새 제품 실행·실제 파일 전송·이미지 검수 결과는 아니다. 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 현재 범위와 실제 입구

클럽 커뮤니티의 사진첩에서 앨범 목록·상세·사진 보기를 연다. 앨범 만들기는 커뮤니티 화면의 만들기 권한에 따른 버튼이고, 상세에서는 회원에게 사진 선택·업로드를 제공한다. 앨범 수정·삭제와 신고는 상세의 더보기에서 각각 관리 권한·신고 조건에 따라 보인다. 업로드는 상세의 사진 추가에서 열린다.

앨범 댓글과 전체 공개는 별도의 공개 기능 설정을 따른다. 현재 저장소의 운영 기본 목록에는 이 기능이 포함되지 않는다. 환경변수가 목록을 바꿀 수 있으므로 이 사실을 실제 운영 환경의 설정 확인으로 대신하지 않는다. 기본 클럽 사진첩의 구현, 댓글·공개 기능의 구현, 현재 공개 여부를 구분한다.

공개 기능이 열리면 로그인한 사용자에게 클럽 상세의 공개 사진첩 입구가 생긴다. 이 입구는 읽을 수 있는 앨범 목록이 있을 때 표시한다. 일반 회원용 사진첩과 공개 사진첩 경로는 같은 앨범 상세를 사용하되, 회원 여부와 서버가 내려준 행동 권한에 따라 조작이 달라진다. 이 기능은 [모임 사진첩](../03_event/F03-09_event-photos_prd.md)의 만료·잠금·좋아요 정책과 별개다. 현재 클럽 사진첩 창구에는 좋아요 동작이 없다.

## 공개 범위와 열람 권한

사진은 앨범의 공개 범위를 따른다. 기본은 클럽 회원만이며, 전체 공개도 **로그인한 사용자 대상**이다. 사진별 공개 범위나 운영진 전용이라는 별도 값은 없다.

| 열람자·조건 | 앨범 목록·상세·사진 읽기 |
| --- | --- |
| 현재 클럽 회원 | 클럽 회원용·전체 공개 앨범을 모두 읽는다. 이 판정은 클럽이 폐쇄·정지됐다는 이유로 기존 회원의 읽기를 막지 않는다. |
| 로그인한 비회원·공개 기능 열림·활성 클럽·클럽 차단 아님 | 전체 공개 앨범만 읽는다. |
| 비회원이며 공개 기능 닫힘, 클럽 폐쇄·정지 또는 해당 클럽에서 차단됨 | 공개 앨범도 읽지 못한다. |
| 읽을 수 없는 앨범 번호를 직접 요청 | 앨범이 없는 것과 같은 결과로 처리한다. 목록의 전체 수에도 읽을 수 없는 앨범을 합산하지 않는다. |

앨범·사진 목록은 생성 시각 역순과 번호 역순으로 정렬한다. 앱은 앨범 20개, 사진 30개씩 읽고 다음 페이지 실패를 기존 목록 아래에 표시해 재시도한다. 상세는 앨범 정보를 단건으로 읽으므로 첫 앨범 페이지에 없는 대상도 열 수 있다. 대표 이미지·사진은 서버가 발급한 표시 URL을 사용하며 저장 키를 곧바로 이미지 주소로 사용하지 않는다.

## 앨범 생성·수정·삭제

현재 회원은 앨범을 만들 수 있으며 생성 시 클럽 구독 조건을 확인한다. 제목은 필수이고 최대 100자, 설명은 최대 500자다. 공개 범위를 생략하면 클럽 회원용으로 만든다. 전체 공개로 새로 만들거나 전환할 때는 공개 기능이 열려 있어야 한다. 앱은 닫힌 상태에서 공개 범위 선택을 감추고 해당 값을 보내지 않는다.

앨범 수정·삭제는 먼저 해당 앨범을 읽을 수 있는지 확인한 뒤 작성자 또는 유효 운영진에게 허용한다. 따라서 클럽을 나간 작성자도 공개 기능·활성 클럽 등 열람 조건을 만족하는 자신의 공개 앨범은 수정·삭제할 수 있다. **공개 범위를 변경하려면 현재 회원이어야 한다.** 사진 업로드 권한과 앨범 관리 권한도 별개다.

앱은 만들기·수정 요청 중 중복 제출을 막고, 실패하면 입력을 유지한다. 변경한 입력을 닫을 때는 이탈 확인을 거친다. 수정 성공은 목록·단건 정보를 다시 읽고, 앨범 삭제는 확인 후 성공할 때 자신의 상세 화면을 닫는다. 앨범 생성에는 사진 등록과 같은 요청 키 계약이 없다.

앨범 전체 삭제는 포함 사진의 파일 참조를 해제하고 파일 정리를 예약한 뒤 사진과 앨범 데이터를 삭제한다. 요청 응답 시점에 모든 S3 객체가 이미 지워졌다고 설명하지 않는다.

## 사진 등록과 파일 경계

1. 앱은 한 번에 최대 10장을 선택하고 계정·클럽·앨범별 기기 초안에 선택한 원본을 보관한다.
2. 파일 업로드 주소 발급 → 원본 전송 → 파일 업로드 완료 처리를 마쳐야 등록에 사용할 파일 키를 얻는다. 원본 전송이나 완료 처리 실패에는 중단 처리를 요청한다.
3. 파일 키와 사진 등록 요청 키·최초 요청 시각을 기기에 보관한 뒤 앨범 등록 요청을 보낸다. 서버는 현재 회원, 대상 앨범, 등록 한도와 파일 소유자를 확인한다.
4. 파일은 완료 상태이고 클럽 사진 용도여야 한다. 사진 설명과 원래 파일명은 각각 200자 이내다. 앨범 행을 잠근 상태에서 **앨범당 최대 50장**을 검사하고 사진 수와 파일 참조를 갱신한다.
5. 대표 사진이 없으면 처음 등록한 사진이 대표가 된다. 사진 등록 자체는 회원 알림을 발송하지 않는다.

앨범 생성 시 구독 검사와 기존 앨범 사진 등록의 회원 검사는 다른 경로다. 모든 사진 추가에 생성과 동일한 구독 검사가 있다고 쓰지 않는다. 선택 10장과 앨범 50장 제한도 서로 다른 제한이다.

## 업로드 실패·재시도와 기기 초안

등록 완료된 사진은 보관 목록에서 제거하고, 실패하거나 결과가 불명확한 사진만 남긴다. 원본 전송을 마친 사진은 저장한 파일 키와 같은 등록 요청 키로 다시 보낸다. 첫 등록이 확정 실패한 경우에는 해당 파일 정리를 요청하고 원본 선택 상태로 되돌린다. 이미 한 번 요청했던 사진에서 오류가 나면 이전 성공 가능성을 고려해 보관 정보를 유지한다.

앱은 최초 등록 요청 후 23시간 이상 지났거나 기기 시간이 최초 요청 시각보다 과거이면 자동 재전송을 막고 먼저 앨범을 확인하라고 안내한다. 이는 새 키로 다시 보내 중복 등록할 수 있다는 뜻이 아니다. 보관 실패·다른 창의 수정·원본 파일 유실도 각각 안내하며, 보관에 성공하기 전 다음 등록으로 진행하지 않는다.

일부만 등록되면 성공한 사진은 목록에서 빠지고 나머지는 화면에 남는다. 사진·앨범 목록을 새로 읽으며, 모두 완료됐을 때 업로드 화면을 닫는다. 계정이 바뀌거나 세션이 끝나면 이전 세션의 처리 결과를 새 계정에 적용하지 않는다.

## 사진 삭제·선택·대표 사진 복구

단건 삭제는 앨범을 읽을 수 있는 업로더 또는 유효 운영진에게 허용한다. 앨범 작성자라는 이유만으로 다른 사람이 올린 사진을 단건 삭제할 수는 없다. 단, 작성자에게 허용된 앨범 전체 삭제는 앨범 안의 사진 전체를 대상으로 한다.

일괄 삭제는 현재 앨범에서 찾은 사진들을 먼저 검사한다. 일반 사용자의 요청에 타인이 올린 사진이 하나라도 있으면 전체 요청을 거절한다. 다른 앨범의 번호·이미 없는 번호는 현재 앨범 조회 결과에 들어오지 않으며, 일치하는 사진이 없으면 변경 없이 끝난다. 빈 목록과 null 번호는 거절한다.

삭제한 사진 수만큼 앨범 수를 줄이고 파일 참조를 해제·정리 예약한다. 대표 사진을 지웠다면 남은 사진 중 가장 최근 사진으로 바꾸고, 사진이 없으면 대표를 비운다.

앱의 현재 상세는 회원에게 선택·전체 선택·일괄 삭제를 제공한다. 전체 선택은 **지금 읽은 사진들**을 대상으로 하며, 작성자별로 자동 선별하지 않는다. 사진 뷰어는 현재 읽은 사진 목록으로 열린다. 서버 단건 삭제와 탈퇴한 업로더의 삭제 가능 조건을 모두 앱 메뉴에서 제공하는 것으로 설명하지 않는다.

네이티브 앱의 사진 선택 모드에는 하단 다운로드가 있으며 웹에서는 이 입구를 표시하지 않는다. 선택한 항목 중 현재 읽은 사진 목록에 있는 사진의 `downloadUrl`로 바이트를 읽어 기기 사진 보관함에 저장한다. 선택 0장이면 비활성화하고 저장 중 중복 실행을 막는다. 일반 저장 실패는 다음 사진을 계속 처리하지만 사진 추가 권한 거절·저장 공간 부족이면 중단한다. 전체 성공·전체 실패·부분 성공의 저장 수와 저장하지 못한 수를 나눠 안내한다. 이 동작은 파일 다운로드이며 서버의 사진 삭제나 공유 범위를 바꾸지 않는다.

## 댓글·답글·언급

공개 기능이 열린 경우, 앨범 상세의 댓글 수를 눌러 댓글 화면으로 이동한다. 비회원은 열람 가능한 공개 앨범의 댓글을 읽을 수 있지만 작성·수정·삭제는 현재 회원이어야 한다. 수정은 본인, 삭제는 본인 또는 유효 운영진에게 허용한다. 앨범 작성자는 댓글 작성자가 아니라면 작성자라는 이유만으로 다른 회원 댓글을 관리하지 못한다.

댓글은 공백만인 내용을 거절하고 최대 1,000자다. 답글은 활성 부모 댓글에 한 단계만 달 수 있다. 본인 댓글도 삭제·숨김 상태이면 수정할 수 없으며, 같은 상태의 부모에게 답글을 달 수 없다. 삭제는 상태를 바꾸고 해당 댓글의 언급을 지우며 앨범 댓글 수를 1 줄인다. 부모 삭제가 남아 있는 활성 답글까지 지우는 동작은 아니다.

활성 부모 또는 활성 답글이 있는 부모를 오래된 순으로 페이지 조회한다. 삭제·숨김 부모에 남은 답글이 있으면 작성자·언급을 드러내지 않는 삭제 자리 표시를 반환한다. 차단한 작성자의 댓글은 가리고, 읽을 수 있는 답글을 가진 부모는 본문·작성자·언급을 비운 채 답글을 유지한다.

앱은 부모 묶음 50개씩 읽으며 다음 조회에 마지막 부모 번호를 사용한다. 응답의 전체 수는 차단으로 숨기기 전 부모 묶음 수이고, 앨범에 표시하는 댓글 수는 답글을 포함한 활성 댓글 수다. 두 수를 동일한 값으로 비교하지 않는다.

언급은 [게시글 댓글의 언급 판정](F04-09_post-comments_prd.md)과 같은 공통 해석기를 사용한다. 본문에 실제로 있는 별칭과 선택한 대상, 신규 대상의 회원 여부를 확인하며, 수정 때는 새로 추가된 언급에만 새 언급 알림을 만든다. 이 공통 해석기 재사용이 게시글 댓글의 운영 삭제 사유·분쟁 절차까지 공유한다는 뜻은 아니다. 앨범 댓글 삭제 요청에는 해당 사유 본문이 없다.

## 댓글 알림·착지·전송 결과

새 댓글·답글의 수신자는 언급 대상, 부모 작성자, 앨범 작성자 순으로 중복을 제거하고 행위자 본인은 제외한다. 본문은 공백을 정리한 최대 50자 요약으로 알림에 사용하며 전달을 요청한다. 사진 등록 알림과 별개다. 알림에는 클럽·앨범·댓글 정보를 담고, 앱은 댓글 화면과 대상 댓글로 이동한다. 앨범 번호가 없으면 클럽으로 돌아간다.

댓글 작성·삭제 성공 후에는 앨범 수와 이미 읽은 댓글 페이지를 다시 읽는다. 작성 성공과 후속 읽기 실패를 구분하며, 읽기가 실패했다고 이미 작성한 댓글을 다시 보내지는 않는다. 수정은 성공한 경우 읽은 페이지를 갱신한다. 공통 댓글 입력은 전송 중 중복 제출을 막고 실패 시 입력을 남긴다.

알림의 대상 댓글 또는 새로 쓴 부모 댓글을 찾을 때 이미 읽은 페이지를 갱신하고 최대 20개 페이지를 더 읽는다. 찾음·더 읽기 상한·최종 없음·읽기 중단을 구분한다. 최종 없음 판단 전에는 읽은 페이지를 다시 확인한다. 계정 변경 시 탐색 상태를 초기화하며, 오래 걸린 이전 알림의 결과가 새 착지를 덮어쓰지 않도록 한다.

## 수용 기준과 검증 근거

- **AC-01 실제 입구:** 커뮤니티의 만들기 권한으로 앨범을 만들고 상세의 사진 추가·선택·더보기로 조작한다. 댓글·공개 목록 입구는 공개 설정에 따라 달라진다. 네이티브 선택 모드 다운로드·웹 비노출·0장 비활성·저장 중 중복·권한/공간 부족 중단과 부분 성공 수를 구분한다.
- **AC-02 공개 범위:** 현재 회원은 두 공개 범위를 읽고, 로그인 비회원은 공개 기능이 열려 있으며 활성·비차단 클럽의 전체 공개 앨범만 읽는다. 익명 열람 기능으로 설명하지 않는다.
- **AC-03 목록 노출:** 읽지 못하는 앨범은 상세와 사진 조회에서 없는 대상으로 처리하고 목록의 전체 수에도 포함하지 않는다.
- **AC-04 페이지와 단건:** 앨범 20개·사진 30개씩 읽으며 다음 페이지 실패 시 기존 목록과 재시도를 유지한다. 첫 페이지 밖 앨범은 단건 조회로 상세를 연다.
- **AC-05 앨범 생성:** 현재 회원·구독 조건을 검사하고 제목 필수·100자, 설명 500자 한도와 기본 회원 공개를 적용한다.
- **AC-06 관리와 공개 변경:** 열람 가능한 앨범의 작성자·운영진은 수정·삭제할 수 있으나 공개 범위 변경에는 현재 회원 조건이 추가된다.
- **AC-07 입력과 삭제 복귀:** 만들기·수정 실패에는 입력을 남기고 변경한 입력의 이탈을 확인한다. 앨범 삭제 성공에만 상세를 닫는다.
- **AC-08 파일 완료:** 원본 전송뿐 아니라 파일 완료 처리까지 끝내야 사진 등록 키를 사용한다. 서버는 소유자·완료 상태·클럽 사진 용도를 확인한다.
- **AC-09 등록 한도:** 한 번에 선택하는 10장과 서버 앨범 총 50장 한도를 구분하고, 앨범 잠금 아래 수와 대표 사진·파일 참조를 갱신한다.
- **AC-10 등록 재시도:** 파일 키·등록 키·최초 요청 시각을 기기에 보관한 뒤 요청한다. 불명확한 결과는 같은 키로 재시도하며 완료한 사진은 남은 목록에서 제거한다.
- **AC-11 오래된 요청:** 최초 요청 후 23시간 이상 또는 시계 역행이면 자동 재전송을 멈추고 앨범 확인을 안내한다. 보관 실패·원본 유실도 다음 전송과 구분한다.
- **AC-12 부분 성공:** 일부 성공 후 실패 사진을 남기고 목록을 갱신한다. 모두 성공했을 때 업로드 화면을 닫으며 새 계정에 이전 세션 결과를 적용하지 않는다.
- **AC-13 삭제 권한:** 단건은 업로더·운영진, 앨범 전체는 앨범 작성자·운영진이다. 일반 사용자의 일괄 요청에 타인 사진이 있으면 전체를 거절한다.
- **AC-14 대표 사진과 정리:** 대표 삭제 후 남은 최신 사진으로 교체하거나 비운다. 참조 해제·정리 예약을 즉시 S3 삭제 완료로 기록하지 않는다.
- **AC-15 댓글 권한:** 공개 댓글 읽기와 회원 쓰기를 구분한다. 수정은 본인, 삭제는 본인·운영진이며 활성 댓글만 대상이 된다.
- **AC-16 댓글 상태:** 댓글 1,000자와 답글 한 단계를 적용한다. 삭제·숨김 부모는 활성 답글을 유지하는 자리 표시로 반환하고 숨긴 댓글 수정·답글을 거절한다.
- **AC-17 댓글 수와 차단:** 부모 페이지 전체 수·답글 포함 앨범 댓글 수·차단 후 화면 행 수가 서로 다를 수 있음을 명시한다.
- **AC-18 언급과 알림:** 실제 본문과 대상의 공통 언급 판정을 사용하며, 수정은 신규 언급만 알린다. 행위자 제외와 언급·답글·앨범 작성자 수신 중복 제거를 적용한다.
- **AC-19 작성 후 읽기:** 댓글 작성 성공과 후속 목록 읽기 실패를 구분하고, 실패한 읽기 때문에 작성 명령을 다시 보내지 않는다.
- **AC-20 댓글 착지:** 대상 탐색은 추가 20개 페이지 상한·최종 재조회·중단/없음 안내를 구분하며 계정·착지 변경의 오래된 결과를 폐기한다.

`ClubPhotoAlbumCommentServiceTest`의 숨긴 부모 답글 거절·숨긴 본인 댓글 수정 거절·숨긴 부모 자리 표시와 활성 답글 유지 단언을 확인했다. `photo_album_paging_test.dart`의 21번째 앨범 조회·다음 페이지 실패 후 같은 페이지 재시도 단언, `photo_album_cover_recovery_test.dart`의 표시 URL 사용·키만 있을 때 자리 표시 단언을 읽었다. 이 확인은 해당 시험을 새로 실행한 결과가 아니다.
