# F04-01. 클럽 찾기와 모임 탭 탐색 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 현재 작업 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다. 2026-11-22 서버·앱 소스와 선택한 기존 시험 단언을 대조했다. 새 앱·브라우저·이미지 검수 결과가 아니다.

## 결론

모임 탭에서 클럽을 이름·소개 키워드와 카테고리로 찾는다. 공개 클럽 목록은 비로그인도 읽을 수 있으며 **운영 중인 ACTIVE 클럽만** 반환한다. 요청의 status를 바꿔 중지·폐쇄 클럽까지 탐색하는 기능이 아니다. 로그인한 사람에게는 카드의 본인 역할·가입 상태를 덧붙인다.

현재 모임 탭에는 클럽 찾기뿐 아니라 로그인 사용자의 요청·내 클럽·등록/주최 정기모임 구역과 공통 메뉴 링크, 인기 클럽 구역이 함께 있다. 이 화면을 예전의 클럽 격자와 생성 FAB만 있는 화면으로 설명하지 않는다. 상세 열람·가입·탈퇴는 [클럽 상세와 가입·탈퇴](F04-02_club-detail-join_prd.md)의 별도 작업이다.

## 실제 입구와 생성 이동

| 입구·행동 | 현재 결과 |
| --- | --- |
| 모임 탭·전체 메뉴의 클럽 찾기 | /clubs의 모임 화면을 연다. 비로그인도 클럽 찾기·인기 클럽을 볼 수 있다 |
| 로그인 사용자 구역 | 요청·내 클럽·등록한 정기모임·주최 정기모임 구역을 추가로 구성한다. 각 자료의 세부 범위는 해당 기능 문서를 따른다 |
| 클럽 카드 | 해당 번호의 /clubs/{id} 상세를 push로 열어 목록으로 돌아올 수 있게 한다 |
| 인기 클럽 카드 | 같은 상세로 이동한다. 인기 목록은 일반 검색 결과와 별도 자료다 |
| 클럽 만들기 | 공통 메뉴의 로그인 회원용 링크로 생성 화면에 간다. 현재 이 목록 화면에는 별도의 생성 FAB가 없다 |
| 필터 없는 빈 목록 | 로그인 상태이면 첫 클럽 만들기 행동을 제공한다. 검색 결과가 빈 경우와 비로그인에게는 이 행동을 제공하지 않는다 |

새 클럽의 생성 권한·입력·결제·소유 한도는 [클럽 생성과 관리](F04-03_club-crud-transfer_prd.md)를 따른다. 목록의 로그인용 생성 입구가 서버 생성 허가까지 보장하는 것은 아니다.

## 공개 검색 계약

GET /api/v1/clubs는 category·keyword·status와 페이지 값을 받고 Spring Page의 ClubSimpleVo를 반환한다. 서비스는 status를 ACTIVE로 고정한다. 카테고리는 앞뒤 공백을 제거하고 대문자로 정규화해 서버 값인지 검사하며 잘못된 값은 CLUB_INVALID_CATEGORY로 거절한다.

키워드가 비어 있지 않으면 클럽 이름 또는 소개의 대소문자 구분 없는 부분 일치로 찾는다. 정렬은 생성 시각 내림차순, 같은 시각이면 클럽 번호 내림차순이다. 일반 클럽 찾기의 정렬을 인기순·거리순이라고 쓰지 않는다. 조회된 목록과 전체 개수는 같은 검색 조건을 사용한다.

응답에는 번호·클럽장 번호/닉네임·이름·분류·인원·가입 방식·상태·대표 이미지·생성 시각이 있다. 대표 이미지 저장 키를 표시용 URL로 바꾸는 처리가 있으므로 외부 파일 표시와 전혀 무관한 조회라고 설명하지 않는다. 이미지 전송 성공을 이번 소스 대조로 판정하지 않는다.

## 본인 역할과 가입 상태

로그인 사용자의 현재 회원 행이 있으면 myRole과 ACTIVE를 채운다. 회원으로 해결되지 않은 클럽에는 현재 가입 신청 PENDING, 가입 차단 BANNED 정보를 덧붙인다. 익명 조회에는 본인 상태를 채우지 않는다.

목록 카드는 이름·분류·인원·대표 이미지와 역할·가입 상태를 표시한다. 거절 사유·최근 신청 처리 상세는 목록 계약에 포함되지 않으므로 상세에서 확인한다. 카드 배지로 모든 운영 권한을 추정하거나 이미 가입했다는 이유로 모든 상세 행동을 허용하지 않는다.

## 검색 입력과 카테고리

검색은 입력을 제출할 때 적용한다. 타이핑 중 매 글자마다 서버에 검색하지 않는다. 제출하면 현재 카테고리를 유지한 채 첫 페이지를 다시 읽는다. 카테고리를 바꾸면 제출된 검색어와 함께 다시 조회한다.

카테고리는 한 개를 고르며 전체를 누르면 null로 해제한다. 선택된 카테고리를 다시 눌러도 선택값을 전달하는 구조이고 자동으로 전체로 되돌리지 않는다. 앱 매퍼는 서버 코드·숫자값·일부 한국어 별칭을 코드로 바꾼다. 지원하지 않거나 빈 앱 입력은 null이지만 서버에 잘못된 문자열을 직접 보낸 경우는 거절되므로 두 경로를 구분한다.

## 페이지·빈 상태·실패 후 재시도

앱은 20개씩 첫 페이지와 추가 페이지를 읽는다. 끝에 가까워지면 다음 페이지를 요청하고, 추가 조회 실패는 이미 받은 카드를 유지한 채 격자 아래 재시도 줄에 표시한다. 처음 조회 오류는 본문 재시도, 처음 로딩은 불러오는 중 표시를 제공한다.

전체 화면은 빈 결과에서도 아래로 당겨 새로고침할 수 있다. 새로고침은 일반 목록 첫 페이지뿐 아니라 인기 클럽과 로그인 사용자 구역의 자료도 다시 읽게 한다. 계정 범위·클럽 카드 변경 신호가 달라지면 목록을 새 상태로 조회한다. 공통 페이지 처리의 실패 유지와 실제 통신 복구 검증은 구분한다.

카테고리 또는 검색 입력이 있으면 검색 결과가 없다는 안내, 없으면 아직 클럽이 없다는 안내를 사용한다. 인기 구역은 처음 로딩·빈 결과에는 숨기고 오류에는 구역 내 재시도를 제공한다. 일반 목록 오류와 인기 구역 오류가 서로 같은 성공·실패 상태라는 뜻은 아니다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 근거·사용자 영향 | 남은 확인 |
| --- | --- | --- | --- |
| Risk | 입력 중 검색어와 적용된 검색어 | 검색은 제출값으로 요청하지만 빈 화면의 필터 판정은 입력 컨트롤러를 사용한다 | 제출 전 입력을 바꾼 뒤 다시 그려질 때 안내와 실제 필터가 일치하는지 확인 |
| 미검증 | 실제 목록·복귀·통신 | 소스와 기존 시험 단언만 읽었다 | 기기에서 계정 변경·검색/추가 페이지 오류·상세 복귀를 실행 근거로 확인 |

예전의 status로 중지 클럽 탐색, 생성 FAB, 상세 이동의 go, 오프라인이면 곧 정상 목록이라는 설명을 현재 계약으로 교정했다. 카드·지도·목록 이미지를 새로 열어 본 검수는 수행하지 않았다.

## 수용 기준과 검증 근거

- **AC-01 공개 범위:** 비로그인으로 클럽 찾기 목록을 읽고 서버는 ACTIVE 클럽만 반환한다.
- **AC-02 필터와 정렬:** 이름·소개 부분 일치와 유효 카테고리를 적용하고 생성 시각·번호 내림차순으로 페이지를 읽는다.
- **AC-03 상태 분리:** 로그인 카드에 본인 역할·ACTIVE/PENDING/BANNED를 반영하되 가입 결정 사유와 운영 권한은 상세에서 확인한다.
- **AC-04 검색 제출:** 제출 전 입력을 서버 필터 변경으로 취급하지 않고 제출 시 현재 카테고리로 첫 페이지를 읽는다.
- **AC-05 카테고리 해제:** 전체 선택으로 카테고리를 해제하고 앱 매핑의 null과 서버 잘못된 값 거절을 구분한다.
- **AC-06 카드 이동:** 일반·인기 카드에서 동일 클럽 상세로 push하고 원래 목록으로 돌아간다.
- **AC-07 다음 페이지:** 20개 단위로 추가 읽기를 수행하며 실패하면 기존 카드와 재시도 입구를 남긴다.
- **AC-08 첫 조회 오류:** 오류를 정상 목록이나 빈 결과로 바꾸지 않고 재시도를 제공한다.
- **AC-09 새로고침:** 빈 목록에서도 새로고침하고 일반·인기·해당 회원 구역의 자료를 갱신한다.
- **AC-10 생성 입구:** 로그인용 공통 메뉴 링크와 필터 없는 빈 목록의 첫 클럽 만들기로 생성에 가며 없는 FAB를 안내하지 않는다.
- **AC-11 인기 구역:** 일반 검색과 별도로 로딩·빈 결과·오류를 처리하고 오류에는 구역 재시도를 제공한다.
- **AC-12 계정 변경:** 계정·클럽 카드 변경을 구독해 본인 가입 상태가 이전 계정의 값으로 고정되지 않게 한다.

검증 근거: club_list_load_more_failure_footer_test.dart의 두 번째 페이지 실패 뒤 격자 하단 재시도 표시 단언과 club_category_mapper_test.dart의 코드·별칭·숫자값·미지원값 처리 단언을 읽었다. 새로 실행하지 않았다. 공통 페이지 실패 시 기존 항목 보존은 앞서 이벤트 탐색에서 읽은 동일 소스 근거를 재사용했다.
