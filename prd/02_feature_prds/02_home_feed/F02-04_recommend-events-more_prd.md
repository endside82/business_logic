# F02-04. 추천 이벤트 더보기·필터·더 읽기 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 2026-11-22 서버·앱 소스와 기존 시험 목적을 대조했다. 새 제품 시험·실기기·실제 위치 검증 기록이 아니다. 실행 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

로그인 회원은 홈 추천 이벤트의 더보기에서 추천 목록을 연다. 서버는 회원에게 보여줄 후보 전체를 점수순으로 정렬해 페이지를 나누고, 앱은 받은 페이지마다 기간·가격 조건과 선택 정렬을 적용한다. 따라서 현재 필터 결과가 전체 후보에 적용된 서버 검색이라고 설명하지 않는다.

인기 모임 제목 조회는 이 목록에서 호출하지 않는다. 과거 문서의 트렌딩 보강 창구 연결은 제거하며, 검색 화면의 인기 태그와 구분한다.

## 추천 대상과 점수

서버는 미래 시작의 공개 탐색 후보 중 마감 표시·본인 주최·차단 호스트를 제외한다. 회원의 참석·대기 상태와 심사 대기·승인 신청도 제외한다. 클럽 전용·링크 전용·비공개 모임을 공개 추천에 넣지 않는다.

점수는 시작까지 남은 시간, 정원 대비 참여 비율, 주최자 후기, 이벤트 생성 시점, 거리를 조합한다. 동점은 이벤트 번호 내림차순이다. 좌표가 없으면 거리 점수는 기본값을 쓰며, 좌표가 있으면 두 지점의 거리로 점수를 계산한다. 이 방식은 관심사·성향의 직접 일치율이나 실제 참여 성공 확률이 아니다.

앱은 페이지당 20개를 요청한다. 각 페이지 요청에서 현재 위치를 시도하고 얻지 못하면 좌표 없이 요청한다. 위치 권한이 없으면 ‘가까운 순’의 새 선택을 막는다. 가까운 순은 서버가 준 거리 점수 내림차순이며 실제 거리 숫자의 정렬과 구분한다.

## 기간·가격·정렬

| 화면 선택 | 현재 계산 |
|---|---|
| 전체 기간 | 기간으로 제외하지 않음 |
| 오늘 | 서울 날짜 0시와 다음 날 0시 사이. 양 끝 정각 제외 |
| 이번 주 | 현재부터 앞으로 7일 사이. 달력상의 이번 주 종료가 아님 |
| 이번 달 | 현재부터 다음 달 같은 날짜까지. 달력상의 이달 말이 아님 |
| 무료·유료 | 받은 페이지의 가격이 0인지 또는 0보다 큰지로 선별 |
| 추천순 | 서버가 정한 현재 페이지의 순서 |
| 날짜순·인기순·가까운 순 | 받은 페이지 안에서 시작 시각·현재 참가 수·거리 점수로 다시 정렬 |

날짜가 없는 항목은 기간 필터에서 제외한다. 조건이나 정렬을 바꾸면 첫 페이지를 다시 요청한다. 초기화는 기간·가격·정렬을 각각 기본값으로 바꾸는 세 호출이며 단일 변경 요청으로 합쳐져 있다고 설명하지 않는다.

## 추가 조회·빈 결과·실패

화면 하단 가까이 가면 다음 페이지를 가져온다. 요청 중 같은 페이지를 중복으로 읽지 않고, 추가 조회 실패는 앞 목록을 유지한 채 꼬리의 다시 시도를 제공한다. 조건 변경으로 세대가 바뀌면 이전 추가 조회 응답을 현재 목록에 붙이지 않는다.

서버의 다음 페이지 여부·전체 건수는 클라이언트 필터 전 기준이다. 첫 페이지를 필터한 결과가 비면 목록 대신 빈 상태를 그려 스크롤 컨트롤러가 붙지 않는다. 뒤 페이지에 조건을 만족하는 항목이 있어도 이 상태에서 다음 페이지를 자동으로 채우는 경로가 없다. 페이지별 정렬도 이미 읽은 전체 목록을 다시 정렬하지 않으므로 전체 거리순·날짜순을 보장하지 않는다.

첫 조회 실패는 전체 오류와 다시 시도를 제공한다. 목록에서 추천 상세를 위에 열고 돌아오면 목록을 이어 보며, 접근 권한·이벤트 변경에 따른 재조회는 별도로 적용한다. 빈 상태의 ‘조건에 맞는 모임이 생기면 알려드릴게요’ 문구만으로 알림 신청이 생성되는 것은 아니다.

## 추천 이유의 표시

현재 더보기 카드의 추천 배지는 점수 항목 중 가장 큰 값을 선택한다. 거리·참여율·등록 시점·시각은 각각 주변·인기·새 이벤트·임박 표시로 연결되지만, 주최자 후기 점수는 ‘관심사 매칭’ 표시로 연결된다. 이 문구를 실제 관심사 매칭의 구현 증거로 쓰지 않는다. 홈 카드의 별도 이유 창과 더보기 배지는 표시 방식도 다르다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 영향·다음 확인 |
|---|---|---|
| Gap | 빈 첫 페이지 뒤 후보 누락 | 첫 페이지가 클라이언트 필터로 비면 다음 페이지를 읽는 화면 입구가 없어질 수 있음 |
| Gap | 페이지별 재정렬 | 추가 페이지를 붙인 전체 목록이 선택한 거리·날짜·인기순으로 정렬되는 것은 아님 |
| Gap | 기간 이름과 계산 | ‘이번 주·이번 달’이 달력 구간이 아닌 이동 구간을 뜻하는 현재 차이를 명시 |
| Gap | 후기 점수의 관심사 표시 | 후기 신호를 관심사 매칭으로 안내하는 문구 불일치 |
| Gap | 빈 결과의 알림 약속 | 이 목록은 빈 결과 알림을 등록하지 않는데 알림을 약속하는 문구가 있음 |
| Risk | 위치·조건 변경과 페이지 | 페이지마다 위치를 다시 구하며 조건 초기화는 여러 재조회 요청이 될 수 있음 |
| 미검증 | 실제 위치·추천 목록 왕복 | 현재 소스와 기존 시험 목적 확인이며 새 기기 위치·전체 페이지 실행 증거는 없음 |

## 수용 기준과 검증 근거

- **AC-01 입구·권한:** 홈 추천 더보기에서 로그인 범위의 목록을 열고 비로그인 직접 접근은 인증 관문을 적용한다.
- **AC-02 후보:** 공개·미래·마감·본인 주최·차단·참여·신청 제외와 동점 순서를 확인한다.
- **AC-03 위치:** 위치 획득·거부·누락과 거리 점수 기본값, 가까운 순 선택 제한을 구분한다.
- **AC-04 기간:** 오늘·앞으로 7일·다음 달 같은 날짜와 양끝 제외를 실제 계산대로 확인한다.
- **AC-05 가격:** 받은 페이지의 무료·유료 선별과 서버의 전체 후보 건수를 구분한다.
- **AC-06 정렬:** 각 페이지 내부 순서와 누적 목록 전체 순서를 따로 확인한다.
- **AC-07 빈 첫 페이지:** 뒤 페이지에 후보가 있는 상태에서 처음 필터 결과가 비는 경우를 확인한다.
- **AC-08 추가 실패:** 앞 목록 유지·중복 읽기 방지·꼬리 재시도·이전 세대 응답 무시를 확인한다.
- **AC-09 초기화·복귀:** 조건 초기화의 여러 요청과 상세 복귀·권한 변경 재조회가 최종 조건에 맞는지 확인한다.
- **AC-10 표시 의미:** 후기 점수의 배지 문구와 빈 결과의 알림 문구를 실제 구현과 구분한다.

기존 `plan_recommend_wall_clock_test.dart`는 서울 벽시계 기준 기간과 경계 제외를 다룬다. 서버 추천 시험과 공통 페이지 추가 조회 시험도 있다. 해당 시험의 통과 이력을 이번 전체 목록·GPS 검증으로 바꾸지 않는다.
