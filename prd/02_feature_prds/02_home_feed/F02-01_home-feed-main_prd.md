# F02-01. 홈 피드 메인 조회 PRD

<!-- release-document: reference -->
> **문서 구분: 기능·설계·절차 참고 문서.** 2026-11-22 서버·앱 소스와 기존 시험 목적을 대조했다. 새 제품 시험·실기기·실제 위치 검증 기록이 아니다. 실행 순서는 [앞으로 할 일](../../../../docs/plan/NEXT_WORK.md)을 따른다.

## 결론

홈은 공개 탐색 목록과 회원별 활동 목록을 함께 조립한다. 핵심 피드 조회는 추천 이벤트·곧 열리는 이벤트·인기 클럽·새 플랜 네 결과를 묶지만, 화면 전체가 네 구역이나 네 요청만으로 구성되지는 않는다. 내 예정 이벤트·사람 추천·찜한 이벤트·최근 본 이벤트는 별도 공급자가 담당한다.

검색·알림·전체 메뉴는 공통 상단의 세 버튼이다. 해당 입구의 로그인·배지·복귀는 [홈의 검색·알림 진입점](F02-05_search-notification-entry_prd.md)을 따른다.

## 화면 순서와 보이는 조건

| 화면 순서 | 현재 자료와 표시 |
|---|---|
| 위치 안내 | 위치 권한이 거절된 상태이면 안내와 다시 확인 행동 |
| 다가오는 내 이벤트 | 로그인 회원의 신청 목록 중 승인·승인 후 입금 대기 상태를 골라 앞 3개. 빈 목록·로딩·실패이면 구역을 숨김 |
| 추천 이벤트 | 로그인 회원에게 추천 결과 최대 10개. 추천이 없는 경우와 구역 조회 실패를 구분 |
| 곧 열리는 이벤트 | 비로그인도 조회. 시작 시각 순 최대 10개. 거리순 목록이 아님 |
| 다시 만나면 좋을 사람 | 로그인 회원의 추천 최대 10명. 빈 목록·로딩·실패이면 숨김 |
| 인기 클럽 | 활동 중인 클럽을 회원 수 내림차순으로 최대 5개 |
| 찜한 이벤트 | 로그인 회원의 위시리스트 첫 페이지 중 앞 5개. 빈 목록·로딩·실패이면 숨김 |
| 최근 본 이벤트 | 로그인 계정의 기기 식별자 목록 중 앞 10개를 현재 상세로 다시 읽고 성공한 항목만 표시 |
| 새로운 플랜 | 마켓 공개 범위가 열렸을 때 발행된 최신 플랜 최대 5개 |

‘다가오는 내 이벤트’는 현재 앱에서 시작 시각으로 다시 거르거나 정렬하지 않는다. 서버 신청 목록은 신청 생성 시각 내림차순이며, 상태 필터만으로 미래 일정순을 보장하지 않는다. 최근 본 목록도 실패한 상세를 빈자리로 두지 않고 제외하므로 기기 기록 개수와 화면 개수는 다를 수 있다.

## 공개 목록과 회원 추천

곧 열리는 이벤트는 클럽 소속이 없는 독립 이벤트·정기모임 중 공개 또는 승인제 공개, 열린 상태, 숨김 제외, 미래 시작을 적용한다. 로그인 사용자의 차단 호스트는 제외한다. 인기 클럽은 활동 상태, 새 플랜은 발행 상태를 적용하고 로그인 회원의 소속·구매·제작자 맥락을 더한다.

이벤트 추천은 미래 공개 탐색 후보에서 본인 주최·마감 표시·차단 호스트·이미 참석 또는 대기 중인 이벤트·심사 대기 또는 승인된 신청을 제외한다. 시작까지 남은 시간·정원 대비 참여율·주최자 후기·등록 시점·거리를 점수화한다. 관심사나 성향의 직접 매칭만으로 순위를 정한다고 설명하지 않는다. 세부 점수와 더보기의 필터는 [추천 이벤트 더보기](F02-04_recommend-events-more_prd.md)를 따른다.

사람 추천은 함께 참석한 근거가 있는 후보를 사용한다. 활동 가능한 회원·차단·검색 숨김을 조회에서 적용하고, 내가 남긴 다시 만나기 선택·공동 참석·같은 클럽·공통 관심과 취향·최근 만남으로 순위를 정한다. 상대가 나를 선택했는지를 공개하는 목록이 아니다. 화면에서는 제한된 추천 이유를 표시하고 공통 사람 상세를 연다. 차단에 성공하면 현재 추천에서 그 사람의 카드를 먼저 빼고 다시 조회한다. 새 응답이 오면 서버 결과를 그대로 표시하며, 차단 해제도 새 응답을 통해 반영한다.

## 로딩·부분 실패·캐시

핵심 네 결과는 병렬로 요청하되 모두 끝난 뒤 피드 상태에 함께 반영한다. 초기 네 상태가 로딩이면 전체 골격 화면을 보여주고, 네 결과가 모두 실패이면 전체 오류와 재시도를 제공한다. 일부 실패는 해당 구역 오류로 표시한다. 비로그인은 추천 요청을 보내지 않고 빈 성공으로 처리하므로 공개 목록들이 실패해도 ‘네 결과 모두 실패’ 조건과는 다르다.

회원별 보조 구역은 자체 조회·오류 처리를 한다. 핵심 골격·전체 오류 화면이 표시되는 동안에는 본문의 보조 구역도 그려지지 않는다. 성공한 홈 목록의 기기 메모리 캐시는 5분이며 계정 범위가 바뀌면 버린다. 부분 실패 뒤 캐시 재사용의 제한과 강제 갱신은 [홈 피드 새로고침](F02-02_home-feed-refresh_prd.md)을 따른다.

## 위치와 마켓 공개 범위

홈은 위치 권한을 확인하지만 현재 핵심 피드 호출에 위도·경도를 넘기지 않는다. 서버의 거리 점수는 좌표를 받지 못하면 기본값을 쓰며, 예정 이벤트는 미래 시작 시각으로 조회한다. 위치 배너가 있다는 이유로 현재 홈 목록이 내 주변으로 좁혀졌다고 판단하지 않는다.

새 플랜 구역을 숨기는 것은 화면 조건이다. 핵심 묶음은 공개 범위와 별개로 플랜 조회를 시작하고 그 응답도 기다린다. 숨긴 구역의 요청이 없어졌거나 전체 피드 대기 시간에서 제외됐다고 기록하지 않는다.

## 현재 제한과 확인 범위

| 판정 | 항목 | 영향·다음 확인 |
|---|---|---|
| Gap | 위치 안내와 실제 전달 | 홈 핵심 요청은 좌표를 넘기지 않아 주변 추천 안내와 실제 거리 반영이 다름 |
| Gap | 숨긴 플랜의 조회 | 마켓 구역이 없어도 플랜 요청과 전체 묶음 대기는 남음 |
| Gap | 내 예정 이벤트의 날짜 | 상태와 신청 생성순의 앞 3개이며 미래 시작순을 보장하지 않음 |
| Gap | 보조 구역의 실패 숨김 | 사람·내 일정·찜·최근 본 목록은 실패와 빈 결과가 같은 숨김으로 보일 수 있음 |
| Risk | 부분 실패 캐시 | 실패한 구역이 뒤의 캐시 읽기에서 이전 값 또는 빈 성공으로 바뀔 수 있음 |
| 미검증 | 실제 계정·위치·추천 결과 | 소스와 기존 시험 목적 대조이며 새 실기기·기기 위치·추천 품질 검증은 아님 |

## 수용 기준과 검증 근거

- **AC-01 순서:** 로그인·비로그인·마켓 공개 범위에 따라 실제 구역 순서와 숨김을 적용한다.
- **AC-02 공개 목록:** 미래 공개 이벤트·활동 클럽·발행 플랜과 로그인 차단·소속·구매 맥락을 구분한다.
- **AC-03 이벤트 추천:** 본인 주최·참여·신청·차단 제외와 현재 다섯 점수 신호를 적용한다.
- **AC-04 사람 추천:** 공동 참석 근거·활동 상태·차단·검색 숨김을 적용하고 상대의 사적 선택을 노출하지 않는다.
- **AC-05 내 일정:** 승인·입금 대기 상태와 앞 3개의 기준을 표시 이름의 미래 일정 의미와 대조한다.
- **AC-06 최근 본 목록:** 계정별 기기 기록을 현재 상세로 다시 읽고 실패 항목 제외를 확인한다.
- **AC-07 로딩:** 핵심 묶음을 모두 기다리는 초기 골격과 보조 구역의 표시 시점을 구분한다.
- **AC-08 실패:** 전체 오류·구역 오류·보조 구역 숨김과 비로그인 추천 빈 성공을 구분한다.
- **AC-09 캐시·계정:** 5분 캐시·부분 실패·계정 변경·관련 데이터 변경 때 결과를 대조한다.
- **AC-10 위치·공개:** 위치 권한 안내와 실제 좌표 전달, 플랜 숨김과 요청 실행을 따로 확인한다.

기존 `home_nav_test.dart`, `home_feed_market_scope_test.dart`, 사람 추천 위젯 시험, `HomeServiceTest`, `RecommendationServiceTest`, `PersonRecommendationServiceTest`가 있다. 해당 시험의 존재·명시한 목적과 새 실행 결과를 구분한다.
