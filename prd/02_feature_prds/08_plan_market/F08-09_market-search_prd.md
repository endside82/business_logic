## 검색 입구와 사용자 행동

[마켓 메인 탐색](F08-08_market-main-browse_prd.md)의 검색창에서 검색어를 제출하면 `Uri.queryParameters`로 인코딩한 `/market/search?keyword=…`를 연다. `&`, `%`, `=`, `?`가 포함되어도 검색어 일부를 별도 URL 조건으로 분리하지 않는다. 검색창을 누르는 것만으로 이동하는 흐름은 아니다.

라우터는 keyword를 검색칸에 채우고 첫 프레임 뒤 비어 있지 않은 검색어를 실행한다. 키워드 없이 들어오면 입력 안내가 표시된다. 앞뒤 공백을 제거한 값이 비었으면 요청하지 않는다. 이미 결과가 있는 화면에서 공백만 제출해도 이전 검색 상태를 비우지 않는다.

검색 결과 카드는 `itemId`를 그대로 `/market/items/{itemId}`에 전달한다. 이 검색은 통합 검색과 별도이며 뒤로 가기는 들어온 탐색 경로로 돌아간다. 앱 내부 경로의 keyword 처리를 확인한 것이며 임의 외부 웹 URL의 앱 연결까지 검증한 것은 아니다.

## 기간권 판매가 닫혀 있을 때의 목록

검색 API는 인증과 MARKET 공개 범위를 요구한다. 결과는 ON_SALE이며 판매 유형이 열린 상품으로 제한한다. SUBSCRIPTION은 MARKET_PERIOD_PASS를 별도로 확인하므로 마켓 전체가 열려 있어도 기간권 판매가 닫혔다면 검색 결과에서 제외한다.

메인 화면은 같은 조건에서 기간권 칩을 숨기고 해당 유형을 지정한 초기 진입을 전체 유형으로 바꾼다. 현재 검색 화면에는 유형 선택 UI가 없다. [회원 상품과 플랫폼 기간권](F08-06_market-item-management_prd.md#회원-상품과-플랫폼-기간권)의 판매 범위를 함께 따른다. 번들 자체의 노출·구매 규칙은 이 상품 검색 API의 결과와 별개로 확인해야 한다.

## 서버 검색 조건과 화면의 범위

| 서버 조건 | 실제 의미 |
| --- | --- |
| `keyword` | 제목 또는 설명의 대소문자 구분 없는 부분 일치. 공백뿐이면 조건 없음 |
| `categoryId` | 보이는 뿌리는 자신과 활성 직계 자식, 보이는 자식은 자신만 포함 |
| `currencyType`, `itemType` | 지정된 enum 조건; 유효하지 않은 문자열은 INVALID_INPUT |
| `minPrice`, `maxPrice` | amount의 하한·상한을 포함하는 비교 |
| `sortBy` | 최신·인기·낮은 가격·높은 가격 |
| `page`, `size` | 페이지 단위 조회 |

categoryId를 지정했지만 해당 분류가 없거나 보이지 않으면 서비스가 빈 페이지로 조기 반환한다. categoryId 자체를 생략하면 분류로 제한하지 않는다. 이 경우 뒤의 enum 조건 평가까지 진행된다고 보장하지 않는다. 일반 enum 변환은 trim 후 대문자로 비교한다. 앱 Repository는 itemType의 표기 변형을 정규화하며 알 수 없는 선택 필터는 null로 보낼 수 있으므로 직접 API의 잘못된 enum 거절과 앱 필터 전달을 구분한다.

현재 검색 화면은 키워드와 page·size만 전달한다. 서버에 가격·통화·분류·유형·정렬 조건이 있다는 이유로 이 화면에 그 선택 UI가 구현됐다고 기록하지 않는다. 메인 화면의 본문 분류 탐색은 같은 검색 API를 다른 조건으로 사용하는 별도 호출이다.

앱은 키워드 양끝 공백을 제거하지만 서버는 공백이 아닌 문자열을 추가 trim하지 않고 부분 일치에 사용한다. 현재 검색 안내의 **플랜 제목, 설명, 태그에서 검색합니다** 중 태그는 실제 쿼리 대상이 아니다. 자동 완성·인기 검색어·태그 검색 기능이 있다고 확대하지 않는다.

## 페이지·건수·정렬 계약

앱은 20개씩 요청하고 서버는 page=0·size=20 기본값, size 최대100을 적용한다. 검색 결과 건수는 `totalElements`를 우선 사용하며 값이 없을 때만 받은 카드 수를 사용한다. 57건 중 첫20개만 받은 화면도 **57건**으로 표시한다.

최신은 createdAt 내림차순·itemId 내림차순, 인기는 purchaseCount 내림차순·itemId 내림차순이다. 낮은 가격은 amount·itemId 오름차순, 높은 가격은 둘 다 내림차순이다. 정렬 값은 대소문자를 구분하지 않고 누락·알 수 없는 값은 최신으로 처리한다. 현재 검색 화면은 sortBy를 지정하지 않아 이 기본 순서를 사용한다.

추가 요청은 첫 조회 중·조회 오류 중·이미 추가 요청 중·마지막 페이지 뒤에는 진행하지 않는다. 공통 PagedList는 요청 세대를 확인해 재검색/무효화 전의 늦은 추가 페이지가 현재 결과에 붙지 않게 한다. 결과가 화면을 채우지 못한 경우에는 로딩 완료 뒤 스크롤 조건을 다시 확인한다.

## 빈 결과·실패·재검색

검색 전은 입력 안내, 성공한 0건은 해당 검색어의 빈 결과, 첫 조회 실패는 오류와 같은 검색어 재시도로 구분한다. 검색어를 바꾸면 조건을 저장하고 첫 페이지부터 다시 조회한다.

추가 페이지 실패는 받은 카드를 지우지 않고 목록 하단에 오류와 재시도를 제공한다. 이 오류가 남아 있는 동안 스크롤만으로 계속 재요청하지 않으며 **명시적인 하단 재시도**가 같은 다음 페이지를 다시 요청한다. 메인 화면의 별도 수동 페이지 처리와 동일하다고 설명하지 않는다.

화면은 공통 AsyncValue 표시의 이전 데이터 유지 정책을 사용한다. 새 응답이 아직 오지 않은 과도 상태의 카드를 최신 검색 결과로 확정하지 않는다. 검색만으로 구매나 보관함 변경을 수행하지 않는다.

## 요청과 응답

`GET /api/v1/market/search`는 `MarketSearchParam`을 받아 `Page<MarketItemVo>`를 반환한다. 앱은 `PageResponse<MarketItemVo>`로 받아 PagedList의 항목·마지막 페이지·전체 건수와 연결한다. 검색 화면의 호출은 `keyword`, `page`, `size`이며 응답 실패는 Repository의 Result 오류를 통해 표시 상태로 전달된다.

## 조회 거절 뒤의 복구

추가 조회를 포함한 자료 접근 거절에서는 이전 목록과 선택·권한 값을 비우고 오류를 표시한다. 기존 목록 유지·재시도는 통신 오류일 때의 복구이며, 401은 세션 처리에 맡긴다.

## 현재 제한과 확인 범위

| 분류 | 현재 관찰 | 처리 |
| --- | --- | --- |
| Gap | 검색 안내는 태그를 언급하지만 서버는 제목/설명만 검색 | 안내와 지원 범위 불일치를 기록 |
| 범위 | 서버 다중 필터 중 검색 화면이 사용하는 것은 키워드 | 필터 UI 추가는 현재 구현 완료로 계산하지 않음 |
| 미검증 | 실제 데이터의 검색 결과·인증/공개 범위·외부 링크 도착 | 소스 및 선택 단언 대조이며 새 제품 실행 없음 |

과거 URL 사전 입력 시나리오는 로컬 시나리오 문서에 원문으로 보존한다. 과거 기록의 존재가 최신 앱과 서버에서 실행에 성공했다는 증거는 아니다.

## 수용 기준과 검증 근거

- **AC-01 검색어 전달:** 메인 제출 시 URI 인코딩으로 특수문자를 보존하고 keyword가 있는 내부 검색 경로에서는 입력칸을 채운 뒤 첫 조회를 수행한다.
- **AC-02 공백 처리:** 앱은 양끝 공백을 제거하고 공백뿐인 제출은 요청하지 않는다. 기존 결과가 있다면 그 제출만으로 초기 안내로 되돌리지 않는다.
- **AC-03 접근과 판매 범위:** 검색은 인증·MARKET 조건과 ON_SALE·열린 판매 유형을 적용한다. 기간권 봉인은 다른 상품 유형과 별도로 판정한다.
- **AC-04 실제 검색 대상:** 제목·설명 부분 일치를 사용하고 태그 검색이 있다고 기록하지 않는다. 서버의 공백뿐인 검색은 조건 없음이며 앱은 이 요청을 보내지 않는다.
- **AC-05 조건의 경계:** 보이는 뿌리/직계 자식 범위와 숨은 분류 빈 결과를 구분한다. 직접 API enum 오류와 앱 Repository의 선택 필터 정규화를 구분한다.
- **AC-06 화면 필터 범위:** 검색 화면은 키워드와 페이지를 보내고 메인의 분류·가격·정렬 탐색과 분리한다. 기본 정렬은 최신이며 각 서버 정렬의 동률 순서가 명확해야 한다.
- **AC-07 서버 전체 건수:** 첫20개를 받았어도 totalElements가57이면57건을 표시한다. 전체 건수가 없을 때만 받은 항목 수를 사용한다.
- **AC-08 페이지 보호:** 동시 추가 요청과 마지막 페이지 이후 요청을 막고, 재검색 전의 늦은 추가 페이지를 현재 결과에 붙이지 않는다.
- **AC-09 실패 복구:** 첫 오류는 같은 검색어 재시도, 추가 조회의 통신 오류는 기존 목록을 유지한 하단 명시 재시도로 복구한다. 빈 결과를 네트워크 실패와 구분한다.
- **AC-10 상세와 복귀:** 유효한 itemId 카드에서 상품 상세를 열고 뒤로 돌아온다. planId 상세나 구매 명령으로 바꾸어 설명하지 않는다.

`market_search_and_refund_list_test.dart`의 특수문자 경로 전달과 서버 전체57건 표시 단언, `MarketCategoryServiceTest`의 가시 분류 범위 단언을 읽었다. 페이지 복구는 현재 공통 PagedList 구현을 대조했으며 다른 화면의 시험을 이 검색의 실행 통과로 합산하지 않았다. 이번에는 제품 시험·브라우저·이미지 검수를 실행하지 않았다.
