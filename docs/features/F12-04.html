F12-04. 방해금지 시간

알림 설정에서 한국 시간 기준의 방해금지 시간·요일을 저장합니다. 시간에 따른 푸시 제한과 다른 수신 조건을 구분합니다.

설정과 저장

알림 설정의 ‘방해금지 시간’에서 사용 여부, 시작·종료 시각, 적용 요일을 정합니다. 처음 값은 꺼짐·22:00~08:00·매일입니다. 켠 상태에서 요일이 없으면 저장을 막고 안내합니다. 끄면 시간·요일 입력을 비활성화하고 기존 값은 유지합니다.

저장 성공 시 안내 후 알림 설정으로 돌아갑니다. 실패하면 오류 안내와 입력 화면이 남습니다. 응답을 잃은 요청은 서버 적용 여부를 다시 조회해 확인합니다.

한국 시간과 요일 경계

설정적용
09:00~22:00선택한 요일의 시작 시각부터 종료 시각 전까지
금요일 22:00~07:00금요일 밤부터 토요일 07:00 전까지. 새벽에는 시작한 날의 요일을 따름
시작·종료가 같음선택한 요일 하루 전체

건너뛴 푸시를 종료 시각에 자동으로 다시 보내는 기능은 아닙니다.

카테고리·동의와 함께 적용

방해금지만으로 알림함 기록을 막지는 않습니다. 일반 카테고리가 켜져 있고 다른 수신 조건도 허용하면 야간에도 알림함에 남고 푸시만 제한합니다. 광고성 정보 수신을 끄면 새 광고 기록과 푸시가 함께 중단됩니다. 이미 받은 기록은 남습니다.

안전·계정 권리 등 방해금지를 적용하지 않는 종류는 별도 규칙을 따릅니다. 방해금지를 꺼도 카테고리·수신 동의·대상자·OS 권한·기기 등록 조건은 그대로 적용합니다.

확인할 상황과 현재 제약

  • 평일 야간을 저장하고 다음 날 새벽·종료 시각에 적용 범위가 맞는지 확인합니다.
  • 꺼짐을 저장한 뒤 다시 켜도 기존 시간·요일이 유지되는지 확인합니다.
  • 광고 스위치 OFF와 일반 카테고리 ON을 구분해 알림함과 푸시 결과를 확인합니다.
  • 앱은 켜짐·0요일 저장을 막지만, 직접 API의 빈 목록은 매일로 정규화합니다. 1~7 밖 정수의 검증 공백은 남아 있습니다.
  • 현재 도움말 연결이 방해금지 기능과 맞지 않는 문제는 PRD에 남깁니다.

2026년 11월 22일 소스 대조이며 실제 기기 수신 결과와 구분합니다.

이 기능의 출시 완료 기준

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 방해금지 시작/종료와 자정을 넘는 구간이 실제 발송 정책에 맞게 적용된다.
  • 시간대·경계 시각·필수 알림 예외·설정 해제 후 행동을 확인한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 알림의 관련 완료 기준도 함께 확인합니다.
