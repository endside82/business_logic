F03-11. 위시리스트 (찜)

찜 추가·해제 조건과 현재 열람 가능한 목록, 즉시 반영·응답 유실·연속 조작을 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

찜은 관심 있는 모임을 저장하는 개인 목록이다. 참가 신청이나 참석 확정과 별개이며, 찜을 해도 좌석이 확보되지는 않는다. 추가는 현재 상세 열람·모임 상태·공개 범위를 검사하고, 해제는 본인의 저장 행을 지운다. 목록은 현재 상세를 볼 수 있는 모임만 반환한다.

접근 경로와 하트 조작

로그인 회원은 마이의 ‘찜한 이벤트’ 바로가기와 전체 메뉴의 ‘내 활동 → 찜한 이벤트’에서 같은 목록으로 이동한다. 현재 경로는 /profile/wishlist다. 목록 카드를 누르면 해당 모임 상세로 이동한다. 홈·검색 등 카드의 찜 지원 여부는 각 카드 호출부가 정하며, 모든 카드에 하트가 있다고 일반화하지 않는다.

상세에서는 비로그인 사용자의 하트 조작을 로그인으로 연결한다. 로그인 상태에서는 이미 찜했거나 서버의 찜 추가 허용 값이 참일 때 조작할 수 있다. 추가가 막힌 모임도 이미 저장한 찜은 해제할 수 있다. 채운 하트와 테두리 하트로 상태를 구분하며, 색은 공통 의미 색상을 사용한다.

상세의 추가 실패는 공용 거절 처리로 사유를 안내하고 상세를 다시 읽는다. 목록의 실패와 상세의 해제 실패는 ‘잠시 후 다시 시도해주세요’를 표시한다. 모든 입구가 같은 서버 사유 문구를 보여 준다고 쓰지 않는다.

추가·해제의 조건과 반복 요청

요청·조건현재 결과
대상 모임 없음 또는 상세 열람 불가추가 거절. 링크 전용 모임은 공유 토큰을 포함한 상세 열람 판정 적용
취소 모임추가 거절: EVENT_ALREADY_CANCELED
종료 모임추가 거절: EVENT_ALREADY_CLOSED

PRIVATE 공개 범위상세 열람 조건을 충족해도 호스트 또는 해당 클럽 회원이어야 추가 가능
현재 추가 조건 충족·이미 찜함기존 저장 행을 유지하며 새 행을 만들지 않음
해제회원과 모임 번호에 해당하는 본인 저장 행 삭제. 모임 상태·상세 권한·존재를 먼저 검사하지 않음
이미 해제된 항목 재해제추가 삭제할 행이 없어도 정상 처리

추가 조건을 중복 여부보다 먼저 검사한다. 따라서 한 번 찜한 모임이 나중에 종료되면 추가 재요청은 거절될 수 있다. ‘추가를 반복하면 상태와 무관하게 언제나 성공한다’는 설명은 맞지 않는다. 이 사전 중복 검사만으로 동시 요청의 DB 경합까지 검증했다고 표시하지 않는다.

목록·정렬·새로고침

목록은 찜한 시각 내림차순, 같은 시각이면 저장 행 번호 내림차순이다. 앱은 한 번에 20개를 요청한다. 서버는 페이지를 먼저 읽고 현재 상세 열람이 불가능한 항목을 걸러 낸다. 기존 찜의 목록 노출에는 신규 추가와 같은 상태 제한을 다시 적용하지 않으므로, 종료·취소 후에도 상세 열람이 가능하면 남을 수 있다.

첫 조회에는 로딩, 결과가 없으면 ‘관심 이벤트가 여기 모입니다’, 실패하면 재시도를 표시한다. 기존 목록을 새로 읽을 때에는 기존 내용을 유지하는 정책을 사용한다. 빈 화면과 오류 화면도 당겨 새로고침할 수 있다. 다음 페이지 실패는 목록 끝의 재시도로 구분하며, 카드에는 현재 일정·장소 투표 요약을 함께 표시할 수 있다.

즉시 반영·실패·응답 순서

하트를 누르면 앱이 먼저 하트 상태를 반영하고, 해제는 찜 목록에서도 즉시 제거한다. 성공하면 변경을 확정하며 상세와 관련 목록을 갱신한다. 추가 성공은 찜 목록을 다시 읽어 서버 정렬을 반영한다. 서로 다른 항목이나 같은 항목의 연속 요청은 개별 변경으로 관리한다.

실패하면 해당 변경을 취소하고 상세를 다시 읽는다. 서버에 반영됐을 가능성이 있는 통신 오류는 관련 모임·카드의 재조회 신호도 보낸다. 화면의 하트가 즉시 바뀌었다는 사실이나 네트워크 단절만으로 서버 성공을 단정하지 않는다. 계정 범위가 바뀌면 이전 계정의 하트 변경 기록을 지우고, 늦은 응답이 현재 계정의 상태를 덮지 않도록 구분한다.

현재 제한과 확인 범위

분류확인 근거현재 차이·영향후속 확인
RiskWishlistQueryRepository·WishlistService페이지를 읽은 뒤 열람 불가 항목을 제거하므로, 표시 항목 수와 전체 수·페이지 정보가 어긋나거나 중간 페이지가 비어 있을 수 있음열람 가능한 항목만 많은 페이지에 섞인 경우의 목록 끝 도달 확인
Gap상세의 _toggleWishlist·목록의 _onToggle상세 추가 거절에는 사유 처리가 있으나 목록 실패·상세 해제 실패는 공통 오류 문구. 옛 문서의 모든 입구 사유 표시 완료 주장은 과도함입구별 실패 안내의 제품 기준과 실제 표시 대조
미검증소스 및 기존 시험의 선택한 단언동시 DB 요청·실제 통신 단절·공유 토큰 만료 뒤 기기에서의 목록 이용은 이번에 실행하지 않음필요한 환경에서 별도 실행 근거 확보

수용 기준과 검증 근거

  • AC-01 목록 진입: 로그인 회원이 마이 바로가기 또는 전체 메뉴의 찜한 이벤트를 누르면 같은 찜 목록으로 이동하고, 카드 선택은 해당 모임 상세로 이어진다.
  • AC-02 정상 추가: 상세 열람과 찜 추가 조건을 충족한 모임의 하트를 누르면 먼저 상태를 반영하고, 정상 응답 뒤 찜 목록을 다시 읽는다. 참가 행이나 좌석 확보로 표시하지 않는다.
  • AC-03 상태별 거절: 취소·종료·새 참가 불가 모임의 추가 요청은 각각 현재 정책의 거절 사유로 끝나며, 기존 저장 여부가 상태 검사를 우회하지 않는다.
  • AC-04 비공개·공유 토큰: PRIVATE는 상세 열람과 호스트·클럽 회원 조건을 함께 검사한다. 링크 전용 모임은 유효한 공유 토큰을 전달한 상세 판정과 토큰 없는 판정을 구분한다.
  • AC-05 반복 추가: 계속 추가 가능한 모임에 같은 회원이 다시 추가하면 저장 행을 새로 만들지 않는다. 종료 후 재요청 성공을 보장하는 기준으로 확대하지 않는다.
  • AC-06 반복 해제: 종료·취소 또는 현재 상세를 읽을 수 없는 모임도 본인의 찜을 해제할 수 있고, 이미 해제된 항목을 다시 지우는 요청도 정상 종료한다.
  • AC-07 목록 순서·노출: 찜한 시각과 저장 행 번호의 내림차순을 유지하고, 현재 상세 열람 불가 항목은 숨긴다. 종료되었다는 이유만으로 모든 기존 찜이 자동 삭제된 것으로 표시하지 않는다.
  • AC-08 새로고침·추가 읽기: 첫 조회·빈 목록·오류·기존 목록 갱신을 구분하고, 다음 페이지 실패에는 기존 항목을 남긴 채 다시 시도할 수 있다.
  • AC-09 해제 중 새로고침: 해제 응답을 기다리는 동안 이전 서버 목록을 다시 읽어도 아직 진행 중인 제거가 즉시 사라지지 않는다. 다른 항목의 성공·실패를 함께 되돌리지 않는다.
  • AC-10 같은 항목 연속 조작: 추가·해제를 연속 실행하면 앞 요청의 늦은 응답이 뒤 요청의 진행 중 표시를 덮지 않으며, 결과가 불확실하면 서버 상태를 다시 조회한다.
  • AC-11 통신 실패: 통신이 끊겼다는 이유로 성공 토스트나 서버 저장 1행을 기대하지 않는다. 요청 결과의 불확실성을 반영하고 재조회 후 현재 상태를 보여 준다.
  • AC-12 계정 전환: 이전 계정의 하트 변경과 늦은 응답이 새 계정의 목록·하트 상태에 적용되지 않도록 계정 범위를 구분한다.

검증 근거: WishlistServiceTest의 이미 찜한 OPEN 모임에 추가 저장하지 않는 단언과 공유 토큰에 따른 거절·저장 단언, wishlist_remove_edit_test의 해제 대기 중 새로고침 및 뒤 조작을 앞 응답이 덮지 않는 단언을 읽었다. 위 수용 기준 전체를 새로 실행한 결과나 실제 기기 통과 기록은 아니다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 관심 모임 추가·해제 결과가 목록과 상세에서 일치하고 재실행 후 유지된다.
  • 중복 클릭·삭제된 모임·공개 권한 회수·계정 전환에도 중복 저장이나 이전 계정 목록 노출이 없다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 이벤트의 관련 완료 기준도 함께 확인합니다.
