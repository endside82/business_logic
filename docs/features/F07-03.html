F07-03. 금액 검토·정산 요청·취소와 반환

검토 후 요청·실제 납부자 알림·바로 완료·정산 번호와 권한·취소와 반환 분리·외부/포인트/가상계좌·응답 불확실·복구와 초안 정리를 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

주최자는 초안의 금액 검토하기 → 정산 요청 보내기 → 확인을 거쳐 납부를 요청한다. 서버는 요청한 정산 번호의 초안·모임 종료 시각·참여 대상·항목과 분담을 확인한다. 요청 결과는 진행 중일 수도 있고, 남은 납부 의무가 없으면 바로 완료일 수도 있다. 정산 요청 자체는 돈을 결제하는 행동이 아니다.

취소는 정산 현황의 더보기 → 정산 취소에서 실행한다. 작성 중 또는 진행 중인 정산을 취소할 수 있지만, 정산 취소 성공과 돈의 반환 완료는 별개다. 포인트·장부에 적립된 가상계좌 금액은 반환을 시도하고, 사람 간 외부 계좌이체는 직접 반환할 금액을 표시한다. 실패한 반환은 정산을 진행 중으로 되돌리는 대신 별도로 기록하고 복구한다.

앱 진입과 금액 검토

  • 정산 현황의 초안 하단과 비용 목록에서 금액 검토하기로 이동한다. 현황 하단은 저장 합계가 0보다 커야 열리며, 비용 목록의 항목·첫 비용 복구 조건은 정산 항목·기존 배분 편집·영수증·최근 항목 재사용을 따른다.
  • 검토 화면 경로는 현재 모임 주최자에게 열린다. 서버에서 정산 상세·항목·요약을 읽고, 정산 번호·상태·항목 소속이 서로 맞지 않거나 조회가 실패하면 요청을 막는다. 기기의 이전 사본으로 검토를 통과시키지 않는다.
  • 지출과 수입을 나누어 표시한다. 각자의 ‘먼저 낸 돈’은 지출 항목을 결제자별로 합산한 값이다. 수입은 ‘미리 받은 수입’으로 분리하고, 부담금은 지출 선지급액에서 수입과 서버 순수취액을 뺀 값으로 계산한다. 분담금이 있다는 이유로 이미 결제한 돈으로 표시하지 않는다.
  • 모임 종료 전에도 비용을 검토할 수 있지만 요청은 막힌다. 모임 정보·초안·항목이 확인되고 첫 비용이 저장 중 또는 결과 불확실 상태가 아니어야 요청할 수 있다. 비용과 나눌 사람 수정하기는 이전 화면으로 돌아간다.
  • 확인창은 요청 후 비용·대상 수정 잠금과 납부 대상 알림을 설명한다. 더 검토하기는 명령을 보내지 않는다. 확정할 때 같은 초안인지 확인하고 모임 정보를 다시 읽어 종료 여부를 확인한 뒤, 검토한 정산 번호로 요청한다.
  • 성공하면 서버가 반환한 실제 상태를 반영하고 정산 현황으로 이동한다. 서버의 바로 완료 결과를 앱이 진행 중으로 덮지 않는다. 요청 중 재진입을 막고, 계정이 바뀐 뒤 도착한 결과를 새 계정에 적용하지 않는다.
  • 이미 초안이 아니거나 처리됐을 가능성이 있는 실패는 관련 현황을 다시 읽고 결과 확인을 안내한다. 요청 거절을 성공으로 표시하거나 자동으로 같은 요청을 다시 보내지 않는다.

요청 조건과 대상

조건현재 서버 판정
정산 번호와 모임경로의 settlementId가 eventId에 속해야 한다. 같은 모임의 나중에 생긴 다른 초안을 대신 활성화하지 않는다.
관리 권한정산 생성자를 기준으로 검사한다. 생성자가 없는 자료에만 현재 주최자 대체 판정이 있다. 앱의 현재 주최자 경로 조건과 항상 같지는 않다.
상태와 시각정산은 DRAFT여야 한다. 모임은 OPEN 또는 CLOSED, 종료 시각이 있고 서버 현재 시각이 종료 시각 이상이어야 한다. 취소된 모임이나 종료 시각 없는 모임은 시간만 지났다는 이유로 허용하지 않는다.
항목과 분담항목이 하나 이상이고 모든 항목에 분담 자료가 있어야 한다. 요청 후 항목을 자유롭게 수정할 수 없다.
요청 대상항목 보유자·분담자·수동 송금 양쪽 당사자를 모아 호스트 또는 실제 참석자인지 확인한다. 고정 정기모임 회차는 체크인 기준이다. 닫힌 계정도 요청 대상으로 허용하지 않는다.
선택 입력서버는 deadlineAt, autoRemindAfterHours를 선택 값으로 받으며 자동 알림 대기는 1~168시간이다. 현재 앱 요청은 선택 입력 없이 보낸다. 이 API에 마감일의 미래 시각 검증이 있다고 확대해서 설명하지 않는다.

요청은 PATCH /api/v1/events/{eventId}/settlement/{settlementId}/activate다. 현재 시작 API는 멱등 키를 받지 않는다. 이미 시작된 정산에 다시 요청하면 초안 상태 조건으로 거절되며, 최초 응답을 그대로 돌려주는 멱등 응답과 구분한다.

정산 방식과 알림

방식요청 직후 생성·갱신완료 판정
직접 송금 DIRECT현재 항목·분담으로 송금 줄을 계산한다. 항목 분담은 완료 표시되지만 실제 포인트 납부를 뜻하지 않는다.남은 송금 의무로 판단한다. 분담의 완료 표시를 이중 수납·환불 근거로 사용하지 않는다.
항목별 납부 HOST_COLLECT직접 송금 계산 줄을 만들지 않고 항목별 실제 지급 방향의 분담 의무를 사용한다. 별도 수동 송금도 함께 다룬다.보유자 본인 부담을 제외한 미완료 분담과 남은 송금 의무가 없어야 한다.

서버는 먼저 요청 시각과 진행 상태를 기록한 뒤 완료 조건을 검사한다. 송금 상태 중 COMPLETED, CANCELLED, SUPERSEDED, BANK_WAIVED는 남은 송금 의무로 보지 않는다. 다른 상태가 남아 있거나 항목별 납부에서 미완료 분담이 남으면 진행 중이다. 처음부터 남은 의무가 없으면 같은 요청에서 COMPLETED로 반환할 수 있다.

요청 알림은 모든 참석자에게 일괄 발송하지 않는다. 항목별 납부의 실제 납부자와 수동 송금의 보내는 사람, 직접 송금의 보내는 사람을 방식에 맞춰 모아 사용자별로 중복을 제거한다. 자기 자신에게 내는 분담은 요청 대상에서 제외한다. 알림은 영속 발송 대기 자료에 등록하며, 이 등록을 기기 푸시 수신 완료로 기록하지 않는다.

취소 상태와 명령 처리

  • 앱에서는 현재 주최자의 정산 현황 더보기 메뉴에 취소를 둔다. 초안·진행 중에서만 제공하고, 실행 중·상세 조회 중·이전 취소 결과 확인 대기에는 다시 취소하지 못하게 한다. 진행 중 하단의 주 행동으로 취소 버튼을 반복 배치하지 않는다.
  • 확인창은 취소 후 되돌릴 수 없음, 포인트 반환 시도, 외부 계좌이체의 별도 반환 가능성을 설명한다. 돌아가면 명령을 보내지 않는다.
  • 취소 API는 PATCH /api/v1/events/{eventId}/settlement/{settlementId}/cancel이며 Idempotency-Key가 필수다. 앱은 회원 금전 명령 처리기를 통해 취소 종류·정산 번호·키를 함께 보낸다. 서버는 모임 소속과 생성자 권한을 검사하고 명령 영수증에 대상 정산을 기록한다.
  • 서버는 부모 정산을 잠그고 DRAFT 또는 ACTIVE를 CANCELLED로 바꾼다. COMPLETED·이미 CANCELLED는 새로운 취소로 받지 않는다. 같은 키의 영수증 재처리는 새 취소 및 자식 반환 실행과 구분되며, 이번 요청에서 처음 취소한 경우에만 이어서 반환을 시도한다.
  • 진행 중 정산을 취소할 때는 대기 송금을 닫고 직접 반환 대상과 반환 복구 표지를 기록한다. 작성 중 정산의 사용자 취소는 같은 금전 정리 분기를 실행하지 않는다. 오래된 초안 자동 정리의 대기 송금 취소는 별도 경로다.
  • 정산 취소 기록과 개별 반환을 분리한다. 송금·분담 한 건의 반환 실패로 이미 기록된 부모 취소를 되돌리거나 다른 건의 반환 시도를 모두 중단하지 않는다. 마지막 조회는 반환 진행 이후의 실제 정산 상태를 읽는다.
  • 앱은 성공 후 정산 상세·요약·송금·분담 등 관련 조회와 지갑 자료를 갱신하고 반환 내역 확인을 안내한다. 일반 거절은 실패로 전달한다. 처리 여부가 불확실하면 현재 정산을 읽으며, 조회 실패·404를 취소 성공으로 간주하지 않는다. 다른 정산 번호로 바뀐 결과도 원래 취소 결과로 덮지 않는다.
  • 결과 확인이 필요한 상태에서는 정산 현황 다시 확인으로 재조회한다. 조회에 실패하면 확인 대기를 유지한다. 이전 계정의 늦은 응답은 현재 계정에 적용하지 않는다.

결제 방식별 반환

취소 시 자료현재 처리와 남는 의미
대기 중 송금취소 전이로 닫는다. 살아 있는 가상계좌가 있으면 폐기 요청을 발송 대기 자료에 넣는다. 은행 처리 완료까지 즉시 보장하지 않는다.
완료된 외부 계좌이체 송금PENDING_MANUAL_REFUND로 전환하고 실제 받은 사람에게 직접 반환이 필요함을 알린다. 지갑 포인트 환불을 만들지 않는다.
항목별 외부 계좌이체 분담완료·입금 확인된 분담에 refundOwedAt을 기록한다. 분담 자체를 송금 상태 enum으로 바꾸는 기능이 아니다.
보냈다는 신고만 있고 수취 확인 전미확인 송금 당사자에게 취소와 확인 필요를 알린다. 항목별 분담에는 반환 필요 표지를 남기되 납부 완료로 만들지 않는다. 실제 받았다면 받은 사람이 돌려주고, 보내지 않았다면 보냈다는 신고를 취소하도록 안내한다. 수입 분담은 지급 방향이 뒤바뀐다.
포인트 또는 혼합 송금원래 거래에서 아직 반환하지 않은 포인트만 되돌리고 받은 사람의 지갑에서 대응 금액을 차감한다. 실패하면 해당 반환 트랜잭션을 롤백한다. 이미 받은 외부 은행분이 남으면 직접 반환 대상으로 전환한다.
가상계좌 금액이 지갑 장부에 적립된 송금은행분 적립 거래 표지가 있는 경우 받은 사람 지갑에서 해당 금액을 차감하고 보낸 사람 지갑에 적립해 역분개한다. 외부 은행 계좌로 자동 송금했다는 뜻이 아니다.
완료된 포인트 분담직접 송금 방식의 정보성 분담을 제외하고 실제 원거래로 반환한다. 성공하면 분담의 납부 완료를 해제하고 포인트 반환 시각을 남긴다.

따라서 ‘포인트는 항상 즉시 전액 자동 환불’, ‘계좌이체는 모두 호스트가 환불’, ‘취소하면 모든 자식 자료가 같은 상태’라는 설명을 사용하지 않는다. 실제 지급·수취 당사자와 원거래·반환 기록으로 판단한다. 이후 납부와 입금 확인은 분담금 납부, 송금 확인에서 이어진다.

실패 복구와 오래된 초안 정리

개별 반환은 독립 트랜잭션으로 실행한다. 실패한 송금은 REVERSAL_FAILED와 실패 횟수·시각을 기록한다. 포인트 분담은 납부 완료 상태를 유지하며 별도의 실패 이유·횟수·시각을 남긴다. 실패 표시는 읽었던 자료의 버전이 그대로일 때만 적용해 이후 결과를 덮지 않는다.

취소의 반환 복구 표지는 아직 첫 시도를 하지 않은 자식이 있는지 판단하는 용도다. 실패 기록까지 끝난 자식은 별도 재시도 대상으로 넘어가므로 복구 표지 해제가 모든 반환 성공을 뜻하지 않는다. 10분 주기 작업은 5분 넘게 남아 있는 표지의 미시도 반환을 이어서 처리한다. 시간별 재시도는 취소된 정산의 실패 건을 골라 실패 횟수에 따른 대기 간격을 적용한다. 실패 횟수 3회에 도달한 자료는 자동 재시도 한도에 도달한 것으로 보고 운영 알림을 요청한다. 주기와 조건은 구현 정책이며 실제 작업 실행·알림 수신의 증거와 구분한다.

오래된 초안 정리는 마지막 수정 시각이 30일 기준보다 이전인 DRAFT를 잠금 후 다시 확인한다. 자료를 삭제하지 않고 CANCELLED로 바꾸며 대기 송금도 취소하고 감사 기록과 생성자 알림을 남긴다. 보존된 취소 자료를 다시 초안으로 복원하는 API가 있다는 의미로 설명하지 않는다. 새 정산 만들기는 정산 생성과 첫 비용 복구의 별도 흐름이다.

현재 제한과 확인 범위

분류확인 내용영향과 다음 확인
Gap앱 경로·메뉴는 현재 모임 주최자를 기준으로 열리고 서버 변경 권한은 정산 생성자 기준이다.주최자가 바뀌면 기존 생성자의 앱 접근과 새 주최자의 서버 실행 권한이 어긋날 수 있다. 역할 변경 후 접근 기준을 맞춰야 한다.
Risk금액 검토와 요청은 별도 조회·명령이며 요청에 항목 버전이나 검토 금액의 지문을 보내지 않는다.같은 초안의 항목이 다른 곳에서 바뀌면 서버는 요청 시점 자료로 처리한다. 검토한 금액과 요청 금액의 원자적 일치 보장으로 설명하지 않는다.
Risk부모 취소, 개별 반환, 외부 계좌 반환, 발송 대기 등록은 완료 조건이 서로 다르다.CANCELLED 응답이나 복구 표지 해제만으로 전체 돈 반환·은행 처리·푸시 수신을 완료 처리하지 않는다.
미검증현재 소스와 선택한 기존 시험 단언을 대조했다.실제 계정·기기·은행·스케줄러·새 제품 시험은 실행하지 않았다. 화면 명세와 소스 검수를 실제 앱 조작 결과로 바꾸지 않는다.

수용 기준과 검증 근거

  • AC-01 실제 입구와 조회: 초안에서 금액 검토로 들어가며 상세·항목·요약의 번호·상태·소속 불일치나 조회 실패는 요청을 막는다. 지출 선지급과 수입·분담을 구분한다.
  • AC-02 종료 조건: 비용 검토는 종료 전에도 가능하지만 요청은 서버의 모임 상태·종료 시각과 초안 조건을 충족해야 한다. 첫 비용 저장 중·결과 불확실 상태도 요청하지 않는다.
  • AC-03 번호와 권한: 검토한 정산 번호로 요청·취소하며 다른 모임 번호를 거절한다. 앱 주최자 조건과 서버 생성자 조건의 차이를 숨기지 않는다.
  • AC-04 항목과 대상: 항목·각 분담이 있고 보유자·분담자·수동 송금 당사자가 허용된 실제 참석자 또는 호스트이며 닫힌 계정이 아니어야 요청한다.
  • AC-05 방식과 최종 상태: 직접 송금과 항목별 납부의 의무를 구분한다. 직접 송금의 분담 완료 표시를 결제로 취급하지 않고, 남은 의무가 없으면 바로 완료 응답을 보존한다.
  • AC-06 알림과 선택 값: 방식별 실제 납부자를 사용자별로 중복 제거해 발송 대기 등록한다. 서버 선택 입력과 이를 보내지 않는 현재 앱을 구분하고 등록을 푸시 수신으로 쓰지 않는다.
  • AC-07 확인과 복귀: 수정하기는 이전 화면으로 돌아가고 더 검토하기는 요청 0회다. 확정 시 초안·모임 정보를 확인하고 성공 후 정산 현황으로 이동한다.
  • AC-08 요청 실패: 실행 중 두 번째 요청을 막고 계정 변경 뒤 응답을 버린다. 초안이 아닌 상태 거절·응답 불확실은 현황 확인으로 이어지며 성공·자동 재전송으로 처리하지 않는다.
  • AC-09 취소 명령: 더보기에서 초안·진행 중만 취소하고 정산 번호·키를 함께 보낸다. 새로운 완료·취소 상태 취소는 거절하며 같은 명령 영수증 재처리에서 반환을 다시 실행하지 않는다.
  • AC-10 외부 계좌 반환: 완료된 외부 송금은 직접 반환 대기, 항목별 외부 분담은 반환 필요 시각으로 표시하며 실제 받은 사람에게 알린다. 지갑 환불이나 모두 호스트 책임으로 바꾸지 않는다.
  • AC-11 미확인 송금: 보냈다는 신고만 있는 분담을 납부 완료로 만들지 않는다. 양쪽 당사자에게 실제 송금·수취에 맞게 반환 또는 신고 취소를 안내하며 수입의 반대 지급 방향을 유지한다.
  • AC-12 포인트·혼합·가상계좌: 포인트 원거래의 남은 반환분만 처리한다. 외부 은행분의 직접 반환과 지갑에 이미 적립된 가상계좌 은행분의 장부 반환을 구분한다.
  • AC-13 분담 반환: 항목별 실제 포인트 납부를 반환하되 직접 송금의 정보성 완료 분담은 제외한다. 성공 시 납부 완료 해제·반환 시각, 실패 시 기존 납부 상태·실패 기록을 유지한다.
  • AC-14 실패 복구: 부모 취소와 개별 반환을 분리하고 버전이 바뀐 결과를 실패 표시로 덮지 않는다. 미시도 복구와 실패 재시도를 구분하며 한도 도달 시 운영 알림을 요청한다.
  • AC-15 취소 결과 불확실: 조회 실패·404·다른 새 정산을 원래 취소 성공으로 단정하지 않는다. 중복 취소를 막고 현황 재확인을 제공하며 이전 계정의 응답을 적용하지 않는다.
  • AC-16 오래된 초안: 마지막 수정 후 30일 기준을 넘은 초안을 재확인하여 취소·대기 송금 정리·감사·생성자 알림을 처리한다. 보존과 복원 기능을 혼동하지 않는다.

근거는 현재 Controller·Service·앱 경로·Provider·화면과 settlement_review_screen_test.dart의 검토 닫기·바로 완료·서버 조회 실패·다른 정산 차단 단언, settlement_cancel_provider_test.dart의 응답 유실·404·새 정산·중복 명령 단언, MeetingSettlementCancelOrchestratorTest의 외부 계좌·혼합·가상계좌 반환 단언, MeetingSettlementSentUnconfirmedCancelTest의 지출·수입 미확인 분담 단언이다. 기존 시험 코드를 읽은 범위이며 새 실행·은행 처리·기기 통과 횟수로 합산하지 않는다.
