F17-08. 환불 (비례 산식 · 세 가지 발생 사유)

고정형 환불은 이미 진행/제공된 회차만큼만 빼고 나머지를 돌려준다(비례 환불). 세 가지 발생 경우 — 멤버 본인 취소·호스트 모임 취소·노쇼 자격박탈 — 가 모두 같은 골격을 쓰되 "차감 기준"이 조금씩 다르다. 100원 단위로 절삭하며 계산 결과는 0원 아래로 내려가지 않는다. 지갑 결제는 자동 환불, 계좌이체는 호스트가 직접 송금하고 "환불 완료"를 눌러야 마감된다.

설계 의도 — "내가 못 받은 만큼만 돌려받는다"

코스 단위로 결제했더라도 환불은 회차 단위 공정성이 필요하다. 시작된 회차는 회사가 이미 자원을 썼다고 보고 환불 대상에서 빼고, 미래 미제공 회차만 비례로 돌려준다. 호스트가 모임을 닫는 경우만 예외 — 호스트가 미제공한 회차는 100% 돌려준다(노쇼한 멤버 책임 아님).

2026-08-30 현재 화면 재확인 — 완료된 환불도 다시 볼 수 있다

참가자는 정기모임 상세에서 자신의 결제와 완료된 환불 이체증을 다시 볼 수 있다. 호스트 운영 화면에는 진행 중 환불 대기열과 별도로 완료 이력이 있으며, 최근 완료 순서로 최대 200건을 보여 준다. 양쪽 모두 화면에 보인 이체증만 전용 열람 주소로 열 수 있고, 다른 모임·다른 사람의 결제 번호나 목록에 없는 파일 번호는 거절된다. 이 권한·범위·파일 상태 거절은 실제 데이터베이스 테스트까지 통과했다. 남은 외부 검증은 운영 파일 저장소에서 발급된 주소로 실제 파일 바이트를 내려받는 왕복이다.

사용자 시나리오

멤버 본인 취소

"3회차까지 듣고 사정이 생겼다"

8회 코스 80,000원 결제, 3회차 시작 후 취소. 산식: 5/8 × 80,000 = 50,000원 환불. 지갑이면 즉시 자동 환불, 계좌이체면 호스트 송금 대기.

사용자가 알 수 있는 것 — 취소 시점에 따라 달라지는 환불액을 확인한 뒤 취소 여부를 결정할 수 있다.

호스트 모임 취소

"호스트가 5회차 진행 후 모임 접음"

8회 중 5회 제공, 3회 남음. 산식: 3/8 × 80,000 = 30,000원 환불. 활성 멤버 전원의 환불을 자동으로 시작한다.

사용자 보호 — 호스트의 사정으로 제공하지 못한 회차는 전액 환불한다.

자격박탈

"노쇼 3회 연속으로 박탈됨"

4회까지 시작된 시점에 박탈. 산식: 4/8 × 80,000 = 40,000원 환불. 멤버 상태 자격박탈 + 자동 환불.

사용자 보호 — 참가자에게 귀책 사유가 있어도 제공하지 않은 미래 회차분은 돌려줘 호스트의 부당한 이득을 막는다.

시작 전 취소

"코스 시작 전에 취소"

0회 시작, 8회 남음. 산식: 8/8 × 80,000 = 80,000원 전액 환불.

사용자가 알 수 있는 것 — 코스 시작 전에는 금전 손실 없이 취소할 수 있다.

코스 끝나가는 시점

"8회 중 8회 다 시작 후 취소"

모든 회차가 시작됐다면 환불 0원. 코스 가치를 다 받았다는 판단.

정책 효과 — 이미 모든 회차를 제공한 뒤 환불을 요구하는 악용을 막는다.

계좌이체 환불 절차

"호스트가 사용자에게 직접 송금"

계좌이체 결제는 외부 송금이라 환불도 외부. 멤버 상태는 "환불 진행중"으로 들어가고, 호스트가 사용자 계좌로 송금한 뒤 "환불 완료" 버튼을 누르면 마감.

사용자가 알 수 있는 것 — 앱 밖에서 송금하는 환불도 시스템이 진행 상태를 기록해 참가자가 확인할 수 있다.

환불 실패

"지갑 환불이 일시적으로 실패"

네트워크·일시 오류 등으로 환불에 실패하면 자동 재처리 목록에 들어간다. 호스트 취소처럼 여러 환불이 한꺼번에 시작될 때 일부가 실패해도 모임 취소 자체는 완료된다.

운영 효과 — 일부 환불의 일시 오류 때문에 모임 운영 전체가 멈추지 않는다.

화면에서 사용자가 인지하는 것

영역사용자가 보는 것그 자리에 둔 이유
취소 전 확인 창"지금 취소하면 X원 환불됩니다" 안내(취소 전).사용자가 환불액을 결정 전에 알고 의사결정하게 한다.
환불 진행 상태계좌이체 환불 진행 중일 때 멤버 상태에 노란색으로 표시.호스트 송금 대기 상태를 사용자가 명확히 인지하게.
환불 완료 안내지갑 환불은 즉시 거래 이력에 표기, 계좌이체는 호스트 마감 후 라벨 변경.두 결제 방식의 환불 흐름 차이를 사용자에게 명확히.
호스트 환불 알림호스트가 모임을 취소할 때 "전 멤버에게 환불됩니다" 확인 창.호스트가 취소의 환불 책임 규모를 직시하게 해 즉흥 취소를 줄인다.
박탈 후 환불 안내자격박탈 알림에 "잔여 회차분 X원이 환불됩니다" 같이 노출.박탈이 일방적 처벌이 아니라 금전적 정산이 함께임을 알리는 균형.

운영자가 알아야 할 것

금액 산정 규칙
  • 100원 단위 절삭 — 원 단위 금액은 자동으로 100원 미만이 깎인다(일반 결제와 동일).
  • 최저 0원 — 차감이 결제 금액을 넘어가도 환불액은 0원 아래로 내려가지 않는다.
  • 회차 시작 시각 기준 — 멤버 취소·박탈 산식에서 "시작된 회차"는 시작 시각이 지난 회차(노쇼 포함).
  • 호스트 미제공 회차는 무조건 환불 — 호스트가 닫은 회차는 멤버 귀책과 무관하게 100% 환불.
  • 자동 재처리 목록으로 환불 실패 추적 — 모든 실패는 별도 목록으로 들어가 운영팀이 확인한다.
  • 완료 뒤에도 환불 근거를 확인할 수 있다. — 참가자는 자기 결제 한 건을, 호스트는 최근 완료 이력 최대 200건을 다시 열어 환불 금액·메모·이체증을 확인한다. 화면에서 이체증을 누르면 결제 당사자 또는 해당 모임 호스트인지 서버가 다시 검사한다.

남아 있는 정책·운영 한계

추가 보완이 필요한 상황
  • 계좌이체 환불 마감 누락 — 호스트가 송금한 뒤 마감하지 않으면 참가자 화면에는 계속 "환불 진행 중"으로 보인다. 환불 단계 알림 기능은 연결돼 있지만(2026-08-18 확인), 송금 후 마감 버튼을 누르는 책임은 호스트에게 남아 있다.
  • 지갑 환불로 음수 잔액 발생 — 사용자가 환불액보다 적은 잔액을 가진 경우 마이너스 잔액이 일시 발생할 수 있음(다음 적립 시 우선 차감).
  • "24시간 전 100% 환불" 같은 시간 비례 정책 미적용 — 1차 출시는 회차 단위 차감만. 시간 비례 환불은 후속.
  • 공결·세션 취소의 환불 정책 — 1차는 멤버 취소 산식과 동일 처리. 약관 검토 후 별도 정책 가능.
