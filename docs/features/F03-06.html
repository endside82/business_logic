F03-06. 신청서 승인·거절 (호스트)

호스트의 심사 권한·무료 배치·유료 결제 대기·사유 기록과 단건·일괄 실패 후 재시도를 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

호스트와 활성 공동호스트가 심사 중인 신청을 승인하거나 거절한다. 무료 승인은 참석 또는 대기 배치로, 선입금 승인은 결제 대기로 이어진다. 비공개 모임의 선정은 일반 승인으로 처리하지 않는다. 일괄 처리는 신청별 요청을 순서대로 실행하며 일부 성공을 전체 성공으로 표시하지 않는다.

참가자의 작성·재신청·본인 취소는 이벤트 신청과 참석, 결제와 반환은 참가비 결제와 신청 취소를 따른다.

입구·권한·목록 표시

모임 상세의 관리 목록에서 권한이 있을 때 신청서 관리를 연다. 해당 경로도 신청 관리 접근을 검사한다. 화면에서 관리 권한이 없다고 판정되면 차단 안내와 돌아가기를 제공한다. 서버의 조회·승인·거절 권한은 호스트 또는 활성 공동호스트이며 클럽 운영진이라는 이유만으로 확대하지 않는다. 다른 모임의 신청 번호는 해당 모임의 유효한 신청으로 다루지 않는다.

목록은 전체·심사중·결제 대기·승인·거절의 다섯 탭과 상태별 건수를 보여 준다. 취소·결제 기한 만료·환불 대기는 별도 탭 없이 전체 목록에서 상태를 구분한다. 신청자 사진·이름의 사람 미리보기와 선택·승인·거절 조작을 구분한다. 결제 대기 카드에는 값이 있을 때 결제액과 기한, 기한 만료 카드에는 만료 안내를 표시한다.

전체 목록이 비어 있으면 모집 공유 입구를, 특정 탭만 비어 있으면 그 상태의 신청이 없다는 안내를 제공한다. 조회 중에는 로딩, 초기 실패에는 재시도, 재조회 중에는 이전 목록을 유지한다. 당겨 새로고침은 신청 목록을 갱신한다. 호스트 계좌이체 대상이면 입금 확인 목록으로 가는 별도 입구도 보여 준다.

승인 조건과 결과

서버는 모임을 잠근 뒤 상세 접근, 호스트·활성 공동호스트, 일반 승인 대상, 신규 참가자를 받을 수 있는 모임, 결정 대기 여부를 검사한다. 이어 해당 모임의 PENDING 신청인지, 이미 직접 참석 중인지, 정원·선입금 설정·결제수단 준비 조건이 맞는지 확인한다. 모임이 종료·취소·숨김 상태이면 신규 참가자를 받을 수 없으므로 승인하지 않는다.

유료 잔여석은 허용 한도에서 실제 참석 수와 결제 대기 일행 수를 뺀 값이다. 유료 승인은 참석 행과 실제 참석 수를 먼저 늘리지 않는다. 무료 참석 생성과 결제 뒤 참석 확정에서는 참가 제재를 다시 검사한다. 승인 결과 알림 저장과 신청자의 기기 수신도 구분한다.

승인은 선택 안내 메시지를 저장하고 처리자·시각·신청 차수별 결정 이력을 남긴다. 앱은 모임과 신청 행의 서버 승인 허용 값을 모두 만족할 때 승인 행동을 제공한다. 허용 값이 없으면 임의로 승인 가능으로 간주하지 않는다. 성공 응답이 결제 대기라면 “승인 완료 — 신청자 결제 대기”로 안내한다.

거절 사유와 기록

거절은 해당 모임의 PENDING 신청만 대상으로 하며 사유 코드가 필수다. 선택 상세 메시지는 최대 500자이고 앞뒤 공백을 다듬어 빈 값은 저장하지 않는다. 신청을 REJECTED로 바꾸고 처리자·시각·사유 코드·메시지·차수별 이력과 알림 저장을 연결한다. 이미 처리된 신청을 다시 거절하면 상태 오류다.

서버는 정원·자격·제재·호스트 판단·중복 프로필·결제 시간 초과·기타 코드를 정의하지만 현재 앱 시트는 코드 선택 UI를 제공하지 않는다. 단건·일괄 거절 모두 기본 호스트 판단 코드와 사용자가 작성한 선택 메시지를 보낸다. 메시지를 비워도 사유 코드가 있어 요청할 수 있다. “거절 사유 글 필수”나 “모든 사유 코드를 앱에서 선택 가능”으로 설명하지 않는다.

승인과 달리 거절 서비스에는 모임 신규 참가 가능 여부·비공개 선정 여부를 다시 막는 동일 가드가 없다. 관리 권한과 PENDING 상태를 만족하는 미처리 신청 정리라는 범위를 구분한다.

단건·일괄 처리와 실패 후 복귀

단건 승인은 안내 시트, 거절은 사유 시트를 연다. 시트는 요청을 기다리는 동안 중복 제출을 막고, 성공이면 닫혀 원래 목록으로 돌아온다. 실패이면 작성한 입력과 목록을 유지한다. 서버 승인 거절 응답에는 관련 모임·신청 자료를 새로 읽는 처리가 연결된다.

여러 건 선택은 PENDING 신청이 있을 때 제공한다. 선택한 건 중 일괄 승인은 현재 서버 허용 값이 참인 신청만 추려 요청하고, 일괄 거절은 선택한 신청에 각각 요청한다. 하나의 메시지를 쓰고 한 건씩 순차 처리하며 성공 수·실패 수를 보여 준다. 성공한 번호는 재시도 대상에서 빼고 실패한 번호만 같은 시트에 남긴다. 모두 성공해야 시트를 닫으며, 일부라도 처리한 뒤 시트를 닫으면 선택 모드를 해제한다. 하나도 성공하지 않았다면 선택 상태를 유지한다.

승인 성공은 신청 목록, 주최·예정·과거·참석 모임 목록, 해당 상세와 카드를 갱신한다. 반영됐을 가능성이 있는 승인 오류도 갱신한다. 거절 성공은 신청 목록만 갱신하며, 결과 복원 불가 응답도 목록을 다시 읽는다. 보통의 거절 오류에서 다른 모임 목록까지 자동 갱신한다고 쓰지 않는다.

요청 재생과 동시 처리의 범위

앱은 같은 신청 번호라도 승인·거절을 구분하고, 메시지·사유·현재 수정 번호를 기준으로 요청 번호를 보관한다. 성공이나 확정된 거절이면 그 번호를 정리한다. 현재 목록에서 더 이상 PENDING이 아닌 신청의 결정 번호도 정리한다. 번호 보관은 로그인 세션의 메모리이며 앱 재시작 이후 영속 재생을 보장하지 않는다.

서버는 요청 번호가 있으면 결과로 저장된 신청 번호를 이용해 현재 권한과 소유 모임에 맞는 결과를 재조회한다. 요청 번호가 없는 기존 호출도 허용하므로 모든 외부 호출이 같은 재생 보호를 받는다고 단정하지 않는다. 모임·신청 잠금과 PENDING 재검사로 중복 심사를 제한하는 코드가 있으나 이번 대조가 실DB 동시 호스트 실행의 통과 증거는 아니다.

수용 기준과 검증 근거

  • AC-01 관리 권한: 호스트·활성 공동호스트만 신청을 조회·심사한다. 경로 진입과 서버 명령 모두 권한을 검사한다.
  • AC-02 다섯 탭: 전체·심사중·결제 대기·승인·거절의 건수와 목록을 구분하고 만료·취소는 전체 목록에 표시한다.
  • AC-03 승인 허용: 모임 및 신청 행의 허용 값이 없거나 거절이면 승인 요청 입구를 임의로 열지 않는다.
  • AC-04 무료 승인: 정원·초과 허용·대기 한도에 따라 본인과 게스트를 배치한다. 대기 허용을 무조건 승인 불가로 설명하지 않는다.
  • AC-05 유료 승인: 선입금 대상은 결제액·기한이 있는 결제 대기로 만들고 실제 참석 수를 즉시 늘리지 않는다.
  • AC-06 잘못된 승인 대상: 다른 모임의 신청·비PENDING·직접 참석 중·비공개 선정·모집 불가·결정 대기·선입금 설정 누락은 각각의 조건으로 거절한다.
  • AC-07 거절 사유: 사유 코드가 없으면 거절 명령을 받지 않는다. 현재 앱은 호스트 판단 코드와 선택 메시지를 전송한다.
  • AC-08 실패 입력 유지: 단건 처리 실패 시 시트의 안내·사유와 아래 목록을 유지한다. 성공 응답 뒤 시트를 닫는다.
  • AC-09 부분 성공: 일괄 처리에서 성공·실패 건수를 나누고 재시도는 실패한 번호만 다시 보낸다.
  • AC-10 선택 상태: 모두 실패하면 선택 모드를 유지하고 일부라도 처리한 뒤 시트를 닫으면 선택을 해제한다.
  • AC-11 조회 실패와 빈 상태: 초기 실패에는 재시도, 재조회에는 이전 목록, 전체 빈 목록에는 모집 공유 입구를 제공한다.
  • AC-12 결과 갱신: 승인 뒤 관련 모임 목록과 상세·카드를 갱신하고, 거절 뒤 신청 목록을 갱신한다. 두 처리의 범위를 동일하다고 가정하지 않는다.
  • AC-13 결정 기록: 신청 차수별 처리자·시각·메시지·거절 코드를 저장하고 같은 요청의 결과 재생과 새 심사를 구분한다.

기존 application_decision_sheet_wait_test.dart는 단건 실패 입력 유지·성공 뒤 닫힘·일괄 실패 건만 재전송을 단언한다. application_decision_failure_keeps_list_test.dart는 실패해도 목록·선택을 유지하는 모의 시험이다. ApplicationServiceTest의 선입금 없는 유료 승인 거절과 사유 코드 없는 거절 단언도 읽었다. 이번 작업에서 이 제품 시험을 새로 실행하지 않았다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 판정 조건에 2026년 11월 22일 신청·심사·결제 대기의 구분을 반영했습니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 첫 출시 포함 여부와 구현·검사 현황은 위 상태표를 따릅니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 호스트의 승인·거절이 신청 상태와 결정 이력·알림 저장에 반영된다. 무료 승인의 참석·대기 배치와 유료 승인의 결제 대기를 구분한다.
  • 다른 호스트·이미 처리한 신청·정원 초과·동시 취소 상황에서 잘못 승인하지 않는다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 이벤트의 관련 완료 기준도 함께 확인합니다.
