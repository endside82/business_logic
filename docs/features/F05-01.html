F05-01. 키워드 검색

실제 검색 입구·유형별 공개 조건·건수·정렬·더 읽기와 복귀를 구분한다. 2026-11-22 소스 대조이며 실제 앱 실행과 구분합니다.

결론

검색은 공통 상단 검색 입구에서 여는 독립 화면이다. 하단 두 번째 탭이 검색이라는 과거 설명은 현재 탐색 구조와 다르다. 같은 검색어로 이벤트·클럽·플랜·사람을 나눠 찾되, 플랜 탭은 마켓 공개 범위에 따르고 사람은 로그인한 회원의 관계 범위 안에서만 찾는다.

검색 결과가 있다는 사실은 상세·참가·구매 권한을 보장하지 않는다. 결과 선택 뒤 각 상세 화면에서 현재 공개 상태와 권한을 다시 적용한다.

실제 입구와 검색 흐름

  1. 상단 검색을 열면 검색 전 안내, 최근 검색어, 인기 모임 제목을 이용한 검색어 태그, 저장된 검색 입구를 볼 수 있다. 검색어가 전달된 진입은 그 값으로 검색한다.
  2. 공백만 있는 입력은 실행하지 않는다. 직접 검색, 최근 검색어, 추천 선택은 같은 검색 실행으로 이어지고 포커스와 추천 목록을 정리한다.
  3. 이벤트·클럽·플랜 조회를 시작하고, 로그인 상태일 때 사람 조회도 시작한다. 플랜 탭을 숨기는 조건과 플랜 요청을 보내는 조건은 현재 같지 않다.
  4. 선택한 결과 탭을 표시한다. 이벤트의 필터·정렬 변경은 이벤트 조회에만 적용한다.
  5. 각 탭은 20개씩 다음 페이지를 가져온다. 클럽·플랜·사람도 더 읽기를 지원하므로 이벤트만 무한 스크롤이라는 설명을 사용하지 않는다.
  6. 이벤트·클럽·플랜은 해당 상세로, 사람은 공통 사람 상세 창으로 이동한다. 돌아왔을 때의 목록 유지와 데이터 변경에 따른 재조회는 구분한다.

결과 종류와 공개 조건

결과현재 검색 대상·순서화면의 건수
이벤트클럽 소속이 없는 독립 이벤트·정기모임 중 공개 또는 승인제 공개, 열린 상태, 숨김 제외. 로그인한 회원의 차단 호스트를 제외. 제목·설명에서 검색서버의 전체 결과 수
클럽활동 중인 클럽의 이름·설명. 생성 시각 내림차순, 같은 시각이면 번호 내림차순현재 읽은 목록 수
플랜발행된 플랜의 제목. 화면은 마켓 공개 범위에 따라 표시현재 읽은 목록 수
사람본인·차단 대상·검색 숨김·활동 불가 계정을 제외. 같은 클럽 또는 함께 참석한 근거가 있는 사람의 닉네임. 닉네임·번호 오름차순현재 읽은 목록 수

사람 검색의 함께 참석한 근거는 같은 이벤트의 체크인 기록을 우선한다. 체크인이 전혀 없는 이벤트는 두 사람의 참석 상태와 유효 노쇼 제외를 적용한다. 단순 신청·관심인 등록·데이팅 매칭을 사람 검색의 공개 관계로 바꾸지 않는다. 검색 숨김과 상세 프로필의 낯선 사람 숨김은 서로 다른 판정이다. 표시용 함께 만난 횟수는 만남 전용 집계를 사용한다. 실제 양쪽 체크인이 있으면 그 근거를 사용하고, 체크인이 전혀 없는 모임의 참석·노쇼 대체 근거는 CLOSED 상태이면서 시작 시각이 현재 이하인 모임만 센다. 상세 접근이나 사람 검색의 후보 관계에 쓰는 기존 공동 참석 권한 판정을 이 표시용 집계로 바꾸었다고 해석하지 않는다.

다가올 모임에 함께 참석할 관계로 검색 후보가 되더라도 표시용 coAttendedCount는 0일 수 있다. 같은 클럽 표시도 없다면 함께한 모임 횟수 라벨 없이 보여 준다. 같은 두 사람의 표시 횟수는 만난 사람·프로필·추천과 같다.

정렬·재조회·실패·복귀

이벤트 화면의 기본 정렬은 추천순이다. 현재 추천순은 시작 시각 오름차순·참여 인원 내림차순·생성 시각 내림차순·번호 내림차순이며 개인화 추천 점수순은 아니다. 최신순은 생성 시각이 아니라 시작 시각 내림차순이다. 인기순은 현재 참여 인원, 가격순은 가격을 기준으로 한다. 일반 검색에 일괄 미래 시작 조건이 있는 것은 아니다.

같은 검색어의 재조회 중에는 기존 결과를 유지하고 검색어가 바뀌면 이전 목록을 비운다. 클럽·플랜·사람의 더 읽기 실패는 기존 목록을 유지하고 재시도를 제공한다. 사람 더 읽기에서 접근 거절·찾을 수 없음 응답은 목록을 비우고 오류로 전환한다. 인증 401은 이 접근 거절 분류와 별개의 세션 처리다. 단순 네트워크 재시도와 공개 권한 회수를 같은 동작으로 설명하지 않는다. 사람 차단에 성공하면 현재 결과에서 그 사람을 먼저 빼고 현재 검색어의 첫 쪽부터 다시 조회한다. 재조회 중에는 예전 쪽 번호로 더 읽지 않으며, 차단 해제는 새 조회 결과에 반영한다.

검색바의 입력 지우기·취소는 이미 실행한 검색 상태를 초기화하거나 이전 화면으로 돌아가는 행동과 다르다. 취소 뒤 포커스가 사라지면 이전 실행 검색어가 다시 입력칸에 맞춰질 수 있다. 계정 변경은 각 계정 범위의 검색 상태를 다시 만든다.

최근 검색어와 저장된 검색

최근 검색어는 계정별 기기에 최대 20개를 저장한다. 검색 결과 조회와 기록 저장은 독립적이며 서버 Redis 검색 이력을 쓰지 않는다. 저장된 검색은 서버의 본인 목록으로 조건을 보관하는 별도 기능이다. 자세한 실패·삭제 범위는 최근 검색어, 저장된 검색을 따른다.

수용 기준과 검증 범위

  • AC-01 입구: 공통 검색 입구와 검색어가 전달된 진입을 구분하고 하단 검색 탭을 전제하지 않는다.
  • AC-02 입력: 공백 검색은 실행하지 않고 직접 입력·최근 검색어·추천 선택이 제출한 검색어로 조회한다.
  • AC-03 이벤트 공개: 공개 분류·열린 상태·숨김·로그인 차단 호스트 제외가 목록과 전체 건수에 적용된다.
  • AC-04 다른 유형: 클럽은 활동 상태, 플랜은 발행 상태, 사람은 로그인·관계·숨김·차단을 적용한다.
  • AC-05 건수: 이벤트 전체 건수와 나머지 탭의 현재 읽은 건수를 구분한다.
  • AC-06 정렬: 추천·최신·인기·가격순의 실제 기준과 동률 순서가 일치한다.
  • AC-07 재조회: 같은 검색어를 다시 찾는 동안 앞 결과를 유지하고 다른 검색어는 앞 목록을 비운다.
  • AC-08 더 읽기: 각 탭의 다음 페이지·중복 요청 방지·실패 재시도와 사람 권한 회수 시 목록 제거를 확인한다.
  • AC-09 결과 이동: 유형별 상세로 이동하고 공개·참가 권한을 재판정하며 검색 화면으로 돌아온다.
  • AC-10 상태 분리: 계정 변경·검색 취소·최근 검색 기록 저장·플랜 탭 공개를 각각 구분한다.

기존 search_typed_tabs_keep_results_test.dart는 같은 검색어 재조회와 다른 검색어의 목록 처리를 다룬다. search_screen_first_search_test.dart, search_clubs_refresh_after_close_test.dart, 페이지 추가 조회 시험이 있다. 파일 존재·시험 목적 대조를 새 실행 통과로 기록하지 않는다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다. 아래 과거 판정 조건의 날짜를 이번 실행일로 바꾸지 않는다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 입력한 검색어로 접근 가능한 모임·클럽·플랜 등을 찾고 정확한 상세로 이동한다.
  • 공백·짧은 검색어·권한 회수·빈 결과·후속 비공개 영역에서 제한을 유지한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 검색의 관련 완료 기준도 함께 확인합니다.
