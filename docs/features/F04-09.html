F04-09. 게시글 댓글

실제 정렬·50개 부모 페이지·차단/삭제 가림·입력 보존·멘션·운영진 사유 삭제·알림 대상 찾기의 결과를 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

실제 입구와 댓글 표시

게시글 상세 아래에 댓글 수·최신순/등록순 전환·댓글 목록·입력란이 있다. 댓글 행을 길게 누르면 본인에게 수정, 서버 actions.delete.allowed가 허용한 행에 삭제, 타인에게 신고가 열린다. 게시글 상단 더보기와 댓글의 행동 메뉴는 대상이 다르다. 삭제된 부모 행에는 행동 메뉴와 새 답글 입구가 없다.

본문 아래 답글은 처음 3개를 표시하고 나머지는 더보기로 펼친다. 답글의 답글 버튼도 최상위 부모 ID를 사용해 같은 깊이의 답글을 만든다. 작성자나 확정 멘션을 누르면 PersonSheet를 연다. 신고는 COMMUNITY_COMMENT, 댓글 ID, 게시글 ID와 클럽 ID를 신고 화면에 전달한다.

댓글 없음과 목록 조회 오류를 구분하며 오류에는 다시 불러오기를 제공한다. 추가 페이지 오류에서는 기존 목록을 유지하고 아래쪽 재시도 버튼을 제공한다.

서버 요청과 응답

기본 경로는 /api/v1/clubs/{clubId}다. 인증을 요구하며 서비스가 실제 회원 관계와 게시글·댓글의 클럽 소속을 검사한다.

동작메서드와 하위 경로요청응답
기존 전체 목록GET /posts/{postId}/comments없음List<ClubPostCommentVo>
현재 앱의 페이지 조회GET /posts/{postId}/comments/pagepage, size, oldestFirst, afterCommentIdClubPostCommentPageVo
댓글 작성POST /posts/{postId}/commentsClubCommentAddParam201 댓글 VO
답글 작성POST /posts/{postId}/comments/{commentId}/repliesClubCommentAddParam201 댓글 VO
수정PUT /comments/{commentId}ClubCommentModParam200 댓글 VO
삭제DELETE /comments/{commentId}선택적 EventMessageDeleteParam; 타인 삭제는 필수204

작성·수정 요청은 content: String, 선택적 mentionedUserIds: List<Long>이다. 본문은 공백만으로 작성할 수 없다. 댓글 VO는 id, nullable parentCommentId, authorId, authorNickname, content, status, 생성·수정 시각, replies, mentions, actions.delete를 제공한다. 멘션은 userId와 저장된 nickname이다. 앱은 nullable 본문·닉네임과 삭제 자리 표시의 authorId=0을 수용한다.

페이지 응답은 content, totalElements, totalPages, number, size, first, last다. content는 부모 댓글과 그 아래 활성 답글의 트리다. 기존 전체 목록 API가 남아 있으나 현재 앱의 페이지 응답과 혼용하지 않는다.

정렬·이어 읽기·차단 가림

페이지 기본 크기와 앱 요청 크기는 50이다. 부모는 최신순이면 createdAt DESC, id DESC, 등록순이면 createdAt ASC, id ASC다. 자식 답글은 생성 시각·ID 오름차순이다. 앱은 첫 장을 page=0, 이후에는 마지막으로 받은 부모 ID를 afterCommentId로 보낸다. 서버는 같은 게시글의 최상위 댓글인지 확인하고 생성 시각·ID 뒤를 읽는다. 잘못된 커서의 INVALID_INPUT 응답을 받으면 앱은 첫 장부터 다시 읽는다. 정렬 전환도 첫 장부터 재조회한다.

부모가 ACTIVE이거나, DELETED이면서 활성 답글이 남아 있으면 조회 대상이다. 삭제된 부모는 원문·멘션 대신 “삭제된 댓글입니다” 자리 표시와 남은 답글을 반환하며 앱도 답글을 유지한다. 마지막 활성 답글까지 삭제되면 삭제 부모는 목록에서 빠진다.

차단 상대의 댓글·답글은 가린다. 차단된 부모 아래 보이는 답글이 남으면 부모의 본문·닉네임·멘션을 비우고 작성자 ID를 0으로 마스킹한다. 보이는 답글도 없으면 부모를 제거한다. 페이지의 총계는 차단 가림 전의 부모 수로, 화면에 보이는 모든 댓글·답글 수가 아니다. 이어 읽기 질의는 차단으로 사라질 부모를 제외하지만 첫 페이지는 조회 뒤 가림을 적용하므로 50개보다 적게 반환될 수 있다.

작성·답글·수정과 입력 보존

작성과 답글은 현재 회원과 ACTIVE 게시글을 요구한다. 서버는 게시글을 잠그고 댓글을 저장하며 게시글 댓글 수를 증가시킨다. 답글 부모는 같은 게시글의 활성 최상위 댓글이어야 한다. 이미 답글인 댓글을 부모로 지정하면 COMMENT_DEPTH_EXCEEDED, 삭제 부모에는 새 답글을 만들 수 없다.

수정은 현재 회원인 원작성자만 가능하고 게시글·댓글이 활성 상태여야 한다. 수정 요청은 최종 본문과 전체 멘션 ID 목록을 보낸다. 운영진에게 타인 댓글 수정 권한을 주지 않는다.

앱은 전송 중 중복 탭을 막고, 성공 응답과 현재 입력이 일치할 때만 보낸 입력을 지운다. 그 사이 새로 쓴 내용이나 바꾼 답글 대상을 지우지 않는다. 다른 답글 대상으로 전환할 때 입력이 있으면 폐기를 확인한다. 답글 취소 버튼은 대상을 해제하며 본문은 남긴다. 답글을 시작할 때 부모 작성자 멘션을 자동 삽입하지 않는다.

수정 창은 기존 본문·멘션을 채우고 전송 중 저장 버튼을 잠근다. 성공 때 해당 창을 닫고, 실패하면 입력을 유지해 다시 시도할 수 있다. 프로필 탐색의 작성 중 여부를 등록하지만 댓글 입력의 기기 저장·앱 재시작 복구 기능은 이 흐름에서 제공하지 않는다.

작성·답글·삭제 성공 또는 서버 반영 가능성이 있는 통신 실패는 게시글 변경 신호와 댓글·게시판 목록 갱신을 일으킨다. 수정 성공은 현재까지 읽은 페이지들을 다시 읽는다. 수정 성공 뒤 재조회 실패는 저장 실패와 구분해 안내한다.

멘션 후보·확정·수정

앱은 @ 입력 후 250ms 대기해 회원 목록 첫 10명을 검색하고 본인·닉네임 없는 후보를 제외한다. 후보 조회 실패는 빈 후보 목록으로 처리한다. 선택한 닉네임을 공백과 함께 삽입하고, 전송 때 본문에 남아 있는 선택 대상 ID만 보낸다. 임의로 쓴 @문자열만으로 알림 대상이 만들어지지 않는다.

서버는 ID 중복을 제거하고 본인을 제외한다. null ID, 남은 후보 10명 초과, 검사 경로에서 유효한 @ 시작점 20개 초과는 INVALID_INPUT이다. 요청 ID가 없으면 멘션 해석을 건너뛰므로 모든 일반 본문의 @ 개수에 무조건 이 제한을 적용하는 것은 아니다.

신규 대상은 현재 회원이어야 하며 실제 본문과 닉네임이 맞아야 한다. 토큰은 문자열 시작 또는 공백 계열 뒤에서 시작하고 최장 닉네임을 우선한다. 동일 닉네임으로 소유자가 모호하면 확정하지 않는다. 수정은 기존 멘션의 닉네임 스냅샷과 현재 닉네임을 함께 고려하며 기존 스냅샷 소유를 우선한다. 기존 관계에는 신규 대상과 동일한 현재 회원 필터를 일괄 적용하지 않는다. 다만 알림 수신자는 현재 회원으로 다시 거른다.

수정 시 관계를 추가·유지·삭제하고 새로 추가한 멘션만 알린다. 유지 관계의 표시 별칭은 해석 결과에 따라 갱신될 수 있다. 삭제하면 멘션 관계도 삭제된다. 앱은 서버가 확정한 mentions만 링크로 표시한다.

본인 삭제와 운영진 조치

삭제 가능 여부는 댓글이 활성 게시글의 목록에 보이는지와 현재 회원·유효 운영진 권한으로 판정한다. 탈퇴한 작성자나 숨겨진 게시글의 댓글을 무조건 지울 수 있다는 과거 설명은 적용하지 않는다. 본인 삭제에는 조치 사유가 필요 없고, 타인 삭제는 서버의 운영진 판정과 사유 본문을 모두 통과해야 한다.

사유 코드는 HARASSMENT, SPAM, OFF_TOPIC, INAPPROPRIATE, AUTHOR_REQUEST, OTHER다. reasonText는 선택 입력이며 500자 이하다. 앱 조치 창도 사유 선택과 길이를 확인하고 전송 중 중복 제출을 막는다. 자기 댓글 삭제는 행 메뉴에서 바로 요청하고, 타인 댓글 삭제는 이 사유 창을 거친다.

삭제는 상태를 DELETED로 바꾸고 멘션 관계를 제거하며 게시글 댓글 수를 감소시킨다. 타인 삭제는 분쟁 원천 COMMENT, 대상 작성자·조치자, COMMENT_DELETE 기록과 사유를 남기고 조치 안내를 요청한다. 서비스에는 운영자 복구 경로가 있으나 회원용 복구 API나 화면은 아니다. 복구는 예상 삭제 시점이 맞을 때만 수행하며 이미 활성·다시 숨김을 구분한다. 복구 코드가 삭제 때 지워진 멘션 관계를 재생성하지 않는 점도 구분한다.

알림과 대상 댓글 찾기

신규 댓글·답글의 수신자는 멘션 → 부모 댓글 작성자 → 게시글 작성자 순서로 중복을 제거하고 행위자를 제외한다. 게시글 작성자 알림은 최상위 댓글뿐 아니라 답글에도 해당한다. 수신 시점의 현재 회원으로 걸러 각각 CLUB_POST_COMMENT_MENTION, CLUB_POST_COMMENT_REPLY, CLUB_POST_COMMENT 알림을 요청한다. 알림 저장·채널 전달의 공통 정책은 별도 계층이며 이 기능 문서가 실제 푸시 도착을 보증하지 않는다.

멘션 알림 중복 키는 멘션 관계 ID, 일반 댓글·답글 알림 키는 알림 종류와 댓글 ID를 사용한다. 발췌는 공백을 평탄화한 뒤 50자를 넘으면 생략 부호를 붙인다. 전달 데이터는 clubId, boardId, postId, commentId, actorUserId다.

앱 알림 경로는 /clubs/{clubId}/posts/{postId}?boardId={boardId}&commentId={commentId}이며 가능한 경우 알림 ID 기반 landing도 붙인다. 게시글·게시판 ID가 없으면 클럽 홈으로, 클럽 ID도 없으면 경로 없음으로 처리한다. 알림 착지의 새 요청은 이전 목록을 그대로 신뢰하지 않고 다시 읽는다.

알림 또는 방금 작성한 댓글 찾기는 현재 목록에서 시작해 최대 20개 추가 페이지를 읽는다. 찾으면 접힌 답글을 펼치고 해당 행으로 스크롤해 약 3초 강조한다. 끝까지 없으면 읽었던 페이지들을 한 번 재조회한 뒤 찾을 수 없음을 알린다. 자동 탐색 한도 도달은 삭제로 단정하지 않고 직접 내려 확인하라고 안내한다. 통신 중단에는 댓글 다시 찾기를 제공한다. 정렬·새 요청·화면 생명주기 변경으로 오래된 탐색 결과가 덮어쓰지 않도록 구분한다.

현재 제한과 확인 범위

분류현재 경계문서·검수 판정
Risk댓글 생성에 별도 멱등 키 계약이 없고 불명확 실패 시 입력이 남는다.앱의 전송 잠금은 한 요청 동안의 중복 탭만 막는다. 결과 확인 없이 수동 재전송하면 중복 가능성이 있다.
Risk페이지 총계는 차단 가림 전 부모 수이며 앱의 게시글 댓글 수와 집계 단위가 다르다.총계·보이는 행·답글을 같은 수로 단정하지 않는다.
범위부모 페이지에 포함되는 활성 답글은 별도 페이지로 나누지 않는다.부모 50개 제한이 답글 포함 50개 제한은 아니다.
범위자동 찾기는 추가 20페이지 한도가 있고 입력의 기기 영속 저장은 없다.모든 깊은 댓글 자동 도착이나 재시작 후 초안 복구를 보장하지 않는다.
미검증이번 작업은 소스와 기존 시험 단언의 문서 대조다.실제 앱 조작, 새 테스트 실행, 알림 기기 수신, 동시성 부하 결과로 표현하지 않는다.

수용 기준과 검증 근거

  • AC-01 실제 입구: 게시글 상세에서 댓글을 읽고, 행 길게 누르기의 수정·삭제·신고가 대상과 권한에 맞게 분리되는지 확인한다.
  • AC-02 페이지 계약: 기존 List API와 현재 앱 Page API를 구분하고 기본 50개·응답 메타데이터·부모 트리 구조를 확인한다.
  • AC-03 실제 정렬: 최신순·등록순이 서버 질의에 전달되고 다음 장에서도 유지되며 정렬 변경 시 첫 장부터 읽는지 확인한다.
  • AC-04 이어 읽기 실패: 마지막 부모 ID 커서로 이어 읽고 일반 실패는 기존 목록과 재시도를, 잘못된 커서는 첫 장 재조회를 제공하는지 확인한다.
  • AC-05 회원과 소속: 읽기·작성·수정·삭제의 현재 회원·활성 게시글·클럽 소속 검사를 우회하지 않는지 확인한다.
  • AC-06 답글 깊이: 활성 최상위 부모만 허용하며 앱의 답글 행에서 답글을 눌러도 같은 부모 아래 1단계 답글을 만드는지 확인한다.
  • AC-07 삭제와 차단 표시: 삭제 부모의 활성 답글을 유지하고 차단 상대의 본문을 가리며 총계와 노출 행 수의 차이를 설명하는지 확인한다.
  • AC-08 작성 입력 보존: 전송 잠금·성공한 입력만 비우기·답글 대상 전환 확인·실패 시 입력 유지를 확인한다.
  • AC-09 수정 결과: 본인만 수정하며 창은 성공 때 닫고 실패 때 유지하고 읽은 페이지 재조회 오류를 저장 결과와 구분하는지 확인한다.
  • AC-10 멘션 확정: 선택 ID와 본문·신규 회원·최장 일치·중복 닉네임·10명/20시작점 조건을 함께 판정하는지 확인한다.
