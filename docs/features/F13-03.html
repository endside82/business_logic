F13-03. 다중 주소 관리

10개 상한·주소 좌표·기본 지정·이름표 잔존·실패 안내 차이를 구분한다. 2026-11-22 소스 대조를 반영했으며 실제 앱 실행과 구분합니다.

결론

마이의 프로필 카드 메뉴에서 주소를 관리한다. 주소는 최대 10개이며 집·회사는 각각 하나, 기타는 여러 개 둘 수 있다. 기본 주소를 새로 지정하면 이전 기본 지정을 해제하지만, 기본 주소가 반드시 하나 존재하는 규칙은 아니다. 최초 추가나 편집에서 기본 지정을 끈 채 저장할 수 있다.

주소 선택 뒤 좌표 확인은 앱이 서버의 주소 변환 기능을 호출하고 서버가 외부 지도 제공자에 조회하는 흐름이다. 예전 ‘서버에는 주소 변환이 없다’는 설명을 현재 계약으로 사용하지 않는다.

실제 진입과 복귀

  1. 하단 마이 → 사진·닉네임 카드 → 주소 관리에서 목록을 연다. 빈 목록은 주소 추가 안내, 조회 실패는 오류와 다시 시도를 제공한다.
  2. 상단 + 또는 빈 목록의 주소 추가에서 폼을 연다. 10개이면 상단 추가를 숨긴다. 각 카드의 수정은 같은 폼을 편집 모드로 연다.
  3. 편집 값은 현재 주소 목록에서 찾고 목록이 아직 로딩 중이면 도착한 값을 받아 채운다. 서버 단건 조회 기능이 있지만 현재 폼이 이를 별도로 호출하지는 않는다.
  4. 주소 유형·이름표·검색 주소·상세 주소·기본 여부를 편집한다. 주소 검색을 취소하면 기존 값을 유지하고, 새 주소 선택 뒤에는 새 좌표를 확인하기 전까지 저장하지 않는다.
  5. 저장 성공은 목록 재조회와 성공 안내 뒤 복귀한다. 실패는 폼을 유지하고 저장 실패를 안내한다. 변경 중 이탈은 계속 쓰기 / 버리고 나가기, 저장 중 이탈은 공통 보호 규칙을 따른다.

주소 선택과 입력 규칙

  • 집·회사·기타를 선택한다. 기타의 이름표는 선택 입력이며 비어 있으면 목록에서 주소를 이름 대신 쓴다. 알 수 없는 옛 유형은 다시 선택하기 전 저장을 막는다.
  • 주소 검색 결과를 고르면 서버를 통해 지도 좌표를 확인한다. 외부 조회 실패·좌표 없음에서는 안내하고 저장을 막는다. 주소 문자열만 보인다고 저장 가능한 것은 아니다.
  • 주소 문자열과 위도·경도가 필요하다. 서버는 유한한 값, 위도 ±90·경도 ±180 범위와 영점 쌍 거절을 검사한다. 수정 때 좌표를 보내려면 두 값을 함께 보낸다.
  • 이름표 50자·주소 500자·상세 주소 200자가 서버 상한이다. 앱은 이름표 50·상세 주소 200을 제한하고 주소는 검색 결과로 받는다. 우편번호는 저장 계약에 없다.
  • 상단과 하단 저장은 같은 처리다. 저장할 필수 값·좌표·유형 재선택 조건을 확인하며, 폼의 기본 여부는 처음에는 꺼져 있다.

저장·기본 지정·소유권

조건현재 결과
목록 조회본인 주소를 기본 주소 우선·그다음 등록 순으로 받음. 빈 목록은 정상 결과
새 주소회원 잠금 뒤 10개 상한·집/회사 중복을 확인함. 기타는 여러 개 허용
수정본인 주소만 변경. 생략한 값은 유지하고 상세 주소의 빈 문자열은 비울 수 있음
기본 지정해당 주소를 기본으로 만들며 앞의 기본 지정을 해제함. 거짓으로 수정하면 기본 없음도 가능
기본 주소 삭제앱은 다른 주소를 기본으로 먼저 지정하라고 안내함. 서버 삭제 자체는 기본 여부를 차단하지 않음
일반 주소 삭제확인 창 취소는 요청하지 않음. 승인 뒤 성공하면 목록을 다시 읽음
없는 주소·남의 주소없는 주소는 찾을 수 없음, 다른 회원 소유는 권한 없음으로 거절함
탈퇴 진행·완료추가·수정은 현재 회원 상태를 잠금 뒤 검사해 거절함. 일반 인증·제한 정책도 별도로 적용됨

기타 주소를 집·회사로 바꿀 때 앱은 이름표 변경값을 생략하고 서버는 기존 이름표를 유지한다. 목록은 이름표를 유형 이름보다 먼저 표시하므로 예전 이름이 남을 수 있다. 이것을 집·회사 이름으로 자동 치환되는 동작으로 설명하지 않는다.

실패·직접 진입·복귀

목록 조회 실패에는 다시 시도가 있지만, 기본 주소 변경·삭제의 실패는 공급자가 실패 여부만 돌려주고 화면은 성공 안내만 처리한다. 기존 카드가 남은 것을 실패 이유 안내나 최신 상태 재확인으로 계산하지 않는다. 주소 추가·수정 실패는 일반 저장 실패 안내로 표시되어 중복 유형·상한·권한 등의 상세 원인이 폼에 구분되어 나오지 않는다.

수정 주소가 현재 목록에서 없어지거나 직접 들어온 주소 식별자가 맞지 않으면 폼을 채우지 못한다. 현재 폼에는 이 경우 전용 ‘주소 없음’ 안내가 없다. 주소 목록의 로딩·실패·직접 진입과 이미 삭제된 주소의 저장을 각각 확인해야 한다. 응답 유실 뒤 새로 추가를 반복하면 기타 주소는 여러 건 생길 수 있으며, 집·회사는 중복 판정으로 막힐 수 있다.

현재 제한과 확인 범위

판정항목영향·다음 확인
Gap기본 변경·삭제 실패 안내실패 시 이유 안내와 재조회가 없어 기존 카드만 남을 수 있음
Gap기본 주소 삭제 규칙 차이앱은 막지만 서버는 허용하며 기본 없음도 가능. 항상 기본 하나라는 설명은 맞지 않음
Gap기타에서 집·회사로 변경한 이름표생략한 이름표가 유지되어 이전 이름으로 표시될 수 있음
Gap편집 대상 없음·명세 입력없는 수정 대상의 전용 안내가 없고 화면 명세의 우편번호·요청 본문은 현재 좌표 계약과 다름
미검증외부 주소 검색·기기서버·앱·직렬화 시험 본문 대조이며 새 주소 검색·외부 지도·기기 복귀 실행 검증은 아님

수용 기준과 검증 범위

  • AC-01 진입: 프로필 메뉴에서 목록·추가·수정을 열고 저장 또는 이탈 결과에 맞게 복귀한다.
  • AC-02 조회: 빈 목록·로딩·오류·다시 시도와 기본 우선 정렬을 구분한다.
  • AC-03 상한·유형: 10개 상한, 집·회사 중복, 기타 복수 등록과 알 수 없는 유형 재선택을 확인한다.
  • AC-04 검색: 선택 취소·주소 선택·좌표 확인 중·외부 실패·성공 뒤 저장 가능 여부를 구분한다.
  • AC-05 값 검증: 글 길이·좌표 쌍·유한값·범위·영점 쌍과 우편번호 미사용을 확인한다.
  • AC-06 기본: 새 기본 지정·기본 해제·첫 주소를 일반으로 저장한 경우를 구분한다.
  • AC-07 삭제: 기본 주소의 앱 차단과 서버 허용 차이, 일반 삭제 확인·취소·성공·실패를 구분한다.
  • AC-08 부분 수정: 상세 주소 비우기, 이름표 생략·빈 값, 기타에서 집·회사 변경을 확인한다.
  • AC-09 소유권·상태: 다른 회원·없는 주소·탈퇴 계정의 조회·변경 허용 범위를 확인한다.
  • AC-10 직접 진입: 목록 미수신·오류·삭제된 주소로 편집에 들어갔을 때의 폼 상태를 확인한다.
  • AC-11 복구: 저장 실패·응답 유실 재시도·변경 중 이탈 후 실제 주소 목록을 다시 확인한다.
