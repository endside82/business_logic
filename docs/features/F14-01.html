F14-01. 이벤트 참석자 위치 공유

참석 확정한 모임에서 일행끼리 지도 위에서 서로 어디쯤 오고 있는지를 보는 화면. 사용자가 직접 opt-in하고 좌표 전송까지 성공해야 본인 위치가 다른 사람 화면에 보인다. 신규 opt-in 뒤에는 내 GPS를 60초마다 다시 보내고 다른 사람 목록을 30초마다 읽지만, 기존 활성 share 재진입에는 목록 타이머가 빠지는 Gap이 있다. 위치 공유는 이 도메인에서 가장 민감한 동작이므로, 사용자 동의 · 모임 시간대 · 호스트의 이벤트 단위 허용 세 가지가 모두 맞아떨어진 경우에만 다른 참석자에게 좌표가 노출된다. "지금 어디쯤?"이라는 질문을 채팅으로 다시 묻지 않게 하는 것이 본 단위의 목표다.

위치는 본 서비스에서 가장 민감한 정보다. 그래서 본 단위의 모든 동작은 "본인이 직접 켜지 않으면 좌표는 한 번도 노출되지 않는다"를 보장한다. 동의를 받았다 해도 모임이 아닌 시간에 보이지 않도록 시간대 게이트가 있고, 호스트가 모임 단위로 위치 공유 자체를 꺼두면 사용자 토글이 켜 있어도 좌표가 더 이상 흘러가지 않는다. 이 세 겹 중 한 겹이라도 풀리는 회귀가 발생하면 "내가 켜지도 않았는데 위치가 보였다"라는, 본 서비스에서 가장 치명적인 신뢰 사고가 즉시 발생한다.

2026-07-29 current source — 최초 opt-in 진입 교착

이벤트 단위 공유가 켜진 경우 일반 참석자의 최초 GET은 본인 opt-in을 요구하지만, opt-in 토글은 GET 성공 뒤 그리는 화면 안에 있다. 따라서 아직 동의하지 않은 참석자는 LOCATION_OPT_IN_REQUIRED 에러 화면에 막힌다. 이벤트 단위 공유가 꺼진 경우에는 빈 data와 토글이 보이지만, 토글 뒤 좌표 update가 LOCATION_SHARE_DISABLED로 실패한다.

이 단위가 한 번에 처리하는 세 가지

사용자에게는 토글 하나처럼 보이지만, 본 단위는 동의·갱신·조회 세 가지를 함께 책임진다.

동의

위치 공유 켜기

운영체제 위치 권한 확인·요청은 토글 시점이 아니라 화면 initState()에서 즉시 실행된다. 렌더된 토글은 권한을 다시 확인하지 않고 opt-in을 먼저 저장한 뒤 첫 좌표 전송을 시도한다. 전송 실패를 확인하지 않은 채 로컬 On·타이머·성공 토스트가 진행될 수 있다.

유지

30초 목록 조회 · 60초 GPS 전송

신규 opt-in 또는 앱 resume 경로에서는 30초 목록 GET과 60초 GPS POST가 함께 시작된다. GPS 갱신이 2번 연속 실패하면 자동 전송을 멈추고 한 번만 안내한다. 기존 활성 share로 화면에 재진입하면 GPS 타이머만 복원되고 목록 타이머는 시작되지 않는 현재 Gap이 있다.

조회

일행 위치 보기

지도 위에 모임 장소(빨강), 본인(파랑), 다른 참석자(초록) 마커가 함께 표시되고, 일반 ATTENDING viewer의 하단 시트에는 참석자 #id와 마지막 갱신 시각만 보인다. 닉네임·프로필·모임 장소까지의 거리·예상 시간 API는 호스트·공동호스트·클럽 운영자 전용이다. 본인이 opt-in하지 않으면 일반 viewer는 다른 사람 좌표도 볼 수 없다.

관리자급 조회

호스트·공동호스트·클럽 운영진은 조회 게이트를 우회

호스트, 공동호스트, 클럽에서 이벤트 생성 권한을 가진 운영진은 본인 opt-in과 참석자 시간창 없이 공유 목록을 볼 수 있다. 다만 응답 대상의 현재 자격·opt-in·만료·차단 관계 필터는 그대로 유지된다.

위치가 다른 사람에게 보이기까지의 세 겹 통과

사용자가 켰다는 것만으로는 부족하다. 시간대, 호스트 허용, 그리고 본인 동의 — 셋 다 통과해야 좌표가 응답에 들어간다.

위치 공유의 상태 흐름

자동 GPS 갱신은 좌표만 최신화하고 활성 공유의 종료 시각은 밀지 않는다. 만료 변경은 명시적 연장이나 만료 모드를 동반한 요청으로만 일어난다.

사용자 시나리오

기본 흐름

모임 30분 전, 처음 위치 화면에 들어온다

이벤트 단위 공유가 켜져 있고 아직 opt-in하지 않은 일반 참석자는 초기 목록 GET에서 거부되어 에러 화면만 본다. 토글이 성공 content 안에 있어 이 화면에서는 공유를 처음 켤 수 없다. OS 권한 요청은 화면 진입과 동시에 별도로 발생할 수 있지만 서버 opt-in 교착을 풀지는 못한다.

이벤트 단위 공유가 꺼져 있으면 GET이 먼저 빈 목록을 반환해 토글은 보이지만, On 뒤 좌표 update가 LOCATION_SHARE_DISABLED로 실패해 opt-in만 true가 될 수 있다.

현재 Gap — GET을 빈 상태로 허용하거나 opt-in CTA를 에러 화면 밖에 배치하기 전에는 최초 공유 happy path가 닫혀 있지 않다.

자동 갱신

신규 opt-in 뒤 이동하는 중에 마커가 따라온다

이 화면에서 토글 On에 성공한 뒤 유지하면 본인 GPS는 60초마다 새 좌표를 보내고, 일행 목록은 30초마다 다시 읽힌다. 사용자가 "지금 한 번 더" 갱신하고 싶으면 우하단 버튼을 눌러 다음 60초를 기다리지 않고 좌표를 보낸다.

이 흐름이 남기는 것 — 사용자가 "내 위치가 진짜로 보내지고 있는가"를 직접 확인할 수 있는 통제 장치.

활성 공유 재진입

내 GPS만 갱신되고 일행 목록은 멈출 수 있다

이미 활성 share가 있는 사용자가 화면을 새로 열면 본인 row로 토글 On과 60초 GPS 타이머는 복원된다. 그러나 이 분기는 30초 목록 타이머를 시작하지 않아, 앱 resume이나 새 opt-in 전까지 다른 참석자의 위치가 자동 갱신되지 않을 수 있다.

현재 Gap — 활성 상태 복원 시 두 타이머를 함께 시작해야 한다.

호스트 우회

호스트는 위치를 켜지 않아도 일행을 본다

모임 호스트가 같은 화면을 열면 본인 토글이 꺼져 있어도 일행의 마커가 즉시 보인다 — 모임을 안내할 책임이 있기 때문에 조회만 따로 허용된다. 다만 본인 위치를 보내려면 호스트도 똑같이 토글을 켜고 시간대 안에 들어와 있어야 한다.

이 흐름이 남기는 것 — 책임 비대칭을 정책에 그대로 반영. 호스트가 일행을 못 보면 "도착했냐"를 채팅으로 다시 물어야 한다.

시간대 분기

모임 30시간 전에 미리 들어와 봤을 때

호기심에 너무 일찍 위치 화면을 연 일반 참석자는 좌표가 한 점도 보이지 않는다. "공유 가능 시간이 아닙니다" 안내만 노출되고, 모임 시작 24시간 전 시점이 되면 그제서야 일행이 보이기 시작한다.

이 흐름이 남기는 것 — 모임과 무관한 시간대에 위치가 노출되지 않게 한다. 사용자가 의식하지 못한 시점의 위치 노출을 막는 안전장치.

권한 분기

운영체제 위치 권한을 영구 거부한 사용자

위치 권한 검사는 토글이 아니라 화면 진입 즉시 실행된다. 영구 거부 상태면 안내 토스트와 운영체제 설정 이동이 시도된다. 토글 자체는 권한을 재검사하지 않으므로, data 화면에 도달한 경우 opt-in만 저장되고 첫 좌표 전송은 실패할 수 있다.

이 흐름이 남기는 것 — 앱 안에서는 풀 수 없는 영구 거부를 사용자가 어디로 가서 해결해야 하는지 한 번에 안내한다.

호스트 차단

호스트가 모임 단위로 위치 공유를 꺼두었다

호스트가 모임 설정에서 "이 모임은 위치 공유 안 함"을 선택한 경우, 일반 참석자가 토글을 켜도 좌표 갱신 자체가 막힌다. 사용자 입장에서는 토글이 켜져 있는데 본인 마커가 다음 갱신에서 사라진다 — 현재 구현은 별도 안내 토스트가 없어 사용자가 "왜 안 보이지?"라고 의아해할 수 있는 분기.

운영 관찰 포인트 — 호스트의 모임 단위 비활성화가 발동되었을 때 일반 참석자에게 명시적 안내가 가도록 보강하는 것이 향후 과제. 현 상태는 "조용한 차단"에 가깝다.

중도 비공개

같이 가던 일행이 도중에 위치를 꺼버렸을 때

모임 중 한 사람이 토글을 끄면 서버는 좌표 row를 즉시 삭제한다. 다른 사람 화면에서는 다음으로 성공한 목록 GET 때 그 사람 마커와 리스트 row가 사라진다. 30초는 정상 폴링 cadence이며 최대 반영 시간 보장은 아니다.

이 흐름이 남기는 것 — 서버 삭제와 클라이언트 화면 반영 시점을 구분해서 관찰해야 한다.

화면에서 사용자가 보는 것

위치 화면을 열었을 때 보이는 정보와, 그 정보가 그 자리에 있는 이유.

화면 요소사용자가 보는 것그 자리에 둔 이유
풀스크린 지도 모임 장소(빨강 마커), 본인(파랑), 다른 참석자(초록). 지도 상단에 마커 색의 의미를 알려주는 작은 캡슐 범례. 색만으로 "나/장소/일행"을 즉시 구분할 수 있어야 시선이 흩어지지 않는다. 범례는 처음 본 사용자가 색의 의미를 한 번에 이해하도록 둔다.
하단 시트 토글 행 + 본인 공유 카운트다운 + 참석자 카운트 + 일행 리스트. 일반 참석자는 사용자 ID·마지막 갱신만, 관리자급은 닉네임·프로필·거리·예상 시간도 표시. 지도와 함께 한 화면에 정보가 있어야 사용자가 시선을 바꾸지 않는다. 시트는 위·아래로 끌어 비율 조절이 가능해 지도 비중과 리스트 비중을 사용자가 정한다.
위치 공유 토글 시트 맨 위 큰 스위치. 꺼진 상태에서는 라벨이 회색, 켜진 상태에서는 색이 들어간다. 사용자가 자신의 공유 상태를 항상 시각적으로 인지하게 만든다 — 위치 공유의 4가지 원칙 중 "공유 상태 시각화"의 실현.
내 위치 갱신 버튼 화면 우하단의 작은 동그란 버튼(현재 위치 아이콘). 60초 GPS 주기를 기다리지 않고 즉시 갱신할 수 있는 사용자 통제 장치. "내가 직접 보냈다"는 통제감을 목록 폴링과 분리해 둔다.
상단 톱니바퀴 오른쪽 위 아이콘 — 누르면 위치 프라이버시 대시보드(F14-04)로 이동. "내 위치가 어디에 보이고 있는가"를 사용자가 언제든 한 번에 확인하러 갈 수 있는 출구. 위치 공유의 4가지 원칙 중 "공유 상태 시각화"가 이 진입로로 완성된다.
일행 카드 한 줄 일반 참석자는 `"참석자 #id"` + "방금 전 / N분 전". 호스트·공동호스트·클럽 이벤트 생성 운영자는 닉네임·프로필·거리·예상 시간도 표시. 거리 endpoint가 관리자급 전용이므로 일반 참석자에게는 위치 좌표 외 신원·도착 추정 정보를 확장하지 않는다.

운영자가 알아야 할 것

본 화면이 정상이라고 부르려면 다음이 보장되어야 한다
  • 본인이 위치 공유를 켜지 않으면 다른 참석자의 좌표도 보이지 않는다. "남 위치는 보면서 내 건 안 보낸다"는 비대칭이 만들어지면 위치 공유의 신뢰 구조가 무너진다. 일방적 관찰 차단이 본 단위의 첫 번째 안전선.
  • 호스트가 모임 단위로 위치 공유를 끄면 일반 참석자에게 안내가 가야 한다. 현재는 토글이 켜져 있어도 좌표가 안 가는 "조용한 차단"에 가깝다 — 사용자가 "내가 진짜 보내고 있는가"를 모른다. 향후 명시적 토스트 안내 보강 필요.
  • 좌표 노출은 매번 접근 이력으로 기록된다. 누가 누구의 위치를 봤는지의 이력이 30일간 남아, 프라이버시 대시보드(F14-04)에서 사용자가 확인할 수 있는 원천이 된다. 이 기록이 빠지면 "내 위치를 누가 봤는가"를 추적할 수 없다.
  • 이벤트 종료+2시간은 일반 참석자의 GET/update 접근창 종료다. 관리자급 GET은 이 시간 게이트를 우회하고 opt-in도 자동 false가 되지 않는다. 좌표 노출은 각 share 만료와 cleanup을 함께 봐야 한다.
  • 운영체제 위치 권한 영구 거부는 앱 안에서 해결 불가능하다. "다시 묻기" CTA를 만들지 않고 운영체제 설정 화면으로 보내는 동작을 유지해야 한다. 앱 안에서 거부를 풀 수 있다고 사용자가 오해하면 권한 다이얼로그를 무한 반복으로 보게 된다.
  • 30초 목록 조회와 60초 GPS 전송은 화면을 벗어나면 모두 멈춰야 한다. 화면을 나갔는데 갱신 루프가 계속 돌면 배터리·데이터가 새고, 사용자가 모르는 사이에 위치가 계속 서버로 흘러간다. 화면 dispose 와 앱 백그라운드 진입 시 둘 다 중지가 보장되어야 한다.
  • 기존 활성 share 재진입에는 목록 타이머 복원이 빠져 있다. GPS는 계속 보내면서 타인의 위치는 stale할 수 있으므로 lifecycle 회귀 테스트가 필요하다.

측정해야 하는 것

위치 공유가 사용자에게 가치를 주고 있는지를 보여주는 지표
  • 모임 시작 24시간 전 진입 → 토글 켜기까지의 비율 — 화면에 들어왔지만 켜지 않는 비율이 높다면 사용자가 가치를 못 느끼거나 안내가 부족한 신호.
  • 토글 켠 채로 모임 종료까지 유지된 비율 — 중간에 꺼버리는 사용자가 많다면 갱신 주기·배터리 부담·노출 범위 어딘가에 문제가 있다는 신호.
  • 운영체제 권한 영구 거부 비율 — 너무 높다면 앱 외부에서 해결해야 하는 사용자가 너무 많다는 뜻 — 첫 권한 요청 시점의 설명이 부족한지 점검.
  • 호스트 차단(모임 단위 비활성화) 발동 후 사용자 행동 — 명시적 안내가 부족한 현 상태에서 사용자가 어떻게 반응하는지를 추적하면 보강 우선순위가 결정된다.
