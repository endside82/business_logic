F14-04. 위치 프라이버시 대시보드

현재 이벤트에서 내 위치 공유 상태와 최근 30일 접근 기록을 확인하고, 그 자리에서 즉시 끄거나 켤 수 있는 통제 자리. 위치 공유의 4가지 원칙 중 "공유 상태 시각화"가 형태로 드러나는 화면이며, 호스트와 일반 참석자가 같은 화면을 보지만 누르는 토글의 의미가 다르다.

설계 의도 — "꺼져 있다"가 시각적으로 보장되어야 사용자가 켤 수 있다

위치 공유는 사용자가 "내가 켰는지 안 켰는지" 확신하지 못하면 가벼운 마음으로 켜지 않게 된다. 본 화면은 사용자가 흩어진 화면을 돌아다닐 필요 없이 "지금 내 위치가 어디에 어떻게 보이고 있는가"를 한곳에서 확인할 수 있는 자리. 한편 호스트에게는 "이 모임 자체에서 위치 공유를 허용할 것인가"라는 모임 단위의 결정이 같은 자리에 함께 있어, 모임 운영자가 위치 공유 정책을 모임 별로 다르게 설정할 수 있다.

2026-07-29 현재 소스 갱신 — 이벤트별 access-log와 서버 상태 소비

화면은 path의 eventId로 최근 30일 접근 기록을 필터링하고, 응답의 `userOptedIn`·`locationShareEnabled`를 토글 상태의 기준으로 쓴다. 접근 기록이 없으면 전용 빈 상태를 보이며, 30일을 넘긴 로그는 서버가 매일 03:30 삭제한다. 호스트 토글은 DRAFT-only 범용 이벤트 PATCH를 재사용하므로 OPEN/진행 이벤트에서는 INVALID_EVENT_STATUS로 실패한다.

호스트와 참석자에게 다른 의미

같은 화면을 봐도 토글이 작동하는 대상이 다르다. 사용자 본인 위치를 끄는가, 모임 전체의 위치 공유를 끄는가.

참석자

내가 이 모임에 위치를 공유할지

일반 참석자가 토글을 켜면 본인의 opt-in 동의 상태만 true가 된다. 이 화면은 GPS 취득·좌표 update·타이머를 시작하지 않으므로 share row가 없다면 위치 화면에서 좌표를 다시 보내기 전까지 일행에게 보이지 않는다. 끄면 서버가 opt-in을 false로 바꾸고 현재 share row를 삭제한다.

호스트

이 모임에 위치 공유 자체를 허용할지

DRAFT 이벤트에서는 호스트가 모임 단위 허용값을 바꿀 수 있다. 그러나 OPEN/진행 이벤트에서 같은 토글을 누르면 범용 이벤트 수정의 상태 가드에 막혀 값이 바뀌지 않는다. 현재 화면은 운영 중 제어 자리처럼 보이지만 실제 계약과 일치하지 않는다.

화면이 보여주는 정보 — 무엇이 있고 무엇이 빠져 있는가

현재 본 화면은 단일 이벤트의 공유 상태와 실제 접근 이력을 함께 보여준다. 빠진 것은 여러 이벤트를 한 화면에서 일괄 관리하는 허브다.

정보현 상태의미
이벤트 카드 한 장 현재 들어온 이벤트 한 개만 카드로 표시. 스펙은 "내가 공유할 수 있는 모든 모임의 리스트"를 의도했으나 현 구현은 한 이벤트 컨텍스트 안에서만 동작.
토글과 상태 라벨 "위치 공유 중" / "위치 비공개" 라벨이 색으로 구분. 처리 중에는 인디케이터가 같은 자리에서 돈다. "내 상태"가 시각적으로 명확해야 사용자가 통제감을 느낀다.
위치 공유 안내 박스 옅은 파랑 배경 박스. 위치 업데이트 시작 -2시간~종료 +2시간, 참석자 조회 시작 -24시간, ATTENDING 한정, 중단 효과, 접근 기록 30일을 안내. 사용자가 "내 위치가 언제까지, 누구에게, 얼마나 오래" 보이는지 한 곳에서 다시 확인할 수 있게 한다.
접근 이력 해당 이벤트의 raw 접근 로그 행 수와 접근자 `"사용자 #id"`·시각을 중복 포함해 표시. 기록이 없으면 전용 빈 상태를 노출. 위치 목록 GET마다 대상별로 기록하므로 30초 자동 갱신도 누적된다. 고유 열람자 수나 의도적 클릭 수가 아니며 내부 ID 표시 Gap도 남아 있다.
활성 시간대 표시 현 화면은 시간대 밖에서도 토글을 누를 수 있다. opt-in 상태는 저장될 수 있지만 좌표 갱신은 서버의 시작 -2시간~종료 +2시간 게이트에서 차단된다. UX 일관성 측면의 보강 항목. 현재는 "왜 안 켜지지?"라는 사용자의 의문이 남을 수 있다.

사용자 시나리오

참석자 기본

일반 참석자가 모임 단위로 끈다

위치 화면 우상단 톱니바퀴를 누른 일반 참석자가 카드의 스위치를 내린다. 다이얼로그 없이 즉시 처리되고 "위치 공유를 중단했습니다" 토스트와 함께 라벨이 "위치 비공개"로 바뀐다. 일행의 다음 갱신 응답에서 본인 좌표가 사라진다.

이 흐름이 남기는 것 — 사용자가 의식하고 들어온 화면이므로 한 번 더 묻지 않고 곧장 처리하는 게 자연스럽다.

호스트 분기

운영 중 호스트가 모임 위치 공유를 끄려 한다

OPEN/진행 이벤트에서는 범용 이벤트 PATCH가 DRAFT-only라 INVALID_EVENT_STATUS로 실패한다. 서버 값은 유지되고 호스트에게 오류 토스트가 뜬다.

현재 Gap — 운영 중 위치 공유 정책을 바꾸려면 상태 범위가 분리된 전용 endpoint가 필요하다.

처리 중

토글을 누르고 응답을 기다리는 잠시 동안

토글을 누르면 그 자리에 작은 인디케이터가 잠시 돈다. 응답이 올 때까지 다시 누를 수 없도록 막혀 있어 사용자가 빠르게 두 번 누르는 사고가 일어나지 않는다.

이 흐름이 남기는 것 — 위치 공유처럼 민감한 동작에서 "이중 처리" 사고를 막는 안전 장치.

에러

이벤트 정보를 불러올 수 없다

이벤트가 삭제되었거나 네트워크가 끊긴 경우 카드 자리에 "다시 시도" 버튼이 있는 안내가 뜬다. 사용자가 누르면 다시 한 번 호출해서 데이터를 가져온다.

이 흐름이 남기는 것 — 사용자에게 무한 로딩 대신 명시적 재시도 기회를 준다.

토글 실패

네트워크가 끊긴 채 토글을 누른다

호스트 분기는 실패를 throw해 오류 토스트를 보여 준다. 일반 참석자 분기는 provider가 오류를 false로 바꾸고 화면이 false에 대한 안내를 하지 않아 조용히 끝날 수 있다.

현재 Gap — 참석자 실패도 원인을 보존해 명시적으로 알려야 한다.

참석자 재동의

토글 On과 실제 좌표 공유가 분리된다

opt-out으로 현재 share가 삭제된 참석자가 이 화면에서 다시 토글을 켜면 opt-in 행만 true가 된다. GPS 취득과 POST /update가 없어 위치 화면에서 좌표를 보낼 때까지 일행에게 노출될 위치는 없다.

현재 Gap — 화면 라벨은 참여 상태를 보여 주지만 실제 share 존재 여부를 구분하지 않는다.

운영자가 알아야 할 것

본 화면의 현 상태와 향후 보강 항목
  • 호스트와 일반 참석자가 같은 화면을 보지만 토글의 의미가 다르다. 호스트 토글은 모임 전체의 위치 공유를 켜고/끄는 동작이고, 일반 참석자 토글은 본인 한 사람의 동의 상태만 바꾼다. 운영 안내에서 이 차이를 명시하지 않으면 "내가 끈 줄 알았는데 다른 사람은 계속 보인다" 같은 혼란이 생긴다.
  • 현재 화면은 단일 이벤트 카드만 보여준다. 스펙이 의도한 "내가 공유 가능한 모든 이벤트의 리스트"는 아직 화면에 반영되지 않았다. 사용자가 여러 모임에 동시 참석 중일 때 한 화면에서 일괄 점검하는 가치가 향후 보강 시점에 살아난다.
  • 접근 이력은 고유 열람자나 의도적 클릭 수가 아니라 raw polling hit다. 위치 목록 응답에 내 좌표가 포함될 때마다 행이 생겨 30초 자동 갱신도 반복 누적된다. 최근 30일만 조회하고 30일 초과 행은 매일 03:30 삭제하며, 접근자가 `"사용자 #id"`로 보이는 점도 보강 대상이다.
  • 참석자 토글 On은 실제 좌표 전송을 시작하지 않는다. opt-in 동의와 share row 존재를 구분하거나 첫 GPS update를 연결해야 한다.
  • 상단 도움말이 위치 기능이 아닌 F12-01 가이드를 가리킨다. 사용자 안내 문서 배선이 잘못된 현재 Gap이므로 위치 공유 가이드 ID로 교정해야 한다.
  • 위치 공유 가능 시간대 외에는 토글이 흐려져야 한다는 스펙이 미반영. 현재는 시간대 밖에서도 토글이 눌리지만 실제 좌표 갱신은 서버에서 차단된다 — 사용자가 "왜 안 켜지지?"라고 느낄 수 있는 상태다.
  • 호스트의 모임 단위 토글은 현재 DRAFT에서만 성공한다. OPEN/진행 이벤트에서는 범용 수정 API가 거부하므로 운영 중 제어 수단으로 간주하면 안 된다.
