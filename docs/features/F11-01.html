F11-01 이벤트 후기 작성과 선택형 피드백

별점 후기와 사람 선택 피드백의 서로 다른 기간·자격·초안·중복 키·태그·본인 기록을 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

서로 다른 두 작성 흐름

별점·본문을 호스트에게 남기는 Review와, 다시 함께하고 싶은 참석자를 고르는 EventFeedback은 별도 원본이다. 자격·기간·중복 처리·응답과 후속 효과도 다르므로 하나의 후기 제출로 묶지 않는다.

현재 이벤트 참여 허브에는 「후기 작성」과 「함께한 사람 고르기」가 각각 연결돼 있다. 후기 작성은 eventId 경로와 URL의 title 질의 값으로 작성 화면을 연다. 제목을 extra로만 전달한다고 한 과거 설명은 현재 라우터와 다르다. 선택형 피드백 입구는 종료된 CLOSED 이벤트와 앱 참석 조건으로 표시하고, 서버가 다시 상세 접근·응답자·기간을 검사한다.

별점 후기의 자격과 저장

POST /api/v1/events/{eventId}/reviews는 {rating, content}를 받아 201 ReviewVo를 반환한다. 별점은 필수 1~5, 글은 선택·1000자 이하다. 일반 이벤트는 ATTENDING 참석 행이 필요하고, 고정 정기모임 회차는 실제 체크인 여부를 사용한다. 이 차이를 전부 「참석 확정」 한 조건으로 줄이지 않는다.

서버는 이벤트 endTime이 지났고 7일 경계 이내인지, 현재 호스트 본인이 아닌지, 같은 이벤트·작성자의 후기 이력이 없는지 확인한다. 정확히 종료 시각과 종료+7일 경계는 허용되는 비교다. 여기의 기간 기준은 선택형 피드백의 closedAt과 다르다. 삭제한 후기도 중복 이력으로 센다.

저장 후 호스트 신뢰점수 재계산, 새 후기 알림 outbox 등록, 작성자의 EVENT/REVIEW 상호작용 기록을 수행한다. 연결 클럽의 마일리지 활성 상태에 따라 적립 신호를 발행하며 판정 불가 상태도 별도로 다룬다. 신호 발행·알림 예약은 실제 적립 또는 알림 수신 완료를 뜻하지 않는다.

별점 후기의 앱 입력과 오류

작성 화면은 별점 선택으로 제출을 허용하고 SubmissionDraft의 review_{eventId}_new 키로 입력 복원·제출 준비·완료를 연결한다. 과거의 「나가면 입력이 항상 사라진다」는 설명은 현재 구현에 맞지 않는다. 제출 성공은 초안 완료 처리 뒤 true로 복귀하고 후기 목록·관련 이벤트 집계를 갱신한다. 적용 여부가 불확실한 오류도 관련 조회를 갱신 대상으로 표시한다.

권한 없음·대상 없음·중복 작성 오류는 안내 후 화면을 닫는다. 기간 만료 등 잘못된 요청과 통신 오류는 원인을 안내한다. 서버에는 이 작성 API의 멱등 키가 없고, 작성 중복 제약과 로컬 초안은 서로 다른 보호다. 수정·삭제는 후기 수정과 삭제를 따른다.

선택형 피드백의 후보와 기간

GET /api/v1/events/{eventId}/feedback/candidates는 candidates, maxSelect, deadline, eligible을 반환한다. 기간은 이벤트 closedAt부터 7일 뒤까지며, 닫힌 시각이 없거나 현재가 그 범위 밖이면 FEEDBACK_WINDOW_CLOSED다. 상세 접근이 허용돼야 하고 호출자도 적격 참석 풀 안에 있어야 한다.

체크인 기록이 하나라도 있으면 체크인 기록을, 없으면 ATTENDING 목록을 원천으로 삼는다. 계정 식별자가 없는 게스트, 확정·이의중 노쇼, 정상/로그아웃 상태가 아닌 계정을 제외한다. 그중 본인·차단 사용자를 제외한 후보가 2명 이상이어야 제출할 수 있다. 순서는 체크인 또는 참석 생성 시각과 사용자 식별자로 정한다. 최대 선택은 min(5, ceil(후보 수/2))다.

선택형 피드백의 제출과 재시도

POST /api/v1/events/{eventId}/feedback의 요청은 {clientRequestId, displayedUserIds, choices, vibeTags}이고 200 EventFeedbackVo를 반환한다. 키는 공백 불가·64자 이하, 표시 후보와 선택 목록은 null 불가다. 선택 0명은 허용하며 앱은 제출 전 확인한다. 선택한 사람은 서버 후보에 있고 중복되지 않아야 하며 선택 상한을 지킨다. 후보 식별자 집합뿐 아니라 순서까지 서버와 같아야 한다. 계정 상태·차단·후보가 달라지면 FEEDBACK_CANDIDATES_CHANGED다.

인상 태그는 긍정 10종인 FUNNY, PUNCTUAL, GOOD_LISTENER, ENERGETIC, THOUGHTFUL, CREATIVE, RELIABLE, WARM, INTELLIGENT, EASYGOING을 허용한다. null 원소·부정 태그는 거절한다. 분위기 태그는 선택이며 최대 3개, 중복·null 원소·알 수 없는 값은 거절한다. 카탈로그는 LIVELY, CALM, TALKATIVE, FOCUSED, WELCOMING, ORGANIZED, FREE_FLOWING, DRINKS_CENTERED다.

기본 요청 검증과 상세 접근 확인 뒤 이미 같은 이벤트·응답자의 응답이 있으면 같은 clientRequestId는 기존 결과를 반환하고 다른 키는 DUPLICATE_RESOURCE다. 같은 키는 본문 변경을 새 수정으로 적용하지 않는다. 새 저장 때만 응답·후보 순서·선택을 저장하고 응답자 취향 프로필을 재구축한다.

앱 키는 화면 초기화 때 한 번 생성해 같은 화면 내 재시도에 사용한다. 화면 재생성까지 키가 보존되는 계약은 아니다. 후보 변경 오류는 사람 선택·인상 태그를 비우고 후보를 다시 읽으며 분위기 선택은 유지한다. 중복·자격 없음·기간 종료는 안내 후 나가고 나머지 오류는 입력 화면에 머문다.

본인 기록과 내보내기

GET /api/v1/feedback/me는 본인 제출 이력의 페이지, /feedback/me/stats는 본인이 한 선택의 통계를 반환한다. 차단된 선택 대상은 이력의 선택 목록과 통계에서 제외한다. 받은 선택 수·상대 응답 여부·상호 선택을 노출하는 필드는 이 응답에 없다.

ReviewDataExportAssembler는 현재 본인이 작성한 vibeTags를 내보내기에 포함한다. 과거 DataExportAsyncWorker의 누락을 현재 미구현으로 남기지 않는다. 이력·통계·취향의 차이는 취향 프로필을 따른다.

현재 제한과 확인 범위

분류현재 경계문서 처리
Risk별점 후기는 endTime, 선택형 피드백은 closedAt을 기간 기준으로 사용한다.두 마감을 동일한 시각으로 가정하지 않는다.
Risk선택형 피드백 키는 화면 내 재시도에 유지되고 별점 후기에는 같은 계약이 없다.두 제출의 중복·재시도 보장을 구분한다.
미검증실제 앱 제출·알림 수신·마일리지 적립·내보내기를 이번에 실행하지 않았다.소스 연결과 실행 성공을 분리한다.

수용 기준과 검증 근거

  • AC-01 별점 후기 자격: 일반 참석 행과 고정 회차 실제 체크인을 구분하고 종료 시각·7일·자기 평가·삭제 포함 중복을 서버에서 검사한다.
  • AC-02 별점 후기 입력: 별점 1~5·선택 본문 1000자 이하를 저장하고 호스트 점수·알림 outbox·상호작용·클럽 조건부 적립 신호를 처리한다.
  • AC-03 작성 입력과 복귀: 초안 복원·제출 준비·완료를 거쳐 성공 복귀와 목록 갱신을 연결하고 오류 종류에 따라 안내·머무르기·나가기를 나눈다.
  • AC-04 선택형 후보: closedAt 기준 7일과 상세 접근·적격 풀·본인/차단 제외·2명 이상·선택 상한을 적용한다.
  • AC-05 후보 변경: 저장 직전 후보 순서·계정 자격이 바뀌면 저장하지 않고 재선택을 요구한다. 앱은 사람과 인상 태그 선택을 초기화한다.
  • AC-06 태그 검증: 긍정 인상 태그만 허용하고 분위기 태그는 유효한 서로 다른 값 3개까지 받는다. 사람 0명 선택은 확인 후 제출할 수 있다.
  • AC-07 선택형 중복: 같은 키면 기존 응답, 다른 키면 중복 오류다. 재응답으로 취향을 다시 누적하지 않는다.
  • AC-08 본인 기록과 내보내기: 본인이 한 선택만 조회하고 차단 대상을 이력·통계에서 제외한다. 내보내기에는 현재 분위기 태그가 포함된다.

근거는 현재 서버 자격·저장·내보내기와 앱 입구·요청·오류 분기다. 이번에 제품 시험을 새로 실행하지 않았다.
