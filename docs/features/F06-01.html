F06-01. 지갑 메인 조회

지갑·최근 세 거래의 별도 조회, 만료 무료 잔액 보정, 입구와 갱신·숨김 경계를 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

지갑은 현재 사용할 포인트와 최근 거래를 확인하고 충전·거래·정산·출금으로 이동하는 허브다. 잔액과 최근 거래는 별도 조회이며, 지갑 잔액 전체가 은행으로 출금할 수 있는 금액이라는 뜻은 아니다. 지갑을 읽을 수 있어도 충전·구독 등 목적지의 공개 범위와 돈 명령 조건은 따로 적용한다.

입구·표시·다음 행동

마이의 지갑에서 잔액을 읽은 뒤 다음 구역을 순서대로 보여준다. 자식 화면은 현재 화면 위에 열며, 지갑으로 돌아왔을 때 잔액과 최근 거래를 다시 읽는 경로를 둔다.

최근 거래는 첫 페이지 세 건을 생성 시각·번호 내림차순으로 읽는다. 지갑 응답에 거래 목록이 포함된다는 옛 설명은 적용하지 않는다. 거래가 없어도 잔액 카드는 0으로 남고 최근 거래 구역만 빈 안내를 보여준다.

지갑의 멤버십 입구는 개인 구독 공개 범위가 열렸거나 현재 구독이 ACTIVE·CANCELLED이고 만료 시각이 없거나 서울 현재 시각보다 뒤인 경우에만 표시한다. 공개 범위가 닫힌 상태에서 구독 조회 오류·구독 없음·그 밖의 상태·만료는 이 입구를 숨긴다. CANCELLED의 남은 이용 기간을 즉시 이용 종료로 취급하지 않는다. 입구 표시 조건과 구독 화면 자체의 기존 구독 조회·해제 허용은 서로 다른 경계다.

무료 포인트와 표시 잔액

처음 읽는 회원에게 지갑이 없으면 회원 존재를 확인해 0 잔액 지갑을 만든다. 회원별 고유 제약 경합은 별도 생성 트랜잭션을 재호출해 처리한다. 일반 조회가 잔액을 증가시키지는 않는다.

아직 저장 잔액에서 정리되지 않은 만료 무료 지급분도 조회 시 만료 잔량을 계산해 전체·무료 표시 잔액에서 제외한다. 제외액은 현재 무료 잔액을 넘지 않는다. 이 읽기 보정과 실제 만료 거래 생성은 구분한다. 지급·사용·환불의 만료 규칙은 결제·정산 공통 정책에서 함께 관리한다.

누적 충전·사용·환불·무료 지급 값은 완료 거래에서 각각의 분류 조건으로 다시 집계한다. 지갑 행의 과거 누계 값을 그대로 내보내는 것으로 설명하지 않는다. 현재 메인 화면은 이 네 누계 값을 별도 통계 카드로 표시하지 않는다.

갱신·숨김·실패·복귀

상황현재 결과
최초 잔액 로딩·실패골격 또는 지갑 오류와 다시 시도
최근 거래만 실패잔액·다른 입구는 유지하고 최근 거래 구역에 오류 문구
화면을 아래로 당김지갑 공급자를 갱신. 최근 거래 공급자를 함께 명시적으로 갱신하지 않음
자식 화면에서 지갑으로 복귀·앱 재개지갑과 최근 거래를 무효화하는 공통 복귀 처리
지갑 자료 변경 알림계정 범위를 구독하는 잔액·최근 거래 공급자가 다시 읽음
잔액 숨김총액을 점으로 가리고 유료·무료 분해 표시도 숨김. 최근 거래 금액은 별도 표시

숨김 설정은 기기의 공통 저장 키를 사용하며 계정별 설정이 아니다. 공급자는 처음에 표시 상태로 시작한 뒤 저장된 설정을 비동기로 읽는다. 계정 전환 시 금액 재조회와 기기 표시 취향을 구분한다.

모임 환불 회수금과 출금의 경계

모임 환불 회수금·판매 대금 미수금 해결과 출금은 잔액 조회와 별도 돈 흐름이다. 관련 규칙은 결제·정산 공통 정책과 정산 내역·이의 제기를 함께 본다. 지갑 허브의 출금 입구가 있다는 사실을 실지급 확인이나 전액 출금 가능 판정으로 쓰지 않는다.

현재 제한과 확인 범위

분류확인한 차이·한계영향·후속
Gap당겨 새로고침은 잔액만 명시적으로 갱신하며 최근 거래 오류 구역에 전용 재시도가 없다외부에서 생긴 거래와 잔액을 함께 다시 확인하려는 사용자의 복구 흐름 보완 대상

미검증실제 결제·환불·출금 뒤 기기에서의 최신 잔액과 최근 거래이번 작업은 조회 소스 대조이며 실거래·실기기 성공으로 확대하지 않음

수용 기준과 검증 근거

  • AC-01 첫 지갑: 회원의 지갑이 없으면 0 잔액 지갑을 만들며 회원별 고유 제약을 유지한다.
  • AC-02 잔액 분리: 총액·유료·무료를 표시하고 만료 대상 무료 잔량은 조회 표시에서 제외한다.
  • AC-03 조회 분리: 최근 거래는 지갑 객체와 별도 요청의 최신 세 건이다.
  • AC-04 빈 거래: 거래가 없어도 지갑 카드를 유지하고 최근 거래에 빈 안내를 보인다.
  • AC-05 입구: 네 바로가기와 내 정산·출금·멤버십의 목적지를 구분한다. 멤버십 입구의 공개 범위·현재 ACTIVE/CANCELLED·만료·조회 오류 조건을 나누고 닫힌 판매 권유를 숨기는지 확인한다.
  • AC-06 부분 실패: 최근 거래 조회가 실패해도 잔액과 다른 행동 입구를 전체 오류로 바꾸지 않는다.
  • AC-07 복귀: 자식 화면에서 지갑이 다시 드러나면 잔액과 최근 거래를 재조회하며 단순 팝업 닫기와 구분한다.
  • AC-08 숨김: 총액과 유료·무료 표시를 숨기되 기기 공통 저장과 최초 복원의 한계를 밝힌다.

이번 근거는 조회·집계·생성 경합 처리·화면과 복귀 공급자의 소스다. 관련 거래 부호 시험의 단언은 별도 거래 기능에서 추적하며 지갑 전체의 새 실행 통과로 세지 않는다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 본인 지갑의 이용 가능한 잔액·예약액·제한 안내가 서버의 상태와 일치한다.
  • 지급/환불 대기 금액을 사용 가능으로 세지 않고 후속 결제의 신규 이용 제한을 유지한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 결제 & 지갑의 관련 완료 기준도 함께 확인합니다.
