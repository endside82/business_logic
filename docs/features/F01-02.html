F01-02. 소셜 로그인 (카카오·네이버·구글·애플)

비밀번호를 새로 만들지 않고도 이미 쓰던 외부 계정으로 들어올 수 있게 한다. 신규 사용자에게는 가입+로그인 한 동작으로 끝낼 수 있는 가장 짧은 경로이고, 기존 사용자에게는 비밀번호를 외울 필요 없는 재방문 경로다. 4종 제공자 모두 같은 흐름을 따르되, 토큰 검증 방식은 제공자별로 다르다.

Google 실제 계정 확인 — 2026년 10월 12일

Android·Web OAuth 설정을 연결하고 서명 Android 16 에뮬레이터에서 실제 개인 Google 계정의 신규 가입·필수 동의·온보딩을 마쳤다. 앱 강제 종료 후에도 로그인 상태와 홈 복귀를 확인했다.

로그아웃 후 재로그인·계정 연결/해제·취소·실기기·iOS·Play 배포본은 별도 확인이 남아 있다. 카카오·네이버·Apple은 이번 Google 검증에 포함하지 않는다.

환경·근거·다음 행동: Google 로그인 등록과 실제 계정 확인.

설계 의도 — 외부 인증 한 번으로 가입과 로그인이 같이 끝난다

사용자가 소셜 버튼을 누르고 마지막 외부 인증을 마치면, 서비스는 그 사람을 이미 알고 있는지 아닌지를 같은 응답으로 결정한다. 이미 아는 사용자면 곧장 홈으로, 처음 보는 사용자면 곧장 온보딩으로. 가입과 로그인의 분기를 사용자가 직접 결정하지 않는다 — "처음이신가요/아니신가요" 같은 질문은 받지 않는다. 이 분기를 사용자에게 떠넘기면 매번 같은 외부 계정으로 두 번째, 세 번째 가입이 만들어지는 사고가 발생한다.

현재 로그인 활성 상태와 iOS 공개 전 결정

현재 앱·서버의 활성 제공자는 이메일·Google이다. 카카오·네이버·Apple의 연결 코드는 있지만 버튼과 직접 호출은 비활성이다. 이 상태는 구현 설정이며 App Store 심사 요건을 충족했다는 판정이 아니다.

iOS에서 Google을 주 계정 로그인으로 유지한다면 Apple 심사 기준에 맞는 동등한 로그인 수단이나 적용 가능한 예외를 확인해야 한다. Sign in with Apple 활성화 방안부터 검토하되, 실제 조건과 선택한 구성을 기록한다. 이메일 가입만으로 충족했다고 간주하지 않는다.

카카오·네이버 추가 공개는 후속으로 진행한다. iOS 로그인 구성 결정은 첫 공개 전에 완료하고, Apple을 선택하면 설정·버튼·실제 계정·탈퇴와 인증 철회까지 검증한다. 가입·설정·완료 기준은 iOS 로그인 구성과 심사 준비를 따른다.

사용자가 보기에는 한 번의 동작이지만, 서비스는 세 단계를 거친다 — 사전 정보 수집, 외부 인증, 가입/로그인 결정.

사용자 시나리오

신규

카카오로 처음 시작

사용자가 카카오 버튼을 누른다. 닉네임·생년월일을 입력하고 필수 약관에 동의하면 카카오 로그인 화면이 뜨고, 카카오 인증을 마치면 곧장 온보딩 화면으로 들어간다. 별도 가입 화면 없이 한 번에 끝난다.

이 흐름이 남기는 것 — 사용자가 처음 본 화면에서 가장 짧은 가입 경로. 이메일 가입 흐름보다 입력 항목이 적기 때문에 가입 완료율이 일반적으로 더 높다.

재방문

이전에 카카오로 가입한 사용자가 다시 로그인

같은 카카오 버튼을 누른다. 닉네임·생년월일을 다시 입력하라는 시트가 떠도 사용자가 입력한 정보는 사용되지 않고 외부 인증을 마치면 곧장 홈으로 들어간다 — 서비스는 이미 그 사람을 알고 있다.

이 흐름이 남기는 것 — 비밀번호를 외울 필요 없는 재방문 경로. 비밀번호 분실 문의를 가장 강하게 줄이는 동선.

중단

외부 인증 화면에서 취소

시트까지 입력했지만 카카오 인증 화면에서 마음이 바뀌어 취소한다. 토스트 없이 로그인 화면 그대로 돌아온다 — 사용자의 명시적 취소이므로 실패로 인지시키지 않는다.

연령 정책

만 19세 미만 신규 가입 시도

시트에서 2010년생을 입력하고 외부 인증을 마쳤다. 서비스는 신규 사용자임을 확인한 직후 연령을 검사해서 가입을 차단한다. 계정 자체가 만들어지지 않는다. 이메일 가입 화면과 정확히 같은 연령 기준이 발현된다.

이 흐름이 남기는 것 — 가입 채널이 달라도 연령 정책이 흩어지지 않게 한다.

계정 상태

차단된 기존 사용자가 다시 소셜 로그인 시도

운영자가 정책 위반으로 차단한 사용자가 같은 카카오 계정으로 다시 로그인한다. 외부 인증은 통과해도 서비스 내부의 계정 상태가 차단 상태라서 로그인이 거부된다.

외부 인증 실패

외부 토큰 검증 실패

외부 제공자의 일시적 장애 또는 키 설정 오류로 인증 토큰이 검증되지 않는다. "소셜 로그인에 실패했습니다" 안내가 떠오르고 사용자는 다른 제공자 또는 이메일 로그인으로 시도할 수 있다.

화면에서 사용자가 인지하는 것

화면 요소사용자가 보는 것그 자리에 둔 이유
소셜 버튼 영역 카카오(노란색)·네이버(녹색)·구글(흰색)·애플(검정) 중 그 시점에 활성화된 제공자의 버튼만 같은 크기로 세로 나열. 현재는 구글 한 개이며 iOS 공개 전 로그인 구성 결정에 맞춰 변경·검증한다. 각 브랜드의 표준 디자인을 그대로 따라야 사용자가 1초 안에 "이 버튼이 뭔지" 인지한다. 비활성 제공자는 버튼 자체를 그리지 않아 "눌러도 안 되는 버튼"이 보이지 않게 한다.
추가 정보 시트 외부 인증 전에 닉네임·생년월일·필수 약관 두 가지를 한 화면에서 묻는 바텀시트 외부 인증이 끝난 뒤 추가 화면을 끼우면 사용자가 "끝났는데 또 뭘 묻나" 답답해한다 — 외부 인증 전에 한 번에 묻는다.
로딩 오버레이 외부 인증 응답을 기다리는 동안 화면 위에 반투명 진행 표시 외부 인증은 1~3초 걸리기 때문에 시각적 피드백 없이는 "버튼이 안 눌렸나" 오해가 생긴다.
실패 안내 토스트 "소셜 로그인에 실패했습니다" / "이미 가입된 계정입니다" 같은 짧은 한 줄 사용자가 본인 잘못이 아니라는 사실을 분명히 인지하고 다른 경로로 시도할 수 있게.

소셜 로그인 현황에서 장애 원인을 확인합니다

2026년 9월 24일, 제공자별 결과 기록·집계와 관리자 웹의 소셜 로그인 현황을 기본 브랜치에 반영했습니다. 대시보드 조회 권한이 있는 운영자가 카카오·네이버·Google·Apple의 성공·실패, 실패율·실패 분류와 일별 변화를 확인합니다.

  • 사람 수가 아닌 시도 건수입니다. 같은 사람이 세 번 실패하면 세 건이며, 신규 가입의 추가 정보 요청 단계는 실패로 세지 않습니다. 시도가 없으면 실패율 0% 대신 시도 없음으로 표시합니다.
  • 한국 날짜 기준 최대 92일을 한 번에 조회하며 시작일과 종료일을 모두 포함합니다.
  • 결과 기록에는 제공자·성공 또는 실패·실패 분류·시각만 남깁니다. 토큰·이메일·이름·사용자 번호·IP·오류 원문은 넣지 않으며, 1년이 지난 기록은 삭제합니다.
  • 집계 기록이 지연되거나 실패해도 로그인 결과를 기다리게 하지 않습니다. 이 화면의 수치를 모든 시도가 빠짐없이 남는 감사 기록으로 해석하지 않습니다.

서버·관리자 API·관리자 웹 자동 검사 기록이 있습니다. 실제 제공자 계정과 서명한 휴대전화 앱의 확인은 남아 있습니다. 이메일·Google이라는 첫 출시 범위는 유지하며, 추가 로그인 제공자의 설정과 실제 계정 확인을 마친 뒤 제공자별로 공개합니다.

운영자가 알아야 할 것

제공자별 검증 방식과 정책 결정점
  • 4종 제공자는 검증 방식이 모두 다르다. 카카오·네이버는 외부 API에 사용자 정보를 묻고, 구글·애플은 토큰 자체를 검증한다. 한 제공자의 장애가 다른 제공자에 영향을 주지 않는다 — 한 곳이 막혀도 나머지 셋은 정상 동작.
  • 카카오·네이버 외부 호출에는 대기 상한이 있다. 연결은 최대 5초, 응답은 최대 10초까지만 기다린다. 제공자가 멈춰도 로그인 요청과 서버 연결이 무기한 묶이지 않으며, 제한시간을 넘기면 사용자는 실패 안내를 받고 다른 로그인 방법을 선택할 수 있다.
  • 외부 식별자 형식이 바뀌면 같은 사용자가 신규로 보일 수 있다. 카카오는 과거 식별자 방식에서 한 번 변경된 적이 있다. 이런 변경이 다시 일어나면 같은 사용자에게 새 계정이 만들어져 데이터가 갈라진다 — 운영 측에 마이그레이션 절차가 사전에 준비되어야 한다.
  • 연결 해제 후 재로그인 시 새 계정이 만들어진다. 사용자가 카카오 연결을 끊은 뒤 다시 카카오로 로그인하면 서비스는 그 사람을 처음 보는 사용자로 인지한다 — 이전 활동 데이터가 새 계정에 자동으로 합쳐지지 않는다는 사실을 CS가 알고 있어야 한다.
  • 소셜만 쓰는 사용자에게는 비밀번호가 없다. 비밀번호 재설정·이메일 인증·소셜 연결 해제 등의 동선이 이메일 가입자와 다르게 흐른다 — F01-08과 함께 정책을 점검.
  • 소셜 신규 가입 계정은 이메일 인증을 이미 마친 것으로 태어난다 (2026-08-18). 이 계정에는 메일을 보낼 실제 주소 자체가 없어(내부 식별용 주소만 있다) 인증 절차에 들어가면 빠져나올 수 없기 때문이며, 신원은 소셜 제공자가 이미 확인해 줬다. ⛔ 다만 이미 이메일로 가입한 계정에 소셜을 연결하는 경우는 다르다 — 그 계정의 주소는 사용자가 직접 적은 실제 주소이고 소셜 제공자가 그것을 확인한 적이 없으므로, 연결만으로는 인증을 인정하지 않는다. 자세한 경계는 F01-03 이메일 인증 참조.
  • 외부 인증 사용자에 대한 닉네임·생년월일은 시트에서 받는다. 만약 시트를 건너뛰는 동선이 만들어지면 닉네임이 임의 문자열로 자동 생성되고 추천·매칭 품질이 떨어진다 — 사전 정보 시트는 항상 외부 인증 직전에 노출되어야 한다.

이 기능의 출시 완료 기준

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 첫 출시 포함 여부와 구현·검사 현황은 위 상태표를 따릅니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 첫 출시의 이메일·Google 목록과 실제 로그인 화면·서버 허용 범위가 일치한다.
  • Google 계정 선택 취소·재로그인·다른 계정 전환을 확인하고 추가 제공자는 후속 공개 전까지 열지 않는다.
