F08-14. 플랜 마켓 환불

마켓 아이템·번들·플랜 직접 구매분에 대한 환불 흐름. 구매자가 신청하고 판매자가 승인/거절하며, 판매자 무응답에는 자동 처리가 붙는다. 1인 크리에이터 판매자가 많아 무응답·지연 응답이 흔하므로 사용 흔적이 없는 7일 무응답 건은 자동으로 환불 승인되고, 사용 흔적이 있는 건만 운영자 검토로 올라간다. 거절에 동의 못 하는 구매자는 분쟁을 열어 운영자 중재로 갈 수 있다.

설계 의도 — 판매자 무응답이 구매자를 인질로 잡지 않는다

1인 크리에이터 판매자가 많아 무응답·지연 응답이 잦다. 판매자 결정만 기다리지 않고 7일 자동 처리를 깐다 — 사용 흔적이 없으면 자동 승인(환불), 사용 흔적이 있으면 운영자 검토로 올라간다. 판매자가 추가 자료를 요청해 타이머를 한 번 멈출 수 있는 안전장치도 있다.

사용자 시나리오

1. 환불 신청

"14일 안에 산 미사용 상품을 환불하고 싶다"

구매자가 사유와 설명을 입력해 전액 환불을 신청한다. 신청은 심사 대기 상태로 저장되고, 상품 사용 권한과 해당 매출은 결정이 날 때까지 잠긴다. 판매자에게 새 신청 알림도 전달된다.

완료 판단 — 신청 기록, 사용 권한, 매출 보류, 판매자 알림이 같은 요청으로 함께 바뀌어야 한다.

2. 환불 불가 조건

"기한이 지났거나 이미 사용·환불한 상품이다"

14일이 지난 단순 변심, 사용한 상품의 단순 변심, 이미 전액 환불된 구매는 돈과 권한을 바꾸지 않고 거절한다. 다만 파일 하자나 설명 불일치는 사용 흔적이 있어도 심사할 수 있다.

완료 판단 — 거절 사유가 사용자에게 보이고, 지갑·권한·매출 원장에는 변화가 없어야 한다.

3. 번들 부분 환불

"묶음 상품 중 문제가 있는 구성품만 환불한다"

구매 당시 번들에 들어 있던 구성품 중 아직 환불하지 않은 항목만 선택한다. 일부를 선택하면 그 항목의 권한과 매출만 잠기고, 전부를 선택하면 전액 환불 신청으로 합쳐진다.

완료 판단 — 선택하지 않은 구성품은 계속 사용할 수 있고, 이미 환불한 구성품은 다시 선택할 수 없어야 한다.

4. 판매자 승인

"판매자가 사유를 확인하고 환불을 승인한다"

구매자 지갑에는 결제 당시의 유료·무료 포인트 구성이 그대로 복원되고 이용 권한은 회수된다. 정산 전 매출은 취소하고, 이미 지급한 매출은 회수 대상으로 전환한다.

완료 판단 — 같은 승인이 다시 들어와도 환불·권한 회수·회계 처리가 한 번만 실행되어야 한다.

5. 거절·취소·재신청

"판매자가 거절하거나 구매자가 결정 전에 취소한다"

판매자가 거절하면 구매 잠금이 풀리고 구매자는 24시간 뒤 한 번만 다시 신청할 수 있다. 구매자가 판매자 결정 전에 스스로 취소한 경우에는 재신청 횟수를 소모하지 않는다.

완료 판단 — 두 경로 모두 권한을 복구하되, 재신청 제한은 서로 다른 정책대로 계산되어야 한다.

6. 추가 자료 보완

"판매자가 사진이나 설명을 더 요청한다"

판매자는 한 번만 자료를 요청할 수 있다. 요청 중에는 7일 자동 처리 시계가 멈추고, 구매자가 자료를 제출하면 판매자 심사 상태로 돌아가 새 기한을 계산한다.

완료 판단 — 구매자가 기한 안에 응답하지 않으면 신청이 만료되고 잠긴 구매 권한이 다시 열려야 한다.

7. 판매자 7일 무응답

"판매자가 일주일 동안 아무 결정도 하지 않는다"

사용 흔적이 없으면 자동 승인해 환불한다. 다운로드·이벤트 연결 같은 사용 흔적이 있거나 판매자를 특정할 수 없는 오래된 구매는 자동 환불하지 않고 운영자 검토 목록으로 보낸다.

완료 판단 — 판매자 무응답이 구매자를 무기한 묶지 않으면서, 사용 후 자동 환불도 허용하지 않아야 한다.

8. 분쟁과 운영자 판정

"판매자 거절에 동의하지 못해 증빙을 제출한다"

구매자는 거절 후 7일 안에 한 번 분쟁을 열 수 있다. 운영자는 증빙과 사용 이력을 보고 거절 유지, 추가 자료 요청, 강제 환불 중 하나를 결정한다.

완료 판단 — 강제 환불도 일반 승인과 같은 안전한 환불 경로를 한 번만 사용하고 판정자 기록을 남겨야 한다.

9. 한도와 동시 신청

"임계 시점에 여러 환불을 동시에 신청한다"

같은 사용자가 월간 한도 직전에 두 건을 동시에 신청하거나, 두 사용자가 서로의 상품에 동시에 신청해도 잠금 순서와 한도 계산이 일관되어야 한다.

완료 판단 — 한도를 우회하거나 요청이 유실되거나 서로의 처리를 무기한 기다리는 일이 없어야 한다.

10. 구매자·판매자 앱 왕복

"앱에서 신청부터 결정·분쟁까지 끝낸다"

구매자는 신청·목록·상세·취소·자료 응답·분쟁 화면을 오가고, 판매자는 받은 요청을 승인·거절·자료 요청으로 처리한다.

완료 판단 — 필수 식별자가 빠진 화면 이동 오류 없이 앱의 상태와 가능한 버튼이 서버 결과와 같아야 한다.

현재 검증 수준

핵심 환불·분쟁·동시성 로직은 서버 테스트로 확인했다. 다만 판매자 거절 전 과정, 자료 요청·응답·만료, 7일 자동 처리, 구매자·판매자 앱과 서버의 전체 왕복은 하나의 시나리오로 묶은 자동 검증이 아직 없다. 따라서 현재 상태를 “환불 전 과정 E2E 완료”로 표시하지 않는다.

운영자가 알아야 할 것

사용 흔적·자동 처리·재신청
  • "사용 흔적"의 정의 — 다운로드 횟수, 이벤트 연결, 활성화 시각. 이 중 하나라도 있으면 자동 환불 불가, 운영자 검토.
  • 거절 후 24시간 1회 재신청 — 같은 구매에 무한 신청을 막기 위함.
  • 분쟁은 거절로부터 7일 이내 1회 — 단발성. 분쟁이 끝나면 결과 확정.
  • 운영자 강제 환불은 별도 라벨 — 정산·노출 패널티 누적에 영향(별도 정책).
  • 구매 잠금 동안 사용 불가 — 환불 신청 즉시 카드는 잠기고, 결정이 날 때까지 사용·다운로드 막힘.

자주 발생하는 케이스
  • 환불 후 유료/무료 분리 보존 (2026-06-06 해소) — 이제 환불은 구매할 때 유료/무료로 낸 구성 그대로 복원한다. 그 전까지는 전액 유료 포인트로 돌아와 무료 포인트가 현금성 유료로 둔갑하던 구멍이 있었는데, 마켓을 포함한 모든 환불 경로에서 봉합됐다.
  • 이중 환불 차단 (2026-06-06 해소) — 한 구매가 두 번 환불되던 구멍을 막았다. 환불이 끝난 건의 상태가 중복 환불 차단 조건에 반영되어, 같은 구매에 환불이 한 번 더 발사돼도 두 번째는 무효화된다(환불액이 결제액을 넘지 못함).
  • 매출 귀속(F08-15)과 의존 — 환불은 크리에이터 매출 원장을 잠그거나 역전시키므로 F08-15가 정확해야 환불도 정확하다.
  • 추가 자료 요청 후 기한 만료 — 사용자가 응답 안 하면 환불 신청이 만료된다(거절 아님). 사용자에게 명확히 안내 필요.
  • 판매자가 잠수타면 7일 카드 잠금 — 사용자 입장에서 답답할 수 있어 신청 시 안내 필수.
