F06-06. 포인트 결제·환불

신청별 참가비 결제와 취소, 서버 예상액·일행 추가분·지갑 반환과 계좌이체 반환 대기, 정산 영향을 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

참가비 결제는 모임의 신청 건을 대상으로 하고, 본인 취소는 신청 취소 명령이 결제 정리까지 연결한다. 별도 지갑 결제·환불 요청 API는 현재 계약이 아니다. 지갑 결제분의 포인트 반환과 계좌이체분의 주최자 반환 대기를 구분한다. 호스팅 개설권·개인 구독 구매는 각 기능의 별도 창구와 조건을 따른다.

모임 상세의 결제 대기 행동에서 시작한다. 앱은 결제 기한과 공개된 결제수단을 확인한다. 계좌이체 대상이면 해당 모임 결제 화면으로 이동하고, 지갑 결제가 허용된 대상이면 신청 건을 결제한다. 잠긴 수단·알 수 없는 정책은 안내하고 필요한 상세를 다시 읽는다. 이 문서는 현재 운영 환경에서 특정 수단이 열렸다고 선언하지 않는다.

지갑 결제의 조건·금액·자동충전

서버는 모임과 본인 신청을 잠그고 접근 권한, OPEN 상태, APPROVED_PENDING_PAYMENT 상태, 결제 기한, 신청 제한, 선입금 필요 여부와 허용 수단을 검사한다. 신청에 활성 결제가 있으면 새 결제를 거절한다. 사용자가 금액을 보내는 API가 아니다. 신청에 저장된 양수 결제액을 우선하고 없으면 모임 선입금 금액을 사용한다.

새 결제 건 번호를 기준으로 중복 차감을 검사하고 부족액이 있으면 자동충전 조정기를 거친다. 자동충전이 확인 중이면 원 결제를 즉시 진행하지 않는다. 확정 뒤 원 요청을 다시 평가하며, 자동충전이 성립하지 않으면 실제 지갑 차감에서 부족액을 돌려준다. 자세한 조건은 자동충전 설정과 실행을 따른다.

차감은 유료 우선이며 무료분도 구분한다. 지갑·충전 원본 소비·결제 기록·회계 기록을 같은 업무 흐름으로 저장하고 결제 상태를 PAID로 바꾼 뒤 참석 확정을 연결한다. 일행 결제 정보와 결과 알림 저장도 이어진다. 차감 근거가 부족한 경우 전체 결제 실패로 처리하며, 알림 저장을 실제 수신으로 쓰지 않는다.

앱은 성공 결과의 PAID 상태를 보고 참석 표시를 바꾸고 모임 상세·카드·예정 모임·지갑 갱신을 알린다. 반영됐을 가능성이 있는 오류도 다시 조회한다. 결과 불명은 같은 명령 번호로 재확인하며 다른 구매로 재전송하는 것과 구분한다. 신청 취소는 저장된 신청 번호로 현재 본인 신청을 다시 읽어 재생한다.

부족액 응답을 받으면 충전 여부를 묻고 동의한 경우 부족액·이유를 담아 충전 화면을 연다. 충전 후 참가비 결제가 저절로 완료되는 것은 아니며 사용자가 다시 시도한다. 자동충전 결과가 불확실한 오류에서는 수동 충전 제안을 앞세우지 않고 확인 중 안내를 한다. 충전 자체는 포인트 충전의 범위다.

취소 전 예상액과 사용자 확인

상세의 참석 취소는 취소 시트를 연다. 화면은 event.price > 0이면 유료 취소 안내와 서버 미리보기를 사용한다. 내 신청 목록에서 같은 모임의 활성 신청을 생성 시각 내림차순으로 골라 참가자 귀책의 예상액을 요청한다. 시각을 보내지 않아 서버가 조회 시각으로 계산한다.

신청·예상액을 읽는 중이거나 실패하면 확정 단추를 막고 해당 조회의 재시도를 제공한다. 대상 신청을 찾지 못한 경우에는 예상액 확인 불가 안내를 보여 주되 동의 후 취소는 허용한다. 예상액을 받은 경우 allowed가 참이어야 동의 체크와 함께 확정할 수 있다. 확정은 시트를 닫고 실제 취소 요청을 시작한다.

예상액에는 기준 금액·환불 비율·수수료·환불액·귀책·정책 코드·허용 여부가 포함된다. 계좌이체 환불이면 주최자가 돌려줄 금액이라는 표현과 즉시 반환되지 않는다는 설명을 보인다. 예상액은 조회 시점의 계산이며 취소 요청은 서버에서 상태와 시각을 다시 판정한다.

취소 명령이 결제수단별로 하는 일

서버는 본인 신청과 모임 접근·취소 가능 상태·열린 예치금 등 관련 조건을 확인한다. 신청이 없거나 이미 취소할 수 없는 상태라고 해서 임의로 환불하지 않는다. 모임 시작 뒤 본인 또는 일행의 체크인으로 이미 사용한 일반 자진 취소도 별도로 차단한다.

결제 상태·수단취소의 결과
활성 결제 없음신청 취소 처리

계좌이체 입금 신고 대기 또는 완료해당 정책의 반환 가능 여부를 확인하고 주최자 반환 대기로 연결. 일행 추가 결제도 대기 처리에 포함

계좌이체 취소 성공은 앱 지갑 적립이나 실제 송금 완료가 아니다. 지갑 환불의 거래 표시는 거래내역·상세와 연결한다. 취소 성공과 반영 가능 오류는 모임·예정/참석 목록·지갑을 다시 읽도록 알린다. 화면은 성공 시 참석 취소를 알리고 현재 상세에 남는다.

모임 정책·귀책·일행 추가 결제의 계산

정책 코드는 STANDARD·STRICT·FLEXIBLE·FULL·NON_REFUNDABLE·CUSTOM이다. 실제 계산은 해당 모임에 저장된 규칙과 수정 규칙을 사용한다. 시작까지 남은 시간을 시간 단위로 내림하고 규칙 배열에서 처음 맞는 비율을 적용한다. 일률적인 24시간·12시간 정책으로 모든 모임을 설명하지 않는다.

참가자 귀책은 정책 비율을 전체 기준액에 적용해 내림한 다음 유료 몫을 비례 내림하고 나머지를 무료 몫으로 둔다. 고정 수수료는 유료 반환분 안에서만 뺀다. 환불 불가 정책·맞는 구간 없음·0%·차감 후 0원은 일반 참가자 환불 허용으로 보지 않는다.

호스트 귀책·불가항력·합의·일정 변경 거절은 해당 계산에서 100%와 수수료 0을 사용한다. 모임이 취소됐다면 입력 귀책 대신 호스트 귀책을 쓴다. 개설권 반환 여부는 귀책 안내 값뿐 아니라 실제 소비 원본·만료 조건도 따라야 한다.

본인과 일행의 전체 취소는 원 결제와 추가 결제를 함께 계산한다. 참가자 귀책의 비율 기준은 앞서 취소한 일행 줄의 원금을 제외하고, 각 결제의 남은 유료·무료 한도를 넘지 않도록 제한한다. 고정 수수료는 원 결제에 적용하고 추가 결제마다 다시 붙이지 않는다. 단순히 최초 결제액에 비율 한 번을 곱한 값과 같다고 단정하지 않는다.

노쇼의 일반 계산은 자동 환불 불가이며 사후 조정은 별도 명령이다. 사후 조정 미리보기는 실제 노쇼 여부와 원 결제·일행 추가 결제의 잔여 합계를 기준으로 수동 금액을 검사한다. 일반 취소 단추가 이 조정을 대신하지 않는다.

주최자 정산과 환불 회수금

참가자 지갑 반환과 주최자 정산 보정은 구분한다. 지급 전 정산에는 환불 조정을 반영하고, 이미 지급한 정산은 회수 경로로 처리한다. 지급 근거가 불일치하면 참가자 반환을 막는 대신 해당 정산을 바꾸지 않고 별도 정합성 처리로 남긴다.

모임 환불 회수금의 조회·상환과 창작자 판매 회수금은 다른 업무다. 구체적인 회수·상환 조건은 주최자 환불 회수금의 조회와 상환을 따른다. 이 문서의 참가비 취소 성공을 주최자의 미해결 회수금 상환 완료로 확대하지 않는다.

계약 변경 이력의 위치

  • 2026-05-22 기록은 새 선입금 경로를 통합하던 시기의 이력이다.
  • 2026-06-06 기록은 표준 차감·환불 경로로 이관하며 옛 직접 결제를 차단한 이력이다.
  • 2026-08-18 첫 유료 출시의 계좌이체 우선 결정은 당시 출시 태세다. 현재 사용 가능 여부는 공개 범위·결제수단 정책으로 판단한다.
  • 2026-10-03 옛 POST /api/v1/wallet/pay·POST /api/v1/wallet/refund 제거 기록을 보존한다. 옛 시험의 직접 호출·고정 잔액 예시는 현재 수용 기준이나 새 실행 증거가 아니다.

수용 기준과 검증 근거

  • AC-01 현재 창구: 신청별 참가비 결제와 신청 취소를 사용하고 제거된 지갑 API를 호출하지 않는다.
  • AC-02 결제 자격: 본인·모임 상태·신청 결제 대기·기한·제한·결제수단을 서버에서 확인한다.
  • AC-03 서버 금액: 클라이언트 임의 금액 대신 신청에 저장된 결제액 또는 선입금 정책 금액을 쓴다.
  • AC-04 중복 재시도: 결과 불명의 같은 명령은 같은 요청 번호로 확인하고 활성 결제 중복을 막는다.
  • AC-05 자동충전: 확정 뒤 원 결제를 다시 판정하며 확인 중이면 새 청구·수동 충전 안내와 구분한다.
  • AC-06 부족액 이동: 동의 후 부족액을 채운 충전 화면을 열고 참가비 재시도는 별도 행동으로 둔다.
  • AC-07 예상액: 신청·미리보기 로딩/오류·없음·허용/거절과 동의 체크를 구분한다.
  • AC-08 결제수단별 취소: 지갑 반환과 계좌이체 주최자 반환 대기를 같은 완료로 쓰지 않는다.
  • AC-09 정책 계산: 모임별 귀책·비율·유료/무료·수수료와 일행 추가분 잔여 한도를 적용한다.
  • AC-10 이미 사용한 참가: 시작 후 체크인으로 소비된 일반 자진 취소를 별도 판정한다.
  • AC-11 정산 영향: 참가자 반환·주최자 정산 보정·회수금 상환 완료를 구분한다.
  • AC-12 결과 갱신: 성공 또는 반영 가능 오류 뒤 관련 모임·지갑을 다시 읽으며 외부 반환을 추정하지 않는다.

기존 refund_policy_form_test.dart의 계좌이체 예상액 표시, 동의 전 차단, 허용 뒤 확정 가능, 거절 시 동의해도 확정 불가 단언을 확인했다. 기존 이벤트 상세 소스 근거를 재사용하고 이번에 결제·취소·계산 연결을 추가 대조했다. 새 앱 시험·실DB·외부 결제·반환 송금은 실행하지 않았다.
