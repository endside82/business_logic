F12-02. 알림 그룹 보기 · 미읽음 배지

읽지 않은 알림 수는 각 탭 상단의 알림 아이콘에서 확인한다. 알림 목록에서는 유형별 그룹 보기로 내용을 모아 본다. 2026-11-02 메뉴 개편으로 알림은 상단에서 여는 화면이다.

상단 알림 배지

각 탭 첫 화면에 검색·알림·전체 메뉴가 같은 순서로 놓입니다. 로그인한 회원은 알림 목록과 같은 상태에서 읽지 않은 수를 받아 배지로 봅니다. 수가 0이면 배지를 숨깁니다. 비로그인 상태에서는 수를 조회하지 않고 알림을 열 때 로그인으로 안내합니다.

구현 근거는 AppTopBarActions의 unreadCountNotifierProvider와 Badge.count입니다. 이전의 ‘하단 탭 배지 미구현’ 설명을 대체합니다.

그룹 보기와 읽음 처리

그룹 보기도 20건씩 다음 알림을 이어 받아 같은 유형의 카드에 합칩니다. 중간에 새 알림이 들어와도 이미 받은 알림을 중복 계산하지 않도록 커서를 사용합니다. 차단 상대를 제외해 한 응답이 비어도 다음 알림이 있으면 계속 읽습니다. 추가 조회가 실패하면 기존 카드와 재시도를 유지합니다.

카드를 누르면 가장 최근 알림 한 건만 읽음 처리합니다. ‘모두 읽음’은 계정 전체에 적용합니다. 상단 배지의 임시 차감은 요청 실패 시 복구하고, 계정이 바뀌면 이전 계정의 값을 비웁니다.

집계 범위와 남은 확인

그룹 카드의 수는 지금까지 불러온 알림의 합계입니다. 상단 배지는 서버의 미읽음 수이며, 1,000건을 넘으면 차단 필터 적용 전 수를 사용하므로 화면에서 센 수와 다를 수 있습니다.

읽음·모두 읽음은 일반 목록과 배지에 반영되지만 별도 그룹 카드의 미읽음 수를 즉시 갱신하는 연결은 없습니다. 그룹 보기에서 업무 화면을 열고 돌아오거나 모두 읽음을 누른 직후, 새로고침 전후의 수를 구별해 확인해야 합니다.

2026년 11월 22일 서버·앱 소스 대조입니다. 커서·합산 시험이 있다는 사실을 운영 푸시 수신이나 실제 기기 복귀의 통과 기록으로 보지 않습니다.

확인할 상황

  • 그룹 보기 끝에서 다음 알림이 합쳐지고 중복되지 않는가.
  • 읽음·모두 읽음 실패 뒤 배지의 임시 변경이 복구되는가.
  • 로그아웃·계정 전환 뒤 이전 회원의 수가 남지 않는가.
  • 알림에서 업무 화면을 열고 돌아왔을 때 그룹 카드와 재조회 수의 차이를 확인했는가.

현재 앱 메뉴 · 검색·알림·전체 메뉴 입구

이 기능의 출시 완료 기준

2026년 11월 22일 갱신한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 첫 출시 포함 여부와 구현·검사 현황은 위 상태표를 따릅니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 그룹의 누적 조회 범위와 상단 배지의 집계 범위를 구별하고, 개별·전체 읽음 후 재조회 결과를 확인한다. 1,000건 초과 시 차단 필터 한도를 함께 기록한다.
  • 동시 수신·읽음 실패·재진입·계정 전환 뒤 배지가 서버 수로 복구되는지 확인하고, 그룹 카드의 갱신 시점은 별도로 기록한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 알림의 관련 완료 기준도 함께 확인합니다.
