F12-05. 푸시 기기 관리

로그인 세션의 푸시 등록과 계정 전환을 관리합니다. 설정에서 현재 발송 가능한 기기를 확인하며, 기기 삭제의 실제 세션 범위를 구분합니다.

로그인 세션과 푸시 등록

로그인 후 현재 계정·세션으로 기기 토큰을 등록합니다. APNs나 FCM 토큰 준비가 지연되면 토큰 변경·앱 복귀 때 다시 맞춥니다. 로그아웃하면 이전 세션의 발송과 기기 알림·토큰을 정리합니다. 실패한 기기 정리는 재시도 대상으로 남깁니다.

토큰이 다른 회원에게 연결되어 있을 때

그 토큰을 현재 회원에게 옮기지 않습니다. 서버는 기존 발송을 비활성화하고 충돌을 반환하며, 앱은 새 토큰을 발급받아 현재 계정으로 등록합니다. 이전 계정의 푸시를 새 계정의 업무 화면으로 연결하지 않도록 수신자도 확인합니다.

설정에서 기기 관리

설정의 ‘기기 관리’는 현재 발송 가능한 기기를 최대 10개 표시합니다. 종류·등록일·수신 상태를 보고 삭제 확인을 할 수 있습니다. 모든 과거 기기나 계정 접속 이력을 보여 주는 화면은 아닙니다.

현재 서버의 삭제는 요청 세션과 같은 토큰에만 적용합니다. 같은 계정의 다른 세션 기기는 실제 변경 없이 성공 응답할 수 있고 앱은 목록에서 숨기므로, 다른 기기를 원격 해제하는 동작은 확인이 필요한 공백입니다. 삭제 성공 표시만으로 다른 기기의 수신이 중단됐다고 판정하지 않습니다.

확인 범위

2026년 11월 22일 서버·앱 소스 대조입니다. 실제 OS·기기·외부 발송 결과와 코드 구현을 구분합니다.

같은 알림의 재발송

전경 배너는 계정과 알림 번호로 중복을 억제합니다. 표시를 억제해도 알림을 눌러 해당 화면으로 이동하는 동작은 유지합니다. 공급자 수락과 모든 기기 표시 완료는 다릅니다.

알림 기록·발송 수락·실제 수신을 구분합니다에서 재처리와 실제 수신의 경계를 확인합니다.

Firebase 연결과 Android 수신 확인 — 2026년 10월 12일

Firebase 프로젝트·Android 앱·서버 발송 계정·권한을 연결했다. Android 16 에뮬레이터에서 실제 FCM의 전경·백그라운드·프로세스 종료 수신, 알림 클릭 후 문의 목록 이동과 알림 권한 거절·재허용을 확인했다. 격리 DB에 넣은 QA 발송 행으로 검사했으므로 개별 업무 이벤트의 발행 검증은 별도다.

이 기록에서 확인하지 않은 iOS/APNs·실제 휴대전화·Play 배포본·계정 전환과 발송 복구는 현재 출시 기록에서 따로 확인한다. 서버 초기화나 발송 수락만으로 기기 수신을 완료로 기록하지 않는다.

환경·근거·다음 행동: Firebase·APNs 푸시 연결.

이 기능의 출시 완료 기준

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 첫 출시 포함 여부와 구현·검사 현황은 위 상태표를 따릅니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 현재 로그인 사용자의 기기가 등록·갱신되고 실제 푸시를 받는다.
  • 로그아웃·계정 교체·토큰 변경/만료·여러 기기·재설치에서 다른 사람에게 알림이 가지 않는다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 알림의 관련 완료 기준도 함께 확인합니다.
