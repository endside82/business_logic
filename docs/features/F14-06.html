F14-06. 주소 ↔ 좌표 변환 (지오코딩)

위·경도 좌표를 한국식 주소로 바꾸고, 주소 문자열을 저장 가능한 좌표로 확정하는 양방향 보조 인프라. 본 단위에는 전용 화면이 없다. 현재 Flutter에서 좌표→주소는 온보딩의 현재 GPS 위치 한 곳, 주소→좌표는 온보딩·프로필 주소 폼·이벤트 생성·편집에서 호출한다.

설계 의도 — 사용자는 좌표가 아니라 주소로 위치를 이해한다

지도에서 핀을 옮기거나 현재 위치를 잡으면 결과로 받는 것은 위·경도 숫자다. 그러나 사용자가 "여기가 어디인가"를 인지하려면 "강남구 역삼동" 같은 한국식 주소가 필요하다. 본 단위는 그 변환을 빠르게 처리해 다른 화면이 사용자에게 의미 있는 라벨을 보여줄 수 있게 한다. 같은 좌표가 반복 호출되어도 외부 변환 서비스 비용을 늘리지 않도록 변환 결과는 24시간 동안 캐시된다.

2026-07-29 현재 소스 갱신 — 일정변경 좌표 동기화와 운영 키 경고

현재 서버는 좌표→주소뿐 아니라 `GET /api/v1/location/geocode?address=...`로 주소→좌표도 제공한다. Flutter 이벤트 생성·편집·일정변경은 주소 변경 시 좌표를 먼저 확정하고 실패하면 저장을 막는다. 운영에서 Kakao 키가 비면 서버는 경고 후 기동을 계속하지만 주소↔좌표 호출은 실패한다. 기존 문서의 지도 핀·long-press·길찾기 reverse-geocode 설명은 현재 호출부와 일치하지 않아 제거했다.

본 변환이 호출되는 자리

본 단위 자체에는 화면이 없다. 다른 화면이 사용자에게 위치를 보여줄 때 본 변환이 보조로 호출된다.

온보딩 위치

현재 GPS 위치를 주소로 표시

사용자가 위치 권한을 허용하고 현재 위치를 불러오면 좌표→주소를 호출해 선택 위치에 반영한다. 현재 소스에서 확인되는 reverse-geocode 화면 호출자는 이 한 곳이다.

온보딩·프로필 주소

검색 주소를 좌표로 확정

온보딩과 프로필 주소 폼은 사용자가 검색 결과를 고르면 주소→좌표를 호출한다. 프로필 주소 화면은 reverse geocode가 아니라 이 forward-geocode 흐름을 사용한다.

이벤트 생성·편집·일정변경

장소 주소와 좌표를 함께 저장

주소가 바뀌면 저장 전에 주소→좌표를 호출한다. 실패하면 저장을 막고, 성공하면 일정변경 요청의 `newLatitude/newLongitude`까지 함께 보내 AUTO 반영과 MAJOR 제안 적용에서 주소·좌표가 어긋나지 않게 한다.

현재 연결되지 않은 흐름

길찾기는 서버의 이벤트 주소·좌표를 그대로 사용한다. 지도 핀 이동, 지도 long-press, 이벤트 핀을 좌표→주소로 바꾸는 Flutter 호출부도 현재 없다. 이 동작들은 구현 사실이 아니라 후속 후보로 취급해야 한다.

운영자가 알아야 할 것

변환 정책과 외부 의존
  • 변환은 외부 지도 서비스(카카오 로컬)를 호출한다. 외부 서비스가 일시적으로 응답하지 않으면 본 변환도 같이 멈춘다. 다른 화면은 이 경우 "주소를 찾을 수 없습니다" 같은 안내로 좌표 숫자를 그대로 노출하거나 사용자에게 직접 입력을 유도해야 한다.
  • 같은 좌표는 24시간 동안 캐시된다. 같은 위치를 여러 사용자가 반복 조회해도 외부 서비스 호출은 한 번만 일어난다. 자주 보이는 주소(많이 등록되는 모임 장소 등)는 변환 비용이 거의 들지 않는다.
  • 바다·산속·미등록 지역의 좌표는 변환되지 않는다. "주소를 찾을 수 없습니다" 안내가 호출 화면에서 노출되어 사용자가 다른 위치를 선택하도록 유도한다.
  • 외부 지도 서비스 인증 키 설정이 끊기면 본 변환 전체가 멈춘다. 프로덕션 기동 시 `SecurityConfigValidator`가 경고하지만 fail-fast 하지는 않는다. 주소 등록·이벤트 장소 등록·일정변경이 런타임에 막히므로 키 경고를 즉시 대응해야 한다.
