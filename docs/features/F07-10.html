F07-10 정산 계좌·내 정산·호스트 평판

계좌 소액 확인의 한계, 개인 합계·기간·원본 이동, 모임별 목록과 평판 공개 조건을 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

본인 정산 계좌 관리, 실제로 주고받을 돈의 개인 목록, 정산 작성자의 평판을 다룬다. 전체 메뉴의 「정산 계좌」와 「내 정산」이 각 화면으로 이어지고, 지갑의 「내 정산」도 같은 개인 목록을 연다. 개인 목록의 「모임별 보기」는 정산 단위 목록으로 이어진다. 평판은 이벤트 호스트 카드의 표시용 배지이며 별도 평판 상세 창이 없다.

계좌 소액 확인은 해당 계좌의 입금 내역을 확인할 수 있음을 증명하는 절차다. 예금주 이름을 법적 실명과 대조하는 절차로 설명하지 않는다. 실제 공급자 연결과 실계좌 확인은 별도 미완료 범위다.

본인 계좌 등록·변경·삭제

은행·계좌번호·예금주가 모두 있어야 등록한다. 첫 계좌만 자동 기본 지정하며, 동일한 세 값을 다시 등록하면 기존 계좌를 돌려준다. 기본 계좌를 삭제해도 다른 계좌를 자동 승격하지 않는다. 기본 지정은 본인의 계좌 집합에서만 수행한다.

등록은 요청 열쇠를 사용한다. 같은 요청의 재생은 보관한 계좌 번호로 현재 계좌와 현재 허용 행동을 다시 읽으므로, 최초 응답의 과거 기본 표시나 인증 상태를 그대로 돌려주는 계약이 아니다. 그 계좌가 삭제되면 재생도 찾을 수 없음으로 끝날 수 있다. 없는 계좌와 남의 계좌를 구분해 노출하지 않는다.

이벤트 선입금 설정·결제 기록, 정기모임·회원·결제 기록이 참조하는 계좌는 은행·번호·예금주 변경과 삭제를 제한한다. 종료된 모임이라고 참조가 자동 해제되는 조건은 없다. 계좌 응답의 현재 허용 행동에 따라 수정·삭제 입구를 보이며, 서버도 같은 제약을 적용한다. 정체 값이 실제로 바뀌면 기존 인증이 해제된다. 등록·수정·기본 지정·인증에는 탈퇴 완료 여부 확인이 있다.

앱은 등록·수정 결과를 기다린 뒤 성공한 경우 창을 닫고 목록을 바꾼다. 같은 등록 창에서 같은 입력으로 재시도하면 요청 열쇠를 재사용하고, 실패 시 입력을 유지한다. 다른 위치에서 먼저 등록된 충돌은 목록 재조회와 재입력 안내를 제공한다. 이를 앱 종료 뒤 복구되는 영구 입력 보존으로 설명하지 않는다.

계좌 소액 확인과 운영 조건

미확인·확인 중·확인됨·실패 상태를 구분한다. 인증 시작 뒤 안내된 네 자리 숫자를 입력한다. 기본 유효시간은 10분, 기본 확인 시도 상한은 5회이며 설정으로 바꿀 수 있다. 시작 요청은 직전 요청 후 60초 제한과 계좌별 24시간 창의 5회 상한을 적용한다. 아직 유효한 인증을 다시 시작해도 이미 쓴 확인 횟수는 회복하지 않는다.

코드 불일치 횟수는 실패 응답에도 저장한다. 만료·시도 소진·유효한 진행 건 없음은 다시 시작이 필요한 종료 조건이다. 앱은 만료 시 제출을 막고, 종료 오류를 받으면 해당 창에서 추가 제출을 막는다. 성공하면 계좌의 확인 상태를 갱신한다.

외부 공급자 오류나 뒤늦은 응답이 다른 인증 시도를 완료 처리하지 않도록 시도 식별자를 대조한다. 운영 프로필은 실제 공급자 준비 상태가 아니면 시작 자체를 거절한다. 개발용 가짜 공급자는 돈을 보내지 않으며 비운영에서만 개발 코드를 돌려줄 수 있다.

확인 계좌만 모임 수납에 연결할지에 관한 저장소 설정 기본값은 개발에서 켜짐, 운영에서 꺼짐이다. 이는 현재 운영 환경변수를 직접 확인한 결과가 아니다. 미확인 계좌를 허용한 직접 송금과 소액 확인 공급자 도입은 별도로 관리한다. 실제 공급자 준비·연결·실계좌 확인 조건은 결제·정산 공통 정책을 따른다.

기본 계좌 공개와 직접 송금

본인의 계좌 관리 목록을 다른 회원에게 공개하지 않는다. 미완료 분담·송금의 당사자에게 수취 계좌를 보여 주는 판단은 해당 원본 거래에서 수행한다. 계좌 조회·복사와 「보냈어요」는 은행 입금을 확인한 결과가 아니다. 완료·취소·수취인 계정 상태와 실제 당사자 조건은 분담금 납부와 직접 송금의 검토된 근거를 재사용한다.

출금 계좌와 외부 지급의 경계

플랫폼 출금 신청 당시의 송금처 보존과 결과 불명 지급 복구는 계좌 관리 화면의 성공 여부로 증명하지 않는다. 이 문서의 등록·인증 검토를 실지급 완료로 확장하지 않는다. 별도 계약과 후속 확인은 결제·정산 공통 정책, 수익 대시보드의 확인 범위를 함께 따른다.

내 정산의 대상·합계·기간

상단은 전체 기간의 확인 전 보낼 돈과 받을 돈을 따로 보여준다. 아래 세 탭은 「보낼 돈」「받을 돈」「지난 내역」이며, 취소·환불·기록 불명 등의 추가 확인 목록은 별도로 펼친다. 실제 지급자·수취인인 분담금과 송금만 본인 목록에 포함한다. 작성자가 관리만 하는 타인 간 돈과 준비 중 정산은 본인의 확정 채권·채무 합계에 넣지 않는다.

보낼 돈·받을 돈은 전체 기간으로, 지난 내역은 이번 달로 시작한다. 목록마다 전체·월·직접 기간 조건을 유지하며 지난 내역에서만 보낸 방향·받은 방향을 고른다. 직접 기간은 종료일을 포함해 최대 12개월 범위다. 대기 내역은 정산 요청일, 없으면 생성일을 사용하고 지난 내역은 확인·기록일을 사용한다.

검색 건수와 방향별 금액은 읽어 온 페이지의 합이 아니라 해당 조건 전체의 합계다. 목록은 최대 1,000건까지만 읽고 초과하면 기간을 좁히도록 안내한다. 기간 밖의 확인 전 내역도 별도 건수로 알린다. 원본 종류와 번호가 같은 페이지 중복은 제거한다.

혼합 납부의 대기 금액은 확인되지 않은 은행 부분이다. 지난 내역의 건수에 취소·면제 등이 포함되더라도 금액 합계에는 정상 확인 완료만 넣는다. 불명 금액은 0원으로 바꾸지 않고 제외 사실을 표시한다. 취소 후 은행 환불 미확인·환불 대기·송금 만료 등은 추가 확인 대상으로 구분한다.

개인 목록의 상세·갱신·복귀

개인 상세의 신고 철회·반환 완료 표시는 서버가 내려주는 canWithdrawSent·canMarkReturned 및 각 행동의 오류 번호를 따른다. 취소 후에도 대기 이의가 있는 새 철회를 허용하지 않으며, 목록의 상태만으로 상세 행동 권한을 만들어내지 않는다.

분담·송금 카드는 원본 종류와 번호로 상세를 연다. 취소된 과거 정산의 카드를 같은 이벤트의 새 정산으로 보내지 않는다. 상세의 확인·반환·신고 권한과 결과 불명 복구는 현황·요약·원본 상세, 입금 확인과 송금 관리의 근거를 따른다.

당겨 새로고침은 전체 요약과 현재 목록을 다시 읽는다. 같은 계정·같은 조건의 갱신 실패는 이전 자료와 실패 안내를 함께 보이고, 조건이나 계정이 바뀌면 이전 결과를 재사용하지 않는다. 늦은 이전 응답이 현재 목록에 합쳐지지 않도록 구분한다. 다음 페이지 실패는 기존 행과 재시도 입구를 남긴다. 탭·필터와 스크롤 보관은 계정 범위를 구분한다.

모임별 목록과 이전 이력 API

「모임별 보기」는 작성한 정산, 송금 당사자인 정산, 분담금이나 항목 보유자로 연결된 정산을 페이지로 조회한다. 준비 중·진행 중·완료·취소 필터가 있다. 이름이 「전체」인 기본 조회는 서버에서 취소를 제외하며, 취소 내역은 취소 필터로 찾는다. 취소 카드는 현재 눌러서 정산 화면으로 가지 않는다. 다른 카드는 이벤트의 정산 화면으로 이동한다. 준비 중 자료는 비작성자의 세부 정보 마스킹을 유지한다.

이전 참여 이력과 월별 요약 API도 남아 있지만 현재 「내 정산」의 자료원이 아니다. 이전 월별 요약의 기본 6개월·최대 24개월과 정산 생성월 집계를 현재 화면의 기간 조건으로 소개하지 않는다. 현재 개인 목록은 내용·검색 합계·페이지 정보를 함께 담는 전용 응답이고, 모임별 목록은 페이지 응답이다.

호스트 평판의 집계와 표시

평판은 정산 작성자를 기준으로 집계한다. 전체 건수에는 준비 중도 들어가고, 진행 중 건수만 진행 상태를 센다. 완료율은 완료 건수/전체 건수다. 평균 완료시간은 완료 정산의 생성 시각부터 마지막 갱신 시각까지의 시간을 이용하므로 은행 입금 시간을 직접 측정한 값이 아니다. 이의 건수는 상태와 무관한 이의 전체이며 이의율은 정산당 이의 건수 비율이라 100%를 넘을 수 있다. 별도의 취소율 응답을 제공한다고 쓰지 않는다.

타인의 평판은 양방향 차단과 낯선 사람 공개 제한을 적용한다. 모든 회원에게 항상 공개된다고 설명하지 않는다. 총 정산이 0건이거나 로딩·조회 실패이면 배지를 숨긴다. 완료율 90% 이상이면서 3건 이상이면 「정산 신뢰 호스트」, 그 외 70% 이상이면 「정산 활발」, 나머지는 「정산 -」로 표시한다. 이벤트 호스트 카드의 축약 배지는 상세 창을 열지 않는다.

현재 제한과 확인 범위

분류확인한 차이·한계영향·후속
Gap인증 창의 「남은 입력 횟수」는 시작 응답 값을 고정 표시하고 오입력 후 줄이지 않음서버 상한은 적용되지만 표시와 실제 남은 기회가 어긋날 수 있어 후속 화면 보완 필요
미검증실제 소액 확인 공급자·운영 환경변수·실계좌 송금과 코드 확인개발 가짜 공급자와 내부 시험을 실제 은행 인증 완료로 표시하지 않음
미검증현재 배포본에서 계정 변경·복귀·기간 전환·은행 인증의 실제 이용이번에는 소스와 아래 기존 단언을 대조했으며 새 제품 실행 결과가 아님

수용 기준과 검증 근거

  • AC-01 계좌 등록: 필수 세 값이 있고 첫 계좌이면 기본 지정하며, 같은 계좌를 중복 생성하지 않는다.
  • AC-02 등록 재생: 같은 요청 열쇠는 현재 보유 계좌를 다시 읽으며 삭제된 계좌의 최초 성공 응답을 재현한다고 약속하지 않는다.
  • AC-03 기본 지정과 삭제: 본인 계좌만 지정하며 기본 계좌 삭제 뒤 다른 계좌를 자동 승격하지 않는다.
  • AC-04 수납 참조 보호: 참조 중 계좌의 정체 변경·삭제를 막고 현재 허용된 수정·삭제만 화면에 제공한다.
  • AC-05 입력과 실패: 등록·수정 성공을 기다려 창을 닫으며 같은 등록 입력 재시도와 실패 입력 보존의 범위를 유지한다.
  • AC-06 인증 의미: 소액 확인을 계좌 제어 확인으로 설명하고 예금주 실명 대조나 실입금 완료로 확대하지 않는다.
  • AC-07 인증 제한: 기본 10분·5회, 시작 60초·24시간 5회와 실패 횟수 저장·유효 창 재시작 시 횟수 유지를 적용한다.
  • AC-08 운영 공급자: 운영의 가짜 공급자는 시작을 거절하고 비운영 개발 코드·실제 공급자 도입을 구분한다.
  • AC-09 인증 결과: 성공은 계좌 상태를 갱신하고 만료·소진 등 종료 오류는 추가 제출을 막는다. 남은 횟수 고정 표시는 후속 결함으로 남긴다.
  • AC-10 본인 합계: 본인이 주고받는 확정 대상만 방향별로 합산하며 전체 요약과 선택 기간 합계를 구분한다.
  • AC-11 기간과 날짜: 보낼·받을 돈은 전체, 지난 내역은 이번 달로 시작하고 요청일과 확인·기록일 기준을 구분한다.
  • AC-12 검색 결과: 최대 1,000건의 표시 제한과 전체 검색 합계를 구분하고 불명 금액·기간 밖 대기 건수를 안내한다.
  • AC-13 취소와 혼합 납부: 남은 은행 부분과 정상 완료 금액을 구분하며 취소·면제 건수를 정상 금액 합계에 넣지 않는다.
  • AC-14 원본 이동: 개인 카드는 원본 분담·송금 상세를 열고, 모임별 목록의 취소 카드는 새 정산으로 이동시키지 않는다.
  • AC-15 목록 복구: 같은 조건 실패만 이전 결과를 보존하고 계정·조건 변경과 늦은 응답·페이지 중복을 구분한다.
  • AC-16 이전 API: 이전 6·24개월 월별 API가 현재 내 정산 화면의 기간 기능이라고 소개하지 않는다.
  • AC-17 평판 집계: 준비 중을 전체 분모에 포함하고 진행 중 건수에서는 제외하며 이의율과 완료율의 의미를 구분한다.
  • AC-18 평판 노출: 차단·비공개·0건·조회 실패를 반영하고 임계값별 표시용 배지를 제공한다.
