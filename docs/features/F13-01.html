F13-01. 내·타인 프로필과 작성 글

허브·상세의 메뉴, 성향·만난 사람, 받은 후기·작성 글·계정별 복귀를 구분한다. 2026-11-22 소스 대조를 반영했으며 실제 앱 실행과 구분합니다.

결론

마이는 내 프로필·활동을 확인하고 다음 화면으로 이동하는 허브다. 현재 구성은 삭제 진행 배너, 사진·닉네임·신뢰점수 카드, 내 이벤트·내 일정·찜한 이벤트·지갑 바로가기, 받은 일정 변경 요청, 참석 예정 이벤트 미리보기다. 예전 지갑 잔액·내 클럽 수 등을 보여 주던 2×2 요약 카드 설명은 현재 화면과 다르다.

프로필 카드의 메뉴와 전체 메뉴는 역할이 다르다. 프로필 편집·선호 태그·성향 검사·취향 프로필·주소는 카드에서 열고, 설정·고객센터·운영 도구 등 전체 기능은 공통 전체 메뉴에서 찾는다. 로그아웃도 설정의 계정 묶음에 있다.

실제 입구와 메뉴의 역할

실제 입구현재 동작
하단 ‘마이’인증 상태에 저장된 본인 정보로 허브를 표시함. 정보가 준비되지 않았으면 로딩 표시
상단 검색·알림·전체 메뉴각각 공통 화면으로 이동함. 설정 톱니나 이 화면 전용 케밥 메뉴가 아님
사진·닉네임 카드프로필 편집·선호 태그·조건부 성향 검사·취향 프로필·주소 관리의 아래 메뉴를 엶
카드 안 신뢰점수프로필 메뉴 대신 신뢰점수 화면으로 바로 이동함. 값이 없을 때도 이름은 표시함
바로가기 네 개내 이벤트 → 내 일정 → 찜한 이벤트 → 지갑 순서. 공통 메뉴 정의와 같은 목적지를 사용함
삭제 진행 배너 관리데이터 프라이버시 화면에서 현재 예약·취소 가능 여부를 확인함
받은 일정 변경 요청현재 답할 수 있는 요청의 제한된 집계를 보고 받은 요청 목록으로 이동함

프로필 메뉴에서 항목을 고르면 메뉴를 먼저 닫고 목적지로 이동한다. 메뉴 바깥을 눌러 닫는 것은 저장·삭제가 아니다. 하위 화면의 뒤로 가기는 이 진입 경로에 맞게 돌아오며 편집 중 이탈은 각 편집 화면의 확인을 따른다.

정보·상태·미리보기 규칙

  • 본인 프로필은 앱 시작·로그인·명시적 갱신 때 받은 인증 상태의 표시 정보를 사용한다. 허브를 열 때마다 모든 프로필·지갑·클럽 정보를 한 서버 응답으로 다시 읽는 구조가 아니다.
  • 현재 카드에는 닉네임·사진과 신뢰점수가 표시된다. 자기소개 두 줄이나 지갑 잔액·클럽 수를 이 카드의 현재 구성으로 설명하지 않는다. 프로필 편집 성공은 같은 계정의 표시 필드를 갱신한다.
  • 참석 예정은 승인 또는 결제 대기 승인된 신청 가운데 시작 전이고 이벤트 상태가 초안·공개인 항목을 가까운 순서로 최대 3건 고른다. 미리보기 노출이 결제 완료나 참석 확정을 새로 증명하지 않는다.
  • 일정 변경 요청 집계는 응답 가능한 항목만 센다. 20개씩 최대 5쪽을 읽고, 더 있으면 확인한 수에 ‘+’를 붙이며 20개를 채우면 ‘20+’로 제한한다. 전체 건수를 보장하는 숫자가 아니다.
  • 삭제 배너는 대기·승인에서 보인다. 승인에서는 취소할 수 없고 제재·의무에 따라 파기가 지연될 수 있다는 현재 차이는 계정 삭제 요청과 취소를 함께 따른다.
  • 최초 조회에서 신뢰점수·성향 입구·일정 변경 요청·예정 미리보기의 값이 없으면 일부는 숫자나 영역을 숨긴다. 실패로 숨겨진 것과 실제로 자료가 없는 것을 같게 판단하지 않는다.

성향 검사와 리포트

성향 입구는 활성 문항이 있거나 본인 점수가 있을 때 표시한다. 활성 문항 조회가 실패하면 입구를 숨기며, 이 경우 기존 점수 조회까지 이어가지 않는다. 메뉴에서 리포트를 열고 점수가 없으면 검사 시작, 점수가 있으면 결과·다시 검사를 제공한다.

앱은 표시 가능한 문항을 모두 답해야 제출할 수 있다. 지원하지 않는 형식은 안내하고 건너뛰며, 답할 수 있는 문항이 하나도 없으면 앱 업데이트 안내를 보인다. 문항·세션 조회 실패는 다시 시도, 제출 실패는 오류 안내와 현재 답변을 유지한다. 답변은 화면 메모리에 있으며 앱 종료 후 이어 쓰기를 보장하지 않는다.

서버는 검사 시작 때의 문항 식별자 목록, 세션 소유권, 중복 문항, 답변 범위를 검사한다. 척도형은 1~5, 양자택일은 0/1이며 부분 제출은 서버가 허용한다. 축별 답변이 2개 이상일 때 0~100으로 환산한 평균을 계산한다. 같은 세션·같은 요청 식별자로 재제출하면 기존 결과를 돌려주고, 완료 뒤 다른 식별자는 중복으로 거절한다. 현재 앱은 같은 화면의 재시도에 같은 식별자를 사용한다.

성공하면 리포트로 돌아가 새 결과를 읽는다. 결과가 있을 때 제공하는 공유 입구와 타인 점수의 자동 공개는 구분한다. 본인 축점수를 타인이 직접 조회하는 창구를 이 기능에 가정하지 않는다.

만난 사람과 공용 사람 카드

‘만난 사람’의 현재 입구는 전체 메뉴 → 활동이다. 마이 본문 메뉴 줄이나 프로필 카드 아래 메뉴에 있다고 설명하지 않는다. 목록은 사람별로 접어 최근 만남 시각 내림차순·같은 시각은 사용자 번호 순으로 표시하고 20개씩 이어 읽는다. 항목을 누르면 공용 사람 카드를 연다.

서버는 매 조회마다 양방향 차단·검색 숨김·활동 가능한 계정 상태를 반영한다. 앱에서 차단에 성공하면 현재 만난 사람 목록에서 해당 행을 먼저 뺀 뒤 첫 쪽부터 다시 조회한다. 재조회 중에는 예전 쪽 번호로 추가 조회하지 않으며, 차단 해제한 사람은 새 조회 결과로 돌아온다. 체크인이 있는 모임은 두 사람의 체크인, 체크인이 전혀 없는 모임은 두 사람의 참석 상태와 노쇼 제외를 근거로 삼는다. 후자의 조회에는 모임 종료 시각 조건이 없어, 항상 ‘끝난 만남만’ 모은 불변 기록이라고 설명할 수 없다.

추가 조회의 통신 오류는 기존 목록과 다시 시도를 유지한다. 권한·인증·찾을 수 없음 오류에서는 이전 목록을 비우고 오류로 전환한다. 사람 카드의 상세 공개는 본인·같은 클럽·확인된 모임 관계와 차단·대상 상태를 따르며, 데이팅 매칭을 커뮤니티 상세 공개 근거로 사용하지 않는다. 공통 관심사 공개 범위는 관심사 태그 기능을 따른다. 메시지 전송 자격은 카드의 현재 서버 판정과 별도 연락 정책을 적용한다.

내 프로필과 다른 사람의 프로필

사람 카드에서 여는 상세 프로필과 하단 마이 허브는 서로 다른 화면이다. 상세에서 본인에게는 프로필 편집·공개 설정을 제공하며 자기 관심인·메시지·신고·차단 행동은 표시하지 않는다. 타인에게는 현재 권한에 따른 관심인·관계 정보와 상단 더보기의 신고·차단을 제공한다. 상세를 볼 수 없는 관계에는 사진·닉네임과 제한 안내만 표시한다. 마이 허브의 전체 메뉴와 타인 프로필의 안전 조치를 같은 메뉴로 설명하지 않는다.

상세의 받은 후기는 펼칠 때 조회하여 처음 3개를 표시한다. 3개를 넘으면 받은 후기 모두 보기로 별도 후기 목록을 열며, 각 후기에는 원 모임으로 가는 입구가 있다. 한 화면에서 이미 받은 나머지를 펼친다는 과거 설명은 현재 동작과 다르다. 서버 목록 조회도 본인 또는 현재 공개 가능한 대상·차단 없음·상세 열람 관계를 확인한다.

받은 후기 아래의 작성 글 보기는 조회자가 현재 가입한 클럽에서 대상이 작성한 게시 상태의 글을 모은다. 목록과 건수는 같은 조건을 쓰며 작성 시각·글 번호 내림차순으로 한 쪽 20개씩 읽는다. 예약·숨김·삭제 글과 비회원 클럽 글은 제외한다. 이 조회에는 클럽 상태 조건이 없으므로 클럽이 운영 중이라는 추가 보장은 하지 않는다. 대상이 작성 클럽을 떠났더라도 남은 글이 조건을 충족하면 보일 수 있다. 대상 계정·차단·상세 열람 관계를 먼저 검사하고, 타인이 가입 클럽을 숨겼으면 빈 목록이다.

글 제목을 누르면 해당 클럽 원문으로 이동한다. 돌아오면 펼침·쪽 상태를 유지하면서 다시 읽고, 재조회 중 이전 제목·건수를 숨긴다. 사라진 쪽은 첫 쪽을 다시 읽으며 조회 실패는 재시도로 안내한다. 프로필로 돌아올 때 열람 권한도 다시 읽는다. 출발점으로 돌아가는 동작은 중간에 등록된 초안을 버릴 때 확인하고, 계정 변경은 이전 탐색·초안 참조를 비운다. 실제 기기 제스처와 다른 기기의 변경 전파는 별도 검증 대상이다.

수용 기준과 검증 범위

  • AC-01 진입: 하단 마이에서 본인 카드·현재 네 바로가기와 보조 영역을 확인한다.
  • AC-02 상단 역할: 검색·알림·전체 메뉴가 각각의 목적지로 가고 설정·로그아웃은 현재 설정 경로에서 찾는다.
  • AC-03 프로필 메뉴: 카드에서 메뉴를 열고 선택 시 메뉴를 닫은 뒤 이동하며 신뢰점수는 별도로 열린다.
  • AC-04 계정 경계: 로그인 준비·제한·계정 교체에서 다른 계정의 정보와 편집 결과를 섞지 않는다.
  • AC-05 예정 목록: 승인·결제 대기·시작 시각·이벤트 상태를 구분해 최대 3건을 고르고 상세와 목록으로 이동한다.
  • AC-06 요청 집계: 응답 가능 여부·20개 상한·5쪽 중단·‘+’ 표시와 조회 실패를 구분한다.
  • AC-07 삭제 배너: 대기·승인·오류와 취소 가능 여부를 구분해 관리 화면으로 이동한다.
  • AC-08 성향 입구: 활성 문항·기존 점수·조회 실패·미지원 형식의 입구와 안내를 구분한다.
  • AC-09 성향 제출: 소유권·답변 범위·중복 문항·부분 응답·동일 키 재시도와 결과 화면 복귀를 확인한다.
  • AC-10 만난 사람: 전체 메뉴에서 진입하고 목록 정렬·차단·숨김·추가 조회 오류·현재 만남 판정을 확인한다.
  • AC-11 공개와 연락: 사람 카드의 상세 권한·데이팅 분리·연락 가능 판정을 목록 노출과 구분한다.
  • AC-12 상세 메뉴: 본인 편집·공개 설정과 타인 신고·차단을 구분하고 마이의 전체 메뉴와 섞지 않는다.
  • AC-13 받은 후기: 펼칠 때 조회·최초 3개·별도 전체 목록·원 모임 이동과 권한 오류를 구분한다.
  • AC-14 작성 글: 두 클럽의 21개 이상 글로 현재 회원 조건·목록과 건수·20개 쪽·최신순·빈 쪽 복구를 확인한다.
  • AC-15 복귀와 공개 변경: 글 원문 왕복·초안 확인·계정 변경·차단·탈퇴·클럽 숨김·글 숨김과 삭제에서 기존 정보를 재사용하지 않는다.
