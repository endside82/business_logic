F10-05 타 사용자 가능 시간 공개 기능 폐기와 비공개 경계

폐기된 공개·친구 가능 시간 조회를 복구 대상으로 두지 않는다. 본인 전용 모델·요청·권한과 관심인 공개 모임의 차이를 확인한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

현재 상태와 폐기된 기능

이 기능 ID는 폐기된 타 사용자 가능 시간 공개 조회의 추적 항목이다. 공개 슬롯·친구 슬롯·상호 후기 기반 친구 판정으로 다른 사람의 가능 시간을 읽는 기능은 현재 제품 계약이 아니다. 과거 시나리오를 실행해야 할 출시 필수 기능으로 복구하지 않는다.

소스 참조표의 옛 /api/v1/users/{userId}/availabilities/public·friends 두 행도 retired이고 연결 함수가 없다. 서비스·모델과 앱 API에 공개/친구 가용성 입력·조회가 없으며 저장 visibility 컬럼/enum의 호환 모델도 제거됐다. 새 공개 기능은 공유 동의·대상·회수 범위를 먼저 결정하는 별도 제품 작업이다.

현재 본인 전용 계약

생성은 로그인 principal을 소유자로 저장하고 목록은 같은 userId로 조회한다. 단건 읽기는 소유자를 검사하고 수정·삭제·반복 규칙 조회는 본인 ID 조합으로 판정한다. 클라이언트에서 타인 userId나 PUBLIC/FRIENDS를 선택해 요청하는 필드는 없다.

가능 시간은 본인 가능 시간 관리와 반복 가능 시간 관리에서 다룬다. 본인이 ICS 파일을 내보내는 동작은 사용자가 선택한 파일 전달이며, 타인에게 상시 조회 권한을 주는 API와 다르다.

관심인 달력과 구분

월 달력의 관심인 보기는 별도 공개 모임 자료를 합친다. 해당 카드가 모임 상세로 연결돼도 상대방의 개인 가능 시간·반복 규칙을 읽는 기능이 생기지 않는다. ownerUserId가 있는 모임 카드와 AVAILABILITY 레코드 소유권을 같은 공유 모델로 해석하지 않는다.

현재 제한과 확인 범위

구분현재 경계
기준기능 없음은 구현 누락이 아니라 폐기된 공개 정책의 현재 상태다. 기능 수와 활성 기능 수를 구분한다
미검증현재 소스·요청 모델·폐기 참조를 대조했다. 익명/타계정 실제 HTTP 보안 시험을 새로 실행한 기록은 아니다

수용 기준과 검증 근거

  • AC-01 폐기 상태: 공개/친구 조회를 현재 구현이나 남은 출시 과제로 표시하지 않는다.
  • AC-02 요청: 가용성 요청에 타인 소유자·공개 범위 입력을 추가하지 않는다.
  • AC-03 소유권: 현재 본인 목록·단건·수정·삭제·반복 규칙의 권한 경계를 유지한다.
  • AC-04 관심인: 관심인 공개 모임과 개인 가능 시간 공유를 구분한다.
  • AC-05 추적: 옛 두 API 참조를 retired로 보존하고 실제 실행 확인과 소스 확인을 구분한다.

위 항목은 비공개 경계의 문서 수용 기준이며 폐기된 기능의 실행 통과 수가 아니다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 폐기된 타인 가용시간 조회와 공개 설정을 고객 화면·직접 요청에서 사용하지 못한다.
  • 본인 가용시간은 비공개를 유지한다. 재도입은 공유 동의·대상·회수에 대한 새 제품 결정으로 별도 계획한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 캘린더의 관련 완료 기준도 함께 확인합니다.
