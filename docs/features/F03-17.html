F03-17. 차량 레이아웃 카탈로그

버스대절 기능에서 사용할 차량 좌석 구조 카탈로그. 사용자 read API와 관리자 생성·수정·좌석맵 교체·활성화 API가 구현되어 있지만 기본 차량 seed와 Flutter 소비 화면은 없다.

설계 의도 — 좌석표를 이벤트마다 새로 그리지 않는다

차량 좌석 구조는 반복해서 재사용되는 운영 자산이다. 카탈로그를 별도로 두면 28인승, 45인승 같은 표준 차량을 여러 이벤트에서 같은 방식으로 쓸 수 있고, 좌석 선택 가능 여부도 레이아웃 단위로 통제할 수 있다.

현재 운영 전제

빈 DB에는 28·45·20·8인승 기본 row가 없다. 관리자가 레이아웃을 생성하고 좌석맵을 등록한 뒤 활성화해야 사용자 active 목록에 나타난다. 단 create body가 active=true를 허용해 좌석맵 없이 즉시 활성 row를 만들 수도 있다. seatType은 enum이 아니라 6개 허용 문자열이다.

사용자 시나리오

기본 조회

초기 active 목록이 비어 있음

기본 seed가 없으므로 운영자가 등록·활성화하지 않은 DB에서는 active 목록이 빈 배열이다.

좌석 그림

레이아웃 좌석 배치 조회

레이아웃을 고르면 좌석의 행·열 위치, 좌석 종류, 선택 가능 여부를 받아 좌석표를 그린다.

비활성

운영자가 비활성화한 레이아웃

비활성으로 표시된 레이아웃은 활성 목록에 보이지 않는다. 기존 이벤트가 이미 참조한 좌석표는 그 이벤트의 좌석으로 그대로 남는다.

권한

비인증 조회 차단

차량 카탈로그는 이벤트 운영 도구의 일부이므로 로그인이 필요하다. 로그인하지 않은 채 조회하면 거절된다.

API가 제공하는 것

동작누가무엇이 일어나는가
활성 차량 목록인증 사용자JSON boolean key는 active. Flutter 호출부는 없다.
좌석 배치인증 사용자JSON boolean key는 selectable. inactive ID도 조회되고 없는 ID는 빈 목록이다.
레이아웃·좌석 운영MANAGE_EVENT 관리자생성·메타 수정·좌석 전체 교체·active 토글. DELETE는 없다.

운영자가 알아야 할 것

관리자 CRUD는 구현됐고 기본 데이터는 없다
  • 관리자 API는 현재 구현돼 있다. `MANAGE_EVENT` 권한으로 목록·상세·생성·수정·좌석 전체 교체·활성 토글을 수행한다.
  • 기본 시드는 없다. 운영 초기화 절차에서 직접 등록해야 한다.
  • 레이아웃은 원본이고 이벤트 좌석은 복사본이다. 레이아웃이 바뀌어도 이미 생성된 이벤트 좌석표를 소급 변경하지 않는다.
  • seatType은 String whitelist다. NORMAL·DRIVER·GUIDE·FOLDABLE·DISABLED·AISLE만 허용한다.
