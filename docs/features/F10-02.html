F10-02 달력 항목과 상세 연결

월 카드·일간 블록의 같은 이동 조건, 잘못된 식별자, 비이동 항목, 편집 후 갱신과 복귀를 연결한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

월·일 화면의 실제 이동

월 날짜를 누르면 선택 날짜를 유지한 채 일간 화면을 연다. 월 선택일 카드와 일간 블록은 같은 itemType/referenceId 조건으로 상세를 연다. 달력을 날짜 선택용 예시 맵으로 대체하지 않고 실제 화면 호출을 기준으로 한다.

항목별 목적지와 권한

항목목적지·조건
HOSTING·ATTENDINGreferenceId가 있으면 /home/events/{id}. 주최/참석마다 별도 가짜 상세 주소를 만들지 않는다
AVAILABILITYreferenceId가 있으면 /profile/calendar/availability?id={id}의 본인 편집
HOSTING_PRIVATE·미지원 종류현재 두 화면 모두 상세 이동 없음
referenceId 없음이동 없음, 열기 표시도 없음

이동하는 카드/블록에만 열기 표시를 제공한다. 관심인 카드도 지원 종류·ID가 있으면 같은 모임 상세로 간다. 도착 화면과 서버가 실제 권한을 다시 판정하므로 ATTENDING 라우트 자체가 참가·수정 권한을 부여하지 않는다. 비공개 만남이 표시된다는 사실과 만남 상세 연결 구현 여부를 구분한다.

신규·편집·반복과 복귀

일간 추가는 선택 날짜를 date query로 전달한다. id가 없으면 신규, 숫자 id면 본인 단일 기록 편집이다. 반복 생성으로 만들어진 기록은 recurrenceRuleId가 있으면 별도 반복 규칙 편집으로 연결한다. 반복 목록과 새 규칙·기존 규칙 편집도 별도 입구다.

라우터는 id/ruleId에 int.tryParse를 쓰므로 잘못된 숫자는 null이 되어 신규 화면으로 해석될 수 있다. date 누락은 기본 오늘을 쓰지만 잘못된 날짜 문자열의 완전한 복구를 보장하지 않는다. 정상 화면의 전달 값과 직접 잘못 만든 URL을 같은 검증 완료 상태로 세지 않는다.

뒤로 돌아가면 유지된 월 선택 상태를 이어 사용한다. 가능 시간·반복 규칙 명령은 calendarChanged를 보내 월·일 자료를 갱신한다. 삭제 확인만 하고 deleted=false인 경우에는 변경 신호를 보내지 않는다. 서버 반영 가능 오류는 재조회 대상이지만 무조건 저장 성공으로 화면을 닫지 않는다.

현재 제한과 확인 범위

구분현재 경계
GapHOSTING_PRIVATE 상세 연결은 없다. 표시와 이동을 분리한다
Gap잘못된 id/ruleId가 신규 입력으로 해석될 수 있으며 날짜 query 오류 처리는 별도 확인 대상이다
미검증실제 화면 라우팅 코드와 기존 열기 표시·관심인 상세 이동 단언을 읽었다. 새 브라우저/기기 이동 시험은 하지 않았다

수용 기준과 검증 근거

  • AC-01 월→일: 날짜 키와 선택 상태를 유지해 일간 화면을 연다.
  • AC-02 모임: HOSTING/ATTENDING은 같은 모임 상세를 열고 목적지 권한을 따른다.
  • AC-03 가능 시간: 기록 ID를 편집으로, 새 날짜를 신규 입력으로 전달한다.
  • AC-04 비이동: ID 없음·비지원 종류에는 열기 표시와 이동이 없다. 기존 월·일 단언을 읽었다.
  • AC-05 관심인: 지원하는 관심인 모임 카드는 모임 상세로 연결한다. 실제 라우트 결과 단언을 읽었다.
  • AC-06 복귀: 저장/삭제 성공과 deleted=false 확인을 구별해 갱신한다. 전체 성공을 라우트 이동만으로 판정하지 않는다.

위 항목은 문서 수용 기준이며 새 시험 통과 수가 아니다.
