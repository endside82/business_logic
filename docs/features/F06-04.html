F06-04. 결제 수단 관리

충전(F06-02)과 자동 충전(F06-05)에 쓰이는 카드를 등록·삭제·기본 설정하는 자리. 기본으로 정한 카드 한 장은 충전 화면에서 이미 선택된 채로 떠올라, 사용자가 매번 카드를 다시 고르지 않게 한다. 최대 다섯 장까지 등록할 수 있고, 한 장을 기본으로 둔다. 카드 번호를 이 화면에 직접 적지 않는다 — 결제사의 카드 인증 창을 거쳐, 그 창이 돌려준 일회용 확인값을 서버가 결제사에서 "저장 카드"로 바꿔 받는 세 단계 절차다. 본 화면은 결제를 일으키지 않는다 — 등록한 카드는 다음 충전 시점에 처음으로 쓰인다.

5장

플랫폼 실결제 미출시 — 등록한 카드 조회·삭제는 열림
2026-09-12 현재 — 신규 카드 등록은 닫혀 있고 조회·삭제는 열려 있다

플랫폼 실결제가 아직 열리지 않아 서버가 카드 인증을 시작하는 단계부터 거절한다. "카드 등록" 버튼은 화면에 그대로 있고, 누르면 막힌 이유·남은 작업·출시 조건을 적은 안내 화면이 열린다. 이미 등록해 둔 카드의 조회·기본 지정·삭제는 그대로 열려 있다 — 닫으면 사용자가 자기 결제 수단을 정리할 길이 사라진다.

설계 의도 — 충전 화면에서 카드를 고민하지 않게 한다

매 충전마다 카드를 다시 고르게 하면 충전 빈도가 떨어진다. 기본 카드 한 장을 미리 정해 두면 충전 화면이 그 카드를 이미 선택한 상태로 떠올라, 사용자는 금액만 정하고 결제 창으로 넘어간다. 여러 장을 둘 수 있는 이유는 카드 한 장이 만료되거나 한도 초과로 막혔을 때 다른 카드로 즉시 갈아탈 수 있게 하기 위해서다. 기본 카드를 지우면 남은 카드 중 하나가 자동으로 기본이 되도록 두어, 사용자가 "기본 카드가 없어 충전이 막히는" 경험을 하지 않게 한다.

사용자 시나리오

첫 등록

첫 결제수단을 추가한다

가입 직후 카드가 한 장도 없는 사용자. 하단의 "카드 등록"을 누르면 결제사의 카드 인증 창이 화면 안에 열리고, 사용자는 그 창에서 카드 정보를 입력한다. 인증이 끝나면 그 창이 일회용 확인값만 돌려주고, 서버가 그 값을 결제사에서 저장 카드로 바꿔 받는다. 목록에 보이는 카드사 이름과 뒷 네 자리는 사용자가 적은 값이 아니라 결제사가 돌려준 값이다. 등록을 마치면 첫 카드는 자동으로 기본으로 설정된다 — 기본 카드 지정을 사용자에게 별도로 묻지 않는다.

이 흐름이 남기는 것 — 사용자가 "기본 설정"이라는 추가 결정 없이 충전을 시작할 수 있게 한다.

두 번째 카드

새 카드를 추가하고 그것을 기본으로 바꾼다

기본 카드(A)를 가진 사용자가 새 카드(B)를 추가한다. B는 일단 기본이 아닌 상태로 들어온다. 사용자가 B의 메뉴 → "기본으로 설정"을 누르면 A의 기본 표시가 해제되고 B가 기본이 된다 — 기본은 항상 한 장만 존재.

이 흐름이 남기는 것 — 사용자가 충전에 자주 쓰는 카드를 명시적으로 결정할 수 있게 한다.

기본 카드 정리

만료된 기본 카드를 삭제 — 다른 카드가 자동 기본 승계

기본 카드(A)가 만료되어 정리하려는 사용자. A를 삭제하면 남은 카드(B 또는 C 중 하나)가 자동으로 기본이 된다. "기본 카드가 없는 상태"가 잠시도 생기지 않게 — 그 사이에 충전 시도가 들어와 막히는 사고를 막는다.

이 흐름이 남기는 것 — 사용자가 카드 정리 후 충전 화면에 들어왔을 때 별도로 기본 카드를 다시 정하지 않아도 된다.

한도

다섯 장이 채워진 상태에서 추가하려 함

이미 다섯 장이 등록된 사용자가 "카드 등록"을 누르면 "결제 수단은 최대 5개까지 등록할 수 있습니다" 안내가 뜨고 카드 인증 창이 열리지 않는다. 서버도 인증을 시작하는 단계에서 같은 이유로 거절해, 사용자가 카드 정보를 다 넣은 뒤에야 거절당하는 일이 흔한 경우에는 생기지 않는다.

이 흐름이 남기는 것 — 한도 판정의 최종 권한은 저장 직전에 있다. 같은 순간 다른 요청이 마지막 자리를 가져가면 인증을 마친 뒤에도 거절될 수 있는데, 그때 발급된 저장 카드는 저장하지 않으므로 청구에 쓰이지 않는다.

자동 충전 영향

자동 충전이 묶여 있던 카드를 지움

자동 충전(F06-05)이 카드 A에 묶여 있는데 A를 삭제한다. 결제수단 화면 자체는 정상적으로 삭제되지만, 다음 자동 충전 시점에 "카드를 찾을 수 없다"는 이유로 자동 충전이 동작하지 않는다. 사용자가 결제 시점에 잔액 부족을 인지하고 자동 충전 설정으로 돌아가 새 카드를 지정해 줘야 정상화된다.

이 흐름이 남기는 것 — 본 화면이 자동 충전 설정까지 연결되어 변경하지 않는다 — 사용자의 명시적 결정으로 자동 충전을 재설정하게 둔다.

마지막 카드

마지막 한 장을 지운다

한 장만 남은 카드를 사용자가 삭제한다. 결제수단 0장 상태가 되고, 다음 충전 시도에서 "결제수단을 등록해 주세요" 안내로 본 화면이 다시 떠오른다.

화면에서 사용자가 인지하는 것

영역사용자가 보는 것그 자리에 둔 이유
등록 개수 표기 "등록된 결제 수단 (N/5)" 카운터가 화면 상단에. 사용자가 한도까지 얼마나 남았는지 미리 안다. 다섯 장을 채운 뒤 등록을 누르면 한도 안내가 뜬다.
카드 항목 카드사 이름 + 뒷 네 자리를 뺀 나머지를 가린 번호 + 기본 배지(기본 카드 한 장) + 결제사가 사용 불가로 판정한 카드에는 "사용 불가 · 재등록 필요" 배지. 카드사와 뒷자리는 결제사가 돌려준 값이라 사용자가 자기 카드를 틀림없이 알아본다. 기본 배지는 충전 화면에서 어느 카드가 자동 선택될지를 미리 보여 주고, 사용 불가 배지는 자동 충전이 조용히 건너뛰는 카드를 사용자가 인지하게 한다.
카드 메뉴 각 카드에 점 세 개 메뉴 → "기본으로 설정" / "삭제". 액션 두 개를 메뉴에 넣어 카드 본체를 깔끔하게 유지. 삭제는 확인 다이얼로그를 거쳐 한 번 더 사용자 의사를 받는다.
빈 상태 카드 일러스트 + "등록된 결제 수단이 없습니다" 안내. 처음 진입한 사용자에게 "여기는 카드를 등록하는 자리"라는 사실을 즉시 인지하게.
추가 버튼 화면 하단에 항상 있는 "카드 등록". 누르면 결제사 카드 인증 창이 화면 안에 열리고, 등록이 닫혀 있는 동안에는 안내 화면으로 간다. 버튼을 숨기면 사용자가 "이 서비스는 카드를 못 쓴다"로 오해한다. 한도·봉인은 눌렀을 때 이유와 함께 알려 준다.

운영자가 알아야 할 것

결제수단 화면의 정책 결정점
  • 기본 카드는 항상 한 장이 존재해야 한다. 기본 카드가 없는 상태가 잠시라도 생기면, 그 사이에 들어온 충전 시도가 카드 선택 단계에서 막힌다. 자동 승계 동작이 깨지는 회귀가 들어가면 충전 전환이 즉시 떨어진다.
  • 결제수단 화면의 카드 삭제는 자동 충전 설정을 자동으로 변경하지 않는다. 사용자가 자동 충전에 묶인 카드를 지웠을 때, 그 사실을 본 화면에서 경고하지 않는다는 점은 운영팀이 알고 있어야 한다 — 사용자 신고("자동 충전이 안 됐다") 발생 시 카드 변경 이력과 자동 충전 설정의 카드 식별자를 함께 봐야 한다.
  • 최대 다섯 장 한도는 사용자 사고 방지용이다. 여러 장이 필요한 사용자가 거의 없다는 가정 아래의 보수적 한도. 비즈니스 카드 사용이 늘어나면 한도 상향을 검토.
  • 앱은 카드 번호를 받지도, 보내지도 않는다. 카드 정보는 결제사 인증 창에만 들어가고, 앱은 그 창이 돌려준 일회용 확인값만 서버로 보낸다. 서버는 그 값을 결제사에서 저장 카드로 바꿔 받고, 목록에 보이는 카드사·뒷자리도 결제사 응답을 그대로 쓴다. "카드 번호가 우리 쪽에 남아 있느냐"는 문의에는 남지 않는다고 답하면 된다.
  • 카드 별칭 칸은 현재 앱 화면에 없다. 서버는 별칭을 받을 수 있게 열어 두었지만 앱이 보내지 않아, 목록에는 카드사 이름으로만 구분된다. 같은 카드사 카드를 여러 장 가진 사용자는 뒷 네 자리로만 구분해야 한다.
  • 결제사가 저장 카드를 무효로 판정하면 그 카드에 "사용 불가" 표시가 붙는다. 자동 충전 실행이 그 카드를 건너뛰므로, "자동 충전이 안 됐다"는 신고에는 이 표시부터 확인한다.
