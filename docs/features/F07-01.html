F07-01. 모임 정산 생성

주최자가 첫 비용의 이름·금액·먼저 결제한 사람·함께 나눌 사람을 적어 정산을 시작합니다. 저장하면 작성 중인 초안과 비용이 생기며, 참가자에게 납부를 요청하지는 않습니다. 비용을 더 넣고 금액을 검토한 뒤 별도로 정산을 요청합니다. 초안 취소나 저장 결과 유실이 생기면 서버의 현재 상태를 확인하고 이어서 작성합니다.

자신이 만든 정산에서만 복사합니다

정산 복사 입구는 자신이 만든 원본에만 표시한다. 다른 사람이 만든 정산을 관리할 수 있다는 이유로 복사 소유권까지 부여하지 않는다. 원본을 다시 읽어 권한을 확인하고 복사본 생성의 중복 요청을 구분한다.

수입 항목과 취소 뒤 송금 확인

지출은 참가자가 먼저 결제한 사람에게 내고, 수입은 수입 보유자가 참가자에게 나눠 줍니다. 보유자의 자기 몫에는 송금이 없습니다. 계좌 보기·송금 신고는 실제 보내는 쪽에만 제공하며, 정산 취소 뒤에도 보냈지만 확인되지 않은 은행 송금은 확인 필요로 남습니다.

정산의 지출·수입과 취소 후 미확인 송금을 구분합니다에서 적용 조건과 예외를 확인합니다.

먼저 낸 돈과 각자 부담할 돈을 구분합니다

수아가 식사비 30,000원을 먼저 냈고 세 사람이 10,000원씩 나누는 경우, 결제자는 수아 한 명이고 분담자는 세 명입니다. 주최자와 결제자가 달라도 실제 결제한 사람을 선택합니다. 비용 작성부터 입금 확인까지의 실제 화면에서 이 예시를 볼 수 있습니다.

첫 비용을 저장하고 금액을 검토합니다

  1. 정산 방식을 고릅니다. 기본인 ‘항목별로 납부하기’는 각 비용을 먼저 결제한 사람에게 내 몫을 냅니다. ‘서로 주고받을 돈만 송금하기’는 선지급액과 부담금을 합쳐 필요한 차액 송금을 계산합니다.
  2. 첫 비용을 입력합니다. 비용명·금액·결제자·나눌 사람을 정하고 각자 부담할 금액을 미리 봅니다. 나누는 방식과 영수증 등은 추가 설정에서 고릅니다.
  3. ‘정산 초안 만들기’를 누릅니다. 비용 저장과 납부 요청이 별개임을 확인합니다. 초안 생성과 첫 비용 저장은 순서대로 처리하며, 첫 비용까지 저장되면 비용 목록으로 이동합니다.
  4. 비용을 추가하고 검토합니다. ‘금액 검토하기’에서 비용별 결제자와 각자의 선지급액·부담금을 확인합니다. 확인한 뒤 ‘정산 요청 보내기’를 실행해야 납부와 참가자 알림이 시작됩니다.

현재 초안이 있으면 그 정산의 방식을 유지합니다. 초안을 취소하고 다시 시작할 때는 현재 상태를 확인한 뒤 방식을 새로 고를 수 있습니다.

첫 비용 저장 결과를 확인하고 다시 작성하기

초안 생성과 비용 저장은 별도 단계입니다. 오류가 났다는 사실만으로 둘 다 실패했다고 판단하지 않습니다. 2026년 9월 26일 보완으로 작성 화면에 다시 들어올 때도 서버의 현재 정산을 확인합니다.

발생한 일앱의 처리와 다음 행동
초안은 생겼지만 첫 비용 저장이 거절됨초안과 입력을 남깁니다. 같은 초안이 계속 작성 중인지 확인한 뒤 입력을 고쳐 다시 저장합니다.
저장 응답을 받지 못함같은 비용을 자동으로 다시 보내지 않습니다. 현재 초안과 저장된 비용을 다시 조회해 결과를 확인합니다. 조회가 실패하면 결과 미확인 상태를 유지합니다.
생성 결과가 불명확했지만 서버에 초안이 없음입력한 비용을 보존하고 다시 저장할 수 있게 합니다. 뒤늦게 초안이 생겨 중복 요청이 거절되면 현재 정산을 다시 읽습니다.
작성하던 초안을 취소함다시 열 때 취소 사실을 안내하고 처음 작성 상태로 돌립니다. 아직 남아 있는 비용 입력은 보존하며 방식 선택·지난 정산 가져오기도 다시 사용할 수 있습니다.
취소 뒤 다른 정산이 생김다른 정산의 비용을 앞선 저장의 성공 근거로 쓰지 않습니다. 정산 현황에서 새 정산을 확인하도록 안내하며, 늦은 첫 비용 요청이 새 정산에 들어가는 것을 서버가 거부합니다.
현재 정산이 이미 요청됐거나 완료됨첫 비용 작성을 계속하지 않고 현재 정산을 확인하도록 안내합니다. 이미 저장한 비용을 새 비용처럼 다시 보내지 않습니다.

첫 비용 저장에는 원래 초안을 확인하는 보호를 적용했습니다. 과거 취소 내역은 원본 정산으로 조회하며 새 정산의 비용·납부 내역과 섞지 않습니다.

지난 정산에서 비용을 가져옵니다

작성 화면 아래의 지난 정산에서 비용 가져오기에서 이전 비용·분담 구조를 선택합니다. 이번 모임의 참여자를 확인하고 필요한 금액을 고칩니다. 지난 납부 완료 상태를 이번 모임의 입금으로 사용하지 않습니다. 이미 초안을 만들었거나 저장 결과를 확인 중일 때는 새 복제를 시작하지 않습니다.

화면에서 확인할 것

보이는 정보확인할 이유와 행동
모임 이름·정산 방식어느 모임의 비용인지 확인하고 항목별 납부와 차액 송금 중 하나를 선택합니다.
비용명·금액·먼저 결제한 사람실제 지출과 수취인을 기록합니다. 결제자가 주최자라고 가정하지 않습니다.
나눌 사람·부담금 미리보기그 비용을 함께 부담할 사람만 고르고 금액 합계를 확인합니다.
저장 결과와 복구 안내거절·결과 미확인·초안 취소를 구분합니다. 이유를 확인하고 재조회하거나 입력을 수정합니다.
정산 초안 만들기비용을 저장합니다. 참가자에게 납부를 요청하는 버튼은 다음 금액 검토 화면에 있습니다.

확인한 범위와 남은 확인

9월 24일에는 가상 회원의 첫 비용 저장·금액 검토·요청을 실제 웹과 서버에서 확인했습니다. 9월 26일 보완은 앱 상태 검사 10건·작성 화면 검사 1건과 서버 항목 검사 2건의 변경 기록을 확인했습니다. 이번 문서 갱신에서 제품 검사를 다시 실행한 것은 아닙니다.

추가 복구 동작의 실제 웹·서명 앱 확인은 남아 있습니다. 정산은 어디까지 확인됐나요?에서 기존 사진의 범위와 남은 화면 개선을 구분합니다.

이 기능의 출시 완료 기준

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 첫 출시 포함 여부와 구현·검사 현황은 위 상태표를 따릅니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 호스트가 비용을 포함한 정산 초안을 만들고 저장 후 같은 사람·항목·금액을 다시 본다.
  • 중간 취소·응답 유실·새 초안 시작 시 이전 저장 요청이 다른 정산을 바꾸지 않는다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 모임 정산의 관련 완료 기준도 함께 확인합니다.
