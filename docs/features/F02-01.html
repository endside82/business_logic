F02-01. 홈 피드 메인 조회

앱을 켰을 때 가장 먼저 보이는 화면. 로그인 사용자에게 네 개 영역 — 추천 이벤트, 곧 시작하는 이벤트, 인기 클럽, 새로 올라온 플랜 — 을 동시에 보여 준다. 로그인하지 않은 사용자도 홈 라우트에는 진입할 수 있지만 추천 이벤트 API만 인증 필수라 현재 해당 영역은 401 오류 카드가 된다. 로그인 사용자에게 추천 사람이 있으면 "다시 만나면 좋을 사람"이 조건부로 더해진다.

2026-07-29 소스 재실측 — 다시 만나면 좋을 사람

로그인 홈은 GET /api/v1/users/me/people-recommendations로 최대 10명을 추가 표시한다. 후보는 증거등급 공동참석자이며 현재 상태·양방향 차단·hideFromSearch를 다시 적용한다. 내가 남긴 다시 만나기 선택, 공동참석, 같은 클럽, 공통 관심, 최근 만남으로 정렬하지만 사용자에게는 점수 대신 이유 최대 2개만 보여 준다. 비로그인·빈 결과·오류에는 섹션과 여백을 모두 숨긴다.

홈은 사용자가 무엇을 원하는지 아직 정하지 않은 상태에서 들어오는 면이다. 추천, 시간 임박, 인기, 새 콘텐츠 네 가지 다른 탐색 동기를 한 화면에 함께 두어 사용자가 어느 쪽으로든 이어 갈 수 있게 한다. 동시에 일부 영역의 일시적 장애가 "앱 전체가 안 된다"는 인상을 주지 않도록, 기본 네 영역 모두 비어 있을 때만 전체 화면 오류를 띄운다. 하나라도 살아 있으면 사용자는 그쪽으로 탐색을 이어 갈 수 있다.

기본 네 영역과 조건부 사람 추천

예정 이벤트·인기 클럽·최신 플랜은 누구나 본다. 추천 이벤트와 사람 재연결은 인증이 필요하며 처리 방식이 서로 다르다.

맞춤 추천

추천 이벤트

인증 사용자의 상태·위치·인기·신선도를 종합해 카드 10장을 보여 준다. 관심사 데이터가 거의 없는 신규 사용자에게도 화면이 비지 않도록 기본 카드를 채워서 내려 보낸다. 현재 게스트 호출은 401이 되어 이 섹션에 재시도 UI가 표시된다.

시간 임박

곧 시작하는 이벤트

지금 시각 이후에 시작하는 모집 중 이벤트 10건을 시작 시각이 가까운 순으로. "오늘 저녁 뭐 하지" 류의 즉시 행동 의도를 받아 내는 자리.

소속·발견

인기 클럽

멤버가 많은 활성 클럽 5개. 로그인 사용자에게는 본인의 가입·대기·차단 상태가 카드에 함께 표시되어 "내 클럽"인지를 한눈에 구분한다.

새 콘텐츠

새로 올라온 플랜

마켓에 새로 발행된 플랜 5개. 가격·제작자·구매 수가 함께 보여 구매 결정의 단서가 한 카드 안에 모인다. 호스트 활동의 진입로이기도 하다.

로그인 전용 재연결

다시 만나면 좋을 사람

증거등급 공동참석자 중 현재 표시 가능한 최대 10명을 보여 준다. 점수 대신 내가 고른 다시 만나기·공동참석·같은 클럽·공통 관심에서 우선순위 이유 최대 2개만 표시한다.

네 콘텐츠 영역과 사람 추천이 그려지는 흐름

사용자가 홈 탭을 누른 순간부터 네 콘텐츠 영역이 자기 자리에 안착하기까지. 핵심은 "한 영역이 늦거나 실패해도 다른 영역은 살린다".

사용자 시나리오

기본 흐름

로그인 직후 첫 진입

로그인을 마친 사용자가 홈으로 들어온다. 기본 네 영역이 채워지고 추천 사람이 있으면 이유 칩과 함께 사람 섹션도 나타난다. 위치 권한을 거부해도 상단 안내 띠로만 알린다.

이 흐름이 남기는 것 — 사용자는 "내가 이 앱에서 뭘 할 수 있는지"를 첫 5초 안에 본다.

즉시 복귀

카드 하나 들어갔다가 돌아옴

추천 카드를 눌렀다가 뒤로가기로 홈에 돌아온다. 5분이 지나지 않았으면 같은 화면이 깜빡임 없이 그대로 보인다.

이 흐름이 남기는 것 — "들락날락"하는 자연스러운 탐색에서 매번 로딩이 깔리는 답답함을 없앤다.

일부 장애

한 영역만 응답이 안 옴

인기 클럽이 일시적으로 안 불러와진다. 다른 세 영역은 평소대로 보이고, 인기 클럽 자리에만 작은 "다시 시도" 카드가 뜬다. 사용자가 누르면 기본 네 영역 전체를 다시 한 번 호출해 정합을 맞춘다.

이 흐름이 남기는 것 — 한 영역 장애가 앱 전체 장애로 인지되지 않게 한다.

완전 단절

비행기 모드에서 켰을 때

기본 네 영역 모두 응답이 없으면 풀스크린 오류로 떨어진다. 스스로 다시 시도하지 않고, 사용자의 명시적 "다시 시도" 동작을 기다린다.

이 흐름이 남기는 것 — 무한 재시도로 배터리·데이터를 낭비하지 않고, 복구 시점을 사용자가 통제한다.

가입 전 탐색

비로그인 사용자가 둘러봄

로그인 없이 홈에는 들어갈 수 있고 곧 시작하는 이벤트·인기 클럽·새 플랜은 보인다. 하지만 Flutter가 인증 필수 추천 이벤트 API도 호출해 해당 섹션에는 401 재시도가 보인다. 사람 추천·내 일정·찜은 인증 상태를 확인해 숨긴다.

현재 Gap — public 라우트와 추천 이벤트 API의 인증 조건을 앱이 조정하지 않아 가입 전 탐색 화면이 완전한 네 영역으로 보이지 않는다.

빈 상태

인기 클럽이 한 건도 없다

응답은 정상이지만 데이터가 0건일 때, 인기 클럽 자리는 그대로 보이고 "아직 인기 클럽이 없어요" 같은 안내만 본문에 표시된다. 헤더(영역 제목)는 그대로 둬서 "이 영역이 존재한다"는 사실 자체는 사용자가 인지하게 한다.

이 흐름이 남기는 것 — 데이터가 적은 초기 환경에서도 영역이 "사라진" 인상은 주지 않는다 — 운영자가 데이터를 채우면 자연스럽게 살아난다.

권한 분기

위치 권한을 거부했을 때

거리 기반 추천은 좌표 없이 계산되어 약해지고, 화면 상단에 "위치 권한이 필요해요" 안내 띠가 한 줄 남는다. 기본 네 영역의 다른 정보는 영향 없이 그대로 보인다.

이 흐름이 남기는 것 — 권한 한 가지를 거부해도 사용자가 다른 가치를 잃지 않게 한다.

화면에서 사용자가 인지하는 것

실제로 화면을 열었을 때 보이는 정보와, 그 정보가 그 자리에 있는 이유.

영역사용자가 보는 것그 자리에 둔 이유
상단 로고·검색·알림 좌측 서비스 로고, 우측에 검색·알림 두 진입점. 알림에는 향후 미읽음 표시가 들어갈 자리. 스크롤과 무관하게 항상 같은 자리에서 검색과 알림으로 빠져나갈 수 있어야 한다.
위치 권한 안내 띠 권한이 거부됐을 때만 노출. 한 줄짜리 카피와 "권한 다시 보기" 버튼. 거리 기반 추천이 약해진 이유를 사용자가 인지하고, 한 번에 설정으로 이동할 수 있게.
추천 이벤트 가로 스크롤 카드 10개, 끝에 "추천 더보기" 진입. 카드에 추천 이유가 한 줄 배지로. "왜 이게 추천됐는지" 보이지 않으면 추천이 노이즈로 인지된다 — 짧은 이유로 신뢰를 만든다.
곧 시작하는 이벤트 세로 리스트 10개. "오늘 19시", "내일 14시" 같은 시작 시각이 가장 먼저 눈에 들어옴. 홈에 들어온 사람의 첫 질문은 보통 "지금/오늘/이번 주" — 시각이 가까운 순이 곧 의도의 순.
인기 클럽 가로 스크롤 5개. 로그인 시 카드 모서리에 "내 클럽" 같은 본인 상태 배지. "이미 내가 속해 있는지"를 카드 단계에서 알아야 가입·재방문 의도가 자연스럽게 갈린다.
새로 올라온 플랜 세로 리스트 5개. 가격·제작자·구매 수가 한 줄 안에. 구매를 결정할 때 가장 먼저 보는 정보(가격·제작자·구매 수)를 카드 안에 함께 두어, 상세에 들어가지 않아도 1차 판단이 가능하게.
다시 만나면 좋을 사람 로그인·결과 있음에서만 수평 카드 최대 10명. 이유 최대 2개와 공동참석 횟수. 받은 선택이나 숫자 점수 없이 이미 만난 사람과 다시 연결할 근거만 설명한다.

운영자가 알아야 할 것

홈에서 사용자가 보는 풍경은 이 다섯 가지 운영 결정으로 결정된다
  • 추천 노출 수 10건은 "스크롤하지 않고 두세 장 노출"의 균형점이다. 늘리면 추천이 풍부해 보이지만 첫 화면의 시간 임박/인기/플랜이 밀린다.
  • 인기 클럽 5건은 화면 한 폭 안에 다 들어가는 최대치다. 늘리면 가로 스크롤이 필요해지고 "인기" 라는 신호가 분산된다.
  • "한 영역이라도 살아 있으면 화면을 살린다"는 정책 때문에 한 영역의 데이터 결핍은 운영 모니터링이 따로 잡아 줘야 한다. 사용자에게는 가시적 경보가 가지 않는다.
  • 가입 전 진입은 허용하지만 추천 이벤트는 인증 필수다. 공개 3영역의 viewer 정보는 로그인일 때만 채우고, 추천 이벤트는 게스트 호출을 막거나 공개 대체 계약을 제공해야 한다.
  • 위치 권한은 첫 진입에서 한 번만 묻는다. 매 진입마다 묻는 회귀가 들어가면 사용자 이탈이 즉시 늘어난다.
