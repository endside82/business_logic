F08-08 마켓 메인 탐색

홈의 플랜 더보기에서 판매 중 상품을 탐색한다. 유형·분류·정렬·가격은 본문 목록에 적용하고 인기10개·최근본목록·조회실패·기간권 공개 조건을 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

실제 입구와 탐색 결과

홈의 새 플랜 영역은 MARKET 공개 시 표시되며 더보기가 /market의 플랜 마켓을 연다. 홈의 개별 플랜 카드는 플랜 ID 상세로 가는 별도 경로다. 마켓을 하단 전용 탭으로 안내하지 않는다.

마켓 상단에는 검색 입력, 내 상품, 내 보관함, 내 큐레이터 묶음 상품 입구가 있다. 검색어를 제출하면 마켓 키워드 검색으로 이동한다. 인기·최근 본 상품·본문 목록의 카드는 itemId를 사용해 /market/items/{itemId}로 간다. 이 화면에서 카드를 누르는 것만으로 구매하지 않는다.

/market?itemType=…는 첫 목록의 유형 필터를 지정한다. 허용 유형은 PLAN·EVENT_PACKAGE·VIRTUAL_ITEM·SUBSCRIPTION이며 잘못된 초기 값은 전체 유형으로 처리한다. 상품 관리와 판매 상태 변경은 내 상품 등록·심사·판매 관리를 따른다.

인증·판매 범위와 목록 계약

목록·인기·분류·검색 API는 인증이 필요하고 MARKET 공개 범위를 적용한다. 개별 상품 상세의 익명 허용을 목록에도 확대하지 않는다. 목록과 인기·검색은 ON_SALE이고 판매 유형이 열려 있는 상품을 대상으로 한다. 공개된 플랜 전체를 직접 나열하는 계약이 아니다.

기간권 SUBSCRIPTION은 MARKET_PERIOD_PASS 공개 여부를 별도로 확인한다. 이 범위가 닫히면 서버 결과에서 제외되고 앱의 기간권 유형 칩도 숨긴다. 닫힌 기간권 유형을 지정한 메인 진입은 전체 유형으로 시작한다. 다른 상품 유형의 공개 범위와 기간권 판매 제한을 혼동하지 않는다.

첫 진입에는 분류 트리·인기 목록·본문 첫 페이지를 독립적으로 요청한다. 본문은 20개씩 읽으며 분류를 선택하지 않았으면 목록 API, 선택했으면 검색 API를 사용한다. 인기·최근 본 영역은 본문의 선택 조건으로 다시 필터링하지 않는다.

분류와 정렬·가격 필터

유형 칩의 추천은 유형 필터 해제다. 별도 분류 줄의 전체는 분류 필터 해제다. 추천이 개인화 추천 알고리즘의 실행을 의미하지 않으며 두 선택은 독립적이다.

분류 API는 활성 뿌리와 활성 직계 자식의 트리를 반환하지만 현재 메인에는 뿌리 분류만 칩으로 표시한다. 뿌리를 선택하면 서버가 그 뿌리와 보이는 직계 자식 ID를 함께 검색한다. 숨은 분류·없는 분류·비활성 부모의 자식·더 깊은 분류는 검색 가능한 범위가 아니며 선택 ID가 보이지 않으면 빈 페이지를 반환한다.

선택서버 정렬
최신 LATEST 또는 알 수 없는 값createdAt 내림차순, 동률 itemId 내림차순
인기 POPULARpurchaseCount 내림차순, 동률 itemId 내림차순
낮은 가격 PRICE_ASCamount 오름차순, 동률 itemId 오름차순
높은 가격 PRICE_DESCamount 내림차순, 동률 itemId 내림차순

정렬 값은 대소문자를 구분하지 않는다. 목록 요청의 이름은 sort, 검색 요청의 이름은 sortBy다. 가격 조건은 경계를 포함한다. 가격 시트는 0~100,000P를 5,000P 단위로 선택하지만 0 끝값은 하한 없음, 100,000 끝값은 상한 없음으로 요청한다. 따라서 맨 오른쪽을 선택했다고 100,000P 초과 상품을 제외하는 것은 아니다. 초기화는 두 제한을 해제하고, 시트를 취소하면 조건을 바꾸지 않는다.

서버 목록의 난이도 필터는 PLAN 및 원본 플랜이 연결된 EVENT_PACKAGE에 적용된다. 현재 이 화면의 API 호출에는 난이도 선택을 보내지 않는다.

인기와 최근 본 상품

인기 provider는 limit=10으로 요청하고 전체보기도 같은 provider를 세로 목록으로 보여 준다. 전체보기가 추가 50개 조회나 별도 무한 스크롤을 수행하는 것은 아니다. 서버 인기 API의 기본값은 10이고 상한은 50이다. 인기 화면 자체에는 오류 재시도와 데이터가 있을 때 당겨서 갱신이 있다.

최근 본 ID는 계정 범위를 사용하는 로컬 저장소에서 읽는다. 표시할 때 앞의 최대 10개 ID에 대해 상품 상세를 다시 요청하고 성공한 항목만 모은다. 저장된 과거 카드의 가격·상태를 그대로 신뢰하는 목록이 아니다. 저장 중 계정이 바뀌면 이전 결과를 새 계정의 provider에 반영하지 않는다.

페이지·실패·갱신

유형·분류·정렬·가격을 바꾸면 첫 페이지부터 다시 읽는다. 요청 세대를 비교하여 이전 조건의 늦은 첫 페이지나 추가 페이지가 새 목록에 섞이지 않게 한다. 첫 페이지가 성공하기 전·추가 페이지 요청 중·마지막 페이지 뒤에는 추가 요청을 막고, 다음 페이지 번호는 성공한 응답을 반영한 뒤 진행한다.

현재 본문 목록은 첫 요청 중 전용 로딩 상태로 바꾸지 않는다. 처음에는 빈 목록 안내가 보일 수 있고, 조건 변경 중에는 이전 카드가 남을 수 있다. 첫 페이지 실패는 플랜을 불러오지 못했습니다 토스트를 보여 주고 이전 또는 빈 목록을 유지한다. 따라서 선택된 조건 아래 남은 카드가 새 조건으로 조회에 성공했다는 증거는 아니다.

추가 페이지 실패는 기존 카드를 유지하고 로딩 표시만 끝낸다. 별도의 오류·재시도 버튼은 없고 이후 스크롤에서 같은 다음 페이지를 다시 요청할 수 있다. 분류가 비었거나 조회에 실패하면 분류 줄을 숨기며, 인기 로딩·실패도 메인에서는 영역을 숨긴다. 성공한 다른 영역까지 막지는 않는다.

메인에서 당겨서 갱신하면 인기 provider와 본문 첫 페이지를 다시 읽는다. 분류 provider까지 무효화하는 것은 아니다. 오류와 빈 결과, 이전 결과 유지를 서로 다른 상태로 검수한다.

수용 기준과 검증 근거

  • AC-01 실제 입구: 홈의 MARKET 공개 플랜 더보기에서 마켓을 열고 상품 카드는 itemId 상세로 이동한다. 홈 개별 플랜의 planId 상세와 혼동하지 않는다.
  • AC-02 인증과 판매 상태: 인증·MARKET 범위를 충족한 목록은 ON_SALE 및 열린 판매 유형만 대상으로 한다. 개별 상세의 익명 허용을 목록에 적용하지 않는다.
  • AC-03 기간권 제한: 기간권 판매가 닫히면 SUBSCRIPTION 결과와 유형 칩을 숨기고 해당 초기 유형 진입은 전체 유형으로 바꾼다.
  • AC-04 분류 범위: 앱은 뿌리 칩을 표시하고 뿌리 검색은 보이는 직계 자식까지 포함한다. 숨은 분류는 빈 결과이며 전체 분류와 유형 추천 해제를 구분한다.
  • AC-05 조건 전달: 분류 없음은 목록 sort, 분류 있음은 검색 sortBy를 사용하고 유형·가격·페이지를 함께 보낸다. 본문 필터가 인기 영역도 바꾼다고 판정하지 않는다.
  • AC-06 가격 경계: 중간 가격은 포함 경계로 적용한다. 0/100000 끝값과 초기화는 각각 제한 해제로 보내며 취소는 현재 조건을 유지한다.
  • AC-07 정렬과 인기: 네 정렬의 동률 순서를 유지한다. 인기 전체보기는 같은 최대10개를 표시하고 더 큰 결과 목록이나 별도 페이지 조회를 약속하지 않는다.
  • AC-08 최근 본 상품: 계정 범위의 ID 앞10개를 상세 재조회하고 성공한 항목만 표시한다. 계정 변경 뒤 이전 저장 결과를 현재 상태에 반영하지 않는다.
  • AC-09 늦은 응답: 조건이 바뀐 뒤 옛 응답을 버리고 첫 페이지 성공 전 추가 페이지를 막는다. 성공하기 전에 다음 페이지 번호를 넘기지 않는다.
  • AC-10 실패 복구: 본문 첫 실패 토스트·추가 실패의 기존 카드 유지·분류/인기 숨김을 구분한다. 빈 목록 문구만으로 성공을 단정하지 않는다.
  • AC-11 갱신 범위: 메인 당겨서 갱신은 인기와 본문을 다시 읽으며 분류까지 갱신한다고 기록하지 않는다. 인기 별도 화면의 오류 재시도를 확인한다.

market_category_filter_test.dart의 늦은 분류 응답 배제, market_subscription_filter_test.dart의 기간권 공개/봉인 진입, MarketCategoryServiceTest의 보이는 분류·뿌리/직계 범위 단언을 읽었다. 이번에는 제품 시험을 실행하지 않았다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 첫 출시 포함 여부와 구현·검사 현황은 위 상태표를 따릅니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 후속 공개 시 허용된 판매 상품을 카테고리별로 탐색하고 정확한 상품으로 이동한다.
  • 판매 중지·권한 회수·첫 출시 제한·빈 결과·페이지 중복을 처리한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 플랜 마켓의 관련 완료 기준도 함께 확인합니다.
