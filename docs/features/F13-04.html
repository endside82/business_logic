F13-04. 선호 태그 관리

내 프로필의 선호 태그는 서버 카탈로그에서 고른 태그를 한 건씩 추가·삭제하는 화면이다. 본인 태그는 최대 20개이며 별도의 저장 버튼·삭제 확인·일괄 저장은 없다. 현재 화면에는 이름이나 가중치를 수정하는 기능이 없다. 태그의 공통 저장 정책과 관계·추천 소비는 관심사 태그의 저장·소유권 규칙과 관계·추천에서 사용하는 범위를 따른다. 이 문서는 가입 후 프로필에서 관리하는 실제 흐름을 다루며, 온보딩의 3개 선택 조건을 이 화면의 최소 보유 수로 적용하지 않는다.

실제 진입과 복귀

  1. 내 프로필 메뉴의 선호 태그에서 연다. 내 태그와 추천 카탈로그를 각각 읽으며, 각 조회의 로딩·오류·다시 시도를 구분한다.
  2. 태그가 없으면 추천 목록에서 추가하라는 안내를 보인다. 전체 삭제도 가능하고 이 화면을 나가기 위해 최소 3개를 유지할 필요는 없다.
  3. 추천 태그를 누르면 단건 추가한다. 이미 선택된 추천 태그는 다시 누르지 못하고 20개일 때 추가를 누르면 한도 안내를 보인다.
  4. 내 태그의 삭제 표시를 누르면 해당 태그를 바로 삭제 요청한다. 성공하면 내 목록을 다시 읽고 추천 태그의 선택 표시도 새 목록에 맞춘다.
  5. 뒤로 가기는 원래 화면으로 돌아간다. 이미 성공한 추가·삭제를 일괄 취소하거나 별도의 저장 확인을 받는 흐름이 아니다.

저장·실패·권한 규칙

조건현재 결과
조회 성공본인 태그를 가중치 내림차순으로 표시함. 추천은 서버 카탈로그를 사용함
새 태그 추가카탈로그 이름·중복·20개 상한을 서버에서 검사함. 현재 앱의 가중치는 1.0
다른 회원의 태그 수정·삭제본인 소유가 아니면 찾을 수 없는 태그로 거절함
과거 카탈로그 밖 태그기존 태그는 조회·삭제 가능. 새 임의 이름을 추가하는 기능은 아님
이름·가중치 수정서버 기능은 있지만 현재 프로필 화면의 조작·호출 경로는 없음
조회 실패해당 오류와 다시 시도를 표시함
추가·삭제 실패공급자는 실패 여부를 반환하지만 화면이 기다리지 않아 별도 오류 안내·재조회가 없음
빠른 반복 조작쓰기 진행을 별도 상태로 잠그지 않음. 서버의 중복·상한 판정을 사용자 조작 한 번당 요청 한 번의 보장으로 읽지 않음

추가·수정의 서버 판정은 회원 잠금 안에서 이루어진다. 입력·가중치·소유권의 정확한 계약은 공통 관심사 PRD의 규칙과 실제 코드가 기준이다. 화면 명세에 남은 저장 버튼·태그 식별자 목록 일괄 저장 설명은 현재 구현과 다르다.

관계·추천과 개인정보

태그는 관계 정보의 공통 관심사 표시와 사람 추천·데이팅의 일부 입력으로 쓰인다. 상대 전체 태그 목록이나 수치 궁합을 공개하는 기능은 아니다. 관계 열람 권한·대상 활동 상태와 데이팅의 양쪽 커뮤니티 데이터 사용 동의를 따로 적용한다.

저장 가중치가 모든 추천 점수의 배수가 되는 것은 아니다. 사람 추천은 공통 개수, 데이팅은 동의 조건에 따른 태그 집합 유사도를 사용한다. 구체적인 한도·빈 목록 처리·점수 기여는 공통 관심사 PRD에 모아 관리한다. 이 화면에서 변경 성공한 것과 이미 열려 있는 다른 추천 화면의 갱신 완료는 구분한다.

수용 기준과 검증 범위

  • AC-01 진입: 내 프로필에서 선호 태그를 열고 뒤로 가면 원래 화면으로 돌아간다.
  • AC-02 조회: 내 목록·추천 카탈로그의 정상·빈 목록·개별 조회 실패·다시 시도를 구분한다.
  • AC-03 추가: 단건 추가 성공 뒤 내 목록과 추천 선택 상태가 일치한다.
  • AC-04 상한·중복: 20개 안내와 이미 선택된 칩을 확인하고 동시 요청의 서버 중복·상한 판정도 구분한다.
  • AC-05 삭제: 확인 창 없이 삭제하고 성공 뒤 추천 칩을 다시 고를 수 있다. 0개로 나갈 수 있다.
  • AC-06 소유권·옛 태그: 다른 회원의 태그는 바꾸지 못하고 기존 카탈로그 밖 태그는 삭제할 수 있다.
  • AC-07 실패·복귀: 쓰기 실패 안내 누락·결과 유실·연속 조작·화면 이동 후 서버의 실제 저장 상태를 확인한다.
  • AC-08 소비와 공개: 관계 열람·양쪽 동의·추천 입력을 구분하고 타인 전체 태그나 수치 궁합을 노출하지 않는다.

2026-11-22 기존 소스 검토의 파일 지문 23개가 그대로임을 확인했다. 새 실행·추천 결과 검증은 아니다.
