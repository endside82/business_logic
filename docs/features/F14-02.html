F14-02 위치 공유 중단과 이벤트 설정

본인 철회와 이벤트 전체 설정의 다른 권한·초기화·알림 효과 및 앱 실패 안내 경계를 명시한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

현재 역할과 입구

위치 공유 화면에서 본인 공유 중단을 확인한 뒤 동의 철회 API를 호출한다. 개인정보 화면은 일반 회원에게 본인 동의 스위치, 이벤트 수정 권한이 있는 회원에게 이벤트 전체 공유 설정을 표시한다. 두 스위치는 대상과 효과가 다르다.

본인 동의 철회

POST /api/v1/events/{eventId}/location/opt-out은 본문 없이 200으로 끝난다. 이벤트·회원 단위 잠금 아래 본인 동의를 false로 만들거나 없는 행을 false로 생성하고 본인 좌표를 삭제한다. 이 메서드는 현재 참석 자격·공유 시간·이벤트 설정을 다시 요구하지 않아 참석 자격을 잃거나 시간이 지난 뒤에도 철회할 수 있다. 이벤트의 존재는 필요하다.

성공하면 다른 사람이 다음에 조회할 위치에서 빠진다. 기존 열람 기록을 함께 삭제하는 호출은 아니다. 조회 기록의 범위와 보존은 위치 개인정보와 열람 기록을 따른다.

이벤트 전체 공유 설정

이벤트 공유 설정 변경은 별도의 이벤트 변경 계약이다. 운영 권한을 확인하고 DRAFT 또는 OPEN에만 허용하며 정기모임 회차는 거절한다. 같은 값이면 변경하지 않는다. 실제로 값이 바뀌면 켜기·끄기 모두 기존 동의와 좌표를 초기화한다. 다시 켰다고 예전 동의나 좌표가 복원되지 않는다.

켜기는 참석자, 끄기는 기존 공유자 중 실행자를 제외한 대상으로 알림 outbox를 만든다. outbox 등록과 실제 기기 알림 수신은 구분한다.

앱 성공과 실패

위치 화면은 철회 성공 뒤 로컬 동의·위치 값을 비우고 GPS 갱신을 멈추며 개인정보를 다시 읽는다. 실패하면 성공 상태로 바꾸지 않고 오류를 알린다. provider는 최근 명령 오류를 보관하고 성공 시 목록을 다시 읽는다.

개인정보 화면에서 본인 동의를 바꾸면 해당 개인정보 조회를 무효화해 위치 화면이 상태를 다시 반영한다. 개인정보 화면이 부모의 GPS 타이머를 직접 취소하는 구조는 아니다. 이 화면의 본인 동의 처리에는 provider가 false를 반환할 때 별도 실패 안내가 없는 경계가 남아 있다. 예외만 처리하므로 모든 실패가 사용자에게 안내된다고 쓰지 않는다.

수용 기준과 검증 근거

  • AC-01 본인 철회: 참석 자격·공유 시간·이벤트 공유 설정과 무관하게 존재하는 이벤트의 본인 동의를 false로 하고 좌표를 삭제한다.
  • AC-02 앱 상태 반영: 위치 화면의 성공은 동의·좌표 초기화와 GPS 중단·개인정보 갱신으로 이어진다.
  • AC-03 실패 구분: 실패를 성공으로 표시하지 않고 개인정보 화면의 false 반환 안내 누락을 미해결로 기록한다.
  • AC-04 전체 설정: 운영 권한·DRAFT/OPEN·정기모임 회차 제외를 확인하며 실제 설정 변경은 켜기·끄기 모두 기존 공유를 초기화한다.
  • AC-05 데이터와 알림: 본인 철회는 기존 열람 기록 삭제가 아니고 전체 설정의 알림 등록은 수신 완료가 아니다.
