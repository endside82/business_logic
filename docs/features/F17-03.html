F17-03. 정기모임 생성 (호스트)

호스트가 정기모임 본체를 만드는 면. 무조건 초안 상태로 먼저 저장한 뒤, 회차를 다 꾸리고 가격·정원·정책을 확정한 다음 별도로 발행한다. 고정형은 코스 전체 회차 수·정원·가격이 필수이고, 변동형은 회차마다 따로 정의되므로 본체에서는 비워둘 수 있다. 앱 화면은 타입별 결제·환불·노쇼·정산 결과를 미리 설명하지만, 현재 카테고리 값과 서버 enum 불일치가 실제 생성을 막을 수 있어 먼저 교정해야 한다.

초기 상태
항상 초안
발행은 별도 단계
가격 단위
100원
100원 미만 자동 절삭

관리자 전용

설계 의도 — 만든 사람이 끝까지 책임진다, 그 사이 자유롭게 다듬는다

정기모임은 코스 단위 결제·정산·환불을 동반하므로 일반 호스트가 스스로 이양할 수 없다. 예외적으로 관리자에게만 internal break-glass 이양 경로가 있으며, 이미 결제·정산이 잡힌 과거 세션의 귀속은 바꾸지 않는다. 반면 초안 단계는 자유롭다 — 발행 전까지 회차·가격·정책을 자유롭게 손볼 수 있고 운영중 사용자에게 영향이 없다. 모임을 "확정"하는 순간(발행)을 별도 단계로 분리해 호스트가 충분히 준비된 다음에 사용자에게 노출되도록 한다.

사용자 시나리오

고정형 코스 생성

"8주 러닝 코스" 만들기

호스트가 운영방식을 "고정형"으로 선택. 총 회차 8, 기본 정원 10, 코스 전체 가격 80,000원, 승인제 입력. 저장하면 "정기모임 생성 완료" 안내 뒤 초안 상세로 이동한다. 회차 추가는 상세에서 별도로 시작한다.

이 흐름이 남기는 것 — 호스트가 회차 셋업 전에 본체 정책(가격·정원·승인)을 먼저 결정하게 해, 회차 추가가 일관성을 잃지 않는다.

변동형 모임 생성

"매달 다른 주제 독서 모임"

운영방식을 "변동형"으로 선택. 총 회차·정원·가격 필드는 비워둔다(회차마다 따로 정의). 현재 앱은 승인·선결제·노쇼 입력도 고정형에서만 보여 주므로 제목·카테고리·장소 유형·설명만 본체에 담아 저장한다.

이 흐름이 남기는 것 — 회차마다 운영을 다르게 가져가야 하는 모임에 필요한 자유도. 본체는 "공통 정책 컨테이너" 역할만 한다.

가격 자동 절삭

12,345원 입력 → 12,300원 저장

가격 입력 후 저장. 100원 미만 단위는 자동 절삭되어 12,300원으로 저장된다. 상세 화면에서 저장된 가격을 다시 보여 줘 사용자가 인지하게 한다.

이 흐름이 남기는 것 — 원 단위 미세 금액을 막아 환불 산식이 깨끗하게 떨어지게 한다(일반 이벤트와 동일).

필수값 누락

고정형인데 회차 수가 비어 있음

고정형 + 총 회차 수가 비어 있으면 저장이 거절되고 "고정형은 총 회차 수가 필요해요" 안내.

이 흐름이 남기는 것 — 고정형의 핵심(코스 전체 규모) 확정이 누락된 채 발행으로 흘러가지 않게 한다.

온라인 모임

장소를 온라인으로 선택 — URL 입력은 현재 공백

앱은 온라인/오프라인 유형을 고를 수 있지만 주소·좌표·온라인 URL 입력칸은 아직 없다. 서버 param과 상속 로직은 준비돼 있으므로 화면 배선이 필요한 확인된 Gap이다.

이 흐름이 남기는 것 — 현재 생성된 초안은 장소 유형만 있고 실제 접속 URL은 비어 있을 수 있다.

노쇼 정책 기본

아무 선택 안 해도 저장됨

노쇼 정책을 지정하지 않으면 "없음"으로 저장된다. 호스트가 명시적으로 "경고" 또는 "자격박탈"을 선택해야 한도 추적이 켜진다.

이 흐름이 남기는 것 — 노쇼 정책이 강한 모임은 의도적 선택이어야 한다(자동 활성화 시 분쟁 가능).

화면에서 사용자가 인지하는 것

영역사용자가 보는 것그 자리에 둔 이유
운영방식 토글"고정형/변동형" 라디오. 선택에 따라 하단 필드가 달라진다.본체 폼이 운영방식에 따라 달라지므로 가장 먼저 결정하게 한다.
총 회차·정원고정형에서만 표시. 변동형에서는 입력 영역 자체가 나오지 않는다.변동형 본체에 입력해도 의미 없는 값이라 폼에서 제거해 혼동을 줄인다.
가격입력 후 100원 단위 안내. 저장 직후 절삭된 값으로 표기."내가 입력한 값과 저장된 값이 다르네?" 혼동을 막기 위해 자동 절삭을 명시 안내.
승인제·선결제토글 두 개. 본체에서 한 번 결정.모임 전체의 운영 방침이라 회차마다 바꿀 수 없게 본체로 묶는다.
노쇼 정책"없음·경고·자격박탈" + 한도 카운트 방식 선택.현금성 박탈 정책이라 명시적 선택을 요구해 분쟁 가능성을 낮춘다.
저장 후 안내"정기모임 생성 완료" 토스트 뒤 초안 상세로 이동한다.상세에서 정책을 다시 확인하고 회차 추가·발행 액션을 선택한다.

운영자가 알아야 할 것

초안 단계의 자유도와 호스트 제약
  • 호스트당 동시 초안 수 제한 없음 — 1차 출시는 quota 없이 자유롭게. 운영상 청소 정책은 후속.
  • 일반 호스트 이양 경로 없음 — 사용자가 직접 넘길 수는 없다. CANCELED가 아닌 모임에는 관리자 internal break-glass 이양만 있고, 기결제·기정산 세션은 기존 호스트 귀속을 유지한다.
  • 변동형 본체에 가격·정원 입력은 무시된다 — 회차마다 따로 정의되므로 본체 값은 의미 없음. 폼에서 비활성 처리 권장.
  • 환불 정책 기본은 "전액" — 호스트가 부분 환불 정책을 명시적으로 선택하면 적용.

2026-07-29 실제 소스 점검

P0 — 앱 카테고리와 서버 enum이 다르다

서버는 BOARD_GAME, HIKING, COOKING, BOOK_CLUB, SPORTS, MUSIC, ART, LANGUAGE, TECH, SOCIAL, TRAVEL, PHOTOGRAPHY, FOOD, FITNESS, OTHER를 받는다. 앱은 CLASS, STUDY, SPORTS, HOBBY, COOKING, OTHER를 보여 주며 기본값도 서버에 없는 CLASS다. 현재 일치하는 세 값 외 요청은 서버 역직렬화 단계에서 실패할 수 있다.

날짜 계약

LocalDate 형식은 해소

앱이 시작일·종료일을 yyyy-MM-dd로 직렬화하므로 서버 LocalDate와 일치한다.

썸네일

서버 안전장치는 있으나 화면 입력 없음

서버는 호스트 소유·업로드 완료·EVENT_THUMBNAIL 목적의 파일 키만 저장하고 표시할 때 새 URL을 발급한다. 앱 생성·수정 화면에는 아직 업로드/선택 입력이 없다.

타입별 강제값

변동형 본체 값은 서버가 비운다

VARIABLE은 본체 날짜·총 회차·가격·정원·선결제·승인을 null/0/false로 강제하고, 금액은 각 회차에서만 받는다.

레드 플래그

자주 발생하는 케이스
  • 카테고리 enum 불일치 — 앱 기본값 CLASS가 서버에 없어 정상 생성 경로가 막힐 수 있다. 최우선 교정 대상.
  • FIXED 음수 가격 서버 가드 누락 — 앱 폼은 막지만 서버 create/update가 음수를 거절하지 않아 직접 요청은 음수 저장이 가능하다.
  • 가격 절삭 혼동 — 입력값과 저장값이 다르므로 저장 직후 상세에서 절삭된 가격이 노출되어야 한다. 누락 시 호스트가 "왜 가격이 줄었지?" 혼동.
  • 변동형인데 본체에 가격을 적은 모임 — 사용자가 카드 단계에서 본체 가격을 "코스 총액"으로 오인할 수 있다. 변동형에서는 입력 자체가 막혀야 함.
  • 썸네일·상세 장소 입력 없음 — 서버 계약은 있으나 현재 authoring 화면에서 값을 만들 수 없다.
  • 초안 많이 만들어 놓고 발행 안 함 — 호스트당 초안 quota 없어 청소가 안 됨. 운영 모니터링 필요.
