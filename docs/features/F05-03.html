F05-03. 검색 필터 적용

이벤트 전용 조건·임시 편집·건수 실패·좌표 누락·추천 힌트의 차이를 명시한다. 2026-11-22 소스 대조이며 실제 앱 실행과 구분합니다.

결론

검색 화면의 필터는 이벤트 결과에 적용한다. 클럽·플랜·사람 검색의 공통 필터가 아니다. 시트 안의 변경은 임시 값이며 결과 보기로 적용한다. 시트를 닫기만 하면 이전 적용 값을 유지한다.

조건과 의미

카테고리여러 개를 선택하고 서버 분류 코드로 정규화

무료만과 최소 가격을 함께 정하면 두 조건을 모두 적용하므로 결과가 없을 수 있다. 일반 검색은 별도의 ‘곧 시작’ 정렬과 달리 모든 조건에 미래 시작을 강제하지 않는다. 거리값을 보내도 위도·경도·반경 셋이 갖춰지지 않으면 서버 거리 조건은 적용되지 않는다.

편집·건수·적용·초기화

  1. 현재 적용 필터로 시트를 열고 변경한다. 초기화는 시트의 임시 값을 비운다.
  2. 변경한 조건과 현재 검색어로 예상 건수를 조회한다. 300ms 대기 뒤 한 건짜리 페이지의 전체 건수를 사용한다.
  3. ‘결과 보기’를 누르면 조건을 적용하고 시트를 닫는다. 검색어가 이미 있으면 다시 검색하고, 없으면 다음 검색에 쓸 조건만 유지한다.
  4. 적용된 조건은 검색 화면의 칩으로 보여주고 개별 제거·전체 초기화를 지원한다. 이 동작도 이벤트 조건을 바꾼다.
  5. 같은 검색어의 재조회 중 앞 결과를 유지하는 처리와 결과 조건이 최종 일치하는 시점을 구분한다.

현재 건수 조회의 일반 실패는 0으로 반환되므로 ‘0개 결과 보기’가 실패를 의미할 수도 있다. 화면의 건수와 실제 결과를 일치한다고 단정하거나 조회 실패를 확인된 검색 0건으로 기록하지 않는다.

위치와 추천 필터

거리 조건에 좌표가 없으면 위치를 요청한다. 실제 결과 조회는 얻은 좌표를 잠시 재사용하지만 예상 건수 조회는 별도 위치 요청 경로다. 위치를 얻지 못한 경우에도 반경만 전송할 수 있어, 거리 칩은 남아 있으나 서버는 거리로 좁히지 않은 결과를 반환한다. 좌표 유효성 검사는 존재하지만 위치 거부를 ‘반경 안 결과’로 바꾸어 주지는 않는다.

추천 필터는 선택 지역과 미래의 공개 탐색 이벤트를 기준으로 카테고리 건수·가격 범위·날짜 범위를 만든다. 현재 검색어와 전체 편집 필터를 적용한 건수와는 다르다. 현재 서버의 카테고리 이름 표는 숫자 키를 쓰지만 조회는 카테고리 객체로 찾으므로 이름이 ‘기타’로 대체될 수 있다. 앱은 그 이름을 표시하고 실제 선택에는 코드를 사용한다.

수용 기준과 검증 범위

  • AC-01 범위: 필터는 이벤트에만 적용하고 다른 결과 유형의 조건이라고 표시하지 않는다.
  • AC-02 편집: 열 때 현재 값을 복사하고 닫기만 하면 적용하지 않는다.
  • AC-03 초기화: 시트 초기화와 적용 후 전체 초기화의 시점을 구분한다.
  • AC-04 날짜·가격: 시작일 범위·양끝 가격·무료 조건의 결합을 실제 결과와 대조한다.
  • AC-05 정원: 최소 인원은 모집 정원을 비교하고 현재 참가자·빈자리로 계산하지 않는다.
  • AC-06 거리: 1~50km와 좌표 유효성을 적용하고 위치 거부 때 거리 조건이 빠지는 현재 차이를 확인한다.
  • AC-07 건수: 같은 검색어·필터의 전체 건수와 실패를 구분하며 현재 0 반환의 제한을 남긴다.
  • AC-08 추천 힌트: 지역·미래 공개 대상 통계와 현재 조건의 결과 건수를 구분하고 카테고리 이름·코드를 대조한다.
  • AC-09 조건 전달: 요일·최소 정원·좌표를 결과 조회와 건수 조회에서 같은 의미로 전달한다.
  • AC-10 결과 갱신: 적용·칩 삭제 뒤 늦은 응답과 다음 페이지가 이전 조건을 섞지 않는지 확인한다.

기존 search_filter_contract_test.dart는 요일·최소 정원이 API, 저장소, 결과 공급자, 건수 공급자를 거쳐 전달되는 것을 다룬다. 이 시험 목적이 실제 GPS·사각 범위·힌트 표시·모든 조합의 실행 통과를 증명하지는 않는다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다. 아래 과거 판정 조건의 날짜를 이번 실행일로 바꾸지 않는다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 선택한 필터·정렬·범위와 실제 결과가 일치하고 초기화하면 기본 목록으로 돌아간다.
  • 필터 변경 중 페이지 요청과 늦은 응답을 분리해 중복/누락·이전 조건 혼입을 막는다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 검색의 관련 완료 기준도 함께 확인합니다.
