F01-07. 관심사 태그 관리

온보딩에서 관심사를 선택하거나 마이의 내 프로필 메뉴에서 선호 태그를 추가·삭제한다. 서버 카탈로그의 라벨만 새로 등록할 수 있고 회원별 최대 20개다. 현재 프로필은 누를 때마다 단건 저장하며 이름·가중치 편집이나 마지막에 전체를 저장하는 화면은 없다. 온보딩은 여러 건을 차례로 저장하므로 중간 실패의 부분 결과와 재시도 문제가 남아 있다.

실제 진입과 복귀

  1. 온보딩의 관심사 선택에서 서버 카탈로그를 읽는다. 일반 ‘다음’은 3개 이상 선택해야 활성화되고 성공하면 위치 단계로 이동한다. ‘건너뛰기’는 태그를 저장하지 않고 같은 다음 단계로 간다.
  2. 내 프로필 메뉴의 ‘선호 태그’를 열면 내 태그와 추천 카탈로그를 각각 읽는다. 읽기 실패는 해당 오류와 다시 시도를 표시한다. 빈 내 태그 목록은 추천 태그 추가 안내로 표시한다.
  3. 프로필의 추천 태그를 누르면 한 건 추가한다. 이미 선택한 항목은 선택 상태로 표시하고 20개인 상태의 추가는 안내와 함께 막는다. 서버도 중복과 상한을 다시 검사한다.
  4. 내 태그의 삭제 표시를 누르면 해당 태그를 바로 삭제 요청한다. 추가·삭제 성공은 내 태그 목록을 다시 읽는다. 별도의 저장 버튼이나 삭제 확인 창을 거치는 흐름은 아니다.
  5. 프로필 쓰기 실패는 현재 공급자가 실패 여부만 반환하고 화면이 기다리지 않아 별도 오류 안내·재조회가 없다. 조회 오류의 다시 시도와 쓰기 실패를 혼동하지 않는다.
  6. 프로필에서 뒤로 가면 원래 화면으로 돌아간다. 저장 중 온보딩 건너뛰기·화면 이동은 이미 성공한 태그를 되돌리는 동작이 아니다.

저장·수정·소유권 규칙

  • 조회는 본인 태그의 목록이며 가중치 내림차순이다. 페이지 응답이나 타인의 전체 태그 조회가 아니다.
  • 새 태그는 앞뒤 공백을 제거한 서버 카탈로그 라벨이어야 한다. 임의 문자열·빈 이름·이름 길이 초과를 거절한다. 이름 입력의 최대 길이는 50자다.
  • 서버는 추가·수정 때 본인 회원 행을 잠근다. 중복 이름과 20개 상한은 추가 시 최종 검사한다. 이름 변경도 다른 본인 태그와 중복할 수 없다.
  • 가중치는 0.1~5.0이며 현재 앱의 추가 요청은 1.0을 사용한다. 가중치가 높다고 모든 추천 점수가 그 배수로 증가하는 것은 아니다.
  • 서버의 단건 수정은 이름·가중치를 바꿀 수 있다. 본인 소유가 아닌 식별자로 수정·삭제하면 찾을 수 없는 태그로 거절한다. Flutter에는 수정 API 선언이 있으나 현재 화면·저장소·공급자의 호출 경로는 없다.
  • 과거에 저장된 카탈로그 밖 이름도 조회·삭제할 수 있다. 기존 이름을 유지하며 서버에서 가중치만 바꾸는 경우와 새 이름으로 변경하는 경우의 카탈로그 검사를 구분한다.

온보딩 저장의 경계

선택한 태그를 한 건씩 요청하며 첫 실패에서 멈춘다. 전체를 한 번에 확정하거나 앞선 성공을 취소하는 API는 아니다. 같은 선택으로 다시 시도하면 먼저 저장된 태그의 중복 오류에서 멈출 수 있다. 현재 온보딩 선택에는 20개 상한이 없으므로 21개 이상을 고르면 서버 한도에서 부분 저장 후 실패할 수 있다. 실패 안내가 보여도 아무 태그도 저장되지 않았다고 설명하지 않는다.

프로필의 20개 제한과 온보딩의 최소 3개 조건은 서로 다르다. 건너뛰기가 있으므로 모든 회원에게 태그 3개가 필수라는 정책으로 확대하지 않는다. 이미 저장된 일부 태그도 건너뛰기로 지워지지 않는다.

관계·추천에서 사용하는 범위

  • 관계 정보는 대상 회원의 활동 상태와 상세 열람 권한을 확인한 뒤 공통 태그만 보여 준다. 앞뒤 공백·대소문자를 정규화해 교집합을 구하고, 보는 사람의 가중치 순서로 최대 5개를 남긴다. 상대의 전체 태그와 수치 유사도를 공개하는 기능은 아니다.
  • 사람 추천은 태그·선호 카테고리·선호 시간대의 공통 개수를 입력으로 쓴다. 공통점은 최대 4개에 각 0.5점으로 반영되므로 이 항목의 최대 기여는 2점이다. 예전 ‘최대 4점’ 설명은 잘못됐다. 추천 사유는 우선순위에 따라 최대 2개이며 총점을 사용자에게 보여 주는 계약은 아니다.
  • 데이팅의 태그 유사도와 신뢰점수는 양쪽 프로필이 모두 커뮤니티 데이터 사용에 동의한 경우에만 반영한다. 미동의이면 해당 요소를 제외하고 나머지 가중치를 다시 맞춘다. 태그가 한쪽이라도 비어 있으면 태그 유사도 요소는 중간값을 사용하며, 미동의를 태그 점수 0으로 처리하는 것과 다르다.
  • 저장 가중치는 관계 공통 태그의 표시 순서에 쓰인다. 사람 추천의 공통 개수와 데이팅의 태그명 집합 유사도에 직접 곱하지 않는다. 태그 추가·삭제가 모든 추천 화면에 즉시 반영된다는 실행 보장은 별도 검증이 필요하다.

수용 기준과 검증 범위

  • AC-01 두 진입: 온보딩 관심사 선택과 내 프로필의 선호 태그를 각각 열고 카탈로그·내 태그의 로딩·빈 결과·조회 실패를 구분한다.
  • AC-02 선택과 건너뛰기: 3개 미만이면 일반 다음을 막고 건너뛰기는 허용한다. 건너뛰기가 기존 저장 태그 삭제를 뜻하지 않는다.
  • AC-03 추가와 상한: 카탈로그 라벨을 기본 가중치로 추가하고 중복·20개 초과·빈 이름·카탈로그 밖 신규 이름을 거절한다.
  • AC-04 소유권: 본인 태그만 수정·삭제할 수 있고 타인의 식별자로 존재 여부를 노출하지 않는다.
  • AC-05 단건 수정: 서버의 이름·가중치 수정과 앱의 실제 편집 입구 부재를 구분한다. 가중치 범위와 이름 중복·카탈로그 조건을 검사한다.
  • AC-06 과거 태그: 기존 카탈로그 밖 이름도 목록에서 보고 삭제할 수 있으며 새 임의 이름 추가는 막는다.
  • AC-07 부분 저장: 온보딩 중간 실패 뒤 실제 저장된 목록을 확인하고 중복 때문에 같은 요청이 막히는 경우를 구분한다.
  • AC-08 쓰기 실패: 프로필 추가·삭제의 오류·응답 유실·반복 입력을 재현해 안내와 목록 일치 여부를 확인한다. 현재 미흡한 동작은 통과로 기록하지 않는다.
  • AC-09 소비와 공개: 공통 태그만 공개하고 보는 사람의 순서·5개 한도·사람 추천의 2점 상한을 확인한다. 데이팅의 양측 동의를 별도로 검사한다.
  • AC-10 복귀와 갱신: 뒤로 가기·건너뛰기·저장 중 이동 뒤 저장 결과와 다음 화면을 확인한다. 변경된 태그가 각 소비 화면에 반영되는지는 별도로 관찰한다.

2026-11-22 코드와 서버 시험 목적을 대조했다. 현재 기기와 추천 화면에서 새로 실행한 통과 기록은 아니다.
