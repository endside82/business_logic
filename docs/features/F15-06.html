F15-06. 경고 부여 & 원장 조정

운영진이 제보를 거치지 않고 직접 점수를 부여하거나(한 명/여러 명), 이미 부여된 경고를 감경·정정·만료로 조정하는 면. 경고 원장은 “추가만 되는” 장부라 한 번 부여된 기록은 지워지지 않고, 조정도 새 기록으로 쌓여 점수에 반영된다.

부여는 요청 표식 한 겹
설계 의도 — 한 경고를 두 번 무효화하거나 과하게 깎을 수 없게 한다

운영 화면은 네트워크 재시도가 흔하다. 그래서 같은 요청 표식으로 다시 들어온 부여·일괄 만료는 한 번만 처리된다. 감경은 남은 유효 점수를 넘을 수 없고, 정정·만료는 한 경고당 한 번만 가능하다. 이 두 가지는 선조회와 기록 고유성 두 겹으로 막혀 있다. 다만 수동 부여에는 이 두 겹이 걸리지 않는다. 운영자가 버튼을 다시 누르면 앱이 새 요청 표식을 만들어 보내므로 같은 경고가 한 건 더 쌓인다.

사용자 시나리오

직접 부여

제보 없이 한 멤버에게 경고를 준다

대상·유형·사유로 부여. 원장에 부여 기록이 생기고 유효 점수가 올라간다. 여러 명을 한 번에 부여할 수도 있다.

중복 방지

같은 부여 요청이 두 번 도착한다

네트워크가 같은 요청을 다시 보내면 처음 결과를 그대로 돌려주고 새 경고를 만들지 않는다. 다만 운영자가 버튼을 다시 누르면 새 요청으로 취급돼 경고가 한 건 더 쌓인다.

감경

경고 점수 일부를 깎아준다

남은 유효 점수 범위 안에서만 감경 가능. 초과하면 “유효 점수 초과”로 막힌다.

정정/만료

잘못 부여된 경고를 정정하거나 만료한다

정정·만료는 한 경고당 한 번만. 이미 정정·만료된 경고에 다시 시도하면 막힌다.

일괄 만료(사면)

여러 경고를 한 번에 만료한다

사면 같은 정책으로 여러 경고를 일괄 만료. 이미 만료된 건은 건너뛰고 “성공 N건/실패 M건”으로 결과가 온다.

운영자가 알아야 할 것 — 비즈니스 리스크

부분 성공이 운영자에게 보이지 않고, 수동 부여는 연타에 약하다
  • 여러 명 일괄 부여는 “부분 성공”이 가능하지만, 운영자는 누가 실패했는지 알 수 없다. 서버는 성공·실패 대상을 나눠 돌려준다. 그런데 앱 화면은 그 결과를 버리고 “처리되었습니다”만 띄우므로 전원 실패해도 성공처럼 보인다.
  • 지금 앱에는 여러 명 일괄 부여 화면 자체가 없다. 운영진이 앱에서 할 수 있는 것은 한 명씩 부여하는 일뿐이다. 일괄 만료 화면은 있으나 결과 처리는 위와 같다.
  • 같은 경고를 두 번 부여하는 실수는 시스템이 막아 주지 않는다. 운영자가 버튼을 두 번 누르면 두 건이 쌓이므로, 잘못 쌓인 건은 정정으로 되돌려야 한다.
