F15-06. 경고 부여 & 원장 조정

운영진이 제보를 거치지 않고 직접 점수를 부여하거나, 이미 부여된 경고를 감경·정정·만료로 조정한다. 앱에서는 한 명씩 부여하고, 여러 명 일괄 부여는 서버 기능만 있다. 경고 원장은 “추가만 되는” 장부라 한 번 부여된 기록은 지워지지 않고, 조정도 새 기록으로 쌓여 점수에 반영된다.

같은 부여의 응답 유실·연속 누르기
설계 의도 — 한 경고를 두 번 무효화하거나 과하게 깎을 수 없게 한다

수동 부여도 재시도를 보호한다. 앱은 처리 중 추가 입력을 막고, 응답을 받지 못한 뒤 같은 대상·사유·점수로 재시도하면 같은 요청으로 결과를 확인한다. 서버는 이미 처리한 결과를 돌려주며 경고를 다시 쌓지 않는다. 감경은 남은 유효 점수를 넘을 수 없고, 정정·만료는 한 경고당 한 번만 가능하다.

사용자 시나리오

직접 부여

제보 없이 한 멤버에게 경고를 준다

대상·사유·점수를 입력하면 원장에 부여 기록이 생기고 유효 점수가 올라간다. 앱은 성공 건수와 실패 건수를 구분해 안내한다.

중복 방지

같은 부여 요청이 두 번 도착한다

같은 화면에서 결과를 받지 못한 부여를 같은 내용으로 재시도하면 처음 결과를 돌려받는다. 성공을 확인한 뒤 새로 부여하거나 내용을 바꾸면 별도 경고다. 화면을 닫았다가 다시 부여하기 전에는 기존 기록을 먼저 확인한다.

감경

경고 점수 일부를 깎아준다

남은 유효 점수 범위 안에서만 감경 가능. 초과하면 “유효 점수 초과”로 막힌다.

정정/만료

잘못 부여된 경고를 정정하거나 만료한다

정정·만료는 한 경고당 한 번만. 이미 정정·만료된 경고에 다시 시도하면 막힌다.

일괄 만료(사면)

여러 경고를 한 번에 만료한다

사면 같은 정책으로 여러 경고를 일괄 만료. 이미 만료된 건은 건너뛰고 “성공 N건/실패 M건”으로 결과가 온다.

운영자가 알아야 할 것 — 비즈니스 리스크

재시도와 새로운 경고 부여를 구분한다
  • 실패 결과: 한 명 부여 화면도 성공·실패 건수를 보여 준다. 실패가 있으면 대상 회원의 기록을 확인한다.
  • 일괄 처리: 앱에는 여러 명 부여 화면이 없다. 일괄 만료의 대상별 실패 내역 확인은 별도 보완 대상이며, 단건 부여 개선으로 완료 처리하지 않는다.
  • 새로운 부여: 성공 뒤 다시 입력한 경고까지 자동으로 중복 판정하는 것은 아니다. 잘못 부여한 경고는 정정으로 되돌린다.
