F03-07. 정원·대기열 관리 (호스트)

정원과 예약 좌석·업무별 권한·대기 정보 공개·승격 조건·제거와 모집 변경의 현재 결과를 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

정원 설정, 대기 명단 조회, 수동 승격, 모집 마감·재개는 서로 다른 권한과 상태 조건을 사용한다. 현재 수동 승격도 실제 참석과 결제 대기 좌석을 합쳐 정원을 검사한다. “수동 승격은 정원을 무시한다”는 옛 설명은 현재 구현이 아니다.

참가자 신청·취소는 신청과 참석, 호스트 심사는 신청서 승인·거절, 참가비 정리는 참가비 결제와 신청 취소를 따른다. 개별 게스트의 유료 추가·제거와 은행 반환 확인은 참가 선입금의 별도 업무다.

실제 입구와 업무별 권한

모임 상세의 관리 목록에서 수용인원 설정과 대기 명단을 연다. 설정 경로는 서버의 정원 관리 권한으로 접근을 검사한다. 대기 명단 관리 입구는 대기열이 켜져 있고 명단 관리 또는 모임 편집 권한이 있는 경우에 나타난다. 대기 중인 본인의 정보는 참가자용 입구에서 이어진다. 화면의 버튼 유무만으로 서버 권한을 대신하지 않는다.

수동 승격호스트, 출석 관리 권한과 위임 조건을 만족한 공동호스트, 클럽 출석 관리자

정원 관리가 가능하다고 모집 마감도 가능한 것은 아니며, 대기 명단을 볼 수 있다고 승격도 가능한 것은 아니다. 해당 명령의 조건을 각각 적용한다.

설정 항목·저장·실패 후 입력

설정 화면에는 기본 수용인원, 대기 명단 사용, 최대 대기인원, 승인제 참석, 게스트 허용, 예매당 최대 게스트 수가 있다. 서버 입력은 기본 정원 1 이상, 최대 대기 0 이상이며 게스트를 허용하면 예매당 1~9명이다. 대기 상한 0은 무제한이 아니라 기본 정원의 두 배를 적용한다. 앱의 현재 “0 = 제한 없음” 문구와 구분한다.

서버는 모임 잠금 뒤 권한·정기모임 회차·DRAFT/OPEN 상태를 확인하고 설정을 바꾼다. 보내지 않은 선택 필드는 유지한다. 대기열이나 승인제를 끄더라도 기존 대기자·심사 중 신청을 일괄 취소하거나 승인하지 않는다. 기본 정원이 같은 값이어도 설정 저장 전체의 상태 검사는 생략하지 않는다.

앱은 숫자로 읽을 수 없는 값을 0으로 보내므로, 기본 정원이나 허용 게스트 수의 잘못된 입력은 서버에서 거절될 수 있다. 저장 성공 뒤 관련 상세·카드·주최 목록을 갱신하고 이전 화면으로 돌아간다. 실패하면 폼과 입력값을 유지하고 조건별 경고를 보여 준다. 저장 중 이탈과 미저장 변경의 이탈은 보호한다. 재조회가 일어나더라도 폼을 처음 한 번만 초기화하므로 사용자가 수정한 값을 자동으로 덮어쓰지 않는다.

정원 판정과 결제 대기 좌석

일반 참석의 배치 정책은 하드 상한을 먼저 보고, 그 아래에서 기본 정원과 초과 허용·대기 사용을 판정한다. 하드 상한과 초과 허용은 현재 설정 화면과 이 설정 요청의 입력 항목이 아니지만 저장된 값이 있다면 판정에 사용한다. 모든 데이터에서 해당 값이 반드시 비어 있다고 가정하지 않는다.

기본 정원 이상·초과 불허대기 허용이면 WAITING, 아니면 FULL

자리 예약은 결제 대기 신청의 일행 수와 호스트 확인 전 계좌이체 일행 추가 신고 인원의 합이다. 정원 축소, 정원 확대 후 자동 승격, 수동 승격이 이 예약을 고려한다. 정원을 낮출 때는 현재 참석 수와 예약 좌석의 합보다 작게 줄일 수 없다. 같은 값까지는 허용하며 기존 참석자를 강제로 취소해 수치를 맞추지 않는다. 하드 상한이 있으면 새 기본 정원이 이를 넘지 못한다.

정원을 늘리면 새 기본 정원에서 실제 ATTENDING 행 수와 예약 좌석을 뺀 빈자리만큼 자동 승격을 시도한다. 결제 확정에서 WAITING/FULL이 나오면 대기 등록 대신 확정 불가로 처리한다. 결제수단별 금액 정리 결과를 정원 설정 저장의 결과로 합쳐 설명하지 않는다.

대기 정보의 공개 범위와 표시

서버는 모임 접근을 확인한 뒤 대기 순서로 조회하고 본인 일행 제한·차단 조건을 적용한다. 반환되는 총 대기 수는 필터를 통과해 이 사용자에게 보이는 행 수다. 본인 일행 조회의 1명과 실제 대기 순번 4번은 동시에 성립하며 전체 모임 대기자가 한 명이라는 뜻이 아니다.

앱은 권한에 따라 “내 대기 정보” 또는 “대기 명단”을 표시하고 자신의 순번을 강조한다. 게스트는 계정 사용자의 사람 미리보기로 연결하지 않는다. 승격 행동은 모임 전체와 해당 행의 서버 허용 값이 모두 참일 때만 표시한다. 초기 로딩·오류 재시도·빈 목록을 구분하고 재조회 중에는 이전 목록을 유지한다. 목록이 있을 때 당겨 새로고침을 제공한다.

수동 승격의 조건과 결과

회원은 회원 번호, 게스트는 참석 행 번호로 승격한다. 서버는 모임과 대상 행을 잠그고 명단 관리 권한·접근·차단을 확인한다. 종료·취소 모임, 유료 또는 선입금 대상 모임, WAITING이 아닌 행, 소유자가 없는 행, 제재 중인 신청 주체는 거절한다. 게스트는 예약한 본인이 이미 ATTENDING이어야 한다.

그다음 실제 참석 행 수에 예약 좌석을 더해 배치 정책을 적용한다. ATTENDING 또는 허용된 OVERCAPACITY 결과여야 승격하며, WAITING/FULL이면 정원 부족으로 거절한다. 성공하면 한 행을 참석으로 바꾸고 정원을 한 자리 늘리며 수동 처리자·이전 순번의 로그를 남긴다. 남은 대기 순번을 다시 매기고 해당 회원 또는 게스트 소유자에게 승격 알림을 저장한다.

앱은 성공 안내 뒤 대기 목록·모임 상세·카드·주최 목록을 갱신한다. 자리가 없으면 수용인원을 늘린 뒤 재시도하라는 안내를, 게스트 소유자가 참석 중이 아니면 본인 참석 확정이 먼저라는 안내를 한다. 이 안내가 설정 화면으로 자동 이동하는 것은 아니다. 현재 대기 명단의 승격 단추는 별도 확인 대화상자 없이 요청을 시작한다.

자동 승격·제재·알림

참석 취소·제거로 해제된 자리와 정원 증가가 자동 승격을 연결한다. 대기 순서대로 보되 소유자가 없는 행, 신청 제한을 받은 본인·게스트 소유자, 본인이 아직 참석 중이 아닌 게스트는 건너뛴다. 건너뛴 행은 자동 거절·취소하지 않고 대기에 남긴다. 따라서 무조건 순번 1번이 다음 참석자가 된다고 설명하지 않는다.

빈자리 하나의 승격은 한 행을 처리하고, 정원 증가는 계산된 빈자리 한도까지 처리한다. 성공마다 참석 상태·정원·승격 사유 로그·순번을 갱신하며 회원 행이면 참가 시작 후속을 발행한다. 알림은 승격 로그 번호로 중복 저장을 제한해 대기열에 남긴다. 실제 푸시 수신은 별도 전달 결과다.

종료·취소 상태의 모임에는 빈자리 자동 승격을 하지 않는다. 유료 전환 시 기존 대기 행이 남아 있으면 거절하는 검사가 있다. 유료 결제 대기의 기한 만료를 무료 대기자 자동 승격과 같은 흐름으로 설명하지 않는다.

참가자 제거와 취소 뒤 대기열

참석자 목록의 제거는 확인 대화상자를 거치며 자기 자신 제거는 서버에서 거절한다. 공개 제거 경로에서 지갑 결제가 완료된 신청을 찾으면 호스트 귀책 환불로 연결한다. 그 밖의 활성 결제·환불 대기·열린 보관금은 참석 행만 지워 우회할 수 없고, 환불이 필요하다는 오류와 관련 안내를 따른다. 계좌이체 반환이나 개별 유료 게스트 제거를 이 단추가 항상 완료한다고 쓰지 않는다.

무료 제거는 본인과 소유 게스트를 정리하고 체크인·이동수단·참가 종료 후속을 연결한다. 실제로 해제한 참석 자리만 정원에서 빼며 그 자리 수만큼 자동 승격을 호출하고 대기 순번을 정리한다. 종료·취소 상태에서는 호출된 승격 본체가 참가자를 올리지 않는다. 앱은 목록에 남아 성공을 알리고 명단·주최/과거/참석 목록·모임 상세·카드·지갑에 필요한 갱신을 알린다. 결과 불명 오류에도 반영 가능성을 고려해 다시 조회한다.

모집 마감·재개와 요청 재시도

수용인원 설정의 모집 상태 구역은 모임을 연 호스트이면서 정기모임 회차가 아닐 때 표시한다. 마감은 기존 참석·대기자가 남는다는 확인을 받고, 다시 시작은 별도 명령으로 보낸다. 성공 후 설정 화면에 남아 모집 상태와 상세·카드를 갱신한다. 설정 저장과 모집 변경을 동시에 누르지 못하도록 처리 중 행동을 막는다.

마감·재개는 정원 설정 본문의 필드가 아니며 별도 필수 요청 번호를 사용한다. 두 공개 경로와 별칭은 같은 명령 실행기로 연결된다. 앱은 이전 마감/재개의 결과가 불명인 채 반대 명령을 선택하면 이전 요청부터 같은 번호로 정리한 후 새 명령을 보낸다. 일반 설정 저장·승격의 번호도 동일 요청 재시도에 재사용하지만 세션 메모리 보관이므로 앱 재시작 이후 영속 재생으로 설명하지 않는다.

모집 다시 시작은 모집 마감 표지만 바꾼다. 종료·취소된 모임의 생명주기를 OPEN으로 되돌리는 명령이 아니며 서버의 설정 저장 가능 상태 검사와도 구별한다.

W1의 초과 정원 정책과 고급 설정 창구 정리, 2026-11-08 예약 좌석 통합·유료 대기 제한은 변경 이력으로 보존한다. 과거 시드 모임 번호·자체 원복 시험 메모·옛 WAITLISTED 호환 설명을 현재 제품 수용 기준으로 사용하지 않는다. 현재 실제 참석 대기 상태는 WAITING이다.

수용 기준과 검증 근거

  • AC-01 업무별 권한: 정원 설정·대기 조회·승격·모집 변경·회원 제거의 권한을 각각 적용하며 화면 접근만으로 쓰기를 허용하지 않는다.
  • AC-02 입력 한도: 기본 정원 1 이상, 최대 대기 0 이상, 게스트 허용 시 최대 1~9명을 검사한다. 대기 상한 0은 기본 정원 두 배다.
  • AC-03 저장 가능 상태: 종료·취소 모임과 정기모임 회차는 설정만 바꾸는 요청도 거절한다. 누락 필드는 유지한다.
  • AC-04 기존 신청 유지: 대기열·승인제를 꺼도 기존 대기자와 심사 중 신청을 일괄 처리하지 않는다.
  • AC-05 정원 축소: 실제 참석과 결제 대기·미확인 일행 추가 예약의 합보다 작게 줄이지 못하며 같은 값은 허용한다.
  • AC-06 정원 확대: 실제 참석과 예약 좌석을 뺀 빈자리까지만 적격 대기자를 승격하고 남은 순번을 다시 매긴다.
  • AC-07 대기 공개: 일반 대기자는 본인 일행만 받고 원래 순번을 유지한다. 반환 건수를 전체 모임 대기 총수로 확대하지 않는다.
  • AC-08 수동 승격 자리: 정원·하드 상한·예약 좌석 때문에 자리가 없으면 WAITING과 정원을 바꾸지 않는다.
  • AC-09 수동 승격 대상: 종료·취소·유료 모임, 비대기 행, 제재 대상과 참석 중인 소유자가 없는 게스트는 해당 조건으로 거절한다.
  • AC-10 자동 승격 후보: 제한된 후보는 건너뛰어 다음 적격 행을 고르고 제외한 행을 임의 취소하지 않는다.
  • AC-11 제거와 환불: 지갑 완료 참가자의 제거는 호스트 귀책 환불로 연결하고 다른 금전 의무는 참석 행 삭제로 우회하지 않는다.
  • AC-12 저장 실패 복귀: 저장이 거절돼도 입력 폼과 수정 값을 유지한다. 성공하면 관련 조회를 갱신하고 이전 화면으로 돌아간다.
  • AC-13 모집 변경: 호스트의 마감 확인 뒤 기존 참석·대기를 유지하고, 재개는 모집 표지만 바꾼다. 불확실한 반대 명령은 이전 결과부터 정리한다.
  • AC-14 이력과 알림: 승격마다 해당 사유·이전 순번·처리자 정보를 남기고 알림 저장을 연결하되 기기 수신 완료로 표시하지 않는다.

기존 WaitlistServiceTest의 정원·하드 상한·예약 좌석에 의한 수동 승격 거절, 본인 순번만 조회하는 단언을 읽었다. EventCapacitySettingsServiceTest는 예약을 포함한 축소 경계를, CapacitySettingsServiceUpdateSettingsTest는 종료 상태 거절과 기존 대기 유지, capacity_settings_save_rejection_test.dart는 저장 거절 뒤 폼·입력 유지를 모의 조건에서 단언한다. 이 제품 시험을 새로 실행하지 않았다.
