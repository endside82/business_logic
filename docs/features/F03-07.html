F03-07. 정원·대기열 관리 (호스트)

정원·대기열·승인제·게스트 정책을 설정하고, 대기자를 승격하거나 참석자를 제거하는 운영 화면. 서버에는 모집 마감/재개와 초과정원 정책도 있지만 현재 Flutter 화면에서는 호출할 수 없다. 사용자 측 대기열 신청은 F03-05에서 처리된다.

모임 취소와 종료 뒤의 신청·대기열

주최자 단건 취소뿐 아니라 클럽 운영진·반복 모임 일괄 취소·정기모임 회차 취소·클럽 폐쇄에서도 심사 대기와 결제 대기 신청을 함께 닫습니다. 이미 끝난 모임에서 참가자를 빼더라도 다음 대기자를 자동으로 올리지 않습니다.

참가자 제거 자체와 남은 대기 기록의 일괄 종료는 별개입니다. 계좌이체 취소는 계좌이체 취소에서 돌려받을 금액을 먼저 확인합니다를 따릅니다.

정원 설정 조절값
6개
대기·게스트 하위값 2개는 조건부 노출
자동 승급 트리거
2가지
정원 확장 · 다른 사용자 취소
설계 의도 — 정원 변경 한 번이 여러 사용자에게 동시 영향

호스트가 정원을 10에서 15로 늘리면 대기열 1~5번까지가 한 번에 자동 승급되고, 서버는 각각에 WAITLIST_PROMOTED 알림 생성을 요청한다. 실제 in-app 저장과 비동기 push는 각 사용자의 채널 설정에 따라 생략될 수 있다. 그래서 본 단위의 동작은 정원 수치 변경에서 끝나지 않고, 대기열 재정렬·자동 승급·설정별 알림 처리까지가 같이 일어나야 한다. 호스트가 "정원을 늘렸다"고만 인지해도 사용자 측에서는 "대기열에서 참석으로 바뀌었다"는 결과가 나와야 한다.

2026-07-29 소스 재실측 — 정원 설정 권한의 단일 기준

서버는 상세 응답의 canManageCapacity를 호스트·공동호스트·클럽 ADMIN/OWNER에게만 참으로 계산한다. Flutter는 이 값을 “수용인원 설정” 행과 route guard에 그대로 사용하며, 기본 설정 조회·저장 API도 같은 범위를 허용한다. 수동 승격·강제 제거·참석 로그는 별도 canManageAttendance 권한이다. 한편 초과정원 고급 API PATCH /capacity-settings는 아직 호스트·공동호스트만 허용하므로 클럽 운영진 범위가 기본 설정 API와 다르다. 더구나 이 PATCH는 API·Repository까지만, 모집 마감/재개는 Provider까지만 연결되어 둘 다 화면 CTA가 없다.

사용자 시나리오

자동 승급

정원을 10 → 15로 확장

호스트가 정원 설정에서 기본 정원을 변경. 대기열 1~5번까지가 자동으로 참석 확정으로 전환되고 5명 각각에 알림 생성이 요청된다. 채널 설정에 따라 in-app/push는 생략될 수 있다. 대기열에 남은 6·7·8번은 1·2·3번으로 순번이 재정렬.

이 흐름이 남기는 것 — 정원 변경 한 번이 다수 사용자에게 동시 영향을 준다. 상태 전이는 서버 트랜잭션으로 확인하고 알림은 설정별 결과를 따로 확인해야 한다.

수동 승급

대기열의 단골을 우선 승격

호스트가 대기열 화면에서 특정 사용자의 "승격" 버튼을 누른다. 그 사용자는 참석 확정으로 전환되고, 현재 인원이 한 명 늘어난다. 다른 대기자들의 순번이 재정렬.

이 흐름이 남기는 것 — 수동 승격도 정원 규칙을 그대로 통과해야 한다. 초과 정원을 허용하지 않았거나 절대 한도에 닿았으면 승격이 거절되고, 이미 끝났거나 취소된 모임과 제재 중인 사용자도 승격 대상이 아니다. 호스트의 재량은 정원 안에서만 쓰인다.

강제 제거

노쇼 우려 사용자를 미리 제거

이전 두 번 무단 결석한 사용자가 또 신청한 상태. 참석자 목록에서 "제거"를 누르면 확인 후 그 사용자는 취소 상태로 전환되고, 1번째 대기자가 자동 승급된다. 체크인 기록이 있었다면 함께 정리.

이 흐름이 남기는 것 — 호스트의 안전 운영 도구. 잠재 노쇼를 사전에 제거해 모임의 실질 운영 인원을 보장.

모집 마감

호스트가 정원 관리 화면에서 모집을 마감하고 다시 연다

모임을 연 호스트에게만 「모집 마감」·「모집 재개」 단추가 보인다(정기모임 회차 제외). 마감은 확인 창을 거친다. 서버는 이벤트 행을 잠근 뒤 호스트인지 확인하고 마감 여부를 바꾼다.

결과. 마감 여부에 따라 단추가 바뀐다. 결과를 모르면 설정을 다시 읽는다. 정원 설정 저장은 마감 칸을 싣지 않아 마감한 모임을 조용히 다시 열지 않는다.

대기열 알림 수신

참가자 시점 — 자동 승급 알림

본인이 대기열 1번. 다른 사용자가 취소 → 자동 승급 → 서버가 WAITLIST_PROMOTED 알림 생성을 요청한다. 채널 설정이 허용하고 비동기 push가 성공한 경우에만 push로 인지할 수 있다.

이 흐름이 남기는 것 — 사용자가 자기 상태 변화를 인지하지 못하면 노쇼로 이어진다. 알림 도달을 상태 전이의 성공 조건으로 단정할 수 없다.

잘못된 승격 시도

이미 참석 중인 사용자를 승격 시도

호스트가 오타로 이미 참석 중인 사용자에 "승격"을 누른다. "참석자 승격에 실패했습니다" 안내. 상태 변경이 일어나지 않는다.

권한

일반 사용자가 정원 설정 URL 진입

canManageCapacity=false인 일반 사용자는 URL로 진입해도 이벤트 상세로 리다이렉트되고 우회 API 호출도 서버에서 차단된다. 호스트·공동호스트뿐 아니라 클럽 이벤트의 ADMIN/OWNER는 canManageCapacity=true로 기본 정원 설정 화면에 들어갈 수 있다.

화면에서 사용자가 인지하는 것

화면사용자가 보는 것그 자리에 둔 이유
참석자 목록 현재 참석자 N / 정원 M명 헤더, 본인 상태 카드, 닉네임 검색, 카드별 "승격"·"제거" 버튼(canManageAttendance 운영자). 호스트뿐 아니라 권한 있는 공동호스트·클럽 출석관리자가 같은 화면에서 운영한다.
대기열 상단 "대기열 (N명)" 배너, 순번 표시 카드. canManageAttendance 운영자는 카드마다 "승격" 버튼, 본인이 대기 중이면 "내 대기 순번 N번" 카드. 대기열은 순번이 핵심 정보. 순번이 명확하지 않으면 사용자가 자기 위치를 가늠하지 못한다.
정원 설정 폼 기본 정원(최소 1), 대기열 활성, 조건부 최대 대기, 승인제, 게스트 동반 허용, 조건부 예매당 최대 게스트(1~9), "저장" 버튼. 정원·대기·승인·게스트 정책을 한 화면에서 함께 결정.
제거 확인 다이얼로그 "닉네임님을 참석자에서 제거하시겠습니까?" 빨강 강조 + 확인 버튼. 제거는 사용자에게 큰 영향을 주는 동작이므로 한 단계 더 강조해서 확인을 받는다.

운영자가 알아야 할 것

정원·대기열 운영의 결정점
  • 정원 변경 시 자동 승급·알림이 한 동작 안에서 일어나야 한다. 정원만 늘리고 자동 승급이 누락되면 "정원은 늘었는데 대기열에 사람이 그대로"라는 사고가 발생.
  • 수동 승격도 정원 규칙 안에서만 된다. 기본 정원과 절대 한도를 함께 검사하므로 호스트가 승격만으로 정원을 무한정 넘길 수 없다. 초과 정원을 허용한 모임에서만 기본 정원을 넘겨 받을 수 있고, 그때도 절대 한도가 상한이다.
  • 강제 제거 시 체크인 기록도 같이 정리된다. 잘못 제거하면 체크인 기록까지 사라지므로, 제거는 한 번 더 확인 단계를 거친다.
  • 클럽 모임에서 나가도 참석 행은 지우지 않는다. 행을 취소(CANCELLED)로 남기고 참석 기록을 적으며, 이미 한 체크인과 체크인으로 받은 점수를 함께 정리한다. 다시 참가하면 같은 행을 앞 신청·결제 연결 없이 되살린다.
  • 모집 마감/재개는 모임을 연 호스트가 정원 관리 화면에서 한다(정기모임 회차 제외). 초과정원 설정은 현재 서버 측 기능이고 Repository까지만 있어 앱 CTA가 없다.
  • 알림 생성 요청과 도달은 다르다. in-app/push 설정으로 생략될 수 있고 push는 비동기이므로 “모두 도달”을 상태 전이의 수용 기준으로 삼지 않는다.

이 기능의 출시 완료 기준

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 첫 출시 포함 여부와 구현·검사 현황은 위 상태표를 따릅니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 정원 변경과 대기자 승격 후 확정 인원·대기 순서·참가자 화면이 일치한다.
  • 동시 승인·취소·정원 축소에도 초과 확정이나 같은 회원의 중복 승격이 생기지 않는다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 이벤트의 관련 완료 기준도 함께 확인합니다.
