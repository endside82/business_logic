F03-20. 이벤트 노쇼 관리

이벤트가 끝난 후, 참석 확정됐지만 나타나지 않은 사람을 기록하고 그 결정에 이의를 제기할 수 있게 한다. 호스트의 확정 → 참가자의 소명 → 결정 뒤집기로 이어지는 3단계 절차와, 노쇼 확정 후 사정이 생긴 경우 호스트가 부분 환불을 줄 수 있는 사후 조정 환불이 이 단위의 두 축이다.

설계 의도 — 호스트 기록이 최종이 아니다

이벤트 당일 연락 없이 불참했다는 사실은 호스트가 가장 잘 안다. 그래서 확정 권한은 호스트에게 있다. 그러나 호스트가 체크인을 놓쳤거나 참가자에게 예외적 사정이 있었을 수 있다. 때문에 확정된 노쇼에 대해 참가자가 소명할 수 있고, 해당 모임의 호스트·출결 권한을 받은 공동호스트·클럽 운영진이 이를 인정해 뒤집거나 기각할 수 있다. 시스템 관리자는 일반적인 모임 운영 판단에 관여하지 않는다. 뒤집힌 노쇼는 제재 누적 카운트에서 제외된다. 회원은 정정 체크인도 생성되어 체크인 기반 공동참석 증거에 다시 포함되고, 원래 노쇼 기록은 감사 목적으로 남는다.

2026-08-30 현재 소스 재확인

노쇼 확정·일괄 확정·목록·직접 소명·소명 증빙 열람·번복·기각의 서버 API 7개와 Flutter 계약이 대응한다. 앱의 노쇼 관리 목록에서 일괄 확정, 소명 검토, 번복과 기각, 사후 조정 환불 화면으로 들어갈 수 있다. 참가자는 같은 모임 안에서 직접 소명한다. 플랫폼 분쟁 접수와 시스템 관리자 번복은 기본 설정에서 함께 닫혀 있어 모임 운영 판단이 플랫폼 운영팀으로 넘어가지 않는다. 번복된 회원에게 기존 체크인이 없으면 서버가 method=NOSHOW_OVERTURN 정정 체크인을 한 번만 만든다. 다만 환불 확인 대기 제외는 일괄 확정에만 적용되고, 단일·일괄 확정 모두 이벤트 종료 시각을 서버에서 강제하지 않는다.

사용자 시나리오

기본 흐름 — 호스트

이벤트 후 체크인 안 한 참가자를 노쇼로 기록

참석자 목록의 노쇼 관리 섹션에서는 체크인하지 않은 인원을 일괄 확정하고, 이미 확정된 노쇼를 번복할 수 있다. 한 명을 사유·증빙과 함께 확정하는 화면은 참석자 행이 아니라 호스트 사건 상세 화면에 있다. 이 단건 화면은 계정이 있는 회원만 대상으로 삼을 수 있어, 계정 없는 게스트 한 명만 골라 확정하는 화면은 아직 없다.

처리 결과 — 노쇼 기록은 이후 제재 횟수를 계산하는 근거로 남는다. 사유와 증거를 함께 남기면 소명 단계에서 판단 근거가 된다.

참가자 — 소명

불가피한 사정이 있었는데 노쇼로 기록됐다

회원 참가자 또는 게스트를 예약한 사람은 참석자 화면의 "소명할게요"를 눌러 사유와 증빙을 제출한다. 플랫폼 운영팀에 보내는 통합 분쟁 화면이 아니라 해당 모임 안에서 호스트와 운영 권한자가 검토하는 직접 소명이다. 소명 진행 중에는 제재 누적이 여전히 유지되지만, 해당 모임의 운영 권한자가 뒤집으면 누적에서 제외된다.

처리 결과 — 서버가 소명 가능 여부와 마감 시각을 계산해 앱에 내려준다. 7일 기한이 지났거나 이미 기각된 건에는 버튼이 보이지 않는다. 게스트 노쇼도 예약자가 자기 일행 이름을 확인하고 대신 소명할 수 있다.

뒤집기

호스트가 체크인을 놓쳐서 잘못 기록됐다

호스트·출결 권한을 받은 공동호스트·클럽 운영진이 "노쇼 아님"으로 뒤집을 수 있다. 뒤집기 사유를 입력하면 해당 노쇼 기록은 제재 카운트에서 빠진다. 회원에게는 기존 체크인이 없을 때 NOSHOW_OVERTURN 정정 체크인이 함께 생겨 공동 참석, 적합도, 재방문 판단에 쓰이는 기록에도 다시 반영된다. 게스트는 계정 기반 기록의 주체가 아니어서 정정 체크인을 만들지 않는다. 기록 자체는 감사 목적으로 남아 있다.

사후 조정 환불

노쇼이지만 호스트가 부분 환불을 주기로 했다

서버 상한은 원 결제의 유료+무료 총액에서 이미 완료된 일반/선결제 환불을 뺀 잔액이다. 양수 환불은 원 결제의 유료·무료 비율대로 나뉘어 지갑에 복구되고 정산금 회수 경로를 거친다. 0원도 허용되어 돈 이동 없이 결정 기록만 남길 수 있다.

현재 제약 — 서비스는 대상 신청에 실제 노쇼 기록이 있는지 검사하지 않는다. 화면도 원 결제액을 조회하지 않아 paidAmount=0으로 진입하고, 서버 상한만 최종 방어로 남는다.

제재 연계

같은 사람이 여러 번 노쇼가 됐다

노쇼 카운트는 일정 기간 내 누적으로 집계되고, 소유 게스트의 노쇼도 예매자에게 합산되며, 뒤집힌 건은 빠진다. 이 서비스는 정책 입력용 카운트만 제공한다. 자동으로 제재를 부여하거나 집행하는 기준은 이 서비스에 구현돼 있지 않다.

운영자가 알아야 할 것

운영 주의사항
  • 환불 확인 대기 중인 참가자는 노쇼 확정 대상에서 제외된다. 계좌이체 취소 후 호스트의 환불 확인을 기다리는 참가자는 일괄 확정 목록에 포함되지 않는다. 단, 한 명만 확정하는 요청은 신청 상태를 검사하지 않아 같은 보호가 적용되지 않는다.
  • 같은 참가자를 노쇼로 두 번 확정해도 한 건으로만 기록된다. 실수로 두 번 눌러도 기존 기록이 그대로 유지되며 중복 기록이 만들어지지 않는다.
  • 소명 기한은 노쇼 확정 후 7일이다. 7일이 지난 노쇼는 소명할 수 없다(요청 거부). 서버가 계산한 소명 가능 여부와 마감 시각을 앱이 받아, 기한이 지나면 소명 버튼 대신 만료 안내를 표시한다.
  • 사후 조정 환불은 유료·무료 포인트를 합친 원결제액에서 기존 완료 환불을 뺀 잔액을 초과할 수 없다. 초과 금액 입력 시 서버가 거부한다. 환불금은 원결제의 유료·무료 비율대로 나뉘어 지갑에 각각 입금되므로 무료 포인트 몫이 유료로 바뀌지 않는다.
  • 같은 신청 건에 대해 환불을 두 번 제출할 수 없다. 신청 기록을 잠근 뒤 기존 환불을 확인하므로 동시에 두 번 눌러도 한 건만 처리된다. 데이터베이스의 단일값 제약이 아니라 서비스의 잠금과 재검사로 보장한다.
  • 사후 조정 환불 권한은 별도로 제한된다. 호스트, 환불 처리 권한을 받은 공동호스트, 클럽의 환불 담당자만 실행할 수 있다. 환불 내역 조회는 이 집행 권한자와 해당 신청자 본인만 가능하며, URL의 이벤트와 실제 환불 기록의 이벤트가 다르면 조회되지 않는다.
  • 환불 성공이 참가자 알림 발송을 뜻하지 않는다. 현재 소스에는 알림이나 발송 대기열 호출이 없고, 화면의 “참가자에게 안내됩니다” 문구만 남아 있다.

남아 있는 문제와 주의점

출시 범위를 정할 때 확인할 사항
  • 회원과 예약한 게스트 모두 앱에서 직접 소명할 수 있다. 참석자 목록의 상태 카드에서 사유와 증빙을 제출한다. 게스트는 예약자가 대신 제출한다. 호스트·권한 있는 공동호스트·클럽 운영진은 별도 노쇼 관리 섹션에서 소명을 읽고 인정 또는 기각한다. 소명 버튼은 서버의 가능 여부와 마감 시각을 그대로 따른다.
  • 체크인 관리 권한이 없는 공동호스트는 노쇼를 확정하거나 뒤집을 수 없다. — 체크인과 노쇼가 같은 권한 판정을 공유한다. 사후 환불도 별도 환불 처리 권한을 검사하므로 공동호스트라는 이유만으로 돈을 움직일 수 없다.
  • 노쇼 환불을 이미 줬는지 앱에서 확인할 수 없다 — 제출 이력 조회 화면이 없어 호스트가 같은 참가자에게 중복으로 시도할 수 있다. 중복 제출 자체는 시스템이 차단하므로 돈이 두 번 나가지는 않는다.
  • “노쇼 환불”이 실제 노쇼 기록과 직접 연결돼 있지 않다. 환불 서비스는 신청과 이벤트가 일치하는지만 확인하고 실제 노쇼 기록의 존재·상태를 조회하지 않는다. 노쇼가 없는 신청도 처리될 수 있고, 확정·소명·뒤집힘 중 어떤 상태를 허용할지도 강제하지 않는다.
  • 환불 화면 진입은 살아 있지만 원 결제액 표시는 불완전하다. 노쇼 관리 목록이 실제 신청 번호와 이벤트 번호를 사용해 환불 화면을 연다. 과거 분쟁 번호를 신청 번호로 잘못 쓰던 경로는 제거됐다. 다만 원 결제액을 조회하지 않아 paidAmount=0으로 열리므로 화면의 금액 안내와 자체 상한은 도움이 되지 않고, 최종 초과 지급 방지는 서버 상한 검사에 의존한다.
  • 이벤트 종료 전에도 확정 요청이 통과할 수 있다. 단일·일괄 서비스와 관리자 버튼 모두 종료시각을 강제하지 않는다. 운영 문구에는 "이벤트 종료 후"라고 적혀 있지만 서버가 이를 필수 조건으로 보장하지 않는다.
  • 소명·번복·기각 주소의 이벤트 번호와 실제 노쇼의 이벤트 번호를 맞추지 않는다. 권한은 실제 노쇼가 속한 이벤트로 다시 검사하므로 다른 모임의 권한을 빌려 처리할 수는 없다. 다만 잘못된 주소로도 처리가 가능해 요청 주소와 처리 대상의 의미가 어긋난다.
  • 환불 후 자동 알림과 별도 분쟁 기록 생성은 구현돼 있지 않다. 서버는 내부 추적용 문자열만 환불 기록에 저장하며, 참가자에게 보낼 알림이나 별도로 조회할 수 있는 분쟁 사건을 만들지 않는다.
