F07-07 다시 알림·마감 연장·알림 기록

실제 지급자·송금 신고·수신자별24시간·마감 기준 시각·자동 처리 주기·입력/이력 표시와 요청/수신의 차이를 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

진행 중 정산의 관리자는 아직 내야 할 돈이 남은 사람에게 다시 알림을 요청하거나 마감을 연장한다. 실제 발송 대상은 서버가 지급 방향·완료 상태·송금 신고·최근 알림 기록으로 다시 계산한다. 받기만 하는 사람이나 납부를 마친 사람에게 일괄 재촉하지 않는다.

수동·자동·연장 알림은 같은 정산·같은 수신자에 대해 24시간 간격을 공유한다. 성공 응답은 요청 처리가 끝났다는 뜻이며, 대상이 없거나 시간 제한에 걸리면 실제 새 알림 기록이 없을 수 있다. 발송 의도를 저장한 사실을 휴대전화 푸시 수신 완료로 쓰지 않는다.

실제 입구와 관리 권한

입구현재 제공 범위
진행 중 정산 현황의 진행 카드관리자에게 다시 알림·마감 연장, 마지막 알림 시각·묶음 횟수를 제공한다. 완료 정산에는 이 진행 카드를 만들지 않는다.
송금 목록 하단정산 생성자에게 ‘입금 확인 다시 알리기’를 제공한다. 현재 목록에 일반 대기·혼합 은행 확인 대기가 있는지 먼저 확인하고 서버에 다시 알림을 요청한다.
자동 알림서버 스케줄 작업이며 앱에서 별도 실행 버튼을 제공하지 않는다.

서버의 수동 알림·연장은 현재 정산을 잠그고 관리자와 ACTIVE 상태를 확인한다. 관리자는 기본적으로 정산 생성자다. 생성자 번호가 없는 자료에만 현재 모임 호스트를 대신 확인한다. 이력 조회는 생성자 번호를 직접 검사한다. 검사 함수 이름에 호스트가 들어가더라도 현재 호스트 전체에 권한을 주는 것으로 해석하지 않는다.

현황 화면의 관리자 표시는 현재 모임 호스트 기준이다. 호스트 변경으로 생성자와 달라지면 입구 표시와 서버 허용이 어긋날 수 있다. 조회·초안과 원본 이력의 다른 조건은 정산 현황·금액 요약·영수증 열람을 따른다.

실제 지급자별 알림 대상

방식서버의 대상 계산
직접 송금PENDING 또는 BANK_AWAITING_CONFIRM 송금의 보내는 사람을 모은다. 신고된 송금은 제외하고 같은 사람이 여러 건을 보내도 한 명으로 합친다. 받기만 하는 사람은 제외한다.
항목별 납부완료되지 않았고 실제 낼 금액이 0보다 큰 사람을 모은다. 자기 몫을 제외한 미완료 지급 의무를 실제 낼 사람별로 묶고, 그 사람의 남은 몫이 모두 ‘보냈어요’이면 제외한다.
수동 다시 알림·연장 알림위 대상에서 요청자 자신을 제외한다. 선택한 대상 번호를 API로 넘기면 현재 대상과 교집합을 취하고 중복을 제거한다. 번호가 없거나 빈 목록이면 전체 대상이다.
자동 알림요청자 자신을 제외하는 규칙이 없다. 정산 생성자도 실제 낼 돈이 남으면 대상일 수 있다.

수입 배분에서는 수입 보유자가 내는 사람이고 배분받는 사람은 받는 사람이다. 따라서 예전의 ‘분담 행에 적힌 참가자’ 또는 ‘호스트에게 낼 참가자’만 대상으로 삼는 설명은 맞지 않는다. 직접 송금의 정보성 분담 완료 표시로 실제 송금 의무를 대신 판단하지 않는다.

앱의 현재 시트는 덧붙일 말만 받으며 개별 대상 선택을 제공하지 않는다. 목록의 후보 수와 서버의 실제 등록 수는 신고·권한·24시간 제한 때문에 다를 수 있다.

수동 요청과 24시간 제한

수동 요청은 현재 정산의 상태·관리 자격과 덧붙일 말 길이를 확인한다. 대상이 없으면 오류 대신 처리를 마친다. 각 대상에 대해 정산·회원 단위 잠금과 마지막 알림 기록을 확인하며, 24시간이 지나지 않았거나 다른 처리가 잠금을 사용하면 그 대상을 건너뛴다. 마지막 알림의 종류가 수동·자동·연장 중 무엇이었는지는 이 간격을 나누지 않는다.

허용된 대상은 수신자·발신자·종류·시각의 기록과 발송 의도를 같은 업무 트랜잭션에 저장한다. 발송 의도에는 알림 기록 번호 기반 중복 방지 키를 사용한다. 수동·연장 알림은 사람 발신자를 싣고 자동 알림은 개인 발신자 없이 업무 알림으로 등록한다.

API 응답은 본문 없는 성공이며 등록 수나 건별 건너뛴 사유를 반환하지 않는다. 앱은 ‘다시 알림 요청을 처리했습니다’ 또는 ‘다시 알림을 요청했습니다’라고 표시한다. 이 문구를 전원 발송·전원 수신의 증거로 확대하지 않는다.

덧붙일 말과 입력 결과

다시 알림 시트와 알림을 켠 마감 연장 시트에는 선택 입력 200자 제한과 수신 문구 미리보기가 있다. 앱은 앞뒤 공백을 제거하고 빈 입력은 보내지 않는다. 서버도 200자를 넘으면 정산 처리 전에 거절한다. 모임 이름·기본 안내와 덧붙일 말은 별도로 전달한다.

입력 중 취소·닫기는 작성 내용 이탈 보호를 거친다. 발송/연장을 확정하면 시트가 먼저 닫히고 요청을 보낸다. 요청 실패 시 오류를 표시하지만 작성한 말을 시트에 자동 복원하는 흐름은 현재 없다. 진행 중이 아닌 정산이라는 거절은 관련 정산 자료를 다시 읽는다.

마감 연장의 계산과 알림

서버는 한 번에 1~168시간을 받는다. 현재 앱은 24·48·72·168시간 선택지를 제공하고 초기값은 24시간이다. ‘함께 다시 알림’은 처음에 꺼져 있으며 켰을 때만 덧붙일 말 입력을 보여 주고 전달한다.

마감이 있으면 기존 마감 + 선택 시간, 마감이 없으면 현재 시각 + 선택 시간으로 계산한다. 이미 오래 지난 마감에 짧은 시간을 더하면 결과도 과거일 수 있다. 항상 지금 이후로 이동하거나 전체 누적 연장이 7일로 제한되는 기능으로 설명하지 않는다.

연장 성공은 자동 알림 실행 표지를 비우고 스케줄 중복 억제 키 제거를 시도한다. 선택한 경우에만 현재 지급 의무 대상에게 연장 알림을 등록하며, 이 경우에도 같은 수신자의 24시간 제한을 적용한다. 마감 연장 성공과 새 알림 등록은 독립적으로 읽어야 한다. 알림을 켰다는 이유로 제한을 우회하지 않는다.

앱은 진행 중 연장 요청을 중복 실행하지 않고, 성공 응답의 새 마감을 표시·반영한다. 이전 계정의 결과는 현재 상태에 적용하지 않는다. 그러나 API 자체에는 연장 명령 식별자 계약이 없어 같은 요청을 나중에 다시 보내면 기존 마감에 시간을 다시 더한다. 응답 유실 후 무조건 재시도를 안전한 동일 명령 재생으로 설명하지 않는다.

자동 알림의 한 주기

스케줄러는 30분마다 진행 중·마감 있음·자동 알림 간격 있음·자동 처리 표지 없음 조건의 후보를 찾는다. 마감에 설정된 시간을 더한 시점이 지났는지 확인하고, 처리 서비스가 잠근 최신 상태에서도 다시 검사한다. 스케줄 중복 억제 키는 30분이며 호출 실패 시 다음 실행을 위해 제거를 시도한다.

실제 미납 의무가 없으면 자동 처리 표지를 저장한다. 반면 아직 의무가 있지만 전부 신고되어 대상에서 빠진 경우에는 표지를 남기지 않아, 신고 철회 후 다시 판단할 수 있다.

대상 처리를 시도한 뒤에는 자동 처리 표지를 남긴다. 이때 각 대상이 24시간 제한 등으로 건너뛰어져 새 발송이 없더라도 표지가 저장될 수 있다. 매일 반복해서 미납자를 재촉하는 스케줄이 아니다. 마감 연장으로 표지가 초기화되면 새 조건에 따라 다시 판단한다. 스케줄 설정·코드 대조는 운영 실행 시각이나 실제 알림 수신 증명이 아니다.

알림 기록과 화면 표시

현재 정산의 생성자는 서버에서 수신자별 기록을 최신순으로 조회할 수 있다. 기록에는 정산·수신자·발신자·MANUAL/AUTO/EXTEND·시각이 있으며 실제 기기 수신 결과는 없다. 취소된 정산을 제외한 현재 정산의 기록이며, 과거 정산 전체 이력을 하나로 합치는 조회가 아니다.

현재 앱에는 별도 수신자별 이력 목록 화면이 없다. 진행 카드가 마지막 시각과 종류 + 분 단위 시각으로 묶은 횟수를 표시한다. 수신자 수·요청 횟수·푸시 수신 횟수와 같은 값이 아니다. 같은 종류의 두 요청이 같은 분에 있으면 한 묶음으로, 한 처리의 기록이 분 경계를 넘으면 여러 묶음으로 표시될 수 있다.

카드의 다시 알림 잠금은 정산 전체의 마지막 기록으로 24시간을 계산한다. 서버의 수신자별 제한보다 넓어, 이전에 알림을 받지 않은 새 대상도 카드에서는 기다리게 될 수 있다. 이력 조회 실패·대기 시에는 현재 카드가 이력을 빈 목록처럼 다루므로 ‘기록이 없다’는 확정 근거로 사용하지 않는다.

수입·송금 신고·취소 이후의 구분

수입 보유자의 지급 의무와 신고 제외는 실제 내는 사람 기준으로 계산한다. 신고된 송금이 오래 미확인으로 남거나, 혼합 은행 확인·직접 반환 대기가 길어지는 상황은 이 문서의 일반 재촉과 다른 알림 경로다.

취소된 정산에 일반 수동 재촉·마감 연장을 실행하지 않는다. 취소 이후 수취 확인·환불 필요 알림·장기 대기 경보는 수취 확인·만료·재요청·손실 정리와 정산 취소와 반환을 따른다. 일반 재촉에서 제외되었다는 이유로 지급·반환 의무가 사라진 것은 아니다.

현재 제한과 확인 범위

분류확인 내용영향과 다음 확인
Gap진행 카드는 정산 전체 마지막 시각으로 알림을 잠그지만 서버는 수신자별 24시간을 적용한다.새 대상에게 허용된 알림도 현황 카드에서 막힐 수 있다. 화면의 잠금 기준을 실제 대상 정책과 맞춰야 한다.
Risk이력은 종류·분 단위로 묶고 조회 실패는 빈 기록처럼 표시할 수 있다.표시 횟수를 요청 수나 수신 수로 오해하지 않도록 한다. 실패와 기록 없음의 구분이 필요하다.
Risk연장 요청에는 영구 명령 식별자가 없고 입력 시트는 요청 전에 닫힌다.응답 유실 후 재요청은 시간을 다시 더할 수 있으며 작성 내용의 자동 복원도 없다. 결과 확인·재시도 흐름 보완이 필요하다.
Risk현황의 현재 호스트 표시와 서버의 생성자 기준이 다를 수 있다.호스트 변경 시 버튼·이력 조회와 실제 관리 권한을 함께 확인한다.
미검증소스와 선택한 기존 단언을 대조했다.새 실제 푸시·메일·스케줄 실행·기기·이미지 시험은 하지 않았다. 과거 DB 시험 기록을 현재 실행 통과로 합산하지 않는다.

과거 확인 기록

아래는 2026년 9월 26일 대상 계산 변경의 당시 확인 기록이다. 현재 소스의 새 실행 결과로 사용하지 않는다.

> 실제 MySQL을 사용한 수동·연장·자동 알림 대상과 알림 호출 검사 기록이 있습니다. 수정 후 실제 웹 조작과 휴대전화 푸시 수신은 별도 확인이 필요합니다.

수용 기준과 검증 근거

  • AC-01 입구와 자격: 진행 중 현황과 송금 목록의 실제 다시 알림 입구를 구분한다. 서버 생성자 자격·예외 호스트 대체와 현재 화면 표시의 차이를 명시한다.
  • AC-02 직접 송금 대상: 일반 대기·혼합 은행 대기의 실제 송금자를 중복 없이 계산하고, 신고된 의무와 받기만 하는 사람은 제외한다.
  • AC-03 항목별 대상: 실제 지급 금액이 남은 사람을 계산한다. 수입 보유자의 지급과 자기 몫 제외, 지급자별 전부 신고 여부를 반영한다.
  • AC-04 발신자와 선택 대상: 수동·연장은 요청자 자신을 제외하고 자동은 제외하지 않는다. 요청된 회원 번호는 현재 대상과 교집합만 사용한다.
  • AC-05 간격과 동시 요청: 같은 정산·수신자의 수동/자동/연장 기록을 함께 보아 24시간 안의 새 등록을 건너뛴다. 잠금·저장·발송 의도 등록을 구분한다.
