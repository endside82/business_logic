F11-03 후기 수정과 삭제

작성자 5회 수정·삭제 후 재작성 금지·입력 보존·응답 불확실성과 관련 목록 갱신을 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

현재 역할과 입구

이벤트 후기 목록의 본인 카드에서 수정·삭제를 선택한다. 수정은 Routes.reviewEditPath(review.id)에 현재 ReviewVo를 넘겨 작성 화면을 재사용하고, 삭제는 복구할 수 없다는 확인 뒤 호출한다. 사용자별 「내 후기」는 받은 후기 목록이므로 작성한 후기 전체의 관리 화면으로 설명하지 않는다. 후기 목록의 구분을 따른다.

서버 권한과 수정 횟수

PATCH /api/v1/reviews/{id}는 {rating, content}를 받고 ReviewVo를 반환한다. 별점은 필수 1~5, 본문은 null 허용·최대 1000자다. 삭제되지 않은 행에 쓰기 잠금을 잡고 작성자 본인인지 확인한다. 다른 작성자는 REVIEW_NOT_OWNER, 없는 행은 REVIEW_NOT_FOUND다. 사용자 계정이 닫혔으면 수정은 TARGET_ACCOUNT_CLOSED로 거절한다.

수정 이력은 최대 5회다. 현재 횟수가 5 이상이면 REVIEW_EDIT_LIMIT_EXCEEDED이고, 허용되면 변경 전 별점·본문을 이력에 남기고 새 값을 저장하며 edited=true로 설정한다. 동일 값을 다시 PATCH해도 이력과 횟수를 소모한다. 수정 API에 멱등 키가 없으므로 응답 유실 뒤 같은 요청을 안전하게 반복한다고 단정하지 않는다. 최초 작성의 종료 후 7일 조건은 이 수정 메서드에 없다.

작성자 응답의 canEdit와 remainingEditCount는 수정 이력에서 계산한다. 비작성자는 canEdit=false, remainingEditCount=null이다. 임시 숨김 중 작성자에게 반환하는 수정 응답에는 호스트 사유 글을 싣지 않는다.

삭제와 연관 결과

DELETE /api/v1/reviews/{reviewId}는 작성자 검증 후 deletedAt을 기록하고 204를 반환한다. 이미 삭제한 행은 REVIEW_NOT_FOUND다. 복구 API는 이 컨트롤러에 없고, 삭제 이력도 최초 작성 중복 판정에 남는다.

수정과 삭제는 평가 대상자의 신뢰점수 재계산을 요청한다. 삭제는 연결 클럽이 있으면 후기 적립의 회수 신호를 발행한다. 신호 발행과 실제 마일리지 회수 완료는 별도 단계이므로 이 문서의 API 호출만으로 후속 소비 성공을 증명하지 않는다. 수정은 기존 적립의 재발행 경로가 아니다.

앱 입력 보존과 복귀

작성 화면은 기존 별점·본문을 채우고, review_{eventId}_{reviewId} 문서 키의 SubmissionDraft로 입력 복원과 제출 준비·완료 처리를 연결한다. 초기 리뷰가 있는 수정 모드는 서버 변경 확인을 사용한다. 남은 횟수를 알면서 canEdit=false일 때 제출을 막고, 횟수 필드가 없는 오래된 응답의 기본 false만으로 잠그지 않는다.

성공 시 초안 완료 처리를 마친 뒤 수정 성공을 알리고 true로 복귀한다. 호출 목록과 이벤트별·사용자별 후기, 참석·지난 이벤트 집계가 갱신된다. 수정 응답의 적용 여부가 불확실한 오류에서는 관련 목록·집계를 다시 읽도록 표시하고, 확실한 거절만 초안의 거절 상태로 처리한다. 초안 연결 자체를 서버 PATCH의 멱등성 보장으로 설명하지 않는다.

삭제는 서버 응답 후 성공 안내와 목록 갱신을 수행한다. 실패 시 미리 카드를 제거하지 않는다. 대상 없음 오류는 목록을 다시 읽고 권한·통신 오류는 이유를 안내한다. 수정된 후기 카드에는 (수정됨)을 표시한다.

현재 제한과 확인 범위

분류현재 경계문서 처리
Risk동일 PATCH도 횟수를 소모하고 서버 멱등 키가 없다.응답 유실 후 재전송을 중복 영향 없는 재시도로 쓰지 않는다.
미검증신뢰점수·마일리지 후속 처리와 실제 초안 복구를 이번에 실행하지 않았다.소스 연결과 실행 완료를 구분한다.

수용 기준과 검증 근거

  • AC-01 유효한 수정: 작성자이며 남은 횟수가 있을 때 이전 값을 이력에 남기고 새 별점·본문·수정됨 표시와 차감한 횟수를 반환한다.
  • AC-02 다섯 번 제한: 이력 5회부터 수정과 추가 이력 저장을 거절한다. 동일 값 제출도 허용된 한 번의 수정으로 센다.
  • AC-03 입력과 권한: 범위를 벗어난 별점·1000자 초과 본문·다른 작성자·삭제된 후기는 각각 서버 조건에 따라 거절한다.
  • AC-04 삭제: 본인 확인 후 soft delete와 점수 재계산·해당 클럽 회수 신호를 수행한다. 삭제 후 같은 이벤트 재작성은 허용하지 않는다.
  • AC-05 앱 한도 표시: 남은 횟수가 알려진 경우 서버의 수정 허용을 따르고, 횟수 정보가 없다는 이유만으로 수정을 막지 않는다.
  • AC-06 성공과 불확실한 수정: 성공하면 초안 완료 후 복귀·관련 목록 갱신을 하고, 적용 여부가 불확실하면 재조회 대상에 표시한다. 서버 멱등성을 가정하지 않는다.
  • AC-07 삭제 실패와 대상 없음: 실패 때 카드를 먼저 빼지 않는다. 대상 없음은 목록 재조회, 다른 오류는 안내로 처리한다.

근거는 현재 서버 저장·이력·권한과 앱 입력·호출·갱신 분기다. 로컬 시나리오의 과거 E2E 기록은 보존하고 이번 실행 통과로 합산하지 않는다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 허용 기한·횟수 내 후기 수정/삭제 후 본문·평균·연결된 점수가 일치한다.
  • 횟수 초과·중복 삭제·권한 없는 수정·동시 조회에서 오래된 통계나 중복 회수가 남지 않는다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 리뷰 & 신고의 관련 완료 기준도 함께 확인합니다.
