F11-02 이벤트 후기와 사용자가 받은 후기 조회

이벤트·받은 후기의 작성자 차단과 호스트 답변 차단, 공개 권한과 표시 범위를 대조했다. 2026-11-23 소스 대조이며 새 제품 실행과 구분합니다.

현재 역할과 입구

ReviewListScreen(eventId, userId)는 이벤트별 목록과 특정 사용자가 받은 목록을 나눈다. eventId가 있으면 이벤트 모드가 우선하고, 둘 다 없으면 생성 조건을 충족하지 않는다. 두 GET 모두 로그인 사용자 정보를 서비스에 전달하며 List<ReviewVo>를 반환한다. 이 컨트롤러에는 페이지·정렬 요청 인자가 없다.

사용자가 받은 후기와 프로필 접근

GET /api/v1/users/{userId}/reviews는 revieweeId=userId인 받은 후기다. 앱 제목이 본인에게는 「내 후기」여도 내가 쓴 후기 전체를 조회하는 API가 아니다. 서버는 본인 또는 차단 관계가 없고 이용 가능한 대상인지 확인하고, 추가로 프로필 상세 접근 권한을 적용한다. 허용되지 않으면 USER_NOT_FOUND다.

본인 받은 목록의 소유자 메뉴 조건도 isViewingMine && reviewerId == currentUserId다. 따라서 이 화면을 일반적인 「내가 작성한 후기 수정함」으로 안내하지 않는다. 이벤트 목록에서는 reviewerId == currentUserId로 수정·삭제 입구를 고른다.

조회 범위와 숨김 처리

이벤트 목록과 사용자별 받은 목록은 모두 삭제되지 않은 활성 후기에서 조회자와 양방향 차단 관계인 작성자를 제외한다. 사용자별 목록은 이 작성자 필터에 앞서 대상 프로필의 접근도 검사한다. 커뮤니티·데이트 차단을 합친 같은 집합으로 작성자를 거르고, 답변을 단 호스트가 차단 관계면 그 답변과 호스트 표시 정보를 붙이지 않는다. 허용된 행에 사용자 기본정보·작성자 수정 가능 횟수·호스트 답변을 붙인다. 내부 페이지형 서비스는 필터 뒤에도 원본 총계를 유지하지만 이 화면의 공개 GET은 단순 목록을 반환한다.

임시 숨김은 행 삭제가 아니다. 서버는 작성자와 현재 이벤트 호스트에게 원래 본문을 남기고 다른 조회자에게 content=null을 준다. 숨김 사유 글은 호스트에게만 남긴다. 별점·행·연결된 답변은 이 임시 숨김 마스킹만으로 제거하지 않는다. 다만 차단 호스트의 답변은 앞의 별도 차단 필터에서 제외된다. 앱 카드 자체는 temporarilyHidden=true이면 본문 대신 숨김 안내를 표시하므로, 서버가 본문을 반환하는 작성자·호스트에게도 목록에서 원문을 펼쳐 보여 주지는 않는다.

정기모임 회차의 후기 연결

이벤트별 호출 주소의 식별자는 eventId다. 정기모임 회차도 해당 회차의 이벤트 식별자로 후기를 조회한다. 정기모임 자체의 식별자를 이벤트 식별자로 대체하거나, 여러 회차의 후기를 이 GET 하나로 합산한다고 해석하지 않는다.

삭제된 후기와 목록 갱신

삭제된 후기는 조회와 앱의 목록 집계에서 빠진다. 삭제한 이력도 서버의 최초 작성 중복 판정에 포함되므로 같은 이벤트에 다시 작성할 수 없다. 후기 수정과 삭제의 성공·대상 없음 처리 뒤 호출 목록을 다시 읽는다.

앱 행동과 결과

앱은 반환된 목록으로 평균과 개수를 계산하고 이벤트 목록에서만 별점 분포를 추가한다. 차단 필터나 삭제 결과가 반영된 목록의 집계이며 서비스 전체 후기 수를 뜻하지 않는다. 「최신순 ▼」는 현재 텍스트 표시로, 눌러 정렬을 바꾸는 동작이 없다. 서버 목록 메서드에도 명시적 정렬 조건이 없어 최신순을 보장한다고 적지 않는다.

서버의 모임 결과 카드에 제공하는 후기 수·평균은 조회자별 차단 필터로 다시 계산하지 않는다. 차단된 호스트의 답변 단건 조회는 없는 답변과 같은 REVIEW_REPLY_NOT_FOUND로 처리한다.

이벤트 목록에서 본인 후기에는 수정·삭제, 다른 후기에는 신고 진입을 연결한다. 호스트 처리 입구는 revieweeId == currentUserId이고 작성자 소유자 메뉴가 우선한다. 카드의 동일 액션 시트에 답변·숨김·신고가 들어간다. 사용자별 목록에는 신고 콜백을 주지 않는다. 호스트 권한의 최종 판정은 호스트 답변과 임시 숨김의 서버 조건을 따른다.

각 목록은 새로고침·오류 재시도로 다시 조회한다. 이벤트 목록은 사람 탐색 변경 신호, 사용자별 목록은 해당 인물의 접근 변경 신호를 구독한다. 빈 목록은 별도 빈 상태를 보여 준다. 재조회 중 이전 자료 유지 정책을 사용한다.

현재 제한과 확인 범위

분류현재 경계문서 처리
Gap「최신순」 표시와 달리 정렬 조작 및 명시적 서버 순서 보장이 없다.정렬 기능 완료로 쓰지 않는다.
Risk앱의 호스트 메뉴는 과거 revieweeId, 답변 생성·숨김 서버는 현재 이벤트 호스트를 사용한다.호스트 변경 시 메뉴 노출과 서버 허용이 다를 수 있음을 구분한다.
미검증실제 계정별 조회·차단 변경·목록 복귀를 이번에 실행하지 않았다.소스 대조와 앱 실행 증거를 분리한다.

수용 기준과 검증 근거

  • AC-01 이벤트 목록: 삭제되지 않은 활성 후기에서 차단된 작성자가 제외되고 단순 목록이 반환된다. 앱 집계는 그 응답으로 계산한다.
  • AC-02 받은 후기: 사용자별 조회는 작성한 후기가 아닌 받은 후기를 반환하고 프로필 상세 접근 거절 시 USER_NOT_FOUND다. 허용된 프로필에서도 차단 작성자의 후기와 차단 호스트의 답변은 제외한다.
  • AC-03 숨김 범위: 일반 조회자의 본문과 비호스트의 사유 글은 마스킹된다. 앱은 숨김 카드에 안내를 표시하며 별점과 차단 필터를 통과한 연결 답변을 유지한다.
  • AC-04 역할별 메뉴: 이벤트 목록 작성자는 수정·삭제, 해당 처리 대상 호스트는 답변·숨김 메뉴를 받는다. 사용자별 목록에는 신고 콜백이 없다.
  • AC-05 삭제 후 조회: 삭제 성공 또는 대상 없음으로 목록을 다시 읽고, 삭제 이력을 이유로 같은 이벤트 재작성은 거절한다.
  • AC-06 정렬 경계: 최신순 문구만으로 정렬 변경이나 서버 순서 보장을 수용했다고 판정하지 않는다.
  • AC-07 변경 신호와 재시도: 각 목록의 변경 구독·당겨 새로고침·오류 재시도가 해당 조회를 갱신하고 빈 응답은 빈 상태로 표시된다.

근거는 현재 컨트롤러·서비스·저장소·앱 호출부와 렌더링 분기다. 이번에 제품 시험을 새로 실행하지 않았다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 허용된 후기를 페이지별로 보고 작성자·평가 대상 이름을 누르면 각각 저장된 인물의 프로필이 열린다.
  • 이름/유효 식별자 없음은 일반 글자로 표시하고 차단·삭제·프로필 복귀 뒤 목록·건수·평균을 다시 확인한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 리뷰 & 신고의 관련 완료 기준도 함께 확인합니다.
