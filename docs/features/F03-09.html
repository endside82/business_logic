F03-09. 이벤트 사진첩

파일 번호 기반 등록·실패 사진 재시도·사진 공개와 신고 보존·앨범의 네 상태·부분 정리와 현재 앱 차이를 구분한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

결론

사진 운영자와 실제 참석자가 모임의 사진을 올리고, 보고, 반응하거나 신고하는 사진첩이다. 업로드에는 완료된 파일 번호를 사용한다. 파일 경로와 원래 이름을 직접 등록한다는 옛 설명은 현재 계약이 아니다. 여러 장의 부분 실패, 업로드 초안 복원, 잠금·연장·복구·정리까지 같은 화면에 연결되어 있다.

모임 종료 뒤에만 시작하는 기능은 아니다. 첫 업로드 준비에서 앨범이 없으면 만들며, 기본 업로드 만료는 모임 종료 시각으로부터 14일이다. 이후 유예·비공개·정리 상태를 구분한다. 사진 등록·삭제의 응답을 저장소 원본 전송·소거, 실제 적립·알림 수신의 완료와 동일하게 취급하지 않는다.

접근 경로와 업무별 권한

사진첩 화면과 /home/events/:eventId/photos 경로가 있으며, 서버의 사진 열람 허용 값을 사용한다. 화면은 초안 모임에서 ‘공개한 뒤에 사진첩을 쓸 수 있어요’를 표시한다. 기존 문서의 ‘모임 상세 → 사진첩 아이콘’ 연결은 현재 앱 소스에서 찾지 못했으므로 실제 일반 진입이 확인된 것으로 표시하지 않는다.

업무서버의 현재 조건
사진·다운로드 링크 조회, 사진 등록호스트·활성 공동호스트·클럽 관리자 판정에 해당하거나 실제 ATTENDING 참가 행이 있음
좋아요·신고위 자격에 더해 ACTIVE·GRACE 상태. 본인 사진 신고와 중복 신고는 거절
본인 사진 삭제업로더 본인 또는 사진 운영자. 참석 취소로 열람 권한을 잃는 것과 삭제 명령의 소유자 조건은 구분
숨김·숨김 해제·대표 사진·앨범 관리사진 운영자. 각 업무의 상태·신고 보존 조건을 추가 검사

대기자나 신청만 승인된 회원을 실제 참석자와 동일하게 취급하지 않는다. 참석 취소 뒤 업로드 사진이 자동 삭제되는 경로는 이 기능에 없다. 비참석자에게 사진 열람을 일반 공개한다는 기존 화면 명세와 현재 서버 권한은 다르다.

사진 목록·전체화면·공개 범위

앨범이 아직 없다는 응답만 빈 사진첩으로 처리한다. 다른 조회 오류는 오류 화면과 재시도로 구분한다. 사진은 최신 등록순 2열 목록으로 보이고, 대표 사진·숨김 표시·업로더와 좋아요 수를 함께 표시한다. 목록 당기기로 새로 조회하며, 갱신 중에는 이전 내용을 유지한다.

일반 참석자의 목록에는 숨기지 않은 사진만 포함한다. 운영자에게는 숨긴 사진도 포함한다. 파일 번호가 없는 옛 사진 행은 목록·다운로드에서 제외한다. 따라서 헤더의 저장된 사진 수와 실제로 보이는 사진 수가 항상 같지는 않다. 숨긴 대표 사진의 썸네일은 반환하지 않는다.

사진을 누르면 좌우로 이동하는 전체화면 뷰어가 열리고, 길게 누르면 해당 사진의 메뉴가 열린다. 본인 또는 운영자는 목록 메뉴에서 삭제할 수 있고, 다른 사람의 사진에는 신고 여부에 따라 신고 또는 이미 신고한 상태를 보인다. 전체화면의 상태 갱신·삭제 허용·삭제 뒤 복귀에는 아래에 적은 차이가 있다.

단건·다중 업로드와 파일 확인

앱의 올리기 버튼은 앨범이 없거나 ACTIVE이면서 잠기지 않은 경우 나타난다. 최종 등록 때 서버가 만료 시각과 현재 상태·잠금을 다시 검사한다. 버튼이 보인다는 것만으로 등록 성공을 보장하지 않는다.

  1. 카메라 또는 갤러리에서 사진을 고른다. 한 번에 최대 20장을 다루며, 갤러리에서 더 많이 선택하면 앞의 20장까지만 처리한다. 선택 사진은 긴 변을 1920 이내·품질 85로 요청하고 앱에서 10MB 초과를 제외한다.
  2. 사진과 공통 설명을 기기에 보관한다. 설명은 서버에서 200자까지 허용하지만 현재 앱 입력란에 해당 상한이 없어 등록 거절 가능성이 있다.
  3. 전송 주소를 받고 원본을 올린 뒤 파일 완료 처리를 요청한다. 이 과정이 성공한 파일 번호를 사진 등록에 사용한다. 전송·완료 실패 시 앱은 파일 중단 처리를 요청한다.
  4. 서버는 본인 소유·COMPLETED·EVENT_PHOTO 용도의 파일인지 확인한다. 원래 이름은 서버 파일 정보에서 가져온다.
  5. 사진을 등록하고 앨범의 실제 사진 수를 반영한다. 앨범 전체 상한은 100장이다. 첫 앨범은 모임을 잠근 뒤 중복 생성 여부와 초안 상태를 다시 확인하여 만든다.

한 장은 단건으로, 여러 장은 파일 전송에 성공한 사진 목록을 일괄 등록한다. 서버는 준비 단계에서 전체 한도를 확인하고 사진마다 별도 트랜잭션으로 처리하며, 성공 사진과 실패 위치·파일·사유를 나누어 돌려준다. 하나가 실패했다고 앞의 성공 사진을 함께 지우지 않는다.

같은 업로더가 같은 앨범에 같은 파일 번호를 다시 보내면 기존 사진을 돌려주는 경로가 있다. 다른 업로더·다른 앨범에 이미 붙은 파일은 거절하며, 일반 사용자가 숨겨진 자기 사진을 다시 보내는 경우에도 거절한다. 이 재시도는 기존 사진의 설명을 수정하는 기능이 아니다.

실패 후 재시도와 업로드 초안

앱은 파일 전송에 성공한 번호를 기억해 재시도 때 원본 전송을 반복하지 않는다. 계정·모임별로 선택 파일·설명·파일 번호를 보관하고 다시 열 때 복원한다. 보관 자료를 읽거나 저장하지 못하면 재시도 안내를 보이고, 보관이 성공하기 전에는 후속 등록을 진행하지 않는 경로가 있다.

전송 중에는 입력·닫기를 잠그며, 나가기는 작성 내용의 보존·폐기 절차를 따른다. 파일 전송이 시작된 사진의 설명은 이후 읽기 전용이 된다. 계정 세션이 끝나면 원래 계정의 후속 등록·화면 반영을 중단한다. 기기 보관을 다른 기기 사이의 동기화로 설명하지 않는다.

좋아요·신고·숨김·삭제

좋아요 추가와 취소는 서버에서 같은 요청을 다시 받아도 중복 증가·감소하지 않게 처리한다. 앱은 먼저 상태를 바꾸고 성공 응답의 수치로 확정하며 실패 시 해당 변경을 되돌린다. 일반 참석자는 숨긴 사진에 좋아요를 할 수 없다.

신고는 사유가 필요하고 보충 설명은 500자까지 받는다. 본인 사진 신고는 거절하며, 같은 사용자의 중복 신고도 별도 거절한다. 누적 신고가 3건 이상이면 아직 보이는 사진을 자동 숨김으로 전환하고 운영자 알림을 예약한다. 앱 신고 창은 결과를 기다렸다가 성공할 때 닫고, 실패하면 입력을 유지한다. 실제 신고 접수·알림 수신은 이번에 실행하지 않았다.

운영자 숨김에는 사유 코드·설명·조치자·시각을 기록할 수 있다. 현재 앱은 숨길지 여부만 보내므로 기본 MANUAL 사유가 쓰이고 상세 사유 입력은 연결되어 있지 않다. 플랫폼이 숨긴 사진은 일반 사진 운영자가 다시 공개할 수 없다. 다른 사람의 사진을 숨기면 분쟁·조치 이력 연결도 발생한다.

미종결 신고(PENDING·IN_REVIEW·ESCALATED)가 있는 사진은 업로더와 운영자 모두 삭제하거나 숨김을 해제할 수 없다. 숨기는 행동은 이 조건으로 막지 않는다. 삭제는 확인창 뒤 요청하고, 대표 사진이면 대표 지정을 비운다. 파일 참조 해제와 소거 예약을 함께 남기며, 저장소 원본이 응답 시점에 반드시 지워졌다고 설명하지 않는다. 파일 번호가 없는 옛 사진의 삭제·강제 정리는 전환 작업 필요 오류로 거절한다.

앨범 상태와 보존 기간

상태열람·다운로드올리기·반응·관리
ACTIVE자격 있는 참석자와 운영자만료 시각 전·잠금 해제 상태에서 올리기. 좋아요·신고 가능
GRACE자격 있는 참석자와 운영자올리기 불가, 좋아요·신고 가능. 운영자 연장 가능
EXPIRED일반 참석자에게 사진·링크를 비움. 운영자는 남은 사진 확인 가능올리기·좋아요·신고 불가. 한도 안에서 복구 가능
CLEANED누구에게도 사진·링크 목록을 돌려주지 않음등록·복구 불가. 이전 사진 복원 상태가 아님

기본 만료 시각은 모임 종료+14일, 유예 종료는 만료 시각+7일이다. 정기 작업이 만료된 ACTIVE를 GRACE로, 유예가 끝난 GRACE를 EXPIRED로 전환하고, 실제 EXPIRED 전환 시각에서 3일이 지난 앨범을 정리 대상으로 고른다. 상태 전환·정리는 정기 작업 시점에 수행하므로 날짜 경과 즉시 모든 원본이 사라진다고 약속하지 않는다.

자동 정리는 사진별로 처리한다. 미종결 신고나 분쟁 보존이 있으면 남기고, 개별 실패가 있어도 다른 사진은 계속 처리한다. 남은 사진이 있으면 EXPIRED와 남은 수를 유지하고, 모두 정리됐을 때만 CLEANED로 바꾼다. 이번 대조는 작업 코드의 조건이며 운영 실행 기록이 아니다.

잠금·연장·복구·강제 정리

사진 운영자는 대표 사진을 고르고 앨범을 잠그거나 풀 수 있다. 서버의 잠금은 올리기를 막는다. 현재 관리 메뉴의 ‘좋아요·신고도 차단’ 안내와 서버의 반응 조건은 다르다.

연장은 ACTIVE·GRACE에서 가능하고, 기존 만료가 미래면 그 시각에서, 이미 지났으면 현재 시각에서 14일을 더한다. EXPIRED 복구는 현재 시각+14일로 ACTIVE를 만든다. 두 작업은 평생 합계 2회의 같은 한도를 사용하며, 연장·복구 뒤에도 잠금 값은 자동으로 풀리지 않는다. CLEANED 복구나 별도의 사진 복원 기능은 없다.

강제 정리는 확인창 뒤 수행한다. 미종결 신고 사진을 제외하고 삭제하며, 일부가 남으면 앨범 상태를 유지하고 남은 수·대표 사진을 정리한다. 모두 삭제돼야 CLEANED가 된다. 서버는 삭제 수·신고로 남긴 수·부분 정리 여부를 돌려주지만 현재 앱은 이 결과를 읽지 않고 ‘사진첩이 정리되었습니다’라고 안내한다.

다운로드 링크와 외부 공유

상단 ‘전체 다운로드’는 사진별 다운로드 링크 창을 연다. 이 창에서 개별 링크 또는 모든 링크의 텍스트를 기기의 공유 기능으로 전달한다. 압축 파일 생성, 원본 일괄 저장 또는 실제 저장 완료를 제공하는 것으로 설명하지 않는다. 원본 링크가 없으면 썸네일 링크를 사용하고, 둘 다 없으면 공유할 주소가 없다고 안내한다.

목록과 같은 권한·상태·숨김·옛 파일 제외 조건을 적용한다. 운영자는 숨긴 사진의 링크도 받을 수 있으므로 일반 참석자의 목록과 다를 수 있다. 링크 조회 실패 시 오류를 보여 주며, 실제 외부 공유·수신·원본 저장은 이번에 확인하지 않았다.

수용 기준과 검증 근거

  • AC-01 접근과 초안: 서버 사진 열람 허용과 실제 참석 행을 사용하고, 초안은 공개 후 이용 안내를 보인다. 상세 입구의 미확인 상태를 감추지 않는다.
  • AC-02 목록 공개: 일반 참석자에게 숨긴 사진을 제외하고 운영자에게 포함한다. 파일 번호 없는 옛 행은 빼며 저장 수와 노출 수를 구분한다.
  • AC-03 첫 등록과 만료: 첫 업로드 준비에서 앨범을 만들고 만료를 모임 종료+14일로 둔다. 초안·현재 앨범 상태·잠금·만료를 등록 시 검사한다.
  • AC-04 파일 소유와 완료: 본인 소유의 완료된 이벤트 사진 파일 번호만 등록한다. 저장소 전송만 끝난 상태를 사진 등록 완료로 안내하지 않는다.
  • AC-05 개수·설명 상한: 한 번에 20장, 앨범에 100장, 설명 200자의 서버 조건을 확인한다. 앱의 설명 입력 차이를 별도 판정한다.
  • AC-06 일괄 부분 실패: 3장 중 1장이 실패하면 성공 2장과 실패 위치를 구분하고, 성공한 사진은 유지한다.
  • AC-07 실패 사진 재시도: 앱은 실패한 사진과 설명을 남기고, 다시 눌렀을 때 남은 사진만 요청한다. 완료된 파일 전송을 반복하지 않는다.
  • AC-08 응답 유실과 초안: 같은 계정·모임에서 초안을 복원하면 동일 파일 번호를 재사용한다. 기존 등록 사진을 중복 생성하거나 설명 변경으로 처리하지 않는다.
  • AC-09 좋아요: 추가·취소를 다시 보내도 한 회원의 좋아요가 중복 집계되지 않는다. 앱 실패 시 낙관적 변경을 되돌린다.
  • AC-10 신고: 본인·중복 신고를 거절하고 입력 실패 시 창을 유지한다. 누적 3건 이상 자동 숨김과 실제 알림 수신은 별도 확인한다.
  • AC-11 숨김과 보존: 운영자 숨김 사유를 저장하고 플랫폼 숨김의 일반 운영자 해제를 막는다. 미종결 신고 사진은 삭제·숨김 해제에서 보존한다.
  • AC-12 삭제와 복귀: 본인 또는 운영자가 확인 후 삭제하고 대표 지정을 정리한다. 목록과 전체화면의 삭제 메뉴·복귀 차이를 판정한다.
  • AC-13 상태별 이용: ACTIVE·GRACE·EXPIRED·CLEANED의 열람·올리기·반응을 구분하고 일반 참석자의 EXPIRED 사진을 비운다.
  • AC-14 연장·복구: 연장은 ACTIVE·GRACE, 복구는 EXPIRED이며 합계 2회다. CLEANED를 복구 가능하다고 표시하지 않는다.
  • AC-15 잠금: 잠금은 서버의 올리기 차단과 대응해야 하며 현재 좋아요·신고 안내 차이를 숨기지 않는다.
  • AC-16 강제·자동 정리: 보존 사진이 남으면 전부 삭제됐다고 판단하지 않는다. 자동 정리는 남은 사진이 있을 때 EXPIRED를 유지한다.
  • AC-17 링크 공유: 현재 공개 가능한 사진별 링크를 공유하며, 링크 목록 제공을 원본 일괄 저장 완료로 표시하지 않는다.
