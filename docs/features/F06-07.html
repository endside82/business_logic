F06-07. 호스팅 티켓 구매

프라이빗 모임을 개최할 권리를 포인트로 구매하는 화면. 한 장에 3,000원인 단일 가격이고, 수량을 정해 한 번에 여러 장을 산다. 산 티켓은 6개월간 유효하고, 모임을 시작할 때마다 한 장씩 차감된다. 결제는 유료 잔액으로만 한다 — 유료 잔액이 모자라면 구매 버튼이 눌리지 않고 충전을 안내한다. 호스트 활동을 시작하려는 사용자가 가장 먼저 거치는 결제 자리.

티켓 값도 지갑에서 빠지므로 플랫폼 실결제 스위치에 함께 걸린다. 구매 영역 자리에 막힌 이유·남은 작업·출시 조건을 적은 안내가 대신 들어가고, 보유 티켓 수와 만료 안내는 평소처럼 보인다. 이미 가지고 있는 티켓은 지금도 그대로 쓸 수 있다.

설계 의도 — 호스트 활동의 첫 결제는 부담 없이 끝나야 한다

프라이빗 모임을 처음 열려는 사용자는 호스트로서의 결정을 막 내린 직후다. 이 시점의 결제가 막히거나 복잡하면 호스트 활동 시작이 미뤄지고, 그만큼 플랫폼의 모임 공급이 줄어든다. 본 화면은 가격을 한 가지로 두고 수량만 고르게 해서, 사용자가 "무엇을 살지" 대신 "몇 장을 살지"만 정하면 되게 한다.

사용자 시나리오

첫 구매

호스트 활동을 시작하려는 사용자가 티켓을 산다

유료 잔액이 충분한 사용자가 수량을 1장으로 두고 "티켓 1장 구매"를 누른다. 구매 확인 안내에 단가·수량·결제 금액·유료 잔액이 나란히 보이고, 확인을 누르면 유료 포인트가 차감되고 6개월간 유효한 티켓이 즉시 발급된다. 화면 상단에 "보유 티켓 · 1장 사용 가능"과 가장 먼저 만료되는 날짜가 떠오른다.

이 흐름이 남기는 것 — 첫 호스트 결정이 수량 하나만 정하면 끝난다.

잔액 부족

유료 잔액이 모자란다

수량을 올려 결제 금액이 유료 잔액을 넘어서는 순간, 금액 줄 아래에 "유료 잔액이 부족합니다. 충전 후 다시 구매하세요" 안내가 붉게 뜨고 구매 버튼이 눌리지 않는다. 충전 화면으로 자동으로 옮겨 주지는 않는다 — 사용자가 직접 지갑으로 돌아가 충전한 뒤 다시 들어와야 한다.

이 흐름이 남기는 것 — 결제 실패 화면을 보여 주는 대신 미리 막는다. 다만 충전으로 이어지는 버튼이 이 자리에 없어, 사용자가 한 번 이탈한다.

만료 임박

곧 만료될 티켓이 있다

지난번에 산 티켓이 사흘 안에 만료된다. 화면 상단에 "만료 임박 · 2일 남음 · 잔여 1장" 배너가 강조된 색으로 떠오른다 — 사용자가 만료 전 사용 또는 재구매를 결정할 수 있게. 이미 만료된 티켓이 남아 있으면 같은 자리에 만료 안내가 대신 뜬다.

운영자가 알아야 할 것

호스팅 티켓 화면의 결정점
  • 티켓 한 장의 가격과 유효기간은 호스트 활동 진입 장벽이다. 너무 높으면 신규 호스트가 시작하지 않고, 너무 낮으면 자리만 잡고 모임을 안 여는 사용자가 늘어난다.
  • 티어 구분은 없다 — 화면과 차감 단가가 같은 한 가지다. 과거 화면이 세 등급 카드를 그리고 시스템은 단일 단가로 차감하던 어긋남은 해소됐다. 지금은 한 장 3,000원 단일 가격에 수량만 고르는 형태이고, 화면에 적히는 금액과 실제 차감액이 같다.
  • 티켓 값은 유료 잔액에서만 나간다. 화면이 유료 잔액만 보고 판정하므로, 무료 포인트가 아무리 많아도 유료 잔액이 모자라면 살 수 없다. "포인트가 있는데 왜 못 사느냐"는 문의는 이 구분 때문이다.
  • 만료된 티켓은 환불되지 않는다. 만료 임박 안내가 명확히 보여야 사용자가 만료 전 사용 또는 재구매로 이어진다 — 안내가 약하면 만료 후 신고가 늘어난다.
