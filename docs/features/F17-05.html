F17-05. 회차 관리 (추가·자동생성·일괄·대체·취소)

회차 데이터는 일반 이벤트 위에 만들어지지만, 현재 정기모임 상세의 회차 카드는 읽기 전용이라 일반 이벤트 상세 화면으로 이동하지 않는다. 일반 이벤트 운영 화면에서의 직접 수정도 막혀 있다. 서버는 다섯 가지 액션을 가진다 — 한 회차 추가, 반복 자동생성, 여러 회차 일괄 추가, 취소된 회차의 대체본 추가, 회차 취소. 앱 호스트 화면은 현재 단건 추가와 1~26회 반복 자동생성까지만 연결돼 있다.

설계 의도 — 회차는 정기모임만의 영역

회차도 결국 이벤트의 한 형태라 일반 이벤트 화면을 재사용할 여지는 있지만, 일반 이벤트 운영 경로로 회차를 수정하면 모임 본체와 정합성이 깨진다. 그래서 호스트는 정기모임 화면에서만 회차를 손볼 수 있고, 일반 이벤트의 게시/취소/정원 변경 같은 경로는 명시적으로 차단되어 있다.

사용자 시나리오

한 회차 추가

8회 코스의 다음 회차 한 건

호스트가 회차 추가 화면에서 제목·설명·시작/종료 시각을 입력한다. 순번은 자동으로 다음 번호가 붙는다. 고정형은 정원을 본체에서 상속하지만 가격은 코스 전체 결제이므로 세션에 항상 0원으로 저장된다.

이 흐름이 남기는 것 — 고정형 회차에서 이중 과금을 막고 코스 정원만 일관되게 상속.

반복 자동생성

첫 회차를 기준으로 최대 26회 생성

앱에서 매일·매주·격주·매월 중 주기와 생성 횟수(1~26)를 고른다. 서버가 첫 회차 길이를 유지해 제한된 회차 목록으로 확장한 뒤 bulk 생성 경로를 재사용한다.

이 흐름이 남기는 것 — 임의 bulk 편집 화면 없이도 가장 흔한 반복 패턴은 앱에서 바로 만든다.

변동형 회차 추가

매번 다른 정원·가격

변동형 회차는 회차마다 정원·가격을 따로 입력한다. 유료면 환불 정책과 결제기한도 고르며, 서버는 가격을 100원 단위로 절삭하고 CASH 사전결제를 만든다.

이 흐름이 남기는 것 — 변동형 모임의 핵심 자유도. 본체는 공통 정책만, 회차는 자유 운영.

회차 취소 — 서버 계약

앱 카드에는 현재 취소 액션이 없다

서버 endpoint로 DRAFT/OPEN 회차를 취소하면 고정형 코스 멤버십은 그대로 유지된다. 변동형 유료 회차라면 참가자에게 취소 알림을 보내고 결제분을 환불하며, 실패분은 운영 추적 대상으로 남긴다.

현재 결과 — 취소 도메인 계약은 있으나 상세의 읽기 전용 카드에서 호스트가 실행할 수 없다.

대체본 추가

서버 계약은 있으나 앱 화면은 아직 없다

서버는 취소된 3회차를 같은 순번의 대체본으로 만들고 원본 참조를 보존한다. 현재 Flutter 호스트 UI에는 이 endpoint로 들어가는 액션이 없어 직접 화면 흐름으로 보장하지 않는다.

이 흐름이 남기는 것 — 원본+대체 이력 모델은 준비됐고, 운영 화면 배선이 후속이다.

현재 앱 진입 공백

회차 카드는 아직 읽기 전용이다

현재 상세의 회차 카드에는 탭 동작이 없어 일반 이벤트 상세로 이동하지 않는다. 일반 이벤트 상세 화면도 회차 순번을 사용한 "정기모임 N회차" 라벨을 표시하지 않는다.

후속 — 회차 상세 진입과 컨텍스트 라벨을 함께 배선해야 일반 이벤트 화면 재사용을 사용자 흐름으로 보장할 수 있다.

화면에서 사용자가 인지하는 것

영역사용자가 보는 것그 자리에 둔 이유
회차 순번"1회차·2회차·3회차" 같은 표기가 모든 회차 카드 상단에 노출.코스에서 자기 위치를 사용자가 직관적으로 인지하게 한다.
대체본 이력서버의 includeHistory=true 응답에는 같은 순번의 취소 원본과 활성 대체본이 함께 존재한다. 현재 앱 기본 목록은 취소 원본을 숨긴다.데이터는 이력을 보존하지만 이를 함께 보여 주는 호스트 UI는 아직 없다.
변동형 정원·가격회차 카드마다 다른 값으로 노출.변동형의 자유도가 카드 단계에서 노출되어야 사용자가 "이번 달은 가격이 다르네"를 인지.
취소 회차 노출서버는 includeHistory=true일 때 이력을 돌려주지만 현재 상세 화면은 기본 활성 목록을 쓴다.호스트가 취소·대체 이력을 보는 앱 제어는 후속 배선이다.
일반 이벤트 운영 차단호스트가 일반 이벤트 화면에서 회차 운영 버튼을 눌러도 거절.운영 경로 분리로 모임 본체와 회차 정합성 보호.

운영자가 알아야 할 것

회차 운영 규칙
  • 고정형 회차 취소 시 멤버 본체는 그대로 — 자동 참석 명단만 갱신. 다른 회차에는 그대로 참여.
  • 변동형은 회차마다 정원·가격이 독립적 — 회차별로 다른 가격을 받을 수 있다.
  • 1~99원은 절삭 후 무료가 된다 — 서버가 100원 단위로 내림하므로 유료로 보이게 입력해도 사전결제가 생성되지 않는다.
  • 회차 시간 겹침 자동 검출 없음 — 호스트가 같은 시간대에 두 회차를 만들 수 있음. 1차는 호스트 자율.
  • 모집 중 모임에 회차 추가 시 가입자에게 알림 미배선 — 1차 출시는 사용자 새로고침 의존. 후속에 알림 통합.
  • 일반 이벤트 운영 화면 우회 차단 — 회차에 대한 모든 변경은 정기모임 화면에서만 가능.

가격과 환불의 실제 경계

세션 이벤트는 정기모임 본체의 안전한 파일 키를 상속한다. 단건/대체 생성 응답은 새 표시 URL로 바꾸지만, 정기모임 상세의 회차 요약 객체 자체에는 별도 썸네일 필드가 없다.

레드 플래그

자주 발생하는 케이스
  • 일괄 추가/대체 호스트 UI 1차 미신설 — 단건 추가는 가능. 일괄·대체는 후속 화면으로 빠짐.
  • 회차 시간 겹침 미검증 — 호스트가 실수로 같은 시간에 두 회차를 만들 수 있음.
  • 1~99원 유료 오인 — 100원 절삭 뒤 0원이 되지만 앱이 최소 유료 금액을 별도로 안내하지 않는다.
  • 모집 중 회차 추가 시 멤버 인지 없음 — 새 회차 추가 전용 알림이 없어 사용자가 새 회차를 놓칠 수 있음.
  • 회차 카드 상세 진입·회차 라벨 없음 — 현재 카드는 읽기 전용이고 일반 이벤트 상세도 정기모임 순번 문맥을 표시하지 않는다.
