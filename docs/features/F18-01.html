F18-01. 통합 분쟁 케이스 조회

다양한 원천에서 발생한 분쟁·신고·이의를 단일 목록으로 묶어 보여 주는 화면. 대부분의 분쟁은 신고한 사람과 직접 영향을 받은 당사자에게만 보이고, 사용자가 직접 접수한 분쟁만 신고한 쪽과 신고당한 쪽 양쪽 모두에게 보인다. 호스트는 정산 이의(개설자 시점)와 환불 분쟁(판매자 시점) 두 종류의 분쟁을 별도로 확인한다. 원천 도메인마다 상태를 부르는 이름이 다르더라도, 사용자에게는 항상 같은 5단계 중 하나로 통일되어 보인다. 7일 이상 미해결 케이스는 운영팀에 알림이 자동으로 발송된다.

통합되는 분쟁 원천
참가자 8종
호스트는 정산 이의·환불 분쟁 2종
통합 상태
5단계
접수됨·검토 중·상위 이관·처리 완료·종결
처리 기한
7일
초과 시 운영팀 알림
화면이 안내하는 가능 동작
역할별 분기
이의·노트·환불 처리 등
설계 의도 — "내 분쟁이 지금 어떻게 되고 있는지" 한 눈에

이전에는 노쇼 이의는 이벤트 화면, 정산 이의는 정산 화면, 경고 이의는 클럽 화면으로 각자 흩어져 있었다. 이 기능은 그 모든 케이스를 하나의 목록으로 모아 사용자가 현재 진행 중인 분쟁과 종결된 분쟁을 한 화면에서 추적하게 한다. 원천이 다르더라도 사용자가 보는 상태 표시는 항상 동일하다.

상태를 바꾸는 것은 대부분 운영팀만 가능

사용자는 대부분 앱에서 케이스 상태를 직접 바꿀 수 없다. 직접 접수한 분쟁은 "접수됨"으로 만들어진 뒤 운영팀이 처리할 때까지 상태가 그대로다. 유일한 예외는 돈이나 제재가 걸리지 않은 1:1 분쟁에서 당사자 양쪽이 모두 종결에 동의하는 경우로, 이때는 운영팀 개입 없이 시스템이 바로 종결 처리한다. 그 밖에는 현재 상태를 조회하고 이의를 제기하는 것만 가능하다.

사용자 시나리오

기본 흐름 — 참가자

내가 관련된 분쟁 목록 확인

이벤트 노쇼 기록, 클럽 강퇴 이의, 직접 접수한 분쟁이 모두 한 목록에 보인다. "처리 중" 필터를 선택하면 접수됨·검토 중·상위 이관 케이스만 추려 볼 수 있다. 카드를 탭하면 상세 화면으로 진입해 진행 이력과 증빙을 확인한다.

이 흐름이 남기는 것 — 어느 도메인에서 발생했든 "내 분쟁 이력"이 한 화면으로 집약된다.

기본 흐름 — 호스트

내 이벤트·클럽에 걸린 분쟁 확인

호스트가 확인하는 분쟁은 두 종류다. 정산 이의(개설자 기준)와 환불 분쟁(판매자 기준). 두 분쟁은 호스트에게 묶이는 기준이 다르며, 같은 목록·필터 구조를 공유한다. 상세 화면에서는 원천별로 가능한 동작과 원천 화면으로 가는 경로가 구분된다.

이 흐름이 남기는 것 — 호스트 입장에서 처리해야 할 케이스를 놓치지 않게 한다.

상세 조회

진행 이력과 증빙으로 맥락 파악

케이스 상세에는 진행 이력(누가 언제 어떤 조치를 했는지)과 증빙이 포함된다. 보이는 내용은 사건 접근 권한과 공개 범위를 따른다. 당사자 공개 증빙과 본인이 제출한 증빙은 확인할 수 있다. 운영팀 전용 진행 이력과 다른 사람이 제출한 운영 전용 증빙은 보이지 않는다.

이 흐름이 남기는 것 — "왜 이 결정이 났는지"를 사용자가 직접 추적할 수 있다.

상태 필터

종결된 케이스만 이력으로 보기

"종결" 필터를 선택하면 처리 완료·종결 케이스만 남는다. 분쟁 종류로도 목록을 좁힐 수 있으나, 일부 분쟁 유형은 유형 필터로 정확히 걸러지지 않을 수 있어 결과를 확인할 때 주의가 필요하다. 무한 스크롤로 이력 전체를 탐색한다.

권한 분기

내가 뭘 할 수 있는지 화면이 알려준다

케이스 상세는 사용자의 역할에 따라 가능한 동작을 다르게 보여 준다. 이의제기 가능 여부, 보완 요청 노트 전송 가능 여부, 환불 분쟁 처리 가능 여부 등에 맞춰 버튼이 표시되거나 숨겨진다. 클럽 경고 이의와 모임 정산 이의의 승인·거절은 각각 경고 인박스와 정산 이의 전용 화면에서 실행한다. 모임 정산 이의는 운영자도 관리자 화면에서 판정할 수 있고(판정 글은 호스트 답과 따로 적힘), 통합 분쟁 이의의 최종 결정은 운영팀 권한이다.

증빙 보존

케이스가 진행 중이면 증빙 보존 안내가 표시된다

분쟁 화면에는 증빙 삭제 버튼이 없다. 진행 중(접수됨·검토 중·상위 이관) 케이스에서는 "증빙 보존 중" 안내가 표시된다. 사용자가 일반 파일 삭제 API를 직접 호출해도 증빙 참조 등록부가 해당 파일을 확인해 삭제를 거절한다. 종결 뒤에는 정해진 1년 보존기간을 채운 후 자동 파기한다.

운영자가 알아야 할 것

운영 주의사항
  • 처리 기한 7일 알림은 분쟁 원천마다 따로 점검한다. 한 원천의 점검이 실패해도 나머지 원천의 미해결 케이스 알림은 정상적으로 발송된다. 같은 케이스에 대한 알림은 한 번만 간다.
  • 운영팀 전용 진행 이력은 사용자에게 보이지 않는다. 운영 전용 진행 이력은 가린다. 증빙에는 제출자 본인 열람 예외가 있고, 나머지 세부 등급을 완전하게 구분하는 것은 별도 범위다. 분쟁 증빙의 공개 범위와 보존을 따른다.
  • 유형 필터가 일부 분쟁 유형을 정확히 거르지 못할 수 있다. 분쟁 종류가 매우 다양해, 특정 유형으로 목록을 좁혔을 때 일부 케이스가 빠지거나 섞일 수 있다. 정밀한 분류가 필요한 운영 작업에서는 결과를 한 번 더 확인하는 것이 안전하다.
  • “이의”라는 이름만 보고 처리 주체를 일반화하면 안 된다. 클럽 경고 이의는 권한 있는 클럽 운영진이, 모임 정산 이의는 정산 생성자·호스트가 각 전용 화면에서 처리한다. 모임 정산 이의는 운영자도 관리자 화면에서 판정하고, 통합 분쟁 이의는 운영팀이 최종 결정한다.

레드 플래그

현재 알려진 미구현·주의 사항
  • 자동 검사 존재와 실제 공개 확인을 구분한다. 현재 소스에는 원천별 조회·당사자 권한·공개 범위·본인 증빙·다운로드 자격을 확인하는 자동 검사가 있다. 이 문서 갱신에서 제품 검사를 재실행하지 않았으며 동일 출시후보의 실계정·실제 파일 확인은 별도로 남긴다.

이 기능의 출시 완료 기준

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 첫 출시 포함 여부와 구현·검사 현황은 위 상태표를 따릅니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 당사자/호스트가 허용된 원천의 분쟁 목록·상세·상태를 올바르게 조회한다.
  • 다른 사건·운영 전용 기록·권한 회수·페이지 필터를 확인하며 지원하지 않는 원천을 포함한다고 안내하지 않는다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 분쟁 해결의 관련 완료 기준도 함께 확인합니다.
