F16-05 적립 규칙·등급·배지·차감 사유·시즌 관리

규칙 중복 거절, 등급 오류 분리와 재계산 예약, 배지/프리셋/시즌 생성 키, 시즌 기간 잠금 및 실패 후 입력 유지의 현재 계약을 대조했다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

현재 범위와 정정

정책 운영진이 자동 적립 규칙, 등급, 배지 정의, 미리 정한 차감 사유, 시즌을 관리한다. 배지 담당자는 정의 목록 조회와 배지 부여 입구를 사용할 수 있지만 정의 편집 권한과는 다르다. 과거 문서의 ‘규칙 POST는 upsert’, ‘등급 검증 오류는 모두 개수 초과’, ‘시즌 close는 상태 변경만 수행’은 현재 계약과 다르다.

현재 서버 계약

공통 접두사는 /api/v1/admin/clubs/{clubId}/mileage다. 기본 권한은 POLICY_OWNER이며 MILEAGE 공개 범위를 적용한다. 아래의 {id}는 각 실제 요청의 ruleId/gradeId/badgeDefId/presetId/seasonId다.

대상현재 요청·결과
적립 규칙GET /earning-rules 목록, POST 생성 201, PUT /earning-rules/{ruleId} 수정 VO
등급GET /grades 목록, POST 생성 201, PUT /grades/{gradeId} 수정, DELETE 삭제 204
등급 재계산POST /grades/recalculate, 선택 body.afterMemberId 기본 0, 처리/변경/실패/마지막 회원 ID 결과
배지 정의GET /badges 목록은 POLICY_OWNER 또는 BADGE_AWARD_MANAGER. POST 생성 201, PUT /badges/{badgeDefId} 수정은 POLICY_OWNER
차감 사유GET /redemption-presets 전체, GET /redemption-presets/active 활성 목록은 POLICY_OWNER 또는 REWARD_MANAGER. POST 생성, PUT 수정, DELETE 비활성화
시즌GET /seasons 목록, POST 생성 201, PUT /seasons/{seasonId} 수정, POST /seasons/{seasonId}/close 마감. 별도 MILEAGE_SEASON 공개 범위

배지 정의·차감 사유·시즌의 생성은 필수 Idempotency-Key와 명령 영수증 실행기를 사용한다. 규칙/등급 생성, 수정/삭제, 시즌 마감을 모두 같은 필수 키 API로 설명하지 않는다. 회원 배지 부여/해제는 적립·차감·정정의 별도 명령이다.

적립 규칙의 생성과 변경

트리거는 EVENT_CHECKIN, EVENT_REVIEW, EVENT_PHOTO_APPROVED다. 같은 클럽/트리거가 이미 있으면 POST는 DUPLICATE_RESOURCE로 거절하며 기존 규칙을 덮어쓰지 않는다. 수정은 ruleId를 사용한다. points는 0 이상, eventPointsCap도 지정했다면 0 이상이다. 후기 기한은 1~7일이며 미지정 생성은 7일을 사용한다.

사진 규칙을 켤 때 MILEAGE_PHOTO 공개 범위를 확인한다. 수정은 버전을 증가시키며 경쟁 갱신은 CONCURRENT_MODIFICATION이다. resetEventPointsCap=true는 별도 상한을 없애고, 동시에 새 eventPointsCap도 보내면 거절한다. 기본 세 규칙을 보충하는 시점과 값은 마일리지 제도 설정·변경 미리보기를 따른다.

등급·배지·차감 사유의 규칙

대상현재 제약·효과
등급최대 10개. 생성 이름 필수/20자, threshold 0 이상, 색/아이콘 필수/각 50자, 표시 순서 0 이상
등급 중복/금지어이름 중복은 MILEAGE_GRADE_NAME_DUPLICATE, 금전성 금지어는 MILEAGE_GRADE_NAME_FORBIDDEN_WORD, threshold 중복은 MILEAGE_GRADE_THRESHOLD_DUPLICATE
등급 삭제현재 등급으로 참조한 요약 행이 있으면 MILEAGE_GRADE_IN_USE
배지 정의최대 50개. 이름 필수/30자, 설명 200자, 색/아이콘 50자. 금지어는 별도 MILEAGE_BADGE_NAME_FORBIDDEN_WORD. 생성은 active=true
차감 사유생성 label 필수/50자, 기본 차감량 양수, 표시 순서 0 이상. 목록은 표시 순서대로 반환
차감 사유 삭제행 삭제 대신 active=false. 이미 비활성이면 그대로 종료하며 이후 사용은 MILEAGE_PRESET_INACTIVE

등급의 ‘단조 검사’ 구현은 다른 등급과 threshold가 같은지를 검사한다. 저장된 displayOrder에 따라 점수가 반드시 증가하도록 검사한다고 확대하지 않는다. 일부 수정 필드는 길이만 검사하므로 생성의 공백 필수 검사와 완전히 같다고 설명하지 않는다.

등급 생성·삭제와 threshold 변경은 재계산 작업을 예약한다. 정의 저장 성공이 전체 회원 등급 재계산 완료를 뜻하지 않는다. 수동 재계산은 200명씩 읽으면서 회원별 오류를 세고 계속 진행한다. 실패한 회원 뒤까지 cursor가 이동할 수 있으므로 실패 복구를 마지막 ID 이후부터만 수행하면 누락된다. 앱의 재계산은 별도 cursor 없이 처음부터 요청하고 결과 및 관련 조회를 갱신한다.

시즌 생성·수정·마감

시즌 생성은 시작/종료 필수, 시작 < 종료, 종료가 현재 이후, 기존 시즌과 기간 비중첩을 요구한다. 이름 최대 50자다. 처음에는 SCHEDULED이며 시작 시각과 다른 시즌 조건이 맞으면 ACTIVE로 전환하고 집계 준비를 수행한다.

기간 수정은 아직 시작 전 SCHEDULED이고 해당 시즌 delta가 없어야 한다. 진행 중인 시즌은 이름만 바꿀 수 있다. CLOSING은 MILEAGE_SEASON_CLOSE_IN_PROGRESS, CLOSED 수정은 여전히 MILEAGE_SEASON_NOT_FOUND로 거절한다. 타 클럽 시즌도 찾을 수 없음으로 처리한다.

마감은 준비된 ACTIVE이면서 종료 시간이 지난 경우만 시작한다. CLOSING에서 회원별 기록·순위 확정과 남은 작업 재시도를 거친다. 전체 상태·동점 규칙·다음 시즌은 시즌 조회·순위 확정·재시도를 따른다. 시즌을 단순 CRUD 결과만으로 완료라고 표시하지 않는다.

앱 행동·실패·복귀

등급/차감 사유/시즌 화면은 정책 권한으로 보호한다. 배지 화면은 정책 또는 배지 부여 권한으로 들어가되 정의 추가·수정과 실제 부여를 나눈다. 각 목록은 로딩·빈 상태·오류 재시도를 제공한다.

편집은 현재 세션과 제출 직전 권한을 확인하고 보내는 동안 중복 실행을 막는다. 성공하면 편집 창을 닫고 실패하면 오류를 표시하며 입력을 유지한다. 배지/차감 사유/시즌 생성 창은 같은 본문의 재시도에 같은 키를 사용하고 성공 때 완료 처리한다. 이름이나 기간 등 본문이 달라지면 같은 명령으로 취급하지 않는다.

등급 편집은 이름 빈 값은 막지만 threshold/표시 순서를 정수로 해석하지 못하면 0으로 대체한다. 모든 숫자 오류를 입력 단계에서 명확히 거절한다고 설명하지 않는다. 시즌 수정은 바뀌지 않은 시작/종료를 null로 전송해 이름만 수정할 때 기간 잠금에 걸리지 않도록 한다. 마감·준비 재시도는 완료/진행 중 결과를 구분한다.

수용 기준과 검증 근거

  • AC-01 권한별 관리: 정책 편집과 배지 부여/활성 차감 사유 조회 권한을 구분한다.
  • AC-02 규칙 중복: 같은 트리거 생성은 거절하고 수정은 기존 ID·버전으로 수행한다.
  • AC-03 규칙 입력: 점수/상한/후기 기한·상한 초기화·사진 공개 범위를 확인한다.
  • AC-04 등급 제약: 개수·이름·threshold 중복·금지어·사용 중 삭제의 서로 다른 오류를 설명한다.
  • AC-05 재계산: 정의 저장의 예약과 회원별 처리 결과/실패 복구를 구분한다.
  • AC-06 배지와 사유: 정의 입력 제한, 활성 목록, 비활성화와 실제 행 삭제를 구분한다.
  • AC-07 생성 키: 배지/차감 사유/시즌 생성의 필수 키를 다른 명령에 확대하지 않는다.
  • AC-08 시즌 기간: 비중첩·시작 전 예약 수정·진행 중 이름 변경·마감/종료 제한을 설명한다.
  • AC-09 입력 보존: 성공 후 닫기와 실패 후 유지, 생성 키의 같은 본문 재사용을 대조한다.
  • AC-10 결과 구분: 저장·재계산·시즌 준비·마감 완료를 각각의 응답 상태로 판정한다.

현재 소스 계약과 후속 확인 시나리오다. 이번 작업에서 새 제품 시험·실기기·시각 검수 통과 기록을 추가하지 않는다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 공개 모임의 체크인/후기 점수·규칙·기간이 확정되고 회원 안내와 실제 적립이 일치한다.
  • 클럽 상한·긴급 중지·사진 심사·취소 회수·실패 재시도와 필요 시 기존 공개 모임의 누락 값을 확인한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 마일리지의 관련 완료 기준도 함께 확인합니다.
