게시글·모임 투표

게시글 의견 수집, 참석자 질문, 무료 클럽 모임의 일정·장소 결정을 구분합니다. 2026-11-22 현재 생성·투표·마감·자동 참가·알림과 복귀 조건을 소스와 대조했습니다.

현재 구현과 확인 범위

2026-11-22 서버·앱 소스를 대조했다. 게시글 투표, 모임 참가자 투표, 무료 클럽 모임의 일정·장소 결정 투표가 각각 구현돼 있다. 기능 공개 여부는 POLL 공개 범위를 따르며, 로컬 운영 설정의 기본 목록에 POLL이 있다는 사실과 실제 배포 환경에서 열려 있다는 사실은 다르다.

이 문서는 기존 175개 기능 목록 밖의 보충 기능 문서다. 기능 수나 실행 통과 수에 더하지 않는다. 이번 작업은 문서 갱신이며 제품 코드 수정·제품 시험·실기기 검수를 실행하지 않았다. 공개 준비는 투표 기능의 공개 준비를 따른다.

어떤 투표를 쓰는가

종류생성·관리참여·열람
게시글 투표글에 첨부하며 글당 최대 5개. 이미 있는 글에 투표를 붙이는 API는 글 작성자만 허용한다. 공개된 글의 투표는 작성자·유효한 클럽 운영진이 관리한다.현재 클럽 회원이며 글 작성자와 양방향 차단 관계가 없어야 한다. 예약 게시글은 작성자만 투표를 열람하며, 공개 전에는 표를 받지 않는다.
모임 참가자 투표DRAFT·OPEN 모임에서 주최자 또는 공지 발송 권한이 있는 유효한 공동주최자가 생성·관리한다. PENDING·OPEN을 합쳐 최대 5개다. 생성에는 공지 발송 제한도 적용한다.주최 측 또는 실제 참석자가 열람한다. 투표는 실제 참석 행이 있는 회원만 하며, 클럽 모임은 현재 클럽 회원이어야 한다. 주최 측이라는 이유만으로 투표권이 생기지 않는다.
일정·장소 결정 투표무료 CLUB_MEETING 모임에서 일정 또는 장소 중 하나를 정한다. 주최자·유효한 공동주최자·클럽 운영진의 관리 권한과 실제 열람 가능 상태를 함께 판정한다.현재 클럽 회원 중 주최자를 제외한 회원이 투표한다. 초안은 주최 측만 열람한다. 공개 후 확정된 후보의 투표자를 참가자로 전환하되 현재 자격을 다시 검사한다.

운영진·공동주최자의 역할 제한은 권한 판정에 적용한다. 결정 투표의 운영진 관리 권한만으로 비회원 열람이나 초안 열람까지 허용하지 않는다. 자세한 공통 정책은 역할 제한이 적용되는 권한을 따른다.

투표하고 고치는 규칙

  • 질문은 100자, 선택지 이름은 80자까지며 선택지는 2~10개다. 공백을 정리한 빈 이름·중복 이름을 거절한다. 일반 투표에는 일정·장소 후보 전용 필드를 넣지 않는다.
  • 현재 선택 전체를 저장한다. 같은 선택은 결과를 다시 반환하고, 빈 목록은 표 거두기다. 중복 ID·다른 투표의 선택지·단일 선택에서 여러 ID는 거절한다. 투표 자체와 부모 글·모임이 열려 있고 마감 전이어야 한다.
  • 앱은 단일 선택을 누르면 저장하며 복수 선택은 고른 뒤 ‘투표하기’를 누른다. 저장 중 중복 요청을 억제하고 실패하면 임시 반영한 표를 되돌린다. 서버에 반영됐을 수 있는 응답 유실은 실제 최신 결과와 다시 대조해야 한다.
  • 결과는 투표 전에도 보인다. 비율은 선택지 표 수를 참여자 수로 나누므로 복수 선택의 합계는 100%를 넘을 수 있다. 익명 투표에서는 운영자도 선택지별 명단을 조회할 수 없다. 비익명 명단은 열람 권한과 조회자 차단 필터를 적용한다.
  • 표가 남아 있으면 질문·기존 선택지·익명·복수 선택을 바꾸거나 삭제할 수 없다. 기존 ID와 순서·내용을 유지한 선택지 추가 및 마감 연장은 가능하다. 일반 투표는 마감 제거도 허용하지만 결정 투표의 마감은 필수다.
  • 일반 투표의 최초 마감은 생성 기준 1시간 뒤부터 30일 안이다. 예약 게시글은 예약 공개 시각이 기준이며 변경 시 최초 상한을 유지한다. 이미 지난 마감과 스케줄러가 저장한 CLOSED 상태는 다르다. 실제 표 저장은 마감 시각부터 차단한다.
  • 예약 공개 시 이미 마감이 지난 일반 투표는 CLOSED로 연다. 모임 취소는 PENDING·OPEN·CLOSED 일반 투표를 CANCELED로 바꾼다. 일반 마감 API로 결정 투표를 닫거나 일반 삭제 API로 제거하지 않는다.

투표로 일정이나 장소를 정하는 모임

  1. 무료 클럽 모임의 일정 또는 장소 후보 2~10개를 만든다. 일정 후보는 미래 시작·종료 순서가 필요하다. 장소 후보는 이름·주소가 필요하고 주소 500자·상세 주소 200자 및 좌표 검증을 적용한다. 일정과 장소를 동시에 투표로 정하지 않는다.
  2. 초안 상세의 ‘후보·마감 수정’은 투표 관리 권한을 사용한다. ‘투표 없이 진행’은 별도의 초안 모임 수정 권한도 필요하다. 앱은 서버의 허용 행동을 따르고 제출 전에 최신 후보·권한·투표 번호를 다시 확인한다. 선택한 실제 일정·장소 저장과 투표 제거를 함께 처리하며 모임은 초안으로 남는다.
  3. 공개할 때 마감과 후보 시각을 다시 검사한다. 마감은 가장 이른 후보 시작 최소 2시간 전이며, 공개 시점에서 최소 1시간 뒤와 최초 30일 상한도 충족해야 한다. 확정 대기 중에는 일반 참가를 받지 않는다.
  4. 자동 처리는 마감 후 득표가 있는 단독 1위와 후보 시작까지 최소 1시간 조건을 확인한다. 동률·무득표·1위 후보 시간 부족이면 투표를 닫고 주최 측에 선택을 요청한다. 후보가 모두 만료돼도 모임을 자동 취소하지 않는다. 일반 투표와 결정 투표의 주기 작업은 별개이며 기본 주기 60초·조회 한도 200개다. 마감 정각 처리 완료를 보장하는 수치가 아니다.
  5. 수동 확정은 후보를 지정하거나 단독 1위를 사용한다. 변경되는 확정에는 현재 투표 버전이 필요하다. 오래된 버전은 충돌로 거절한다. 이미 같은 후보이고 모임의 일정·장소도 일치하면 변경 없는 결과를 반환하며 새 참가 등록을 반복하지 않는다.
  6. 첫 확정의 주최자도 현재 회원·참가 제한·기존 참석 행을 확인한다. 선택된 후보의 투표자는 기존 참석 행, 신청 경로 기록, 참가 이탈 기록, 탈퇴, 참가 제한, 운영자가 제외한 ID에 따라 건너뛴다. 등록된 수만큼 현재 인원을 늘리고 필요하면 기본 정원을 올린다. 대기열로 전환하지 않는다.
  7. 재확정은 현재 모임 시작까지 최소 3시간, 체크인 없음, 진행 중 일정 변경 동의 절차 없음이 필요하다. 새 후보도 시작까지 1시간 이상 남아야 한다. 기존 참가자는 유지하고 새 후보 투표자를 자격에 따라 추가한다. 참가를 취소한 사람을 강제로 다시 넣지 않는다. 후보 밖 일정 변경은 일반 변경 절차다.

앱의 인원 예상은 선택지 표 수에서 제외 수를 뺀 계산이다. 서버의 기존 참석·신청·제한 검사 결과를 미리 확정한 값이 아니다. 성공 후에는 서버가 반환한 실제 전환 수·주최자 등록·정원 변경을 표시한다. 버전 충돌이면 시트를 닫고 모임을 다시 읽으며, 일반 실패는 안내 후 입력을 남긴다.

회원에게 먼저 알려야 할 것

  • 투표가 참가 등록으로 이어질 수 있다. 익명은 선택지별 명단의 비공개이며, 확정 뒤 참가자 명단의 비공개까지 뜻하지 않는다. 익명 결정 투표에서는 운영자의 개별 제외 ID를 허용하지 않지만 공통 자격 검사는 적용한다.
  • 확정 대기 중인 모임은 개인 주최·참가 일정 조회와 ICS 내보내기에서 제외·제한한다. 클럽 달력은 날짜 결정 투표 모임을 숨기고 장소 결정 투표처럼 날짜가 정해진 모임은 표시할 수 있다.
  • 모임 마일리지 규칙은 확정 때가 아니라 모임 공개 때 고정한다. 후보 확정과 참가 등록이 별도의 새 규칙 고정을 뜻하지 않는다.
  • 현재 데이터 내보내기 구성에는 투표 정의·개별 표를 위한 별도 항목이 없다. 내보내기 성공을 모든 투표 자료 제공 완료로 설명하지 않는다.

앱의 결과·복귀와 현재 한계

항목확인한 현재 동작과 한계
목록·만들기모임 투표 목록은 20개씩 받아 진행 중·마감됨을 나눈다. 허용된 운영자에게 만들기를 표시하고 5개 한도에서 막는다. 추가 조회 오류는 기존 목록을 보존하되 권한 거절은 목록을 비운다.
작성 실패편집기는 전송 중 닫기·중복 저장을 막고 성공할 때만 닫는다. 참가자 투표 생성은 같은 편집 세션·같은 본문에서 키를 재사용하지만 화면을 닫고 다시 열 때까지 영속 보관하는 계약은 아니다.
일반 관리 API와 화면일반 수정·삭제 API는 있지만 현재 참가자 투표 목록·상세에서 확인한 입구는 만들기·투표·마감이다. API 존재를 모든 수정·삭제 화면 제공으로 확대하지 않는다.
확정·후보 수정 후 조회성공 또는 반영됐을 수 있는 오류에서 모임 상세·카드·목록 관련 조회를 갱신한다. 상세 재조회 자체가 실패할 수 있으므로 즉시 모든 화면의 최신 표시를 보장하지 않는다.
직접 링크의 모임·투표 결합경로의 모임 열람 가능 여부를 확인한 뒤 pollId로 투표를 읽는다. 응답에는 소속 eventId가 없고 화면도 두 ID의 결합을 대조하지 않는다. 각각 볼 수 있는 다른 모임의 투표를 끼운 경로가 잘못된 복귀·갱신 문맥을 만들 수 있다. 서버의 투표 자체 권한 검사는 별도로 존재한다.
재확정 시각 경계서버는 정확히 3시간 남은 경우를 허용하지만 앱의 재확정 입구 판정은 3시간보다 뒤인지 확인한다. 경계 시각의 차이를 동일 계약으로 설명하지 않는다.
실행 증거실제 자동 마감 시각·동시 투표/확정·응답 유실·실기기 알림·배포 설정은 이번에 실행 확인하지 않았다. 아래 과거 실행 기록과 구분한다.

공개 전에는 실제 입구에서 생성·선택 변경·표 거두기·마감·동률 처리·확정·재확정·취소·권한 회수·복귀를 확인한다. Android/iPhone의 수신과 이동은 별도 증거가 필요하다. 함께 적용하는 권한·실패·복구 확인을 따른다.
