F09-01. 본인 인증

데이팅을 사용하려는 모든 사용자가 가장 먼저 통과해야 하는 관문. 서버 설정으로 선택한 외부 본인인증 사업자(TOSS 또는 NICE)의 절차를 거쳐 실명·생년월일·성별·고유식별값을 검증받고, 이 단계를 통과해야 비로소 프로필 작성, 후보 카드 조회, 호감 표시, 채팅까지 모든 후속 기능에 접근할 수 있다. 데이팅에서 발생할 수 있는 안전 문제는 이 단계의 강도에 의해 1차로 걸러진다.

2026-09-06 현재 — 증빙 제출·수동 승인·취소까지 구현·검증·로컬 통합 완료

앱은 서버가 내려준 공급자·인증 주소·성공/실패 복귀 주소를 그대로 사용하고, 허용된 복귀 주소만 받아 서버에 확인을 요청한다. NICE 경로도 암호화 요청·무결성 검증·복호화와 운영 필수 설정 기동 거부까지 구현됐다. 공급자는 서버 설정으로 정하며 사용자가 TOSS/NICE를 고르는 화면은 없다.

시스템 관리자는 전용 웹에서 본인확인 결과 목록·상세, 회원별 시도 이력, 공급자와 실패 원인을 조회하고 증빙을 검토해 수동 승인·취소할 수 있다. 증빙·생년월일·남성/여성 성별·최대 365일 유효기간· 승인 사유를 필수로 받고 만 20세 여부·파일 검사·현재 신청 자격을 다시 확인한다. 상태만 바꾸던 무입력 승인 명령은 제거했다. 변경 전후 감사·암호화·회원정보 동기화·증빙 보존도 연결했다.

네 저장소의 전체 회귀·빈 데이터베이스 대조·로컬 기본 브랜치 통합은 완료됐다. 데이트 공개 출시는 여전히 보류이며 실제 파일 저장소·악성코드 검사·관리자 역할·알림과 NICE 실신원·서명 앱 왕복이 남아 있다. 완료 근거는 W2 데이트 수동 검토 통합 검증에 있다.

설계 의도 — 데이팅 도메인에서 한 번 무너지면 다른 모든 안전 장치가 의미를 잃는다

데이팅은 다른 도메인과 다르다. 사용자끼리 실제로 만나서 오프라인으로 이어지는 흐름이기 때문에, 허위 신원·미성년 가입·중복 계정이 한 건이라도 통과하면 그 한 건이 곧 사고로 이어진다. 그래서 본 단위는 "데이팅을 시작하기 전에 가장 강한 관문을 한 번 통과시키되, 한 번 통과한 사용자는 1년 동안 다시 묻지 않는다"는 균형으로 설계되어 있다. 너무 자주 묻으면 사용자가 지치고, 너무 길게 두면 신원의 신뢰가 헐거워진다 — 1년은 그 사이의 결정점.

누가 영향을 받는가

본 단위는 데이팅을 처음 만나는 모든 사용자에게 가장 먼저 작동한다
  • 신규 진입자 — 데이팅 탭을 처음 누른 사람이 마주하는 첫 화면이 본 인증이다. 이 자리에서 이탈하면 데이팅 도메인 전체 사용자 수가 그만큼 줄어든다.
  • 1년 후 재사용자 — 한 번 인증했지만 1년이 지난 사용자. 다시 데이팅을 켰을 때 같은 흐름을 한 번 더 거쳐야 한다 — 이 재인증의 불편이 너무 크면 휴면 사용자가 돌아오지 않는다.
  • 시스템 관리자 — 전용 웹에서 인증 결과와 회원별 시도 이력, 공급자, 실패 코드·메시지를 확인한다. 외부 사업자 장애가 데이팅 신규 가입에 직접 영향을 주므로 실패가 몰리는 공급자와 시점을 빠르게 파악해야 한다.

인증 한 번이 거치는 단계

사용자에게는 한 동작처럼 보이지만, 그 안에서 외부 사업자 호출과 개인정보 암호화가 순서대로 일어난다.

사용자 시나리오

기본 흐름

데이팅을 처음 켜는 사용자

데이팅 탭에 처음 진입한다. 후보 카드 대신 본인 인증 안내가 보인다. "본인 인증하기"를 누르면 서버가 설정한 공급자의 인증 페이지가 화면 안에 열린다. 통신사·이름·생년월일·휴대폰을 입력하고 문자 인증까지 마치면, 화면이 자동으로 닫히고 "본인인증이 완료되었습니다" 토스트가 뜬다. 뒤로 가서 다시 데이팅 탭으로 들어오면, 이번에는 후보 카드 또는 프로필 작성 안내로 바로 넘어간다.

이 흐름이 남기는 것 — 데이팅의 모든 후속 기능이 이 한 번의 통과를 전제로 한다. 첫 인증까지의 시간이 짧을수록 가입 후 첫 매칭까지의 시간도 짧아진다.

중도 이탈

인증 페이지를 띄웠다가 닫음

외부 본인인증 화면이 열렸지만 사용자가 X를 눌러 닫는다. 화면은 다시 안내 화면으로 돌아오고, 사용자에게 별다른 강제 안내는 뜨지 않는다. 필요하면 사용자가 같은 자리에서 다시 시도할 수 있다.

이 흐름이 남기는 것 — 사용자가 마음을 바꿀 권리를 막지 않는다. 한 번 닫은 사용자가 다른 시간에 돌아와 다시 시도하는 게 자연스러운 사용자 흐름.

반복 실패 차단

하루에 다섯 번 넘게 시도

같은 사용자가 하루에 5번까지 인증 페이지를 띄울 수 있다. 여섯 번째 시도부터는 인증 요청이 차단되고, 클라이언트는 "본인인증 요청에 실패했습니다" 토스트만 보여 준다. 다음 날이 되면 자동으로 풀린다.

이 흐름이 남기는 것 — 외부 인증 사업자에게 무한 호출이 가지 않도록 막는다. 동시에 사용자에게는 "내일 다시 시도"라는 인지로 자연스러운 정리.

외부 장애

외부 사업자가 일시적으로 응답하지 않는다

사용자는 인증 페이지에서 정상 입력을 마쳤지만, 서버가 결과를 받아오는 단계에서 외부 사업자가 응답하지 않는다. 토스 경로는 일시적인 서버 오류를 최대 세 번 다시 시도한다. 끝까지 결과를 확인하지 못하면 해당 인증 시도는 실패로 기록되고 실패 안내를 보여 준다. 사용자는 잠시 뒤 새 인증 시도를 시작할 수 있다.

운영자가 확인하는 것 — 실패한 시도는 관리자 웹의 회원별 이력에 공급자·실패 코드·메시지와 함께 남는다. 여러 회원에게 같은 실패가 몰리면 개인의 입력 문제가 아니라 공급자 장애인지 판단할 수 있다.

운영 예외 · 구현·검증 완료, 실환경 확인 전

정상 본인확인이 실패하거나 만료돼 검토를 요청한다

최근 인증 시도의 실패·만료 또는 응답 대기 만료가 확인되고 정상 인증이 진행 중이지 않을 때, 서버가 수동 검토 진입을 허용한다. 회원은 비공개 신분 증빙을 올리고 검사 중·검토 대기·처리 결과를 본다. 이미 유효한 인증이 있거나 정상 인증이 진행 중이면 새 제출로 이를 대체할 수 없다.

권한 있는 플랫폼 관리자가 검사를 통과한 실제 제출물을 열람하고 생년월일·성별·만료일·사유를 입력해 승인한다. 검토 도중 회원이 파일을 바꾸면 이전 파일에 대한 승인 입력과 열람 확인은 무효가 된다. 반려된 증빙은 자격이 허용될 때 다시 제출할 수 있다.

회원에게 남는 결과 — 승인·취소 알림과 화면 재진입으로 현재 자격을 확인한다. 떠 있는 화면이 결정 푸시만으로 즉시 갱신된다고 보장하지 않는다. 실제 저장소·검사·서명 앱 왕복은 출시 전에 확인한다.

1년 후 재인증

작년에 인증한 사용자가 다시 데이팅을 켰을 때

작년에 데이팅을 잠깐 써 보고 나갔다가 1년 뒤에 다시 들어온 사용자. 앱은 만료 시점을 인지하고 "본인 인증이 만료되었습니다" 화면과 만료일을 함께 보여 준다. "다시 인증하기"를 누르면 첫 인증과 동일한 흐름이 진행되고, 통과하면 또 다시 1년 동안 데이팅을 사용할 수 있다.

이 흐름이 남기는 것 — 휴면 사용자가 돌아왔을 때 안전 검증을 한 번 더 거치되, 새 가입처럼 모든 정보를 다시 받지는 않는다 — 데이팅 프로필 본문은 그대로 살아 있다.

이미 인증된 사용자

호기심에 다시 인증을 시도

이미 인증 완료 상태에서 사용자가 "본인 인증하기" 버튼을 다시 누르는 경우. 서버는 재인증이 필요 없다는 의미로 요청을 막는다. 사용자에게는 "본인인증 요청에 실패했습니다" 안내가 뜬다.

운영 관찰 포인트 — 현 안내는 "이미 인증되어 있어 추가 인증이 필요 없습니다" 같은 적극적 메시지가 아니다. 사용자가 혼란스러워하는 신호가 들어오면 안내 카피의 분기를 따로 둘 여지 있음.

화면에서 사용자가 인지하는 것

화면 요소사용자가 보는 것그 자리에 둔 이유
안내 헤더 "안전한 데이팅을 위해 본인 인증이 필요합니다" 라는 한 줄과 보조 설명. 인증을 단순한 행정 절차가 아닌 "내 안전을 위한 절차"로 사용자에게 다시 한 번 자리매김한다. 본인 인증을 "왜 하라는 거지?"의 의문 없이 자연스럽게 받아들이게.
안전 체크리스트 세 줄 "실명 인증으로 안전한 매칭 / 나이·성별 자동 확인 / 개인정보는 인증 목적으로만 사용". 사용자가 가장 자주 갖는 세 가지 의심에 대한 답을 미리 둔다. 동의 화면이 아니라 안내 화면이지만, 사용자가 본인 정보를 넘기는 것에 대한 심리적 저항을 줄이는 자리.
본인 인증하기 버튼 화면 하단에 고정된 큰 버튼. 누르면 "인증 요청 중..."으로 잠깐 라벨이 바뀐 뒤 서버가 설정한 공급자의 인증 페이지가 자리에 들어온다. 정상 본인확인이 기본 경로다. 실패 뒤 수동 검토 가능 여부는 서버가 별도로 판정한다.
인증 페이지 안착 풀스크린 모달이 아니라 같은 화면의 본문 자리에 인증 페이지가 자연스럽게 들어온다. "외부 페이지로 떠난다"는 인상을 주지 않는다. 사용자에게는 "같은 앱 안에서 한 단계 진행 중"으로 보이는 게 자연스럽다.
만료 안내 화면 서버가 유효기간 만료로 판정하면 만료일과 "다시 인증하기" 버튼을 보여 준다. 수동 승인 취소도 현재 자격에 반영된다. "왜 갑자기 또?" 라는 의문에 미리 답한다. 만료일을 직접 보여 줘 사용자가 시간 흐름을 자기 눈으로 확인하게 한다.
실패 사유 카드 실패 시 노출 — "입력한 정보가 일치하지 않을 수 있습니다 / 일시적 장애일 수 있습니다 / 일일 시도 횟수를 초과했을 수 있습니다" 세 가지 후보. 실패 사유를 단정하지 않는다. 정확한 원인은 외부 사업자에게 있어 알기 어렵기 때문 — 사용자가 자신의 상황과 대조해 다음 행동을 정할 수 있게 후보를 나열한다.
본인확인 검토 요청 신청 가능한 경우 증빙 업로드·다른 파일로 재제출·제출 철회가 보인다. 검사 중과 검토 대기를 구분한다. 회원이 무엇을 기다리는지 알게 한다. 승인된 증빙을 철회하면 그 증빙으로 받은 자격도 사라질 수 있음을 확인받는다.

측정해야 하는 것

본 단위가 건강하다고 말하려면 이 네 가지 신호가 추적되어야 한다
  • 데이팅 첫 진입 → 인증 완료 전환율 — 신규 사용자가 인증을 거쳐 데이팅 사용자가 되는 비율. 이 숫자가 떨어지면 본 단위의 안내·인증 흐름 자체가 진입 장벽이 되고 있다는 신호.
  • 인증 요청 → 인증 완료 시간 — 사용자가 "본인 인증하기"를 누른 시점부터 완료 토스트까지의 시간. 너무 길면 외부 환경 또는 사용자의 입력 단계 어딘가에서 막힌다.
  • 실패 사유 분포 — "일치 안 함 / 외부 장애 / 일일 한도 초과" 어느 사유가 늘어나는지. 외부 장애 비중이 커지면 외부 사업자 측 상태를 의심한다.
  • 1년 만료 → 재인증 회수율 — 만료된 휴면 사용자가 돌아와 다시 인증하는 비율. 너무 낮으면 만료 → 재인증 흐름 자체가 사용자 이탈 지점이 되고 있을 가능성.

운영자가 알아야 할 것

본 단위에서 신뢰가 무너지면 데이팅 도메인 전체가 신뢰를 잃는다
  • 외부 본인인증 사업자에 강하게 의존한다. 사업자 측 장애가 그대로 데이팅 신규 가입 정지로 나타난다 — 외부 상태 모니터링이 본 도메인 모니터링과 함께 가야 한다.
  • 일일 5회 한도는 사용자 1명 단위다. 같은 사람이 빠르게 다섯 번 시도하면 그날 안에는 더 이상 못 한다. 이 한도가 너무 낮다는 신호가 들어오면 조정 여지 있음 — 다만 외부 사업자 호출 비용·악용 방지 측면에서 균형이 필요.
  • 인증 원문과 서비스용 회원정보를 구분해야 한다. 인증 결과의 실명·생년월일·CI·DI는 암호화해 보관하고 휴대폰 번호는 플랫폼에 저장하지 않는다. 데이트 자격 판정에 필요한 생년월일·성별은 정상 인증 뒤 회원정보에도 동기화되므로 접근 권한과 내보내기·삭제 정책을 함께 적용해야 한다.
  • 수동 검토는 클럽 운영진의 권한이 아니다. 권한 있는 플랫폼 관리자가 실제 증빙을 확인하고 승인·취소한다. 제출물 교체나 늦은 응답으로 다른 파일의 검토 결과를 재사용하지 않으며, 감사 상세에서도 개인정보를 가린다.
  • 신분 증빙은 정해진 기간만 보관하고 스스로 사라진다. 승인·취소로 검토가 끝난 증빙은 기본 90일이 지나면 매일 도는 정리 작업이 원본까지 지운다. 결론이 나지 않은 제출물도 30일이 지나면 자동으로 닫아 같은 정리 대상에 넣는다. 회원이 직접 제출을 철회하면 보관 기간을 기다리지 않고 즉시 지우며, 그 증빙으로 받은 자격도 함께 거둔다. 이 기간은 운영 설정값이라 법무 판단에 따라 조정할 수 있지만, 바꾸면 개인정보 보유기간 고지도 함께 맞춰야 한다.
  • 1년 만료 처리가 정확히 동작하지 않으면 두 가지 위험이 동시에 발생. 너무 빨리 만료시키면 멀쩡한 사용자가 갑자기 데이팅에서 튕겨 나가고, 너무 늦게 만료시키면 신원이 바뀐 사용자가 통과 상태로 머문다.
  • 본 인증 통과는 데이팅 모든 후속 기능의 전제다. 프로필 작성, 후보 카드 조회, 호감 표시, 채팅 어느 한 곳이라도 인증 가드가 풀리는 사고가 발생하면 안전 보장이 전 도메인에서 의미를 잃는다.
