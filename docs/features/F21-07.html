F21-07. 정기모임 묶음 배정 · 정산

여러 회차로 구성된 정기모임에 같은 제공자를 한 번의 동작으로 direct 배정하고, 모든 회차를 한 번에 정산할 수 있다. 회차별로 정산 결과가 따로 표시되며, 막힌 회차가 있으면 호스트가 직접 조치한 뒤 다시 시도해야 한다.

설계 의도 — 반복되는 모임에서 매번 배정·정산을 반복하지 않도록

같은 강사가 매주 오는 정기모임에서 회차마다 배정을 새로 만들고 정산을 따로 실행하면 호스트의 반복 작업이 누적된다. 묶음 배정은 한 번의 동작으로 전체 회차에 제공자를 배정하고, 묶음 정산은 준비된 회차를 한 번에 처리한다. 각 회차의 결과는 개별로 추적되어 어느 회차가 정산됐고 어느 회차에 문제가 있는지 바로 알 수 있다.

2026-07-29 현재 소스 갱신 — 카탈로그·회차 승계 경계

묶음 배정 API는 CATALOG 출처를 거부한다. 수락된 카탈로그 계약의 다음 회차는 상품 스냅샷과 X/D를 새 terms v1로 복제하되 재수락 전까지 돈 동작을 열지 않는다. direct 또는 미수락 계약은 provider id/role만 DRAFT로 복제되지만 현재 DRAFT 재개 API가 없다. 회차 replace는 비종단 assignment의 eventId를 옮기므로 연결 charge/prepayment/terms도 assignmentId를 따라간다. 묶음 SETTLED는 earning APPROVED이며 실제 지급은 주간 배치다.

회차별 정산 결과 6가지

묶음 정산을 실행하면 각 회차에 다음 중 하나의 결과가 붙는다.

정산됨

이번 정산에서 정상 완료된 회차

해당 회차의 분담금 합계와 이행 조건이 충족돼 배정이 잠기고 earning이 APPROVED가 됐다. 실제 제공자 지갑 지급은 주간 배치가 수행한다. 이후 이 회차는 재처리 대상에서 제외된다.

이미 정산

이전에 이미 완료된 회차

지난번 묶음 정산 또는 개별 정산에서 이미 처리된 회차다. 이번 실행에서 건너뛰어 중복 지급이 발생하지 않는다.

대상 없음

이 회차에 배정된 제공자가 없다

해당 회차에는 서비스 배정 자체가 없는 경우다. 정산 대상이 아니므로 자동으로 건너뛴다. 호스트가 의도적으로 이 회차에 제공자를 배정하지 않은 것이다.

준비 안 됨

배정이 아직 CONFIRMED가 아니거나 회차가 끝나지 않았다

SKIPPED_NOT_READY는 오직 이 두 조건에 사용된다. 시간이 지나 회차가 끝나거나 배정을 CONFIRMED로 만든 뒤 묶음 정산을 다시 실행해야 한다. 미납·과수금이나 조건 금액 불일치는 "막힘"으로 분류된다.

막힘

호스트 조치가 필요한 문제가 있다

미납·금액 불일치·earning 이상·노쇼 출석 충돌·계약금 미적용·terms 재수락 대기· 이행 확인 미완료처럼 호스트 조치가 필요한 상태다. 호스트가 화면에서 원인을 확인하고 직접 조치한 뒤 재시도해야 한다. 다른 회차의 정산은 이 회차 때문에 멈추지 않는다.

실패

시도했지만 오류로 처리되지 못했다

정산 시도 중 예상치 못한 오류가 발생하여 지급이 이루어지지 않았다. 실패 회차는 별도 재시도 또는 개별 정산으로 처리해야 한다. 다른 회차의 결과는 이 실패에 영향받지 않는다.

사용자 시나리오

기본 흐름 — 묶음 배정 후 일괄 정산

4주 연속 정기모임에 같은 강사를 배정하고 한 번에 정산한다

호스트가 4주 정기모임의 제공자로 강사를 설정한다. 한 번의 동작으로 4개 회차 모두에 배정이 생성된다. 4주차가 아직 끝나기 전에 묶음 정산을 실행하면 회차별 결과가 나란히 표시된다. 1~3주차는 "정산됨", 4주차는 회차 미종료라 "준비 안 됨"으로 표시된다.

이 흐름이 남기는 것 — 4번 반복할 배정과 정산이 하나의 동작으로 줄어든다. 미완료 회차가 어디인지 한눈에 파악할 수 있다.

막힘 회차 처리

3개 회차 중 하나가 막혀 있다

묶음 정산을 실행했더니 2회차가 "막힘"으로 표시된다. 호스트가 2회차 상세를 열어 원인을 확인한다. 원인을 해소한 뒤 해당 회차만 개별 재정산을 실행한다. 1회차와 3회차는 이미 "정산됨" 상태이므로 영향을 받지 않는다.

이 흐름이 남기는 것 — 한 회차의 문제가 전체를 막지 않는다. 정상 처리된 회차는 확정된 채로 유지되고, 막힌 회차만 별도로 해결한다.

재실행 — 이미 정산된 회차 건너뜀

묶음 정산을 두 번 실행했다

호스트가 실수로 묶음 정산 버튼을 한 번 더 눌렀다. 이미 "정산됨" 처리된 1~3회차는 "이미 정산" 결과로 건너뛴다. 아직 처리되지 않은 4회차만 새로 시도된다. 중복 지급이 발생하지 않는다.

이 흐름이 남기는 것 — 운영 과정의 실수로 같은 정산이 두 번 처리되는 사고를 막는다. 정산된 회차는 안전하게 잠기고 재처리에서 자동으로 제외된다.

배정 없는 회차 포함

5회차 중 3회차는 제공자가 없다

5회차 정기모임 중 3회차는 호스트가 직접 진행하여 제공자를 배정하지 않았다. 묶음 정산 시 1, 2, 4, 5회차는 정상 처리되고, 3회차는 "대상 없음"으로 자동 건너뛴다. 특별한 조치 없이도 전체 묶음 정산이 완료된다.

이 흐름이 남기는 것 — 배정이 없는 회차가 섞여 있어도 묶음 정산이 중단되지 않는다. 호스트는 매 회차 배정 여부를 신경 쓰지 않고 일괄 처리를 누를 수 있다.

준비 안 됨 — 종료 후 수동 재실행

이번 달 4개 회차 중 마지막 회차가 아직 끝나지 않았다

묶음 정산 결과 4회차가 "준비 안 됨"으로 나왔다. 앱은 결과 배지만 보여 주고 재시도 시점이나 CTA를 별도로 안내하지 않는다. 호스트가 회차 종료 뒤 묶음 정산을 다시 실행해야 한다.

현재 결과 — 다음 실행에 다시 포함되지만 자동 재시도되지는 않는다. 종료 시각과 안내 CTA가 없어 호스트가 직접 추적해야 한다.

운영자가 알아야 할 것

한 회차의 문제가 전체를 막지 않는다 — 회차별 결과를 각각 확인해야 한다
  • 묶음 정산을 실행했다고 모든 회차가 처리된 것이 아니다. 회차별 결과를 반드시 확인해야 한다. "정산됨"이 아닌 결과가 있으면 각 결과에 맞는 조치가 필요하다.
  • "막힘"과 "실패"는 다르다. 막힘은 운영 또는 배정 상태 문제로 시스템이 진행을 멈춘 것이고, 실패는 진행하다가 오류가 난 것이다. 막힘은 호스트가 원인을 해소하면 재시도 가능하고, 실패는 오류 내역을 확인하여 재시도하거나 운영팀에 문의해야 한다.
  • 이미 정산된 회차는 중복 처리되지 않는다. 묶음 정산을 여러 번 실행해도 "이미 정산" 회차는 건너뛴다. 호스트가 실수로 다시 눌러도 중복 지급 사고가 발생하지 않는다.
  • 묶음 배정 취소 API는 현재 없다. 서버가 제공하는 정기모임 묶음 endpoint는 배정 생성과 정산뿐이다. 배정을 취소하려면 각 회차의 개별 취소 경로를 사용해야 한다.
  • 결과 화면은 회차를 회차 #eventId로만 식별한다. 날짜·sequenceNo·제목이 없어 실제 회차와 맞추기 어렵다. BLOCKED만 "분담금 현황" CTA가 있고 SKIPPED_NOT_READY에는 재시도 안내 CTA가 없다.
  • 회차 단위 개별 정산과 묶음 정산은 함께 사용할 수 있다. 급한 회차를 먼저 개별 정산으로 처리한 뒤, 나머지를 묶음으로 정산해도 된다. 이미 처리된 회차는 묶음 정산 시 자동으로 건너뛴다.
