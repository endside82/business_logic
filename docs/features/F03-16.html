F03-16. 이벤트 버스대절

서버에서 호스트가 버스를 추가하고 좌석을 지정하는 단위. 세 가지 배정 enum은 존재하지만 FIRST_COME 자동 배정과 실제 좌석 swap·unassign은 구현되지 않았고 Flutter 운영 화면도 없다.

설계 의도 — 좌석을 단순 목록이 아니라 운영 상태로 관리한다

버스 대절은 참석자 수만 아는 것으로 충분하지 않다. 좌석이 있는 차량인지, 호스트가 고정 배정하는지, 참가자가 직접 바꿀 수 있는지, 한 사용자가 두 버스에 중복 배정되지 않는지가 모두 중요하다.

현재 구현 경계

FIRST_COME도 빈 좌석을 복사할 뿐 자동 배정하지 않는다. SKIP LOCKED 쿼리는 없고, 좌석 PUT은 target의 사용자를 덮어쓸 뿐 기존 좌석을 비우거나 두 좌석을 맞바꾸지 않는다. add/assign은 event status를 검사하지 않아 CLOSED/CANCELED에서도 변경 가능하다. 81~82 알림은 enum만 있으며 Flutter 버스 기능은 없다.

사용자 시나리오

버스 추가

레이아웃으로 버스 생성

호스트가 vehicleLayoutId를 보내면 선택 가능한 좌석을 복사한다. 기본 28인승 seed는 없고 FIRST_COME도 승인 참가자를 자동 배정하지 않는다.

호스트 지정

좌석을 직접 배정

호스트는 특정 좌석의 userId를 지정한다. 현재 API는 lockedByHost를 검사하지 않고, 이미 좌석이 있는 사용자의 이동은 unique 제약으로 실패할 수 있다.

자유석

좌석표 없이 인원만 관리

자유석 모드에서는 좌석표를 만들지 않고 탑승 인원만 표시한다. 실제 탑승 위치는 현장 운영으로 넘긴다.

제한

4번째 버스를 추가하려 함

이벤트당 최대 3대까지만 허용한다. 버스 수 상한을 넘으면 추가할 수 없다.

소속 검증

다른 이벤트의 버스로 좌석 조회

버스가 해당 이벤트 소속이 아니면 거절된다. 좌석을 가리키는 값을 바꿔도 다른 이벤트의 좌석을 볼 수 없다.

동시성

한 사용자를 두 버스에 동시에 배정

DB unique가 중복을 막고 event lock이 같은 이벤트의 write를 직렬화한다. 다만 오류는 전용 코드가 아닌 일반 INVALID_REQUEST로 바뀌며 seat lock/SKIP LOCKED는 없다.

운영자가 알아야 할 것

차량과 좌석은 별도 수명주기를 가진다
  • 차량 레이아웃은 카탈로그에서 온다. 호스트가 임의 좌석 구조를 만들지 않는다.
  • 자유석 방식은 좌석 배치가 없다. 화면이 빈 좌석표를 오류로 해석하면 안 된다.
  • 한 참가자는 한 이벤트에서 한 좌석만 가진다. 여러 버스가 있어도 사용자 중복 배정을 막는다.
  • 이동수단 방식이 "버스"가 아니면 전체 기능이 닫힌다. 하위 기능은 F03-14의 이동수단 방식을 따른다.
  • 목록 GET은 예외다. 현재 서비스는 mode나 event 존재·역할을 검사하지 않는다.
  • 자기 좌석 변경 가드가 부족하다. 참석 자격·assignment mode·lockedByHost를 검사하지 않는다.
  • SELF_SWAP 테스트도 실제 swap을 보장하지 않는다. 타인의 target 좌석을 본인으로 덮어쓰는 현재 동작을 성공으로 고정할 뿐 두 좌석 교환은 검증하지 않는다.
