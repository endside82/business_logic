대절 버스와 자리 배정

버스 등록·첫 직접 잡기/배정 후 변경/비우기 권한·차량과 물리 좌석 분리·도면 전환·전체 변경 보존을 구분한다. 2026-11-22 소스 대조이며 새 실행 결과와 구분합니다.

구현 있음웹 확인실제 환경 확인 대기

결론

버스를 먼저 차량별 배정으로 등록하고, 필요할 때 검증된 배치도를 선택해 실제 좌석을 지정한다. 어떤 차량에 타는지와 그 차량의 어느 물리 좌석에 앉는지를 분리한다. 버스 기사는 회원 승객 정원에 포함하지 않는다.

자리 채우기 방식(HOST_ASSIGNS·SELF_CLAIMS), 좌석 지정 여부(DESIGNATED·UNDESIGNATED), 모임의 배정 후 본인 변경 허용은 서로 다른 조건이다. ‘참가자 자기 선택’ 하나로 첫 자리 잡기·배정 후 이동·자리 비우기를 모두 허용하거나 금지한다고 설명하지 않는다.

버스 등록과 기본 상태

호스트·활성 공동호스트가 상세 열람 가능, 모임 OPEN, 이동 조율 사용 조건에서 등록한다. 확정된 BUS가 10대 미만이어야 하며 취소된 차량을 같은 상한의 확정 버스로 세지 않는다. 모임 안의 기존 차량 번호 최댓값 다음 번호를 부여한다.

입력은 기사 제외 승객 정원 1~100, 선택 경로·안내 각 500자 이내, 선택 비용 0~10억 원, 선택적인 자리 채우기 방식이다. 비용 빈칸과 0원은 미정과 무료로 구분하며 안내 금액 자체가 결제 명령은 아니다. 방식 누락 시 HOST_ASSIGNS를 사용하고 앱도 이 값을 기본 선택한다.

새 버스는 소유 회원·운전자 자리가 없는 BUS·CONFIRMED·UNDESIGNATED·allocationVersion 2다. 승객 정원만큼 내부 정원 칸을 만들며, 등록 때 배치도 번호를 받거나 승객의 물리 좌석을 확정하지 않는다. 내부 seatNo 순번을 실제 좌석 번호로 화면에 내세우지 않는다.

첫 배정·본인 이동·자리 비우기

공통으로 OPEN·조율 사용과 현재 배정 자격을 검사한다. 대상은 실제 참석 회원과 호스트·활성 공동호스트이며 종료된 계정은 제외한다. LEFT인 사람, 살아 있는 본인 차량의 운전자, 유효하지 않은 기존 배정 등에는 추가 제한이 있다.

앱은 상태에 따라 ‘빈 자리 직접 잡기’, ‘빈 차량·좌석으로 변경’, ‘내 자리 비우기’를 따로 표시한다. 지원 확인 대기·구형 기록 확인 필요 상태에서는 본인 조작 입구를 더 제한한다. 정원과 실제 좌석 점유는 제출 시 다시 검사한다.

정책 폼의 ‘처음 배정은 언제나 호스트’, ‘자리를 반납할 수는 없어요’ 안내는 위 실제 조건보다 좁다. 현재 화면 버튼·provider 판정·서버 명령·선택한 기존 시험에는 첫 직접 잡기와 조건부 본인 비우기가 구현돼 있다. 안내 문구를 기준으로 이 기능들을 문서에서 없애지 않는다.

주최자 일괄 조정과 정원 변경

배정 요청은 사람별 목적 차량 또는 미배정 의사, 선택적인 실제 좌석 번호, 차량별 정원·경로·안내·비용·자리 채우기 방식, 필수 사유를 담는다. 사람 변경은 최대 200개, 차량 변경은 최대 100개이며 사유는 공백이 아닌 500자 이내다. 같은 사람·차량을 중복 지정하지 않는다.

사람별 결과는 목적 차량 또는 NEEDS_ASSIGNMENT·INDIVIDUAL 중 하나다. 개별 이동 정책도 검사한다. 목적 차량은 같은 모임의 확정된 공동 차량이어야 하며 SELF를 공동 목적지로 쓰지 않는다. 카풀로 이동하는 경우 운전자와 승객의 차단 관계도 검사한다. 그 조건을 버스 탑승자 전체의 차단 관계 제한으로 확대하지 않는다.

변경 대상들의 최종 상태를 먼저 계산해 정원·중복·좌석 조건을 검사한다. 정원을 줄여도 남는 인원이 정원보다 많으면 거절하며, 다른 차량이나 배정 필요로 보낼 사람을 같은 조정에 포함해야 한다. 지정 좌석 차량의 정원은 이 일반 명령으로 임의 변경할 수 없고 좌석 방식 변경 절차를 사용한다.

검사 후 실제로 변경되는 기존 자리를 먼저 비우고 새 배정을 저장한다. 정원에서 제외되는 빈 내부 칸은 비활성으로 남기며 점유한 칸을 조용히 삭제하지 않는다. 차량 정책만 바꾸는 경우에도 현재 탑승자를 임의 해제하지 않는다. 최초 배정·재배정·본인 이동·해제·정원/차량 변경의 이력을 구분해 남긴다.

차량 탑승과 물리 좌석의 분리

비지정은 승객 정원과 탑승 명단을 관리한다. 지정은 배치도의 실제 번호를 추가로 사용하지만, allocationVersion 2에서 주최자가 차량만 먼저 배정하고 세부 좌석을 나중에 정할 수도 있다. 이 경우 ‘차량은 배정됐고 세부 좌석을 기다리는 승객’으로 표시한다. 본인이 지정 차량의 자리를 잡거나 변경할 때는 실제 좌석 번호가 필요하다.

선택 가능한 승객 칸만 목적지가 된다. DRIVER·AISLE·DISABLED, 선택 불가 칸, 존재하지 않는 번호, 이미 다른 사람이 쓰는 물리 좌석은 거절한다. 버스 기사의 운전석을 회원 승객에게 배정하지 않는다. 카풀은 별도의 운전자 칸을 유지한다.

DB 정의에는 모임 내 회원당 한 자리, 차량 내 내부 번호 유일성, 차량 내 물리 좌석 번호 유일성과 비활성 칸 비점유 제약이 있다. 명령은 공통 모임 잠금·개정 검사와 트랜잭션을 거친다. 이는 소스·스키마 근거이며 실제 동시 접속 부하나 마지막 자리 경합 시험을 이번에 실행했다는 뜻이 아니다.

좌석 지정·해제·다른 배치도로 전환

주최자는 차량 카드의 ‘좌석 방식·배치도 변경’에서 차량별 배정 또는 실제 좌석 지정을 선택한다. 지정은 해당 차량 종류의 활성·확인 기록이 있는 배치도 목록을 사용한다. 앱은 도면·출처/참고 내용을 보여 주고 실제 이용 차량과 차종·운전석·통로·좌석 위치가 같은지 확인한 뒤 탑승자 조정으로 이동한다. 선택 화면에서 미리 보기만으로 저장하지 않는다.

서버는 현재 모임·차량·탑승자 자격, 도면 활성/확인/차종/개정과 좌표·번호·운전석·승객 정합성을 검사한다. 지정된 도면에는 운전석이 정확히 하나 있어야 하고 선택 가능한 승객 수가 선언 정원과 같아야 한다. 실제 차량과 같다는 앱 확인을 서버의 실물 검증으로 간주하지 않는다.

전환은 내부 배정을 보존한 채 물리 번호를 초기화하고 필요한 인원·정원을 조정한 뒤 새 물리 좌석을 적용한다. 최종 승객 전원의 항목이 있어야 하지만 물리 번호 null은 세부 미배정으로 허용한다. 줄어든 정원에 남을 수 없는 사람의 이동 결과를 빼면 실패한다. 실패한 전환은 일부 정원·좌석만 저장하는 별도 작업으로 나뉘지 않는다.

변경 기록·화면 갱신

좌석 방식 변경 기록에는 전후 방식·배치도·정원, 기존 배정 버전, 행위자·사유·적용 개정과 사람별 전후 차량·좌석·상태를 저장한다. 조회는 주최자 권한으로 최근 기록부터 반환한다. 앱은 날짜·방식·정원·사유·사람별 전후 결과와 로딩·오류 재시도를 표시한다.

현재 배정 결과의 도면은 읽기 전용이다. 본인 변경은 별도 버튼과 편집 폼에서 진행한다. 도면 로딩 실패는 다시 불러올 수 있고 신원이 숨겨진 점유자는 일반 참가자 문구로 표시한다. 앱의 결과 도면·편집 도면과 실제 차량 도면 확인을 서로 같은 검수로 세지 않는다.

저장 후 현황·차량·관련 변경 기록 갱신과 응답 유실 복구는 공통 설정의 저장 후 갱신과 실패 표시 및 충돌과 응답 유실 복구를 따른다.

안전 안내·취소·자리 신고

지원·버스 등록 폼은 당사자의 운전자·보험·차량 확인과 서비스의 안전 보증 범위를 안내한다. 현재 고지와 운행 취소·모임 참가 종료의 구분은 카풀 지원 문서의 안전 안내와 차량 신고, 운행 취소·다시 배정·지원 차량 교체를 따른다. 차량 취소는 이력을 보존하고 남은 사람을 다시 배정하는 흐름이며, 차량 행의 단순 삭제와 다르다.

자리 신고는 실제 ATTENDING 회원, 같은 모임 차량·자리, 현재 점유 회원을 검사한다. 빈 자리·본인 신고를 거절하고 expectedTargetUserId가 전달됐다면 현재 점유자와 비교해 변경 오류를 반환한다. 클라이언트가 신고 대상 회원을 임의 확정하는 구조가 아니다. 성공은 HTTP 201·ReportVo이며 출시 범위의 안전 출구다. 신고 처리 결과나 실제 기기 왕복은 이번에 확인하지 않았다.

현재 API와 출시 근거

버스 등록 POST /api/v1/events/{eventId}/transport/coordination/buses, 주최자 조정 POST /assignments, 본인 조정 POST /my-assignment는 같은 coordination 접두 경로를 사용한다. 좌석 전환 POST /vehicles/{vehicleId}/layout와 기록 GET /vehicles/{vehicleId}/layout-changes도 그 아래에 있다. 변경은 공통 requestId·expectedRevision과 TransportCommandVo를 사용하며 도면 개정은 별도 expectedDiagramRevision이다.

자리 신고는 POST /api/v1/events/{eventId}/vehicles/{vehicleId}/seats/{seatNo}/report다. 여기의 seatNo는 해당 저장 자리 식별자이며 allocationVersion 2의 물리 layoutSeatNo와 무조건 같은 값이라고 가정하지 않는다.

2026-09-02 작성본의 ‘신규 이용 봉인’·‘표준 9종을 곧바로 운영에 사용’·예전 EventTransportScreen 중심 설명은 현재 상태로 재사용하지 않는다. 공통 설정의 출시 상태와 기존 기록의 해석에 따라 구현·기존 실행 기록·실제 기기의 남은 확인을 구분한다.
