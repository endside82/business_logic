F03-16. 이벤트 버스대절

호스트가 최대 3대의 버스를 편성하고 참가자가 좌석을 확인하거나 정책에 따라 직접 고르는 기능이다. 서버의 권한·좌석 상태기계, Flutter의 버스 편성·좌석표·배정·반납·안전 신고 화면, 변경 이력과 알림 발행까지 연결돼 있다. 첫 출시에서는 신규 버스 운영을 닫고 좌석 반납·안전 신고 출구만 유지한다.

설계 의도 — 좌석을 단순 목록이 아니라 운영 상태로 관리한다

버스 대절은 참석자 수만 아는 것으로 충분하지 않다. 좌석이 있는 차량인지, 호스트가 고정 배정하는지, 참가자가 직접 바꿀 수 있는지, 한 사용자가 두 버스에 중복 배정되지 않는지가 모두 중요하다.

2026-08-23 현재 — 역할별 화면과 좌석 상태기계 완료

자유석은 현장에서 정하고, 선착순은 참석자가 빈 좌석을 직접 고르며, 호스트 지정은 운영자가 참가자를 배정한다. 좌석 이동은 기존 좌석 해제와 새 좌석 점유를 한 처리로 묶고, 경합 시 한쪽만 성공한다. 호스트가 남의 좌석을 바꾸거나 해제하면 사유·변경 이력·알림이 남는다.

개통을 위해 남은 핵심은 차량 레이아웃을 등록·활성화하는 플랫폼 관리자 웹 화면과 초기 데이터, 실제 기기에서의 다중 역할·알림·신고 검증이다. 호스트 본인을 좌석에 넣는 범위도 확정해야 한다.

사용자 시나리오

버스 추가

레이아웃으로 버스 생성

호스트가 앱에서 운영팀이 활성화한 차량 레이아웃과 좌석 운영 방식을 고른다. 자유석을 제외하면 선택 가능한 좌석이 이벤트용 좌석표로 복사된다.

호스트 지정

좌석을 직접 배정

호스트는 참석자를 빈 좌석에 배정하거나 기존 좌석에서 옮기고 해제할 수 있다. 다른 사람에게 영향을 주는 변경은 사유를 필수로 받고 대상자에게 알린다.

자유석

좌석표 없이 인원만 관리

자유석 모드에서는 좌석표를 만들지 않고 탑승 인원만 표시한다. 실제 탑승 위치는 현장 운영으로 넘긴다.

제한

4번째 버스를 추가하려 함

이벤트당 최대 3대까지만 허용한다. 버스 수 상한을 넘으면 추가할 수 없다.

소속 검증

다른 이벤트의 버스로 좌석 조회

버스가 해당 이벤트 소속이 아니면 거절된다. 좌석을 가리키는 값을 바꿔도 다른 이벤트의 좌석을 볼 수 없다.

동시성

한 사용자를 두 버스에 동시에 배정

이벤트 잠금과 사용자당 한 좌석 제약이 중복 배정을 막는다. 같은 좌석이나 같은 사용자를 동시에 옮기면 한 요청만 성공하고, 실패한 요청은 다시 읽어 선택하도록 응답한다.

서버 동작과 현재 제품 노출

동작누가무엇이 일어나는가
버스·좌석 조회호스트/공동 호스트·참석/대기 참가자Flutter 좌석표에 연결된다. 일반 참가자에게는 타인의 식별 정보를 숨기고 점유 여부만 보여 준다.
버스 추가·삭제호스트·공동 호스트버스 방식에서 최대 3대까지 편성한다. 탑승자나 안전 신고가 남은 버스는 먼저 종결하지 않으면 삭제할 수 없다.
좌석 선택·이동선착순 방식의 참석자빈 좌석만 고르고, 자리 이동이 허용된 경우 기존 좌석에서 새 좌석으로 원자적으로 옮긴다. 정책에 따라 자기 좌석을 반납할 수 있다.
좌석 배정·해제호스트·공동 호스트참석 자격을 확인하고 타인 변경 사유를 기록한다. 변경 이력과 좌석 배정·변경 알림이 남는다.
좌석 안전 신고신고 대상이 아닌 참석자좌석을 길게 눌러 신고하고 플랫폼 신고·분쟁 운영 화면에서 사건 맥락을 확인한다.

운영자가 알아야 할 것

차량과 좌석은 별도 수명주기를 가진다
  • 차량 레이아웃은 카탈로그에서 온다. 호스트가 임의 좌석 구조를 만들지 않는다.
  • 자유석 방식은 좌석 배치가 없다. 화면이 빈 좌석표를 오류로 해석하면 안 된다.
  • 한 참가자는 한 이벤트에서 한 좌석만 가진다. 여러 버스가 있어도 사용자 중복 배정을 막는다.
  • 이동수단 방식이 "버스"가 아니면 전체 기능이 닫힌다. 하위 기능은 F03-14의 이동수단 방식을 따른다.
  • 목록과 좌석은 참여 범위를 확인한다. 호스트·공동 호스트 또는 참석/대기 행이 있는 사용자만 보며, 일반 참가자의 타인 신원은 숨긴다.
  • 좌석 이동·해제는 실제 상태 전이다. 기존 좌석을 먼저 비우고 새 좌석을 잡으며, 참가자 권한·운영 방식·호스트 잠금·각자 이동 허용을 서버가 검사한다.
  • 참가 종료와 좌석 정리가 같이 움직인다. 취소·강퇴·환불로 참석이 끝나면 좌석도 같은 처리에서 회수돼 유령 좌석을 남기지 않는다.
  • 차량 레이아웃 운영 화면이 개통 선행 조건이다. 관리자 API만 있고 관리자 웹은 없으며 빈 데이터베이스에 기본 차량도 없다.
