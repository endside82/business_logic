F03-14. 이동수단 공통 베이스

이벤트마다 이동수단을 없음·카풀·버스 중 하나로 정하고 하위 기능의 진입을 통제하는 공통 설정이다. 호스트용 Flutter 설정 화면과 이벤트 상세 진입 버튼이 서버 계약에 연결돼 있다. 방식 변경은 초안에서만 가능하고, 공개 뒤에는 참가자의 기존 배정이 사라지지 않도록 고정한다.

설계 의도 — 이동수단 기능의 단일 스위치

카풀과 버스는 둘 다 참석자의 이동을 바꾸는 기능이라 동시에 켜질 수 없다. 본 단위는 이벤트마다 하나의 이동수단 방식을 정하고, 하위 기능이 자기 방식이 아닐 때 동작하지 않도록 막는 공통 가드다. 공개 후 방식 변경을 막는 이유는 이미 운전자 지원, 탑승자 선택, 좌석 배정이 시작됐을 수 있기 때문이다.

2026-08-23 현재 — 설정 화면까지 연결, 첫 출시는 봉인

호스트와 공동 호스트는 이벤트 상세의 “이동수단 설정”에서 방식을 정하고, 버스를 편성하거나 카풀 운영 화면으로 이동할 수 있다. 방식을 바꿀 때 기존 카풀·버스 데이터를 지운다는 경고와 확인 절차도 있다.

다만 “각자 이동 허용”은 현재 버스 참가자의 자기 좌석 반납 여부에는 실제 적용되지만, 카풀의 개별 이동 선택에는 같은 방식으로 적용되지 않는다. 이동수단을 개통하기 전에 이 토글을 버스 정책으로 좁혀 설명할지, 카풀에도 강제할지 제품 결정을 맞춰야 한다.

사용자 시나리오

초안 단계

호스트가 카풀 이벤트로 설정

이벤트 생성 중 이동수단을 카풀로 바꾸면 이동수단 설정이 만들어지고, 이후 카풀 지원·배정 화면이 열릴 수 있다.

전환

카풀에서 버스로 바꾼다

초안 상태에서는 이동수단 방식 전환이 가능하다. 단, 기존 카풀 지원자·탑승자 데이터는 더 이상 유효하지 않으므로 삭제된다.

모집 공개 후

모집 공개 후 방식 변경 차단

이미 참가자에게 이동 정책이 공개된 뒤에는 없음·카풀·버스 사이 전환이 막힌다. 우회 시도도 서버에서 거절된다.

개별 이동

공개 후 개별 이동 허용 여부만 조정

이동수단 방식 자체는 고정되지만, 자차 이동 허용 여부는 운영 상황에 따라 조정할 수 있다. 카풀·버스 배정을 받지 않는 참가자의 선택지를 통제하는 토글이다.

이동수단 설정 변경호스트·공동 호스트초안에서는 방식과 각자 이동 허용 여부를, 공개 뒤에는 각자 이동 허용 여부만 바꾼다. 화면과 서버가 모두 권한·상태를 확인한다.

운영자가 알아야 할 것

이동수단 방식 전환은 데이터 삭제를 동반한다
  • 설정이 없으면 기본값은 이동수단 없음 + 자차 이동 허용. 신규 이벤트가 이동 기능을 쓰지 않아도 별도 설정이 필요 없다.
  • 초안 단계의 방식 전환은 하위 데이터 정리를 포함한다. 카풀에서 버스로 바꾸면 카풀 지원·탑승자 기록이 제거된다.
  • 모집 공개 이후 방식 변경은 정책상 금지다. 이미 공개된 이동 약속을 뒤집으면 참가자 피해가 크다.
  • 각자 이동 허용은 공개 뒤에도 조정할 수 있다. 현재 버스의 참가자 자기 좌석 반납 허용 여부에 실제 사용된다.
  • 카풀에는 토글 의미가 아직 일치하지 않는다. 토글이 꺼져도 카풀 참가자는 개별 이동을 선택할 수 있으므로, 개통 전에 정책 문구를 좁히거나 서버 집행을 넓힌다.
  • 서버 생애주기 E2E와 앱 권한·화면 테스트가 있다. 첫 개통 전에는 같은 출시후보를 실제 역할별 계정·기기로 다시 왕복한다.
