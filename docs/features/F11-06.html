F11-06 본인 취향 프로필과 선언 선호 관리

선호 전체 해제·저장 실패 유지·본인 선택 누적과 행동 근사·내보내기·태그 표시 한계를 현재화한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

현재 역할과 입구

취향 프로필은 본인이 선언한 카테고리·시간대·그룹 크기와, 본인이 다른 참석자에게 붙인 긍정 인상 태그의 누적을 보여 준다. 타인이 나를 평가한 결과나 성격 검사 결과를 뜻하지 않는다. 등록된 취향 프로필 화면에서 현재 프로필과 본인 선택형 피드백 통계·이력을 각각 읽고, 설정 시트로 선언 선호를 바꾼다.

본인 조회와 선언 선호 저장

GET /api/v1/taste/profile과 PUT /api/v1/taste/preferences는 로그인한 본인만 다룬다. 프로필 행이 없어도 조회는 빈 프로필 VO를 만든다. 응답은 preferredCategories, preferredTimeSlots, preferredGroupSize, positiveTagWeights, updatedAt이며 행동 근사 필드는 없다.

PUT의 세 선언 선호 필드는 문자열 목록이다. 서버는 받은 세 값을 모두 JSON 컬럼에 덮어쓴다. null은 이전 값 유지가 아니라 해당 선호를 비우는 값이다. 앱은 현재 프로필로 시트를 채우고 아무 칩도 선택하지 않은 항목을 null로 보내므로 전체 해제로 기존 선호를 지울 수 있다. 서버의 이 서비스에는 문자열 카탈로그·목록 길이를 별도 제한하는 검사가 없다.

앱은 프로필이 로딩·오류·빈 데이터 상태이면 설정 시트를 열지 않는다. 저장 성공 때 응답 프로필을 반영하고 시트를 닫으며 성공 안내를 보여 준다. 실패는 기존 프로필과 시트 선택을 유지하고 실패 안내를 표시한다. 과거 「저장 실패여도 성공으로 닫힌다」는 시나리오는 현재 Result 분기와 맞지 않는다. 계정 변경 후 오래된 요청 결과를 다음 계정 상태에 반영하지 않도록 계정 표식을 확인한다.

태그 가중치의 원천과 행동 근사

TasteProfileService.rebuildProfile은 본인이 제출한 이벤트 피드백 응답과 그 선택의 인상 태그를 읽어 태그마다 1.0씩 더한다. 받았거나 상호 선택한 횟수가 아니다. 선언 선호는 이 재구축에서 덮어쓰지 않는다. 현재 운영 소스의 재구축 호출은 새 EventFeedbackService.submit 저장 경로다. 같은 키 재시도는 재구축하지 않는다. 데이트 만남 피드백 원본은 이 집계 쿼리에 포함되지 않는다.

행동 근사는 최근 12개월 증거가 있는 참석 이력으로 계산해 별도 저장한다. 3개 미만이면 빈 축과 INSUFFICIENT_EVIDENCE를 남긴다. 충분하면 카테고리 기반 활동 정도와 평균 그룹 크기 선호를 만들고 입력 분포·표본 수·계산 시각을 함께 기록한다. 이는 현재 본인 profile API에 실리지 않으며 앱 레이더의 데이터도 아니다. 참석 변경마다 자동 갱신된다고 설명하지 않는다.

화면 표시와 본인 선택 이력

앱 레이더는 긍정 태그 상위 5개를 사용하고 값은 0~1로 제한한다. 태그 종류가 부족한 경우 데이터 부족 안내를 표시한다. 상위 관심사에는 상위 4개를 쓴다. 별도의 태그 막대는 최대 가중치에 대한 상대 길이를 사용하지만 글자는 weight * 100에 %를 붙이므로 누적 2.0은 200%로 표시될 수 있다. 확률이나 정규화한 비율로 해석하지 않는다.

GET /api/v1/feedback/me의 본인 이력은 처음 20개를 요청하고 더 보기마다 size를 20씩 늘려 첫 페이지를 다시 읽는다. 다음 페이지를 덧붙이는 구현으로 쓰지 않는다. 통계는 totalResponses, totalChoicesGiven, tagCounts이며 받은 선택 수가 아니다. 이력과 통계는 차단 대상을 제외하지만 취향 태그 캐시 재구축에는 같은 차단 필터가 없어 서로 다른 값을 가질 수 있다.

선택형 피드백 제출 성공 경로는 현재 취향·통계·이력 provider를 명시적으로 무효화하지 않는다. 서버의 재구축이 이미 열려 있는 모든 관련 화면의 즉시 갱신을 보장한다고 기록하지 않는다. 이벤트 선택형 피드백의 제출·재시도·후보 변경 계약을 따른다.

내보내기와 데이터 구분

현재 ReviewDataExportAssembler는 선언 선호와 behaviorStyleEstimate를 내보낸다. positiveTagWeights는 본인의 원본 선택 기록에서 다시 만들 수 있는 파생 캐시여서 의도적으로 제외한다. 이벤트 피드백 내보내기에는 vibeTags도 포함되므로 이를 현재 누락 문제로 남기지 않는다.

이 문서의 태그 누적·행동 근사와 다른 추천·성향검사 기능의 점수를 동일하게 취급하지 않는다. 특정 추천에 어떤 값이 사용되는지는 해당 추천 계약에서 판단한다.

수용 기준과 검증 근거

  • AC-01 본인 조회: 본인만 profile API를 사용하고 행이 없어도 빈 프로필을 반환한다. 행동 근사 축은 응답에 포함되지 않는다.
  • AC-02 선언 선호 삭제: 현재 선택으로 시트를 채우고 모두 해제한 항목의 null을 서버에 저장해 이전 선호를 비운다.
  • AC-03 저장 성공과 실패: 성공에만 응답 반영·닫기·성공 안내를 하고 실패는 기존 프로필과 선택을 유지한다. 다른 계정에 이전 요청 결과를 반영하지 않는다.
  • AC-04 태그 원천: 본인이 이벤트 피드백에서 준 인상 태그를 건수로 누적한다. 받은 선택·데이트 만남 피드백을 합산하지 않는다.
  • AC-05 행동 근사 표본: 최근 12개월 표본 3개 미만이면 부족 근거와 빈 축을 저장하고 화면 축을 만들어내지 않는다.
  • AC-06 표시 의미: 누적 가중치와 비율을 구분하고 100% 초과 글자·레이더 제한을 현재 표시 경계로 남긴다.
  • AC-07 본인 이력: size 20부터 더 보기마다 20을 늘리고 차단 대상 제외와 본인이 한 선택 통계를 적용한다. 취향 캐시와 같은 집계라고 가정하지 않는다.
  • AC-08 내보내기: 선언 선호·행동 근사와 본인 분위기 태그를 포함하고 파생 태그 캐시는 의도적으로 제외한다.

근거는 현재 프로필 저장·재구축·내보내기와 앱 설정·표시·이력 요청 분기다. 이번에 제품 시험을 새로 실행하지 않았다.
