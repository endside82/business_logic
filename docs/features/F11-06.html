F11-06. 취향 평가 · 취향 프로필

종료 이벤트에서 또 함께하고 싶은 사람·긍정 인상·모임 분위기를 비공개로 남기고, 본인이 남긴 선택을 취향 프로필로 재구축한다. 선호 카테고리·시간대·그룹 크기도 직접 저장한다. 현재 사람 추천과 관계 공통점은 카테고리·시간대만 소비하고 그룹 크기는 저장·조회·내보내기에 머문다. 받은 선택과 상대 응답은 누구에게도 노출하지 않는다.

2026-07-29 소스 재실측 — 행동 근사 스타일

UserTasteProfile.behaviorStyleEstimate는 최근 12개월 증거등급 참석 이벤트로 ACTIVITY_LEVEL과 GROUP_SIZE_PREFERENCE를 산출한다. 3건 미만이면 축 없이 INSUFFICIENT_EVIDENCE를 저장하고, 재계산은 이벤트 피드백 제출 성공 때 일어난다.

현재 TasteProfileVo와 Flutter 화면에는 행동 근사가 없지만 export taste 섹션에는 포함된다. 이벤트·클럽 fit은 이 값이 아니라 최신 제출 trait 점수만 사용한다. 데이트 만남 피드백도 현재 TasteProfile 재구축 원천이 아니다.

설계 의도 — 받은 평판이 아니라 내가 남긴 선택의 기록

공개 리뷰(F11-01)는 다른 사용자의 의사결정을 위한 평판이다. EventFeedback은 반대 방향으로, 응답자가 고른 사람과 긍정 인상만 본인 이력·취향 프로필에 남긴다. 받은 선택 횟수나 상호 선택은 조회할 수 없다. 데이터가 적을 때는 차트를 억지로 만들지 않고 안내를 보여 준다.

2026-07-29 현재 소스 갱신

legacy PreferenceRating·TasteNeighbor·GraphQL 추천은 현재 계약이 아니다. TasteProfile 재구축 원천은 이벤트 선택형 피드백이며 데이트 만남 피드백은 별도 privatedate 원본이다. 사용자 작성 vibeTags가 데이터 export에서 빠지는 점은 확정 Gap이다.

두 종류의 데이터가 같은 화면에 모인다

본인 선택에서 재구축되는 값, 직접 선언한 값, 내부 행동 근사를 구분한다.

데이터 종류어떻게 만들어지는가화면에서 어디에 보이는가
자동 누적 — 태그 가중치 이벤트 선택형 피드백에서 내가 고른 사람에게 붙인 긍정 ImpressionTag 10종을 집계한다. 제출 성공 때마다 본인의 positiveTagWeights를 다시 계산한다. "취향 요약" 레이더 차트, "상위 관심사" 칩, "긍정적 인상" 막대 그래프.
수동 입력 — 선호도 화면의 "선호도 설정" 시트에서 카테고리(8개) · 시간대(4개) · 그룹 크기(3개)를 직접 선택해 저장. 세 값 모두 저장·조회된다. 현재 사람 추천/관계 공통점은 카테고리·시간대만 사용하며 그룹 크기는 소비하지 않는다.
내 피드백 이력 본인이 제출한 EventFeedback만 조회한다. 차단된 상대가 뒤에 생기면 해당 choice는 이력에서 소급 제외한다. 20건 단위로 노출되고 "더 보기"로 누적 로딩한다.
내부 행동 근사 최근 12개월 증거등급 참석 이벤트 3건 이상으로 활동성·그룹 크기 선호 축을 계산한다. 현재 profile API/UI에는 없고 본인 export에만 포함된다.

사용자 시나리오

기본 흐름

내가 남긴 선택이 취향 프로필로 보인다

이벤트 선택형 피드백을 여러 번 남긴 사용자가 마이페이지에서 "취향 프로필"로 진입한다. 긍정 태그가 3개 이상이면 레이더 차트와 상위 태그·긍정 인상 막대가 보이고, 아래에는 내가 제출한 피드백 통계와 이력이 표시된다.

경계 — 상대가 나를 선택했는지, 몇 번 선택받았는지, 상호 선택인지에 대한 값은 없다.

데이터 부족

가입 직후라 이벤트 피드백이 없다

새로 가입한 사용자가 화면에 들어온다. 태그 데이터가 3개 미만이라 레이더 차트는 그려지지 않고 "아직 취향 데이터가 부족합니다" 안내만 뜬다. 이력 영역은 "아직 고른 사람이 없습니다"를 표시하고, 선호도 설정은 계속 사용할 수 있다.

선호도 설정

선호 카테고리·시간대·그룹 크기 저장

"선호도 설정" 시트가 열린다. 카테고리에서 "음식/맛집", "문화/예술"을 토글하고, 시간대에서 "저녁(18-21)", 그룹 크기에서 "중규모(6-15명)"를 선택한 뒤 "저장"을 누른다. 토스트가 뜨고 시트가 닫힌다. 카테고리·시간대는 다음 사람 추천/관계 공통점 조회부터 사용되고, 그룹 크기는 현재 저장·조회·export만 된다.

피드백 제출

종료 이벤트의 증거등급 참석자가 사람·인상·분위기를 고른다

종료 후 7일 이내이고 차단·본인을 제외한 후보가 2명 이상이면, 서버 후보 snapshot을 그대로 echo해 사람은 0명부터 min(5, ceil(후보/2))명까지 고른다. 분위기 태그는 8종 중 최대 3개다. 성공하면 응답·표시 후보·선택을 저장하고 본인의 태그 가중치와 행동 근사를 재구축한다.

후보 변경

조회 뒤 차단·자격 변화로 snapshot이 달라진다

제출 시 서버가 후보 집합과 순서를 다시 계산한다. 요청의 displayedUserIds와 하나라도 다르면 FEEDBACK_CANDIDATES_CHANGED로 거절하고 응답·선택·취향을 변경하지 않는다.

멱등·중복

같은 제출을 네트워크 재시도로 다시 보낸다

같은 이벤트·응답자의 기존 응답과 clientRequestId가 같으면 기존 응답을 그대로 반환한다. 다른 key면 DUPLICATE_RESOURCE다. 두 경로 모두 추가 저장이나 취향 재구축을 하지 않는다.

행동 근사

최근 12개월 증거 이벤트가 3건 미만이다

재구축은 provenance=BEHAVIOR_V1, 빈 axes, reason=INSUFFICIENT_EVIDENCE를 저장한다. 충분해져도 현재 profile API/UI에는 노출하지 않고 본인 export에서만 확인할 수 있다.

운영자가 알아야 할 것

취향 데이터가 다른 도메인에 닿는 자리
  • 받은 선택은 어떤 조회에도 노출하지 않는다. 공개 리뷰(F11-01)는 평판이고 본 단위는 내가 작성한 선택의 기록이다. 상대 응답 여부·상호 선택·선택받은 횟수를 통계나 추천 이유로 우회 노출해서도 안 된다.
  • EventFeedback 제출 성공 때 본인의 태그 가중치와 행동 근사를 재구축한다. 참석 이력 변화만으로는 즉시 재계산되지 않고 다음 피드백 제출까지 오래된 값일 수 있다.
  • 레이더 차트는 태그 3개 미만이면 비표시한다. 데이터가 적을 때 부정확한 차트로 사용자를 오해시키지 않으려는 결정 — "더 모일 때까지" 안내가 빈 차트보다 정직하다.
  • 선호도(카테고리·시간대·그룹 크기)는 빈 리스트로 저장할 수 없다. 시트에서 아무 것도 고르지 않고 "저장"을 누르면 그 항목은 갱신되지 않는다 — 사용자가 의도적으로 "초기화"하고 싶다면 별도 경로가 필요하다(현재는 미지원).
  • 본인 피드백 이력은 20건 단위다. 누적이 많은 사용자는 "더 보기"로 size를 늘려 다시 조회한다.
  • 행동 근사는 저장·export되지만 profile API/UI에는 없다. 또한 본인이 작성한 vibeTags는 현재 export에서 누락된다. 두 항목을 같은 "구현 완료"로 보지 않는다.
