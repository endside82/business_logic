F16-07. 호스트 제안

이벤트 호스트가 자기 모임에서 활약한 멤버에게 줄 점수를 제안하고, 운영진이 검토 후 승인하면 적립이 실행되는 흐름. 호스트는 직접 점수를 줄 수 없고 제안만 한다. 제출·조회·승인·반려와 실제 적립까지 코드와 화면 검증을 마쳤으며, 2026-09-04 운영 기본 출시 목록에 포함했다. 실기기 결과 알림 확인은 출시 후 운영 점검으로 남아 있다.

현재 상태 — 실제 적립까지 화면 왕복 완료

호스트의 제안 제출과 목록, 운영진의 승인·반려, 승인 점수 조정과 원장 반영을 확인했다. 목록에는 대상 회원과 제안자 이름을 표시하고, 동시에 승인과 반려가 들어오면 하나만 성공하도록 보호한다.

설계 의도 — 현장을 아는 사람이 제안하고, 책임지는 사람이 승인한다

누가 모임에서 활약했는지는 호스트가 가장 잘 안다. 하지만 점수를 직접 주게 하면 남용 위험이 있다. 그래서 호스트는 "이 멤버에게 이만큼"이라고 제안만 하고, 운영진이 검토 대기열에서 승인할 때 비로소 적립이 일어난다. 운영진은 승인 시 점수를 조정할 수도 있다.

제안 한 번이 거치는 흐름

flowchart LR A["호스트: 회원·점수·사유 제안"] --> B["제출 + 검토 대기열 등록"] B --> C{"운영진 결정"} C -->|"승인"| D["적립 실행 + 승인 처리"] C -->|"반려 (사유 필수)"| E["반려 + 기록"]

사용자 시나리오

제안

호스트가 활약 멤버를 제안

모임 후 호스트가 "이 멤버에게 50점"을 사유와 함께 제안한다. 제안은 검토 대기열에 자동으로 올라간다.

권한 가드

호스트가 아닌 사람이 제안 시도

해당 이벤트의 호스트가 아니면 제안 자체가 거절된다.

승인

운영진이 점수를 조정해 승인

운영진이 50점 제안을 30점으로 조정해 승인하면 30점이 적립되고 제안은 승인 상태가 된다.

반려

운영진이 사유와 함께 반려

반려는 사유가 필수다. 사유 없이는 반려할 수 없다.

호스트·운영진이 할 수 있는 동작

동작누가무엇이 일어나는가
제안 제출이벤트 호스트자기 이벤트에서 활약한 멤버에게 줄 점수를 사유와 함께 제안한다. 제안은 검토 대기열에 올라간다.
내 제안 목록 보기이벤트 호스트자기 이벤트에 올린 제안들의 처리 상태를 본다.

제안 반려집행 담당제안을 반려한다. 사유 없이는 반려할 수 없다.

운영자가 알아야 할 것

권한과 동시 처리
  • 제안할 수 있는 사람은 해당 이벤트 호스트이고, 실제 적립을 승인하거나 반려하는 사람은 클럽의 마일리지 관리자다.
  • 승인 직전에 대상이 현재 클럽 회원인지 다시 확인한다. 확인 직후부터 원장 잠금 사이에 회원이 탈퇴하는 매우 짧은 경합 가능성은 첫 출시의 알려진 한계다.
  • 실제 기기 결과 알림은 운영 점검으로 남았다. 서버 알림 생성은 확인했으며, 푸시 수신과 제안 화면 이동을 출시 후 확인한다.
