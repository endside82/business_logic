F09-08 내 데이트 프로필 방문 기록

선택 시점의 24시간 방문 기록, 페이지 전 양방향 차단, 현재 표시 정보와 비공개 필터 경계 및 앱 페이지 복구를 정리한다. 2026-11-22 소스 대조이며 새 제품 실행과 구분합니다.

입구와 공개 계약

본인 데이트 프로필 상단의 방문자 입구는 /dating/profile/viewers로 이동한다. 이 입구와 GET /api/v1/date/profile/views는 DATING 공개 범위를 따른다. 닫힌 공개 범위에서도 본인 프로필 조회가 가능하다는 이유로 방문자 목록까지 열린다고 설명하지 않는다.

서버는 본인 프로필을 확인하고 Page<DateProfileViewVo>를 반환한다. 앱은 page·size를 보내 PageResponse로 읽으며 페이지당 20개다. 프로필이 없으면 DATE_PROFILE_NOT_FOUND이며 현재 방문자 화면은 일반 오류·재시도를 보여 준다. 자동으로 생성 화면으로 이동하지 않는다.

방문 기록이 생기는 시점

방문 기록은 후보 좋아요·넘김 처리에서 매치 저장 뒤 같은 트랜잭션으로 남긴다. 후보 카드를 보기만 했다는 사실을 기록하는 별도 열람 API가 아니다. 본인 자신과 대상 프로필이 없는 경우는 생략한다. 커밋된 기록 조회에서 같은 방문자·대상 프로필의 최근 24시간 기록이 있으면 새 행을 만들지 않는다.

recordProfileView는 MANDATORY 거래이며 직접 호출만으로 독립 저장하는 작업이 아니다. 차단·매치의 동시성은 호출한 후보 선택 흐름의 잠금과 함께 판단한다. 조회 이력 기능만으로 모든 후보 동시 처리 결과가 검증됐다고 주장하지 않는다.

차단과 방문자 표시 범위

내가 차단한 사람과 나를 차단한 사람을 합쳐 페이지를 읽기 전에 제외한다. 따라서 페이지 내용뿐 아니라 total도 이 제외 조건을 따른다. 정렬은 viewedAt 내림차순 뒤 ID 내림차순이다.

응답은 기록 ID·viewerId·현재 프로필의 표시 이름·첫 번째 삭제되지 않은 APPROVED 사진의 표시용 서명 URL·viewedAt이다. 방문 시점의 이름/사진 스냅샷이 아니다. 방문자 프로필이 없으면 이름·사진이 null일 수 있다. 사진은 해당 페이지의 고유 방문자별로 읽어 URL을 묶어 서명한다.

현재 이 조회 메서드는 방문자의 isActive·visibility·현재 인증 자격을 추가로 걸러내지 않는다. 비활성·HIDDEN 방문자가 자동으로 목록에서 사라진다고 쓰지 않는다. 양방향 데이트 차단 제외와 후보 탐색의 자격·공개 필터는 서로 다른 계약이다.

앱의 페이지·빈 목록·오류

화면은 방문자의 이름·사진·상대 시각을 표시하고 이름이 없으면 익명, 사진이 없거나 읽기 실패면 기본 표시를 사용한다. 방문자 행에 상세 이동·신고·차단 동작은 없다.

다음 페이지는 공통 스크롤 로더로 읽고, 목록이 짧으면 프레임 뒤 다시 추가 로드 필요 여부를 확인한다. 추가 페이지 실패는 목록 하단의 재시도로 처리한다. 자료가 있는 목록은 당겨서 첫 페이지를 다시 읽을 수 있다. 빈 상태는 안내만 보여 주며 이 화면의 빈 상태 분기에는 별도 새로고침이나 프로필 생성 버튼이 없다. 최초 조회 오류에는 재시도 입구가 있다.

현재 제한과 확인 범위

분류현재 경계문서 처리
Risk방문자 비활성·공개 범위·현재 인증은 이 조회의 추가 제외 조건이 아니다.양방향 차단과 후보 공개 정책을 혼동하지 않는다.
Gap빈 목록에 별도 재조회 버튼이 없고 프로필 없음도 자동 생성 이동이 아니다.실제 오류·빈 상태의 복귀 입구만 설명한다.
미검증실제 계정 간 차단·동시 기록·대량 페이지 성능은 실행하지 않았다.페이지 구현을 동시성/성능 시험 통과로 기록하지 않는다.

수용 기준과 검증 근거

  • AC-01 입구와 응답: DATING 범위·본인 프로필·20개 페이지 및 프로필 없음 오류를 구분한다.
  • AC-02 기록 원인: 좋아요/넘김과 같은 거래에서 기록하며 단순 카드 노출로 기록하지 않는다.
  • AC-03 중복과 차단: 커밋된 24시간 기록 확인과 양방향 차단의 페이지 전 제외를 적용한다.
  • AC-04 표시 범위: 현재 이름·승인 사진·시각과 비활성/비공개 미필터 경계를 명시한다.
  • AC-05 앱 복구: 첫 조회·추가 페이지 오류, 자료 있는 목록 새로고침과 빈 안내를 구분한다.

이 기능의 출시 완료 기준

현재 제한과 확인 범위를 함께 판정한다.

2026년 10월 13일 정리한 판정 조건입니다. 아래 목록 자체는 검사 통과 기록이 아닙니다. 현재 공개 범위와 실행 확인은 출시 상태와 근거를 따릅니다. 위의 날짜별 기존 분류는 현재 운영 설정이나 검사 통과를 대신하지 않습니다. 후속 기능은 첫 출시에서 신규 이용 제한을 확인하고, 기능을 열 때 아래 결과를 검증합니다.

  • 후속 프로필 조회 이력은 허용된 대상과 보관 범위만 본인에게 보인다.
  • 차단·탈퇴·중복 조회·빈 이력·계정 전환 뒤 개인정보 노출을 확인한다.

기능 본문에 남은 미구현·결함은 해결 증거 또는 명시적인 공개 범위 결정 없이 완료 처리하지 않습니다. 함께 적용하는 권한·실패·복구 확인과 버전·환경·결과·승인 기록을 갖춘 뒤 판정합니다. 프라이빗 데이팅의 관련 완료 기준도 함께 확인합니다.
