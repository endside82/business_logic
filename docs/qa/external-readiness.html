준비한 설정으로 실제 외부 서비스 연결을 일부 확인했다. 10월 10일 Google Play 앱 등록·업로드 키·Firebase Android 등록에 이어, 10월 12일 Google OAuth·지도·Kakao Local·SMTP·FCM을 임시 시험 서버와 서명 APK에 연결했다. Android 16(API 36) 에뮬레이터와 격리 DB·Redis를 사용했으며 운영 서버는 아직 구축 전이다.

  • Google: 실제 개인 계정의 신규 가입·필수 동의·온보딩, 강제 종료 후 로그인 유지와 홈 복귀를 확인했다.
  • 지도·주소: Google 지도 타일·팬 이동·핀 재선택을 앱에서 확인했다. Kakao 주소↔좌표 변환은 실제 공급자와 Tunnel 경유 서버에서 확인했다.
  • 메일: SMTP 시험 메일은 Gmail에서, 가입 인증·비밀번호 재설정 메일은 자체 도메인 시험 수신함에서 받았다. 앱 링크 인증·복구와 이전 비밀번호·기존 토큰·재사용 링크 거절을 확인했다. 관련 앱 자동 테스트 28개가 통과했다.
  • 푸시: 실제 FCM의 전경·백그라운드·프로세스 종료 수신, 알림 클릭 후 문의 목록 이동과 권한 거절·재허용을 Android 에뮬레이터에서 확인했다. QA 발송 행을 이용한 시험이며 개별 업무 이벤트의 발행 검증은 별도다. Firebase·APNs 푸시 연결에 근거와 남은 조건을 기록한다.
  • 외부 접속: 공개 HTTPS 반복 요청 20/20, 채팅 소켓 두 종류의 연결·재연결 3회와 무인증 거절을 확인했다. 실제 채팅 메시지 왕복·두 휴대전화·장시간 안정성은 이 결과에 포함하지 않는다.

아래 표의 부분 확인은 적힌 환경과 동작만 통과했다는 뜻이다. 서비스별 남은 조건은 계속 추적하며, 현재 출시 결론의 외부 고객 공개 보류는 유지한다.

진행 순서와 완료 상태

기능 범위와 공개 판단은 첫 출시 범위와 공개 전에 할 일을 함께 따른다. 문서 작성이나 키 발급만으로 출시 완료가 되지는 않는다.

  1. 계정 소유자·배포 방식: 서비스 명의, 콘솔 소유 계정, 복구 수단, 비용 결제 주체를 확인한다. Apple 가입과 Google Play 계정별 테스트 요건을 먼저 확인하고 iOS 로그인 구성을 결정한다.
  2. 도메인·운영 환경: 공개 주소, 검사 서버, 메일 발신 도메인, 파일 저장소, 관리자 허용망을 준비한다.
  3. 프로젝트·키·권한: Google·Firebase·지도·메일 자격 증명을 발급하거나 기존 보관 위치를 확인한다. 개발·시험·운영 환경을 구분해 빌드와 서버에 전달한다.
  4. 같은 출시후보로 확인: Android와 iPhone에 서명 앱을 설치하고 가입·알림·지도·파일·채팅·직접 송금 확인을 수행한다. 실패·취소·중복 요청·권한 회수도 같은 이용 흐름에서 확인한다.
  5. 운영·공개 확인: 경보 수신·백업 복구·이전 버전 복귀를 확인하고 스토어 자료와 검사한 앱을 대조한다.
상태완료로 기록할 근거
가입·계약 확인운영자에게 콘솔 접근 권한과 해당 서비스의 이용 권한이 있다. 기존 계약이 있다면 새로 가입하지 않는다.
발급·설정 확인사용 환경·앱 식별자·허용 권한이 맞고 키가 실행 환경에 전달됐다. 키 본문 대신 보관 위치·식별자·만료일을 기록한다.
실제 연동 확인서명 앱·실제 공급자·역할별 시험 계정의 성공과 실패 결과가 있다. 모사 응답이나 공급자의 접수 성공만으로 완료 처리하지 않는다.
운영 준비 확인한도·비용·만료·실패 경보를 받을 수 있고 재처리·복구 절차를 수행했다.

현재 상태: 가입·설정만 끝난 항목, 시험 환경에서 실제 연동을 확인한 항목, 아직 확인하지 않은 항목을 아래에 구분한다. 콘솔을 조회하지 않은 항목의 미확인은 계정이나 계약이 없다는 뜻이 아니다. 이전 자동 검사와 이번 외부 검증은 각각의 범위로 기록한다.

다음 확인 순서

현재 진행 조건 — 2026-10-12: 운영자는 에뮬레이터 두 대를 사용하는 채팅 검증을 메모리가 넉넉한 환경에서 진행하기로 했다. iOS는 Apple 개발자 가입, 파일·첨부파일은 S3 준비를 기다린다. 현재 환경에서는 메일의 남은 서버·실수신 검증, 사용량·비용 경보 설정, 스토어 제출 자료 정리를 먼저 진행할 수 있다.

  1. 시험 환경의 남은 연동: 푸시의 남은 복구 시나리오를 확인한다. 두 테스트 계정의 텍스트 채팅 메시지 왕복·재접속은 메모리가 넉넉한 환경에서 진행한다. 파일 업로드·열람·검사·삭제와 채팅 첨부파일은 S3 가입·버킷·권한 준비 후 검증한다. Firebase 초기화나 소켓 연결만으로 완료 처리하지 않는다.
  2. 통과한 서비스의 미확인 동작: Google 재로그인·연결/해제, 외부 수신함의 인증 메일과 만료·반송, 앱 주소 변환·위치 권한·길찾기 실패를 확인한다. 동일한 소스·환경의 통과 기록은 재사용한다.
  3. 배포 환경과 기기: 운영 서버·고정 HTTPS 주소를 준비하고 Android 실기기·Play 내부 테스트, iOS 서명·TestFlight·로그인 구성·지도·APNs를 확인한다. 임시 주소를 바꾸면 메일 링크와 앱 링크도 함께 맞춘다.
  4. 출시후보 확정: 검증한 소스·미커밋 수정·APK 지문을 배포 대상과 대조한다. 같은 출시후보의 전체 이용·경보·복구와 스토어 자료를 확인한 뒤 공개 여부를 기록한다.

iOS 빌드·TestFlight 내부 테스트 절차

진행 보류 — 2026-10-12 운영자 확인: Apple Developer Program 가입이 아직 완료되지 않았다. 운영자 지시에 따라 iOS 배포 서명·TestFlight·APNs 연결과 iPhone 검증은 개발자 가입 완료 후 진행한다. 그동안 Android와 공통 서버의 외부 연동 검증을 이어간다.

  1. 가입·앱 등록: Apple Developer Program 가입 안내에 따라 기존 회원 자격·권한을 확인한다. 조직 가입이면 D-U-N-S 등 조직 확인 조건을 준비한다. App Store Connect에 앱과 내부 테스트 사용자를 등록한다.
  2. 서명: Xcode 계정, Developer Team, Runner의 자동 서명, 배포 인증서·개인 키 또는 Xcode 관리 배포 서명을 준비한다. Push Notifications와 Associated Domains를 앱 Identifier 및 프로비저닝에 반영한다.
  3. 업로드 인증: App Store Connect의 Users and Access → Integrations에서 팀 API 키를 발급한다. Key ID·Issuer ID·다운로드한 .p8 파일을 보관하고 앱 업로드 권한을 확인한다. fastlane API 키 인증 안내를 따른다.
  4. 빌드·설치: 아래 설정 검사와 IPA 빌드 뒤 업로드를 실행한다. Apple 처리 완료 후 TestFlight 내부 그룹에 빌드를 연결해 iPhone에 설치한다. 수출 규정 질문은 앱의 실제 동작에 맞게 답한다.

bundle install
cp -n fastlane/.env.example fastlane/.env
