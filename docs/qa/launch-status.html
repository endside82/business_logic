첫 출시 현황과 남은 준비

현재 제공할 범위와 공개 전에 해야 할 일을 정리했다. 운영자 한 사람이 다음 행동과 완료 조건을 확인하며 진행한다. 관리자 업무는 메뉴와 권한으로 나뉘며, 각각 별도 담당자를 두지 않는다.

공개 전에 할 일첫 출시 범위 외부 서비스 가입·계약과 출시 준비 버스·카풀 확인 결과후속 기능 준비상태 구분공개 승인 기준

10월 12일 외부 연동 반영과 남은 준비

Android 업로드 키와 staging 서명 APK를 준비하고 실제 Google 신규 가입·온보딩·로그인 유지, Google 지도 표시와 Kakao 주소 변환을 확인했다. SMTP 시험 메일의 Gmail 수신과 자체 도메인 시험 수신함의 인증·비밀번호 복구, Android 앱 링크·기존 토큰 무효화를 각각 기록했다.

Firebase 발송 계정·권한과 Android 에뮬레이터의 실제 푸시 수신·문의 목록 이동·권한 거절/재허용을 확인했다. 공개 Tunnel의 HTTPS·소켓 연결/재연결도 확인했다. 상세 결과와 최신 푸시 확인 범위는 10월 12일 진행 결과 — 실제 공급자와 Android 시험 앱 연결을 따른다.

검증 범위: Android 16 에뮬레이터·격리 시험 서버·실제 공급자다. 파일 저장소·채팅 메시지 왕복·실기기·iOS·운영 서버·스토어 배포·복구 확인은 남아 있다. 기존 통과 기록은 보존하고 다음 확인 순서의 미확인 범위를 이어간다.

같은 날 기능 반영: 받는 사람 계좌 보기·복사와 ‘보냈어요’ — 2026년 10월 12일도 구현·자동 검사 기록을 반영했다. 이 화면의 실제 이용 확인은 외부 로그인·메일·QA 푸시 검증과 별도다.

이번 문서 반영의 확인 범위와 남은 작업

10월 7일 시점 기록: 아래 표와 검사 수치는 당시 범위다. 이후 외부 연동 상태는 10월 12일 외부 연동 반영과 남은 준비에서 갱신했다.

10월 2일 문서 사이트 반영 이후 10월 7일 조사 시점까지의 원본 변경을 반영했습니다. 구현·병합 상태는 작업 현황표와 제품 기본 브랜치를 함께 확인했습니다. 이후 진행 중인 변경은 이번 기준에 포함하지 않습니다.

영역반영된 범위남은 범위
프로필·리뷰공개 범위, 사람 링크, 탐색 복귀·계정별 갱신과 자동 검사실제 로그인 서버 왕복·두 휴대전화·푸시 확인. 작성 글 집계는 별도 서버 계약 필요
알림·인증 메일발송 의도 저장·복구·운영자 조회와 재시도·앱 배너 중복 억제실제 수신함·기기 표시·알림 이동. 공급자 수락을 실제 수신으로 세지 않음
정산·환불회수 한도·혼합 반환·계좌이체 취소·일행 추가 결제·구독 및 개최권 운영자 환불·종료일 요율실제 PG·은행·배포 데이터·서명 앱. 출금 재투입·해소 경합과 지급 대상 계좌 연결 보완
클럽 폐쇄서버 반환 순서·평소 미수금 상환·구독 종료·홈 갱신새 폐쇄 금액 확인 화면과 폐쇄 납부 통화 선택은 병합 전. 개별 기부·가입비 운영자 환불은 대기
제재·탈퇴제재 해제 보호·회원 알림과 이의 진입·탈퇴 회원 목록·채팅 연결 정리새 행동 제한 관리자 화면·위임. 보관금·상품·개최권·승인 경합을 묶은 탈퇴 구조 개선
마일리지·외부 일정저장된 후속 작업 복구, 일부 처리 단위·일정 요청 누락 보완마일리지 남은 처리 단위·누락 점검·재계산 화면, 외부 일정 재연결·범위 변경 보완

자동 검사 기록: 프로필은 10월 3일 앱 6,377건과 공개 서버 11,861건 기록 및 후속 영향 검사가 있습니다. 정산은 10월 4일 고정 소스에서 앱 6,392건·공개 서버 11,952건이 통과했습니다. 이후 10월 7일 서버 묶음은 단위 9,474건·통합 3,168건, 10월 6일 앱 묶음은 6,557건, 개최권 관리자 웹은 400건, 실시간 서버는 305건의 통과 기록이 있습니다. 각기 다른 소스·시점의 결과로 합산하거나 현재 다섯 프로그램 전체의 동시 검증으로 표시하지 않습니다.

앱의 기존 경고 정리는 끝났으며 정보 수준 분석 지적 112건은 남아 있습니다. Android 릴리스 자동화와 테스트 서버 선택 도구에 이어 iOS TestFlight 내부 테스트용 fastlane 설정을 추가했습니다. iOS 설정의 로컬·격리 검증은 통과했지만 실제 서명 빌드·업로드·휴대전화 설치는 남아 있습니다. iOS 빌드·TestFlight 내부 테스트 절차에서 필요한 입력과 실행 방법을 확인합니다.

2026년 10월 7일 — 프로필 탐색·발송 복구·환불 규칙 반영에서 기능 본문으로 이동할 수 있습니다.

현재 결론

버스·카풀, 주최자 계좌 직접 송금, 게시글·모임 투표를 첫 출시 기본 설정에 추가했다. 스탬프·마일리지 시즌·반복 수동 적립 검토·사진 심사 적립도 포함한다. 실제 배포와 휴대전화·외부 서비스 검사는 남아 있어 공개는 보류한다.

버스·카풀은 소스 검수 24개·추가 웹 검사 6개 통과다. 남은 것은 휴대전화·실제 푸시·좌석 지정에 사용할 실차 도면 확인이다. 버스·카풀의 확인 결과와 다음 할 일을 따른다.

Android 서명과 일부 실제 연동은 시험 환경에서 확인했다. Google·지도·메일 설정을 연결하고 Firebase 발송 준비와 시험 앱 검증을 진행했다. 운영 서버·고정 주소·파일 저장소·Play 배포본·iOS·실기기 확인이 남아 있다. 상세 상태는 첫 출시 필수 서비스를 따른다.

자동 테스트는 기록에 적힌 기존 범위만 통과했다. 새 개발은 새 검사 결과를 남기고, 검사한 소스와 배포할 소스를 연결해 서명 앱에서 실제 이용·복구를 확인한다.

개발이 남았는지, 실제 확인만 남았는지

  • 추가 개발: 없는 서버 기능·화면·연결을 만들어야 한다. 후속 범위에는 기간권 판매 운영·환불과 계좌 소액 인증 공급자 연결이 남아 있다. 차량 조율과 소셜 로그인 결과 집계·관리자 화면은 구현돼 있으며 실제 환경 확인은 따로 구분한다.
  • 기존 기능 보완: 구현된 기능의 결함을 고치는 일이다. 카풀의 이름·경로·취소 안내와 기본 검사 실패는 수정 후 해당 범위를 확인했다. 이를 운영 배포 완료로 읽지 않는다. 다른 기능의 남은 보완과 수정 후 화면은 별도로 확인한다.
  • 자동 테스트: 기록에 적힌 동작만 확인했다. 외부 응답을 모사한 테스트는 실제 서비스 이용과 다르다.
  • 실제 환경 확인: 배포용 앱·실제 계정·서비스로 실행한 결과가 남아 있어야 한다. 미실행을 미구현으로 바꾸거나 통과로 추정하지 않는다.
  • 외부 준비: 실행에 필요한 서명·계정·설정·접근 권한이다. 보관 위치 미확인을 계약이나 계정이 없다는 뜻으로 쓰지 않는다.

각 작업의 완료 조건을 충족하면 남은 할 일에서 뺀다. 후속 개발을 마쳐야 첫 출시할 수 있는 것은 아니다.

모임 정산: 비용 작성부터 개인 내역 조회까지 확인했습니다

첫 비용 작성 → 금액 검토 → 정산 요청, 항목별 입금 확인, 여러 모임의 보낼 돈·받을 돈·지난 내역과 월·기간 검색을 구현하고 기본 브랜치에 반영했습니다. 운영 배포와 실제 돈 이동 제한 해제는 하지 않았습니다.

구분확인한 것과 남은 일
구현·자동 검사서버 정산·탈퇴 연결 345건, 서버 규칙 74건, 앱 정산 228건을 통과했습니다. 자기 부담분 제외, 마지막 입금 확인의 동시 처리, 개인 내역의 금액·기간·원본 조회를 확인했습니다. 전체 회귀 결과는 아닙니다.
실제 화면변경 시나리오 네 가지와 수정 후 묶음 확인을 통과했습니다. 첫 비용부터 요청까지, 항목별 입금과 완료, 내 정산의 월·기간·취소 원본 복귀, 직접 송금 확인 후 금액 갱신입니다. 가상 회원을 사용한 웹 화면이며 새 소개 사진 11장을 추가했습니다.
최종 자동 검사최초 실행의 실패·중단 뒤 영향 검사를 수행했고, 10월 4일 고정 소스의 후속 전체 검사는 앱 6,392건·공개 서버 11,952건 통과입니다. 기존 경고는 정리했으며 분석 오류·경고 0건, 정보 수준 지적 112건입니다. 이후 묶음은 이번 문서 반영의 확인 범위와 남은 작업에서 별도로 확인합니다.
9월 26일 추가 보완초안 취소·생성 결과 유실 뒤 작성 상태 복구, 늦은 첫 비용 요청의 다른 정산 저장 차단, 직접 송금 미납자 알림 대상을 수정했습니다. 서버 실제 MySQL 알림 검사 3건·항목 검사 2건, 앱 상태 검사 10건·작성 화면 검사 1건의 변경 기록이 있습니다. 이 수치를 9월 24일 검사 건수와 합산하지 않습니다.
다음 행동추가한 복구·미납 알림 동작의 실제 웹 확인과 서명한 휴대전화 앱·실제 알림·은행 내역 대조가 남아 있습니다. 기존 분석 지적과 화면 배치 개선은 별도로 판단합니다. 이미 통과한 기본 웹 여정의 기록은 해당 범위에서 유지합니다.

확인 범위는 정산 화면 검사, 이용 방식은 내 정산과 비용 작성, 최신 보완은 초안 취소 뒤 다시 작성하고, 실제 미납자에게 알립니다에 정리했습니다. 실제 은행 송금·휴대전화·푸시 확인은 별도입니다.

버스·카풀: 확인한 것과 다음 할 일

소스 검수 24개와 추가 웹 시나리오 6개를 통과했다. 배정 해제·배정 후 개별 이동·전 운전자를 포함한 카풀 교체·운전자 참가 취소·미해결 모임 종료·도면 변경 사유를 실제 화면과 저장 결과로 대조했다. 여섯 검사의 결과와 화면을 볼 수 있다.

구분현재 상태
구현주최자 중심 명단·배정·지원 취소·교체·조정 요청·선택적 좌석 지정·관리자 조회·개인정보 보호를 기본 브랜치에 반영했다. 이번 추가 웹 검사에서 제품 결함은 발견하지 않았다.
소스·자동 검사소스 검수 24개 통과. 기본 검사 수정분은 커밋·푸시 완료. 앱·관리자 서버의 전체 자동 검사는 통과했다. 공개 API는 전체 실행에서 나온 실패를 고치고 해당 검사를 다시 통과했다.
실제 웹 이용기존 배정·지원·취소·재배정·좌석 전환 근거를 재사용하고 미확인 6개만 추가 통과했다. 시험 계정을 사용한 데스크톱 웹 검사이며, 실제 휴대전화 검사가 아니다.
실제 환경·출시휴대전화·실제 푸시·사용할 실차 도면은 미확인이다. 첫 출시 범위는 유지하지만 운영 배포·고객 공개 완료로 표시하지 않는다.

운영 규칙

  • 최초 배정은 주최자만 하고 왕복은 나누지 않는다. 참가자 본인 변경은 주최자가 허용한 동안만 가능하며 기본은 꺼짐이다. 지원자에게 별도 배정 권한을 주지 않는다.
  • 지원 확정 전에는 기존 배정을 유지한다. 자리 반납·개별 이동 희망은 주최자 조정 요청이며, 요청만으로 배정이 사라지지 않는다.
  • 운행만 취소하면 모임에 남는 전 운전자·승객은 배정 필요가 된다. 운전자가 모임 참가도 취소하면 남은 승객만 재배정한다. 자동 자차 복귀는 없다.
  • 취소 묶음은 남은 사람이 0명일 때 자동 종료한다. 모임이 먼저 끝나면 미해결 그대로 보관하며 처리 완료로 바꾸지 않는다.

지금 남은 확인

  1. 휴대전화: 설치 가능한 Android·iPhone 앱과 시험 서버를 준비한다. 주최자 배정 입력·저장 후 갱신·참가자의 내 차량, 좌석표 스크롤·선택을 확인한다. 작은 화면·큰 글자·밝고 어두운 배색은 같은 화면으로 확인한다.
  2. 실제 푸시: 주최자는 지원·변경 의견 알림, 참가자는 배정 결과 알림을 받아야 한다. 중복 수신이 없고 알림을 누르면 해당 모임의 이동 화면으로 열리는지 확인한다.
  3. 사용할 도면: 좌석을 지정할 차량의 차종·연식·인승 사양과 좌석 사진을 대조한다. 후보 도면 4종을 일괄 승인하지 않는다. 좌석을 지정하지 않는 차량별 배정에는 도면 확인이 필요하지 않다.

검수 순서: 이미 통과한 웹 경로는 중간에 반복하지 않는다. 환경을 포함한 개별 검사 전체 통과 뒤 변경 범위 전체 시나리오를 한 번 실행한다. 코드 통합을 위한 전체 자동 검사는 실행했고 실패 항목은 수정 후 재검사했다. 자동 검사 통과를 휴대전화·실제 푸시 확인으로 세지 않는다.

기존 데이터 이관·백필은 제외한다. 새 모임으로 검사하며 실제 데이터를 삭제하거나 초기화하지 않는다. 상세 동작은 카풀·개별 이동, 대절 버스와 배정, 좌석 배치도 운영에서 확인한다.

무엇부터 해야 하는가

    운영자 한 사람이 전담한다. 입금·환불·신고·배치도 등은 메뉴와 권한의 구분이지 인력 배정 조건이 아니다. 고객 앱의 주최자·회원·운전자·탑승자 권한 제한과 자기 처리 금지 규칙은 그대로 유지한다.

    관리자 화면이나 서버가 허용되지 않은 네트워크에서도 열리면 운영자는 접근 차단을 다른 작업보다 먼저 처리한다.

    공개 전에 할 일

    아래는 공통 배포 준비·실제 이용·운영 확인이다. 첫 출시 기능에 남은 주최자 중심 차량 조율의 실제 이용 확인도 함께 진행해야 한다.

    외부 서비스 가입·계약과 출시 준비에 가입·키 발급·설정 위치·실제 연동 완료 조건을 모았다. 계약 또는 키 보관 위치가 미확인인 항목은 없다고 단정하지 않고, 콘솔·권한·실행 결과를 확인한 뒤 상태를 갱신한다.

    iOS 공개 전 결정: 현재 이메일·Google 구성의 심사 적합성은 미확인이다. iOS 로그인 구성과 심사 준비에 따라 동등한 로그인 수단·예외 또는 공개 범위를 결정한다.

    첫 출시 범위

    • 이메일·Google 가입, 무료 모임, 클럽, 게시글·사진·알림·개인 일정과 신고·이의 처리를 제공한다.
    • 마일리지의 적립·사용·정정·등급·배지·순위와 시즌·반복 수동 적립 검토·사진 심사 적립을 포함한다. 사진 적립은 클럽이 규칙을 켠 경우에만 적용한다.
    • 클럽 스탬프를 포함한다. 클럽장이 도장판 만들기를 허용한 클럽에서 운영진이 사용한다.
    • 버스·카풀·자리 배정, 주최자 계좌 직접 송금 유료 모임, 게시글·모임 투표를 포함한다. 일정·장소 결정 투표는 무료 클럽 모임에서만 사용한다.
    • 클럽 가입비·기부는 무료 포인트만 사용한다. 클럽 기금으로 구독료 전액을 낼 수 있는 경우도 허용한다.
    • 지갑으로 내는 유료 모임·플랫폼 결제·마켓 구매·개인 유료 구독·데이트·제공자 거래는 후속 출시 대상이다.
    • 새 이용을 막더라도 기존 이용자의 환불·해지·신고는 계속 처리할 수 있어야 한다.

    첫 출시 포함은 제공할 범위와 운영 기본 설정을 정했다는 뜻이다. 추가 개발이 모두 끝났거나 실제 서비스 배포를 마쳤다는 뜻이 아니다.

    이메일·Google은 현재 활성 설정이다. Apple 비활성 상태를 iOS 심사 승인으로 해석하지 않으며, iOS 로그인 구성과 심사 준비를 공개 전에 완료한다.

    세부 범위는 기능별 출시 상태와 다음 할 일에서 확인한다. 사적 모임의 결제 구분은 사적 모임 이용과 정산에 있다.

    후속 기능 준비

    후속 기능은 필요한 개발·검사·승인을 마친 기능부터 공개 여부를 결정한다. 단, 현재 비활성인 Apple 로그인과 별개로 iOS 로그인 구성과 심사 준비는 첫 공개 전 결정에 포함한다. 마켓 기간권의 판매 운영·환불, 계좌 소액 인증 공급자 연결에는 개발이 남아 있다. 소셜 로그인 실패 집계와 관리자 화면은 구현됐다. 제공자 설정·실제 계정·서명 앱 확인이 남아 있다. Google Calendar는 동기화 코드와 모사 응답 테스트가 있고 재연결·범위 변경 보완 및 실제 계정 연결 확인이 남아 있다.

    후속 기능의 공개 순서
    1. 카카오·네이버 등 추가 로그인을 제공자별로 준비한다. Apple은 iOS 첫 공개 전 로그인 구성 결정에 따라 준비 시점을 정한다.
    2. 본인확인과 안전 운영을 확인한 뒤 데이트를 준비한다.
    3. 실제 계약·거래·복구를 확인한 뒤 플랫폼 결제를 준비한다.
    4. 플랫폼 결제를 사용하는 인출·개인 구독·마켓·제공자 거래를 준비한다.

    직접 송금·버스·카풀·투표와 시즌·사진 심사 적립·반복 수동 적립 검토·스탬프·모임별 점수는 후속 기능 목록에서 제외하고 첫 출시 검사에 포함한다.

    외부 준비는 후속 기능의 외부 계약, 유료 기능은 디지털 상품·구독의 결제 방식 결정을 함께 확인한다.

    첫 출시와 별도로 진행할 운영 확인

    두 항목은 구현이 아니라 실제 파일 확인과 운영 자료에 근거한 제품 판단이 남아 있다.

    공개 승인 기준

    운영자는 다음 결과를 확인하고 승인 또는 보류를 기록한다. 문서를 고쳤다는 사실만으로 승인되지 않는다.

    • 검사한 앱·서버·관리자 화면과 실제 배포할 프로그램의 버전이 일치한다.
    • 실제 계정과 Android·iPhone에서 이용·권한 제한·실패 후 재시도를 확인했다.
    • 메일·로그인·알림·채팅·지도·파일 서비스와 관리자 접근 제한·장애 경보·복구를 확인했다.
    • 중대한 결함을 해결했고, 예외로 수용할 위험은 사유와 대응 담당자를 기록해 승인했다.
    • 개인정보·고객지원·탈퇴 안내와 스토어 설명이 실제 기능과 맞고, 검사한 설치 파일을 제출한다.
    • iOS 로그인 구성의 심사 기준과 Google Play 계정에 적용되는 테스트·프로덕션 접근 조건을 확인하고 결과를 기록한다.
    • 공개 대상·시점·규모·중단 기준과 공개 전후 7일간 운영자가 확인할 경보·고객 공지 경로가 정해져 있다.

    현재는 보류다. 위 항목의 최종 완료 기록과 공개 승인은 아직 없다.

    확인한 것과 아직 확인하지 못한 것

    기능별 확인 범위는 기능별 출시 상태와 다음 할 일, 검사 근거는 기능별 시나리오 완성도에서 확인한다.
