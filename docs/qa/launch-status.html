첫 출시 현황과 남은 준비

현재 제공할 범위와 공개 전에 해야 할 일을 정리했다. 담당자는 자기 항목의 현재 상태를 확인하고 다음 행동과 완료 조건에 따라 결과를 제출한다.

공개 전에 할 일첫 출시 범위 후속 기능 준비공개 승인 기준
현재 결론

공개 보류 상태다. 첫 출시 기능과 관리자 웹 화면은 구현됐고 자동 검사도 마쳤다. 현재 확인된 첫 출시의 개발 차단 항목은 없다.

배포할 버전은 2026년 9월 12일에 고정했다. 다섯 프로그램이 모두 원격 저장소와 같은 상태이고, 설치 파일의 지문과 빈 데이터베이스 설치·서버 기동 결과를 같은 후보로 묶었다.

남은 일은 그 버전으로 서명한 배포용 앱을 만들고, 실제 서비스·휴대전화 검사와 장애 복구를 거쳐 공개 승인을 받는 것이다. 자동 검사 통과가 실제 고객 환경의 확인을 대신하지는 않는다.

무엇부터 해야 하는가

    아래의 담당자는 역할이다. 출시 책임자가 실제 담당자 이름과 제출일을 정해야 한다. 서비스 계정·기기 준비는 프로그램 준비와 동시에 진행할 수 있다.

    관리자 화면이나 서버가 허용되지 않은 네트워크에서도 열리면 서버 운영 담당자는 접근 차단을 다른 작업보다 먼저 처리한다.

    공개 전에 할 일

    각 항목은 아직 실제 환경의 확인 또는 승인이 필요하다. 완료 조건을 충족한 기록이 있어야 끝난 일로 처리한다.

    첫 출시 범위

    • 이메일·Google 가입, 무료 모임, 클럽, 게시글·사진·알림·개인 일정과 신고·이의 처리를 제공한다.
    • 핵심 마일리지의 적립·사용·정정·등급·배지·순위를 포함한다.
    • 클럽 가입비·기부는 무료 포인트만 사용한다. 클럽 기금으로 구독료 전액을 낼 수 있는 경우도 허용한다.
    • 유료 모임·플랫폼 결제·마켓 구매·개인 유료 구독·데이트·버스와 카풀·제공자 거래·스탬프는 후속 출시 대상이다.
    • 새 이용을 막더라도 기존 이용자의 환불·해지·신고는 계속 처리할 수 있어야 한다.

    세부 범위는 기능별 출시 상태와 다음 할 일에서 확인한다. 사적 모임의 결제 구분은 사적 모임 이용과 정산에 있다.

    후속 기능 준비

    아래 기능은 첫 출시를 기다리게 할 이유가 아니다. 담당자는 필요한 개발·검사·승인을 마친 기능부터 따로 공개를 요청한다. 마켓 기간권 판매와 추가 로그인의 실패 확인 화면에는 개발이 남아 있다.

    후속 기능의 공개 순서
    1. 주최자 계좌 직접 송금과 버스·카풀을 각각 준비한다.
    2. 카카오·네이버·Apple 로그인을 제공자별로 준비한다.
    3. 본인확인과 안전 운영을 확인한 뒤 데이트를 준비한다.
    4. 실제 계약·거래·복구를 확인한 뒤 플랫폼 결제를 준비한다.
    5. 플랫폼 결제를 사용하는 인출·개인 구독·마켓·제공자 거래를 준비한다.

    시즌·사진 심사 적립·반복 적립 검토와 스탬프는 결제와 독립적으로 준비한다. 모임별 적립 점수는 후속 기능이 아니라 첫 출시 검사에 포함한다.

    첫 출시와 별도로 진행할 운영 확인

    두 항목은 구현이 아니라 실제 파일 확인과 운영 자료에 근거한 제품 판단이 남아 있다.

    공개 승인 기준

    출시 책임자는 다음 결과를 확인하고 승인 또는 보류를 기록한다. 문서를 고쳤다는 사실만으로 승인되지 않는다.

    • 검사한 앱·서버·관리자 화면과 실제 배포할 프로그램의 버전이 일치한다.
    • 실제 계정과 Android·iPhone에서 이용·권한 제한·실패 후 재시도를 확인했다.
    • 메일·로그인·알림·채팅·지도·파일 서비스와 관리자 접근 제한·장애 경보·복구를 확인했다.
    • 중대한 결함을 해결했고, 예외로 수용할 위험은 사유와 대응 담당자를 기록해 승인했다.
    • 개인정보·고객지원·탈퇴 안내와 스토어 설명이 실제 기능과 맞고, 검사한 설치 파일을 제출한다.
    • 공개 대상·시점·규모·중단 기준, 공개 전후 7일의 비상 연락 담당자와 고객 공지 담당자가 정해져 있다.

    현재는 보류다. 위 항목의 최종 완료 기록과 공개 승인은 아직 없다.

    확인한 것과 아직 확인하지 못한 것

    기능별 확인 범위는 기능별 출시 상태와 다음 할 일, 검사 근거는 기능별 시나리오 완성도에서 확인한다.

    개발 담당자용 작업 연결표

    왼쪽 식별자는 개발 문서를 찾을 때만 사용한다. 현재 판단과 다음 할 일은 위의 업무 이름으로 읽는다.

    상태를 갱신할 때

    담당자는 확인한 날짜·프로그램 버전·실행한 역할·실제 결과·남은 문제와 승인자를 기록한다. 실제로 확인하지 않은 내용을 완료로 바꾸지 않는다. 문서의 검토 대기 수는 결함 수와 구분한다.
