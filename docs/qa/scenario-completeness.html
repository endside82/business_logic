기능별 시나리오 완성도

175개 기능을 제품 시나리오가 정의되어 있는가, 옛 소스 근거가 현재도 유효한가, 자동 테스트와 사용자 여정 검증이 어느 기능을 증명하는지 명시되어 있는가로 나눠 본다. 이 표의 “문서 연결 없음”은 곧바로 기능이나 테스트가 없다는 뜻이 아니다. 기존 테스트가 있어도 제품 시나리오 문서가 테스트 파일을 직접 가리키지 않으면 무엇을 증명하는지 확정할 수 없으므로 별도로 표시한다. 테스트 안에서 발견한 기능 번호는 번호 재사용 오탐이 있어 완료 근거가 아닌 연결 후보로만 센다.

1,403개를 “1,403개 테스트 통과”로 읽으면 안 된다. 1,403은 기능 목록에 적혀 있던 숫자의 합일 뿐이다. 상세 시나리오 문서 117개에서 실제 식별한 시나리오 제목은 1,086개이며, 그중 49개 기능은 등록 숫자와 제목 수가 다르다. 이번 감사로 정식 시나리오 정의 175/175는 확보했지만, 실제 통과율은 각 시나리오 ID에 코드·테스트·최근 실행 결과를 연결한 뒤에만 계산한다. 아래 33%·67%·100%는 구현률이 아니라 세 종류의 근거가 문서에 연결됐는지를 보여 주는 값이다.
기능 수준 확인과 개별 시나리오 증명도 다르다. 첫 출시 원장에서는 – 기능을 전체 자동 회귀로, – 기능을 로컬 실계정으로 확인했고 1개는 설계 철회로 분류한다. 이 174개는 코드 저장소 수준의 확인 결과다. 아래 표의 자동 테스트·통합 여정은 제품 시나리오 문서가 구체적인 실행 파일을 직접 지목했는지를 더 엄격하게 보여 준다.

제품 정의는 채워졌다

시나리오 수가 비어 있던 경고·징계, 마일리지, 분쟁, 클럽 레퓨테이션의 기존 수용 조건을 등록했고, 실제 시나리오가 없던 플랜 마켓 환불 10개와 매출 귀속·정산 9개를 현재 코드 기준으로 새로 작성했다. 정본 PRD가 8월 구현을 따라가지 못한 이동수단 4개 기능도 26개 시나리오별 코드·검증·출시 판정으로 다시 작성했다.

검증 연결은 아직 불완전하다

자동 테스트 파일 1,565개와 사용자 여정 파일 231개를 검색했다. 그중 시나리오 문서가 파일을 직접 지목한 자동 검증은 –, 통합·E2E 실행은 –다. 테스트 내부 기능 번호는 각각 –, –에서 발견됐지만 의미가 다른 번호도 섞일 수 있어 후보로만 둔다. 문서 연결이 없는 기능은 기존 테스트를 먼저 찾아 매핑하고, 정말 없을 때만 새 테스트를 만든다.

옛 소스 줄 링크는 신뢰할 수 없다

기존 소스 줄 표식 –개 중 현재 위치가 맞는 것은 –개뿐이다. 대부분은 코드가 이동했는데 줄 번호가 갱신되지 않은 문서 문제다. 파일 자체가 사라진 2개 표식은 철회된 타 사용자 가용시간 기능에 속한다.

무엇부터 해야 하는가

  1. 첫 출시 범위인데 알려진 문제가 연결된 기능부터 처리한다. 외부 계정·실기기 문제와 코드·화면 문제를 섞지 않고 첫 출시 현황의 남은 작업에서 해소 조건을 확인한다.
  2. 첫 출시 기능 중 자동 테스트 문서 연결이 없는 기능은 기존 테스트를 검색해 기능과 시나리오를 먼저 연결한다. 테스트가 실제로 없을 때 정상·권한·실패·중복 시나리오를 추가한다.
  3. 등록 숫자와 실제 제목 수가 다른 상세 시나리오 문서 49개는 시나리오 ID를 정규화한다. 그래야 기능별·도메인별 자동 검증률을 실제 분모로 계산할 수 있다.
  4. 돈·권한·개인정보·상태 전이가 큰 기능은 단위 테스트만으로 닫지 않는다. 앱 또는 운영자 화면에서 서버 상태가 바뀌는 통합 여정을 추가하고, 실제 계정이나 외부 서비스가 필요한 경계는 별도 실환경 검증으로 남긴다.
  5. 봉인 기능은 “테스트가 있으니 완료”로 처리하지 않는다. 고객 안내 화면, 운영 조회·처리·복구, 외부 계약·키, 봉인 해제 설정, 같은 버전의 회귀 검증까지 한 시나리오로 통과해야 개통할 수 있다.

도메인별 현황

자동 테스트와 통합·E2E 수치는 시나리오 문서가 해당 파일을 직접 지목한 기능 수다. 기능 번호만 발견된 파일은 포함하지 않는다.

표 읽는 법

  • 시나리오의 큰 숫자는 기존 기능 목록의 등록값이다. 상세 시나리오 문서는 실제 제목 수도 함께 표시한다. 두 값이 다르면 정규화가 필요한 문서이며, 어느 값도 자동 테스트 통과 건수가 아니다.
  • 검증 근거 연결도는 제품 정의, 자동 테스트 연결, 통합·E2E 또는 로컬 실계정 근거의 세 칸 중 몇 칸이 연결됐는지를 나타낸다. 3/3도 모든 시나리오 통과나 실환경 출시 완료를 뜻하지 않는다.
  • 옛 서버 줄 링크는 옛 문서의 파일·줄 번호가 지금도 맞는지를 기계적으로 확인한 결과다. “정비 필요”는 보통 코드 결함이 아니라 문서 줄 번호 이동이다.
  • 자동 테스트 문서 연결은 시나리오 문서가 테스트 파일을 직접 가리킨다는 뜻이다. 테스트 안의 기능 번호는 별도 후보이며, F03-17 번호가 전혀 다른 일정 변경 안내 테스트에서 발견된 사례처럼 번호만으로는 완료 근거가 되지 않는다.
  • 사용자 여정은 시나리오 문서가 통합·E2E 실행 파일을 지목했는지와 로컬 신규 계정 왕복 근거가 있는지를 각각 보여 준다. 외부 서비스와 서명 앱 실증은 첫 출시 현황에서 따로 본다.
