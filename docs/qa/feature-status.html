기능별 출시 상태와 다음 할 일

기능별로 출시 범위와 구현·자동 테스트·실제 환경을 따로 읽는다. 다음 행동을 누르면 준비물과 완료 조건으로 이동한다. 후속 부분의 미구현을 첫 출시 전체의 미구현으로 읽지 않는다.

현재 공개는 보류 중

첫 출시 포함은 제공하기로 정한 범위이며, 고객에게 이미 공개했다는 뜻이 아니다. 개발용 환경의 이용 확인도 실제 휴대전화·외부 서비스 검사와는 다르다. 공통 준비와 승인 기준은 공개 전에 할 일에서 확인한다.

버스·카풀의 기본 조율 흐름을 실제 앱과 서버로 확인했다. 배정·지원·의견 처리·취소 후 재배정·자동 종료·차량 교체·만석 맞교환에 이어 정원 감소와 승객 분산, 관련자 종료 안내, 저장 충돌 후 입력 보존과 재검토까지 확인했다. 관리자 기록 조회도 실제 로그인·저장 내용 대조·비공개·권한 차단까지 확인했다. 가상 도면의 카풀·버스 좌석 전환·본인 좌석 이동·다른 도면 변경과 관리자 웹 도면 관리도 확인했다. 배정 전 이동 의사·개별 이동 선택도 확인했다. 주최자의 배정 해제·배정 후 개별 이동 조정·참가 및 모임 종료 경로의 실제 이용, 휴대전화·실제 푸시·차종별 실물 도면은 아직 확인해야 한다. 현재 구현·자동 검사·다음 실제 확인에서 구분한다.

기능첫 출시 범위구현·테스트·실제 환경다음 할 일

기존 175개 목록과 별도로 클럽 스탬프와 게시글·모임 투표를 설명한다. 둘 다 첫 출시 범위다. 투표를 추가했다고 기존 게시글·모임의 검사 등급을 올리지는 않는다.

상태를 읽는 기준

  • 구현 기록 있음: 해당 범위의 코드가 있다는 기록이다. 모든 시나리오가 검증됐다는 뜻이 아니다. 일부 추가 개발은 빠진 기능의 이름을 따로 적는다.
  • 실제 환경 확인 대기: 배포용 앱·실제 서비스에서 실행한 결과가 없다. 자동 테스트가 없거나 코드가 없다는 뜻은 아니다.
  • 일부만 포함: 기능 안에서 제공할 부분과 막아 둘 부분이 다르다. 범위 설명에서 구분한다.
  • 이용 확인: 개발용 환경에서 앱을 사용하고 서버 결과를 확인한 기록이다. 새 계정으로 시작했는지, 준비된 계정을 썼는지 구분한다.
  • 전체 자동 회귀 기록: 앱·서버 전체 테스트 기록이다. 기능별 세부 실행 근거가 연결되지 않은 경우 따로 표시한다. 이를 모든 기능의 시나리오 통과로 해석하거나 새 결함으로 세지 않는다.
  • 공통 출시 준비: 배포할 버전·외부 서비스·휴대전화 검사·장애 복구·스토어 자료와 공개 승인을 준비한다.
  • 문서 검토 후보: 아직 사실 확인이 끝나지 않은 문장 수다. 확인된 결함 수와 다르며 기능의 검사 범위를 펼치면 볼 수 있다.

상세 근거는 기능별 시나리오 완성도, 문서 작성 상태는 기능 문서 점검 상태에서 확인한다.
