시나리오 커버리지 기준

제품 기능 175개 모두 시나리오 또는 수용 조건을 갖는다. 기능 목록에 적힌 숫자의 합은 1,403이지만 동일한 기준으로 센 통과 건수가 아니다. 상세 시나리오 문서 117개에서 식별한 제목은 1,086개이고 49개 기능은 등록값과 제목 수가 다르다. 이 페이지는 새 시나리오를 작성할 때 빠뜨리지 않을 8개 범주를 설명한다. 기능별 실제 연결 상태는 기능별 시나리오 완성도에서 본다.

2026-09-05 — 시나리오 정의와 시나리오 검증을 구분한다

175개 기능 모두 시나리오 또는 수용 조건을 갖지만, 시나리오 문서가 자동 테스트 파일을 직접 지목한 것은 59개 기능, 통합·E2E 실행 파일을 직접 지목한 것은 56개 기능이다. 테스트 안에서 발견한 기능 번호는 오탐이 있어 완료 근거가 아닌 검색 후보로만 둔다. 문서 연결이 없다는 사실은 테스트 부재를 뜻하지 않으며, 현재는 증명 범위를 확정할 수 없다는 뜻이다. 따라서 59개·56개를 제품 구현률로 환산해서는 안 된다. 출시 상태 문서도 근거 없는 전체 구현률 대신 기본 브랜치 반영·자동 회귀· 역할별 흐름·출시 설정을 따로 판정한다. 출시 가능 여부와 산정 근거는 첫 출시 현황의 단계별 구현 상태, 기능별 근거 연결은 기능별 시나리오 완성도에서 확인한다.

이번에 실제 상태 변경까지 확인한 범위

포인트 결제·환불은 현재 이벤트 화면에서 신청→결제→취소를 수행하고 신청·결제·지갑·원장을 다시 조회하는 7개 시나리오를 통과했다. 제공자 배정은 호스트 생성→제공자 수락→호스트 확정→정리의 네 상태를 역할별 화면과 서버 재조회로 확인했다. 화면 진입이나 빈 상태 확인으로 끝내지 않는다. 미리 준비한 계정을 썼으므로 두 기능의 확인 수준은 “로컬 서버 E2E”이며, 외부 서비스나 새 계정 생성 검증은 아니다.

그 뒤 추가된 마일리지 사진 승인은 표적 테스트에 이어 2026-09-05 현재 기본 브랜치 전체 회귀도 통과했다. 아직 회원 사진 업로드→운영진 반려→회원 재심→운영진 승인·취소를 실제 앱과 서버로 이어 실행하지 않았으므로 확인 수준은 “자동 회귀”에 머문다. 이 역할별 상태 변경 여정을 만든 뒤에만 “로컬 서버 E2E”로 올린다.
