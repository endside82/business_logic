사용 흐름 확인회원·주최자·운영자가 화면에서 행동하고 서버 저장 결과까지 대조한다.로컬 웹·시험 계정·에뮬레이터 결과를 실기기나 운영 배포 결과로 바꾸지 않는다.

공개 승인첫 출시 범위의 필수 결과, 운영 복구·고객 안내·스토어 자료와 운영자의 공개 결정을 같은 버전에 연결한다.후속 범위는 계속 제한한다. 스토어 제출·승인·실제 공개는 각각 기록한다.

과거 관문 문서의 “완료 13개”는 정책 결정 12개와 코드 완료 1개를 뜻하는 당시 분류입니다. 서명 출시후보·실환경 증거·승인까지 모두 닫힌 관문 수나 현재 공개 완료 수로 읽지 않습니다. 과거 검사 이후 소스가 바뀌면 변경 영향을 다시 연결합니다.

공개 범위와 제외 기능의 경계

175개는 등재 기능 수입니다. 이번 공개의 포함·부분 포함·후속·제외 범위는 현재 결정과 환경 설정을 대조해 정합니다. 이전 문서의 134개 포함·16개 일부 포함·24개 후속·1개 제외는 당시 분류이며 현재 기능 완성도나 공개율이 아닙니다.

  • 부분 포함 기능은 실제 공개한 행동과 필요한 기존 의무 처리만 해당 후보의 기준으로 삼습니다. 닫힌 기능의 신규 이용과 환불·해지·신고·미결 처리의 접근을 구분합니다.
  • Google Calendar 연결·선택 전송·자동 전송·연결 해제는 현재 일정 연동 계약과 환경별 OAuth·기기 근거를 따릅니다. 이전 에뮬레이터 기록을 현재 운영 공개나 iOS 확인으로 읽지 않습니다.
  • 타인 가용시간 공개 조회의 폐기 상태를 유지합니다. 본인 비공개 가용시간·관심인 활동 공개 설정·이벤트 일정은 각각 별도 계약입니다.
  • 계좌 소액 인증이나 후속 PG 계약을 주최자 직접 송금의 선행 조건으로 임의로 추가하지 않습니다. 기존 데이터가 없는 설치에 이관 검사를 요구하지 않고 실제 보존 대상과 복구 의무를 확인합니다.

변경된 업무와 남은 질문에 맞는 근거를 선택합니다. 배치·잘림·대비·이미지 표시를 판단할 때만 화면 이미지를 확인하고, 큰 글자·다기기·전수 촬영을 일괄 요구하지 않습니다. 요청·권한·저장·횟수는 소스와 실행 결과로 판단합니다.

함께 적용하는 권한·실패·복구 확인

  • 화면과 저장 결과: 성공 문구만 보지 않고 다시 조회한 상태·명단·건수·금액·기간이 기대한 결과와 같은지 확인합니다.
  • 권한과 회수: 본인/타인·회원/비회원·주최자/참가자·운영 권한을 구분합니다. 차단·탈퇴·제재·비공개 전환 후 기존 화면과 직접 링크에서도 제한이 적용돼야 합니다.
  • 중복과 경합: 상태를 바꾸는 기능은 연속 누름·응답 유실 후 재시도·동시 처리에서 중복 등록/차감/환불/적립을 만들지 않아야 합니다. 단순 읽기에는 해당 쓰기 조건을 억지로 붙이지 않습니다.
  • 실패와 복귀: 빈 상태·권한 거절·외부 오류·시간 초과를 구분하고 사용자가 다시 시도하거나 이전 화면으로 돌아갈 수 있어야 합니다. 계정 전환 후 이전 응답·비공개 정보를 남기지 않습니다.
  • 날짜와 금액: 해당 기능의 시간대·만료·마감 경계, 반올림·부분 환불·포인트/현금 구분을 확인합니다. 실제 돈 이동은 공급자/은행 기록과 대조합니다.
  • 외부 서비스: 실제 메일·푸시·지도·파일·결제를 사용한 범위와 모사 응답·에뮬레이터 범위를 기록합니다. 제공하지 않는 연동을 이 기능의 필수 조건으로 만들지 않습니다.
  • 운영: 사람이 판단하는 조치는 대상·사유·권한·감사 기록과 실패 재처리 결과를 남깁니다. 운영자 한 사람이 역할별 계정과 메뉴를 바꿔 확인할 수 있습니다.

조건을 충족하지 못하면 실패, 아직 실행하지 않으면 미실행, 준비물이 없어 실행할 수 없으면 실행 차단으로 적습니다. 해당하지 않는 검사는 이유와 공개 범위를 기록해 해당 없음으로 둡니다. 보류나 해당 없음을 통과 건수에 더하지 않습니다.

현재 기능 정본의 제한과 완료 조건

이전 한계 목록을 현재 결함 수로 복사하지 않습니다. 각 기능의 현재 계약·공백·위험과 공개 범위를 함께 대조합니다. 해결 증거가 없거나 간접 근거만 있으면 완료로 바꾸지 않습니다.

  • 알림 그룹과 상단 미읽음 배지의 갱신 범위: 서버 미읽음 수와 불러온 그룹 카드 수를 구분합니다. 하단 알림 탭을 현재 입구로 가정하지 않습니다.
  • 경고 이의제기의 제출·재제출 조건과 검토 큐·집계와 운영 화면의 범위를 따릅니다.
  • 분쟁 증빙의 접근·보존·표시 한계를 기준으로 서버 권한과 앱의 파일 열기 입구를 구분합니다.
  • 마켓 아이템·기간권 운영 계약과 외부 일정 연동 계약의 남은 조건을 해당 공개 판단에 연결합니다.
  • 사적 모임의 생성 입구·조회 실패·정산 안내 한계를 전용 API 존재만으로 완료 처리하지 않습니다.

공개 판단에 필요한 실행 순서

현재 출시 준비의 순서와 보류 결정를 따릅니다. 먼저 공개 범위와 후보를 정하고 관련 소스·설정·산출물·기존 근거를 연결합니다. 새 API 선행 배포 등 의존 관계를 확인한 뒤 남은 기능·기기·외부 연동·복구 질문에 맞는 검사만 수행하고 결과와 공개 판단을 남깁니다.

플랫폼 가이드와 현재 설정·산출물이 옛 고정 순서보다 우선합니다. Android 내부 트랙 배포, iOS 서명 IPA, 스토어 업로드·처리·설치·정식 공개를 분리합니다. 문서만 바뀌었다면 제품 전체 검사를 반복하지 않습니다.

프로필 글과 후기 이름의 구체적인 확인

내·타인 프로필과 작성 글의 완료 기준은 조회자의 현재 가입 클럽, 대상의 공개 설정·차단, 게시 상태를 목록과 건수에 함께 적용합니다. 20개 페이지 경계를 확인할 때 두 클럽·21개 이상 글 조건을 사용합니다. 대상이 클럽을 떠난 경우와 조회자가 떠난 경우를 구분하고, 글 원문 왕복·마지막 쪽 소멸·계정 변경에서 이전 정보를 재사용하지 않아야 합니다.

정기모임 후기의 작성자·평가 대상 연결은 두 사람과 실제 목적지를 구분합니다. 현재 호스트를 기록된 평가 대상으로 대체하지 않고, 허용된 프로필 링크·복귀·차단 뒤 후기 범위와 집계의 조건을 확인합니다. 필요한 페이지·건수 조건은 이 업무의 계약이며 모든 기능에 같은 시험 데이터를 강제하는 기준이 아닙니다.
