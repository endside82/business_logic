1. 지갑의 유료·무료 포인트와 클럽 마일리지

1.1 유료 포인트

충전, 허용된 정산·수취·환불 등으로 생긴 유료 잔액입니다. 무료 잔액과 별도 원본·사용 이력을 가지며 결제·차감·환불에서 그 구성을 보존합니다. 유료 잔액 전체가 곧 출금 가능액은 아닙니다. 출금 자격·예약·회수 의무·계좌·공개 범위를 추가로 확인합니다.

1.2 무료 포인트

프로모션 지급이나 허용된 무료 매출 적립 등으로 생긴 비현금성 잔액입니다. 해당 소비가 무료 사용을 허용해야 쓸 수 있고 외부 현금으로 출금하거나 유료 잔액으로 바꾸지 않습니다. 무료 지급·만료·환불 원본의 기한도 별도 규칙을 따릅니다.

1.3 클럽 마일리지

클럽 활동의 적립·차감·정정·만료와 등급·배지·랭킹을 위한 정수 점수입니다. 지갑 포인트와 바꾸거나 결제·환불·현금 정산으로 연결하지 않습니다. 회원 조회, 정책 관리, 보상 집행, 배지 집행, 운영 검토의 권한이 다릅니다. 일반 마일리지·시즌·사진·고급 검토의 공개 경계도 각각 확인합니다. 마일리지 영역과 현재 제한이 정본입니다.

이전 마일리지 출시·실행 기록 원문

아래는 이전 문서의 기록입니다. 이번 소스 대조로 재실행하거나 현재 공개·배포 상태를 확인한 기록이 아닙니다.

시즌·사진 심사 적립·반복 수동 적립 검토까지 첫 출시 기본 목록에 포함했다. 기능별 서버 검사와 앱 전체 검사를 통과했다. 시즌·반복 적립 판정·모임별 점수는 실제 앱과 서버에서도 확인했다. 사진 심사의 반려·재심·승인·취소와 점수 회수는 로컬 앱에서 확인했다. 실제 사진 파일·운영 배포·휴대전화 알림은 남아 있으며, 기존 데이터를 유지하는 경우에만 필요한 보강을 확인한다. 어느 기능도 현금 결제·환불로 연결하지 않는다. 기능별 출시 조건과 순서는 마일리지 현황에서 본다.

2. 제품 전체에 공통으로 적용되는 원칙

2.1 지갑 차감과 비즈니스 처리의 역할이 다르다

지갑 차감, 구매·참석 권리, 수취자 수익, 회계 원장은 서로 연결되는 별도 결과입니다. 참가비를 냈다는 사실과 호스트에게 지급 가능한 수익이 생겼다는 사실은 같지 않습니다. 공통 차감은 유료·무료 몫과 충전 원본 소비를 기록하고, 각 업무가 참석 확정·판매자 귀속·기금 적립 등을 처리합니다. 자금 전달 분류 하나만으로 모든 권리와 장부가 자동 완성된다고 설명하지 않습니다.

2.2 무료 포인트는 현금화되지 않는다

허용된 참가비·상품·기부 등에서 무료분을 쓸 수 있어도 그것을 현금 수익이나 출금액으로 바꾸지 않습니다. 무료 매출의 지급·보조·플랫폼 비용 처리는 해당 도메인을 따릅니다. 모임 비용 정산처럼 유료 전용인 흐름도 있습니다. 참가비 선입금과 별도 모임 정산 선입금을 같은 통화 정책으로 묶지 않습니다.

2.3 환불은 원래 결제 구성을 넘을 수 없다

  • 원거래의 유료·무료별 잔여 원금을 넘겨 반환하지 않습니다. 같은 결제의 여러 환불과 일행 추가 결제도 실제 원금·이미 반환한 몫을 연결합니다.
  • 취소 예상액은 조회 시점 값입니다. 실행 때 저장된 정책·귀책·시각·권한·남은 원금·추가 결제를 다시 판정합니다.
  • 지갑 반환, 카드 원수단 취소, 호스트 은행 반환, 참가자의 수령 확인은 각각 다른 결과입니다. 상태명만으로 실제 은행 입금이나 원금 전액 반환을 단정하지 않습니다.
  • 보상 지급은 원결제 취소와 다른 명령입니다. 보상으로 돈을 더 줬다는 이유로 구매 권리나 상대방 정산이 자동 취소되지 않습니다.

2.4 수수료·원천세는 원천과 적용일에 맞춰 계산한다

유료 매출의 수수료를 먼저 계산하고, 그 공제 후 금액으로 원천세를 계산하며 각 단계의 반올림을 적용합니다. 무료분은 이 유료 공제 계산과 분리합니다. 일반 이벤트는 종료일, 정기모임은 기간 끝과 실제 종료일 또는 취소일을 비교한 기준일로 유효 요율을 조회합니다. 정기모임에 종료일이 있으면 취소일보다 먼저 사용합니다. 마켓과 클럽 출금의 기본 상수 사용도 이 날짜별 조회와 다릅니다.

따라서 모든 흐름에 일률적으로 10%·3.3%를 적용하거나 ‘총액 × (1 − 수수료율 − 세율)’로 합쳐 계산하지 않습니다. 수치와 적용 조건, 창작자 수익 배분·월 지급, 클럽 기금 인출을 확인합니다.

2.6 운영자 조치도 원거래·권한·상태·한도를 검사한다

운영자가 환불·지급·보정 버튼을 눌렀다는 사실만으로 처리가 끝나지 않습니다. 환불 중인 정산, 기존 지급 거래, 회수 예약·잔액을 재검사하며 이미 돈이 움직인 건을 실패 표시로 바꿔 한도를 다시 열지 않습니다. 추가 입금 보정 한도와 최초 지급액을 포함한 총 지급액은 다른 기준입니다.

무료 포인트 지급은 MANAGE_PAYMENT 권한과 필수 요청 키, 대상·금액·사유 검사를 거쳐 운영자 작업을 예약하고 사용자 서비스의 지갑 경로에 위임합니다. 현재 금액은 1~10,000,000P, 필수 사유는 최대 185자입니다. 원결제를 지정하지 않는 지급이므로 구매 취소나 현금 환불로 쓰지 않습니다. 이 서버 대조로 관리자 화면 실행·배포 보안 검증까지 완료했다고 기록하지 않습니다.

2.7 응답 유실은 명령별 결과 확인·재시도 규칙을 따른다

결과를 모를 때는 같은 원본·작업 식별자로 상태와 거래를 확인합니다. 저장된 결과를 재생하는 경로도 현재 권한·대상·본문 조건을 따르며, 재구성할 수 없는 결과를 새 성공으로 꾸미지 않습니다. 모든 쓰기가 같은 요청 키나 앱 재시작 복구를 제공하지는 않습니다. 예를 들어 지갑 참가비와 은행 신고, 기부와 회원 기금 출금은 보장이 다릅니다.

운영자 작업 원문의 기본 보존 작업은 확인 완료 시각 또는 거절 갱신 시각에서 90일이 지난 종결 행을 대상으로 합니다. 계정 파기 시에는 해당 회원의 확인 완료·거절 행을 기간과 무관하게 가립니다. 진행 중인 모든 작업 원문까지 같은 시점에 지우는 것은 아니며, 사유·메모 마스킹과 금전 원장 삭제는 다릅니다. 개인정보·안전 정책의 운영 기록 보존을 따릅니다.

2.8 금전 기능 제한과 의무 처리의 예외를 구분한다

공통 지갑 차감은 소비 종류와 허용 통화를 판정합니다. 금전 기능이 닫히면 일반 신규 소비를 거절하고, 지정된 기부·가입비·클럽 미납금 상환·클럽 구독 지갑분은 허용된 무료 전용 정책으로 좁힙니다. 지정된 환불성 반환·정산 보정·회수·계정 폐쇄 환급은 별도 예외입니다.

이 예외를 모든 환불·상환·출금 API의 무조건 허용으로 확대하지 않습니다. 주최자 회수금의 신규 상환과 외부 지급 작업처럼 금전 기능을 다시 검사하는 경로가 있습니다. 기존 의무의 조회·반환·복구 경로도 각 권한·원본 상태·공급자 결과를 따릅니다.

3. 비즈니스 유형별 분류

3.1 수취자에게 전달되는 구매

참가비, 마켓·번들·플랜, 프라이빗 미팅비, 클럽 기부·가입비, 정기모임 지갑 결제 등이 해당합니다. 통화 허용은 별도 기준입니다. 제공자 서비스비처럼 수취자에게 전달되어도 유료 전용인 거래가 있고, 상품의 승인 가격 정책에 따라 혼합·유료 전용·무료 전용을 구분합니다.

3.2 플랫폼 소비와 플랫폼 소유 판매

개인 구독·클럽 구독 지갑분·프라이빗 개설비·개설권은 공통 분류상 플랫폼 소비입니다. 등록부에서 무료를 허용해도 화면이 모두 무료 결제를 제공하는 것은 아니며 현재 개설권 구매는 유료만 사용합니다. 플랫폼 소유 마켓 상품은 별도 판매 수익 경로이며 회원 창작자 월 지급으로 보내지 않습니다.

3.3 정산성 이동과 통화별 채무

모임 정산·반환·회수·외부 출금·계정 폐쇄 환급 중 지정 경로는 유료 전용입니다. 클럽 미납금 상환은 한 명령이 유료 또는 무료 한 통화의 채무를 처리합니다. ‘수취자에게 전달’·‘플랫폼 소비’ 같은 분류와 ‘유료만 사용’은 서로 다른 축이므로 서로 바꿔 부르지 않습니다.

4. 상황별 빠른 판단표

질문현재 판단
무료 포인트로 참가비·상품을 낼 수 있나요?공개된 수단과 해당 거래의 통화·가격 정책이 허용할 때입니다. 무료분을 외부 현금으로 바꾸지는 않습니다.
클럽 구독은 기금 전액이 있어야 하나요?아닙니다. 기금 유료·무료 다음 클럽장 지갑 부족분을 처리합니다. 제한 중 허용 지갑분은 무료 전용입니다.
무료로 비용 정산 분담금이나 외부 출금을 할 수 있나요?해당 유료 전용 흐름에는 쓸 수 없습니다. 클럽 기금도 무료 잔액은 출금 대상이 아닙니다.
결제 성공이면 판매자 지급과 참석도 모두 끝났나요?아닙니다. 결제·권리·정산·지갑 지급·은행 지급을 각각 확인합니다. 자동충전 성공도 원 구매 성공과 다릅니다.
환불 완료 상태면 은행에서 전액 돌려받았나요?일반 모임 은행 반환은 양수의 상한 미만 금액도 REFUNDED로 닫을 수 있습니다. 기록된 반환액·증빙·실제 수령을 확인합니다.
정산 후 환불이면 회수도 끝났나요?아닙니다. 이미 지급된 몫의 미수금·회수 예약·상계·잔액 부족을 따로 추적합니다. 무료분으로 유료 미수금을 갚지 않습니다.
출금 승인이나 공급자 요청 성공이 은행 입금인가요?아닙니다. 예약·지급 시작·결과 불명·공급자 확정·원장 반영을 구분합니다. 통신 실패로 새 송금을 바로 만들지 않습니다.
운영자 무료 지급이 구매 환불을 대신하나요?아닙니다. 별도 보상 지급은 원 구매 권리와 상대방 수익을 되돌리지 않습니다.
마일리지를 지갑 포인트로 바꿀 수 있나요?현재 마일리지는 별도 클럽 점수이며 지갑 교환·현금 정산으로 연결하지 않습니다.

5. 기획에서 특히 주의해야 할 경계

5.1 “잔액”이라는 단어는 하나가 아니다

총 지갑, 유료, 무료, 출금 가능액, 정산 예정액, 실제 지갑 지급액, 회수 미수금, 클럽 기금, 기금 출금 가능액, 마일리지를 구분합니다. 정산 예정액은 이미 입금된 잔액이 아니고, 전액 미수금 상계된 지급은 명목 수익과 실제 유료 적립액이 다를 수 있습니다.

5.2 환불 시점은 정산 전과 정산 후로 나눠야 한다

지급 전에는 구매자 반환과 미지급 수익 정리를, 지급 후에는 구매자 반환과 수취자 회수를 각각 연결합니다. 환불 보류·종결 상태와 남은 유료/무료 원금을 먼저 확인하며, 이미 수익이 지급됐다는 이유로 모든 원천에 동일한 미수금 처리 하나를 적용하지 않습니다. 창작자 환불 종결과 미수금 상계와 참가비 환불의 원천별 규칙을 따릅니다.

5.3 직접 은행 송금과 플랫폼 외부 결제 연동을 구분한다

호스트 계좌로 직접 낸 참가비, 비용 정산의 직접 송금은 플랫폼 지갑 밖의 돈 이동입니다. 신고·호스트 수취 확인·반환 기록·상대 수령은 서로 다른 증거입니다. 가상계좌 통지·카드 결제·외부 출금은 공급자 증거와 플랫폼 거래·원장을 연결하는 연동이므로 모두를 ‘장부 밖’이라고 묶지 않습니다.

5.4 소스 계약과 실제 외부 결과를 구분한다

  • 문서의 기본 설정, 소스의 경로 존재, 서버 허용, 앱 노출, 공급자 준비, 운영 공개 승인은 각각 확인합니다.
  • 외부 지급 호출 뒤 시간 초과는 미지급 확정이 아닙니다. 기존 공급자 번호·같은 지급 키로 확인하고 오래된 실행의 응답이 최신 상태를 덮지 않도록 처리합니다.
  • 탈퇴 뒤 지정된 반환·지급은 지갑 대신 보류금으로 남을 수 있습니다. 원출금의 늦은 증빙과 재지급·외부 종결을 함께 확인합니다.
  • 실결제·은행 입금·카드 원수단 환불·가상계좌 통지·운영 대사·실제 알림 수신은 해당 배포본의 별도 증거가 필요합니다. 이번 문서 대조는 이 결과를 새로 통과한 기록이 아닙니다.

6. 문서 사용법

돈의 종류와 납부·반환·수익·지급 단계를 먼저 정하고 업무별 도식과 종착점, 행위자별 상황 시나리오를 찾습니다. 수치는 값과 적용 조건으로, 최종 권한·상태·가격·복구 규칙은 결제·정산 공통 정책과 각 기능 정본으로 확인합니다. 연결 문서의 이전 실행 기록을 현재 운영 완료로 합산하지 않습니다.
