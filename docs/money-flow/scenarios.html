1. 지갑 충전

충전 · 자동충전 · 금액 한도와 기본 설정

1.1 사용자가 직접 충전하는 경우

  1. 금액을 확인하고 결제를 진행합니다. 앱과 서버의 상한이 다르며 지갑 총잔액 상한도 적용합니다.
  2. 공급자 확인과 지갑 적립 결과를 확인한 뒤 충전 성공을 표시하고 거래 내역을 다시 읽습니다. 충전액은 유료 원본으로 남습니다.
  3. 승인 실패·확인 중·결과 불명·적립 후 조회 실패를 구분합니다. 화면 통신 실패만으로 결제 실패·잔액 불변을 확정하지 않습니다.

공급자 승인 뒤 내부 반영 실패는 취소·기존 결과 조회·복구가 따릅니다. 취소 응답도 불명확하면 돈이 돌아왔다고 단정하지 않습니다. 이미 완료된 같은 충전의 결과 재사용과 확인 중 중복 오류는 다르며 모든 경쟁 요청의 성공을 보장하지 않습니다.

1.2 자동충전이 발생하는 경우

  1. 원 구매에서 실제 부족액이 생기면 설정·카드·월 한도·충전액·지갑 상한을 확인합니다. 저장된 잔액 임계값과 실제 부족액 기준 실행은 다릅니다.
  2. 자동충전 결과를 확인합니다. 진행 중이거나 결과를 알 수 없으면 원 구매 성공으로 표시하지 않습니다.
  3. 충전 뒤 원 구매를 다시 처리할 때 가격·권한·참석 정원 등 현재 조건을 재검사합니다. 충전은 성공하고 원 구매는 실패할 수 있습니다.

수동 충전 후의 원 구매 재시도와 자동충전 내부 처리를 혼합하지 않습니다. 가입·구독 등 모든 지갑 소비가 자동충전을 호출하는 것도 아닙니다.

2. 지갑 소비 공통

재원 선택은 자금 전달 방식과 다른 기준입니다. 결제·정산 공통 정책의 통화와 가격 규칙을 따릅니다.

2.1 유료 우선 결제

유료 우선·무료 부족분 사용이 허용된 경로에서만 합산 잔액을 사용합니다. 상품·번들·플랜은 승인 가격 정책에 따라 유료 전용, 무료 전용, 유료 우선 혼합을 나눕니다. 무료 전용가가 있는 상품의 일반 결제는 유료만 사용할 수 있습니다. 앱 선택지와 서버 최종 가격도 별개입니다.

클럽 기부·가입비·구독 지갑분은 금전 기능이 닫히면 허용된 무료 전용 정책으로 좁힙니다. 유료가 충분하다는 이유로 무료 부족분을 대신 쓰게 하지 않습니다. 실제 사용한 유료·무료 몫은 환불·수익에도 유지합니다.

2.2 유료만 가능한 결제

모임 비용 정산·지정 회수·외부 출금 등 유료 전용 경로에는 무료 잔액을 쓰지 않습니다. 현재 개설권 구매와 제공자 서비스비도 유료 전용입니다. 별도 정산 선입금은 공개 제한 중이며 참가비 선입금과 다릅니다. 클럽 미납금은 한 명령에서 한 통화의 채무를 처리합니다.

2.3 무료 포인트만 복원되는 경우

무료로 낸 몫의 반환은 무료로 돌아오며 현금 출금 권리를 만들지 않습니다. 이미 반환한 몫을 제외한 원금 한도를 적용합니다. 무료 환불 원본의 기한이 복원일부터 30일보다 짧으면 해당 반환 몫만 30일 원본으로 분리하며, 더 긴 기한과 원본 전체를 무조건 새로 연장하지 않습니다.

3. 이벤트 참가비와 호스트 정산

참가비 선입금과 은행 반환 · 신청 취소와 참가비 환불 · 호스트 정산 내역과 이의 제기

3.1 지갑 선결제로 참가하는 경우

  1. 자동 승인 또는 호스트 승인이 결제 대기 신청과 기한을 만듭니다. 승인이 곧 참석 확정은 아닙니다.
  2. 현재 수단·서버 금액·신청·기한·중복 결제·계정 조건을 확인해 지갑 납부를 시도합니다. 필요하면 자동충전의 결과를 먼저 확인합니다.
  3. 납부 명령에서 정원·제재·참석 확정 조건을 검사합니다. 완료 결과를 재조회하고 실패·결과 불명을 나눠 안내합니다.

같은 키의 처리 결과 재생과 다른 새 결제의 중복 거절을 구분합니다. 원 결제와 유료 일행 추가 결제도 별도 기록이므로 한 신청에 결제는 언제나 하나라는 설명을 쓰지 않습니다.

3.2 은행 이체 선결제로 참가하는 경우

  1. 참가자는 안내된 주최자 계좌를 확인하고 실제 송금 후 신고합니다. 신고 자체는 입금 확인이 아닙니다.
  2. 확인 권한이 있는 담당자가 외부 은행 내역과 현재 신청·정원·제재를 확인합니다. 입금이 있어도 참석을 확정할 수 없으면 반환 요청으로 이어질 수 있습니다.
  3. 취소된 돈은 주최자가 은행에서 반환하고 금액·증빙·시각을 기록합니다. 참가자의 실제 수령 확인은 별도입니다.

일반 모임은 양수의 상한 미만 반환액도 REFUNDED로 종결할 수 있습니다. 상태만으로 전액 반환을 단정하지 않습니다. 확인 대기 신고는 일반 결제 기한 만료와 구분합니다.

3.3 이벤트 종료 후 정산되는 경우

  1. 종료된 모임의 정산 대상과 남은 결제·환불·보류를 확인합니다. 직접 은행 수취를 플랫폼 지갑 지급에 다시 더하지 않습니다.
  2. 유료 매출과 무료분을 나누고 모임 종료일에 적용되는 수수료·원천세를 순차 계산합니다.
  3. 정산 생성·운영 승인·지급·미수금 상계·실제 지갑 적립을 각각 확인합니다. 호스트 정산 지급 상태가 외부 은행 입금을 뜻하지는 않습니다.

예를 들어 적용 수수료가 10%, 원천세가 3.3%인 경우에만 유료 100,000원에서 10,000원과 2,970원을 공제해 명목 순액 87,030원이 됩니다. 무료 10,000P는 별도 무료 몫입니다. 실제 적립액은 보류·조정·회수 등에 따라 달라지므로 이 예시를 모든 정산의 고정 요율·입금 보장으로 쓰지 않습니다.

3.4 이벤트 결제 환불이 발생하는 경우

취소 미리보기 뒤 실행에서 정책·귀책·남은 원금·추가 결제를 다시 계산합니다. 지급 전에는 미지급 수익을 정리하고 지급 후에는 이미 받은 수익의 회수 의무를 별도로 추적합니다. 참가자 반환과 호스트 회수의 완료는 다릅니다. 지갑 반환·카드 원수단 취소·호스트 은행 반환도 서로 바꾸어 설명하지 않습니다.

정기모임 회비의 별도 조건

회비 결제 · 남은 회차 환불 · 정기모임 수익 정산

등록 납부 기한 72시간과 신고 뒤 호스트 확인 기본 5일은 다릅니다. 회원 취소·몰수는 시작된 회차, 호스트 취소는 CLOSED 회차를 소비분으로 보고 취소 회차는 제외합니다. 환불액은 100원 단위로 내립니다. 종료·취소 뒤에도 환불 보류나 잔여 0 때문에 지갑 정산이 생성되지 않을 수 있으며, 은행 직접 수취를 지갑 지급에 합산하지 않습니다.

4. 마켓 아이템·번들·플랜 구매

구매·가격·재원 · 구매 환불과 분쟁 · 창작자 매출 배분과 월 지급

4.1 단일 아이템 구매

  1. 판매 상태·활성 승인 버전·가격·재원·재고·한도를 확인합니다. 화면 조회 가격이 요청 시점에도 고정된다고 보장하지 않습니다.
  2. 구매 기록과 권리를 만들고 구매 당시 소유자별 수익을 기록합니다. 플랫폼 소유 상품은 회원 창작자 지급과 다릅니다.
  3. 회원 매출의 PENDING 중 생성 후 14일 초과 등 월 지급 후보 조건을 적용하고 지급 때 환불·기지급·미수금 상태를 다시 확인합니다.

구매 기록, 보관함 이용권, 창작자의 명목 수익, 실제 지갑 지급은 각각 확인합니다. 모든 미지급 상태를 월 배치가 자동 재시도하는 것은 아닙니다.

4.2 번들 구매

구매 당시 구성품의 활성 버전 단가 × 구성 수량을 가중치로 배분하고 합계가 0이면 균등 배분합니다. 총액을 정수 내림하고 마지막 행에 잔여를 배정하며 유료·무료 합계도 각각 보존합니다. 회원·플랫폼 소유자가 섞일 수 있습니다.

부분 환불은 구매 당시 bundleItemId와 아직 종결되지 않은 수익 행을 고릅니다. 전체 열린 구성품을 선택하면 FULL로 합치고, 임의 금액 환불 입력은 받지 않습니다. 승인 때 실제 대상 권리·수익만 회수합니다. 창작자 무료 매출 적립을 구매자 보너스로 설명하지 않습니다.

4.3 플랜 구매

PUBLISHED 플랜, 본인 플랜 아님, 같은 플랜의 ACTIVE 직접 구매 없음, 연결된 판매 상품·활성 버전을 검사합니다. 환불 이력만 남았다면 재구매할 수 있습니다. 직접 플랜은 상품·번들의 월 구매 50건 제한이나 재고 차감과 동일하지 않습니다.

무료로 시작하기가 본문 이동인 경우 구매 기록·보관함·수익 생성으로 세지 않습니다. 유료 직접 구매의 실제 재원과 창작자 수익은 해당 승인 가격 정책을 따릅니다.

4.4 마켓·플랜 환불

회원 판매의 SELLER 처리와 플랫폼 소유가 포함된 PLATFORM_QUEUE를 나눕니다. 플랫폼 큐는 처음부터 ESCALATED이며 회원 판매자의 판정·자동 승인·구매자 분쟁 경로를 그대로 열지 않습니다.

반환은 유료·무료 원금을 보존하고 대상 권리를 회수합니다. 지급 후 환불의 유료 미수금은 다음 유료 순액에서 상계하며 부족하면 남깁니다. 전액 상계 뒤 수익 상태가 PAID여도 환불 종결 표지가 있으면 다시 지급하거나 환불하지 않습니다.

5. 모임 선입금과 모임 정산

공개 제한 중인 정산 선입금 · 분담 납부 · 은행 수취 확인 · 정산 요청·취소와 반환

5.1 모임 선입금

별도 정산 선입금은 MEETING_PREPAYMENT 관문으로 닫혀 있습니다. 여덟 공개 API와 앱의 관리·환불 규정 하위 경로도 제한되므로 납부 성공을 현재 정상 이용 시나리오로 제시하지 않습니다. 호스트 요청·금액 고정·정산 차감을 갖춘 상품은 채택 전 후보이며 문서 갱신으로 개방하지 않습니다.

관문 뒤에 남은 POINT/BANK_TRANSFER 결제·환불 계약과 종료·취소의 내부 정리 연결은 참가비 선입금과 다릅니다. 가상계좌 통지는 정산 이체를 확인하는 경로이며 이 선입금을 자동 확인하는 근거가 아닙니다. 기존 의무·실제 설정은 별도 확인합니다.

5.2 모임 정산 분담금

  1. 생성자가 지출·수입 항목과 몫을 만들고 금액을 검토합니다. 초안 작성은 납부 요청이 아닙니다.
  2. 정산 요청에서 모임 종료·현재 항목·분담·당사자·상태를 재검사합니다. 지출은 분담자에서 선지급자, 수입은 보유자에서 배분받는 사람에게 흐릅니다.
  3. 유료 포인트 납부·직접 차액 송금·외부 은행 신고/수취를 구분합니다. 자기 몫을 자기에게 송금하지 않습니다.
  4. 남은 의무를 기준으로 완료를 판단합니다. 송금 기한 만료나 신고 성공만으로 채무가 사라지지 않습니다.

5.3 모임 정산 취소

  1. DRAFT·ACTIVE 취소 권한과 원본을 확인해 부모 정산을 CANCELLED로 저장합니다. COMPLETED에 임의 새 취소를 만들지 않습니다.
  2. 진행 중 정산의 개별 반환을 이어 시도합니다. 포인트는 원거래의 미반환 몫, 직접 은행 수취는 실제 받은 사람의 수동 반환이 대상입니다.
  3. 보냈다는 신고만 남은 건도 별도 확인합니다. 실제 보냈으면 반환, 보내지 않았으면 신고 취소가 필요할 수 있습니다. 수입 분담은 지급 방향이 다릅니다.
  4. 반환 실패와 수동 은행 반환을 남기고 관련 내역을 다시 읽습니다. 취소 성공·복구 표지 해제만으로 전체 반환 완료를 표시하지 않습니다.

지갑 장부에 적립된 가상계좌 송금의 역분개는 지갑 반환이며 외부 은행 자동 송금이 아닙니다. 미시도 반환 복구와 실패 재시도는 별도입니다. 현재 실패 횟수 3회에 도달하면 자동 재시도 한도와 운영 알림 조건에 해당하지만, 작업 선언은 실제 재실행·기기 알림 수신 증거가 아닙니다.

6. 클럽 기금

기부와 폐쇄 반환 · 클럽 가입·탈퇴 · 운영 구독 · 기금 인출

6.1 클럽 기부

ACTIVE인 FREE 클럽의 현재 회원이 1,000~1,000,000 범위에서 기부합니다. 금전 기능이 닫히면 무료만, 열리면 유료 우선 정책으로 차감해 실제 통화별 기금을 늘립니다. 같은 기부의 요청 키와 결과 조회를 연결합니다.

본인 취소는 현재 회원·본인 ACTIVE 기부·생성 후 7일 조건과 원금 잔여·기금 가용액을 검사합니다. 폐쇄 반환은 다른 배분이며 모든 기부 전액 환불을 보장하지 않습니다.

6.2 클럽 가입비

가입 신청, 승인, 초대 수락에서 실제 회원이 되는 시점과 가입비 납부를 연결합니다. 금전 기능 제한 중 허용된 가입비는 무료 전용이고 받은 무료 기금을 현금 출금할 수 없습니다. 회원이 되는 결과·지갑·기금을 각각 확인합니다.

자발적 탈퇴·강퇴·차단·클럽 폐쇄는 반환 조건이 다릅니다. 실제 가입비 원거래와 사유·기금·미납금 조건을 판정하며 탈퇴 성공만으로 반환이나 클럽의 채무 정리가 모두 끝났다고 안내하지 않습니다.

6.3 클럽 운영 구독

  1. 현재 클럽장과 클럽·구독 상태, 선택 플랜을 확인합니다.
  2. 기금 유료 → 기금 무료 → 클럽장 지갑 부족분 순서로 결제합니다. 금전 기능 제한 중 허용 지갑분은 무료 전용입니다.
  3. 달력 기준 월간·연간 기간과 자동갱신 상태를 반영합니다. 실패·정지·유예·운영 정지의 효과를 구분합니다.

기금이 전액을 부담해야만 성공하는 계약이 아닙니다. 운영자 환불은 이번 결제가 더한 기간과 실제 지갑·기금 유료/무료 재원을 나눕니다.

6.4 클럽 기금 인출

  1. 현재 클럽장이 등록된 본인 계좌로 최소 금액·월 제한·최근 요청 횟수/금액 한도를 확인해 신청합니다.
  2. 유료 기금에서 예약·환불 보호액·미납금을 반영한 가능액을 계산합니다. 무료 기금은 출금 대상이 아닙니다.
  3. 승인 시 원금을 예약 차감하고 연결된 출금 작업으로 보냅니다. 수수료 뒤 원천세를 계산한 순지급액과 예약 원금을 구분합니다.
  4. 외부 지급 결과를 확인합니다. 신청·승인은 은행 입금이 아니며 현재 회원 신청을 오너 지갑 즉시 지급 선택지로 설명하지 않습니다.

기금 가용액에서 제외한 미납금을 다시 무조건 순지급액에서 상계한다고 쓰지 않습니다. 거절된 신청의 월 제한 예외와 다른 한도도 함께 적용합니다.

7. 개인 구독과 개최권

개인 구독 · 개설권 구매·사용·운영자 환불

7.1 개인 구독

현재 판매 플랜은 PREMIUM, 기본 설정은 30일 2,800P이며 실제 서버 플랜을 확인합니다. BASIC은 신규 판매 대상이 아닙니다. 지갑의 유료 우선·무료 부족분으로 새 이용 기간을 더하며 이 가입 경로가 자동충전을 호출하지는 않습니다.

자동갱신 해제는 남은 이용 기간을 즉시 없애거나 환불하는 동작이 아닙니다. SUSPENDED의 다시 시작은 현재 가격으로 새 결제·기간을 만듭니다. 가입·재활성화·배치 갱신은 공개·금전 기능을 검사하고, 기존 조회·해제와 다릅니다. 현재 API에는 개설권과 같은 영속 구매 키 계약이 없으므로 서버 기간 중복 검사와 최초 결과 재생을 구분합니다.

7.2 프라이빗 모임 개최권·호스팅 티켓

개설권은 현재 유료 포인트로 구매하며 수량·만료·원 구매 거래를 기록합니다. 티켓 사용과 모임 개설의 지갑 비용은 다른 경로입니다. 취소 때 수량 복원이 가능한지 원 사용·상태를 확인하고 운영자 환불은 원 단가·남은 유효 수량으로 판단합니다.

프라이빗 개설비의 재원·해당 기능 공개 여부도 별도 정책입니다. 등록부의 통화 허용만으로 앱에 무료 선택지가 열렸다고 쓰지 않습니다. 플랫폼 소비와 참가비의 호스트 수익 지급을 구분합니다.

8. 사용자 외부 출금

외부 지급의 대기·결과 불명·늦은 증빙을 따릅니다. 이 설명은 실제 공급자 설정·은행 입금을 검증한 기록이 아닙니다.

8.1 출금 신청

총 지갑과 출금 가능 권리를 나누고 계좌·예약·회수 의무·현재 허용 조건을 확인해 신청합니다. 무료 잔액을 출금 권리로 바꾸지 않습니다. 신청 기록이 생겼다는 사실은 차감·승인·송금 완료와 다릅니다.

8.2 출금 승인

승인은 해당 출금의 예약과 지급 작업으로 이어집니다. 원래 계좌·통화·금액과 현재 상태를 확인하며 기존 예약을 새 지급처럼 중복 만들지 않습니다. 사용자 안내는 지급 진행 단계이며 은행 수령 완료가 아닙니다.

8.3 지급 성공, 실패, 복구

관측후속 판단
지급 시작 전 작업 선점 만료대기로 돌리고 새 지급 호출 없이 다음 처리를 기다림
공급자 호출 뒤 시간 초과·통신 오류결과 불명·조회 대기. 같은 지급 키 또는 공급자 번호로 확인

지급 성공 증거현재 작업 소유권·허용된 상태 전이를 확인해 원장에 반영

탈퇴 뒤 지정된 반환·지급은 보류금과 원출금의 늦은 증빙을 함께 확인합니다. 공급자 호출·원장 반영·실제 은행 수령·알림 도착은 각각 다른 증거입니다.

9. 마일리지

마일리지 영역의 현재 권한·공개 경계·제한을 따릅니다. 지갑과 교환하거나 현금 환불·정산으로 연결하지 않습니다.

이전 마일리지 실행·출시 기록 원문

아래 기록은 이번에 재실행하거나 현재 배포 상태로 재확인한 결과가 아닙니다.

첫 출시 범위: 핵심 마일리지와 시즌·사진 심사 적립·반복 수동 적립 검토를 포함한다. 기능별 서버 검사와 앱 전체 검사를 통과했고, 시즌·반복 적립 판정·모임별 점수는 실제 앱과 서버에서도 확인했다. 사진 심사의 반려·재심·승인·취소는 로컬 앱에서 확인했다. 실제 사진 파일·운영 배포·휴대전화 검사는 남아 있다. 기존 공개 모임을 유지할 때만 누락된 확정 점수를 배포 전에 준비한다.

9.1 적립

클럽의 활성 상태·적립 규칙·당사자·실제 집행 권한을 확인해 원장과 잔액을 반영합니다. 호스트 제안과 운영진 승인·직접 집행은 다릅니다. 등급 재계산 예약과 전체 회원 반영 완료도 구분합니다. 사진·반복 적립 검토의 별도 공개·권한 조건을 그대로 적용합니다.

9.2 사용

권한 있는 보상 담당자가 회원·잔액·차감 사유와 요청 키를 확인해 만료가 빠른 적립부터 소비 관계를 만듭니다. 회원이 자신의 잔액을 조회하는 권한이 임의 사용 명령 권한을 뜻하지 않습니다. 차감은 지갑 결제 기록이 아닌 마일리지 원장에 남습니다.

9.3 회수와 만료

적립 정정은 이미 만료된 양을 제외해 회수하고 등급 누적은 원 적립액 기준으로 조정합니다. 사용 정정은 소비를 복원합니다. 만료는 남은 잔액을 소멸시키지만 등급 누적을 같은 방식으로 깎지 않습니다. 원장·잔액·등급의 결과를 구분하며 과거 회수 기록 자체를 새 적립처럼 다시 정정하지 않습니다.

10. 운영자 작업

운영자 조치의 권한·한도와 돈 관련 상태 정책을 함께 확인합니다.

10.1 정산 승인·완료

원 정산의 권한·상태·기지급 거래·환불 보류·미수금·보정을 확인합니다. PENDING·APPROVED·PAYING·PAID·FAILED·REJECTED는 호스트 수익 정산 상태이며 모임 비용 정산의 COMPLETED와 다릅니다. FAILED를 모두 자동 재지급 대상으로 안내하거나 PAID를 외부 은행 입금과 동일시하지 않습니다.

10.2 운영자 환불·보상

원거래 환불과 원거래 없는 무료 보상을 구분합니다. 무료 지급은 결제 운영 권한·필수 요청 키·대상·1~10,000,000P·필수 사유 최대 185자를 검사해 작업 예약 뒤 지갑 경로에 위임합니다. 보상 지급은 구매 권리나 상대방 수익을 취소하지 않으며 현금 반환을 대신하지 않습니다.

응답 유실 시 같은 작업과 실제 거래 결과를 확인합니다. 보장이 없는 다른 명령까지 동일 키 재생으로 일반화하지 않습니다. 원문 기본 보존 작업은 확인 완료·거절 종결 행의 해당 시각에서 90일 뒤, 계정 파기 때는 해당 종결 행을 기간과 무관하게 가립니다. 진행 중 원문·금전 원장 전체의 즉시 삭제가 아닙니다.

10.3 차지백

차지백 접수·검토·종결은 일반 구매 환불과 다른 운영 사건입니다. 현재 종결 명령은 LOST 또는 ACCEPTED 결과에서 차지백 손실 분개를 기록합니다. 사용자 지갑을 직접 환불하거나 카드사 처리를 실행하는 명령으로 설명하지 않습니다. 손실 전표와 실제 공급자 증거를 연결해 확인합니다.

10.4 원천징수세 납부

원천세 납부 기록은 예수금과 플랫폼 현금의 회계 분개입니다. 현재 서비스는 납부 잠금을 잡고 기존 키·요청 내용과 오늘까지 누적 예수금 잔여를 확인해 초과 기록을 거절합니다. 기록 성공이 실제 세금 납부·은행 송금·신고 완료를 자동 증명하지는 않습니다. 회원 지갑 지급과도 다릅니다.

12. CS 답변 기준 예시

아래 문구는 실제 거래·금액·상태를 확인한 뒤 상황에 맞춰 사용합니다.

12.1 “왜 환불금 일부가 무료 포인트로 들어왔나요?”

결제 때 사용한 무료 포인트의 반환 몫은 무료 포인트로 돌아옵니다. 이미 반환한 금액과 수수료·정책을 반영하므로 이번 반환의 유료·무료 금액을 거래 내역에서 함께 확인해 주세요. 무료 포인트는 현금으로 출금할 수 없습니다.

12.2 “이벤트 결제했는데 호스트에게 바로 입금되나요?”

지갑 참가비는 참석 확정과 호스트 수익 지급이 별도입니다. 은행으로 주최자에게 직접 보낸 경우에는 이미 받은 은행 돈과 플랫폼 지갑 정산을 구분해야 합니다. 결제수단과 현재 확인 상태부터 확인합니다.

12.3 “마켓 판매금이 왜 바로 안 들어오나요?”

회원 판매 수익은 월 지급의 대상 기간·상태와 환불·미수금 조건을 확인합니다. 판매액과 실제 지갑 적립액이 다를 수 있습니다. 플랫폼 소유 상품이나 다른 수익 원천은 같은 월 지급 대상이 아닐 수 있습니다.

12.4 “정산 후 환불이 승인되면 판매자는 어떻게 되나요?”

구매자 반환과 판매자 회수는 따로 처리합니다. 이미 지급된 유료 수익의 남은 회수액은 다음 지급 상계나 해당 원천의 회수 절차를 따릅니다. 환불 승인만으로 회수까지 완료됐다고 안내하지 않습니다.

12.5 “클럽 기금은 전부 인출할 수 있나요?”

무료 기금과 예약·환불 보호액·미납금을 제외한 유료 가능액에 신청 한도를 적용합니다. 표시된 총기금 전액을 바로 인출할 수 있는 것은 아닙니다.

12.6 “출금 신청했는데 왜 아직 입금이 안 됐나요?”

신청·승인·예약·지급 시작·공급자 결과 확인은 서로 다른 단계입니다. 응답이 지연됐으면 기존 출금의 결과와 은행 증빙부터 확인합니다. 결과를 모른 채 새 출금을 만들어 다시 보내지 않습니다.
