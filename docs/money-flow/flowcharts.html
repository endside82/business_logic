0. 읽는 법

이 문서는 내부 구현을 설명하는 문서가 아니다. 기획자가 정책, 화면 문구, 운영 매뉴얼, CS 답변을 만들 때 필요한 “상황별 흐름”과 “최종 상태”만 먼저 보여준다.

각 도식의 마지막 노드는 다음 다섯 가지 종착점으로 읽는다.

종착점 접두어 의미 기획·운영 해석
T-SUCCESS 정상 완료 사용자나 수취자가 기대한 상태로 끝난다. 추가 조치가 없다.
T-HOLD 대기·보류 돈이나 권리가 확정되지 않았다. 다음 액션 주체와 제한 시간을 명확히 안내해야 한다.
T-FAIL 실패·거절 거래가 끝났고 잔액 변화가 없거나 원복됐다. 재시도 가능 여부를 안내해야 한다.
T-OPS 운영 개입 필요 자동 흐름만으로 닫히지 않는다. 운영자 보상, 수동 확인, 재처리, 대사가 필요하다.
T-NO-MONEY 돈 이동 없음 상태만 바뀌거나 기능 이용권만 소모된다. 지갑·정산·출금에 영향이 없다.

1. 전체 경로 지도

제품의 금전 흐름은 크게 “유입, 소비, 정산, 환불, 반출, 보상·복구, 마일리지”로 나뉜다.

전체 지도 종착점

종착점 설명 후속 액션
T-SUCCESS 내부 종결 플랫폼 내부 지갑, 정산, 회계 상태가 닫힌다. 일반 화면에는 완료 상태만 노출한다.
T-SUCCESS 외부 지급 완료 실제 은행 지급 또는 외부 지급 큐까지 끝난다. 지급 내역과 완료일을 노출한다.
T-SUCCESS 원결제 기준 환불 완료 유료는 유료로, 무료는 무료로 복원된다. 사용자 환불 완료 알림과 내역을 노출한다.
T-HOLD 또는 T-OPS 환불 대기 자동 처리로 닫히지 않았다. 운영자 대시보드, CS 매뉴얼, SLA가 필요하다.
T-SUCCESS 마일리지 장부 내 종결 지갑 포인트와 분리된 클럽 마일리지 안에서만 끝난다. 포인트·정산 화면과 섞어 보여주지 않는다.

3.2 케이스별 결과

케이스 허용 통화 대표 사용처 돈의 종착점
유료 전용 소비 paid only 모임 선입금, 모임 정산, 외부출금, 정산 보정 paid lot만 차감된다. 부족하면 실패한다.
무료 전용 소비 free only 일부 프라이빗 호스팅 무료 코인 흐름 free lot만 차감된다. paid로 대체하지 않는다.
유료 우선 소비 paid first, then free 이벤트, 마켓, 플랜, 클럽 기부, 개인 구독 paid와 free가 함께 차감될 수 있다.
일반 지갑 환불 원결제 구성 유지 이벤트·마켓·클럽·구독 등 paid는 paid로, free는 free로 복원된다.
중복·초과 환불 불가 모든 지갑 환불 원결제 총액을 넘으면 실패한다.

3.3 종착점 상세

종착점 닫히는 상태 다음 액션 주체 기획 주의
T-SUCCESS 소비 완료 사용자의 지갑 차감과 도메인 처리 완료 없음 결제 완료 화면에 결제 수단별 구성까지 보여줄 수 있다.
T-SUCCESS 소비 원복 도메인 실패로 소비가 되돌아감 없음 사용자는 “결제 실패, 포인트 반환”으로 이해해야 한다.
T-FAIL 잔액 부족 소비 전 실패 사용자 자동충전 가능 상품인지에 따라 CTA가 달라진다.
T-FAIL 환불 거절 환불 요청 거절 사용자 또는 운영자 원결제 없음, 이미 환불 완료, 금액 초과를 구분한다.
T-HOLD 환불 완료 확인 대기 은행·PG·호스트 확인 필요 호스트 또는 운영자 “환불 요청 접수”와 “환불 완료”를 분리해 표시한다.
