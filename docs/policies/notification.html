알림 정책

알림은 도메인 이벤트의 “결과”를 사용자에게 전달하는 보조 흐름이다. 알림 기획 시 화면보다 먼저 정해야 할 것은 “누가, 언제, 왜 받아야 하는가”다.

알림의 이동 목적지와 실제 변경 결과를 맞춥니다

클럽 구독의 결제 실패·정지·만료 관련 알림은 해당 클럽의 구독 관리로 연결합니다. 가입비 환불 때문에 탈퇴가 막힌 안내에는 고객센터로 이어지는 동선을 제공합니다. 이전 계정의 알림 처리·응답을 현재 로그인 계정에 적용하지 않습니다.

정산 취소 자체와 지갑 반환 완료 알림을 구분합니다. 반환된 대상의 지갑·거래·정산 상태를 새로 읽으며, 송금 신고만으로 실제 반환 완료를 안내하지 않습니다. 정산 취소와 실제 지갑 반환 완료를 구분합니다를 따릅니다.

알림 기록·발송 수락·실제 수신을 구분합니다

아래 복구 설명은 영속 업무 알림과 채널 작업에 적용합니다. 주간 요약 메일의 대상과 발송 한계와 수신 동의 재확인의 시점과 실패 경계에 적은 별도 비동기 메일은 같은 재시도 보장을 갖지 않습니다.

업무가 저장될 때 알림 발송 의도를 함께 기록합니다. 서버 중단이나 실행기 인계 실패 뒤에도 저장된 작업을 찾아 재처리하고, 운영자는 채널·목적·시도 횟수·대기와 실패 사유를 조회합니다. 유효기간 안의 실패 작업만 현재 정책을 확인해 재시도합니다.

인앱 알림 생성, 공급자의 발송 수락, 휴대전화 표시와 메일 수신은 서로 다른 결과입니다. 공급자가 수락한 뒤 결과 저장에 실패하면 같은 알림이 다시 발송될 수 있습니다. 앱은 계정과 알림 번호로 전경 배너 중복을 억제하지만 모든 기기에 정확히 한 번 표시된다고 보장하지 않습니다.

무음 시간·수신 설정·차단·탈퇴·활성 기기를 발송 직전에 다시 확인합니다. 무음 시간에 건너뛴 푸시는 나중에 몰아서 보내지 않습니다. 설정 누락은 성공으로 기록하지 않고 보류 사유를 남깁니다.

2026년 10월 29일부터 가입·비밀번호 재설정·Google 계정 연결 번호는 요청 중 메일로 보낸다. 발송 실패 시 발송 횟수를 되돌리고 재시도 안내를 한다. 예전 인증 링크용 요청·아웃박스 목적·서명 키는 제거됐다. 업무 알림의 저장·재처리 계약과 번호 메일을 구분한다.

아래는 기존 문서에 남아 있는 2026년 10월의 실행 이력이며 이번에 재실행한 결과가 아닙니다. 10월 4~5일 기본 브랜치 반영과 자동 검사 기록이 있습니다. 10월 12일에는 SMTP 시험 메일의 Gmail 수신, 자체 도메인 시험 수신함의 인증·복구 메일과 Android 앱 링크 처리를 확인했습니다. Firebase 서버·Android 시험 앱도 연결했으며 수신·이동의 최신 범위는 Firebase·APNs 푸시 연결을 따릅니다. 실기기·iOS·운영 복구, OCI 반송·신고 이벤트는 남아 있습니다. 메일 발송 계약·도메인 인증·실수신에서 수신함과 실패 검증 범위를 확인합니다.

본인확인·스탬프·마일리지 결과 알림

  • 본인확인 검토: 수동 승인·취소 결과를 알림과 본인확인 화면 재진입으로 확인한다. 떠 있는 화면의 결정 푸시 자동 갱신은 제공 범위가 아니며, 실제 기기 수신·복귀는 출시 전 확인 대상이다.
  • 스탬프: 클럽 활동 알림 설정과 카드 화면 이동이 연결됐다. 기능이 닫혀 있을 때의 진입 차단, 도장판 정보가 없는 알림, 앱 백그라운드·종료 상태 복귀를 서명 앱에서 확인해야 한다.
  • 마일리지: 반복 적립 판정의 점수 정정·검토 종결·감사·알림은 함께 기록한다. 기존 검증 기록은 동일 요청 재시도로 점수와 결과 알림이 중복 생성되지 않는 범위를 다룬다. 이번 문서 갱신에서 새로 실행한 결과는 아니다. 기존 실행 기록에는 사진 심사의 반려·재심·승인·취소를 로컬 앱에서 확인했다고 남아 있으며 실제 사진 파일·실기기 수신·알림 이동은 남아 있다.

알림 경로 구현이나 자동 테스트 통과를 실제 푸시 수신 증거로 확대하지 않는다. 현재 검증 수준은 첫 출시 현황을 따른다.

참가자 알림과 운영 알림을 구분한다. 참가자 알림을 꺼도 주최자의 후보 선택 요청까지 함께 꺼지지는 않는다. 투표 기능을 비활성화한 상태에서는 알림을 눌러도 제한된 투표 화면으로 들어가지 않아야 한다.

구현은 게시글·모임 투표에 반영했다. 실제 휴대전화 수신·앱 종료 후 복귀는 공개 전 검사 대상이다.

알림 트리거 유형

아래는 제품 검토에 사용할 트리거 예시다. 각 예시의 실제 발송 연결과 수신을 모두 확인했다는 뜻은 아니다. 데이터 내보내기는 현재 PRD의 요청·상태 조회 흐름이 확인 범위이며, 완료 알림의 실제 전달은 별도 근거가 필요하다.

앱의 카테고리 스위치는 새 푸시와 알림함 기록을 함께 바꿉니다. 방해금지는 일반 푸시를 건너뛰며, 이미 생성된 알림함 기록을 취소하지 않습니다. 항상 전달하는 종류·시간 예외·광고 동의·차단 관계·현재 수신자 조건을 구분합니다.

공급자 수락은 실제 기기 수신과 다릅니다. 실패한 작업은 대기·만료·시도 한도에 따라 재시도하고, 현재 처리 소유권을 확인한 결과만 종결합니다. 관리자 재시도는 유효한 실패 작업에 처리자와 사유를 남깁니다.

선입금·이동 조율·분쟁의 목적지

참가자의 결제 화면, 운영자의 입금 확인 큐, 정기모임 처리 화면을 구분합니다. 현재 이동 조율 알림은 통합 이동수단 화면으로 연결합니다. 옛 카풀·버스 알림 번호를 현재 생산 계약으로 사용하지 않습니다.

일정 변경 제안은 응답 화면, 적용된 변경은 모임 상세로 안내합니다. 환불·분쟁·안전 체크인도 해당 업무의 현재 목적지를 따릅니다. 필요한 식별자가 없으면 안내하고, 공개 범위·접근 권한을 다시 확인합니다.

수신자와 발생 시점은 해당 기능 명세·실제 생산 소스를 따릅니다. 이 페이지의 과거 번호별 배선 표를 최신 enum이나 미구현 목록으로 읽지 않습니다.

광고 수신 동의와 처리 결과

2026-11-22 코드 기준으로 광고 동의를 요구하는 알림 종류는 PROMOTION이다. 앱의 광고성 정보 수신과 추천 알림은 다른 스위치다. 추천 알림은 저장한 검색의 새 결과와 관심 있는 사람의 새 모임을 묶으며, 현재 코드에서는 광고 동의 대상으로 분류하지 않는다. 이는 구현의 분류이며 모든 콘텐츠의 법적 성격을 일괄 판정한 결과가 아니다.

광고 스위치는 푸시와 알림함 설정을 함께 보낸다. 서버는 두 채널이 모두 켜졌을 때 동의로 반영하며, 이메일만 수정하는 요청은 동의 자체를 바꾸지 않는다. 설정에서 동의 값이 실제로 달라지면 SETTINGS 이력을 추가한다. 이미 같은 동의 상태를 다시 저장하는 것은 새 동의 이력·결과 통지를 만드는 명령이 아니다. 동의하지 않은 광고 종류는 조회 시 모든 채널을 꺼짐으로 반환한다.

가입·재동의·설정 변경·메일 수신 거부에서 광고 동의 이력이 생길 때 같은 트랜잭션으로 MARKETING_CONSENT_RESULT 발송 의도를 기록한다. 이력 번호를 중복 방지 키로 쓰고, 동의·최초 거부·기존 동의 철회를 구분해 전송자 이름·날짜·처리 결과를 만든다. 재동의 요청에서 광고 항목을 생략하면 광고 동의 이력을 추가하지 않는다. 결과 알림은 일반 채널 끄기와 구분되는 항상 전달 종류지만, 현재 수신자 자격·단말 권한·발송 처리까지 모두 우회하는 것은 아니다. 즉시 의도 저장은 즉시 실수신이나 통지 기한 준수의 증거가 아니다.

주간 요약 메일의 대상과 발송 한계

주간 요약은 월요일 오전 9시의 서버 기본 시간대 스케줄이다. 한국 시간으로 고정된 방해금지 계산과 혼동하지 않는다. 최근 일주일에 알림이 생성된 회원 번호를 500명씩 조회하며, 한 번에 최대 5,000명 또는 10분 예산으로 제한한다. 한도를 넘긴 나머지를 같은 주에 이어 보내는 저장 커서는 없다. 제목은 주간 요약이지만 본문의 참석 수는 countAttendingEvents 결과, 미읽음 수는 현재 알림 서비스 결과다. 이 수치 모두를 일주일 동안의 새 활동 수로 해석하지 않는다.

선별 시점과 비동기 메일 작업이 시작될 때 광고 동의 및 PROMOTION 이메일 설정을 확인한다. 설정 행이 없으면 이메일은 허용으로 보지만 동의는 반드시 필요하다. 주소가 없으면 보내지 않는다. 두 번째 확인 이후 실제 전송까지 발생하는 철회를 원자적으로 차단한다고 보장하지 않는다.

제목 앞에 (광고)를 붙이고 본문에는 전송자 이름·주소·전화·이메일과 한글·영문 수신 거부 안내를 넣는다. 발송자 설정은 빈 문자열을 거절하지만 개발용 기본값도 있으므로 설정 검증 통과를 운영 발송자 정보 확정으로 쓰지 않는다.

이 메일 경로는 일반 업무 알림의 영속 채널 작업과 다르다. 비동기 실행기 거절은 집계·로그를 남기며 자동 재처리를 예약하지 않는다. 메일 전송기는 수신 억제 주소를 건너뛰고, 공급자 전송 호출의 성공·실패 기록을 남긴다. 스케줄러의 제출 수는 실제 전송 성공 수가 아니며, SENT도 받은편지함 도착을 증명하지 않는다. 현재 이 경로에 영속 발송 큐의 재시도 보장이 있다고 설명하지 않는다.

로그인 없는 메일 수신 거부

메일의 수신 거부 주소는 GET /api/v1/marketing/unsubscribe?t=...에서 확인 화면을 보여 주고 같은 주소의 POST에서 처리한다. 두 요청은 로그인 없이 허용된다. GET만으로 동의를 철회하지 않는다. 메일에는 List-Unsubscribe와 한 번 누르기 헤더를 넣으며 해당 주소의 POST를 사용한다. 메일 프로그램에서 실제 단추가 노출되고 정상 작동하는지는 별도 실행 확인이다.

서버는 회원 번호와 용도가 결합된 HMAC 서명을 검증한다. 토큰 자체의 만료 시각은 없으며 서명에 사용하는 비밀 변경의 영향을 받는다. 잘못된 토큰은 400, 실제 동의 철회와 이미 거부 상태는 서로 다른 안내의 200이다. 실제 철회에만 동의 값·변경 시각·EMAIL_UNSUBSCRIBE 이력·결과 통지를 함께 기록한다. 반복 요청으로 이력을 계속 늘리지 않는다. 이 주소는 광고 전체의 수신 동의를 철회하며 주간 메일 한 종류의 설정만 끄는 주소가 아니다.

수신 동의 재확인의 시점과 실패 경계

매일 오전 10시 서버 기본 시간대 작업이 최신 광고 동의 이력이 동의이고 현재 동의 값도 켜진 회원을 대상으로 삼는다. 동의일의 매 2년 해당일을 기준으로 30일 전부터 30일 후까지를 처리 창으로 계산한다. 매 주기마다 이력 번호와 회차로 중복을 막는다. 기록 직전에 동의를 잠그고 최신 이력이 그대로인지 다시 확인한다. 동의 값만 있고 이력이 없는 회원은 날짜를 입증할 수 없어 건너뛰며 경고 수를 남긴다.

MARKETING_CONSENT_RECHECK는 일반 설정으로 끄는 알림과 구분되며, 전송자·동의일·동의 유지와 철회 방법을 안내한다. 의도를 저장한 뒤 주소가 있으면 별도의 비동기 메일도 요청한다. 유지에는 새 동의 요청이 필요 없고 철회는 앱 설정 또는 수신 거부 주소에서 한다.

의도 저장 뒤 메일 제출·전송이 실패해도 다음 스케줄은 이미 기록된 회차로 판단해 메일을 다시 요청하지 않는다. 알림 의도와 메일을 하나의 영속 전달 작업으로 취급하지 않는다. 처리 창 전체가 지나면 해당 회차를 일반 스케줄에서 보충한다는 보장도 없다. 따라서 ‘모든 회원에게 2주년 전에 전달 완료’라는 과거 설명을 현재 동작으로 사용하지 않는다.

법령 대조 범위와 기존 출시 결정

국가법령정보센터의 정보통신망법 시행령 수신동의 관련 조문 검색 본문에서 제62조의2의 처리 결과 14일 이내 통지와 제62조의3의 매 2년 해당일 전 확인 기준을 확인했다. 조문 페이지의 전체 본문은 이번 열람에서 표시되지 않았다. 코드의 해당일 이후 30일 처리 창은 이 법정 기한을 연장하는 근거가 아니다. 실제 기한 내 전달·누락 복구를 확인하기 전에는 준수 완료로 표시하지 않는다.

시행령 별표 6의 광고 표시와 수신 거부 방법은 원문을 확인했다. 전자우편 제목의 광고 표시, 발송자 식별 정보, 한글·영문 안내와 간편한 거부 수단을 메일 구성 코드와 대조했다. 실제 운영 정보·메일 클라이언트·수신함 검증이나 법령 전체 검토를 완료했다는 뜻은 아니다.

기존 문서의 결정 Q10은 출시 전 광고 푸시·인앱 방송 입구를 열지 않고, 광고 푸시를 열 때 야간 전송 제한과 광고 표기를 함께 갖추는 계획이다. 이 계획을 서버의 광고 판정 기능이 없다는 설명으로 바꾸지 않는다. Q11의 주간 광고 메일·재확인, Q12의 처리 결과 통지, Q13의 동의·추천 스위치 분리는 위 현재 구현과 각각 대조했다. 실제 공개 여부와 운영 준비는 첫 출시 현황을 따른다.

이번 광고 정책 대조의 근거

동의 기록은 PolicyConsentService와 NotificationSettingService, 재확인은 MarketingConsentRecheckService·스케줄러·후보 조회, 요약은 WeeklyDigestScheduler·수신자 조회·메일 발송기, 수신 거부는 MarketingUnsubscribeController·MarketingUnsubscribeLink, 메일 구성·결과는 AdvertisingMailFormat·EmailMessageComposer·EmailDispatcher를 읽었다. 앱의 두 스위치와 일괄 변경 요청도 대조했다. 상세 소스 범위와 해시는 전체 문서 최신화 기록의 알림 광고 정책 근거에 기록한다. 제품 코드 수정·메일 발송·브라우저·기기 시험은 실행하지 않았다.

수용 기준

  • 알림 한 줄을 읽고 사용자가 곧장 어떤 화면으로 가야 할지, 거기서 무엇을 누를지 알 수 있게 쓴다. “정산이 도착했어요”만 보이면 부족하다.
  • 알림을 눌렀는데 대상이 이미 삭제·만료·차단 상태라면 빈 화면 대신 “이 모임은 끝났어요” 같은 안내 화면을 띄운다.
  • 휴대폰 푸시 권한을 끈 사용자에게도 앱 안 알림함은 그대로 쌓여야 한다. 푸시 끔 = 모든 알림 끔이 아니다.
