권한 · 역할 매트릭스

“기능을 빠뜨리지 않는 것”만큼 중요한 게 “누가 할 수 있는가”다. 같은 화면이라도 비로그인·일반 사용자·참가자·호스트·클럽 관리자·크리에이터에게 보이는 버튼과 허용 액션이 다르다. 이 페이지는 그 차이를 통일된 표로 정리한다.

운영자 처리 사실과 회원 정보를 구분합니다

경고·마일리지·출금·정산·문의의 운영자 번호는 일반 회원 번호와 별도 필드로 기록합니다. 회원 화면은 “운영자”·“시스템”을 구분하고 운영자 번호를 다른 회원 프로필로 연결하지 않습니다. 회원 응답에서 내부 관리자 번호와 응대자 사이 인계 사유를 제외합니다.

관리자 조회의 대상 회원은 명시된 대상 회원 필드로 선택합니다. 돈 처리·신고·문의의 원천 사건은 실제 종류·번호·당사자로 확인하며 이동수단 원천을 다른 사건으로 잘못 분류하지 않습니다. 운영자 판정과 호스트 답변을 구분합니다와 운영 문의의 원천 기록을 바르게 연결합니다를 함께 따릅니다.

관리자 로그인과 민감 작업의 재인증

관리자 로그인은 비밀번호 확인 뒤 인증 앱의 2단계 확인을 거칩니다. 처음에는 인증 앱을 등록하고, 복구 코드는 한 번만 사용할 수 있습니다. 비밀번호만 맞은 대기 상태는 관리 화면 권한이 없으며 5분 뒤 만료됩니다. 비밀번호가 변경되면 이전 로그인 대기를 계속 사용할 수 없습니다.

돈 정정·권한 변경·개인정보 내보내기는 현재 세션에서 5분 이내의 재인증을 요구합니다. 단순 조회·메모·금전 이동이 없는 상태 변경까지 전부 같은 범위로 묶지는 않습니다. 이미 쓴 인증 코드를 다시 사용해 재인증 시간을 늘릴 수 없습니다.

관리자 세션은 브라우저 스크립트가 읽지 못하는 쿠키로 전달하고, 관리자 웹과 같은 출처에서 요청하며 상태 변경의 CSRF를 검사합니다. 운영 설정은 보안 쿠키를 사용합니다. 다른 창의 변경 때문에 생긴 충돌은 로그인 만료와 구분하고 입력·처리 사유를 보존한 뒤 최신 값을 다시 확인합니다.

구현 반영과 실제 관리자 두 창 검사는 다릅니다. H-531의 두 창 손 검사와 배포 환경 리허설이 남아 있습니다.

미해결 돈과 회차 책임을 남긴 채 주최자를 바꾸지 않습니다

정기모임 호스트 이전은 현재 코스 호스트가 맡은 회차 중 이전 가능한 회차만 넘깁니다. 활성 결제, 호스트 수익 정산, 선입금, 취소되지 않은 모임 정산, 끝나지 않은 제공자 배정, 계좌이체 결제 대기 신청, 새 호스트의 연결 가능한 기본 계좌 부재를 검사합니다.

넘길 수 없는 회차는 이전 호스트에게 남고 그 사실을 알립니다. 새 코스 호스트의 일괄 명령이 남겨진 회차까지 바꾸지 않도록 거절하거나 건너뜁니다. 넘어가는 계좌이체 회차는 새 호스트의 계좌에 다시 연결합니다. 남겨진 회차의 종료 처리는 기존 책임자 기준으로 이어집니다.

클럽 소유권 이전은 진행 중 출금, 미정산, 같은 통화 기금으로 상계하고도 남는 미수금을 확인합니다. 제공자 환불 회수금도 현재 호스트가 아니라 원래 해당 몫을 낸 사람에게 귀속시킵니다.

화면의 동작과 서버의 권한 판정을 맞춥니다

모임 신청·취소·출석·관리, 클럽 가입·운영·소유권 이전, 정산·계좌, 경고·마일리지, 플랜·마켓·데이트의 변경 동작은 서버가 현재 사용자에게 내려준 허용 여부를 따릅니다. 화면에 표시할 수 있다는 사실만으로 실행을 허용하지 않으며 서버 입구에서 같은 조건을 다시 검사합니다.

허용 정보가 없거나 갱신 중이면 변경 버튼을 열지 않습니다. 복귀·권한 거절 뒤에는 현재 상세와 허용 동작을 다시 읽습니다. 프리미엄 개인정보 옵션과 캘린더 자동 전송도 서버가 제공하는 권한에 따라 켜며 앱의 구독 표시만 믿고 실행하지 않습니다.

다른 모임의 하위 기록 번호를 끼워 넣거나 관계없는 분쟁 대상을 연결하는 요청은 거절합니다. 운영자 식별자와 내부 인계 사유는 일반 회원 응답에 섞지 않습니다.

클럽 운영과 플랫폼 검토의 경계

행동허용 대상추가 제한
스탬프 만들기·공동 운영현재 클럽장·운영진클럽장이 만들기를 허용해야 새 판을 만든다. 발행자 잠금은 클럽장에게도 적용되며 자격을 잃은 발행자는 이관으로 복구한다.
시즌 준비·마감 재시도클럽 정책 담당자현재 권한을 확인하고 재시도 이력을 남긴다.
반복 수동 적립 판정마일리지 검토 담당자부정 판정으로 점수를 회수할 때는 점수 집행 권한도 필요하다. 일반 대기열의 처리 버튼으로 대신 승인하지 않는다.
이벤트별 적립 점수 설정해당 이벤트 호스트공개 전 클럽 상한 안에서만 수정한다. 클럽 정책 담당자가 상한을 관리한다.
본인확인 증빙 열람·수동 승인·취소권한 있는 플랫폼 관리자클럽 운영 권한으로는 처리하지 못한다. 현재 제출물·파일 검사·자격·만료일과 사유를 확인한다.

이 표는 기능이 활성화됐을 때의 권한이다. 구현 완료 여부만으로 닫힌 기능의 사용을 허용하지 않으며, 현재 공개 범위는 첫 출시 현황을 따른다.

역할 제한이 적용되는 권한

클럽에서 역할 제한 제재를 내리면, 유효 기간 동안 운영진 관리 권한과 그 클럽 모임의 공동주최자 위임 권한이 정지된다. 회원 관리·게시글 관리·경고 검토·마일리지 운영·스탬프 운영 등은 저장된 역할 이름만 보고 허용하지 않는다.

  • 유지되는 것: 일반 회원 자격과 기본 회원 활동은 유지한다. 역할 제한 자체가 참가 신청 제한이나 강제 탈퇴를 뜻하지 않는다.
  • 예외: 클럽 소유자는 이 역할 제한으로 소유자 권한을 잃지 않는다. 본인이 직접 주최한 모임의 주최 권한도 공동주최자 위임과는 다르므로 유지한다.
  • 해제 후: 역할·위임 기록은 지우지 않는다. 제재 만료·철회 뒤 현재 자격이 유효하면 다음 권한 확인부터 다시 사용할 수 있다.
  • 새 위임: 제한 중인 회원을 운영진으로 승격하거나 해당 클럽 모임의 공동주최자로 새로 위임하는 요청도 거절한다.

집행 절차는 제재 집행, 투표 관리의 역할별 범위는 투표 종류별 작성·관리·참여 권한에서 확인한다.

정산 이의제기·열람 조건 (2026-06-05)

정산 이의제기는 정산이 신청(활성화)된 이후부터만 가능하다 — 준비 중 정산에는 시스템이 이의 접수를 거부하고 앱도 버튼을 숨긴다. 호스트 본인 분담에 대한 이의는 상태와 무관하게 불가. 모임 정산 열람 자격은 참석 확정자 + 해당 정산에 분담금·송금이 걸린 사람 + 호스트다 — 참석을 취소했어도 내 돈이 걸려 있으면 본인 정산을 볼 수 있다. 준비 중 정산은 참가자에게 총액·상태·내 분담금만 보이는 미리보기 수위로 차등 노출된다.

권한 검토 체크리스트

  • 비로그인 사용자가 이 화면을 볼 수 있는가
  • 로그인했지만 관계 없는 사용자가 할 수 있는 액션은 무엇인가
  • 소유자·작성자·호스트 본인이 대상일 때 금지해야 할 액션이 있는가
  • 관리자급 권한과 소유자 권한을 구분했는가
  • 차단·탈퇴·삭제·비활성 사용자 상태를 고려했는가
  • 한 사용자가 여러 역할을 동시에 가질 때 우선순위가 있는가
  • 화면 진입 후 권한이 바뀌면 어떻게 갱신하는가
  • 권한 없음은 버튼 숨김·비활성·에러 중 무엇으로 표현하는가

수용 기준

  • 주요 액션마다 비로그인·로그인·관계자·소유자/관리자가 각각 어떤 결과를 보는지 적는다 — “이 사람은 이걸 못 한다”까지 포함해서.
  • 권한이 없을 때 화면이 어떻게 보일지(버튼 숨김·비활성·로그인 유도·접근 불가 안내) 한 가지로 정하고 다른 화면에서도 같은 방식을 쓴다.
  • 한 사람이 호스트이면서 참가자, 클럽 관리자이면서 일반 멤버 같은 상황에서 어느 역할이 우선인지 미리 정한다.
