2026-09-12 소스 재실측 — 발견·데이팅·본인 데이터

hideFromStrangers의 직접 프로필 열람과 hideFromSearch의 발견 표면 제외는 별도 정책이다. 사람 후보는 증거등급 공동참석·현재 상태·양방향 비차단을 요구하고 받은 다시 만나기 선택을 추천에 쓰지 않는다.

관심사 태그·신뢰점수의 데이팅 유입은 양쪽 명시 옵트인일 때만 허용하며, 종교는 별도 동의가 필요하다. Export는 본인 trait·취향·분위기 태그·작성 피드백을 모두 포함하며, 삭제는 개인 데이터를 지우되 거래·active legal hold 증거를 보존한다.

2026-09-06 추가 — 검토 증빙과 운영 기록의 보존 경계

  • 본인확인 증빙: 본인이 올린 비공개 신분 증빙만 검토에 사용한다. 악성코드 검사를 통과한 실제 제출물을 권한 있는 플랫폼 관리자가 열람하고 승인한다. 제출물이 바뀌면 이전 열람 확인으로 승인하지 못한다.
  • 데이트 차단·안전신고 증빙: 본인확인 증빙과는 별개다. 데이트 상대를 차단하거나 안전 신고를 접수할 때 첨부한 증빙은 사건 처리가 끝난 뒤 1년간 보존한 뒤 파기한다.
  • 회원의 통제: 제출 철회가 가능하며 승인된 증빙을 철회하면 그 증빙에 따른 자격도 종료될 수 있음을 안내한다. 보존 기간은 서버가 알려 준 값으로 표시한다. 승인에 사용한 파일은 자격이 끝난 때부터 보존 기간을 센다. 계정 파기와 보존이 필요한 증거의 처리는 별도 파기 절차를 따른다.
  • 관리자 돈 조치: 중복 집행을 막는 작업 식별 근거는 보존하되, 종결 확인 뒤 보존 기간이 지난 원문 사유·조사 메모는 가린다. 현재 기본 기간은 90일이며 대상 회원 탈퇴 처리 때는 기간과 무관하게 가린다.
  • 스탬프: 클럽을 떠난 회원의 카드·이력은 정정 근거로 남는다. 계정 파기 때 개인 메모를 지우며, 뒤의 보상 표시 변경으로 지운 메모를 되살리지 않는다.
  • 마일리지 사진 심사 자료: 심사에 쓰는 사진 자체는 별도 규정 없이 클럽 사진첩 정책을 따르고, 사진이 지워져도 심사 기록은 독립적으로 남는다. 아직 공개 범위 밖인 기능이라 출시 전에 보존 규정을 정리해야 한다.

기능별 상세는 본인확인 검토·승인·취소와 클럽 스탬프, 검증과 운영 출시의 구분은 첫 출시 현황을 따른다.

설계 시 4가지 질문

민감 기능을 추가·수정할 때 매번 묻는다.

  1. 동의가 명확한가 — “설정에 들어가서 켰다”가 아니라 사용자가 결과를 알고 동의했는가.
  2. 끄는 방법이 명확한가 — 끄는 경로가 1탭 거리에 있는가.
  3. 지금 켜져 있다는 사실이 보이는가 — 현재 상태가 본인 화면에서 보이는가.
  4. 실수로 켜졌을 때 되돌릴 수 있는가 — 신고·차단·삭제의 잘못 누름을 복구할 동선이 있는가.

수용 기준

  • 민감 기능을 켤 때만 화면을 만들지 말고, 끌 때 어디로 가야 하는지도 같은 자리에 둔다. 켜기와 끄기가 한 화면에서 모두 보여야 한다.
  • 한 화면에 “남에게 보이는 정보”와 “나만 보는 정보”가 섞이지 않게 영역을 나눠 표시한다.
  • 삭제·차단·신고·위치 공유 중지는 버튼을 누른 그 순간에 화면이 즉시 바뀌어야 한다. “처리 중”은 허용하지 않는다.
