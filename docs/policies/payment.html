결제 · 정산 정책

포인트 충전, 결제, 환불, 호스트 정산금, 모임 정산, 클럽 기금을 서로 구분해 사용자·운영자가 돈의 상태를 오해하지 않게 한다. 한 줄로 요약하면 “돈의 흐름을 절대 섞지 말 것”.

탈퇴 뒤 도착한 돈은 운영 보류로 처리합니다

즉시 탈퇴는 잔액을 보존하고 사용을 막으며, 유예 만료 파기에서 유료 환급 예약·무료 소멸을 처리합니다. 탈퇴 뒤 지정된 반환·지급은 지갑 대신 보류금에 기록합니다. 재지급 예약과 외부 지급 증빙 종결은 실제 송금과 구분합니다. 원출금의 늦은 증빙이 미검토이면 재지급·외부 종결을 막고 거래별 지급 여부를 먼저 판정합니다. 중복 지급·손실 처리 전체를 탈퇴 성공으로 완료 처리하지 않습니다. 계정 탈퇴의 현재 돈 처리를 따릅니다.

무료 포인트는 지급 단위별로 만료됩니다

현재 무료 지급은 1년 만료일을 가진 지급 단위로 기록합니다. 해당 단위에 남은 무료와 지갑 무료 잔액 중 작은 금액을 정리하며 이미 쓴 몫·유료 잔액·원 지급 거래의 완료 이력을 무료 만료로 지우지 않습니다. 무료를 허용하는 소비는 잔액 판정 전에 만료 대상을 정리합니다. 환불한 무료의 원래 기한이 복원일부터 30일보다 짧으면 해당 반환분만 30일짜리 단위로 분리하고 원본 전체의 기한은 늘리지 않습니다. 더 긴 기한은 유지합니다. 이는 소스 계약이며 실제 운영 만료 작업 통과 기록이 아닙니다.

외부 지급의 시작 전 대기와 결과 불명을 구분합니다

지급을 시작하기 전에 작업 선점 시간이 끝난 출금은 지급 실패로 확정하지 않고 대기로 돌려 다시 처리합니다. 결제사 호출 뒤 결과가 불명확한 건은 거래 증거를 확인하며, 오래된 실행의 응답으로 최신 처리 결과를 덮지 않습니다. 자동 충전·취소·가상계좌·지급대행을 기다리는 동안 회원·지갑 잠금과 DB 연결을 계속 잡지 않도록 보완했습니다.

탈퇴한 회원의 지갑에 운영자의 “결제사대로 정산”으로 돈을 다시 적립하지 않습니다. 해당 거절에서는 미해결 상태를 근거 없이 종결하지 않고 별도 회수·환불 경로로 확인합니다. 외부 공급자와의 실거래 검증은 후속 출시 조건으로 남습니다.

주최자 환불 회수금을 확인하고 상환합니다

모임 환불 때문에 주최자에게 남은 회수금을 지갑에서 조회하고 유료 포인트로 상환할 수 있습니다. 창작자 판매 환불 회수금과 별도 항목입니다. 확인한 금액과 실제 금액이 달라졌다면 새 금액을 다시 확인한 뒤 처리합니다.

탈퇴 전에 남은 회수금을 정리해야 합니다. 상환 중 응답 유실은 같은 작업으로 확인하며 중복 차감하지 않습니다. 신규 상환은 서버의 금전 기능 허용을 별도로 요구합니다. 환불·회수라는 이름만으로 제한 예외가 되는 것은 아닙니다.

정산의 지출·수입과 취소 후 미확인 송금을 구분합니다

항목보내는 사람받는 사람
지출몫을 부담하는 참가자먼저 결제한 보유자
수입수입 보유자몫을 받는 참가자
보유자 자신의 몫자기 자신에게 송금하지 않음

항목별 납부 모드는 분담금으로 처리하며 계산용 송금 행을 만들지 않습니다. 직접 송금 모드는 실제 주고받을 차액을 송금으로 관리합니다. 지출·수입·보낸 돈·받은 돈을 하나의 총 납부액으로 합치지 않으며, 인당 지출 평균도 수입을 더해서 계산하지 않습니다.

“보냈어요”만 있고 받는 쪽 확인이 없는 상태에서 정산을 취소해도 은행 송금 사실이 사라지지는 않습니다. 항목별 분담금은 반환이 필요한 상태를 남기고, 송금자는 잘못 신고했다면 신고를 철회할 수 있습니다. 직접 송금의 취소 후 미확인 건도 확인 필요로 남깁니다. 이미 보냈다고 신고한 송금을 단순 경과 일수만으로 자동 만료시키지 않습니다.

송금 신고와 실제 수령 확인은 다릅니다. 취소·반환·신고 철회 뒤 관련 상세와 지갑을 다시 확인합니다. 플랫폼이 실제 은행 송금을 자동 검증했다는 의미는 아닙니다.

응답이 끊겨도 같은 돈 처리를 중복 실행하지 않습니다

구매·출금, 모임 정산의 납부·선입금, 환불·취소 등 보완된 경로는 완료 결과를 보존하고 같은 작업의 재시도에 재사용합니다. 보관 방식은 명령별로 다릅니다. 상품·번들 구매 등의 영속 보관과 은행 확인 명령의 같은 세션 메모리 보관을 구분합니다. 직접 플랜 구매·은행 입금 신고·클럽 기금 출금에 같은 영수증 재생 보장을 붙이지 않습니다. 다시 가입하거나 새로 계약한 건은 이전 건과 구분합니다.

응답을 받지 못했다는 사실만으로 실패나 미차감을 확정하지 않습니다. 이미 처리됐지만 결과를 재현할 수 없다는 응답에서는 목록·잔액·상세를 다시 읽어 확인합니다. 서로 다른 실제 거래를 같은 요청으로 합치거나, 결과 불명인 요청을 새 거래로 다시 보내지 않습니다.

모든 쓰기 경로의 보완이 끝났다는 뜻은 아닙니다. 남은 요청 처리·돈 처리 구조 작업은 현재 작업표의 H-515·H-505 등으로 관리합니다. 실제 PG·은행 왕복과 출시 후보 검증은 별도입니다.

환불·회수·보정의 한도와 반환 대상을 맞춥니다

정산의 환불 회수와 운영자 회수 보정은 같은 남은 회수 한도를 사용합니다. 진행 중 보정의 예약도 한도에서 차감하며, 이미 돈이 움직인 작업을 실패로 표시해 한도를 다시 열지 않습니다. 추가 입금은 이미 집행했거나 대기·집행 중으로 예약한 추가 입금 합계에 새 금액을 더해 정산 총액을 넘으면 거절합니다. 최초 지급액까지 합산한 총 지급액 상한과는 구분합니다.

은행 이체와 포인트를 섞은 분담금의 손실 정리에서는 남은 포인트를 즉시 반환하고 은행분만 면제합니다. 뒤늦은 은행 확인이나 정산 취소에서 이미 반환한 포인트를 다시 납부액에 넣거나 재반환하지 않습니다.

늦게 실행한 모임 정산은 모임 종료일의 요율을 씁니다. 정기모임은 계획 종료일과 실제 종료·취소일 중 이른 날을 기준으로 합니다. 운영자의 새 요율은 다음 날 이후부터 적용하며 이미 적용된 이력을 소급해 바꾸지 않습니다.

계좌이체 취소에서 돌려받을 금액을 먼저 확인합니다 · 운영자가 남은 개최권을 환불합니다 · 구독 환불은 실제로 낸 곳으로 돌아갑니다

정산 일관성 보완과 자동 검증·기본 브랜치 반영은 완료했습니다. 실제 PG·은행·배포 데이터·서명 앱 확인과 진행 중인 다른 돈 처리 보완은 별도입니다.

참가비, 모임 비용 정산, 플랫폼의 수익 지급은 서로 다른 상태 모델을 쓴다. 모든 돈을 주최자 한 사람에게 보내는 구조가 아니며, 수익 화면의 합계가 출금 가능액도 아니다. 결제·지갑 영역과 모임 정산 영역을 함께 읽는다.

공개 범위와 기존 돈 의무

소스의 결제 경로 존재, 서버 금전 기능 허용, 앱의 공개 범위, 공급자 준비, 운영 공개 승인은 각각 확인한다. 문서의 기본 설정이나 과거 출시 날짜만으로 현재 운영 환경에서 특정 수단이 열린다고 단정하지 않는다.

현재 공통 지갑 차감에서 금전 기능이 닫히면 일반 신규 소비는 거절한다. 예외 목록의 기부·가입비·클럽 미납금 상환·클럽 구독 지갑분은 허용된 무료 전용 정책으로 좁힌다. 환불성 반환·정산 보정·회수·계정 폐쇄 환급 등의 지정된 의무 처리는 별도 예외다. 이 예외를 모든 돈 API의 무조건 허용으로 확대하지 않는다.

클럽 구독은 기금의 유료, 기금의 무료, 부족분의 클럽장 지갑 순서다. 금전 기능이 닫혀도 마지막 지갑분은 무료 전용으로 처리할 수 있다. 기존 문서의 ‘기금이 전액을 충당해야만 성공한다’는 설명은 현재 계약이 아니다. 클럽 구독의 결제 재원과 기간 연장을 따른다.

참가비 직접 송금과 별도 모임 정산 선입금을 구분한다. 정산 선입금의 현재 제한은 참가비 은행 수납 경로가 있다는 이유로 해제되지 않는다. 제한 중에도 기존 돈 의무의 조회·반환·종결 경로를 별도로 확인한다.

유료·무료 통화와 자금 전달

유료와 무료는 잔액·차감·환불·수익 귀속에서 구분한다. 무료 포인트를 유료 잔액이나 외부 현금으로 바꾸지 않는다. 유료 잔액 전체가 즉시 출금 가능한 것도 아니다. 출금 자격·예약·회수 의무·계좌·금전 기능 조건을 추가로 적용한다.

자금 전달 방식과 사용 가능한 통화는 서로 다른 기준이다.

자금 전달 방식현재 등록된 대표 사용처통화 판단
수취자에게 전달참가비, 상품·번들·플랜 구매, 프라이빗 미팅비, 클럽 기부·가입비, 정기모임 지갑 결제등록부가 허용한 정책을 실제 호출자가 좁힌다. 각 경로의 유료·무료 분해를 보존
플랫폼 소비개인 구독, 클럽 구독 지갑분, 프라이빗 개설비, 개설권등록부의 무료 허용이 모든 화면의 무료 결제 제공을 뜻하지 않음. 현재 개설권 구매는 유료만 사용
정산성 이동모임 정산·반환·회수·외부 출금·계정 폐쇄 환급 등지정된 경로는 유료 전용. 구매 지출과 회수·상환 집계를 구분
제공자 서비스비제공자에게 귀속되는 구매수취자에게 전달되지만 유료 전용. 무료를 허용하는 상품으로 소개하지 않음
클럽 미납금 상환클럽의 통화별 채무 정리한 명령은 유료 또는 무료 한 통화로 처리하며 채무별 허용 조건 적용

공통 차감은 실제 유료·무료 몫을 저장하고 충전 원본 소비가 부족하면 실패한다. 무료를 쓸 수 있는 차감은 같은 지갑 잠금 아래 만료된 무료 원본을 먼저 정리한다. 자금 전달 분류 하나만으로 모든 회계 분개·판매자 지급이 자동 완성된다고 설명하지 않는다.

가격 확정과 구매 재원

상품 단건과 플랜 직접 구매는 활성 상품 버전, 번들은 잠근 번들의 가격으로 최종 계산한다. 플랜 응답의 무료 허용 필드만으로 최종 결제 규칙을 대체하지 않는다.

참가비 신청·승인·납부

유료 신청의 자동 승인 또는 호스트 승인은 APPROVED_PENDING_PAYMENT와 결제 기한을 만든다. 승인만으로 참석을 확정하지 않는다. 지갑 결제 또는 은행 입금 확인 뒤 참석 확정 조건을 다시 판정한다. 확인 대기 은행 신고가 있으면 일반 결제 기한 만료에서 제외한다.

지갑 납부는 신청별 서버 금액·현재 상태·기한·접근권한·활성 결제·허용 수단을 검사한다. 자동충전 확인 중은 원 참가비 결제 완료가 아니며, 수동 충전 뒤에도 사용자가 다시 결제를 시도한다. 은행 신고는 실제 입금을 증명하지 않는다. 호스트 확인 요청도 제재·정원 때문에 반환 요청으로 끝날 수 있다.

POINT·CASH·MIXED 정책과 실제 앱 선택지를 구분한다. 현재 상세는 POINT를 지갑으로, CASH·MIXED를 은행 안내로 보낸다. 원 결제와 일행 추가 결제는 별도 기록이며 신청 하나에 항상 결제 한 건만 있다고 쓰지 않는다. 참가비 선입금이 현재 정본이다.

취소 예상액과 실제 환불

취소 미리보기는 조회 시점의 예상이다. 실제 명령은 모임 정책·귀책·시각·남은 유료/무료 원금·이전에 취소한 일행과 추가 결제를 다시 판정한다. 옛 고정 24시간·12시간 안내를 모든 모임에 적용하지 않는다.

지갑 환불과 원 결제수단의 외부 취소는 같은 명령이 아니다. 외부 환불 대기·처리 중·실패를 지갑 반환 완료로 표시하지 않는다. 주최자에게 이미 지급한 수익의 회수도 참가자 반환과 별도이며, 남은 회수금을 취소 성공만으로 상환 완료 처리하지 않는다. 참가비 취소와 환불을 따른다.

은행 반환과 수령 확인

입금 신고 대기 또는 입금 완료 상태의 취소는 이미 보냈을 수 있는 돈을 보존해 반환 요청으로 이어진다. 주최자가 외부 은행에서 반환한 뒤 금액·증빙·시각을 기록하고, 참가자는 별도로 실제 수령을 확인한다. 환불 완료 버튼이 은행 이체를 실행하는 것은 아니다.

현재 일반 모임의 은행 반환은 상한보다 적은 양수 금액도 REFUNDED로 닫을 수 있다. 따라서 상태명만으로 원금 전액 반환을 보장하지 않는다. 서버는 증빙을 선택으로 받지만 앱은 하나 이상 요구한다. 미입금 종결은 실제 입금 확인이 없는 반환 요청에 사유를 남기는 별도 처리다.

정기모임의 회비 환불은 남은 회차 산식과 별도 결제 상태를 따른다. 미확인 은행 신고, 노쇼로 인한 등록 박탈, 모임 전체 취소를 일반 모임의 시간별 비율로 계산하지 않는다. 정기모임 회비 환불을 함께 확인한다.

모임 비용 정산과 반환

지출은 몫을 부담하는 사람에게서 먼저 낸 사람에게, 수입은 보유자에게서 몫을 받는 사람에게 흐른다. 자기 몫을 자신에게 송금하지 않는다. 항목별 분담 납부와 직접 차액 송금도 구분한다.

초안은 납부 요청이 아니다. 서버는 요청 시 모임 종료·항목·분담·상태를 다시 검사한다. 취소 성공도 은행 반환·포인트 복원·실패 복구의 완료가 아니다. 보냈어요 신고가 남은 미확인 송금이나 만료된 의무를 단순 시간 경과로 없애지 않는다.

완료 알림도 실제 지갑 이동액과 수동 은행 잔여를 구분한다. 실제 지갑 반환 완료의 알림은 양수 지갑 반환의 발송 의도이며 실기기 수신·은행 반환 완료를 대신하지 않는다.

기금·구독·수익과 출금

클럽 기금 출금 가용액은 유료 잔액에서 미승인 예약·최근 환불 보호액·미납금을 반영한다. 신청 때 기금이 바로 차감되는 것이 아니라 승인 때 총액을 예약 차감하고 지급 작업으로 넘긴다. 회원의 클럽 기금 출금 신청에는 기부와 같은 필수 요청 키가 없다. 클럽 기금 출금의 신청·승인·반려·실지급을 구분한다.

기부 취소는 현재 회원·본인·활성 상태·7일 조건과 원거래 잔여/기금 가용액을 적용한다. 폐쇄 반환은 별도 배분이며 모든 기부금 전액 환불 보장이 아니다. 클럽 기부와 반환을 따른다.

구독 해지는 자동갱신 중지와 남은 기간 이용이며 즉시 전액 환불과 다르다. 클럽 운영자 환불은 현재 결제가 더한 기간과 실제 낸 지갑·유료/무료 기금으로 나눠 계산한다. 개설권도 현재 단가가 아니라 원 구매 근거와 남은 유효 수량으로 운영자 환불을 판단한다. 개설권 사용·반환과 구독 정본의 현재 기간·정지 원인을 따른다.

창작자 수익은 구매 당시 귀속과 후속 지급이 별도다. 유료분의 수수료를 먼저 빼고 그 남은 금액으로 원천징수액을 계산하며 각 단계의 반올림을 적용한다. 무료분은 무료로 지급하고 유료 미수금 상계와 분리한다. 회원 판매와 플랫폼 판매, 원천별 요율·지급 시점도 다르다. 모든 거래에 같은 요율 또는 ‘총액 × (1 − 수수료율 − 세율)’을 적용하지 않는다. 크리에이터 매출 귀속·정산이 해당 계산과 환불 종결의 정본이다.

주최자 회수금 상환과 정산 보정의 한도

주최자의 모임 환불 회수금 상환은 본인 미해결 행 번호 전체와 화면에서 확인한 합계를 다시 대조한다. 목록이나 금액이 달라지면 최신 값을 돌려주고 차감하지 않는다. 신규 상환은 서버 금전 기능이 허용돼야 하며 유료 전액으로 처리한다. 환불·회수라는 이름만으로 공개 제한의 예외라고 가정하지 않는다. API는 필수 요청 키를 사용하며 앱은 결과 불명에도 지갑과 회수금 목록을 다시 확인한다.

정산 보정의 추가 입금에는 상한이 있다. 해당 정산에서 집행했거나 PENDING·EXECUTING으로 예약한 추가 입금 합계에 새 금액을 더해 정산 총액을 넘으면 거절한다. 이를 최초 지급액까지 합한 총 지급액 상한과 혼동하지 않는다. 회수형 보정은 공통 잔여 회수 한도를 적용하며 대기·집행 중 예약도 반영한다. 이미 실제 거래가 있으면 취소·강제 실패로 한도를 다시 열지 않고 거래 대상·금액·통화·종류를 대조해 완료 상태를 복구한다.

무료 만료와 탈퇴 뒤 돈

무료 지급은 현재 지급 경로에서 1년 만료일을 가진 원본으로 기록한다. 만료 처리는 해당 원본에 남은 무료 몫과 지갑 무료 잔액 중 작은 금액만 정리한다. 이미 쓴 몫이나 유료 잔액을 무료 만료로 다시 차감하지 않는다. 원 지급 거래의 완료 이력도 유지한다.

무료 환불 몫의 원본 만료가 복원일부터 30일보다 짧으면 그 몫만 30일짜리 별도 무료 원본으로 분리한다. 원본 전체의 만료일을 연장하지 않는다. 더 긴 기존 기한은 유지한다. 이 소스 확인이 운영 만료 작업의 실제 실행 기록은 아니다.

즉시 계정 탈퇴는 지갑 잔액을 보존하고 사용을 막는다. 유예 만료 파기에서 유료 환급 예약과 무료 소멸을 처리하며 예약과 실제 송금을 구분한다. 탈퇴 뒤 반환·지급되는 지정된 돈은 지갑 대신 보류금에 남기고 원출금의 늦은 증빙·재지급·외부 종결을 판정한다. 미검토 증빙이 있으면 중복 지급 위험을 먼저 해소한다. 계정 탈퇴의 돈 처리를 따른다.

수용 기준과 확인 범위

  • 금액 보존: 원결제·유료/무료 몫·충전 원본·반환 누계·정산 회수 한도를 연결해 중복 차감·무료 현금화를 막는다.
  • 원장 대사: 지갑 거래와 원장, 충전 원본 잔여, 창작자 미지급금, 기금, 미수금, 환불채무, 원천세 예수금, 분개 차대를 각각 확인한다. 정책 표와 과거 감사 수치가 현재 대사 통과 증거는 아니다.
  • 권한과 상태: 결제·입금 확인·은행 반환·출금 승인·실지급을 서로 다른 행위자·원본 번호·현재 상태로 검사한다.
  • 복구: 결과 불명·중단·부분 실패·늦은 증빙·회수 부족의 미해결 상태를 보존한다. 오래됐다는 이유로 실제 돈 의무를 자동 완료 처리하지 않는다.
  • 외부 결과: 공급자 수락·앱 표시·지갑 적립·은행 입금·실제 수령·알림 도착을 각각 증명한다.

현재 근거는 위 기능 정본과 SpendPolicyRegistry·WalletSpendService·무료 지급/만료/복원 코드다. 과거 돈 흐름 감사의 결함 수, 테스트 통과, 기본 브랜치 반영 기록은 Git 이력에 보존하며 이번 실행 결과로 합산하지 않는다. 옛 참가비 만료 발행 누락·알림 경로 부재·환불 재알림 비잠금·취소 시 참석자만 순회한다는 설명은 현재 참가비 정본으로 교체했다.

공통 외부 지급 복구·운영자 보정·대사의 모든 실행 경로는 이 정책 요약만으로 검증 완료가 아니다. 공개 HTML의 보충 운영 절차와 돈 흐름 감사 문서의 남은 대조는 최신화 대장에 별도로 남긴다. 제품 출시 판정에는 해당 배포본의 실거래·복구·운영 증거가 추가로 필요하다.
