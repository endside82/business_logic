결제 · 정산 정책

포인트 충전, 결제, 환불, 호스트 정산금, 모임 정산, 클럽 기금을 서로 구분해 사용자·운영자가 돈의 상태를 오해하지 않게 한다. 한 줄로 요약하면 “돈의 흐름을 절대 섞지 말 것”.

탈퇴 뒤 도착한 돈은 운영 보류로 처리합니다

끝난 결제 이력만으로 탈퇴를 막지 않는다. 진행 중 돈 의무를 정리한 뒤 탈퇴하며, 탈퇴 뒤 외부·자동 처리가 보내는 돈은 탈퇴 회원 지갑 대신 보류 행에 기록한다. 운영자는 새 계좌 재지급 또는 외부 지급 증빙으로 종결한다. 늦게 도착한 지급 증빙은 거래별로 검토하며 미검토 증빙이 있으면 재지급·외부 종결을 막는다. 원출금 지급 확정·지급되지 않음 판정을 먼저 할 수 있다. 중복 지급 손실 처리의 제품 결정(H-543)은 별도로 남아 있다.

무료 포인트는 지급 단위별로 만료됩니다

무료 포인트는 지급일부터 1년 유효하며 지급 단위의 남은 무료 잔액만 만료시킨다. 이미 사용한 몫을 다시 차감하지 않는다. 무료 포인트 환불은 원래 만료일을 유지하되 반환일부터 최소 30일을 보장한다. 유료 포인트에는 이 무료 만료 규칙을 적용하지 않는다. 만료 대상은 주기 작업과 지갑 사용 전 정리에서 같은 규칙으로 처리한다. 원거래를 EXPIRED로 바꾸지 않고 거래 완료 이력과 지급 단위 만료를 구분한다.

외부 지급의 시작 전 대기와 결과 불명을 구분합니다

지급을 시작하기 전에 작업 선점 시간이 끝난 출금은 지급 실패로 확정하지 않고 대기로 돌려 다시 처리합니다. 결제사 호출 뒤 결과가 불명확한 건은 거래 증거를 확인하며, 오래된 실행의 응답으로 최신 처리 결과를 덮지 않습니다. 자동 충전·취소·가상계좌·지급대행을 기다리는 동안 회원·지갑 잠금과 DB 연결을 계속 잡지 않도록 보완했습니다.

탈퇴한 회원의 지갑에 운영자의 “결제사대로 정산”으로 돈을 다시 적립하지 않습니다. 해당 거절에서는 미해결 상태를 근거 없이 종결하지 않고 별도 회수·환불 경로로 확인합니다. 외부 공급자와의 실거래 검증은 후속 출시 조건으로 남습니다.

주최자 환불 회수금을 확인하고 상환합니다

모임 환불 때문에 주최자에게 남은 회수금을 지갑에서 조회하고 유료 포인트로 상환할 수 있습니다. 창작자 판매 환불 회수금과 별도 항목입니다. 확인한 금액과 실제 금액이 달라졌다면 새 금액을 다시 확인한 뒤 처리합니다.

탈퇴 전에 남은 회수금을 정리해야 합니다. 상환 중 응답 유실은 같은 작업으로 확인하며 중복 차감하지 않습니다. 이 처리는 신규 현금 결제를 개방한다는 뜻이 아닙니다.

정산의 지출·수입과 취소 후 미확인 송금을 구분합니다

항목보내는 사람받는 사람
지출몫을 부담하는 참가자먼저 결제한 보유자
수입수입 보유자몫을 받는 참가자
보유자 자신의 몫자기 자신에게 송금하지 않음

항목별 납부 모드는 분담금으로 처리하며 계산용 송금 행을 만들지 않습니다. 직접 송금 모드는 실제 주고받을 차액을 송금으로 관리합니다. 지출·수입·보낸 돈·받은 돈을 하나의 총 납부액으로 합치지 않으며, 인당 지출 평균도 수입을 더해서 계산하지 않습니다.

“보냈어요”만 있고 받는 쪽 확인이 없는 상태에서 정산을 취소해도 은행 송금 사실이 사라지지는 않습니다. 항목별 분담금은 반환이 필요한 상태를 남기고, 송금자는 잘못 신고했다면 신고를 철회할 수 있습니다. 직접 송금의 취소 후 미확인 건도 확인 필요로 남깁니다. 이미 보냈다고 신고한 송금을 단순 경과 일수만으로 자동 만료시키지 않습니다.

송금 신고와 실제 수령 확인은 다릅니다. 취소·반환·신고 철회 뒤 관련 상세와 지갑을 다시 확인합니다. 플랫폼이 실제 은행 송금을 자동 검증했다는 의미는 아닙니다.

응답이 끊겨도 같은 돈 처리를 중복 실행하지 않습니다

구매·출금, 모임 정산의 납부·선입금, 환불·취소 등 보완된 경로는 완료 결과를 보존하고 같은 작업의 재시도에 재사용합니다. 앱은 계정별로 진행 중 작업을 기억하므로 응답 유실 뒤 앱을 다시 켜도 같은 작업을 이어 확인합니다. 다시 가입하거나 새로 계약한 건은 이전 건과 구분합니다.

응답을 받지 못했다는 사실만으로 실패나 미차감을 확정하지 않습니다. 이미 처리됐지만 결과를 재현할 수 없다는 응답에서는 목록·잔액·상세를 다시 읽어 확인합니다. 서로 다른 실제 거래를 같은 요청으로 합치거나, 결과 불명인 요청을 새 거래로 다시 보내지 않습니다.

모든 쓰기 경로의 보완이 끝났다는 뜻은 아닙니다. 남은 요청 처리·돈 처리 구조 작업은 현재 작업표의 H-515·H-505 등으로 관리합니다. 실제 PG·은행 왕복과 출시 후보 검증은 별도입니다.

환불·회수·보정의 한도와 반환 대상을 맞춥니다

정산의 환불 회수와 운영자 회수 보정은 같은 남은 회수 한도를 사용합니다. 진행 중 보정의 예약도 한도에서 차감하며, 이미 돈이 움직인 작업을 실패로 표시해 한도를 다시 열지 않습니다. 추가 입금에는 별도의 정책 상한을 새로 두지 않았습니다.

은행 이체와 포인트를 섞은 분담금의 손실 정리에서는 남은 포인트를 즉시 반환하고 은행분만 면제합니다. 뒤늦은 은행 확인이나 정산 취소에서 이미 반환한 포인트를 다시 납부액에 넣거나 재반환하지 않습니다.

늦게 실행한 모임 정산은 모임 종료일의 요율을 씁니다. 정기모임은 계획 종료일과 실제 종료·취소일 중 이른 날을 기준으로 합니다. 운영자의 새 요율은 다음 날 이후부터 적용하며 이미 적용된 이력을 소급해 바꾸지 않습니다.

계좌이체 취소에서 돌려받을 금액을 먼저 확인합니다 · 운영자가 남은 개최권을 환불합니다 · 구독 환불은 실제로 낸 곳으로 돌아갑니다

정산 일관성 보완과 자동 검증·기본 브랜치 반영은 완료했습니다. 실제 PG·은행·배포 데이터·서명 앱 확인과 진행 중인 다른 돈 처리 보완은 별도입니다.

2026-09-26 첫 출시 적용 범위

현금성 충전·일반 지갑 결제·외부 지급은 봉인한다. 일반 모임·정기모임의 주최자 계좌 직접 송금은 첫 출시 범위에 포함하되, 배포용 앱·실제 송금·책임 안내 확인과 공개 승인이 남아 있다. 클럽 가입비와 무료 클럽 기부는 무료 포인트만 쓴다. 클럽 구독은 원래 클럽 기금을 먼저 쓰고 부족분을 오너 지갑에서 마저 차감하는 규칙이지만, 오너 지갑 차감 자체가 지금 봉인돼 있어 결과적으로 기금이 전액을 충당할 때만 결제가 끝까지 성사된다.

환불·회수·탈퇴 잔액 정리는 고객의 돈을 묶지 않기 위해 계속 열어 둔다. 실제 결제 출시는 계약·운영 키·소액 정상/실패/복구 왕복·운영자 종결 증거가 같은 출시후보에서 끝난 뒤 별도로 한다.

횡단 흐름 문서

이 페이지는 결제·정산 정책의 개요 문서다. 충전, 소비, 환불, 정산, 출금, 운영 복구가 실제 제품 상황에서 어떻게 이어지는지는 돈·포인트 흐름 감사 문서에서 확인한다. 상세 도식은 도식·종착점, 업무 설명은 상황별 시나리오를 기준으로 본다.

돈의 6개 흐름

서로 섞이면 안 되는 거래 종류. 각자 별개 거래 타입과 별개 상태 모델을 가진다.

클럽 기금멤버·운영 → 클럽공동 자금

유료/무료 분리정산

무료 포인트로 프로모션을 운영하되 무료가 절대 현금이 되지 않도록 유료/무료를 잔액·결제·정산·인출 전 구간에서 분리한다.

  • 핵심 원리: 지갑·클럽 기금 잔액을 유료(충전·현금환불로 들어온 인출 가능 잔액) / 무료(프로모션으로 지급된, 사용은 되지만 현금 인출 불가한 잔액)로 나눠 관리한다. 결제 시 유료/무료가 나뉘어 빠지지만, 이 구분이 받는 쪽까지 전달되는지는 사용처 분류(아래 3분류)에 따라 다르다. 전파형(받는 사람이 있는 흐름)에서만 무료로 결제하면 받는 쪽(창작자·호스트·기금)도 무료로 받아 현금화되지 않는다. 소각형(받는 사람이 없는 흐름)은 무료분이 받는 쪽 없이 지갑에서 그대로 차감(소각)된다. 유료 전용은 무료 결제 자체를 허용하지 않는다. 이벤트 참가비도 현재 표준 지갑 차감·분리정산 flow-through를 사용한다.
사용처 분류대상무료 처리
전파형
(받는 사람이 있는 흐름)		회원 판매 상품의 마켓 구매, 플랜 직접 구매, 프라이빗 미팅비, 클럽 기부·가입비(→기금), 이벤트 참가비, 제공자 배정 서비스비생산자가 허용하면 무료 결제 가능. 무료분은 받는 쪽·기금에 무료로 적립되고, 유료분만 정산·인출 대상이 된다.
소각형
(플랫폼 매출, 받는 사람 없음)		개인 구독, 클럽 구독, 프라이빗 호스팅비, 호스팅 티켓생산자가 허용하면 무료 결제 가능. 무료분은 지갑에서 그대로 차감(소각). 클럽 구독은 기금의 무료분을 프로모션 비용으로 기록하도록 구현됐다. 다른 사용처는 승인된 출시 범위와 회계 분개를 각각 확인한 뒤 연다.
유료 전용
(개인 간 실제 채무 정산)		모임 정산 송금·회수·선입금, 외부 인출·탈퇴 환급무료 불가 — 실제 채무를 프로모션 포인트로 갚게 두지 않는다

플랫폼 소유 기간권은 회원 판매자의 지급 채무를 만들지 않고 플랫폼 구매 수익으로 따로 기록한다. 판매 시작과 환불의 남은 준비는 플랫폼 기간권의 현재 구현과 남은 일을 따른다.

차등 가격 (콘텐츠 생산자가 직접 결정)

  • 무료로 결제할 수 있는지는 생산자가 정한다. 마켓 상품·번들은 결제 화폐(유료 전용 / 무료 전용 / 둘 다 허용)와 구매자의 결제 방식 선택으로, 플랜 직접 구매는 무료 허용 여부 설정과 구매자의 결제 방식 선택으로 결정된다. 무료로 결제할 때 적용할 별도 가격(무료 전용가)도 양쪽 모두 따로 정할 수 있다.
  • 차등가 콘텐츠는 전액 무료(무료 전용가 또는 기본가) 또는 전액 유료(기본가) 중 하나로만 결제된다. "둘 다 허용"이면서 무료 전용가를 따로 두지 않은 경우에만 유료 포인트를 먼저 쓰고 모자라면 무료로 채우는 혼합 결제가 허용된다.
  • 무료를 허용하지 않은 콘텐츠에 무료로 결제하려 하면 거부된다. "둘 다 허용"이면서 무료 전용가를 두지 않은 콘텐츠를 무료로 결제하려는 경우도 거부된다(기본가는 무료로 결제할 수 없다).

인출(현금화) — 유료분만

무료는 어떤 경로로도 현금이 되지 않는다

사용자·클럽 외부 출금은 유료 잔액만 대상이다. 탈퇴 시 유료는 환불, 무료는 소멸한다. 클럽 기금 인출 가용액 = 유료 잔액 − 예비금·미수금이며, 수수료(5%)·원천징수(3.3%)는 유료(현금)분에만 부과한다. 클럽 폐쇄 인출도 유료만 현금화하고 무료 기금은 소멸한다. 창작자 정산도 유료·무료를 분리 기록해 수수료·세금은 유료분에만 적용하고, 무료 매출은 수수료 없이 창작자의 무료 잔액으로 적립된다.

클럽 기부·가입비·구독 환불의 유료/무료 구성 보존과 이벤트 결제·환불의 분리정산 이관은 완료됐다. 첫 출시의 신규 클럽 가입비·기부는 무료 포인트만 허용하고, 다른 유료 사용처는 결제 출시 전까지 새 소비를 막는다.

한 이벤트가 “유료이면서 승인제”일 수 있다. 이 경우 호스트 승인과 결제, 결제와 참석 확정이 다 다른 단계라서 상태를 따로 둔다. 이 흐름은 사전결제를 사용하는 이벤트에 한해 적용되며, 사전결제를 쓰지 않는 유료 이벤트의 흐름은 후속 결정 대상이다.

현재 이벤트 결제 경계

첫 출시에는 무료 모임과 주최자 계좌 직접 송금 유료 모임을 포함한다. 참가자가 외부 은행에서 송금하고 주최자가 확인하는 방식이며 플랫폼이 돈을 보관하거나 자동 환불하지 않는다. 지갑 결제와 유료 결정 투표는 제공하지 않는다.

기존 거래의 확인·거절·환불·수령 확인은 계속 처리한다. 플랫폼 결제는 계약·운영 설정·실제 거래·복구 확인 뒤 별도로 연다. 범위와 남은 확인은 배포용 앱의 직접 송금과 관리자 재처리 확인을 따른다.

2026-09-05 추가 — 직접 송금과 관리자 재시도

일반 이벤트와 정기모임 모두 호스트 계좌 안내·입금 신고·확인·거절·환불·수령 확인이 연결됐다. 플랫폼이 돈을 보관하거나 자동 환불하는 방식이 아니므로 입금 확인·환불의 책임 안내를 승인하고 서명 앱의 역할별 흐름을 확인한 뒤 첫 출시 공개를 승인한다.

관리자 웹의 돈 조치는 응답을 잃어도 같은 작업으로 다시 확인한다. 미확정 작업은 감독 화면에서 상태를 확인하며 이전 결과를 모른 채 새 조치를 만들지 않는다. 정기모임의 확인·거절·환불·취소 복구 등 여섯 조치도 서버 사이에서 같은 작업으로 이어진다. 이 코드는 기본 브랜치에 반영됐지만 실제 결제 승인은 아니다.

고객 흐름은 정기모임 회비 결제, 개인정보 처리 경계는 개인정보·안전 정책, 실제 출시 준비는 첫 출시 현황을 따른다.

정산 승인·지급 결과와 재시도를 함께 관리합니다

9월 25일 반영으로 이벤트·정기모임 정산의 승인·거절·실패·지급 완료와 연결된 판매 수익의 상태를 함께 맞춥니다. 지갑 입금·회계 기록·미수금 상계·지급 완료를 한 번에 저장하며, 이미 지급한 증거가 있으면 다시 입금하지 않고 상태를 복구합니다.

관리자가 같은 작업을 다시 보내면 처음 확정한 결과를 돌려줍니다. 응답을 받지 못했을 때는 기존 작업의 결과를 먼저 확인하며, 같은 작업 번호로 내용을 바꿔 보내는 요청은 거부합니다. 처리 여부를 확인하지 못한 작업은 미확정으로 남겨 재조회·재처리합니다.

기본 브랜치의 서버 처리를 확인한 내용입니다. 실제 결제·외부 지급의 출시 승인이나 운영 환경 확인을 대신하지 않습니다.
