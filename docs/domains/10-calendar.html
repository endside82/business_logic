10. 캘린더

본인 달력·가능 시간·반복 규칙과 폐기된 타인 공개 기능, 외부 동기화의 현재 입구와 과거 검증을 구분한다.

이 영역의 기능별 출시 완료 기준에서 확인할 결과와 증거를 봅니다. 기능 포함 여부와 구현 완료·실환경 통과·공개 승인은 별도로 판정합니다.

범위와 기준 문서

달력은 본인의 주최·참석 모임과 개인 가능 시간을 조회하고 해당 상세로 연결한다. 가능 시간은 개인 일정 기록이며 다른 회원에게 공개하는 기능이 아니다. 기능 문서 5개 중 F10-01~04는 현재 계약, F10-05는 폐기된 공개·친구 조회의 비공개 경계를 관리한다. ‘활성 기능 5개’로 세거나 옛 타인 조회를 미구현 기능으로 복구하지 않는다.

기능 기준 문서현재 상태확인 범위
F10-01 월간·일간 통합 달력현재 기능 계약월·일·기간 조회의 집계 범위, 서울 날짜 이동, 관심인 모임과 본인 가능 시간, 변경 신호·오류 재조회를 구분한다.
F10-02 달력 항목과 상세 연결현재 기능 계약월 카드·일간 블록의 같은 이동 조건, 잘못된 식별자, 비이동 항목, 편집 후 갱신과 복귀를 연결한다.
F10-03 본인 가능 시간 등록·수정·삭제현재 기능 계약본인 전용 가능 시간의 서울 시각·30분 단위·겹침·제목·삭제 확인과 실제 저장 후 달력 갱신을 정리한다.
F10-04 반복 가능 시간 규칙 관리현재 기능 계약매주·격주·매월 규칙의 본인 목록·편집·실제 인스턴스와 예상 개수·전체 삭제·무기한 연장 조건을 구분한다.
F10-05 타 사용자 가능 시간 공개 기능 폐기와 비공개 경계폐기된 공개 기능의 경계폐기된 공개·친구 가능 시간 조회를 복구 대상으로 두지 않는다. 본인 전용 모델·요청·권한과 관심인 공개 모임의 차이를 확인한다.

통합 조회와 실제 상세 연결

본인 월·일·기간 조회는 시작 시각의 포함/제외 범위로 모임·가능 시간을 모은다. 기간 전에 시작해 넘어온 모든 일정을 겹침 기준으로 읽는 조회와 다르다. 취소·결정 대기·참석 원천·위임된 개인 모임 필터는 기능 문서의 실제 조건을 따른다. isPast는 시작 시각 기준이다.

월 날짜는 일간 화면으로, 지원하는 HOSTING/ATTENDING은 모임 상세로, AVAILABILITY는 본인 편집으로 간다. HOSTING_PRIVATE와 식별자 없는 항목은 현재 상세 이동이 없다. 표시를 곧 상세 연결·행동 권한으로 해석하지 않는다. 월의 관심인 보기는 별도 공개 모임 자료이며 상대방의 개인 가능 시간을 공유하는 기능이 아니다.

날짜 이동은 서울 오늘과 날짜 성분을 사용한다. 가능 시간·반복 규칙·모임 변경 신호가 월·일 자료를 다시 읽으며 성공·미실행 삭제 확인·결과 불명을 구분한다. 링크 이동만으로 저장·갱신 완료를 확인했다고 기록하지 않는다.

본인 가능 시간과 반복 규칙

가능 시간에는 공개 범위 입력이나 visibility 저장 모델이 없다. 소유자·서울 timezone·30~480분의 30분 배수·본인 기록 겹침을 확인한다. 단일 생성의 과거 시작 금지와 PATCH의 null 유지·변경 범위는 다르다. 삭제는 겹친 주최 모임 건수 확인 후 필요하면 force로 재요청하며 모임 자체를 취소하지 않는다.

반복 규칙은 매주·시작일 기준 격주·매월 일자를 지원한다. 본인 목록은 페이지로 읽고 종료된 규칙도 포함한다. 규칙의 예상 날짜·서버 expand·실제 저장 건수는 겹침 제외 등으로 다를 수 있다. 수정은 오늘 이후를 다시 만들고 과거를 유지하지만 전체 규칙 삭제는 과거 인스턴스도 지운다. 자동 연장은 무기한·남은 기간·물리 인스턴스 존재 조건을 가지며 인스턴스 0건을 무조건 복구하지 않는다.

현재 오류·동시 요청·잘못된 직접 URL·타인 접근의 검증 경계는 각 기능의 「현재 제한과 확인 범위」를 따른다. 새 사용자 흐름을 추가하거나 제품 결함을 고친 작업으로 문서 갱신을 세지 않는다.

파일 내보내기와 Google 동기화의 현재 입구

월 내보내기와 본인 가능 시간 ICS 내보내기, Google 계정 연결, 선택 전송, 자동 설정은 각각 다른 입구다. 내보낸 파일을 사용자가 공유하는 행위를 서버의 타인 가능 시간 조회 권한으로 확대하지 않는다.

현재 Google 창구는 /api/v1/users/me/calendar/google 아래 연결 상태·code 연결·설정·해제, GET/POST /sync, PUT /auto-sync다. 두 컨트롤러는 P0로 선언되어 있다. 그러나 실제 전송 서비스는 Google 클라이언트·OAuth 설정·ACTIVE 연결을 확인하므로 선언이나 화면 입구만으로 운영 환경 사용 가능 여부가 증명되지는 않는다.

선택 전송은 eventId와 확인한 내용의 fingerprint를 보내고 한 요청은 최대 500개다. 서버는 현재 내용을 재확인해 accepted·stale·unchanged·unavailable을 구분하고 작업을 예약한다. 접수는 Google 반영 완료가 아니다. 자동 설정은 OFF/ALL/SELECTED이며 OFF 이외에는 현재 프리미엄 혜택을 검사한다. SELECTED의 빈 선택은 거절하고 다른 모드에 선택 ID를 섞지 않는다. 기본 모드는 OFF다.

이번에는 이 입구·선택/자동 설정 계약을 확인했다. OAuth 실제 동의·토큰 갱신·외부 생성/수정/삭제·물리 기기와 iOS의 결과를 재실행하지 않았다. 현재 운영 공개 판단은 외부 연결 준비 현황과 선택·자동 동기화의 완료 조건을 함께 확인한다. 이 연결 문서도 전체 최신화 대상이며 예전 완료 문구만으로 지금의 환경을 완료 처리하지 않는다.

Google 동기화의 과거 검증 기록

아래는 갱신 전 공개 영역 페이지에 남아 있던 두 기록의 인용이다. 당시 시험·연결 범위를 보존하며 이번 실행 결과나 현재 운영·물리 기기·iOS 공개 완료로 합산하지 않는다.

유지와 확인 범위

기능 PRD 5개의 검토 해시와 기존 소스 근거를 재사용했고 Google 컨트롤러·선택 서비스의 제한된 범위를 추가 대조했다. PRD·로컬 개요·HTML의 링크와 파생 해시를 검사한다. 기능 문서에 보존한 과거 E2E 인용은 당시 기록이며 새 실행 통과 수가 아니다.

API·시간 조건·소유권·화면 소비부가 바뀌면 해당 기능 기준 문서부터 고치고 파생 문서와 색인을 맞춘다. 달력 개요에 별도의 공개 범위·API·날짜 정책을 중복 정의하지 않는다. 전체 작업 상태는 문서 최신화 추적 자료를 따른다.
