13. 프로필 · 설정

내 프로필·주소·선호 태그를 관리하고, 데이터 내보내기·계정 삭제·비활성화 같은 “계정의 마지막 동선”까지 책임진다. 사용자가 떠나는 흐름이 깔끔해야 신뢰가 유지된다.

이 영역의 기능별 출시 완료 기준에서 확인할 결과와 증거를 봅니다. 기능 포함 여부와 구현 완료·실환경 통과·공개 승인은 별도로 판정합니다.

운영자의 탈퇴 회원 조회

운영자는 회원 번호·탈퇴 기간으로 탈퇴 유예와 파기된 회원을 조회합니다. 목록에는 회원 번호·상태·탈퇴 시각을 표시하고 연락처는 표시하지 않습니다. 일반 회원·삭제 신청 중 회원·미인증 정리 계정은 제외하며, 탈퇴 회원 조회 권한이 없으면 새로고침으로도 조회하지 않습니다.

관리자 서버·웹의 기본 브랜치 반영과 자동 검사를 마쳤습니다. 이 목록 추가는 탈퇴·파기 처리 자체를 새로 구현한 것이 아닙니다.

사람 정보를 확인하고 원래 화면으로 돌아오기

모임·클럽의 사진과 이름에서 사람 미리보기를 열고, 조회가 허용되면 상세 프로필로 이동합니다. 프로필에서 공개 가입 클럽·게시글·받은 리뷰의 원 모임을 둘러본 뒤 한 단계씩 돌아올 수 있습니다. 출발 화면과 스크롤·댓글 초안을 유지하며, 처음 화면으로 돌아가면서 중간 초안을 버리게 되면 확인합니다.

같은 사람을 다시 열어도 방문별 상태를 보존합니다. 직접 주소로 들어와 이전 방문이 없으면 홈 이동을 제공합니다. 계정을 바꾸면 이전 계정의 탐색과 편집 입력을 비우고, 프로필로 돌아오거나 앱을 다시 열 때 공개 권한을 재확인합니다.

현재 볼 수 있는 정보만 표시합니다

일반 프로필의 관계는 본인·같은 클럽·그 외로 나눕니다. 데이트 매칭이나 같은 모임 참석만으로 이름·성별·소개 같은 비공개 정보가 열리지 않습니다. 정지·차단·탈퇴 계정의 프로필과 연관 클럽·리뷰·신뢰점수도 제한합니다. 조회 중·실패·거절에서는 이전 정보를 남기지 않고, 열람할 수 없다는 중립적인 안내를 보여 줍니다.

소개·MBTI는 반환된 값만 보여 주며 빈 값을 미입력 또는 비공개라고 추정하지 않습니다. 공개 클럽 목록 길이를 전체 가입 수로 표시하지 않습니다. 받은 리뷰는 펼칠 때 조회해 세 개부터 보여 주고, 이미 받은 나머지를 펼칩니다. 아래의 작성 글 목록과 정기모임 후기 이름 링크도 첫 출시 범위에 포함하며, 10월 13일 서버·앱에 반영했습니다.

사진·이름과 승인·거절·역할 변경 버튼은 별도 동작입니다. 사용자 ID가 없는 동반자를 예약자 프로필로 연결하거나 익명 투표에 참여자 목록을 만들지 않습니다. 운영자 자격만으로 일반 프로필 공개 범위를 넓히지 않습니다.

10월 3일 프로필 탐색과 10월 13일 작성 글·후기 링크의 기본 브랜치 반영 및 자동 검사 기록이 있습니다. 앱 라우터 시험과 브라우저의 대체 응답 검사는 실제 로그인 서버 왕복과 다르며, Android·iPhone의 제스처·푸시·실제 계정 확인은 남아 있습니다.

다른 사람의 클럽 글을 내가 볼 수 있는 범위에서 모아 봅니다

다른 사람의 프로필에서 받은 리뷰 아래의 ‘작성 글 보기’를 누르면 ‘내가 볼 수 있는 작성 글’이 열립니다. 글 제목·클럽명·게시판명·작성일을 최신순으로 한 쪽에 20개씩 표시하고 이전·다음 쪽으로 이동합니다. 글을 누르면 해당 클럽의 원문으로 이동하며, 돌아왔을 때 펼침·페이지·스크롤은 유지하고 내용은 다시 읽습니다.

현재 내가 가입한 클럽에서 그 사람이 쓴 게시된 글만 목록과 건수에 포함합니다. 예약·숨김·삭제 글과 비회원 클럽의 글은 제외합니다. 작성자가 클럽을 떠났더라도 계정과 프로필 열람이 허용되고 글이 남아 있으면 표시할 수 있습니다. 가입 클럽 숨김 설정은 빈 목록으로 처리하고, 차단·탈퇴 등으로 프로필을 볼 수 없으면 목록도 열지 않습니다.

건수는 그 사람의 전체 작성 수가 아니라 지금 내가 볼 수 있는 글 수입니다. 다시 확인하는 동안에는 이전 제목과 건수를 숨깁니다. 글 삭제나 권한 감소로 현재 쪽이 사라지면 첫 쪽을 다시 읽고, 통신 실패는 빈 목록 대신 재시도로 안내합니다. 다른 기기의 변경은 화면 복귀·앱 재개·새로고침 때 확인합니다.

서버 집계·권한·페이지 검사와 앱 상태·원문 왕복 자동 검사를 마쳤습니다. 10월 13일 구현 반영과 남은 실제 확인에 따라 실제 서버·서명 앱에서 차단·탈퇴·숨김·복귀를 확인합니다.

2026-07-29 소스 재실측 — 연결성·성향·개인정보

허브에는 만난 사람, 메시지, 성향 검사/리포트가 연결됐다. trait는 활성 11축·24문항이며 타인 원점수 API가 없다. 만난 사람은 현재 상태·차단·검색 숨김을 매 조회 다시 적용한다.

내보내기 묶음은 아홉 갈래를 담고, 받을 수 있는 기한은 30일이다. 삭제는 개인정보 삭제·익명화와 법적 보존을 구분한다.

2026-08 이후 보완 — 기한이 지난 내보내기 파일은 매일 새벽 정리 작업이 저장소에서 실제로 지우고 요청도 "만료됨"으로 바꾼다. 계정 삭제 때는 데이팅 사진·본인확인 신분 증빙·내보내기 산출물의 원본 파일까지 지우고, 지우지 못한 건은 재시도 장부에 남겨 다음 회차가 다시 지운다. 취소된 삭제 요청을 관리자가 뒤늦게 실행하던 구멍도 닫혔다.

사용자가 요청하지 않아도 계정이 정리되는 경우

이메일 인증을 끝내지 않은 계정은 안내 뒤 자동으로 익명화된다

가입만 하고 이메일 인증을 마치지 않은 계정은 가입 30일이 지나면 먼저 안내를 받고, 안내로부터 7일이 더 지나도 인증이 없으면 자동으로 익명화된다. 두 회차 모두 매일 새벽에 돈다. 미인증 상태에서는 알림함과 푸시가 닿지 않으므로, 안내는 알림이 아니라 인증 관문 화면이 직접 "언제까지 인증하지 않으면 정리된다"를 보여 주는 방식으로 전달한다.

정리 대상은 정상·로그아웃 상태 계정뿐이다. 제재 중이거나 이미 탈퇴 절차에 들어간 계정은 건너뛰고, 진행 중인 신고·이의·분쟁이 걸려 있거나 정산·환불 같은 금전 의무가 남아 있으면 안내 회차와 익명화 회차 모두에서 제외한다. 클럽에 소속이 남아 있어도 익명화하지 않고 다음 회차로 넘긴다.

익명화는 신원만 지우고 활동 기록은 남긴다 — 닉네임·이메일·휴대전화·비밀번호·이름·생년월일·성별· 자기소개·프로필 사진을 지우고 계정을 탈퇴 상태로 바꾼 뒤 세션을 즉시 끊는다. 동의 원장과 활동 기록은 계정 삭제 요청과 달리 그대로 둔다. 익명화하면서 원래 이메일 주소를 놓아 주므로 같은 주소로 다시 가입할 수 있다.

이 정리는 운영 설정으로 켜고 끄며, 유예 일수와 한 회차 처리 건수도 설정값이다. 잘못된 값이 들어가면 서버가 아예 기동하지 않도록 막아 두었다.

1년 미접속 휴면 정책은 아직 없다

오래 접속하지 않은 계정을 휴면으로 돌리거나 분리 보관하는 처리는 현재 구현되어 있지 않다. 마지막 로그인 시각은 기록하지만 그 값으로 계정을 처분하는 작업은 없다. 휴면 정책이 필요해지면 별도 과제로 다뤄야 한다.

레드 플래그

  • 삭제 예약과 즉시 탈퇴 문구 혼동 — 사용자가 “지웠다”와 “감췄다”를 헷갈리지 않게 분명히 안내. 특히 즉시 탈퇴를 “잠시 쉬는 기능”으로 오해하면 안 된다 — 되돌릴 수 없다.
  • 데이터 내보내기를 즉시 다운로드라고 오해 — 비동기 처리임을 명시.
  • 주소 한도 초과 시 명확한 안내 없음 — “더 이상 추가할 수 없다”라고 정확히 알림.
  • 즉시 탈퇴 시 미정산 처리 누락 — 호스트가 정산 중인데 탈퇴하면 참가자 환불·납부 차단.
  • “탈퇴했다가 다시 켜 드릴게요” 식 상담 — 되살리는 경로가 없어 지킬 수 없는 약속이 된다.
