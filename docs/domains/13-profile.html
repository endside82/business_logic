13. 프로필 · 설정

내 프로필·주소·선호 태그를 관리하고, 데이터 내보내기·계정 삭제·비활성화 같은 “계정의 마지막 동선”까지 책임진다. 사용자가 떠나는 흐름이 깔끔해야 신뢰가 유지된다.

2026-07-29 소스 재실측 — 연결성·성향·개인정보

허브에는 만난 사람, 메시지, 성향 검사/리포트가 연결됐다. trait는 활성 11축·24문항이며 타인 원점수 API가 없다. 만난 사람은 현재 상태·차단·검색 숨김을 매 조회 다시 적용한다.

Export는 FileStorage key+presigned URL과 9개 섹션을 사용한다. 자연 만료는 자동 EXPIRED가 아니라 COMPLETED+URL 없음이고 관리자 expire만 EXPIRED로 바꾼다. 삭제는 개인정보 삭제·익명화와 법적 보존을 구분한다. CANCELLED row도 실행 가능한 관리자 process, 데이팅 사진 실물, deletion Entity/V1 제약이 현재 Gap이다.

항목값

접수 직후 상태PENDING 삭제 예약 — 취소 버튼과 서버 취소는 이 상태에서만 가능
실제 처리스케줄러가 매일 새벽 04:00에 만료된 요청을 실행
삭제 후 계정 상태EXIT — 개인정보 삭제·익명화, 거래/정산·법적 분쟁 기록은 보존 정책 적용
유예 중 취소 동선로그인은 진행 중 요청과 관리 동선만 노출한다. 취소는 사용자가 DELETE /api/v1/users/me/data-deletion을 명시적으로 호출해야 하며 로그인 자동 취소 계약은 없다.
요청 방식사용자가 설정 화면에서 직접 계정 삭제를 신청한다
UI 스펙 vs 현재 구현스펙의 비밀번호 재확인은 현재 Flutter 화면과 서버에 없다. POST /data-deletion은 body 없이 처리된다 — Gap

레드 플래그

  • 삭제 예약과 즉시 비활성화 문구 혼동 — 사용자가 “지웠다”와 “감췄다”를 헷갈리지 않게 분명히 안내.
  • 데이터 내보내기를 즉시 다운로드라고 오해 — 비동기 처리임을 명시.
  • 주소 한도 초과 시 명확한 안내 없음 — “더 이상 추가할 수 없다”라고 정확히 알림.
  • 즉시 비활성화 시 미정산 처리 누락 — 호스트가 정산 중인데 비활성화하면 참가자 환불·납부 차단.
