2026-09-02 — 대절 버스·카풀 통합 완료 반영

종전 버스·카풀 분리 모델과 “관리자 차량 화면 없음” 설명을 현재 코드에서 제거하고, 실제 완료 범위와 개통 전 운영 검증을 구분했다.

  • 차량 모델을 하나로 설명한다 — 대절 버스·참가자 승용차·자차가 같은 차량· 자리 모델을 쓰며, 지정·비지정 자리와 호스트 전담·참가자 자기 선택을 독립 설정한다.
  • 완료된 운영 기능을 반영했다 — 표준 차량 9종, 관리자 목록·좌석표·복제· 이름/설명 수정·활성화, 빈 좌석표와 사용 중 배치도 보호가 완료됐다.
  • 봉인 이유를 바로잡았다 — 신규 이동수단이 닫힌 이유는 화면 미구현이 아니다. 서명 앱의 호스트·운전자·탑승자 왕복, 실기기 알림·신고, 참가자 간 이동 책임 고지 승인을 마친 뒤 TRANSPORT를 연다.
  • 표적 회귀를 다시 실행했다 — 사용자 API 156건, 앱 160건, 관리자 API 23건, 관리자 웹 차량 배치도 E2E 3건이 실패 없이 통과했다.

2026-08-30 — 현재 코드와 전체 자동 검증을 다시 고정

최근 추가된 문의 관할, 노쇼 처리, 정기모임 환불 이력과 외부 호출 안전장치를 기능 설명과 출시 현황에 다시 대조했다. 이전에 해소된 문제는 현재 미해결 목록에서 제거했다.

  • 현재 검증 기준과 수치를 갱신했다 — 사용자용 API 7,641건, 앱 2,826건, 관리자 API 1,081건, 관리자 웹 E2E 162건, 실시간 서버 256건이 실패 없이 통과했다. 이 기준에서 첫 출시 범위의 확인된 코드·화면 차단 항목은 0건이다. 다만 앱·관리자 API· 관리자 웹의 최신 커밋은 아직 원격 저장소보다 각각 한 커밋·한 커밋·두 커밋 앞서 있다. 이 네 커밋을 반영해 고정한 코드 조합의 회귀와 최초 설치 SQL 빈 데이터베이스 비교, 요구 Node 버전, 서명 앱·실기기와 외부 서비스 왕복을 공개 출시 전에 끝내야 한다.
  • 제품 전체 코드 완성도와 출시 준비도를 분리했다 — 전체 제품 코드는 약 95%, 첫 출시 범위 코드는 100%로 보되 공개 출시 준비는 미완료로 표시했다. 시나리오 문서가 자동 테스트 59개 기능, 통합·사용자 여정 54개 기능을 직접 가리킨다는 수치는 구현률이 아니라 문서 추적 가능성이라는 설명도 세 상태표에 동일하게 넣었다.
  • 문의 답변 권한을 현재 구현에 맞췄다 — 이벤트 문의는 호스트·공동호스트가, 클럽 문의는 클럽 운영진이 직접 답변·이관·종결할 수 있다. 플랫폼 운영팀은 플랫폼 관할 문의만 처리한다. 이용 제한 계정도 기존 문의를 읽고 답할 수 있지만 새 문의 생성은 현재 차단돼 있어, 실제 문의 실패 지표를 본 뒤 후속 정책을 결정하도록 남겼다.
  • 노쇼 환불 문서의 잘못된 보안 문제를 삭제했다 — 환불 단건 조회는 URL의 이벤트와 실제 기록을 맞추고, 신청자 본인 또는 환불 집행 권한자만 통과한다. 환불 실행도 호스트, 환불 권한을 받은 공동호스트, 클럽 환불 담당자로 제한된다. 실제로 남은 문제는 환불 행이 노쇼 상태에 직접 묶이지 않은 점, 화면이 원 결제액을 받지 못하는 점과 완료 알림 부재다.
  • 정기모임 환불 완료 이력을 현재 화면에 맞췄다 — 참가자는 자기 이체증을, 호스트는 최근 완료 이력 최대 200건을 다시 볼 수 있다. 다른 모임 결제, 목록 밖 파일, 업로드 미완료·격리·차단 파일의 열람 거절은 실제 데이터베이스 테스트로 확인했다. 운영 파일 저장소에서 실제 바이트를 내려받는 검증만 외부 관문으로 남는다.
  • 소셜 로그인 외부 호출의 장애 확산 방지를 반영했다 — 카카오·네이버 호출은 연결 5초·응답 10초 상한을 사용하며, 제한시간 없는 외부 HTTP 클라이언트가 다시 들어오지 않도록 자동 검사한다.
  • 앱의 순서 변경과 붙여넣기 안전성을 반영했다 — 플랜 블록, 연결 플랜, 게시글 사진과 여러 블록 편집 화면에서 아래로 옮길 때 위치가 한 칸 어긋날 수 있던 계산을 새 Flutter 규칙에 맞췄다. 외부 문서의 허용되지 않은 서식 때문에 저장만 실패하는 문제는 글자만 붙여 넣도록 막았고, 라이브러리의 실험 기능 의존성은 자동 검사와 정적 분석 경고로 계속 드러나게 했다. 앱 전체 2,826건은 통과했고 정적 분석은 오류 0건, 경고 4건이다.
  • 관리자 웹의 무기한 대기를 막았다 — 로그인은 5초, 일반 조회·명령은 30초 안에 응답이 없으면 중단하고 결과 확인 방법을 안내한다. 정산 완료와 파일 내려받기처럼 원래 오래 걸리는 작업은 별도의 긴 제한시간을 사용한다. 무료 포인트 지급은 첫 요청의 응답이 끊겨 운영자가 다시 눌러도 같은 중복 방지 키를 보내도록 보완했다. 타입 검사와 전체 E2E 162건을 통과했으며, 저장소가 요구하는 Node 24.14 이상 환경의 재실행은 출시 관문으로 남겼다.
  • 관리자 돈 조치의 남은 재시도 위험을 미완료로 분리했다 — 무료 포인트 지급은 닫혔지만 환불·출금·정산·이벤트 결제 등 같은 형태의 호출부 10개는 아직 실행할 때마다 새 중복 방지 키를 만든다. 현금성 기능의 봉인을 풀기 전에 같은 작업의 재시도 키를 보존하고, 성공 뒤에만 키를 폐기하며, 첫 응답 유실 뒤 재실행이 한 번만 처리되는 화면 검증을 각 경로에 추가해야 한다.

2026-08-30 — 본인확인 장애 대응 방식을 확정

정상 본인확인 API가 동작하지 않을 때 시스템 관리자가 수동으로 인증을 완료할 수 있게 하되, 단순 상태 변경이 아니라 신원·성인 여부·유효기간·책임 소재를 검증할 수 있는 안전한 승인 절차로 구현하기로 했다.

  • 현재 운영 화면의 범위를 바로잡았다 — 관리자 웹에는 본인확인 결과 목록·상세, 회원별 시도 이력, 공급자, 실패 코드·메시지 조회가 이미 있다. “전용 관리자 웹이 없다”는 설명을 삭제하고, 조회 화면과 승인 화면을 구분했다. 현재 사용자·운영 흐름은 본인확인 기능 설명에서 확인한다.
  • 수동 승인에 필요한 정보를 확정했다 — 공급자 장애 또는 실패·만료 시도를 근거로 증빙 파일, 정확한 생년월일, 남성/여성 성별, 최대 365일 유효기간과 승인 사유를 모두 받아야 한다. 정상 인증과 같은 만 20세 판정·암호화·회원정보 동기화, 변경 전후 감사, 중복 실행 방지와 증빙 보존도 필수다.
  • 기존의 단순 상태 변경 명령은 계속 숨긴다 — 현재 서버 명령은 인증 상태와 승인 시각만 바꾸므로 성인 여부·유효기간·증빙을 보장하지 못한다. 새 승인·취소 명령과 관리자 입력 화면을 구현하고 표적 테스트와 관리자 웹 전 과정 테스트를 통과하기 전에는 운영에 쓰지 않는다.
  • 개통 조건과 기능 구현을 분리해 표시했다 — 수동 승인 구현 뒤에도 NICE 계약·키, 실제 성인 신원과 실기기 왕복, 두 기기 채팅, 5계정 신고와 관리자 판정, 적법한 경찰 로그 제공 훈련까지 끝나야 데이트 기능을 열 수 있다. 전체 순서와 완료 조건은 첫 출시 현황에서 관리한다.

2026-08-25 — 미해결 항목을 다음 행동 기준으로 재분류

“출시 후 보완할 한계”라는 한 목록을 해체했다. 아직 닫히지 않은 사실은 숨기지 않되, 지금 바로 화면을 연결할 일과 제품 결정을 먼저 할 일, 대체 동선이 있어 출시 후 개선할 일, 제품과 별개인 문서 작업을 서로 다른 표에서 보도록 바꿨다.

  • 검증 기준일도 현재 증거에 맞췄다 — 8월 24일 같은 커밋 묶음에서 공개 API 6,906건·앱 2,442건·관리자 API 919건·관리자 웹 141건과 빈 데이터베이스 설치 비교를 통과했다. 그 뒤 8월 25일 코드 품질 수리 커밋이 다시 들어왔으므로, 현재 소스는 저장소별 검증과 별개로 다섯 저장소 통합검증을 한 번 더 고정해야 한다.
  • 잘못 등록된 이의 처리 결함을 삭제했다 — 클럽 경고 이의는 권한 있는 클럽 운영진의 인박스에서 인용·부분 인용·기각과 재제출 허용까지 처리할 수 있고, 모임 정산 이의도 정산 생성자·호스트의 전용 화면과 서버 권한 검사가 연결돼 있다. 운영팀만 최종 결정하는 것은 통합 분쟁 도메인의 이의다. 세 경로를 “이의”라는 이름만으로 일반화했던 설명을 상태표와 분쟁 상세 문서에서 제거했다.
  • 화면 배선 두 건을 가장 작은 실행 단위로 분리했다 — 리뷰 답변 수정은 이미 있는 수정 함수를 화면에서 고르면 되고, 정기모임 주소 입력은 서버 요청과 앱 데이터 계층에 이미 있는 주소 필드를 생성 화면에 연결하면 된다. 각 항목에 표적 화면 테스트까지 포함한 완료 기준을 붙였다.
  • 출시 전 결정과 출시 후 개선을 분리했다 — 증빙 보존·삭제, 저장된 검색 정렬, 미인증 계정 정리는 출시 승인 전에 처리 방식을 선택하고 반영해야 한다. 알림·입력·탐색·안내처럼 대체 동선이 있는 항목은 아직 미해결임을 명시한 채 담당자·다음 행동·완료 기준을 가진 후속 개선 후보로 분리했다.
  • 당시 신규 기능과 화면 누락을 구분했다 — 이 시점에는 모임·클럽 문의의 호스트 직접 답변에 서버 권한과 발신자 모델이 없어 단순 배선 작업이 아니라고 판단했다. 이 기능은 이후 구현됐으며, 현재 상태는 위 2026-08-30 기록을 따른다.
  • 봉인 해제 선행 작업을 봉인 항목 안으로 옮겼다 — 정기모임 회비의 계좌 안내 화면은 일반 출시 한계가 아니라 호스트 계좌 직접 송금을 다시 열기 전에 닫아야 하는 조건이다. 사적 모임 결제 버튼은 공개 출시 차단 항목에 흡수했고, 사적 모임 전용 설명서 공백은 제품 결함 수에서 분리했다.

  • 표시 정비 — 참가자에게 보이던 호스트용 신청 안내를 "정산자가 작성 중이에요"로 분리, 내 분담금에 "준비 중 — 금액이 바뀔 수 있어요" 표시 (F07-05).
