주요 변경 기록

제품 범위와 이용·운영 방법에 영향을 준 변화를 요약한다. 지금 제공할 기능과 남은 준비는 첫 출시 현황에서 확인한다.

구현 완료와 공개 출시는 다르다

아래 내용은 2026년 9월 6일까지 문서에 반영한 변경이다. 기능을 만들고 개발용 환경에서 검사한 것과 실제 고객에게 공개하는 것은 별개다. 외부 고객 공개와 실제 결제 가동은 아직 보류 중이다.

2026년 9월 — 주요 기능과 공개 조건 정리

핵심 마일리지와 모임별 적립 점수

클럽 마일리지의 적립·사용·정정·등급·순위를 첫 출시의 기본 제공 목록에 포함했다. 모임별 체크인·후기 점수는 공개할 때 확정하고, 모임 취소 시 해당 적립을 회수하도록 구현했다. 모임별 점수 기능은 핵심 마일리지와 함께 배포하므로 첫 출시 검사에 포함한다. 자세한 범위는 클럽 마일리지에서 확인한다.

마일리지 추가 기능

시즌 시작·마감·순위 확정, 사진 심사를 통한 적립, 반복 수동 적립의 검토를 구현했다. 회원과 운영진의 실제 이용을 확인한 뒤 각각 공개할 기능이며, 핵심 마일리지와 함께 자동으로 열지는 않는다. 이용 방법은 마일리지 시즌과 모임 사진과 적립 심사에서 확인한다.

클럽 스탬프

운영진 공동 관리, 발행자만 수정하도록 잠그는 기능, 발행자 변경, 시작일·칸별 보상과 여러 회원에게 한 번에 도장 찍기를 구현했다. 실제 계정에서 권한 변경과 통신 끊김 후 재시도, 휴대전화 알림을 확인한 뒤 별도로 공개한다. 마일리지와 자동으로 연결되는 기능은 아니다. 자세한 규칙은 클럽 스탬프에 있다.

본인확인 장애 때의 증빙 검토

정상 인증을 완료하지 못한 회원이 증빙을 제출하고, 권한 있는 운영자가 확인해 승인·취소하는 절차를 구현했다. 회원이 증빙을 바꾸면 운영자는 새 파일을 다시 검토해야 한다. 데이트 공개 전에는 실제 인증 서비스·파일 보관·운영자 검토·회원 알림이 이어지는지 확인해야 한다. 절차는 본인확인과 증빙 검토에 있다.

운영자의 송금·환불 재시도

운영자가 성공 응답을 받지 못해 같은 작업을 다시 요청해도 돈이 두 번 움직이지 않도록 보강했다. 운영자는 결과가 확인되지 않은 작업을 찾아 처리 결과를 확인할 수 있다. 직접 송금과 플랫폼 결제를 공개하기 전에 실제 서비스에서도 재시도를 검사한다.

계좌 직접 송금과 버스·카풀

일반·정기모임의 계좌 안내, 입금 확인과 환불 처리를 연결하고 이동수단 등록·탑승의 책임 안내를 반영했다. 주최자·참가자·운전자·탑승자의 실제 이용 검사와 책임 문구 승인 후에 공개한다. 자세한 흐름은 정기모임과 모임 이동수단에서 확인한다.

서비스 제공자 거래와 결제 확인

제공자 배정·수행 확인·정산·환불과 운영 화면을 구현했다. 개발용 환경의 결제·환불·배정 검사에서는 화면뿐 아니라 서버에 저장된 결과도 확인했다. 실제 공개에는 결제·지급 서비스 준비, 법무·세무 승인과 배포용 앱 검사가 필요하다. 업무 범위는 서비스 제공자 배정·정산에서 확인한다.

마켓 기간권의 판매 방식

플랫폼이 기간권을 판매하고 기존 상품 심사·정지 절차를 적용하기로 정했다. 기간권을 편성하고 판매를 시작하는 경로에는 개발 작업이 남아 있다. 준비 상태는 첫 출시 현황에서 관리한다.

이전 주요 변경

과거의 제품 결정과 문서 구조 변경만 남겼다. 필요한 시기를 펼쳐서 읽는다.

2026년 8월 — 첫 출시 범위와 운영 책임 정리
  • 유료 모임을 먼저 제공하려던 계획을 바꾸고, 무료 모임·클럽 중심으로 첫 출시 범위를 좁혔다. 기존 이용자의 환불·해지·신고 처리는 계속할 수 있도록 구분했다.
  • 이메일 인증 전의 이용 제한, 제재 계정의 기존 문의 열람·답변, 모임 주최자·클럽 운영진·플랫폼 운영자의 문의 처리 책임을 문서에 반영했다.
  • 기능이 구현됐는지, 실제 환경에서 확인했는지, 고객에게 공개할 수 있는지를 기능별 출시 상태에서 따로 확인하도록 했다.
2026년 7월 — 기능 설명과 실제 동작 대조
  • 모임·결제·플랜·위치·개인정보·제공자 거래의 설명을 서버와 앱의 실제 동작에 맞춰 고쳤다.
  • 서버에 기능이 있는 것과 사용자가 앱 화면에서 실행할 수 있는 것을 구분하고, 확인하지 못한 부분은 완료된 기능으로 표시하지 않도록 했다.
2026년 6월 — 거래·운영 기능과 문서 탐색 확장
  • 분쟁 해결·관심인·고객지원·서비스 제공자 배정과 정산을 문서 목록에 추가했다.
  • 결제·환불·정산의 돈 흐름과 운영자 복구 절차, 플랜 편집·예약 발행·상품 심사를 반영했다.
  • 문서 메뉴를 시작·발견, 모임, 클럽, 돈, 사람·관계, 신뢰·운영, 기반의 일곱 묶음으로 정리했다.
2026년 5월 — 제품 문서 체계 마련
  • 제품 이해·업무 영역·기능·정책·검사 기준을 나누고 실제 소스와 근거를 먼저 확인하는 작성 원칙을 마련했다.
  • 정기모임·경고와 제재·마일리지 등 빠져 있던 영역과 정책 수치를 문서에 추가했다.
  • 휴대전화에서 본문을 먼저 읽고 필요할 때 메뉴를 여는 탐색 방식을 적용했다.

상세 근거가 필요한 경우

개별 기능의 현재 규칙은 해당 기능 문서에서 확인한다. 커밋 번호·검사 건수·개발 중간 과정은 이 페이지에 반복하지 않는다.

  • 기능별 시나리오와 검사 근거
  • 개발 담당자용 버전 확인 기록
  • 통합 기능의 자동 검사 기록

요약에서 생략한 날짜별 원문과 편집 과정은 이 문서 저장소의 버전 관리 이력에 남아 있다.

변경 기록 작성 원칙

  • 문서 작성자는 바뀐 기능의 본문을 먼저 고치고, 제품 범위나 이용·운영 방법이 달라진 경우에만 여기에 요약한다.
  • 같은 기능의 연속 작업은 한 항목으로 합친다. 표현 수정·검사 재실행·저장소 반영만으로 날짜별 항목을 추가하지 않는다.
  • 현재 공개 상태와 남은 일은 출시 현황에서 관리하고, 이 페이지에는 당시 달라진 내용만 남긴다.
