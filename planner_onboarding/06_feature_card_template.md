# 기능 카드 템플릿

<!-- release-document: reference -->
> 2026-11-22 현재 175개 기능 PRD의 요약을 만드는 형식이다. 상세 단위 시나리오 문서가 있는 117개 기능과 나머지 58개 기능에 같은 형식을 쓸 수 있다. [기능 PRD 작성·검수 기준](../prd/FEATURE_PRD_STANDARD.md)이 정본이며 현재 작업 순서는 [앞으로 할 일](../../docs/plan/NEXT_WORK.md)을 따른다.

카드는 실제 입구·조건·행동·결과·복귀를 요약한다. 기능 PRD와 확인 버전을 연결하고, 별도 구현 계약이나 독립적인 미완료 총계를 만들지 않는다. 시각 설명이 필요하지 않은 카드에 도식·이미지를 의무적으로 붙이지 않는다.

## 카드 기본 형식

```markdown
# 기능 번호와 이름

정본 문서와 확인 버전:

## 목적과 사용자
사용자가 달성할 목적, 주 사용자·보조 사용자·금지 사용자를 적는다.

## 실제 입구와 시작 조건
메뉴·목록·알림·공유 링크, 로그인 후 복귀, 현재 역할·상태를 적는다.
같은 행동이 여러 곳에 보이면 차이와 필요한 이유를 적는다.

## 행동과 결과
1. 사용자가 확인하는 정보와 선택하는 행동
2. 현재 조건의 허용 또는 거절과 이유
3. 성공 뒤 실제로 바뀌는 상태
4. 원래 화면으로 돌아온 뒤 갱신되는 정보

## 취소·실패·결과 불명
| 조건 | 사용자에게 보이는 결과 | 가능한 다음 행동 |
|---|---|---|

## 관련 영향
돈·알림·캘린더·위치·리뷰·신뢰 중 실제 관련 항목만 적는다.
요청 접수·의도 저장·외부 완료를 구분한다.

## 수용 조건과 근거
| 시작 조건 | 조작 | 관찰 결과 | 근거와 확인 범위 |
|---|---|---|---|

## 남은 제한
Gap·Risk·결정 필요·미검증을 구분하고 정본의 후속 작업을 연결한다.
```

## 예시: 이벤트 신청·참석·본인 취소

정본은 [이벤트 신청·참석·본인 취소](../prd/02_feature_prds/03_event/F03-05_event-attendance_prd.md)다. 아래는 소스 대조된 내용의 카드 요약이며 실제 업무를 새로 실행한 기록이 아니다.

참가자는 모임 상세의 참석 신청에서 본인·허용된 게스트와 안내를 확인한다. 로그인·접근·현재 모임과 회원 상태·호스트 본인 여부 등을 다시 판정한다. 확인창을 닫는 것과 신청 요청이 성공하는 것을 구분한다.

| 조건 | 결과와 다음 행동 |
|---|---|
| 무료·승인 불필요 | 자리와 대기 허용에 따라 참석 또는 참석 대기. 일행의 결과가 나뉠 수 있음 |
| 승인 필요 | 심사 대기. 승인만으로 유료 결제나 참석 완료를 뜻하지 않음 |
| 선입금 필요 승인 | 결제액·기한이 있는 결제 대기. 별도 참가비 확정으로 참석을 연결함 |
| 상태 변경·중복·결과 불명 | 현재 신청·모임을 다시 확인하고 안내. 새 확인창에서 입력하는 것과 같은 요청의 결과 확인을 구분함 |

성공 뒤 상세·카드·예정 모임을 다시 읽고 서버의 실제 신청·참석 상태를 표시한다. 취소·재신청·결제·환불 조건은 정본에서 이어 확인한다. 카드를 간단히 만들기 위해 유료 신청을 즉시 지갑 차감으로 바꾸지 않는다.

## 예시: 금액 검토·정산 요청·취소와 반환

정본은 [금액 검토·정산 요청·취소와 반환](../prd/02_feature_prds/07_meeting_settlement/F07-03_activate-cancel_prd.md)이다. 현재 앱 입구는 금액 검토하기 → 정산 요청 보내기 → 확인이다. 현재 주최자에 대한 앱 입구와 정산 생성자를 기준으로 하는 서버 관리 권한을 하나로 합치지 않는다.

| 조건 | 결과와 다음 행동 |
|---|---|
| 초안·종료 시각·현재 항목과 분담이 유효함 | 요청 가능. 검토만 하는 행동과 실제 납부 요청을 구분함 |
| 남은 의무가 있음 | 진행 중인 실제 상태로 현황에 복귀 |
| 처음부터 남은 의무가 없음 | 요청 결과가 바로 완료일 수 있음. 앱이 진행 중으로 덮지 않음 |
| 조회 실패·다른 초안·처리됐을 가능성 | 요청을 막거나 현재 현황을 재조회. 자동으로 재전송하지 않음 |
| 작성 중·진행 중 취소 | 더보기의 취소 경로와 확인을 사용. 상태 취소와 포인트 반환·외부 이체 직접 반환을 구분함 |

알림은 방식별 실제 납부 대상의 발송 대기 자료에 등록한다. 모든 참석자 수신 완료로 표시하지 않는다. 이 카드의 상태 요약·도식만으로 정산 전체 상태 기계나 실제 돈 복구 완료를 증명하지 않는다.

## 검토와 갱신

[기획 QA 체크리스트](10_planning_qa_checklist.md)로 관련 조건을 선택한다. 정본이 변경되면 해당 카드의 근거 버전과 본문을 함께 바꾸며, 이전 카드에 적힌 성공 사례를 현재 실행 통과로 재사용하지 않는다. 정해진 사례 수를 채우기 위해 내용이 같은 항목을 늘리지 않는다.
