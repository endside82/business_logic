# 역할과 현재 권한을 읽는 가이드

<!-- release-document: reference -->
> 2026-11-22 권한 정책 정본과 검토 완료한 기능 문서를 재사용한 기획용 안내다. 새 제품 시험·기기 검수·운영 환경 확인 결과가 아니다. 실행 순서는 [앞으로 할 일](../../docs/plan/NEXT_WORK.md)을 따른다.

## 역할 이름 다음에 확인할 것

권한은 **현재 계정 + 대상과의 관계 + 유효한 위임 + 대상 상태 + 공개 범위 + 명령별 조건**으로 판단한다. 예전에 운영진이었다는 사실, 상세 화면에 들어왔다는 사실, 버튼이 보인다는 사실만으로 쓰기 권한이 확정되지는 않는다.

[권한 정책 정본](../prd/03_policy_prds/permission_policy_prd.md)을 우선한다. 이 문서의 행은 기획자가 구분할 역할과 질문이며 서버 역할 enum이나 전 기능 허용표가 아니다. 권한을 확인하지 못한 상태와 확인 결과 거절된 상태도 나눈다.

## 역할을 구분하는 매트릭스

| 구분 | 확인할 관계·행동 | 빠뜨리기 쉬운 조건 |
|---|---|---|
| 비로그인·로그인 사용자 | 공개 조회·본인 작업 | 서비스 내부에 익명 분기가 있어도 HTTP 경로가 공개인지 별도 확인 |
| 신청자·납부 대기자 | 신청·신고·취소·반환 | 신청 승인, 납부 완료, 실제 참석은 별개 |
| 참석자·대기자·게스트 책임 회원 | 참석 현황·체크인·게스트 변경 | 실제 참석 행과 책임 회원. 현재 이동 조율 조회는 승인 신청만으로 열리지 않음 |
| 호스트·공동호스트 | 모임 운영·출석·환불·공지 | 현재 위임이 유효한지와 해당 행동의 권한을 검사. 호스트와 모든 권한이 같지 않음 |
| 클럽 회원·운영진·소유자 | 명단·기본정보·역할·권한 위임·이전 | 역할·위임 변경은 소유자 전용. 소유권 이전은 별도 절차 |
| 정산 생성자·현재 주최자·금전 당사자 | 초안 편집·확정·납부·반환·이의 | 현재 관리 권한과 원 납부자의 책임·수취 권리를 분리 |
| 작성자·현재 구매자 | 플랜 본문·초안·판매·이용 권리 | 공개 읽기와 구매 권리, 숨김과 기존 유효 구매 권리는 다름 |
| 데이팅 당사자·차단 관계 | 제한된 프로필·대화·차단·해제 | 호감·매칭·연락처 동의·현재 차단은 각각 확인. 해제는 과거 방 복원이 아님 |
| 위치 공유자·조회자 | 동의·좌표·만료·목적별 열람 | 상대 정보는 현재 자격·동의·조회 목적을 함께 검사 |
| 경고 검토자·제재 담당자 | 검토·집행·철회 | WARNING_REVIEWER와 SANCTION_PROPOSER를 분리. 강제 탈퇴 집행·재시도·철회에는 OWNER 조건 |
| 마일리지·스탬프 운영자 | 정책·심사·점수·배지·발급 | POLICY_OWNER·REWARD_MANAGER·BADGE_AWARD_MANAGER·MILEAGE_MANAGER와 스탬프 발급 권한을 한 이름으로 합치지 않음 |
| 플랫폼 관리자 | 별도 로그인·직무 권한·민감 작업 | 두 번째 인증·재인증·작업별 관문·설정 예외를 구분. 클럽 ADMIN과 다름 |

## 같은 화면에서 다른 권한을 검토하는 법

모임 상세를 보았다고 참석 관리·출석 확인·선입금 반환을 모두 실행할 수 있는 것은 아니다. 상세 조회, 실제 행동, 그 행동의 현재 상태를 각각 적는다. 하위 신청·정산·제안 번호가 현재 부모 모임에 속하는지도 확인한다.

초안 정산은 참가자에게 일부 미리보기 정보가 보일 수 있으므로 ‘DRAFT는 생성자 외 전부 열람 불가’라고 쓰지 않는다. 대신 어떤 필드가 제한되는지와 쓰기 권한을 나눈다. 정산 이의의 회원 작성·호스트 답변·운영팀 판단 역시 서로 다른 행동이다. [모임 정산 도메인](../prd/01_domain_prds/07_모임_정산_prd.md), [정산 이의와 변경 기록](../prd/02_feature_prds/07_meeting_settlement/F07-08_appeal-audit_prd.md)을 따른다.

## 위임과 소유권 변경을 검토하는 법

클럽 ADMIN 또는 공동호스트 행이 남아 있어도 현재 역할 제한으로 위임이 효력을 잃을 수 있다. 일반 회원으로 강등할 때 위임 비트도 회수하며, 허용 목록 밖 권한을 서버에 그대로 되돌려 보내지 않는다. POLICY_OWNER와 스탬프 발급의 자동 자격은 일반 위임 목록과 다르다.

새 소유자·주최자와 과거 납부·정산·보류된 모임의 책임자가 같지 않을 수 있다. 이전 직전 화면의 버튼으로 후속 행동을 확정하지 말고 현재 소속·역할·대상 상태를 다시 읽는다. [회원 역할·권한 위임](../prd/02_feature_prds/04_club/F04-04_member-management_prd.md), [클럽 폐쇄·소유권 이전](../prd/02_feature_prds/04_club/F04-03_club-crud-transfer_prd.md)을 따른다.

## 공개 범위와 권한을 분리하는 법

구현된 API, 공개 관문에서 허용된 기능, 현재 사용자의 실행 자격, 실제 운영에서의 활성화는 별개다. 기존 납부·반환·종료를 위한 안전 출구가 공개 관문을 통과하더라도 본인·사건·상태 검사는 유지된다. 기본 비활성인 플랫폼 개입 경로가 코드에 있다는 이유로 일반 운영 권한표에 O를 넣지 않는다.

관리자 인증에도 지정된 예외 정책이 있으므로 ‘모든 관리자는 언제나 동일 인증 절차’라고 단정하지 않는다. 현재 배포값은 이번 문서 대조에서 확인하지 않았다. [플랫폼 관리자 작업의 관문](../prd/03_policy_prds/permission_policy_prd.md#플랫폼-관리자-작업의-관문), [관리자 로그인과 민감 작업의 재인증](../prd/03_policy_prds/permission_policy_prd.md#관리자-로그인과-민감-작업의-재인증)을 따른다.

## 화면·오류·복귀를 기획서에 남기는 법

서버 오류 번호가 있는 403·404 접근 거절에서는 예전 본문·목록·권한을 계속 사용하지 않는다. 다음 쪽 조회가 거절돼도 앞 목록을 비우고, 예전 값으로 명령이나 다음 화면을 열지 않는다. 번호 없는 통신 실패는 유효한 기존 값과 재시도 안내를 유지할 수 있으며, 401은 세션 처리, 재동의·정지 등 계정 관문은 해당 관문이 맡는다. 닫힌 1:1·데이트 대화의 읽기 전용 기록과 플랜·정기모임 소개 편집의 기기 초안 보존은 별도 예외다.

| 확인 | 기록할 결과 |
|---|---|
| 실제 입구 | 메뉴·목록·알림·공유에서 어느 사용자에게 보이는가 |
| 실행 전 | 최신 권한을 받기 전·조회 실패·명시 거절·역할 회수 때 행동을 어떻게 제한하는가 |
| 실행 뒤 | 저장 성공과 후속 조회 실패를 구분하는가, 원래 화면의 현재 행동을 갱신하는가 |
| 결과 불명 | 새 요청을 반복하지 않고 해당 명령의 키·현재 결과를 확인하는가 |
| 증거 범위 | 소스 대조·기존 시험·새 실행·실제 배포와 기기 확인 중 무엇으로 판정했는가 |

버튼 숨김·비활성·안내의 선택은 기능별 제품 흐름에 맞춘다. 코드의 허용 조건과 실제 메뉴 중복 검수는 다른 증거가 필요하다. [기획 QA 체크리스트](10_planning_qa_checklist.md)와 [상태와 정책 가이드](04_state_policy_guide.md)를 함께 따른다.
