# 시나리오 커버리지를 읽는 가이드

<!-- release-document: reference -->
> 2026-11-22 현재 정본·목록을 대조한 문서다. 새 제품 시험·실기기·운영 승인 결과가 아니다. 실행 순서는 [앞으로 할 일](../../docs/plan/NEXT_WORK.md)을 따른다.

현재 **21개 도메인·175개 기능**이다. 기능 목록의 확인 항목 등록값 합은 **1,654개**, 별도 상세 시나리오 문서 **117개**에서 식별한 제목은 **1,276개**다. 별도 units 시나리오 문서가 없는 **58개 기능**도 기능 PRD의 수용 기준을 가진다. 이 숫자는 시험 실행·통과 수가 아니다.

## 집계 기준과 해석

- 등록 확인 항목은 기능 목록의 scenarios 값이다. 정본 수용 조건과 기능별 작성 기준을 반영하며 시험 통과 수가 아니다.
- 상세 제목은 units의 scenarios.md에서 S/SC 번호·시나리오 제목·E2E-derived 제목을 현재 집계식으로 식별한 수다. 별도 문서가 없는 기능은 ‘없음’으로 표시하며 기능 자체의 정의 없음과 구분한다.
- 도식은 별도 units/diagrams.md의 Mermaid 코드 블록 수다. 보이는 화면 개수나 실행된 경로 수가 아니다.
- F12-02는 정본 수용 기준과 등록값이 6개이고, 상세 문서가 기존 조건을 풀어 쓴 E2E-derived 제목을 추가로 포함해 7개다. 두 값을 억지로 같게 만들지 않는다.
- 소스 연결·자동 시험 파일·여정 파일의 식별 결과는 후보 근거다. 단언 내용·버전·실행 결과까지 대조해야 해당 수용 기준의 통과를 주장할 수 있다.

## 기능별로 적용할 확인 범주

| 범주 | 빠뜨리지 않을 질문 |
|---|---|
| 정상 결과 | 실제 요청 성공과 사용자에게 필요한 후속 결과가 무엇인가 |
| 입구와 복귀 | 메뉴·카드·목록·알림·공유 중 실제 연결과 중복 행동은 무엇인가 |
| 빈 상태·로딩·조회 실패 | 자료 없음·권한 거절·부분 실패·미조회 상태를 구분하는가 |
| 현재 권한 | 계정·관계·유효한 위임·공개 범위·역할 제한을 검사하는가 |
| 상태 변화 | 화면을 연 뒤 정원·가격·주최자·기한·보류가 바뀌면 어떻게 처리하는가 |
| 입력 | 서버 필드·nullable·범위·서로 의존하는 값과 앱 검증이 맞는가 |
| 실패·복구 | 확정 거절·외부 결과 불명·저장 후 재조회 실패·부분 처리를 나누는가 |
| 중복·동시성 | 같은 명령 재전송·다른 기기·늦은 응답·동시 변경을 판정하는가 |
| 후속 효과 | 돈·권리·알림·캘린더·위치·평판·증빙 보존의 실제 연결을 확인하는가 |

이 표는 검토할 질문이다. 모든 도메인에 O를 채운 실행 결과표가 아니다. 해당하지 않는 범주는 이유를 적으며, 근거가 충분하고 소스·조건이 바뀌지 않은 항목은 재사용한다.

## 핵심 여정에서 구분할 결과

| 여정 | 확인할 경계 |
|---|---|
| 가입·로그인 | 번호 확인·가입 확인표·계정 생성·내 정보 조회·세션 설치. 제공자 취소·기존 이메일 연결·마지막 수단 해제·늦은 응답 |
| 모임·클럽 참여 | 신청·논리 정원 예약·납부·실제 참석·대기 승격·게스트 책임. 취소·퇴장·차단과 반환·이력 보존 |
| 돈·정산 | 충전과 원 구매, 결제 신고와 수취 확인, 초안 확정과 돈 이동, 취소와 지갑/은행 반환, 외부 결과 불명 |
| 데이팅·위치·안전 | 현재 자격·연락처 동의·차단 관계·방 종료·신고, 위치 동의·OS 권한·좌표·만료·열람 목적 |
| 리뷰·신고·평판 | 작성 자격·자기 대상·중복 조건·수정/삭제·운영 판단·점수 반영. 모든 신고가 자동 제재나 점수 변화를 뜻하지 않음 |
| 운영·분쟁 | 사건 접근·증빙·결정·보상·수동 수습·보류 해제. 플랫폼 개입 기본 설정과 실제 공개 상태 |

위 항목은 경계를 찾는 안내다. 기능별 허용 전이·현재 제약은 [상태 정책](../prd/03_policy_prds/state_policy_prd.md), [권한 정책](../prd/03_policy_prds/permission_policy_prd.md)과 연결된 기능 정본을 따른다.

## 기록 양식과 증거 선택

기능 ID, 실제 입구, 계정·역할, 시작 상태, 명령과 입력, 예상 결과, 관측 결과, 남은 후속 작업, 버전·환경, 증거 위치를 적는다. 미실행·환경 미확인·실패·확인 완료·적용하지 않음을 구분한다. 계획 항목을 통과로 기록하지 않는다.

[공통 QA 수용 기준](../prd/00_prd_items/11_qa_acceptance_criteria.md)과 [기획 QA 정책](../prd/03_policy_prds/planning_qa_policy.md)에 따라 증거를 선택한다. 문서 집계에는 이미지·실결제·브라우저 실행이 필요하지 않다. 실제 메뉴 동선과 외부 결과를 주장할 때만 그 주장에 맞는 실행 근거를 확인한다.
