# 서비스 큰 그림

<!-- release-document: reference -->
> 2026-11-22 현재 기능·정책 정본을 대조한 기획용 안내다. 문서 대조와 제품 실행·외부 연동·공개 확인은 구분한다. 실행 순서는 [앞으로 할 일](../../docs/plan/NEXT_WORK.md)을 따른다.

## 한 문장 정의

관심사에 맞는 오프라인 모임을 찾고 참여하며, 클럽 관계와 후속 운영·정산·안전 절차를 이어 가는 서비스다. 제품 전체에는 마켓·데이팅·제공자 거래도 있지만 구현·문서 존재와 현재 공개는 다르다.

[첫 출시에서 제공할 것](../../docs/README.md#첫-출시에서-제공할-것), [후속 공개 대상](../../docs/README.md#첫-출시를-기다리게-하지-않는-일), [기능별 남은 확인](../../docs/development/IMPLEMENTATION_WORKBOARD.md#첫-출시-기능의-확인-범위)을 나누어 읽는다. 직접 송금과 플랫폼 지갑 결제도 같은 공개 범위로 취급하지 않는다.

## 주요 사용자 유형

| 사용자 관점 | 하려는 일 | 구분할 조건 |
|---|---|---|
| 탐색자·참가자 | 활동 발견·신청·참석·후기 | 비로그인 공개 조회, 승인·납부·참석·체크인 자격 |
| 게스트의 책임 회원 | 동반 인원의 예매·체크인·변경 | 게스트는 독립 계정과 같은 행동 권한을 갖지 않음 |
| 호스트·공동호스트 | 모임과 회차 운영 | 현재 소유권·위임과 명령별 권한 |
| 클럽 회원·운영진·소유자 | 커뮤니티·활동 제도·재정 관리 | 회원 자격과 운영 권한, 소유자 전용 행동 |
| 작성자·판매자·구매자 | 플랜 작성·판매·활용 | 작성물 공개·상품 승인·판매·구매 권리 |
| 데이팅 당사자 | 후보·매칭·대화·만남 | 본인확인·동의·현재 관계·차단·공개 조건 |
| 제공자·납부자 | 서비스 조건·이행·분담·정산 | 계약 당사자, 지급 전 조건과 실제 지급 |
| 문의·분쟁 당사자와 운영자 | 문제 접수·응대·판정 | 원천별 관할·열람·처리·이의 권한 |

이 표는 관점의 구분이다. 역할명이 전 기능의 허용표가 되지는 않는다. [역할과 현재 권한](09_actor_permission_matrix.md)을 함께 본다.

## 전체 범위를 읽는 법

현재 문서 체계는 21개 영역·175개 기능이다. [서비스 지도](01_service_map.md)에서 전체 책임을 찾고 [전체 기능 인벤토리](07_full_feature_inventory.md)로 기능 정본에 들어간다. 별도 원천 메모 117개와 소스·제품 결정에서 출발한 58개를 서로 다른 제품 집합으로 나누지 않는다.

<a id="처음-파악할-때의-관점"></a>

## 사용자 여정을 읽는 법

활동 발견 → 현재 조건 확인 → 신청·등록 또는 구매 → 실제 결과 조회 → 활동·운영 → 필요한 후기·정산·문의로 읽는다. 모든 여정이 돈·후기·매칭을 반드시 거치는 것은 아니다.

가입·로그인 뒤에도 온보딩을 건너뛸 수 있으므로 모든 정보가 채워졌다고 가정하지 않는다. 신청 승인이 참석 확정은 아니며, 결제·입금 확인이나 대기열 조건이 남을 수 있다. 취소 표시 뒤에도 돈 반환이나 자료 정리가 남을 수 있다. [대표 여정](02_core_journeys.md)과 [상태 가이드](04_state_policy_guide.md)에서 경계를 확인한다.

기획자는 실제로 들어온 메뉴·목록·알림·공유 링크, 사용자가 한 행동, 관찰한 결과, 실패·결과 불명의 복구, 돌아온 화면의 상태를 기록한다. 문서의 예시를 실제 앱 실행 기록으로 바꾸지 않는다.
