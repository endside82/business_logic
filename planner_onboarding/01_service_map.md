## 연결을 검토하는 순서

```mermaid
flowchart TD
    A["실제 입구와 사용자 목적"] --> B["현재 계정·관계·위임"]
    B --> C["대상 상태·기한·공개 조건"]
    C --> D["사용자 행동과 현재 결과"]
    D --> E["돈·권리·정원·일정 영향"]
    D --> F["알림·열람·보존 영향"]
    E --> G["실패·결과 불명·부분 처리 복구"]
    F --> G
    G --> H["재조회와 원래 화면 복귀"]
```

화살표는 기획 검토 순서다. 모든 기능이 돈을 움직이거나 모든 알림이 실제 도착한다는 실행 계약은 아니다.

## 연결별로 구분할 것

| 연결 | 확인할 경계 |
|---|---|
| 발견과 접근 | 홈·검색·관심인에 보이는 것과 직접 상세를 열 권한은 다름 |
| 신청·승인·결제·참석 | 정원·대기열·납부·은행 확인이 남을 수 있음 |
| 클럽·정기모임·이벤트 | 클럽 회원 관계, 코스 등록, 회차 참석은 별도 기록 |
| 지갑·직접 송금·모임 정산 | 플랫폼 잔액과 당사자 은행 수취, 실제 수취자별 반환 책임을 구분 |
| 마일리지·스탬프·무료 포인트 | 활동 점수·참여 기록·지갑 통화를 서로 바꾸어 설명하지 않음 |
| 후기·신고·경고·분쟁 | 접수·판정·제재·이의·보상과 공개 범위가 각각 다름 |
| 일정·위치 | 본인 가능 시간, 공개 모임 표시, 좌표 동의·조회·열람 기록은 별개 |
| 판매·제공자 거래 | 판매 승인·구매 권리·계약 이행·정산 확정·실제 지급을 분리 |
| 알림과 지원 | 발송 의도·알림함·기기 수신, 문의 종결·원래 업무 해결을 구분 |

영역별 작업 질문은 [업무 영역 검토 안내](03_unit_playbooks.md), 상태·권한·검증은 [상태 가이드](04_state_policy_guide.md), [역할 가이드](09_actor_permission_matrix.md), [기획 QA](10_planning_qa_checklist.md)에서 이어서 확인한다.
