# 용어집

<!-- release-document: reference -->
> 2026-11-22 현재 기능·정책 정본을 대조한 기획용 안내다. 문서 대조와 제품 실행·외부 연동·공개 확인은 구분한다. 실행 순서는 [앞으로 할 일](../../docs/plan/NEXT_WORK.md)을 따른다.

같은 단어라도 원천 기록과 완료 범위가 다를 수 있다. 아래는 사용자·기획 문서의 구분 기준이며 실제 상태·수치·허용 행동은 [상태 정책](../prd/03_policy_prds/state_policy_prd.md)과 [권한 정책](../prd/03_policy_prds/permission_policy_prd.md)을 따른다.

## 핵심 콘텐츠

| 용어 | 의미와 구분 |
|---|---|
| 이벤트 | 개별 모임. 모집 상태·활동 시간·실제 참석은 별개다. |
| 클럽 | 지속되는 회원 관계와 커뮤니티. 모든 이벤트·정기모임의 상위 객체라는 뜻은 아니다. |
| 정기모임·회차 | 고정/가변 모임의 코스·등록과 각 이벤트 회차를 구분한다. |
| 플랜·마켓 상품 | 구성한 콘텐츠와 심사·가격·판매 계약을 가진 상품. 플랜·아이템·번들·기간권을 한 객체로 합치지 않는다. |
| 구매 권리 | 구매 시점 대상과 조건에 따른 사용 자격. 현재 상품의 노출·판매 상태와 다르다. |
| 프라이빗 데이팅·비공개 모임 | 데이팅의 후보·매칭·대화와 Event 기반 비공개 모임의 상태·보관금 흐름은 별개다. |
| 제공자 배정 | 모임의 서비스 제공자와 조건·이행·대금을 연결하는 관계. 단순 참가자 등록과 다르다. |

## 신청, 참석, 체크인

| 용어 | 의미와 구분 |
|---|---|
| 신청·승인 | 참여 요청과 그 판단. 유료 승인 뒤 납부 대기가 남을 수 있어 곧바로 참석 확정으로 쓰지 않는다. |
| 참석·대기열 | 실제 참가 자격과 정원 대기. 신청 승인·논리 예약·실제 참석 행을 구분한다. |
| 게스트 | 책임 회원에 연결된 동반 인원. 독립 회원의 후기·메시지·프로필 권한과 같지 않다. |
| 체크인·출석 확정 | 현장 확인과 후속 출석 판정. 정기모임의 회차 확정도 별도 조건을 따른다. |
| 노쇼·소명 | 미참석 판정과 당사자의 설명·검토. 단순 체크인 없음만으로 모든 제재·환불 결과를 단정하지 않는다. |

[이벤트](../prd/01_domain_prds/03_이벤트_prd.md)와 [정기모임](../prd/01_domain_prds/17_정기모임_prd.md) 정본을 함께 본다.

## 돈과 활동 기록

| 용어 | 의미와 구분 |
|---|---|
| 지갑·유료/무료 포인트 | 회원의 통화별 잔액·거래. 유료와 무료의 소비·만료·반환 조건을 구분하며 모두 현금 출금 가능하다고 하지 않는다. |
| 충전·자동충전 | 외부 결제에 따른 잔액 반영. 원래 구매나 납부의 성공과 다르다. |
| 직접 송금 | 참가자가 주최자 계좌로 보내고 수취자가 확인하는 경로. 플랫폼이 받은 돈을 다시 지급하는 경로가 아니다. |
| 결제·입금 확인 | 해당 채무의 납부와 수취 확인. 신고·확인·실제 은행 거래 증거를 구분한다. |
| 환불·반환 | 원천별 조건에 따른 돈·권리 복구. 신청·승인·지갑 입금·외부 반환 기록·실제 외부 송금은 별개다. |
| 호스트 정산금·외부 출금 | 수익 산정·승인·지급과 사용자 출금 요청. 같은 ‘정산 완료’로 합치지 않는다. |
| 모임 정산 | 지출·수입과 실제 수취자를 반영한 분담. 항상 호스트에게만 돈을 내는 구조는 아니다. |
| 참가비 선결제·정산 선입금 | 참가 조건의 사전 납부와 별도 정산 선입금 상품은 다르다. 후자는 현재 공개 제한을 따른다. |
| 클럽 기금 | 클럽의 통화별 공동 자금. 회원 지갑이나 모임 정산 결과와 자동으로 합쳐지지 않는다. |
| 마일리지·스탬프 | 클럽 활동 점수·참여 기록과 보상 조건. 지갑 무료 포인트와 다르다. |
| 결과 불명·부분 처리 | 성공 또는 거절을 아직 확정할 수 없거나 일부만 처리된 상태. 전체 실패·자동 원복으로 바꾸지 않는다. |

[결제·정산 정책](../prd/03_policy_prds/payment_settlement_policy_prd.md), [돈의 상황별 흐름](../docs/money-flow/scenarios.html), [마일리지](../prd/01_domain_prds/16_마일리지_prd.md)를 따른다.

|---|---|
| 별점 후기·선택형 피드백 | 호스트에 대한 후기와 다시 함께할 사람 선택. 기간·자격·표시 범위가 다르다. |
| 신고·경고·제재 | 접수와 판정·기록·제한 집행. 신고 제출만으로 모두 발생하는 것은 아니다. |

| 문의·운영 이슈·분쟁 | 질문·원천별 처리·사건과 이의의 서로 다른 채널. 접수·종결·보상·기록 파기를 나눈다. |

## 상태값과 화면 문구

`PENDING`을 모든 곳에서 ‘심사 중’으로 번역하지 않는다. 어떤 신청·결제·송금·처리의 대기인지 먼저 적는다. `CLOSED`·취소·완료도 모집 마감, 실제 종료, 돈 반환의 범위가 다르다. 서버 상태와 화면에서 계산하는 단계를 구분하고 해당 정본의 값을 따른다.

| 실제로 확인한 사실 | 문구에 드러낼 내용 |
|---|---|
| 승인 뒤 납부가 남음 | 신청 승인과 납부 필요를 함께 안내 |
| 수취 확인이 남음 | 확인할 수취자와 현재 이체 신고 상태 |
| 정산 확정 | 납부 요청을 확인할 수 있음. 실제 알림 전송 완료를 단정하지 않음 |
| 요청 응답을 받지 못함 | 결과 확인 중과 재조회·복구 행동 |
| 조회 실패·좌표 만료 | 최신 자료를 확인하지 못함. 이전 좌표를 최신처럼 표시하지 않음 |
| 기기 알림 권한 거부 | 현재 기기 설정에서 변경할 수 있는 경로 |

대기 순번·환불 완료·알림 도착처럼 확인되지 않은 값을 문구 예시 때문에 새로 만들어 넣지 않는다.
